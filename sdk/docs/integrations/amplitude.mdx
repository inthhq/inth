Use c15t to load Amplitude Browser SDK 2 with [web consent](#web), or connect
Amplitude Analytics in [React Native and Expo](#mobile). Native Swift and Kotlin
adapters are deferred.

## Web

The c15t `amplitude` helper keeps the Amplitude Browser SDK 2 off the page until
`measurement` has consent. Until then, c15t does not define `window.amplitude`.
When `measurement` has consent, the helper queues `init` and `setOptOut(false)`
before the SDK loads. If the visitor withdraws consent, the helper calls
`amplitude.setOptOut(true)`. The SDK stays on the page. By default, c15t also
reloads the page.

### Configure Amplitude

Use your Amplitude project API key. The `amplitude` helper initializes Browser
SDK 2 for you, so remove any existing Amplitude snippet or `init` call.

<CommandTabs command="@c15t/integrations" mode="install" />

```ts title="src/consent-scripts.ts"
import { amplitude } from '@c15t/integrations/amplitude';

export const scripts = [amplitude({ apiKey: 'YOUR_PROJECT_API_KEY' })];
```

### Options

| Option | Default | Behavior |
| --- | --- | --- |
| `apiKey` | Required | Project API key passed to `amplitude.init`. The helper trims it. Empty or whitespace-only values log an error and the script does not load. |
| `initOptions` | `{}` | Browser SDK 2 options passed as the second argument to `init`. Use JSON-serializable values only. |
| `scriptUrl` | `https://cdn.amplitude.com/libs/analytics-browser-2.44.4-min.js.gz` | Loader URL override. The default pins Browser SDK 2 version `2.44.4`. A blank value falls back to the default. |

### Loading and revocation

`amplitude` uses the `measurement` category. Before measurement is allowed,
c15t defines no `window.amplitude` and loads nothing from Amplitude. When
measurement becomes allowed, the helper creates the Browser SDK 2 queue stub,
queues `init(apiKey, initOptions)` and `setOptOut(false)`, then loads the SDK,
which replays the queue. Amplitude saves an opt-out in its cookie, so the
queued `setOptOut(false)` clears one left by an earlier revocation.

On revocation the helper calls `amplitude.setOptOut(true)` and leaves the SDK
on the page, because removing the script would not stop the running client.
If the visitor allows measurement again before the page reloads, the helper
calls `setOptOut(false)` on that SDK instead of loading a second copy.

### Verify Amplitude

After you allow measurement, the `analytics-browser-2.44.4-min.js.gz` request
loads and a test event reaches your Amplitude project. Revoke measurement, then
allow it again on a later page and check that events reach Amplitude again.

## Mobile

Use the bundled Amplitude helper to keep Analytics opt-out in sync with native
c15t permission. Pending or denied permission enables opt-out. A grant disables
opt-out. The default category is `measurement`.

The helper ships in `@c15t/react-native/integrations`.
Native Swift and Kotlin Amplitude support is deferred. Your app owns the
Amplitude dependency, configuration and event calls.
This adapter uses the modern JavaScript Analytics client's `setOptOut` API;
it does not bind a native Amplitude client.

### Before you start

Complete the [React Native](/docs/frameworks/react-native/quickstart) quickstart.
Include `measurement` in your native category configuration and Inth policy. Connect
the same installed engine your consent UI uses. Mobile SDKs currently have
[private prerelease access](/docs/guides/mobile-status).

Install the current [React Native](https://amplitude.com/docs/sdks/analytics/react-native/react-native-sdk)
Analytics SDK. This mapping targets the current SDK, rather than its legacy
maintenance library.

Initialize Amplitude with `optOut` enabled before optional collection can begin.
Configure automatic tracking, advertising identifiers, location and session
replay separately. A measurement grant does not authorize every Amplitude
product. For a strict startup, defer initialization until a native gate allows it.
A JS helper cannot stop an earlier native initializer. See
[native startup](/docs/frameworks/react-native/native-behaviour).

Expo needs an app build containing the vendor and c15t native modules. Expo Go
does not provide c15t's native engine.

### Native Swift and Kotlin support

There are no bundled native Amplitude helpers in this release. In the reviewed
AmplitudeSwift 1.19.4 and Android Analytics 1.36.0 sources, the runtime `optOut`
value has no documented synchronization contract across consent callbacks,
event callers and vendor worker queues. c15t's native notifications can arrive
on different threads.

A future native adapter needs a vendor-supported synchronization or event-gating
contract. Suppressing Swift's `Sendable` warning or dispatching a setter to the
main queue does not prove withdrawal across vendor workers. Other bundled
[mobile integrations](/docs/integrations/overview#mobile-sdks) remain available.

### Connect React Native or Expo

Copy this function into `amplitude-consent.ts`:

Connect the modular API after initializing that same Amplitude client:

{/* example: fragment */}

```ts
import { setOptOut } from '@amplitude/analytics-react-native';

const amplitudeConsent = connectAppAmplitude(
	{ setOptOut },
	reportAnalyticsError
);
await amplitudeConsent.ready;
```

For multiple projects, pass the chosen client's `setOptOut` method through a
closure. Do not connect the default singleton and send app events to a separate
instance. Retain the connection for the service lifetime. Report automatic
failures through `onError`, and handle rejections from `ready`, `sync()` and
`disconnect()` at their call sites.

### Handle reset and teardown

After an app-owned Amplitude reset completes, call `await amplitudeConsent.sync()`.
This reapplies current native permission without recording a new choice.

For final teardown, call `await amplitudeConsent.disconnect()`.
The helper detaches and enables opt-out.
It does not log the person out, rotate their identity or shut down unrelated
app services.

Opt-out blocks new covered event collection. It does not establish that every
older event queue is deleted or every request stops. Previously queued events
can still upload. Data already uploaded needs the vendor's
retention or deletion controls. Keep optional event calls behind current
permission and check startup as well as the eventual opt-out value.

### Verify your app

Check fresh pending startup, refusal, grant and an intentional event, then
withdrawal. Relaunch after both choices, reset the vendor and reapply permission.
Check that unrelated consent changes do not submit new opt-out commands.
Inspect previously queued events separately from events attempted after refusal.

The checked mapping uses RN Analytics 1.13.0.
Helper tests and vendor consumer checks cover the binding;
they do not prove your app's actual network or device behavior. Follow
[mobile verification](/docs/guides/mobile-verify) before relying on collection
and withdrawal behavior.
