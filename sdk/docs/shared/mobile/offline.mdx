## Choose the offline behavior you need

Saved choices already survive a process restart without a network connection.
The native engine restores its protected record before returning from
installation. Optional SDKs stay off while authority is unresolved or invalid.

A fresh installation has no saved policy. Bundle an exported policy if that
first launch must explain consent without connectivity. Keep hosted transport
configured so the app can refresh policy and deliver queued records when it
reconnects.

In backend mode the SDK picks the policy in this order:

1. The live `/init` response.
2. The last good response cached on the device.
3. The manifest bundled into the app at build time.

A newer bundled manifest replaces an older bundled one cached by an earlier
build. It never replaces a cached live response.

No-backend mode (`mode: 'offline'`) sends nothing and reads no bundled
manifest. Its only policy source is a policy you keep in source control. The
two modes do not mix, so Expo prebuild refuses `backendURL`, `initURL`,
`policyResource` and `iab` in offline mode.

## Define the policy in code

In no-backend mode, write the policy as rules in the backend's `PolicyRule`
names: `id`, `match`, `model`, `prompt`, `categories`, `scopeMode`,
`preselectedCategories`, `actions`, `validity`, `privacySignals` and
`copyRevision`. The SDK resolves them on the device with the backend's
matching order: region, country, `regionFallbacks`, `fallback`, then
`isDefault`.

The device has no geolocation without a backend. The `fallback` rule applies
unless your app sets an override country and region, so every policy needs a
rule with `match.fallback` or `match.isDefault`. Choices stay on the device;
nothing sends them anywhere.

```ts title="app.config.ts"
export default {
	plugins: [
		[
			'@c15t/react-native/expo-plugin',
			{
				mode: 'offline',
				consentCategories: ['necessary', 'measurement', 'marketing'],
				policy: {
					rules: [
						{
							id: 'germany',
							match: { countries: ['DE'] },
							model: 'opt-in',
							prompt: 'choice',
						},
						{
							id: 'everywhere_else',
							match: { fallback: true, isDefault: true },
							model: 'opt-in',
							prompt: 'choice',
						},
					],
				},
			},
		],
	],
};
```

```swift title="Swift"
let policy = try ConsentPolicy(rules: [
    PolicyRule(id: "germany", match: PolicyMatch(countries: ["DE"]), model: .optIn, prompt: .choice),
    PolicyRule(id: "everywhere_else", match: PolicyMatch(fallback: true, isDefault: true),
               model: .optIn, prompt: .choice),
])
core.bootstrap(CoreConfig(policy: policy, transport: OfflineTransport.offline()))
```

```kotlin title="Kotlin"
val policy = ConsentPolicy(listOf(
    PolicyRule("germany", PolicyMatch(countries = listOf("DE")), ConsentModel.OPT_IN, PolicyPrompt.CHOICE),
    PolicyRule("everywhere_else", PolicyMatch(fallback = true, isDefault = true), ConsentModel.OPT_IN, PolicyPrompt.CHOICE),
))
C15tAndroid.install(context, NativeConfig(backendUrl = null, policy = policy))
```

Both cores also read the same rules as JSON, `{"rules": [...]}`:
`ConsentPolicy(json:)` in Swift and `ConsentPolicy.fromJson` in Kotlin. Expo
writes that file for you and names it with `com.c15t.policy.rules` in
`Info.plist` and `com.c15t.POLICY_RULES` in the Android manifest.

Change `copyRevision` when the wording people agreed to changes. Returning
people are asked again after the update.

IAB TCF does not work in no-backend mode. The `iab` model needs the Global
Vendor List, and only a backend serves it, so the SDK refuses an `iab` rule
without one. Use backend mode with a bundled manifest for offline IAB.

## Export the policy

From an authorized source checkout, build the exporter's dependencies and
export your project's public manifest:

```sh
bun turbo run build --filter=@c15t/schema --filter=@c15t/translations
bunx tsx scripts/export-mobile-policy.ts \
  --endpoint https://your-project.inth.app \
  --out /absolute/path/to/app/c15t-policy.json \
  --expires-at 2027-01-01T00:00:00.000Z \
  --languages en,de
```

Replace the URL, output path, languages and expiry. Choose a future expiry
for your release; the example date is not a recommended lifetime. This
exporter is currently a repository tool, not an installed RN command.

The manifest needs a conservative opt-in or IAB fallback for unknown
geography, with no preselected optional categories. Export fails when that
fallback is absent. For a scoped IAB app, supply `--vendors` with the
comma-separated vendor IDs. Export also needs the GVL and all configured
Additional Consent provider disclosures.

## Include the resource in the app

| App | Where the JSON goes | Configuration |
| --- | --- | --- |
| Swift | The app target's Copy Bundle Resources | Load `BundledPolicyResource` and pass it as `bundledPolicy` during installation |
| Bare RN, iOS | The app target's Copy Bundle Resources | `com.c15t.policy.resource` names the bundled resource |
| Kotlin or bare RN, Android | `app/src/main/assets/c15t-policy.json` | `com.c15t.POLICY_RESOURCE` names the asset for automatic installation |
| Expo | Beside your app config, or another source path | Set `policyResource` in the c15t config plugin and rebuild |

For app-owned Android installation, read the asset JSON and pass it as
`NativeConfig.bundledPolicy`. Keep the same backend endpoint at export and
startup. Native loading validates the resource schema, integrity, endpoint
binding and authority dates.

The JSON is a public app artifact. Put no secrets in it. Its SHA-256 checks
byte integrity; it is not a signature or an external approval.

## When the bundled manifest expires

An expired bundled manifest still works. If the device is offline, the SDK
uses it to show the prompt and record choices, and emits a `policyStale`
event. Optional categories stay off until the person chooses. The next live
`/init` response replaces the manifest.

| Platform | Event | Current state |
| --- | --- | --- |
| Swift | `CoreEvent.policyStale(authority)` on `eventStream` | `ConsentCore.isPolicyStale` |
| Kotlin | `ConsentCore.onPolicyStale { authority -> }` | `ConsentCore.isPolicyStale` |

Kotlin calls a new `onPolicyStale` observer at once when a stale manifest is
already in force, so a subscription made after startup still hears it.

A manifest bound to a different backend URL, or issued in the future, supplies
no policy. Optional SDKs stay off and the core keeps trying to refresh.

IAB disclosures have their own deadline, measured from the original GVL or
provider-list source date. The default maximum age is seven days. Copying an
old list into a new app build does not renew it, and an expired list cannot
authorize a new IAB grant.

Rejection and withdrawal remain available without connectivity. Confirm local
commit success before dismissing app-owned settings. The native engine stores
the denial and its delivery obligation together. A later transport failure
does not undo that withdrawal.

On reconnect, queued records must not restore an earlier grant over a newer
withdrawal. Do not clear the queue or edit platform IAB keys to recover from a
delivery failure. See [identity and reset](/docs/guides/mobile-identity) for
the difference between withdrawal and starting over.

## Check that it works

1. Install a build with a valid bundled policy and launch it offline with no
   previous choice. The prompt appears and optional SDKs stay off.
2. Reject, stop the app and relaunch offline. The saved refusal remains.
3. Reconnect. Confirm delivery at the configured backend.
4. Repeat with an expired bundle. The prompt still appears, optional SDKs stay
   off until you choose, and the app receives `policyStale`.
5. Repeat with a bundle exported for a different backend URL. No prompt
   appears and optional SDKs stay off.

Changing the bundled resource changes the native binary. Re-export during
release preparation and build a new binary; a JavaScript OTA update does not
replace the native resource.
