Use `ConsentTheme` to match the stock screens to your app. The same theme
works in a SwiftUI app and in a UIKit-hosted presenter. It changes native
appearance while the presenter continues to own drafts, saving and navigation.

## Set your app's theme

Create `AppConsentTheme.swift` in your app target. This example gives the
consent screen your app's name and asset, changes the primary color in both
appearances, widens the page gutter, sets a larger body size and a serif
headline, rounds the outlined actions into pills, and uses Inth provider
attribution:

<include src="../../shared/examples/native/core-swift/AppleInstallation/swift-app-theme.mdx" />

Replace `My app` with your app name and add an image named `AppPrivacyMark`
to the app's asset catalog, or use the name of an existing asset. The
introduction should describe your app's actual purposes. This copy example
assumes both measurement and marketing are in scope.

Pass the theme to the `.c15tConsent` modifier from the [quickstart](/docs/frameworks/swift/quickstart):

<include src="../../shared/examples/native/core-swift/AppleInstallation/swift-themed-root.mdx" />

`ConsentRootViewController` takes the same `theme` argument in a UIKit app.
The primary color applies to switches, links and Save. Accept all and Reject
all keep the same `decision` fill and `textOnDecision` label treatment.

## Choose what to change

| Setting | Use it for |
| --- | --- |
| `brand.name`, `brand.markImageName` | Your app's identity above the headline |
| `brand = .hidden` | Removing that app identity block |
| `copy.headline`, `copy.introduction` | First-layer wording |
| `colors.canvas`, `surface`, `surfaceMuted` | Page, cards and subordinate content |
| `colors.text`, `textMuted` | Primary and supporting text |
| `colors.primary`, `textOnPrimary` | Links, switches and the Save action |
| `colors.decision`, `textOnDecision` | Both Accept all and Reject all |
| `radius.md` | Card and button shape; `radius.sm` and `radius.lg` follow it until set |
| `spacing.xs` to `spacing.xl` | Page gutters, section gaps and padding |
| `typography.fontSize.sm`, `.base`, `.lg` | Supporting, body and headline sizes; `nil` keeps the text style |
| `typography.fontFamily` | A bundled font for every role except the headline |
| `typography.headlineFont` | System sans, serif, rounded or a bundled custom headline font |
| `slots` | One part: `.consentBannerTitle`, `.consentBannerDescription`, `.buttonPrimary` or `.buttonSecondary` |
| `branding` | `.c15t`, `.inth` or `.custom(name:markImageName:)` provider attribution |
| `showsBranding` | Visibility of the provider attribution |

Names that have a web token match it: `primary` is `--c15t-primary`, and
`radius.md` is `--c15t-radius-md`. A font size groups text styles: `sm` sizes
subheadline, footnote and captions, `base` sizes body and headline, and `lg`
sizes the large title. Each style keeps its ratio to its group, and Dynamic
Type still scales it. Spacing does not change a control's own padding, so tap
targets keep their size. A slot's `color`, `backgroundColor`, `borderRadius`
and `fontSize` override the tokens for that part only; `buttonPrimary` colors
fall back to the stock decision colors below 5:1 contrast.

`ConsentThemeColor` takes sRGB `0xRRGGBB` values for `light` and `dark`.
Omitting `dark` uses the light value in both appearances. Keep text legible
against every surface. The SDK does not certify a custom palette's contrast.

App identity and provider attribution have separate purposes. Hiding the app
identity with `.hidden` does not hide the small provider mark beside or below
the first-layer controls.

## Configure appearance without changing view code

When no explicit theme is passed, the presenter uses `ConsentTheme.current`
with supported `Info.plist` values applied. Set `current` once during app
startup, before constructing the consent root. An explicit modifier theme has
priority over both.

| `Info.plist` key | Value |
| --- | --- |
| `com.c15t.consent.brandName` | Your app's name |
| `com.c15t.consent.brandMark` | Image asset name |
| `com.c15t.consent.primary` | `#RRGGBB` or `#RRGGBB,#RRGGBB` for light,dark |
| `com.c15t.consent.textOnPrimary` | Label color using the same format |
| `com.c15t.consent.radiusMd`, `spaceLg`, `fontSizeBase` | A number of points; the other steps follow the same pattern |
| `com.c15t.consent.buttonPrimary.borderRadius` | One slot field, as `<slot>.<field>` |
| `com.c15t.consent.headline` | First-layer headline |
| `com.c15t.consent.introduction` | First-layer introduction |
| `com.c15t.consent.brandingProvider` | `c15t` or `inth` |
| `com.c15t.consent.branding` | Boolean controlling provider attribution |

Use a native Boolean for `branding`, rather than the string `"false"`.
Other color, size and slot keys are declared in `ConsentTheme.InfoPlistKey`.

## Account for language and screen size

The stock screens read every label from `@c15t/translations`, in the policy's
translation language: the language `/init` serves, or `overrides.language` in
`C15tAppleConfiguration`. Buttons, headings and category names use the web banner's keys,
so they read "Accept All" and "Reject All". App-only sentences, such as the
category explanations and save errors, come from native-only keys in the same
package. A language c15t has no copy for falls back to English. IAB screens
follow the served vendor list's language.

`ConsentTheme.Copy` changes the headline and introduction. Leave a field `nil`
to keep the translated stock copy; a string you set is shown as given in every
language. It is not a localization dictionary for the other labels.

The presenter follows Dynamic Type, safe areas and window geometry. On
supported iOS layouts with enough side-column space, compact attribution can
sit beside the actions. It falls back inline when that area is unavailable
or accessibility text needs more room. No device-model check is required.

Test light and dark appearance, the largest text sizes, narrow and wide windows,
and VoiceOver after changing the theme. Keep Accept and Reject equally
prominent and Privacy settings reachable after either choice. If the layout
itself needs different controls, use
[app-owned UI](/docs/frameworks/swift/headless).
