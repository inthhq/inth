UIKit apps use the same native core, Keychain storage and consent screens as
SwiftUI apps. Install the engine during app startup, then host the SwiftUI
consent root in your scene. React Native and JavaScript are not required.

## Add the package and shared files

Follow [Add the Swift package](/docs/frameworks/swift/quickstart#add-the-swift-package)
to link `C15tCore`, `C15tApple` and `C15tConsentUI`. Add the
`ConsentModel.swift` and `ConsentRoot.swift` files from that quickstart to your
UIKit app target. These files own installation, observation, the consent
modifier and the standing Privacy settings action.

Use your Inth project's HTTPS backend URL and the app's HTTPS privacy-policy
URL. Your project needs the policy and categories described in the
[quickstart prerequisites](/docs/frameworks/swift/quickstart#before-you-start).

Replace both placeholder URLs. Keep one `@main` entry point in the target; do
not also include the SwiftUI quickstart's `MyApp.swift`.

The app must have scene support enabled in its Application Scene Manifest. This
delegate supplies `SceneDelegate` programmatically and clears the scene
storyboard. If your existing app uses a storyboard or a named scene
configuration, keep its lifecycle and apply the model and hosting setup there
rather than adding a second window.

`UIHostingController` hosts native SwiftUI views. It does not introduce a web
view, a JavaScript runtime or a second consent record.

## Keep your existing UIKit navigation

The example uses `ConsentRoot` as the window root to make the whole integration
visible. In an existing app, place the hosting controller in your existing
controller hierarchy using normal UIKit child-controller containment. Keep the
host mounted for as long as it owns the consent presentation. Do not create a
new presenter every time Settings opens.

Use the shared model's `presenter?.presentPreferences()` from your UIKit
Privacy settings action. Call it on the main actor after the model reports
`isReady`. That opens the same stored choices used by SDK gates. The host
modifier handles the actual sheet or full-screen presentation.

The presenter owns draft edits, partner navigation, rejected-save retry and
discard confirmation. Keep your app's navigation outside that flow, and avoid
presenting a second consent controller while it is already open.

## Handle startup and unlock

`ConsentModel` installs synchronously during `didFinishLaunchingWithOptions`.
Saved consent is therefore available before optional SDK startup. An app with
no saved policy remains pending while it loads the project's policy.

`ConsentRoot` observes protected-data and activation notifications. After a
Keychain failure it retries the same protected installation; it never replaces
the store with memory or a plaintext file. The rest of the app can remain
usable while optional collection stays off.

For a UIKit vendor integration, use the same standing
[native gate subscription](/docs/frameworks/swift/headless#keep-sdk-gates-current)
as a SwiftUI app. A permission read during launch alone does not handle later
withdrawal.

## Check the UIKit journey

Run the app with a policy that asks for a choice. Reject optional use, navigate
to your app's settings, reopen Privacy settings and save a different choice.
Relaunch and confirm that the same choice is restored. Repeat after background
and foreground transitions, and confirm the app has only one active presenter.

The maintained UIKit demo lives in `native/examples/consent-demo/ios`. Its
`C15tUIKitDemo` scheme hosts the same stock presenter and has local category
and IAB demonstrations. Those sample policies are separate from your hosted
project and its review configuration.

See [Customize](/docs/frameworks/swift/customize) for styling and
[mobile verification](/docs/guides/mobile-verify) for the full app checks.
