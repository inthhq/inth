The standard React Native integration opens SwiftUI and Compose consent
screens. Customize those screens through native `ConsentTheme` settings or
native build metadata. React `style` props and web CSS do not style them.

## Choose what to change

| Change | Use |
| --- | --- |
| Colors, corner radius and headline font | Native theme metadata or native `ConsentTheme`. |
| Your app's name and logo | Native app-identity settings. |
| c15t, Inth or custom provider attribution | Native branding settings. |
| First-layer heading and introduction | Native copy settings. |
| Entirely custom React controls | [Headless hooks and commands](/docs/frameworks/react-native/headless). |

The presenter keeps Accept and Reject on the same decision style. Their
first-layer action labels are not replaceable introductory copy.

## Set colors in the native app

For bare RN, merge these iOS entries into the app target's `Info.plist`. This
fragment changes the accent, decision fill and corner radius:

{/* example: fragment */}

```xml title="Info.plist entries"
<key>com.c15t.consent.accent</key>
<string>#2563EB,#60A5FA</string>
<key>com.c15t.consent.decision</key>
<string>#172554,#DBEAFE</string>
<key>com.c15t.consent.onDecision</key>
<string>#FFFFFF,#172554</string>
<key>com.c15t.consent.cornerRadius</key>
<real>16</real>
```

On Android, add the corresponding metadata inside `<application>`:

{/* example: fragment */}

```xml title="AndroidManifest.xml application entries"
<meta-data android:name="com.c15t.consent.ACCENT" android:value="#2563EB,#60A5FA" />
<meta-data android:name="com.c15t.consent.DECISION" android:value="#172554,#DBEAFE" />
<meta-data android:name="com.c15t.consent.ON_DECISION" android:value="#FFFFFF,#172554" />
<meta-data android:name="com.c15t.consent.CORNER_RADIUS" android:value="16" />
```

A single `#RRGGBB` color applies in both appearances. A comma-separated pair
selects light and dark values. Corner radius uses points on iOS and dp on
Android. Rebuild the binary, open Privacy settings and check both appearances.

For Expo, the c15t config plugin does not expose a `theme` prop. Apply these
native keys through an app-owned Expo config plugin, or maintain them in your
native projects when your app owns those files. Regenerating native files
with prebuild can replace manual edits.

## Add your app's identity

Use `brandName` and `brandMark` on iOS, or `BRAND_NAME` and `BRAND_MARK` on
Android. iOS marks name bundled image assets; Android marks name drawable
resources. Set the `brand` or `BRAND` boolean to false to hide the app identity.

App identity and provider attribution are separate. Hiding the app identity
does not select a different consent provider.

## Use Inth attribution

Set `com.c15t.consent.brandingProvider` to `inth` in iOS `Info.plist`, or
`com.c15t.consent.BRANDING_PROVIDER` to `inth` in Android application metadata.
Use `c15t` for the other built-in provider. Both names use bundled marks.

For custom attribution, set `brandingName` and optionally `brandingMark` on
iOS, or `BRANDING_NAME` and `BRANDING_MARK` on Android. The mark uses a bundled
native asset. `branding` or `BRANDING` controls attribution visibility.

On supported iOS 27.1+ layouts, the presenter can place compact provider
attribution in the system's vertical side area, aligned with Customize. The
layout follows window geometry and system-reserved regions. It does not test
the device model. It falls back below Customize when that area is unavailable
or accessibility text needs more space.

## Native setting reference

Every iOS suffix below starts with `com.c15t.consent.`. Android suffixes use
the same prefix inside application metadata.

| Setting | iOS suffix | Android suffix |
| --- | --- | --- |
| Accent and text on accent | `accent`, `onAccent` | `ACCENT`, `ON_ACCENT` |
| Page and card surfaces | `canvas`, `surface`, `surfaceMuted` | `CANVAS`, `SURFACE`, `SURFACE_MUTED` |
| Main and secondary text | `text`, `textSecondary` | `TEXT`, `TEXT_SECONDARY` |
| Decision buttons | `decision`, `onDecision` | `DECISION`, `ON_DECISION` |
| Corner radius | `cornerRadius` | `CORNER_RADIUS` |
| Headline font | `headlineFont` | `HEADLINE_FONT` |
| App name and mark | `brandName`, `brandMark` | `BRAND_NAME`, `BRAND_MARK` |
| Show app identity | `brand` | `BRAND` |
| First-layer copy | `headline`, `introduction` | `HEADLINE`, `INTRODUCTION` |
| Show provider attribution | `branding` | `BRANDING` |
| Built-in provider | `brandingProvider` | `BRANDING_PROVIDER` |
| Custom provider name and mark | `brandingName`, `brandingMark` | `BRANDING_NAME`, `BRANDING_MARK` |

Body text uses the system face. Android maps `rounded` headline type to its
system sans face. Check contrast and larger text after changing theme values;
the native screen retains its layout and interaction rules.

## Copy and languages

`headline` and `introduction` change the first-layer copy. They are not a
complete localization dictionary. The current stock native navigation, action
labels and category explanations contain English strings. Changing the policy
language does not translate all native UI.

GVL descriptions use the available language disclosures and fallback. ATT
usage descriptions have separate native localization. If your app needs a
fully app-owned localized category interface today, use
[headless controls](/docs/frameworks/react-native/headless) and include the
required policy information in that UI.

## React-rendered components

The package also exports `ConsentBanner`, `ConsentDialog`,
`ConsentPreferences`, `ConsentIabDrawer` and React theme helpers. Those render
React Native UI and have separate component props. Their theme does not affect
the native presenter.

Use the shared native screens for the standard flow. If you use the React
components or your own controls, preserve the native engine, check every
[commit result](/docs/frameworks/react-native/usage#inspect-every-local-commit)
and keep SDK startup gates.
