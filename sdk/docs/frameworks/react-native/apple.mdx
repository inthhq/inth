SwiftUI and UIKit apps can use `C15tApple` without React Native, Expo or JavaScript. The local Swift package at `native/core-swift` exports `C15tCore`, `C15tApple` and optional `C15tConsentUI`. These are private source artifacts. Do not invent a remote SwiftPM release URL or tag.

## Resolve the source products

For authorized source integration, add `native/core-swift` as a local Swift package in Xcode. Link `C15tApple` and `C15tCore`; add `C15tConsentUI` only if you use the SwiftUI stock screens. The RN path is different: its CocoaPods target compiles these sources into `C15tReactNative`.

The mobile UI target is iOS 16.4 or later. The source manifest also lists other Apple targets for core use; that is not a tested consent-UI or ATT support claim for those targets.

Call it from app startup before optional SDK initialization or RN attachment. The installer validates storage, hydrates synchronously and returns the process's native core. It defaults to Keychain. Repeated installation returns the same engine and keeps its original configuration.

Read `C15t.isAllowed(.measurement)` or `C15t.decision(for: .measurement)` before starting the corresponding optional SDK. Keep an observation alive to stop or reconfigure collection after withdrawal. Unknown or unavailable consent keeps the SDK off.

`protectedStorageUnavailable` leaves no new core installed. Retry after protected-data availability or activation; never fall back to plaintext or memory. The repository's SwiftUI/UIKit installation examples show retry ownership. Keychain may survive reinstall, so uninstall is not a reset guarantee.

## Present native screens

Retain one `ConsentPresenter(core:)` on the main actor and apply the `.c15tConsent(presenter:privacyPolicyURL:theme:)` modifier to your SwiftUI host. UIKit can host that SwiftUI tree. The presenter observes the same native core, owns drafts and automatically presents an owed choice by default. `ConsentTheme` configures the [native appearance](/docs/frameworks/react-native/customize). An IAB host must supply native CMP/publisher settings and current disclosures before accepting vendor decisions.

## Attach to an RN CocoaPods host

Import only `C15tReactNative` for host-owned installation in a CocoaPods RN app. Set `com.c15t.reactnative.AutoBootstrap` to false, call that module's `C15tApple.install`, then `C15tReactNativeBootstrap.install(core)` before RN starts. Do not also link separately compiled core/platform products, which would create competing singleton authorities.

The RN workspace `Package.swift` supports a local core path, optionally `C15T_CORE_PATH`. It refuses `C15T_CORE_VERSION` and `C15T_CORE_URL` while remote native distribution is unavailable. That workspace manifest is not included in the npm tarball.

## Use ATT and custom services separately

`C15tApple.tracking` shares the explicit ATT orchestration with RN. It requires the app's usage description and never changes c15t consent. Platform services own foreground/reachability subscriptions; `C15tApple.shutdown()` tears down those subscriptions without clearing consent.

Advanced self-hosted/custom `CoreConfig` installation remains available. Raw `CoreConfig()` uses memory/no transport and is not a production installation recipe. Custom stores must distinguish missing values from operational read failures.
