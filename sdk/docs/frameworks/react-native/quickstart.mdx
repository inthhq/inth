c15t gives your app a native consent prompt, saved preferences and hooks for
reading permissions in React. SwiftUI renders the iOS screens and Compose
renders the Android screens. Choices live in the native engine, so an optional
SDK can check them before JavaScript starts.

## Before you start

You need a React Native app with the New Architecture enabled, or an Expo SDK
57 app with a custom native build. Expo Go cannot load the native module.
The current integration targets RN 0.86.x or 0.87.x, React
`>=19.2.3 <19.3.0`, iOS 16.4 and Android API 24 or later. Check
[compatibility](/docs/frameworks/react-native/platform-support) if you are
upgrading an existing app.

The mobile SDK is currently a private prerelease. Obtain the package tarball
and access to its matching Android Maven artifacts from your maintainer.
[Mobile availability](/docs/guides/mobile-status) tracks distribution and release
scope.

This guide uses an [Inth project](https://inth.com) for policy and consent
records. In your project:

1. Configure the policy for the regions your app serves.
2. Include the categories your app uses, such as measurement and marketing.
3. Copy the project URL and prepare your app's HTTPS privacy-policy URL.

The project URL is public configuration, such as
`https://your-project.inth.app`. It is not an API key. Hosted policy changes
reach the app when it next refreshes policy. [Configuration](/docs/frameworks/react-native/configuration)
covers self-hosted and app-owned native installation.

## Install the package

Run this in your app directory, replacing the path with the tarball you
received:

```sh
npm install /absolute/path/to/c15t-react-native.tgz
```

React Native uses `@c15t/react-native` as a separate package. The web `c15t`
package does not include it.

## Configure the native app

The backend URL belongs in native build configuration. `C15tProvider` attaches
to that installed engine after JavaScript starts.

| App | Native setup |
| --- | --- |
| Expo | Follow [Expo and EAS](/docs/frameworks/react-native/expo) to add the config plugin and build a native app. |
| Bare React Native | Follow [bare setup](/docs/frameworks/react-native/bare) to configure CocoaPods, Maven and native launch metadata. |

Complete the setup for each platform you ship, then return here. Native
configuration changes require a new app binary.

Replace `https://example.com/privacy` with your app's privacy policy. Move the

You do not need to mount `ConsentBanner` or `ConsentDialog` with this setup.
`presentConsentPrompt` and `presentPreferences` open the native screens.

## Gate analytics and other optional work

A consent screen does not stop an SDK that your app already starts. Remove the
vendor's unconditional initialization and subscribe to the permission it needs.
For measurement code owned by React, this hook starts collection on a grant
and calls your cleanup function when permission closes:

<include src="../../shared/examples/react-native-bare/headless-gate.mdx" />

Pass a stable `start` function that returns the vendor's actual stop or disable
operation. Mount the hook under `PrivacyApp`. The tracking variant is only for
a feature that also needs Apple's tracking authorization.

Native analytics and advertising initializers can run before React. Put those
behind [native startup gates](/docs/frameworks/react-native/native-behaviour) as
well. Hiding a React component does not stop a native background service.

## Check that it works

Build the app, then test with a policy that asks for a choice:

1. Open an installation with no saved choice. The native consent prompt appears
   and optional collection stays off.
2. Choose Reject all. The prompt closes and optional collection stays off.
3. Terminate and reopen the app. The refusal remains and the prompt stays
   closed while that choice is valid.
4. Open Privacy settings. Enable measurement and save. The measurement gate
   opens and your integration starts collection.
5. Open Privacy settings again and disable measurement. The gate closes and
   your integration stops collection.

A `committed` presenter outcome confirms that the choice was saved on the
device. Backend delivery can happen later, including after reconnecting.
[Commands and outcomes](/docs/frameworks/react-native/usage) explains that
boundary. Use the [mobile verification guide](/docs/guides/mobile-verify) for
offline, storage-failure and accessibility checks.

## First release scope

The current path includes native stock screens, React hooks and category
commands. App-owned React UI uses the [headless APIs](/docs/frameworks/react-native/headless).
A separate package that excludes native UI, and turnkey typed RN/Expo IAB
bootstrap, are deferred. See [mobile availability](/docs/guides/mobile-status)
for the release scope and [IAB setup](/docs/guides/mobile-iab) for native
CMP configuration.
