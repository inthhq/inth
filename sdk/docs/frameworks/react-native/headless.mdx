Use the headless APIs when consent needs to fit your app's settings screen,
onboarding or design system. React renders your controls, while the native
engine keeps the policy, saved choices and SDK permissions.

## Start with the same native setup

Complete [Expo](/docs/frameworks/react-native/expo) or
[bare RN setup](/docs/frameworks/react-native/bare), then keep one
`ConsentProvider` above your app. If your app owns both the initial prompt and
the standing settings screen, pass `autoPresent={false}` so the provider does
not present the native prompt:

{/* example: fragment */}

```tsx
<ConsentProvider autoPresent={false}>
	<App />
</ConsentProvider>;
```

Your custom flow is then responsible for showing an owed prompt and keeping
preferences reachable. `presentConsentPrompt` and `presentPreferences` still
open the native screens when you call them.

Headless hooks are included in `@c15t/react-native`. The package still links
the stock native UI. A separate UI-free RN distribution is deferred; see
[mobile availability](/docs/guides/mobile-status).

## Read one permission

For a feature that only needs measurement permission, use
`useConsent('measurement')`. It returns `false` while policy is unresolved
and whenever that category is denied. The component subscribes to that
permission, so unrelated snapshot changes do not rerender it.

Use `useConsentDecision('measurement')` when your interface needs to distinguish
`pending` from `denied`. Both keep optional collection off.

## Build a preferences screen with a draft

For a screen that collects several choices and saves them together, stage them
in a draft with `useConsentDraft()`. It uses the same names as the web
preference dialog's draft in `@c15t/react`. Edits stay in JavaScript until you
call `save()`, which records every displayed category in one commit:

<include src="../../shared/examples/react-native-bare/draft-preferences.mdx" />

`displayedCategories` lists the categories the resolved policy puts in scope,
`necessary` first. A category with a saved receipt starts at that choice. One
without a receipt starts at its effective permission. The draft shows the
subject's own choices, so a GPC restriction does not appear as a staged
refusal. `isDirty` tells you whether anything changed. `acceptAll` and
`rejectAll` stage values only; they save nothing.

While the draft has no edits, it follows the saved record. While it has
edits, a category you did not change still takes the newly saved value, so a
save writes back only what the subject changed. A staged value that the record
now holds is no longer an edit. If another surface records a different
decision for a category the subject staged, the newer decision wins: the
category drops its staged value, shows the record, and is listed in
`staleCategories`. Setting that category again clears it from the list.

A save through `useSaveConsents()` with `'all'`, `'none'` or a per-category
object clears the edits the draft held when the save began. An edit made while
a save is pending stays staged. If another decision landed after the save, an
edit made meanwhile that disagrees with the record goes to `staleCategories`
instead.

If the policy or the displayed categories change under an unsaved edit, or
`staleCategories` is not empty, `isStale` turns true and `save()` resolves
`ok: false` with `reason: 'concurrent-change'`, writing nothing. Call `reset()`
and let the subject review again.

A draft save names the snapshot revision the draft was built on, and the native
core refuses it if another screen, or native code, recorded a decision after
that. The draft then reads the new record under the rules above and tries once
more if none of the staged categories was overtaken. Otherwise `save()` resolves
`concurrent-change` with the overtaken categories in `staleCategories`. A
binary built with an older `@c15t/react-native` cannot do this check;
`useC15tBootstrap().commitRevision` reads `false` there, the draft saves with
the JavaScript-side check alone, and development builds log a warning once.

Every component outside a `ConsentDraftProvider` shares one draft, so a Save
button elsewhere on the screen can call `useSaveConsents()()` with no argument,
as on the web. Wrap a screen in `ConsentDraftProvider` to give it a draft of its
own; its `initial` prop sets values for categories that have no receipt yet.

Effective permission is different from an explicit saved choice. An opt-out
policy may allow a category before anyone uses the switch. Read
`snapshot.explicitChoice` when you need to display whether a choice was
recorded. Do not submit a save merely because the initial effective value is
true.

## Handle accept, reject and save failures

Use `useSaveConsents()` for explicit button actions. The function it returns
takes `'all'`, `'none'` or a per-category object, or no argument to save the
current draft, and resolves with a local `CommitResult`; check `ok` before
dismissing your form. This reusable Reject button keeps a retry path on failure:

<include src="../../shared/examples/react-native-bare/commit-results.mdx" />

Use `onSaved` to close your app-owned screen after durable local success.
Pending network delivery does not require leaving the form open. Read
[commands and outcomes](/docs/frameworks/react-native/usage) for the result
fields and presenter APIs.

## Show your own first prompt

`ConsentPrompt` calls its child only while a resolved policy requires an
interaction. The child receives `activeUI`, `promptRequirement` and `actions`.
Use `promptRequirement.kind` to distinguish a consent `choice` from a
`notice`; the `none` case renders the fallback.

For a category choice, wire your Accept, Reject and Save controls to the
corresponding actions and handle their results as above. For a notice,
`dismissNotice()` records acknowledgement. It does not record an optional
consent grant. Keep the policy disclosures and your privacy-policy link in the
custom prompt.

Use `ConsentReady` around UI that needs a resolved policy. Its fallback renders
until `ready` is true and `policyPending` is false. It does not need to wrap the
whole app; necessary features can remain usable while consent is loading.

For a React-owned SDK integration, subscribe to the permission and return

Keep `start` stable, for example as a module-level function. Its cleanup must
stop or disable collection using the vendor's supported API. A hook cannot
reverse a native initializer that ran before JavaScript; disable that path
and use [native startup gates](/docs/frameworks/react-native/native-behaviour)
as well.

The tracking variant combines category permission with platform authorization.
It is for features that require both. It does not ask for authorization.

## Choose a subscription

| API | Use it for |
| --- | --- |
| `useConsent(category)` | One effective permission. |
| `useConsentDecision(category)` | A permission with `pending`, `denied` and `granted` states. |
| `useConsentStatus()` | Readiness, pending policy, active UI and owed prompt. |
| `useConsentSelector(selector, equals?)` | A custom snapshot slice with optional equality. |
| `useSnapshot()` | A screen that needs several snapshot fields, such as scope and restrictions. |
| `useSaveConsents()` | Save `'all'`, `'none'`, a per-category choice, or the current draft. |
| `useConsentDraft()` | Stage several category choices and save them together. |
| `ConsentDraftProvider` | A separate draft for one screen, with defaults for undecided categories. |
| `useDismissNotice()` | Acknowledge a notice without recording a choice. |
| `useIdentify()` | Attach an external id from your account system. |
| `useSetOverrides()` | Pin country, region, language or GPC for testing. |
| `useConsentActions()` | Stable `refresh`, `logout`, `reset` and `requestTrackingAuthorization` commands. |
| `useC15tBootstrap()` | The native protocol and subject bootstrap payload. |
| `ConsentGate` | Render-prop content for an allowed category, with an optional fallback. |
| `ConsentReady` | Render-prop content after native readiness and policy resolution. |
| `ConsentPrompt` | Your initial prompt while an interaction is owed. |
| `useTrackingAuthorization()` | The separate platform tracking status. |
| `useIsTrackingAllowed(category)` | A category permission combined with platform tracking authorization. |

## Check the custom flow

Test both a fresh prompt and reopened settings. Confirm that a refused save
keeps the control's old value, a successful change survives relaunch, and
withdrawal stops optional work. Test larger text, focus, labels and error
announcements as part of your app's accessibility checks.

For IAB, prefer the native presenter for the complete stock flow. The RN
snapshot's served GVL is disclosure data; it does not provide a complete
per-vendor commit API or the committed TC String.
