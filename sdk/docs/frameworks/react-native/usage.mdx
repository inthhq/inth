Use `useSaveConsents()` under `ConsentProvider` when your own controls need to
save a choice. For the stock screens, call `presentConsentPrompt` or
`presentPreferences` and let the native presenter manage the form.

## Save a category choice

`saveConsents({ measurement: true })` records the supplied category choices.
Omitted categories keep their existing receipts. `saveConsents('all')` grants
the resolved policy scope, and `saveConsents('none')` records a necessary-only
choice.

Call them in response to a person's explicit action. Reading an allowed
permission, mounting a provider or resolving policy does not record a choice.
For app-owned controls, follow [Build your own UI](/docs/frameworks/react-native/headless).

## Inspect every local commit

Every `saveConsents` call returns `Promise<CommitResult>`. Check
`result.ok` before closing a form or displaying a saved confirmation. A
resolved promise can still report a refused save.

The button waits for durable local storage. `onSaved` runs only after success,
so its parent can close the screen. A refused or thrown save keeps the screen
open with an error.

| Field | Meaning |
| --- | --- |
| `ok` | Whether the native engine applied and durably stored the action. |
| `reason` | Why a local commit was refused, when `ok` is false. |
| `revision` | The resulting snapshot revision, or null when nothing changed. |
| `confirmed` | The optional categories for which this action recorded receipts. |
| `queued` | The delivery obligation was durably queued. This is not a live queue-length value. |
| `delivered` | The backend accepted the save before the command returned, when reported. |

`ok: true, queued: true` is a successful local save. The app can update its
consent UI and permissions immediately, including offline. Delivery may
happen later. `delivered: true` can coexist with `queued: true`; iOS currently
reports delivery separately rather than setting that flag on the local result.

Common refusals are `policy-pending`, `queue-write-failed`,
`concurrent-change` and invalid intent. Keep the person's form open and
resolve the cause before retrying. A later network error does not reverse a
durable withdrawal. [Offline behavior](/docs/guides/mobile-offline) covers
queued delivery and reconnects.

## Open the native screens

`ConsentProvider` presents the initial prompt by itself when one is owed. Call
these functions for anything else, such as a Privacy settings button, or for
the initial prompt when you pass `autoPresent={false}`. Both take your app's
HTTPS privacy-policy URL:

| Function | Opens |
| --- | --- |
| `presentConsentPrompt(privacyPolicyURL)` | The initial native prompt, only when the policy requires an interaction. |
| `presentPreferences(privacyPolicyURL)` | Standing privacy settings, including when the initial prompt is already answered. |

The [quickstart](/docs/frameworks/react-native/quickstart#keep-privacy-settings-reachable)
shows a settings button.

The returned `ConsentPresenterSession` describes presentation:

| `status` | Meaning |
| --- | --- |
| `presented` | A native session opened. |
| `already-presented` | A session is already open, for example the one the provider presented. Repeated requests reuse it. |
| `not-required` | No prompt is owed. `sessionId` is null. |

Opening a screen is separate from saving a choice. Subscribe with
`onConsentPresenterOutcome(listener)` before presenting, and call the returned
unsubscribe function when your React owner unmounts.

## Handle the final presenter outcome

Each final outcome includes the session ID and snapshot revision:

| `kind` | Meaning |
| --- | --- |
| `committed` | A consent action was saved durably on the device. |
| `acknowledged` | A notice was acknowledged. This is not optional consent. |
| `dismissed` | The screen closed without a new committed choice. |
| `unavailable` | The native host could not complete the session. |

Draft switch changes do not create bridge consent events. React hooks update
from the native committed snapshot.

`closeConsentPresenter(sessionId)` asks native to close that session. An
obsolete ID does nothing. Dirty drafts require confirmation, and a pending
save cannot be closed. Let the stock presenter handle those states instead
of dismissing an overlapping React dialog.

## Other actions

| Action | Use |
| --- | --- |
| `dismissNotice()` | Acknowledge the current notice locally. It sends no consent save. |
| `refresh()` | Resolve policy again and retry pending delivery. It does not record a choice. |
| `identify(externalId)` | Attach the signed-in app identity. |
| `logout()` | Detach that external identity. |
| `reset()` | Clear local consent authority and require a new choice while keeping the c15t subject. |
| `setOverrides(overrides)` | Set QA country, region, language or GPC inputs. |
| `requestTrackingAuthorization()` | Explicitly request Apple's separate tracking authorization where supported. |

Await asynchronous actions and handle their errors. See
[identity and reset](/docs/frameworks/react-native/identity),
[configuration](/docs/frameworks/react-native/configuration) and
[ATT](/docs/frameworks/react-native/iab#keep-att-separate) for the behavior that
applies to each.

Category commands are not a complete IAB vendor-draft interface. Use the native
presenter for purpose/vendor choices, legitimate-interest objections and
Additional Consent. [IAB setup](/docs/guides/mobile-iab) describes that path.
