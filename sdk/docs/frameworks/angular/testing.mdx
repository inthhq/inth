`@c15t/angular/testing` has one Angular CDK component harness per consent
surface. Your TestBed tests use them to click Accept all, toggle a category or
open the dialog without depending on c15t's markup, the same way you test
Angular Material components with their harnesses.

## Install the CDK

The harnesses are built on `@angular/cdk/testing`, an optional peer
dependency of `@c15t/angular`. Install the CDK version that matches your
Angular major if your app does not already use Angular Material or the CDK:

<CommandTabs command="@angular/cdk" mode="install" />

## Write a test

This test renders the banner and dialog under `provideC15t()` with `local()`,
so no request leaves the test, and drives them with `ConsentBannerHarness` and
`ConsentDialogHarness`:

<include src="../../shared/examples/angular/harness-banner-test.mdx" />

Three parts of the setup matter:

- **A policy rule.** With no `policyRules`, `local()` uses the recommended
  rules, and the policy a test gets depends on that pack. The rule in the
  example asks every visitor for an opt-in choice, so the test always gets
  the banner.
- **`await fixture.whenStable()` before the first query.** The consent runtime
  starts after the first render; waiting once lets it pick the banner.
- **`disableAnimation: true`.** Keeps the banner's entrance from fading in,
  so a test reads it as it will look. After a choice the banner leaves the
  page at once, so `getHarnessOrNull` returns `null`.

Assert on `ConsentManager`, not only on the page. `has('marketing')` after
`acceptAll()` shows the choice was recorded, which a closed banner alone does
not.

## Find surfaces that render into the body

The banner, dialog, floating trigger and both IAB surfaces move themselves to
`<body>`, outside your component, so the fixture's own loader cannot see them.
Find them with `TestbedHarnessEnvironment.documentRootLoader(fixture)`, as you
would `MatDialogHarness`.

The widget, the consent gate, `c15t-consent-button` buttons and `c15tSwitch`
switches render where you put them. `TestbedHarnessEnvironment.loader(fixture)`
finds those.

| Harness | Drives | Loader |
| --- | --- | --- |
| `ConsentBannerHarness` | `<c15t-consent-banner>` and the banner in `<c15t-consent-root>` | document root |
| `ConsentDialogHarness` | `<c15t-consent-dialog>` | document root |
| `ConsentDialogTriggerHarness` | `<c15t-consent-dialog-trigger>` | document root |
| `IABConsentBannerHarness` | `<c15t-iab-consent-banner>` | document root |
| `IABConsentDialogHarness` | `<c15t-iab-consent-dialog>` | document root |
| `ConsentWidgetHarness` | `<c15t-consent-widget>`, and the widget inside the dialog | fixture, or `ConsentDialogHarness.getWidget()` |
| `ConsentGateHarness` | `<c15t-consent-gate>` | fixture |
| `ConsentButtonHarness` | `<button c15t-consent-button>` | fixture |
| `SwitchHarness` | `[c15tSwitch]` | fixture, or a surface harness |

A surface harness exists only while the surface shows. Check that a banner is
gone with `getHarnessOrNull`, which returns `null`.

## Harness methods

Every method returns a promise. The action methods click the stock button and
throw an error naming the surface and the action when the policy does not
offer it.

| Harness | Methods |
| --- | --- |
| `ConsentBannerHarness` | `getTitle()`, `getDescription()`, `getPrompt()`, `isBlocking()`, `getVariant()`, `getPosition()`, `getActions()`, `acceptAll()`, `rejectAll()`, `openPreferences()`, `dismiss()` |
| `ConsentDialogHarness` | `getTitle()`, `getDescription()`, `isBlocking()`, `getWidget()`, `close()`, `acceptAll()`, `rejectAll()`, `save()` |
| `ConsentWidgetHarness` | `getCategories()`, `getCategoryTitle(category)`, `getCategorySwitch(category)`, `isCategoryChecked(category)`, `isCategoryDisabled(category)`, `toggleCategory(category)`, `setCategory(category, allowed)`, `getActions()`, `acceptAll()`, `rejectAll()`, `save()` |
| `ConsentDialogTriggerHarness` | `getLabel()`, `openPreferences()` |
| `ConsentGateHarness` | `isPlaceholderShown()`, `getPlaceholderText()`, `canOpenPreferences()`, `openPreferences()`, `getText()`, and the loader methods of a content container |
| `ConsentButtonHarness` | `getText()`, `getAction()`, `isDisabled()`, `click()` |
| `IABConsentBannerHarness` | `getTitle()`, `getDescription()`, `getPurposes()`, `acceptAll()`, `rejectAll()`, `openPreferences()`, `openVendors()` |
| `IABConsentDialogHarness` | `getTitle()`, `getDescription()`, `isBlocking()`, `getSelectedTab()`, `selectTab(tab)`, `getSwitches(filters)`, `close()`, `acceptAll()`, `rejectAll()`, `save()` |
| `SwitchHarness` | `isChecked()`, `isDisabled()`, `getLabel()`, `toggle()`, `check()`, `uncheck()`, `focus()`, `blur()`, `isFocused()` |

`ConsentDialogHarness.close()` presses Escape and records nothing.
`setCategory()` and `toggleCategory()` change the widget's draft only; nothing
is recorded until `save()`. `isCategoryChecked()` reads the draft, so it can
differ from `ConsentManager.has()` before a save.

## Filter harnesses

Each harness has a static `with()` that returns a `HarnessPredicate`. Every
predicate accepts `selector` and `ancestor`. Some harnesses add their own
filters:

| Harness | Filters |
| --- | --- |
| `ConsentBannerHarness` | `title`, `prompt` (`'choice'` or `'notice'`) |
| `ConsentDialogHarness`, `IABConsentBannerHarness`, `IABConsentDialogHarness` | `title` |
| `ConsentDialogTriggerHarness` | `label` |
| `ConsentButtonHarness` | `text`, `action` |
| `SwitchHarness` | `label`, `checked`, `disabled` |

Text filters take a string or a regular expression. Tell several gates apart
with a class you set on each:

{/* example: fragment */}

```ts
const gate = await loader.getHarness(
	ConsentGateHarness.with({ selector: '.video' })
);
```

`ConsentButtonHarness`'s `action` filter reads `data-action`, or a static
`action="accept"` attribute. A button bound with `[action]` and no
`data-action` does not match it; filter by `text` instead.

## Test the consent gate

`ConsentGateHarness` waits one animation frame before it reads the gate, since
the gate fills itself one frame after its first render. `isPlaceholderShown()`
reports the built-in placeholder. A gate with a
`c15tConsentGatePlaceholder` template renders your markup instead, so read it
with `getText()` or your own harness. `openPreferences()` clicks the built-in
placeholder's button, which opens the consent dialog.

## Test the IAB surfaces

The IAB banner and dialog render after the IAB code and the Global Vendor List
load, and `fixture.whenStable()` does not wait for either. Pass the vendor list
inline with `iab: { cmpId, gvl }` so the test makes no request, and poll until
the harness appears. With Vitest:

{/* example: fragment */}

```ts
const banner = await vi.waitFor(async () => {
	const found = await loader.getHarnessOrNull(IABConsentBannerHarness);
	expect(found).not.toBeNull();
	return found!;
});
await banner.acceptAll();
await vi.waitFor(() => expect(consent.iab()?.purposeConsents[1]).toBe(true));
```

The TC string is encoded after the click returns, so wait for
`ConsentManager.iab()` to change before you assert on it.
`IABConsentDialogHarness.getSwitches({ label })` finds a purpose, stack or
special feature switch by the name it shows.
