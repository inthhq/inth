c15t has native Swift and Kotlin SDKs, a React Native adapter and an Expo config
plugin. The mobile SDKs are currently available for private integration testing.
Use the matching artifacts supplied by the maintainer while public publication
is being prepared.

## Choose your app

| Your app | Start here | What you add |
| --- | --- | --- |
| SwiftUI | [Swift quickstart](/docs/frameworks/swift/quickstart) | SwiftPM core, Apple services and optional SwiftUI screens |
| UIKit | [UIKit setup](/docs/frameworks/swift/uikit) | The same Swift products, with a UIKit host |
| Kotlin with Compose | [Android quickstart](/docs/frameworks/android/quickstart) | Core and Android artifacts, plus optional Compose screens |
| React Native | [React Native quickstart](/docs/frameworks/react-native/quickstart) | `@c15t/react-native` and its matching native artifacts |
| Expo | [Expo setup](/docs/frameworks/react-native/expo) | The RN package and config plugin in a custom native build |

Swift and Kotlin apps can use the core and platform services without the stock
UI. React Native apps can draw their own prompt, category preferences and IAB
screens with the hooks and the draft API, although the current RN package still
links the native presenter.

## Obtain the matching artifacts

For Swift, use a source checkout with the root `Package.swift`. The package is
named `c15t`, with library products `C15tCore`, `C15tApple` and
`C15tConsentUI`. It lives in the monorepo. Private Git dependencies use normal
repository authentication; local development can add the checkout in Xcode.
The current source setup does not require a separate Swift repository.

For Android, obtain a versioned Maven repository containing
`com.c15t:c15t-core`, `com.c15t:c15t-android` and, for stock screens,
`com.c15t:c15t-consent-ui`. Keep the three artifacts on one native version.
The Android quickstart shows where that repository belongs in Gradle.

For React Native and Expo, install the supplied `@c15t/react-native` tarball.
Its iOS pod includes the native Swift sources. Its Android bridge resolves the
native version pinned by that package. The npm version and native version can
differ; keep the adapter's selected native version.

Public npm, Maven Central and tagged SwiftPM installation instructions will
replace these private setup steps after publication and clean registry installs
are verified. Do not substitute a similarly named public package.

## First release scope

The implementation includes native category consent, notice acknowledgement,
TCF choices, Additional Consent v2, protected platform storage, SDK gates,
offline policy resources and SwiftUI/Compose presenters. The RN adapter exposes
category commands, hooks and native presenter sessions. The Expo plugin and
bare RN metadata configure category startup and IAB CMP identity and publisher
country during native builds.

An RN app can draw its own banner, category preferences and IAB screens with
`ConsentPrompt`, the draft API and the IAB hooks; see
[Build your own UI](/docs/frameworks/react-native/headless). An RN build that
leaves out the stock native UI is not in this release. RN apps that need IAB
publisher restrictions or custom purposes still use app-owned native
installation.

The [IAB guide](/docs/guides/mobile-iab) explains both setups. Build vendor
decisions with the IAB hooks or the stock presenter, never from the category
API. Custom IAB screens support configurations without publisher restrictions
or Additional Consent providers; with either, use the stock screens.

## Certification and production rollout

c15t's CMP ID is 490. Its existing registration covers web; mobile validation
and Google App certification are separate work. The SDK implementation and a
working demo do not establish those approvals.

Before a production rollout, complete the
[mobile verification checklist](/docs/guides/mobile-verify) with your actual
app, backend, vendor SDKs and delivered binaries. Private local fixture apps
use sample identities and disclosures and are for development only.
