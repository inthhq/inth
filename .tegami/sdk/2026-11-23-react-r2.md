### The React banner survives a failed container download, and removed prompt options warn

- **React, Next.js and TanStack Start:** when the code for the banner's container (Card, Banner or Drawer) fails to download, the banner loads it again a second later, up to three times. Meanwhile a server-rendered banner stays on the page, and a banner that a visitor tapped before the engine loaded shows again instead of staying hidden. The tap is replayed once the container loads.
- **Every framework:** in development, `presentation.prompt.blocking`, `variant` or `position` now logs a warning that names its replacement (`blockUntilChoice` or `container`), since these options do nothing. Banner experiments still run arms whose base presentation carries one.
- **Docs:** the React rendering guide has a new "Custom server rendering" section. If you call `renderToString` yourself, await `preloadContainers()` first. Before you hydrate a page you rendered yourself, await `preloadServerContainer()`.
