Inth is the open standard for cookie banners. It's an open-source cookie consent manager and consent management platform (CMP) for JavaScript. You get a GDPR cookie banner, a preference dialog, and consent-gated scripts for React, Next.js, Vue, Nuxt, Svelte, Astro, TanStack Start, Angular, and plain HTML. Google Consent Mode v2 works through `@inth/integrations`, and IAB TCF through an optional add-on.

**[Docs](https://inth.com/docs)** · **[Hosted on Inth](https://inth.com?utm_source=github&utm_medium=repo_homepage)** · **[Discord](https://c15t.link/discord)**

## Why Inth

- **Consent lives in your code.** The banner ships in your bundle and renders with your app, not from a third-party snippet that loads after your page.
- **Analytics, ads, and pixels follow each visitor's choice.** Ready-made loaders cover 40+ vendors, such as Google Tag Manager, GA4, Meta Pixel, and PostHog.
- **One setup for every region.** Policies decide who sees a banner: opt-in for visitors in the EU, opt-out for some US states, or rules that you write.
- **Server-rendered pages can ship the banner in the first HTML.** Next.js, Nuxt, Astro, TanStack Start, and SvelteKit resolve each visitor's policy on the server, so the banner does not wait for a request from the browser.
- **Standards built in:** Google Consent Mode v2, IAB TCF 2.4, IAB GPP, and Global Privacy Control.
- **Your design or ours.** Use the prebuilt components with a theme system, or build your own UI on headless hooks and composables.
- **Managed policy storage and audit history.** Keep consent records and policies on Inth, or use `testing()` in local development and tests.

## Hosting

[Inth](https://inth.com?utm_source=github&utm_medium=repo_homepage) keeps your policies and consent records. You get policy storage, consent records, audit history, and a dashboard, with no database or server to run. Sign-up is free. Set the project URL from your Inth dashboard as `projectUrl`.

For local development, previews, and tests, `testing()` keeps choices in the browser and sends no consent records. It throws in production builds.

## Example

A Next.js App Router app with the prebuilt banner, the preference dialog, and PostHog held until the visitor allows measurement. Install Inth and the vendor loaders:

```bash
pnpm add @inth/nextjs @inth/integrations
```

Set `NEXT_PUBLIC_INTH_PROJECT_URL` to your Inth project URL in `.env.local`, then add three files:

```ts
// next.config.ts
import { withConsentManifest } from '@inth/nextjs/build'
import type { NextConfig } from 'next'

const nextConfig = {} satisfies NextConfig

// Downloads your policy at build time and finds inth.config.ts
export default withConsentManifest(nextConfig)
```

```ts
// inth.config.ts
import { posthog } from '@inth/integrations/posthog'
import { defineConsentConfig } from '@inth/nextjs'

export default defineConsentConfig({
  scripts: [
    posthog({
      id: 'phc_your_project_key',
      initOptions: { cookieless_mode: 'never' },
      loadMode: 'after-consent',
    }),
  ],
})
```

```tsx
// app/layout.tsx
import {
  ConsentBanner,
  ConsentDialog,
  ConsentDialogLink,
  InthProvider,
} from '@inth/nextjs'
import { resolveConsent } from '@inth/nextjs/server'
import type { ReactNode } from 'react'

import './globals.css'

const RootLayout = ({ children }: { children: ReactNode }) => (
  <html lang="en">
    <body>
      {/* Not awaited: the page renders while consent resolves. */}
      <InthProvider state={resolveConsent()}>
        {children}
        <ConsentBanner />
        <ConsentDialog />
        <footer>
          <ConsentDialogLink>Privacy settings</ConsentDialogLink>
        </footer>
      </InthProvider>
    </body>
  </html>
)

export default RootLayout
```

The layout stays a Server Component. You write no `'use client'` wrapper and need no Inth stylesheet import. The [Next.js quickstart](https://inth.com/docs/frameworks/next/quickstart) walks through each file. The quickstart for each other framework has the same example.

## Integrations

[`@inth/integrations`](./integrations) has a loader for each vendor below. Most wait until the visitor allows the vendor's consent category. A few, such as Google Tag Manager and Mixpanel, load at once and pass the choice to the vendor's own consent API. The [integrations overview](https://inth.com/docs/integrations/overview) shows what each loader does.

- **Tag managers**: Google Tag Manager, Cloudflare Zaraz
- **Analytics**: Google tag (GA4 and Google Ads), Adobe Analytics, Ahrefs Analytics, Amplitude, Clay, Cloudflare Web Analytics, Databuddy, Fathom, FullStory, Gainsight PX, Heap, Hightouch, Hotjar, LogRocket, Lucky Orange, Matomo, Microsoft Clarity, Mixpanel, OneDollarStats, Oracle Eloqua, Pendo, Pirsch, Plausible, PostHog, Promptwatch, RB2B, RudderStack, Rybbit, Segment, Statable, Umami, Vercel Analytics, Vercel Speed Insights
- **Experimentation and personalization**: Adobe Target, Appcues, Dynamic Yield, Optimizely Web Experimentation, Wisepops
- **Default**: Pixel after measurement consent or standalone Forms SDK after functionality consent, with configurable categories and an opt-in always mode for the Pixel ([guide](https://inth.com/docs/integrations/default-com))
- **Ads and pixels**: AdRoll, Meta Pixel, OpenAI Pixel, TikTok Pixel, LinkedIn Insight Tag, LiveIntent, Microsoft UET, Pinterest Tag, Reddit Pixel, Snapchat Pixel, The Trade Desk, Vector, X Pixel
- **Enrichment, email, and SMS**: ActiveCampaign, Attentive, Clearbit, Customer.io, Insider, Klaviyo, Marketo Munchkin, Salesforce Account Engagement
- **Chat and support**: Ada, Intercom, Crisp, Front Chat, Gorgias Chat, Zendesk Messaging
- **Monitoring**: Sentry
- **Embeds**: YouTube and Google Maps, with no extra package

## Develop Inth

The SDK's packages are part of the repository's pnpm workspace. Run these from
the repository root. Bun 1.3.11 must also be installed, because many of the
SDK's scripts still run on it.

```bash
pnpm install
pnpm sdk:dev            # the demo app in apps/playground
pnpm sdk:build          # every library package
pnpm sdk:check-types
pnpm sdk:test           # the library packages' tests
pnpm sdk:lint && pnpm sdk:fmt:check
```

## Security

Do not open a public issue for a security vulnerability. Report it privately through [GitHub's vulnerability reporting](https://github.com/inthhq/inth/security/advisories/new). We examine every valid report.

- Do not share the vulnerability in public forums, issues, or pull requests
- Give the steps to reproduce it and the versions it affects
- Give us time to release a fix before you disclose it
