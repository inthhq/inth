The AppsFlyer helper keeps the SDK stopped until a category allows it, then
starts it and sends Google's DMA consent through
[`setConsentData`](https://dev.appsflyer.com/hc/docs/android-send-consent-for-dma-compliance).
The category defaults to `marketing`. The three consent fields come from the
shared [Consent Mode mapping](/docs/integrations/google-tag#how-categories-map-to-google-consent-types),
so marketing grants them too.

The helper ships in `InthApple`, `inth-android` and
`@inth/react-native/integrations`. Inth adds no AppsFlyer dependency. The web
has no AppsFlyer helper.

## What the helper changes

| Consent | AppsFlyer calls |
| --- | --- |
| Category denied or pending | Stop the SDK, then send consent data |
| Category granted | Send consent data, then resume and start the SDK, once per grant |
| Marketing changes while the category stays granted | Send consent data only |

| `AppsFlyerConsent` field | From |
| --- | --- |
| `isUserSubjectToGDPR` | Your app |
| `hasConsentForDataUsage` | `adUserData` |
| `hasConsentForAdsPersonalization` | `adPersonalization` |
| `hasConsentForAdStorage` | `adStorage` |

### Who supplies `isUserSubjectToGDPR`

Inth's policy model says how the app asks for consent, not which law applies,
so the helper does not guess. Set the flag from your own region logic. If you
cannot tell, `true` is the cautious value: it limits what AppsFlyer passes on.

## Before you start

Complete the [Swift](/docs/frameworks/swift/quickstart),
[Android](/docs/frameworks/android/quickstart) or
[React Native](/docs/frameworks/react-native/quickstart) quickstart, with
`marketing` in your Inth policy and native configuration. Install AppsFlyer
**6.16 to 6.x** through its [iOS](https://dev.appsflyer.com/hc/docs/ios-send-consent-for-dma-compliance),
[Android](https://dev.appsflyer.com/hc/docs/android-sdk-reference-appsflyerconsent)
or [React Native](https://dev.appsflyer.com/hc/docs/rn_cmp) guide: the iOS and
Android SDK 6 and `react-native-appsflyer` 6. This page does not cover
AppsFlyer 7; see [AppsFlyer 7](#appsflyer-7).

Initialize AppsFlyer, but **do not call `start` yourself**. The helper starts
it once consent allows. AppsFlyer requires `stop(false)` before `start` after
a stop, and the helper does both. Do not also turn on
`enableTCFDataCollection`; AppsFlyer prefers manual consent data when both
exist.

## Connect a Swift app

```swift title="AppsFlyerConsentOwner.swift"
import AppsFlyerLib
import InthApple
import InthCore

final class AppsFlyerConsentOwner {
    private let integration: AppsFlyerIntegration

    init(core: ConsentCore, subjectToGDPR: Bool) {
        integration = AppsFlyerIntegration(
            core: core,
            setConsentData: { consent in
                AppsFlyerLib.shared().setConsentData(AppsFlyerConsent(
                    isUserSubjectToGDPR: NSNumber(value: subjectToGDPR),
                    hasConsentForDataUsage: NSNumber(value: consent.adUserData),
                    hasConsentForAdsPersonalization: NSNumber(value: consent.adPersonalization),
                    hasConsentForAdStorage: NSNumber(value: consent.adStorage)
                ))
            },
            setStopped: { AppsFlyerLib.shared().isStopped = $0 },
            start: { AppsFlyerLib.shared().start() }
        )
    }

    func stop() { integration.cancel() }
    func syncAfterReset() { integration.sync() }
}
```

`AppsFlyerConsent` takes `NSNumber?` arguments in Swift, hence the
`NSNumber(value:)` wrappers. Create the owner after configuring
`AppsFlyerLib.shared()` with your dev key and app ID, and keep it for the
app's lifetime. Pass
`category: .measurement` if you treat attribution as measurement.

## Connect an Android app

```kotlin title="AppsFlyerConsent.kt"
import android.content.Context
import com.appsflyer.AppsFlyerConsent
import com.appsflyer.AppsFlyerLib
import com.inth.android.integrations.AppsFlyerIntegration
import com.inth.core.Inth

fun connectAppsFlyerConsent(
	context: Context,
	subjectToGdpr: Boolean,
	onError: (Exception) -> Unit,
): AppsFlyerIntegration {
	val core = checkNotNull(Inth.current) { "Install Inth before connecting AppsFlyer" }
	val appsFlyer = AppsFlyerLib.getInstance()
	return AppsFlyerIntegration(
		core = core,
		setConsentData = { consent ->
			appsFlyer.setConsentData(
				AppsFlyerConsent(subjectToGdpr, consent.adUserData, consent.adPersonalization, consent.adStorage),
			)
		},
		stop = { stopped -> appsFlyer.stop(stopped, context) },
		start = { appsFlyer.start(context) },
		onError = onError,
	)
}
```

Call `AppsFlyerLib.getInstance().init(...)` first, without `start`. Keep the
returned helper on the application.

Copy the checked connection function into `appsflyer-consent.ts`:

Initialize `react-native-appsflyer` with `manualStart: true`, then supply it:

```ts title="appsflyer-vendor.ts"
import appsFlyer, { AppsFlyerConsent } from 'react-native-appsflyer';

import { connectAppAppsFlyer } from './appsflyer-consent';

export const connectAppsFlyerVendor = (
	subjectToGdpr: boolean,
	onError: (error: unknown) => void
) =>
	connectAppAppsFlyer(
		{
			setConsentData: ({ adUserData, adPersonalization, adStorage }) =>
				appsFlyer.setConsentData(
					new AppsFlyerConsent(
						subjectToGdpr,
						adUserData,
						adPersonalization,
						adStorage
					)
				),
			start: () => appsFlyer.startSdk(),
			stop: (isStopped) => appsFlyer.stop(isStopped),
		},
		onError
	);
```

React Native runs this after native startup. Use AppsFlyer's Expo config
plugin and a development build; Expo Go cannot load either native module.

## AppsFlyer 7

AppsFlyer 7 is a breaking release, and the snippets above do not work with it:

- `react-native-appsflyer` 7 removed `AppsFlyerConsent` and `initSdk`, takes
  one object per call (`stop({ shouldStop })`, `setConsentData({ ... })`), and
  needs React Native's New Architecture.
- The Android SDK 7 `start()` takes no `Context`, and `AppsFlyerConsent` moved
  to `com.appsflyer.share`.
- On iOS, Android and React Native, SDK 7 starts a session only when `start`
  runs after its session-ready listener has fired. Without the listener,
  `start` does nothing.

The Inth helper's calls (`setConsentData`, `stop`, `start`) map onto SDK 7,
but its `start` call can come before the session is ready, and coordinating
the two is untested. Stay on AppsFlyer 6 with this helper for now. See
AppsFlyer's [Android](https://dev.appsflyer.com/hc/docs/migrate-android-sdk-to-v7)
and [iOS](https://dev.appsflyer.com/hc/docs/migrate-ios-sdk-to-v7) migration
guides and the [React Native 7 release notes](https://github.com/AppsFlyerSDK/appsflyer-react-native-plugin/releases/tag/v7.0.2).

## Handle reset and teardown

`sync()` reapplies current consent and starts AppsFlyer again if allowed, so
call it only after you have reset AppsFlyer. Teardown (`stop()`, `close()` or
`disconnect()`) stops the SDK. Stopping does not delete data AppsFlyer already
received.

On withdrawal, the helper makes both calls, stop and the denied consent
data, even if one of them fails, and reports the failure to `onError`.

## Check the integration

1. Launch with no saved choice. Confirm AppsFlyer reports stopped and sends no
   launch.
2. Grant marketing. Turn on AppsFlyer's debug log and confirm `consent_data`
   shows `ad_user_data_enabled` and `ad_personalization_enabled` as `true`,
   then a launch.
3. With `category` set to measurement, grant measurement, then change
   marketing. Confirm consent data changes without a second launch.
4. Withdraw. Confirm AppsFlyer stops.

The helper tests cover start order, withdrawal during start, a failing stop
call and marketing-only changes with recorded calls. They were not run
against the AppsFlyer SDK. The snippets were checked against these versions:

| Platform | Version | How |
| --- | --- | --- |
| React Native | `react-native-appsflyer` 6.18.0 | Type-checked against the package's published types |
| Android | `af-android-sdk` 6.18.3 | Method signatures read from the published AAR |
| iOS | AppsFlyerLib 6.18.1 | Initializer and method signatures read from the published framework's Swift interface |
