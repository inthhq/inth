The bundled AppsFlyer helper in `InthApple`, `inth-android`, and `@inth/react-native/integrations` keeps AppsFlyer stopped until the visitor grants its category, `marketing` by default, then sends Google DMA consent via [`setConsentData`](https://dev.appsflyer.com/hc/docs/android-send-consent-for-dma-compliance) and starts the SDK. Your app installs AppsFlyer separately. There is no web helper.

## What the helper changes

| Consent | AppsFlyer calls |
| --- | --- |
| Category denied or pending | Stop the SDK, then send denied consent data |
| Category granted | Send consent data, then resume and start the SDK once per grant |
| Marketing changes while category stays granted | Send consent data only |

DMA fields come from the [Consent Mode mapping](/docs/integrations/google-tag#how-categories-map-to-google-consent-types):

| `AppsFlyerConsent` field | Source |
| --- | --- |
| `isUserSubjectToGDPR` | Your app |
| `hasConsentForDataUsage` | `adUserData` |
| `hasConsentForAdsPersonalization` | `adPersonalization` |
| `hasConsentForAdStorage` | `adStorage` |

Supply `isUserSubjectToGDPR` from your own region logic because Inth's policy model controls how you prompt, not which law applies. If unknown, `true` is the safer value because it restricts what AppsFlyer shares.

## Before you start

Complete the [Swift](/docs/frameworks/swift/quickstart), [Android](/docs/frameworks/android/quickstart), or [React Native](/docs/frameworks/react-native/quickstart) quickstart and add `marketing` to your Inth policy and native config. Install AppsFlyer **6.16 to 6.x** using its [iOS](https://dev.appsflyer.com/hc/docs/ios-send-consent-for-dma-compliance), [Android](https://dev.appsflyer.com/hc/docs/android-sdk-reference-appsflyerconsent), or [React Native](https://dev.appsflyer.com/hc/docs/rn_cmp) guide. For SDK 7, see [AppsFlyer 7](#appsflyer-7).

Initialize AppsFlyer without calling `start`. The helper calls `stop(false)` before `start` when resuming after a stop. Leave `enableTCFDataCollection` disabled because AppsFlyer prefers manual consent data when both exist.

## Connect a Swift app

Configure `AppsFlyerLib.shared()` with your dev key and app ID, then create and retain `AppsFlyerConsentOwner` for the app lifetime. Pass `category: .measurement` if you classify attribution as measurement:

```swift title="AppsFlyerConsentOwner.swift"
import AppsFlyerLib
import InthApple
import InthCore

final class AppsFlyerConsentOwner {
    private let integration: AppsFlyerIntegration

    init(core: ConsentCore, subjectToGDPR: Bool) {
        integration = AppsFlyerIntegration(
            core: core,
            setConsentData: { consent in
                AppsFlyerLib.shared().setConsentData(AppsFlyerConsent(
                    isUserSubjectToGDPR: NSNumber(value: subjectToGDPR),
                    hasConsentForDataUsage: NSNumber(value: consent.adUserData),
                    hasConsentForAdsPersonalization: NSNumber(value: consent.adPersonalization),
                    hasConsentForAdStorage: NSNumber(value: consent.adStorage)
                ))
            },
            setStopped: { AppsFlyerLib.shared().isStopped = $0 },
            start: { AppsFlyerLib.shared().start() }
        )
    }

    func stop() { integration.cancel() }
    func syncAfterReset() { integration.sync() }
}
```

## Connect an Android app

Call `AppsFlyerLib.getInstance().init(...)` without `start`, then connect and retain the helper on your `Application`:

```kotlin title="AppsFlyerConsent.kt"
import android.content.Context
import com.appsflyer.AppsFlyerConsent
import com.appsflyer.AppsFlyerLib
import com.inth.android.integrations.AppsFlyerIntegration
import com.inth.core.Inth

fun connectAppsFlyerConsent(
	context: Context,
	subjectToGdpr: Boolean,
	onError: (Exception) -> Unit,
): AppsFlyerIntegration {
	val core = checkNotNull(Inth.current) { "Install Inth before connecting AppsFlyer" }
	val appsFlyer = AppsFlyerLib.getInstance()
	return AppsFlyerIntegration(
		core = core,
		setConsentData = { consent ->
			appsFlyer.setConsentData(
				AppsFlyerConsent(subjectToGdpr, consent.adUserData, consent.adPersonalization, consent.adStorage),
			)
		},
		stop = { stopped -> appsFlyer.stop(stopped, context) },
		start = { appsFlyer.start(context) },
		onError = onError,
	)
}
```

```ts title="appsflyer-vendor.ts"
import appsFlyer, { AppsFlyerConsent } from 'react-native-appsflyer';

import { connectAppAppsFlyer } from './appsflyer-consent';

export const connectAppsFlyerVendor = (
	subjectToGdpr: boolean,
	onError: (error: unknown) => void
) =>
	connectAppAppsFlyer(
		{
			setConsentData: ({ adUserData, adPersonalization, adStorage }) =>
				appsFlyer.setConsentData(
					new AppsFlyerConsent(
						subjectToGdpr,
						adUserData,
						adPersonalization,
						adStorage
					)
				),
			start: () => appsFlyer.startSdk(),
			stop: (isStopped) => appsFlyer.stop(isStopped),
		},
		onError
	);
```

JavaScript connects after native startup. Expo requires AppsFlyer's config plugin and a custom native build, not Expo Go.

## AppsFlyer 7

Stay on AppsFlyer 6 with this helper for now. AppsFlyer 7 breaks the snippets above:

- `react-native-appsflyer` 7 removes `AppsFlyerConsent` and `initSdk`, switches to object arguments like `stop({ shouldStop })` and `setConsentData({ ... })`, and requires React Native's New Architecture.
- Android SDK 7 drops `Context` from `start()` and moves `AppsFlyerConsent` to `com.appsflyer.share`.
- On all three platforms, SDK 7 starts a session only when `start` runs after its session-ready listener fires, and coordinating that with the Inth helper is untested.

See AppsFlyer's [Android](https://dev.appsflyer.com/hc/docs/migrate-android-sdk-to-v7) and [iOS](https://dev.appsflyer.com/hc/docs/migrate-ios-sdk-to-v7) v7 migration guides and the [React Native 7 release notes](https://github.com/AppsFlyerSDK/appsflyer-react-native-plugin/releases/tag/v7.0.2).

## Handle reset and teardown

Call `syncAfterReset()` on Swift, `sync()` on Android, or `await appsFlyerConsent.sync()` on React Native only after resetting AppsFlyer, because `sync()` restarts the SDK when allowed. Calling `stop()`, `close()`, or `disconnect()` stops the SDK without deleting previously sent data. On withdrawal, Inth runs both stop and denied consent updates even if one throws, reporting errors to `onError`.

## Check the integration

1. Launch with no saved choice. Confirm AppsFlyer reports stopped and sends no launch.
2. Grant `marketing`. Check AppsFlyer debug logs for `consent_data` with `ad_user_data_enabled` and `ad_personalization_enabled` set to `true`, followed by a launch.
3. With `category` set to `measurement`, grant `measurement` and then toggle `marketing`. Confirm consent data updates without a second launch.
4. Withdraw consent. Confirm AppsFlyer stops.

Checked against `react-native-appsflyer` `6.18.0`, `af-android-sdk` `6.18.3`, and `AppsFlyerLib` `6.18.1`. Complete [mobile verification](/docs/guides/mobile-verify) on real devices.
