Gate Amplitude Browser SDK 2 on [web consent](#web), or sync Amplitude Analytics opt-out in [Swift, Kotlin, React Native, and Expo apps](#mobile).

## Web

The `amplitude` helper blocks Amplitude Browser SDK 2 and keeps `window.amplitude` undefined until the visitor grants `measurement` consent. On withdrawal, Inth calls `amplitude.setOptOut(true)`, leaves the SDK mounted, and reloads the page by default.

### Configure Amplitude

Remove any existing Amplitude snippet or `init` call, then install `@inth/integrations`:

{/* example: fragment */}

```ts title="src/consent-scripts.ts"
import { amplitude } from '@inth/integrations/amplitude';

export const scripts = [amplitude({ apiKey: 'YOUR_PROJECT_API_KEY' })];
```

### Options

| Option | Default | Behavior |
| --- | --- | --- |
| `apiKey` | Required | Project API key passed to `amplitude.init`. Trimmed automatically. Blank values log an error and skip loading. |
| `initOptions` | `{}` | Browser SDK 2 options passed as the second argument to `init`. Must be JSON-serializable. |
| `scriptUrl` | `https://cdn.amplitude.com/libs/analytics-browser-2.44.4-min.js.gz` | Loader URL override. Pins Browser SDK 2 version `2.44.4`. Blank values use the default. |

### Loading and revocation

`amplitude` gates on `measurement`. On first grant, Inth creates the Browser SDK 2 queue stub, queues `init(apiKey, initOptions)` and `setOptOut(false)` to clear any opt-out cookie left by an earlier revocation, and loads the SDK.

On withdrawal, Inth calls `amplitude.setOptOut(true)` and keeps the script mounted because removing the tag does not stop the running client. Regranting before reload calls `setOptOut(false)` on the existing SDK without loading a second copy.

### Verify Amplitude

Filter DevTools Network by `cdn.amplitude.com`. Allow `measurement` and confirm `analytics-browser-2.44.4-min.js.gz` loads and a test event reaches Amplitude. Withdraw `measurement`, then allow it again on a reloaded page and confirm events resume.

## Mobile

The bundled Amplitude helper in `InthApple`, `inth-android`, and `@inth/react-native/integrations` syncs Analytics opt-out with Inth's `measurement` category by default. Pending or denied permission enables opt-out, and a grant disables opt-out. Your app installs Amplitude separately. Swift and Kotlin set the native `optOut` property, while React Native calls `setOptOut`.

### Before you start

Complete the [Swift](/docs/frameworks/swift/quickstart), [Android](/docs/frameworks/android/quickstart), or [React Native](/docs/frameworks/react-native/quickstart) quickstart and add `measurement` to your native config and Inth policy. See mobile availability for [Swift](/docs/frameworks/swift/availability), [Android](/docs/frameworks/android/availability), or [React Native](/docs/frameworks/react-native/availability).

Install the current [iOS Swift](https://amplitude.com/docs/sdks/analytics/ios/ios-swift-sdk), [Android Kotlin](https://amplitude.com/docs/sdks/analytics/android/android-kotlin-sdk), or [React Native](https://amplitude.com/docs/sdks/analytics/react-native/react-native-sdk) Analytics SDK, not the legacy maintenance library. Initialize Amplitude with `optOut` enabled and configure automatic tracking, ad IDs, location, and session replay separately. For strict startup gating, defer initialization behind a [native startup gate](/docs/frameworks/react-native/native-behaviour) because a JS helper cannot block an earlier native initializer. Expo requires a custom native build, not Expo Go.

### Connect a Swift app

Create Amplitude with `optOut: true`, then construct and retain `AmplitudeConsentOwner` on every launch because Amplitude Swift does not persist `optOut`:

```swift title="AmplitudeConsentOwner.swift"
import AmplitudeSwift
import InthApple
import InthCore

final class AmplitudeConsentOwner {
    private let integration: AmplitudeIntegration

    init(core: ConsentCore, amplitude: Amplitude) {
        integration = AmplitudeIntegration(core: core) { amplitude.optOut = $0 }
    }

    func stop() { integration.cancel() }
    func syncAfterReset() { integration.sync() }
}
```

### Connect an Android app

Create Amplitude with `optOut = true`, then connect and retain the helper on your `Application`:

```kotlin title="AmplitudeConsent.kt"
import com.amplitude.android.Amplitude
import com.inth.android.integrations.AmplitudeIntegration
import com.inth.core.Inth

fun connectAmplitudeConsent(amplitude: Amplitude, onError: (Exception) -> Unit): AmplitudeIntegration {
	val core = checkNotNull(Inth.current) { "Install Inth before connecting Amplitude" }
	return AmplitudeIntegration(
		core = core,
		setOptOut = { amplitude.optOut = it },
		onError = onError,
	)
}
```

Both native helpers set `optOut` on the consent-publishing thread while Amplitude reads `optOut` on its own event queue with no ordering guarantee. Guard your own event calls on current permission so Amplitude does not process events fired during withdrawal under the prior value.

### Connect React Native or Expo

Copy the connection function into `amplitude-consent.ts`:

<include src="../shared/examples/react-native-bare/rn-amplitude-integration.mdx" />

Connect the modular API after initializing that Amplitude instance and retain the handle for the app lifetime:

{/* example: fragment */}

```ts
import { setOptOut } from '@amplitude/analytics-react-native';

const amplitudeConsent = connectAppAmplitude(
	{ setOptOut },
	reportAnalyticsError
);
await amplitudeConsent.ready;
```

For multiple projects, pass the target instance's `setOptOut` method through a closure instead of connecting the default singleton. Report automatic update failures in `onError`, and handle rejections from `ready`, `sync()`, and `disconnect()` at their call sites.

### Handle reset and teardown

After an Amplitude reset completes, call `syncAfterReset()` on Swift, `sync()` on Android, or `await amplitudeConsent.sync()` on React Native to reapply permission without recording a new choice. For final teardown, call `stop()`, `close()`, or `await amplitudeConsent.disconnect()` to detach and enable opt-out without logging the user out or rotating identity.

Opt-out stops collection of new covered events, but previously queued events can still upload and already-uploaded data requires Amplitude's retention or deletion controls.

### Verify your app

1. Launch with no saved choice and after Reject all. Confirm opt-out stays enabled.
2. Grant `measurement` and track a test event. Confirm it arrives.
3. Withdraw `measurement` and confirm Amplitude drops new events.
4. Relaunch after grant and refusal, toggle an unrelated category to confirm no extra opt-out call runs, then reset Amplitude and call `sync()`.

Checked against `@amplitude/analytics-react-native` `1.13.1`, `com.amplitude:analytics-android` `1.37.1`, and `AmplitudeSwift` `1.20.0`. Complete mobile verification for [Swift](/docs/frameworks/swift/verify), [Android](/docs/frameworks/android/verify), or [React Native](/docs/frameworks/react-native/verify) on real devices.
