The `optimizelyWeb` helper waits for `experience` consent before loading the Optimizely Web Experimentation or Personalization snippet. Until then, Inth defines no `window.optimizely` global and makes no Optimizely requests. On withdrawal, Inth removes the snippet and reloads the page because a running SDK cannot be unloaded.

## Configure Optimizely

In Optimizely, open **Settings > Implementation** and copy the project number before `.js` in the snippet URL. Use one Optimizely snippet per page, and remove the original snippet and any tag-manager copy so Inth controls when it loads.

## Options

| Option | Default | Behavior |
| --- | --- | --- |
| `projectId` | Required | Public project number as a string or safe integer. Inth trims surrounding whitespace; use a string above `Number.MAX_SAFE_INTEGER`. Missing, blank, nonnumeric, or unsafe values log an error and skip loading. |
| `category` | `'experience'` | Consent category or condition required before loading, such as `'measurement'` or `{ and: ['experience', 'measurement'] }`. |
| `scriptSrc` | `https://cdn.optimizely.com/js/<projectId>.js` | Custom snippet or proxy URL. `projectId` is still required, blank overrides use the default, and this does not proxy the SDK's other requests. |
| `nonce` | None | CSP nonce for the loader element, trimmed. You can also set the nonce on your consent provider. |

Optimizely leaves cookie classification to the site owner. `optimizelyWeb` defaults to `experience` because the snippet alters page experiences. Pass `{ and: ['experience', 'measurement'] }` if your policy also requires measurement consent.

## Loading and revocation

### Page flicker

After consent, Inth inserts the loader into `<head>` with `async: false`. Optimizely activates configured experiments when the snippet runs. The helper does not call `sendEvents`, start a second SDK, or replace an existing `window.optimizely`.

Optimizely recommends a synchronous snippet at the top of `<head>` and advises against tag managers. A runtime-inserted script with `async: false` does not block HTML parsing, so visitors can see the original page before Optimizely applies a variation. Plan experiments for that flicker and for visitors who refuse consent.

This helper has no early-load or event-holding mode. Optimizely's `holdEvents` API delays dispatch, but the SDK still runs and queues events in `localStorage`, and `sendEvents` releases queued events from earlier pages.

### Revocation

Keep `reloadOnConsentRevoked` enabled. When a visitor revokes the mapped category or disables the Optimizely vendor, Inth removes the loader and reloads after pending saves finish.

- **Removing the element does not stop the SDK.** A running SDK keeps applying variations and sending events until unload, and a browser can finish executing an in-flight download after removal.
- **No runtime stop API exists.** Optimizely documents `disable` only for calls before the snippet loads, and `holdEvents` leaves local collection running.
- **Direct loader and policy changes.** Standalone `createScriptLoader` removes elements without reloading, so your app must persist the denial and reload. Expiry or policy updates also do not trigger visitor-action reloads.

## Persistent Optimizely opt-out

For a deliberate persistent opt-out, import `optOutOptimizely` from `@inth/integrations/optimizely` and call `optOutOptimizely()`. It sends `window.optimizely.push({ type: 'optOut', isOptOut: true })` to an existing SDK or queue and does nothing if neither exists.

Optimizely stores this choice in the 10-year `optimizelyOptOut` cookie. Granting consent again in Inth does not clear it, so `optimizelyWeb` never calls `optOutOptimizely` on ordinary revocation. The command returns no promise and does not undo active page changes; keep page reload enabled.

To reverse an explicit opt-out after the visitor grants consent, follow Optimizely's [cookie implementation guidance](https://support.optimizely.com/hc/en-us/articles/22060116282509-Cookie-implementation-options): delete `optimizelyOptOut` or set it to `false` with its existing domain and path, then reload or navigate to a page where Inth allows the snippet. Optimizely notes that an opt-in command alone cannot restart a snippet blocked by `optimizelyOptOut`; your app must reset the cookie.

## Cookies and localStorage

Optimizely's [storage reference](https://docs.optimizely.com/web-experimentation/docs/cookies-and-localstorage-in-snippets) documents these first-party cookies; browser policies can shorten lifetimes:

| Cookie | Documented lifetime | Purpose |
| --- | --- | --- |
| `optimizelyEndUserId` | Six months from last visit, configurable | Visitor identifier. |
| `optimizelySession` | Six months | New or returning session detection. |
| `optimizelyRedirectData` | Five seconds | Data passed across redirect experiments. |
| `optimizelyDomainTestCookie` | Removed after test | Domain detection. |
| `optimizelyOptOut` | Ten years | Persistent opt-out. `optimizelyWeb` never sets this cookie. |

The SDK stores events, assignments, profiles, and pending requests under `localStorage` keys prefixed with `optimizely_data$$`, followed by the visitor ID, namespace, and names such as `events`, `event_queue`, `variation_map`, `session_state`, `visitor_profile`, `layer_states`, `layer_map`, `tracker_optimizely`, `pending_events`, or `contextual_mab`.

Cross-origin tracking can sync through an account-specific `cdn.optimizely.com` origin. Edge Delivery can add six-month `OPTY$$...$$VPROF` and `OPTY$$...$$VMAP` cookies, though this helper loads the browser snippet rather than an Edge Delivery worker. Sampled Real User Monitoring uses session cookies on `rum.optimizely.com`, including `AWSELB`, `AWSELBCORS`, and `optimizelyRumLB`.

Reloading keeps existing storage. Inspect exact names and domains in DevTools and add them to `clearOnRevocation`. Origin cleanup cannot delete storage on Optimizely-owned origins. Do not read Optimizely keys as an app API; their formats can change.

## Verify Optimizely

Use a test project in a clean browser profile and filter DevTools Network by `optimizely.com`:

1. Deny consent and confirm no snippet loads and `window.optimizely`, Optimizely cookies, and `optimizely_data$$` keys are absent.
2. Grant the mapped category and confirm `<projectId>.js` loads and `typeof window.optimizely.get === 'function'`. Verify experiment targeting and events in Optimizely.
3. Disable the Optimizely vendor inside an allowed category and confirm the reload blocks the snippet.
4. Grant consent again to confirm ordinary revocation did not set `optimizelyOptOut`. If you use `optOutOptimizely`, also test clearing the cookie and reloading before expecting experiments to resume.
