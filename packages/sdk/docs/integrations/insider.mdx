The `insiderTag` helper waits for `marketing` consent before creating `InsiderQueue` or loading `ins.js`. On grant, it queues `user` with `gdpr_optin: true`, optional `currency`, `pageType`, and `init`, then inserts the loader. On withdrawal, it queues `gdpr_optin: false`, `{ type: 'other' }`, and `init`, then removes the loader.

## Configure Insider One

Get your public `partnerName` and `partnerId` from Insider and enable Web SDK integration. Remove existing Insider tags, tag-manager copies, and legacy `window.insider_object` code. Keep the tag off pages handling payment card data.

## Options

| Option | Default | Behavior |
| --- | --- | --- |
| `partnerName` | Required | Public partner name, validated as one lowercase DNS label for `<partnerName>.api.useinsider.com`. Invalid values log `insiderTag: missing or invalid partnerName` and load nothing. |
| `partnerId` | Required | Public partner ID, trimmed and URL-encoded. Blank values log `insiderTag: missing or invalid partnerId` and load nothing. |
| `user` | Omitted | Complete current user attributes for grant, including checkout IDs and `custom`. Non-JSON values log `insiderTag: user must be JSON-serializable` and load nothing. |
| `currency` | Omitted | Non-blank currency string such as `'GBP'`, queued as-is before the page and `init`. Invalid values log `insiderTag: currency must be a non-blank string` and load nothing. |
| `pageType` | `{ type: 'other' }` | Complete page definition with required `value` fields. Purchases require a durable per-order guard. |
| `category` | `'marketing'` | Consent condition controlling queue creation, loading, and `gdpr_optin`. Set `'experience'` for personalization accounts. |

Invalid options do not throw; the helper returns a non-loading script while keeping Insider listed in the preference dialog.

## Supply user and currency

Pass the complete current user's attributes in `user`. The helper copies `user` at call time, sets `gdpr_optin: true` after your fields so user data cannot override consent, and sends `{ gdpr_optin: true }` when omitted.

Match Insider's types: strings for `email`, E.164 `phone_number`, and `uuid`; number for `age`; boolean for `email_optin`; and string values inside `custom` for Identity Resolution Management IDs. Logging out does not reset Insider's browser ID, so pass guest checkout identifiers in `user` before a guest purchase `init`.

<include src="../shared/examples/javascript/insider-current-user.mdx" />

Multi-currency sites must pass `currency` because Insider retains earlier user and currency values across `init` calls. The helper does not watch login, logout, currency, or route changes; rebuild the configuration before a new registration or page load.

## Define the page context

| `type` | `value` |
| --- | --- |
| `'home'` | Optional `{ custom }`. |
| `'other'` | Optional `{ name, custom }`. |
| `'category'` | `{ breadcrumb: string[] }`. |
| `'product'` | `{ id, name, taxonomy, unit_price, unit_sale_price, url, product_image_url }`. |
| `'cart'` | `{ total, items, shipping_cost? }`, each item with product fields plus `quantity`. |
| `'purchase'` | `{ order_id, total, items, shipping_cost? }`, each item with product fields plus `quantity`. Requires a per-order guard. |

Products and items also accept optional `brand`, `description`, `gtin`, `sku`, string `identifier_exists`, `locale`, `google_title`, `gender`, string `omnibus_price`, `groupcode`, `color`, `size`, numeric `stock`, and `custom`.

<include src="../shared/examples/javascript/insider-product.mdx" />

Page values pass through as literal JSON, including objects shaped like `kind: 'inth.runtime-value'`; `Date` becomes a string and `undefined` drops.

For SPA navigation, push `user` with `gdpr_optin` explicitly set, since missing values default to `true`, then `currency`, the new page, and `init`, only while consent and the vendor switch allow it. See Insider's [Web SDK guide](https://academy.insiderone.com/docs/insider-web-sdk-integration-guide).

### Prevent duplicate purchases

**Add a durable backend per-order guard before using `type: 'purchase'`.** The helper does not deduplicate `order_id`, and Insider's [confirmation-page guide](https://academy.insiderone.com/docs/integrate-insider-into-your-confirmation-page) forbids repeating purchases on refresh, Back navigation, or a new tab.

Atomically claim the completed `order_id` in your backend before rendering. Emit `type: 'purchase'` only for the winning request, and return `{ type: 'other' }` on later requests, reloads, regrants, and SPA navigations. If you cannot enforce this, send `'other'`.

## Loading, revocation, and storage

On grant, Inth inserts `https://<partnerName>.api.useinsider.com/ins.js?id=<partnerId>` async in `<head>`. Before grant, it creates no globals, requests, or storage.

On category or vendor withdrawal, Inth pushes `{ type: 'user', value: { gdpr_optin: false } }`, `{ type: 'other' }`, and `{ type: 'init' }` without resending `user` or `currency`, then removes the loader. Sending `{ type: 'other' }` prevents replaying a prior purchase. `gdpr_optin: false` blocks non-cookieless campaigns and messages, but the withdrawal `init` can send an Other Page View and cannot unload running code. Keep `reloadOnConsentRevoked` enabled.

After consent, Insider can write cookies and Web Storage such as `spUID`, `ins-current-currency`, and `ins-cart-product-list`. Inspect DevTools Application for your account and add observed keys to `clearOnRevocation`.

## Verify Insider One

In a private window with an opt-in policy, filter Network by `useinsider.com`:

1. Before grant and after reject and reload, confirm no requests fire and `window.InsiderQueue` is `undefined`.
2. Grant consent and confirm `ins.js` loads with `user`, `currency`, page, and `init` queued in order. Verify profile, currency, and guest checkout inside Insider, since placeholder partners can return HTTP 200 HTML error pages.
3. Withdraw the category or vendor switch and confirm the reloaded page makes no Insider requests.
