The `plausibleAnalytics` helper keeps Plausible Analytics off the page and `window.plausible` undefined until `measurement` is granted. It sends no consent signal to Plausible. On withdrawal, Inth removes the script element and reloads the page by default.

## Configure Plausible Analytics

Copy the script ID from your Plausible snippet, the part inside `pa-<id>.js`. Sites using the legacy domain-based snippet can pass `domain` instead of `scriptId`.

<CommandTabs command="@inth/integrations" mode="install" />

{/* example: fragment */}

```ts title="src/consent-scripts.ts"
import { plausibleAnalytics } from '@inth/integrations/plausible-analytics';

export const scripts = [plausibleAnalytics({ scriptId: 'YOUR_SCRIPT_ID' })];
```

## Options

| Option | Default | Behavior |
| --- | --- | --- |
| `scriptId` | None | Script ID for `pa-<scriptId>.js`. Takes precedence over `domain` and `extension`. |
| `domain` | None | Legacy site domain, set as `data-domain`. If both `scriptId` and `domain` are blank, the helper logs an error and skips loading. |
| `extension` | None | Legacy script extension or array, such as `['file-downloads', 'outbound-links']`, joined into `script.<extensions>.js`. Ignored when `scriptId` is set. |
| `customProperties` | None | Properties sent with each page view. |
| `endpoint` | None | Custom event endpoint. With `domain`, also sets `data-api`. |
| `fileDownloads` | None | `{ fileExtensions?: string[] }` for file download tracking. |
| `hashBasedRouting` | None | `true` tracks hash-based routes. |
| `autoCapturePageviews` | None | `false` disables automatic page views. |
| `captureOnLocalhost` | None | `true` records visits on `localhost`. |
| `scriptUrl` | `https://plausible.io/js/pa-<scriptId>.js`, or `https://plausible.io/js/script.js` with `domain` | Loader URL override. |

The helper writes `customProperties`, `endpoint`, `fileDownloads`, `hashBasedRouting`, `autoCapturePageviews`, and `captureOnLocalhost` to `window.plausible.o`, which the `scriptId` loader reads. With the legacy loader, select features through `extension`.

## Loading and revocation

`plausibleAnalytics` uses the `measurement` category. On grant, the helper defines a queueing `window.plausible` stub if one does not already exist, then loads the tracker so calls queued before load still run.

On revocation, the helper removes the script element and calls no Plausible API. Plausible sets no cookies, but Inth still waits for `measurement` permission before loading it.

## Verify Plausible Analytics

1. Allow `measurement` and confirm `pa-<scriptId>.js`, or `script.js` with `data-domain` for legacy snippets, loads in DevTools Network.
2. Confirm a page view request goes to `plausible.io/api/event` or your custom `endpoint`.
3. Because `window.plausible` remains defined after revocation, check `measurement` permission before sending custom events.
