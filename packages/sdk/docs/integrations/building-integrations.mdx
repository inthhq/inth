Write an Inth `Script` configuration to gate a vendor that has no `@inth/integrations` helper, or to sync consent with an SDK your app already imports. Check the [integration list](/docs/integrations/overview) first to confirm no built-in helper exists.

## Define a script

Give the script a stable `id`, a consent `category`, and a `src` URL. Import `Script` from your framework package, such as `@inth/react`, or `@inth/sdk/engine` in plain JavaScript:

```ts title="src/consent-scripts.ts"
import type { Script } from '@inth/react';

const exampleAnalytics: Script = {
	id: 'example-analytics',
	category: 'measurement',
	src: 'https://analytics.example.com/sdk.js',
	onLoad() {
		// Initialize the vendor here.
	},
	onError({ error }) {
		console.error('Analytics SDK failed to load', error);
	},
};

export const scripts = [exampleAnalytics];
```

Inth appends `<script>` only while `measurement` is allowed. Register `scripts` with your provider using any vendor guide, such as [Ahrefs Analytics](/docs/integrations/ahrefs-analytics).

## Script fields

| Field | Default | Behavior |
| --- | --- | --- |
| `id` | Required | Stable identifier tracking the script across renders. |
| `category` | Required | Category name, or boolean condition such as `{ or: ['measurement', 'marketing'] }`, `{ and: [...] }`, or `{ not: '...' }`. |
| `src` / `textContent` | None | Provide one, unless `callbackOnly` is `true` or returns `true`. |
| `vendor` | None | Vendor slug for per-vendor switches inside an allowed category. |
| `callbackOnly` | `false` | `true` or a predicate returning `true` runs callbacks without inserting `<script>`. |
| `alwaysLoad` | `false` | Loads regardless of permission. |
| `persistAfterConsentRevoked` | `false` | `true` keeps the element after revocation; `'loaded'` keeps only completed loads. |
| `onBeforeLoad`, `onLoad`, `onError` | None | Run before insertion, after load, and on failure. |
| `onConsentChange` | None | Runs on permission changes after load, and on removal. |
| `onDispose` | None | Runs when the registration is removed or disposed, not on revocation alone. |
| `target` | `'head'` | `'head'` or `'body'`. |
| `async`, `defer`, `attributes`, `fetchPriority` | None | Copied to `<script>`. |
| `nonce` | Provider `nonce` | CSP nonce for this element. |
| `anonymizeId` | `true` | Random element ID; `false` uses `inth-script-<id>`. |

Callbacks receive `{ id, elementId, hasConsent, consents }`, plus `vendor` when declared and `element` when mounted.

## Load before consent and signal the vendor

Use `alwaysLoad: true` only for SDKs with a built-in consent API, such as Consent Mode tags. Inth loads the script on every page and never removes it on permission changes, while `hasConsent` still reports the real permission:

```ts
const consentModeTag = {
	id: 'example-consent-mode',
	category: 'marketing',
	src: 'https://tags.example.com/tag.js',
	alwaysLoad: true,
	onBeforeLoad({ hasConsent }) {
		window.exampleTag = window.exampleTag ?? [];
		window.exampleTag.push(['consent', hasConsent ? 'grant' : 'deny']);
	},
	onConsentChange({ hasConsent }) {
		window.exampleTag?.push(['consent', hasConsent ? 'grant' : 'deny']);
	},
};
```

An `alwaysLoad` script contacts the vendor before any consent choice. Do not use it if your policy forbids pre-consent network requests.

## Keep a loaded SDK and switch it off

Set `persistAfterConsentRevoked: true` to keep the `<script>` element when a visitor withdraws consent. Inth calls `onConsentChange` with `hasConsent: false` so you can call the vendor's opt-out API. If the visitor grants permission again on the same page, Inth reuses the element and calls `onConsentChange` with `hasConsent: true` without running `onLoad` again:

```ts
const examplePixel = {
	id: 'example-pixel',
	category: 'marketing',
	src: 'https://pixel.example.com/pixel.js',
	persistAfterConsentRevoked: true,
	onConsentChange({ hasConsent }) {
		window.examplePixel?.(hasConsent ? 'optIn' : 'optOut');
	},
};
```

On the next page load or after Inth's revocation reload, the script still waits for permission. Without `persistAfterConsentRevoked`, Inth removes the element on revocation and then runs `onConsentChange`.

## Sync an SDK your app already loads

Set `callbackOnly: true` when your app bundles and initializes the SDK itself and Inth only needs to push permission updates. Combine it with `alwaysLoad: true` so `onBeforeLoad` runs on initial load even while permission is denied:

```ts
const existingSdkConsent = {
	id: 'existing-sdk-consent',
	category: 'measurement',
	callbackOnly: true,
	alwaysLoad: true,
	onBeforeLoad({ hasConsent }) {
		existingSdk.setTracking(hasConsent);
	},
	onConsentChange({ hasConsent }) {
		existingSdk.setTracking(hasConsent);
	},
};
```

Initialize your bundled SDK with tracking disabled by default, because Inth does not delay its import. Without `alwaysLoad`, callbacks wait until permission is allowed. See [PostHog](/docs/integrations/posthog#use-an-existing-posthog-sdk) for a complete example.

For runtime detection, `callbackOnly` also accepts a pure, SSR-safe zero-argument function returning a boolean. Define it at module scope so its reference stays stable across updates; a new function reference triggers a remount. If the predicate throws during server startup, Inth defers that script to the client loader.

## Revocation and verification

By default, Inth reloads the page when a visitor revokes an allowed category or vendor, stopping listeners and timers that script removal cannot clear. Set `reloadOnConsentRevoked: false` only when every registered script stops itself in `onConsentChange`.

For nonce-based CSP, pass `nonce` on the provider or per script. Test that no vendor request fires before a choice or after rejection, the script loads after allowing, and no request fires after revocation and reload. See [consent verification](/docs/guides/verify-consent).
