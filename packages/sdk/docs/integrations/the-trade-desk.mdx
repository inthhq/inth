The `theTradeDeskPixel` helper keeps The Trade Desk Universal Pixel off the page and its globals undefined until a visitor grants `marketing` consent. Because The Trade Desk provides no stop API, Inth leaves the loader mounted and reloads the page on withdrawal by default.

## Configure The Trade Desk

Copy the advertiser ID and Universal Pixel IDs from your account snippet. This helper loads Universal Pixel 3; Unified ID 2.0 setup is separate. Remove any direct snippet or tag manager copy before installing `@inth/integrations`:

## Options

| Option | Default | Behavior |
| --- | --- | --- |
| `advertiserId` | Required | Public advertiser ID, trimmed. Missing or blank values log an error and skip loading. |
| `pixelIds` | Required | Non-empty array of public Universal Pixel IDs, each trimmed. An empty array or any blank entry logs an error and skips the helper. |
| `enableCookieSyncing` | Vendor default | Passed to `init` when set. Setting `false` disables cookie syncing but does not stop all cookies or allow loading before consent. |
| `dataProcessingOption` | None | Limited data use setting, such as `{ policies: ['LDU'], region: 'US-CO' }`. Does not replace consent. |
| `scriptUrl` | `https://js.adsrvr.org/up_loader.3.0.0.js` | Loader URL override. Blank values use the default. Walmart DSP accounts use `https://azjs.adsrvr.org/thetradedesk-ads/up_loader.3.0.0.js`. |

## Loading and revocation

When a visitor grants `marketing`, the helper creates `ttdConversionEventsLayer` and `ttdConversionEvents` if absent, queues one `init` and one `event` call, and inserts the async loader. When `dataProcessingOption` is set, the helper passes it as `dataProcessingOption` to `init` and as `data_processing_option` on the event.

The SDK reads TCF and GPP signals after loading, which do not replace the Inth gate. Guard your own conversion calls on current `marketing` and vendor consent.

Because The Trade Desk documents no stop or teardown API, Inth leaves the loader element mounted on withdrawal and relies on `reloadOnConsentRevoked`. Disabling reload lets running code, requests, and frames continue until navigation. Regranting consent before reload reuses the loader without queueing `init` or the initial event again.

## Cookies and storage

The Trade Desk documents the `TDID` cookie on `adsrvr.org` with a one-year lifetime, which appeared in read-only tests even with `enableCookieSyncing: false`. The served SDK can also read local storage debug flags and existing GA4 cookies when configured. Treat this as a starting point, not an exhaustive inventory.

For Content Security Policy, allow `js.adsrvr.org` for scripts, `insight.adsrvr.org` and `match.adsrvr.org` for frames, and `insight.adsrvr.org` for realtime conversions. Account settings may require extra hosts.

## Verify The Trade Desk

Filter DevTools Network by `adsrvr.org` in a fresh browser profile and inspect storage in Application:

1. Deny consent, then allow an unrelated category. Confirm no requests, globals, cookies, local storage, or session storage appear.
2. Allow `marketing` and confirm the loader URL matches your account snippet.
3. Withdraw `marketing` and confirm the page reloads with The Trade Desk blocked on the new page.

Browser privacy monitors can block collection, so a clean Network trace does not prove events reached your account.
