The bundled Branch helper in `InthApple`, `inth-android`, and `@inth/react-native/integrations` maps `marketing` and `measurement` consent to Branch's [consumer protection attribution level](https://help.branch.io/developer-hub/honoring-opt-out-of-processing-requests) and sends Google DMA parameters through `setDMAParamsForEEA`. Even at `NONE`, Branch resolves deterministic deep links so your app keeps working without consent. Your app installs Branch separately. There is no web helper.

## What the helper changes

| Consent | Attribution level |
| --- | --- |
| Marketing granted | `FULL`: advertising and device identifiers |
| Only measurement granted | `MINIMAL`: device identifiers for analytics, no advertising frameworks |
| Neither, or pending | `NONE`: deterministic deep linking only |

When the level increases, the helper sends DMA parameters first. When the level drops, it lowers the attribution level first. DMA values come from the [Consent Mode mapping](/docs/integrations/google-tag#how-categories-map-to-google-consent-types):

| `setDMAParamsForEEA` argument | Source |
| --- | --- |
| `eeaRegion` | Your app |
| `adPersonalizationConsent` | `adPersonalization` |
| `adUserDataUsageConsent` | `adUserData` |

Supply `eeaRegion` from your own region logic because Inth's policy model controls how you prompt, not where the user is located. Branch requires all three arguments.

## Before you start

Complete the [Swift](/docs/frameworks/swift/quickstart), [Android](/docs/frameworks/android/quickstart), or [React Native](/docs/frameworks/react-native/quickstart) quickstart and add `marketing` and `measurement` to your Inth policy and native config. Install Branch using its [iOS](https://help.branch.io/developer-hub/ios-full-reference), [Android](https://help.branch.io/developer-hub/android-full-reference), or [React Native](https://help.branch.io/developer-hub/react-native-full-reference) guide. React Native requires `react-native-branch` 6.5 or later.

Connect the helper before Branch initializes its session so the first request carries the attribution level.

## Connect a Swift app

```swift title="BranchConsentOwner.swift"
import BranchSDK
import InthApple
import InthCore

final class BranchConsentOwner {
    private let integration: BranchIntegration

    init(core: ConsentCore, inEEA: Bool) {
        integration = BranchIntegration(
            core: core,
            setConsumerProtectionAttributionLevel: { level in
                let branchLevel: BranchAttributionLevel
                switch level {
                case .full: branchLevel = .full
                case .minimal: branchLevel = .minimal
                case .none: branchLevel = .none
                }
                Branch.getInstance().setConsumerProtectionAttributionLevel(branchLevel)
            },
            setDMAParamsForEEA: { consent in
                Branch.setDMAParamsForEEA(inEEA, adPersonalizationConsent: consent.adPersonalization, adUserDataUsageConsent: consent.adUserData)
            }
        )
    }

    func stop() { integration.cancel() }
    func syncAfterReset() { integration.sync() }
}
```

Inth names its type `BranchAttribution` so it does not collide with Branch's `BranchAttributionLevel`. On iOS, `setDMAParamsForEEA` is a class method on `Branch`, while `setConsumerProtectionAttributionLevel` runs on `Branch.getInstance()`.

## Connect an Android app

```kotlin title="BranchConsent.kt"
import com.inth.android.integrations.BranchIntegration
import com.inth.core.Inth
import io.branch.referral.Branch
import io.branch.referral.Defines

fun connectBranchConsent(inEea: Boolean, onError: (Exception) -> Unit): BranchIntegration {
	val core = checkNotNull(Inth.current) { "Install Inth before connecting Branch" }
	return BranchIntegration(
		core = core,
		setConsumerProtectionAttributionLevel = { level ->
			Branch.getInstance().setConsumerProtectionAttributionLevel(
				Defines.BranchAttributionLevel.valueOf(level.name),
			)
		},
		setDMAParamsForEEA = { consent ->
			Branch.getInstance().setDMAParamsForEEA(inEea, consent.adPersonalization, consent.adUserData)
		},
		onError = onError,
	)
}
```

Call this after `Branch.getAutoInstance(this)` in `Application.onCreate` and retain the returned helper on the `Application`.

Wrap `react-native-branch` in `branch-vendor.ts`:

```ts title="branch-vendor.ts"
import branch from 'react-native-branch';

import { connectAppBranch } from './branch-consent';

export const connectBranchVendor = (
	inEea: boolean,
	onError: (error: unknown) => void
) =>
	connectAppBranch(
		{
			setConsumerProtectionAttributionLevel: (level) =>
				branch.setConsumerProtectionAttributionLevel(level),
			setDMAParamsForEEA: ({ adPersonalization, adUserData }) =>
				branch.setDMAParamsForEEA(inEea, adPersonalization, adUserData),
		},
		onError
	);
```

React Native uses the same level strings Branch accepts. Because JavaScript runs after Branch's native session starts, also set a default level in native code if the first session must carry it. Expo requires a custom native build with Branch's config plugin, not Expo Go.

## Handle reset and teardown

Call `syncAfterReset()` on Swift, `sync()` on Android, or `await consent.sync()` on React Native to reapply the current level and DMA parameters. Calling `stop()`, `close()`, or `disconnect()` sets `NONE` and sends denied DMA values while deep links keep working.

When the level drops, Inth runs both calls even if one fails and reports the error to `onError`.

## Check the integration

1. Launch with no saved choice. Confirm Branch requests carry no advertising or device identifiers and a deep link still opens.
2. Grant `measurement` only. Confirm `MINIMAL`.
3. Grant `marketing`. Confirm `FULL` and DMA consent `true`.
4. Withdraw both. Confirm `NONE`.

Checked against `react-native-branch` `7.0.0`, `io.branch.sdk.android:library` `5.21.3`, and Branch iOS `3.14.2`. Complete [mobile verification](/docs/guides/mobile-verify) on real devices.
