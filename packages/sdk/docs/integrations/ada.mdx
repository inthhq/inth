The `ada` helper blocks Ada's Messaging Web SDK until the visitor grants `functionality` consent and keeps the Messaging interface private. On withdrawal, it calls `stop()` to remove the widget and Inth reloads the page by default. `stop()` does not delete stored conversations or cookies.

## Configure Ada Messaging

Get your AI Agent's public `handle` from Ada, plus `cluster` or `domain` if your account uses a regional setup. Remove any existing Ada module snippet, `embed2.js` tag, or tag-manager copy because Ada allows only one Messaging interface per page. This helper targets the Messaging Web SDK only and does not load the legacy Chat SDK or accept a `legacy` option.

## Options

| Option | Default | Behavior |
| --- | --- | --- |
| `handle` | Required | Public AI Agent handle passed to `start()`. Trimmed automatically. Missing or blank values log `ada: missing or invalid handle` and skip loading. |
| `cluster` | Ada default region | Regional segment such as `eu`, `us2`, or `maple`, or a full cluster domain from Ada. Trimmed, and omitted when blank. |
| `domain` | Ada default domain | Ada base-domain segment. Use only the value Ada provides. Trimmed, and omitted when blank. |

The helper dynamically imports `https://messaging-assets.ada.support/sdk.js` with no URL override and does not bundle the runtime. For Content Security Policy, allow `https://messaging-assets.ada.support` in `script-src`, `connect-src`, and `frame-src`, plus your Agent API origin in `connect-src` per [Ada's CSP guide](https://docs.ada.cx/messaging/web/getting-started#content-security-policy).

## Loading and revocation

`ada` returns a callback-only script with no `src`. On grant, it imports the SDK, calls `createAdaEmbedInterface()`, and awaits `start({ handle, cluster, domain })`. It creates no `window.adaEmbed` or `window.adaSettings` global, respects category overrides and the Ada vendor switch, and ignores repeated grants.

- **One configuration per page.** Registrations with identical `handle`, `cluster`, and `domain` share one private interface. A different configuration granted while one is active logs `ada: Ada supports one configuration per page`, and Inth ignores it until reload even after the first stops.
- **Stopping the widget.** When the last granted registration loses consent or disposes, Inth calls `stop()`, removing SDK frames and interrupting a pending `start()`. Regrant waits for pending start and stop calls before restarting. Once all registrations are gone and `stop()` completes, a new configuration can start.
- **In-flight imports.** If the visitor withdraws consent while the dynamic import downloads, Inth skips creating or starting the interface. Browsers cannot cancel an active import, so the module can still fetch dependencies, write bootstrap storage, and stay in memory until unload. Keep `reloadOnConsentRevoked` enabled.
- **Conversation data.** Ada has no consent signal API. `stop()` does not clear conversations, tokens, or cookies, and Inth never calls `deleteHistory()`.
- **Errors.** Failures log to `console.error` without throwing. Failed imports, missing `createAdaEmbedInterface`, or rejected `start()` calls log `ada: failed to start Messaging.` and drop current registrations so a later update can retry. Rejected `stop()` calls log `ada: failed to stop Messaging.`

## Cookies and storage

Entries listed in [Ada's client-side storage reference](https://static.ada.support/ada-web-storage-list.html):

| Name | Purpose and retention |
| --- | --- |
| `__Host-ada-session-[session ID]-[generation]` | HttpOnly refresh cookie on the Agent's Ada subdomain, up to seven days. |
| `ada-embed_*`, `ada-embed-*`, `ada-functional-storage` | Persistent Web Storage for SDK state, sessions, and version caches. |
| `chatter`, `created`, `inLiveChat`, `messagingAuthState` | Persistent Web Storage for conversation, session, handoff, and auth state. |
| `ada-messaging-sdk-rollout:*` | Local storage rollout assignments written on module evaluation. Can remain after `stop()`. |

Embedded services inside your Agent, such as Calendly, YouTube, or live support tools, can add storage in widget frames. Your site cannot read or delete Ada's HttpOnly cookies on another origin.

## Verify Ada Messaging

Filter DevTools Network by `ada.support` in a private window with an opt-in policy and your real handle:

1. Load the page before choosing, then reject and reload. Confirm no Ada module, manifest, iframe, API request, or storage appears.
2. Allow `functionality`. Confirm `sdk.js`, the rollout manifest, the versioned module, and the launcher load while `window.adaEmbed` stays undefined.
3. Withdraw `functionality` or disable the Ada vendor switch. Confirm `stop()` runs, the page reloads, and no Ada requests fire on the new page.
4. Repeat grant and revoke on a throttled network to verify pending startup cancellation, and check the console for `ada:` warnings.
