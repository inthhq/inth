The `vector` helper keeps the Vector pixel off the page until a visitor grants `marketing` consent. Vector identifies visiting people and companies to build ad audiences and documents no complete shutdown API, so Inth reloads the page on withdrawal by default.

## Configure Vector

Copy your pixel ID from **Settings > Pixel** in Vector, where the install snippet calls `vector.load`. Remove any direct snippet or tag manager entry so Vector loads only through Inth.

## Options

| Option | Default | Behavior |
| --- | --- | --- |
| `pixelId` | Required | Pixel ID from your account snippet, trimmed. Missing or blank values log `vector: missing or invalid pixelId` and skip loading. |
| `scriptUrl` | `https://cdn.vector.co/pixel.js` | Custom SDK URL. Blank values fall back to the default. |

## Loading and revocation

`vector` gates on `marketing` to match Vector's advertising consent guidance. On grant, the helper creates `window.vector` with a queue for `load`, `identify`, and `on` using Vector's nested `[methodName, argsArray]` format, preserves callback references and existing SDK methods, queues `load(pixelId)`, and inserts the async SDK script. The helper never calls `identify` itself.

On withdrawal, the loader stays registered across revocation and regrant to prevent duplicate execution on the same page. Because Vector documents no shutdown API, keep `reloadOnConsentRevoked` enabled; disabling it lets running code, pending loads, and partner activity continue until navigation.

The helper does not call undocumented `block` or `removeVisitor` methods. Form listening and IP-to-company lookup depend on your account settings, and Vector's IP-to-company consent hooks cover only that lookup rather than replacing the full pixel gate.

## Requests, cookies, and storage

Vector's CSP guide lists `cdn.vector.co`, `api.vector.co`, and `a.usbrowserspeed.com`. The current SDK also bundles LiveIntent and may contact `idx.liadm.com`; inspect your account's network traffic before locking down CSP rules.

The SDK prefers local storage and falls back to session storage, cookies, and memory. Observed keys include `vector_pixel_<pixelId>_visitor_id`, `vector_pixel_<pixelId>_visitor_uuid`, `vector_pixel_<pixelId>_synced_at`, and `vector_pixel_<pixelId>_last_identified_id`, alongside legacy and global keys.

When your account enables `pixelCookieFallback`, the SDK sets `vector_visitor_id` with a 3,650-day lifetime and `SameSite=None; Secure`, though browsers may shorten that lifetime. Partner keys can include `_lc2_fpi`, `_lc2_fpi_js`, `_li_dcdm_c`, and local storage `_li_duid`, and Vector can read an existing `hubspotutk` cookie. Treat this as observed behavior rather than a fixed storage contract.

## Verify Vector

Test with your real pixel ID on a domain allowed by your Vector account in a fresh browser profile:

1. Deny optional consent, then allow only `measurement`. Confirm no `window.vector` global, SDK request, or vendor storage appears.
2. Allow `marketing` and confirm `pixel.js` loads once.
3. Withdraw `marketing` and confirm the page reloads with Vector blocked on the new page. Check Network, cookies, local storage, and session storage.

Because Vector checks the requesting domain before returning account settings, verify account configuration and visitor identification on an allowed domain rather than with placeholder IDs.
