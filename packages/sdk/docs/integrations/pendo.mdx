The `pendo` helper waits for `measurement` consent before downloading the Pendo web agent and calls `pendo.initialize()` only if consent is still granted after load. Until then, Inth defines no `window.pendo` global. On withdrawal, the helper calls `pendo.stopSendingEvents()`, resumes with `startSendingEvents()` on same-page regrant, and Inth reloads the page by default.

## Configure Pendo

Copy your web agent API key from Pendo and remove Pendo's install snippet and any tag-manager copy. Pass `visitor` and `account` metadata only when your app has permission to identify the visitor.

## Options

| Option | Default | Behavior |
| --- | --- | --- |
| `apiKey` | Required | Web agent API key, trimmed and URL-encoded into the default loader URL. Missing or blank values log an error and skip loading. |
| `visitor` | Unset | Visitor metadata passed to `pendo.initialize()`. Overrides `visitor` inside `initializeOptions`. |
| `account` | Unset | Account metadata passed to `pendo.initialize()`. Overrides `account` inside `initializeOptions`. |
| `initializeOptions` | Unset | Additional `pendo.initialize()` options such as `disableCookies`, `localStorageOnly`, `excludeAllText`, and `cookieDomain`. |
| `category` | `'measurement'` | Consent category or condition required before the agent loads. |
| `scriptUrl` | `https://cdn.pendo.io/agent/static/<apiKey>/pendo.js` | Custom, regional, or proxied agent URL. Blank values use the default. |

## Loading and revocation

After consent, the helper loads `pendo.js` asynchronously without queuing calls beforehand. Once loaded, it rechecks consent before calling `pendo.initialize()`. If the visitor withdrew during download, initialization waits until the next grant. Calling `pendo()` again with equal options returns the same script so Pendo initializes once per page.

If the loaded script does not define `window.pendo`, for example because of an invalid `apiKey` or `scriptUrl`, the helper logs `pendo: loader did not install the Pendo API` and does not throw.

On withdrawal, the helper keeps the agent on the page and calls `pendo.stopSendingEvents()`. On a later grant, it calls `pendo.startSendingEvents()` without reinitializing, preserving the visitor's identity.

- **Never calls `clearSession()`.** Calling `pendo.clearSession()` starts a new anonymous visitor and can send identification events. Call it yourself only when a visitor signs out while Pendo is loaded and consented, never during consent withdrawal or denial. Use your Pendo account's data deletion or Do Not Process controls to remove collected data.
- **Storage and active guides.** Stopping events does not delete cookies or local storage, and guides already on screen remain visible. Keep `reloadOnConsentRevoked` enabled if the next page must run without Pendo loaded.

## Cookies and storage

Pendo storage keys typically start with `_pendo_` and include the app ID. Cookie behavior depends on `initializeOptions` such as `disableCookies`, `localStorageOnly`, and `cookieDomain`.

## Verify Pendo

Filter DevTools Network by `pendo.io`:

1. Before consent and with only an unrelated category allowed, confirm no Pendo requests, `window.pendo` global, cookies, or `_pendo_` storage appear.
2. Allow `measurement` and confirm the agent loads and initializes once.
3. Withdraw consent and confirm the page reloads with Pendo blocked.
4. If you set `reloadOnConsentRevoked: false`, withdraw consent and confirm `pendo.isSendingEvents()` returns `false`, then grant again and confirm sending resumes without creating a new anonymous visitor. Test guide behavior in your own account.

If the console logs `pendo: loader did not install the Pendo API`, verify `apiKey` and `scriptUrl`.
