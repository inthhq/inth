The `customerIo` helper keeps `cioanalytics` and the Customer.io Data Pipelines SDK off the page until visitors grant `marketing` consent, then resets stored identity on withdrawal.

## Options

| Option | Default | Behavior |
| --- | --- | --- |
| `writeKey` | Required | Data Pipelines JavaScript source write key, trimmed automatically. Missing or blank values log an error and skip loading. |
| `region` | `'us'` | `'us'` uses `cdp.customer.io`; `'eu'` uses `cdp-eu.customer.io`. Other values throw `customerIo: region must be 'us' or 'eu'`. |
| `loadOptions` | Unset | Loader options such as destination settings. Inth copies the object and forces `initialPageview: false`. |
| `category` | `'marketing'` | Consent condition for the entire loader. |
| `cdnUrl` | Regional HTTPS origin | Proxy origin for the loader, source settings, and SDK files. Blank values use the regional default. See [Use a proxy](#use-a-proxy). |
| `scriptUrl` | `<cdnUrl>/v1/analytics-js/snippet/<writeKey>/analytics.min.js` | Overrides the initial loader URL only. Blank values use the default. |

## Use a proxy

Set `cdnUrl` to your proxy's HTTP or HTTPS origin. Inth trims whitespace and trailing slashes, and throws `customerIo: cdnUrl must be an HTTP(S) origin` if you pass a path, query, fragment, credentials, or missing scheme. `cdnUrl` sets `cioanalytics._cdn` along with the default loader URL so source settings and SDK files load through your proxy. Keep Customer.io's URL paths intact and forward them to your workspace's regional host. Setting `scriptUrl` alone does not redirect secondary SDK files.

To proxy collected events too, set `apiHost` under `loadOptions.integrations['Customer.io Data Pipelines']` to your collection proxy host plus `/v1` without a scheme, and set `protocol: 'https'`:

## Loading and revocation

On grant, Inth creates Customer.io's queue and method stubs, assigns `_writeKey`, `_cdn`, and `_loadOptions`, inserts the namespaced script element, and reuses an already-loaded `cioanalytics` if present. While the SDK downloads, each stub returns `cioanalytics` so chained calls such as `cioanalytics.identify('customer-123').track('Signed up')` queue in order. Because `cioanalytics` stays undefined before consent, check `marketing` permission before calling it.

Inth forces `initialPageview: false` and sends the first `page()` call itself once the SDK loads while consent remains granted, and again on each subsequent grant on the same page. It does not wait for `ready()` because a failing destination can stall `ready()` while other destinations require `page()` to start. Revoking or disposing the loader cancels any pending first `page()`.

On withdrawal, Inth calls `cioanalytics.reset()` to clear stored identity. Because `reset()` does not stop the SDK, retries, or destination SDKs, keep `reloadOnConsentRevoked` enabled. The SDK loads once per page; regranting before reload reuses it instead of inserting a second copy. On the reloaded page while `marketing` is denied, Inth creates no queue and makes no requests.

## Cookies and storage

Customer.io writes analytics identity cookies and `localStorage` keys including `ack`, `reclaimStart`, `reclaimEnd`, `inProgress`, and `queue`. Destinations can write additional storage, and `reset()` does not erase all destination data.

## Verify Customer.io

Filter DevTools Network by `customer.io` or your proxy domain:

1. Before consent and after granting an unrelated category, confirm no snippet request, `cioanalytics` global, cookies, or browser storage appear.
2. Allow `marketing` and confirm the SDK initializes. An HTTP 200 JSON response for an invalid write key does not prove initialization.
3. With a proxy, confirm the snippet, `/v1/projects/<writeKey>/settings`, and SDK files load from `cdnUrl`, and check event collection separately against `apiHost`.
4. Revoke `marketing` and confirm the page reloads with no Customer.io requests.
