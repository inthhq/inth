The `frontChat` helper keeps the Front Chat bundle off the page until visitors grant `functionality` consent, then loads the bundle and calls `FrontChat('init')`.

## Configure Front Chat

Copy `chatId` from your Front Chat channel's **Installation** tab.

<CommandTabs command="@inth/integrations" mode="install" />

{/* example: fragment */}

```ts title="src/consent-scripts.ts"
import { frontChat } from '@inth/integrations/front-chat';

export const scripts = [frontChat({ chatId: 'YOUR_FRONT_CHAT_ID' })];
```

## Options

| Option | Default | Behavior |
| --- | --- | --- |
| `chatId` | Required | Public chat ID passed to `FrontChat('init')`. Trimmed automatically; blank values log an error and skip loading. |
| `useDefaultLauncher` | `true` | Shows Front's launcher. Set `false` to open the widget from your own button via Front's [SDK](https://dev.frontapp.com/docs/chat-sdk-reference). |
| `nonce` | None | CSP nonce for the loader and Front's generated scripts. Provider nonces forward to `init` too. |
| `scriptSrc` | `https://chat-assets.frontapp.com/v1/chat.bundle.js` | Loader URL override. Proxying the loader does not proxy the widget's other requests. |

Front injects additional resources for the widget; see Front's [CSP instructions](https://help.front.com/en/articles/2049) for the full policy.

## Loading and revocation

`frontChat` gates on `functionality`, appends its loader to `<body>` once allowed, and calls `FrontChat('init')`. If a visitor revokes consent while the bundle downloads, Inth skips `init`.

On withdrawal, Inth removes the loader element without calling a Front API. Keep `reloadOnConsentRevoked` enabled so the running widget unloads.

## Clear the Front session on revocation

Reloading removes the widget but keeps the visitor's Front session. To clear it, call `shutdownFrontChat()` in `onBeforeConsentRevocationReload`:

{/* example: fragment */}

```ts title="src/consent-callbacks.ts"
import { shutdownFrontChat } from '@inth/integrations/front-chat';

export const callbacks = {
	onBeforeConsentRevocationReload: ({ preferences }) => {
		if (!preferences.functionality) {
			shutdownFrontChat();
		}
	},
};
```

`shutdownFrontChat` calls `FrontChat('shutdown', { clearSession: true })` if the SDK loaded and no-ops otherwise. Front returns no completion signal, so the reload does not wait for cleanup to finish.

## Verify Front Chat

1. Allow `functionality` and confirm `chat.bundle.js` loads and connects to your Front inbox.
2. With `shutdownFrontChat` configured, revoke `functionality` and regrant it to confirm a new Front session starts.
