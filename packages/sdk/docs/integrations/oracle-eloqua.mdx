The `eloquaTracking` helper waits for its mapped category, `marketing` by default, and vendor consent before defining `_elqQ` or downloading Oracle Eloqua. On withdrawal, it queues `elqOptOut` and Inth reloads the page by default.

## Options

| Option | Default | Behavior |
| --- | --- | --- |
| `siteId` | Required | Eloqua site ID. Missing or blank values log an error and skip loading. |
| `firstPartyCookieDomain` | Unset | First-party tracking hostname configured in Eloqua. |
| `category` | `'marketing'` | Consent condition for the loader. |
| `scriptUrl` | `https://img.en25.com/i/elqCfg.min.js` | Custom or proxied loader URL. Blank values use the default. |

Custom loaders, including URLs moved via `scriptLoader.sources`, must synchronously append one matching consent response script when `elqOptIn` or `elqOptOut` runs, preserving `pps=41` for opt-in, `pps=42` for opt-out, and the installed account's `siteid` query parameter. The response can finish asynchronously. A deferred, unmatched, or throwing custom dispatcher leaves consent indeterminate and blocks tracking and further consent commands until reload.

## Loading and revocation

After consent, the helper creates `_elqQ`, sets the site ID and optional `firstPartyCookieDomain`, downloads `elqCfg.min.js`, queues `elqOptIn`, and waits for its response before sending `elqTrackPageView` with the full current URL including path, query, and fragment.

- **Serialized consent requests.** The helper sends one consent command at a time. Changes during a pending response wait until it settles before sending the latest choice. Withdrawal or disposal during opt-in queues `elqOptOut` afterward and suppresses the page view if no remaining provider permits tracking. Regrant waits for any pending opt-out before opting in again.
- **No automatic retry loop.** Failed or unappended stock responses log a dispatch failure and send no page view. A later consent update, remount, or script reconciliation can retry. A failed opt-out can leave Eloqua's opt-in cookie in place; the helper does not delete it or report withdrawal as complete.
- **Multiple providers.** Calling `eloquaTracking` with equivalent options shares one lifecycle across disposal, remount, and differing categories or loader URLs. Every registered provider, including a denied provider that never loaded, must allow the category and vendor before tracking starts. Disposing one provider keeps the active lifecycle while remaining providers allow tracking, and a compatible provider can adopt an already-loaded tag.
- **One account per page.** Use one `siteId` and normalized `firstPartyCookieDomain` per page; an unset domain differs from a configured one. A provider with a different site ID or domain logs a conflict and blocks tracking through the installed account until removed, even if it starts denied. Changing the installed site or domain requires a reload.
- **Keep reload enabled.** Eloqua's opt-in and opt-out commands are asynchronous and do not cancel in-flight requests or disable all SDK methods. A hung response can block later choices until reload. The loader stays in the DOM for same-page regrant because Eloqua replaces `_elqQ` with a dispatcher, so keep `reloadOnConsentRevoked` enabled for a clean next page.

Eloqua sets `ELOQUA`, `ELQSTATUS`, `ELQOPTOUT`, and first-party `OPTIN` cookies, with documented lifetimes up to 13 months. Reloading does not delete existing vendor cookies.

## Verify Oracle Eloqua

In a clean browser profile, filter DevTools Network by your Eloqua loader host:

1. Before consent and after granting an unrelated category, confirm no `elqCfg.min.js` request, `_elqQ` global, cookies, or browser storage appear.
2. Grant `marketing`, or your mapped category, and allow the Oracle Eloqua vendor. Confirm the real dispatcher replaces the `_elqQ` array and `elqOptIn` completes before `elqTrackPageView`.
3. Revoke consent and inspect the `elqOptOut` request with `pps=42`.
4. Regrant consent with your configured account and confirm page tracking fires after the asynchronous opt-in completes.
