The `cloudflareWebAnalytics` helper keeps Cloudflare's `beacon.min.js` off the page until visitors grant `measurement` consent, then removes the loader and reloads the page on withdrawal.

## Configure Cloudflare Web Analytics

Copy the beacon token from your Web Analytics snippet. Turn off automatic beacon injection in Cloudflare so only Inth loads the beacon.

<CommandTabs command="@inth/integrations" mode="install" />

{/* example: fragment */}

```ts title="src/consent-scripts.ts"
import { cloudflareWebAnalytics } from '@inth/integrations/cloudflare-web-analytics';

export const scripts = [cloudflareWebAnalytics({ token: 'YOUR_BEACON_TOKEN' })];
```

## Options

| Option | Default | Behavior |
| --- | --- | --- |
| `token` | Required | Beacon token written into `data-cf-beacon`. Trimmed automatically; blank values log an error and skip loading. |
| `spa` | `true` | Written into `data-cf-beacon` to enable SPA route tracking. Set `false` for sites with full page loads only. |
| `scriptUrl` | `https://static.cloudflareinsights.com/beacon.min.js` | Loader URL override. |

## Loading and revocation

Although Cloudflare states the beacon sets no cookies, `cloudflareWebAnalytics` still waits for `measurement` consent and loads `beacon.min.js` with `defer` once allowed. On withdrawal, Inth removes the script element without calling a Cloudflare API and reloads the page by default.

## Verify Cloudflare Web Analytics

Filter DevTools Network by `cloudflareinsights.com`:

1. Allow `measurement` and confirm `beacon.min.js` loads with your token and `"spa":true` in `data-cf-beacon`.
2. Navigate to another route and confirm the beacon reports the new page.
