Gate third-party scripts, embeds, and native SDKs with Inth consent permissions. Web helpers live in `@inth/integrations`; [mobile SDK helpers](#mobile-sdks) ship inside `InthApple`, `inth-android`, and `@inth/react-native`.

## Install web helpers

Complete your [framework quickstart](/docs/frameworks) first, then install `@inth/integrations` alongside your framework package such as `@inth/react` or `@inth/nextjs`:

<CommandTabs command="@inth/integrations" mode="install" />

Each helper returns a script configuration that you pass to your existing Inth provider. Importing a helper loads nothing on its own. Remove the vendor's standalone snippet, tracking pixel, framework plugin, or tag manager entry so Inth is the only loader. For framework plugins, see [migrate from `@next/third-parties`](/docs/frameworks/next/scripts#migrate-from-nextthird-parties), [migrate from `@nuxt/scripts`](/docs/frameworks/nuxt/scripts#migrate-from-nuxtscripts), and [migrate from `nuxt-gtag`](/docs/frameworks/nuxt/scripts#migrate-from-nuxt-gtag).

Most helpers wait for their category to be allowed. Helpers that support a vendor consent API can load immediately and pass the current permission signal.

## Vendor switches and cookie cleanup

Every helper declares a `vendor` slug, name, and privacy policy URL. Once you enable vendor switches, visitors can turn off individual vendors inside an allowed category. Inth blocks disabled vendors, or sends a denied signal to always-loaded helpers like Google Tag Manager, Microsoft UET, and Mixpanel. Declare a vendor with the same slug to override its name or links.

When a visitor withdraws a category, Inth reloads the page to stop running scripts. Gating does not delete cookies already set; configure `clearOnRevocation` to remove them.

## Send events only to allowed integrations

The event dispatcher sends a single named event to every allowed, registered integration that supports events, dropping calls when `measurement` is denied. One vendor error does not block other vendors.

| Framework | Dispatcher API |
| --- | --- |
| React, Next.js, TanStack Start | `useEventDispatcher()` from `@inth/react`, `@inth/nextjs`, or `@inth/tanstack-start` |
| Vue, Nuxt | `useEventDispatcher()` from `@inth/vue/vue-plugin`, auto-imported in Nuxt |
| Svelte, SvelteKit | `getEventDispatcher()` from `@inth/svelte` inside `InthProvider` |
| Angular | `injectEventDispatcher()` from `@inth/angular/consent-gate` |
| Astro | `getEventDispatcher()` from `@inth/astro/client` |
| JavaScript | `getEventDispatcher(runtime)` from `@inth/sdk` |

{/* example: fragment */}

```tsx
import { useEventDispatcher } from '@inth/react';
import { useEffect } from 'react';

export const DocsSearch = ({ path }: { path: string }) => {
	const events = useEventDispatcher({ pageviews: ['posthog'] });
	useEffect(() => {
		events.pageview(path);
	}, [events, path]);
	return (
		<button onClick={() => events.track('docs_search', { resultCount: 4 })}>
			Search
		</button>
	);
};
```

`track` dispatches to Google Tag Manager, Google Tag, PostHog, Mixpanel, Segment, Hightouch, Heap, Amplitude, LogRocket, Adobe Analytics, Databuddy, Plausible, Fathom, Pirsch, Microsoft Clarity, Hotjar, Vercel Analytics, OneDollarStats, Umami, Rybbit, RudderStack, and Matomo. `pageview` sends SPA navigation events to the integrations listed in `pageviews`: PostHog, Segment, or Hightouch. Call it from your router navigation hook; repeated paths and hash-only changes are skipped automatically.

Outside a provider, create one long-lived dispatcher with `createEventDispatcher` from `@inth/integrations/events`, passing `scripts` and a `getSnapshot` callback.

For a vendor without a helper or an SDK your app already loads, see [custom integrations](/docs/integrations/building-integrations). Test every setup with the [consent verification guide](/docs/guides/verify-consent).

## Resolve integrations on a server

`@inth/integrations/remote` turns an integration key and a few options into a `ResolvedManifest`, plain JSON that the SDK runs as a script. The Inth server uses it to load integrations a project adds without a code change on the site. The module runs without a DOM.

{/* example: fragment */}

```ts
import {
	remoteIntegrations,
	validateRemoteOptions,
} from '@inth/integrations/remote';

const result = validateRemoteOptions('googleTagManager', {
	id: 'GTM-ABC1234',
	loadMode: 'after-consent',
});
if (!result.ok) {
	throw new Error(result.issues.join('\n'));
}

const manifest = remoteIntegrations.googleTagManager?.resolveRemote(
	result.options
);
```

Each entry's `options` is plain data, so a settings form can render from it. Every option has a `kind`, and every value is JSON:

| Kind | Value |
| --- | --- |
| `id` | A string that matches `pattern`, such as `example`. |
| `hostname` | A DNS name such as `go.example.com`: lowercase labels, with no scheme, port, path, credentials or IP address. Only for a tracker on the customer's own domain. |
| `enum` | One of `values`. Missing takes `default`. |
| `boolean` | `true` or `false`. Missing takes `default`. |
| `number` | A finite number within `min` and `max`; with `integer`, no fraction. |
| `idList` | Up to `maxItems` distinct strings, each matching `pattern`. |
| `object` | The declared `fields` only, each a scalar kind or one more object of scalars. |
| `map` | Up to `maxEntries` keys matching `keyPattern`, each mapped to one of `values`. |

No kind takes a URL or a function, so script URL overrides, init options and callbacks stay npm-only. A string that looks like a URL fails in every kind.

- `validateRemoteOptions` rejects unknown keys at any depth, missing required values, wrong types, values outside a pattern, range or list, and URL-shaped strings, with one issue per problem. It fills in `enum` and `boolean` defaults. `resolveRemote` throws on options that fail validation and returns a new object on every call.
- A remote entry builds the same script as its npm helper called with the same options, including the helper's consent settings. Google Tag Manager still loads before a choice in the `necessary` category. With `loadMode: 'after-consent'` it waits until `measurement` or `marketing` is allowed, which an opt-out policy can allow before any choice.

A manifest that needs a manifest runtime above level 1 carries `requires`, the level it needs. The SDK runs level 4. Level 2 adds steps such as `loadScriptStep` and runtime values such as `hasConsent`; level 3 adds `if` steps, `setFlag`, `listen`, `defer` and `callGlobal.then`; level 4 adds `adapter`, which names code the SDK ships for a vendor, such as Sentry's consent handling. The script tag loads level 3 from `inth.manifests3.js` in place of `inth.manifests.js`, and npm builds load it as a separate chunk, only when a listed manifest requires level 3. Each adapter loads the same way, as `inth.adapter-<id>.js` or a chunk, only when a listed manifest names it. Every remote integration carries `globals`, which is level 2, so each one carries `requires`: 2, 3 when it uses level 3 steps, and 4 for Sentry. The SDK sends its own level as the `manifestLevel` query parameter on `/v1/consent/init` and `/v1/consent/manifest`, and refuses a manifest whose `requires` is higher. On the server, call `manifestLevel(manifest)`, set `requires` to the result when it is above 1, and list an entry only for a request whose `manifestLevel` is at least that level. Read a request without `manifestLevel` as level 1.

Each vendor file exports its entry as `remote`, made with `defineRemote` from the resolver its npm helper calls, and `remoteIntegrations` collects them from the integrations registry. Integrations that run their own lifecycle code, such as HubSpot and Sentry, stay npm-only until the SDK can run them from a manifest.

The script tag loads these integrations by default; set `data-remote-scripts="false"` on it to turn that off. With npm, only React and the core runtime support it so far: set `remoteScripts: true`, such as `<InthProvider options={{ remoteScripts: true }}>`. The Vue, Svelte, Angular and Astro packages don't pass the option on yet. A script your site declares in code for the same integration wins over the one from the server.

### Mobile integration rules

- **Install Inth first.** Complete your [Swift](/docs/frameworks/swift/quickstart), [Android](/docs/frameworks/android/quickstart), or [React Native](/docs/frameworks/react-native/quickstart) quickstart and attach helpers to that engine.
- **Keep one app-lifetime connection.** Do not recreate helpers on re-render or close them on Activity rotation. Detach with `cancel()` in Swift, `close()` in Kotlin, or `disconnect()` in React Native, and call `sync()` after any vendor reset.
- **Guard native startup.** Firebase and PostHog persist earlier grants across launches. For zero pre-consent traffic, defer SDK init behind a [native startup gate](/docs/frameworks/react-native/native-behaviour). React hooks cannot block an SDK that already started natively.
- **Wire routers and ads natively.** Segment and RudderStack need per-destination consent mappings through native gates, not web helpers. IAB signals, ATT, and notification permissions stay separate from category consent.
- **Handle failures explicitly.** React Native requires `onError` and `await ready`; Kotlin requires a non-throwing error handler; Swift callbacks are synchronous and non-throwing. Call vendor APIs directly in callbacks so updates stay ordered, and retry failed disable calls.
- **Verify on a real build.** Check fresh install, saved grant, refusal, withdrawal, and reset with mobile verification for [Swift](/docs/frameworks/swift/verify), [Android](/docs/frameworks/android/verify), or [React Native](/docs/frameworks/react-native/verify).
