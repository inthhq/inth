The `zendeskWidget` helper waits for `functionality` consent before creating Zendesk's globals or loading the Zendesk Messaging Web Widget. Before loading, it maps `measurement` consent to Zendesk's cookie range so analytics storage stays off unless allowed. On withdrawal, it instructs Zendesk to hide the widget and delete its local and session storage, and Inth reloads the page by default.

This helper supports Zendesk Messaging only. Web Widget Classic uses a different API.

## Configure Zendesk Messaging

Open **Admin Center > Channels > Messaging and social > Messaging**, select your widget, and copy the widget key from **Installation**. Remove any existing Zendesk snippet from your page or tag manager.

## Options

| Option | Default | Behavior |
| --- | --- | --- |
| `key` | Required | Public Messaging widget key, trimmed and URL-encoded. Missing or blank values log `zendeskWidget: missing or invalid key` and skip loading. |
| `category` | `'functionality'` | Consent category or condition required to load the widget. `measurement` still controls analytics storage. |

## Loading and revocation

When consent passes, Inth creates the `zE` queue, also exposed as `zEmbed`, and loads `https://static.zdassets.com/ekr/snippet.js?key=<key>`. Before the loader runs and on every consent change, it calls `zE('messenger:set', 'cookies', range)`:

| Mapped consent | Measurement consent | Zendesk range |
| --- | --- | --- |
| Granted | Granted | `all` |
| Granted | Denied | `functional` |
| Denied after loading | Either | `none` |

With `functional`, Zendesk disables analytics for Pages viewed and Proactive messages. With `none`, Zendesk hides the widget and clears its local and session storage, as documented in Zendesk's [Set cookies API](https://developer.zendesk.com/api-reference/widget-messaging/web/core/#set-cookies). Turning off the visitor's Zendesk vendor switch counts as denied and sends `none`.

Inth removes the loader on revocation, but `none` does not unload the SDK or cancel in-flight requests. Keep `reloadOnConsentRevoked` enabled to stop running code. Regranting consent before reload inserts a new loader and applies the current range.

### Several helpers and one widget key

Helper instances with the same `key` and consent condition share one loader, so recreating the helper on re-render keeps updates active. Across shared registrations, the widget stays available while any registration has consent, and `all` requires `measurement` consent from every granted registration.

Use one widget key per page. Zendesk exposes a single global `zE` API, so multiple widgets on one page interfere with each other even when loading separate scripts.

### Removing the helper

Removing the helper or unmounting its provider releases that registration. When the last registration ends, Inth removes the loader without sending `none`, clearing storage, or unloading running code, and stops forwarding consent updates. Revoke consent first or reload the page when you need the widget stopped and cleared.

## Cookies and storage

Zendesk's [in-product cookie policy](https://support.zendesk.com/hc/en-us/articles/4408824378650-Zendesk-In-Product-Cookie-Policy) documents these Web Widget entries; check your widget configuration for other product storage:

| Name | Zendesk category | Lifetime |
| --- | --- | --- |
| `<integrationId>.appUserId`, `<integrationId>.clientId`, `<integrationId>.sessionToken` | Essential | Local or session storage, subject to browser policy |
| `ZD-suid` | Analytics | 20 minutes |
| `ZD-buid` | Analytics | Forever |
| `ZD-widgetOpen`, `ZD-launcherLabelRemoved` | Functionality | Forever |
| `ZD-soundNotificationDisabledKey`, `ZD-campaigns`, `<integrationId>.conversationStartedAt` | Functionality | Subject to browser policy |

## Verify Zendesk Messaging

Filter DevTools Network by `zdassets.com` and your Zendesk subdomain:

1. Before consent, confirm no Zendesk requests appear and `window.zE` is undefined.
2. Grant `functionality` without `measurement` and confirm analytics storage stays off. Grant `measurement` while the widget is open, then withdraw it, and confirm the widget stays active with analytics off.
3. Revoke `functionality` and confirm Zendesk hides the widget. After Inth reloads the page, confirm the loader stays absent.
4. Open a conversation in the widget; a successful `snippet.js` response alone does not prove your widget key or Messaging setup works.

Sources: [install and show the Web Widget](https://developer.zendesk.com/documentation/zendesk-web-widget-sdks/sdks/web/messaging-show-web-widget/), [Messaging core API](https://developer.zendesk.com/api-reference/widget-messaging/web/core/), and [Zendesk privacy notice](https://www.zendesk.com/company/agreements-and-terms/privacy-notice/).
