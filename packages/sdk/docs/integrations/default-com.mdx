Use `defaultComPixel` to gate the Default Pixel on `measurement` consent, or `defaultComFormsSdk` to gate the standalone Forms SDK on `functionality` consent. Default identifies companies under `analytics` and can load Vector for people identification under `marketing`. The Pixel also supports opt-in `loadMode: 'always'` to keep form capture available before consent.

## Choose one helper

- **Use `defaultComPixel`** for automatic HubSpot and Marketo form capture and scheduler handoff.
- **Use `defaultComFormsSdk`** for custom forms, Pardot, or a custom API proxy.

Register only one Default helper per document. The first helper that starts loading claims the document until reload, and a second helper logs an error and stays disabled. The SDK stays blocked if `window.__defaultPixel__.key` exists, and the Pixel stays blocked if `window.DefaultPixelSDK` exists, because they cannot share consent reliably when browsers block cookies.

Remove direct Default snippets and tag-manager copies first. Both helpers target `handshake.default.com`, not legacy `pixel-cdn.default.com` or `import-cdn.default.com` scripts.

## Options

| Option | Default | Behavior |
| --- | --- | --- |
| `publicKey` | Required | Public workspace key. Blank or non-string values log an error and skip loading. |
| `category` | Pixel: `'measurement'`; SDK: `'functionality'` | `IntegrationConsentCondition` for loading and permission. With Pixel `'always'`, controls permission without delaying load. |
| `loadMode` | Pixel only: `'after-consent'` | `'after-consent'` waits for `category`; `'always'` loads before consent. Not accepted by Forms SDK. |
| `scriptUrl` | Pixel: `https://handshake.default.com/index.js`; SDK: `https://handshake.default.com/sdk.js` | Loader URL override. Blank values use the default. |
| `schedulerOrigins` | Default's setting | Allowed scheduler origins forwarded to the script. |
| `autoDisplayScheduler` | Pixel: Default's setting; SDK: `true` | Boolean or `{ target, loader? }` forwarded to Default. |
| `endpoint` | SDK only: Default's setting | API endpoint override for Forms SDK. Blank values use the SDK default. |

## Loading and consent forwarding

By default, neither helper creates globals or loads scripts until its category and the `default-com` vendor switch allow it. Override `category` to tighten the gate:

{/* example: fragment */}

```ts
defaultComPixel({ publicKey: 'YOUR_PUBLIC_KEY', category: 'marketing' });
```

Every update sends both fields: Inth `measurement` maps to `analytics` and `marketing` maps to `marketing`, with both `false` when denied. Granting `measurement` without `marketing` loads the Pixel with `{ analytics: true, marketing: false }`, allowing company identification while blocking new Vector loads.

- **Pixel lifecycle.** On start, Inth sets the key and scheduler options, queues `['setConsent', { analytics, marketing }]`, and inserts `index.js`. Once started, `publicKey`, `scriptUrl`, `schedulerOrigins`, and `autoDisplayScheduler` lock for that document; changing them throws until reload.
- **Forms SDK lifecycle.** After `sdk.js` loads, Inth calls `DefaultPixelSDK.setConsent()` before `init()`. Withdrawal during download defers `init()` until permitted. Updating options while permitted re-calls `init()` without resetting identity or session; omitting `endpoint` or `schedulerOrigins` restores defaults, and omitting `autoDisplayScheduler` restores `true`.

After init, `window.DefaultPixelSDK` exposes `submitForm()`, `recordFormInteraction()`, `on()`, and `scheduler`. Verify `submitForm()` results in your workspace; see the [Default SDK API reference](https://docs.os.default.com/pixel-sdk-reference).

## Early Pixel loading

With `loadMode: 'after-consent'`, declined visitors cannot use Pixel form capture, so provide a fallback form path. Opt into `loadMode: 'always'` to keep form capture active before consent:

{/* example: fragment */}

```ts
defaultComPixel({ publicKey: 'YOUR_PUBLIC_KEY', loadMode: 'always' });
```

This requests `index.js` and the form catalogue from `https://api.default.com` before consent, even when the vendor switch is off. Inth still queues `{ analytics: false, marketing: false }` first and updates both fields as consent changes.

## Withdrawal and storage

Both helpers retain their loader elements after withdrawal to forward `{ analytics: false, marketing: false }` and reuse the script on regrant. Changing the Forms SDK `scriptUrl` after load requires a reload.

Analytics withdrawal clears Default's identity cookies, session-storage copies, and `_dflt_attr`, while `_dflt_consent`, `_dflt_wi`, and pending scheduler handoffs can remain. Marketing withdrawal blocks future Vector loads but cannot unload running Vector or clear partner storage. Storage on `book.default.com`, including `default.reservation`, `_dflt_*`, and `ph_*`, does not follow Pixel consent.

Keep `reloadOnConsentRevoked` enabled. With Pixel `loadMode: 'always'`, reloading loads the Pixel again with denied fields; stopping all requests requires `loadMode: 'after-consent'`.

## Verify Default

Test with your workspace key and filter DevTools Network by `default.com`:

1. **Pixel:** Confirm no `index.js` or `__defaultPixel__` before `measurement`. Grant `measurement` only and verify `{ analytics: true, marketing: false }`.
2. **Forms SDK:** Confirm no `sdk.js` or `DefaultPixelSDK` before `functionality`. Grant `functionality` only and verify `setConsent` runs before `init()` with both fields `false`.
3. **Early Pixel:** With `loadMode: 'always'`, confirm `index.js` and catalogue requests fire before consent with both fields `false`.
4. **Withdrawal and updates:** Toggle `measurement`, `marketing`, and the `default-com` switch, withdraw to verify reload blocking, and confirm live Forms SDK option updates apply without repeating session startup.
