The `luckyOrange` helper waits for `measurement` consent before creating `window.LOQ`, loading Lucky Orange, and calling `LO.privacy.setConsentStatus(true)`. On withdrawal, it calls `setConsentStatus(false)` and relies on Inth's default page reload to stop active recording code.

## Configure Lucky Orange

Turn on **Require Consent** in your Lucky Orange dashboard so Lucky Orange waits for its privacy API. Copy your site ID and remove any direct snippet or tag manager copy so Lucky Orange loads only through Inth.

## Options

| Option | Default | Behavior |
| --- | --- | --- |
| `siteId` | Required | Site ID, trimmed and URL-encoded into the default loader URL. Missing or blank values log an error and skip loading. |
| `category` | `measurement` | Consent category or condition required before the loader runs. |
| `scriptUrl` | `https://tools.luckyorange.com/core/lo.js?site-id=<siteId>` | Custom or proxied loader URL. Blank values use the default. |

A proxied `scriptUrl` must keep `lo.js` in its path because Lucky Orange finds the site ID from script URLs containing that filename. Renamed proxy paths are untested.

## Loading and revocation

When the category is allowed, the helper creates `window.LOQ` (or reuses an existing array), pushes a `ready` callback, and inserts the loader. Once Lucky Orange's privacy module starts, the helper passes the visitor's current choice to `setConsentStatus`, passing `false` if consent was withdrawn mid-load so a late callback cannot grant consent.

If the privacy module fails to start, the helper logs `luckyOrange: privacy initialization failed.` with the error and never calls `setConsentStatus`, even if Inth disposed the helper while waiting.

On withdrawal, the helper keeps the loader mounted and calls `setConsentStatus(false)`. Re-granting consent on the same page calls `setConsentStatus(true)` without loading the script again. Calling `luckyOrange()` again with equal options returns the same script.

The helper does not call `optOut()`, which writes a two-year opt-out cookie that blocks later grants. Because `setConsentStatus(false)` is not verified to stop every active recording, keep `reloadOnConsentRevoked` enabled.

## Cookies and storage

Lucky Orange writes `lo-domain-check`, `lo-opt-out`, `lo-uid`, and `lo-visits` cookies (some lasting two years), plus `lo-session`, `lo-messenger`, and `lo-visitor` in `localStorage`. Test Do Not Track and any existing Lucky Orange opt-out cookie against your own account.

## Verify Lucky Orange

Filter DevTools Network by `luckyorange.com`. Before consent, and with only an unrelated category allowed, confirm no loader, `LOQ`, `LO`, cookies, or storage entries appear. Allow `measurement`, wait for the privacy module, and check that `LO.privacy.getConsentStatus()` returns `true`. Withdraw consent and confirm the page reloads with Lucky Orange blocked.

With `reloadOnConsentRevoked: false`, withdraw while the loader downloads to confirm no late callback grants consent, and check recording state after withdrawal and re-grant with **Require Consent** enabled. If the console logs `luckyOrange: privacy initialization failed.`, Lucky Orange received no consent status.
