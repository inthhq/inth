Load the Meta Pixel only after `marketing` consent is granted. Before consent, Inth does not define `window.fbq` or contact Meta. Once `marketing` is allowed, `metaPixel` queues `fbq('consent', 'grant')` before `init` and `PageView`, then loads `fbevents.js`. On revocation, it calls `fbq('consent', 'revoke')` and reloads the page by default.

## Configure the Meta Pixel

Copy your pixel ID from Meta Events Manager. Remove any existing pixel snippet, `<noscript>` image, or tag manager entry loading the same pixel, then install `@inth/integrations`:

<CommandTabs command="@inth/integrations" mode="install" />

```ts title="src/consent-scripts.ts"
import { metaPixel } from '@inth/integrations/meta-pixel';

export const scripts = [metaPixel({ pixelId: '123456789012345' })];
```

## Options

| Option | Default | Behavior |
| --- | --- | --- |
| `pixelId` | Required | Pixel ID passed to `fbq('init', ...)`. Trimmed automatically; blank values log an error and skip loading. |
| `initOptions` | None | Object passed as the third argument to `fbq('init', ...)`. |
| `trackPageView` | `true` | Queues `fbq('track', 'PageView')` after `init`. Set `false` to send page views yourself. |
| `dataProcessingOptions` | None | `{ options, country?, state? }` queued via `fbq('dataProcessingOptions', ...)` before `init`, such as `{ options: ['LDU'], country: 1, state: 1000 }` for California Limited Data Use. |
| `scriptSrc` | `https://connect.facebook.net/en_US/fbevents.js` | Loader URL override. Blank values fall back to the default. |

## Loading and revocation

`metaPixel` gates on the `marketing` category. When `marketing` is allowed, it queues `fbq('consent', 'grant')`, any `dataProcessingOptions`, `init`, and `PageView`, then loads `fbevents.js`.

On revocation, the script stays mounted and calls `fbq('consent', 'revoke')` before Inth's default reload. If `marketing` is re-enabled before reload, it calls `fbq('consent', 'grant')`.

## Guard your own fbq calls

Because `window.fbq` remains defined after revocation, check `marketing` permission from your framework, such as `useConsent('marketing')` in React, before calling `fbq`:

```ts title="src/track-purchase.ts"
export function trackPurchase(marketingAllowed: boolean, value: number) {
	if (!marketingAllowed || typeof window.fbq !== 'function') return;
	window.fbq('track', 'Purchase', { currency: 'USD', value });
}
```

`@inth/integrations/meta-pixel` also exports typed wrappers: `metaPixelEvent`, `metaPixelCustomEvent`, `metaPixelSingleEvent`, and `metaPixelSingleCustomEvent`. They no-op while `window.fbq` is undefined, accept a trailing `eventID` string for Conversions API deduplication, and do not check consent themselves, so guard them with your permission check too.

## Verify the Meta Pixel

Allow `marketing` and confirm `fbevents.js` loads and a `facebook.com/tr` request sends `ev=PageView`. Trigger a guarded event and verify its `tr` request fires. After revoking `marketing`, confirm `trackPurchase` sends nothing before reload. With client-side routing, confirm each navigation sends one `PageView`.
