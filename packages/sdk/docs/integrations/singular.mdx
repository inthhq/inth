The bundled Singular helper in `InthApple`, `inth-android`, and `@inth/react-native/integrations` starts Singular only after consent passes, resumes tracking, records a GDPR opt-in, and stops tracking on withdrawal. It drives [`limitDataSharing`](https://support.singular.net/hc/en-us/articles/23269267011611--March-2024-Google-Updates-for-the-EU-Digital-Markets-Act-DMA) from `marketing` so Singular forwards Google DMA consent signals. The default category is `marketing`.

Install Singular separately. Inth ships no web helper for Singular.

## What the helper changes

| Consent | Singular calls |
| --- | --- |
| Category never granted | Nothing. Singular does not start. |
| Category granted for the first time | Your `start` callback with the data-sharing limit, then `limitDataSharing`, `resumeAllTracking()`, and `trackingOptIn()`. |
| Category granted again after withdrawal | `limitDataSharing`, `resumeAllTracking()`, and `trackingOptIn()`. |
| Category withdrawn after Singular started | `stopAllTracking()`, then `limitDataSharing(true)`. |
| Marketing changes while category stays granted | `limitDataSharing` only. |

The helper passes `true` to `limitDataSharing` unless both `adUserData` and `adPersonalization` pass consent, matching the shared [Consent Mode mapping](/docs/integrations/google-tag#how-categories-map-to-google-consent-types). Singular keeps tracking stopped across launches until `resumeAllTracking()` runs.

### Why the helper starts Singular

Singular ignores `stopAllTracking`, `resumeAllTracking`, `trackingOptIn`, and `limitDataSharing` before initialization. In Android SDK 12.17.0, each logs `"Singular SDK not initialized"` and returns, and the React Native wrapper forwards calls straight to the native SDK. Initializing Singular also sends a session immediately, and no config option starts it stopped. Calling your `start` callback on the first grant keeps a denied launch silent.

If `start` fails by returning `false` in Swift or Kotlin, throwing, or rejecting, the helper reports the error, makes no tracking call, and retries `start` on the next consent update or `sync()`. At launch with a saved grant, the helper stays connected and reports the failure instead of throwing, while `ready` rejects on React Native. Restrictive calls such as `stopAllTracking()` and `limitDataSharing(true)` still follow consent after a failed start because Singular may have initialized anyway.

## Before you start

Complete the [Swift](/docs/frameworks/swift/quickstart), [Android](/docs/frameworks/android/quickstart), or [React Native](/docs/frameworks/react-native/quickstart) quickstart with `marketing` in your Inth policy and native config. Install Singular using its [iOS](https://support.singular.net/hc/en-us/articles/36198287576987-iOS-SDK-Data-Privacy), [Android](https://support.singular.net/hc/en-us/articles/37157391877019-Android-SDK-Methods-Reference), or [React Native](https://support.singular.net/hc/en-us/articles/36069276969627-React-Native-SDK-Data-Privacy) guide.

**Do not initialize Singular yourself.** Put `Singular.init` on Android and React Native, or `Singular.start` on iOS, inside the helper's `start` callback and connect the helper at startup. If your app requires Singular before consent, such as for resolving Singular Links, skip this helper.

## Connect a Swift app

```swift title="SingularConsentOwner.swift"
import InthApple
import InthCore
import Singular

final class SingularConsentOwner {
    private let integration: SingularIntegration

    init(core: ConsentCore) {
        integration = SingularIntegration(
            core: core,
            start: { limit in
                Singular.limitDataSharing(limit)
                return Singular.start(SingularConfig(apiKey: "YOUR_SDK_KEY", andSecret: "YOUR_SDK_SECRET"))
            },
            limitDataSharing: { Singular.limitDataSharing($0) },
            stopAllTracking: { Singular.stopAllTracking() },
            resumeAllTracking: { Singular.resumeAllTracking() },
            trackingOptIn: { Singular.trackingOptIn() }
        )
    }

    func stop() { integration.cancel() }
    func syncAfterReset() { integration.sync() }
}
```

## Connect an Android app

```kotlin title="SingularConsent.kt"
import android.content.Context
import com.inth.android.integrations.SingularIntegration
import com.inth.core.Inth
import com.singular.sdk.Singular
import com.singular.sdk.SingularConfig

fun connectSingularConsent(context: Context, onError: (Exception) -> Unit): SingularIntegration {
	val core = checkNotNull(Inth.current) { "Install Inth before connecting Singular" }
	return SingularIntegration(
		core = core,
		start = { limit ->
			Singular.init(context, SingularConfig("YOUR_SDK_KEY", "YOUR_SDK_SECRET").withLimitDataSharing(limit))
		},
		limitDataSharing = Singular::limitDataSharing,
		stopAllTracking = Singular::stopAllTracking,
		resumeAllTracking = Singular::resumeAllTracking,
		trackingOptIn = Singular::trackingOptIn,
		onError = onError,
	)
}
```

Call `connectSingularConsent` in `Application.onCreate` instead of `Singular.init`, and retain the returned helper on the `Application` instance.

```ts title="singular-vendor.ts"
import { Singular, SingularConfig } from 'singular-react-native';

import { connectAppSingular } from './singular-consent';

export const connectSingularVendor = (onError: (error: unknown) => void) =>
	connectAppSingular(
		{
			limitDataSharing: (limit) => Singular.limitDataSharing(limit),
			resumeAllTracking: () => Singular.resumeAllTracking(),
			start: (limit) =>
				Singular.init(
					new SingularConfig(
						'YOUR_SDK_KEY',
						'YOUR_SDK_SECRET'
					).withLimitDataSharing(limit)
				),
			stopAllTracking: () => Singular.stopAllTracking(),
			trackingOptIn: () => Singular.trackingOptIn(),
		},
		onError
	);
```

Call `connectSingularVendor` at startup instead of `Singular.init`. On React Native's New Architecture, Singular documents `NativeSingular` from `singular-react-native/js/NativeSingular` with the same methods. Expo requires a development build that includes Singular's native module.

## Handle reset and teardown

Call `sync()` to reapply current consent and record another opt-in when allowed. Call `stop()`, `close()`, or `disconnect()` to stop tracking if Singular has started. Neither deletes data Singular already received.

On withdrawal, the helper calls both `stopAllTracking()` and `limitDataSharing(true)` even if one fails, and reports any error to `onError`.

## Verify Singular

1. Launch with no saved choice. Confirm Singular sends nothing and logs no initialization.
2. Grant `marketing`. Confirm Singular initializes, resumes tracking, records one opt-in, and sets `limitDataSharing` to `false`.
3. With `category` set to `measurement`, grant `measurement`, then toggle `marketing`. Confirm only `limitDataSharing` changes.
4. Withdraw consent. Confirm `isAllTrackingStopped()` returns `true` and a relaunch sends nothing.

Inth tests verify call order and category transitions against recorded stubs rather than a live Singular SDK. Checked SDK versions:

| Platform | Version | Verification |
| --- | --- | --- |
| React Native | `singular-react-native` 4.3.1 | Type-checked against published package types |
| Android | `singular_sdk` 12.17.0 | Signatures and pre-init behavior read from the published AAR |
| iOS | Singular iOS SDK 12.16.0 | Checked against the public `Singular.h` header |
