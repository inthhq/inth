The `appcues` helper blocks `AppcuesSettings` and the Appcues SDK until the visitor grants `experience` consent. On withdrawal, it calls `Appcues.reset()`, removes the loader, and reloads the page by default so the running SDK stops cleanly.

## Configure Appcues

Copy your account ID from the [Appcues installation snippet](https://docs.appcues.com/install-appcues-web/install-the-appcues-sdk), set `region: 'eu'` for EU accounts, and remove any existing Appcues snippet or tag-manager copy.

Inside `onReady`, read the signed-in user from your auth state, replace the `identify` placeholder with a real stable ID, call `group` after `identify` if needed, and skip these calls when signed out. Send `track` only for events that actually occurred. `onReady` runs once per successful loader load, including when consent is already granted at startup.

If sign-in finishes after `onReady`, check that `window.Appcues?.identify` exists, the user is signed in, and Inth allows both the script's category, `experience` by default, and the `appcues` vendor before calling `identify`.

## Options

| Option | Default | Behavior |
| --- | --- | --- |
| `accountId` | Required | Appcues account ID. Trimmed and URL-encoded as one path segment. Blank values log an error and skip loading. |
| `region` | `'us'` | `'us'` loads from `fast.appcues.com`, and `'eu'` loads from `fast.eu.appcues.com`. |
| `settings` | `{ enableURLDetection: true }` | JSON-serializable `AppcuesSettings` merged over the default, replacing any existing `window.AppcuesSettings`. Set `enableURLDetection: false` to track route changes yourself. |
| `scriptUrl` | `https://fast.appcues.com/<accountId>.js` | Proxy or custom account loader override. Blank values use the default. Affects only the account loader, not later SDK requests. |
| `onReady` | None | Synchronous callback run once per successful load after `window.Appcues` exists and while consent still holds. |

The helper has no `category` option or pre-consent load mode. To change the category, override `category` on the returned script object before registering it.

## Loading and revocation

On `experience` grant, Inth sets `AppcuesSettings` and loads your account loader, which buffers `identify`, `group`, and `track` calls until the runtime finishes loading. Inth creates no `AppcuesReady` global and skips `onReady` if the loader fails or does not set `window.Appcues`.

Revoking consent or removing a pending loader cancels its `onReady`. Recreating the helper before the download finishes swaps to the new callback. Recreating it after completion does not replay `onReady`. If `onReady` starts async work, recheck consent and auth after every `await`, timer, or event before calling Appcues.

On revocation, Inth calls [`Appcues.reset()`](https://docs.appcues.com/dev-api-data/javascript-api-developer) when available and removes the loader element. Because `reset()` clears user state and active flows without unloading the SDK, stopping listeners, or canceling in-flight scripts, keep `reloadOnConsentRevoked` enabled. Regranting after removal loads the SDK again without duplicating loaders.

## Cookies and storage

Documented in [Appcues' storage FAQ](https://docs.appcues.com/security-privacy/faq-required-cookies-local-storage-and-session-data):

| Storage | Keys |
| --- | --- |
| Local storage | `apc_ann_errors`, `apc_local_id`, `apc_user_id`, `apc_next_content_id` |
| Session storage | `apc_user`, `apc_debug_enabled`, `apc_debug_url`, `apc_curr_flow`, `apc_curr_checklist`, `apc_cl:{id}`, `apc_followed_test_link` |

Appcues can change keys across SDK releases, and `reset()` does not erase every key.

## Verify Appcues

In a fresh browser profile with your real account ID, filter Network by `appcues.com`:

1. Deny optional consent and allow `measurement` only. Confirm no Appcues requests, storage, or `Appcues`, `AppcuesSettings`, or `AppcuesReady` globals appear.
2. Allow `experience`. Confirm the account loader, runtime, and `onReady` run once and your flows target as configured.
3. Revoke `experience` while the loader downloads on a throttled network and confirm `onReady` does not run.
4. Revoke `experience` after load and confirm the page reloads with Appcues absent until regranted.
