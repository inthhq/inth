Connect PostHog capture to Inth `measurement` consent on [the web](#web) or in [Swift, Android, React Native, and Expo apps](#mobile). Web setup uses `@inth/integrations/posthog`; mobile helpers ship in `InthApple`, `inth-android`, and `@inth/react-native/integrations`.

## Web

By default, `posthog` loads `array.js` on every page with `loadMode: 'always'`, calling `opt_out_capturing()` while `measurement` is denied and `opt_in_capturing()` when allowed. Default `cookieless_mode: 'on_reject'` switches PostHog to cookieless capture after refusal. Set `loadMode: 'after-consent'` to block `array.js` until consent is granted, and `cookieless_mode: 'never'` to stop capture on refusal.

### Configure PostHog

Install `@inth/integrations` and create `src/consent-scripts.ts` with your `phc_` project token and region:

<CommandTabs command="@inth/integrations" mode="install" />

```ts title="src/consent-scripts.ts"
import { posthog } from '@inth/integrations/posthog';

export const scripts = [
	posthog({
		id: 'phc_YOUR_PROJECT_TOKEN',
		region: 'eu',
		loadMode: 'after-consent',
		initOptions: { cookieless_mode: 'never' },
	}),
];
```

Remove any standalone `posthog-js` initializer, framework plugin, or array snippet. If your app already bundles `posthog-js`, follow [use an existing PostHog SDK](#use-an-existing-posthog-sdk) instead.

### Options

| Option | Default | Behavior |
| --- | --- | --- |
| `id` | Required | Project token starting with `phc_`. Trimmed automatically; blank values log an error and skip loading. |
| `region` | `'eu'` | `'eu'` or `'us'`. Selects default API, UI, and loader hosts. |
| `apiHost` | `https://eu.i.posthog.com` | Custom API host or reverse proxy. Without `scriptUrl`, the loader URL becomes `<apiHost>/static/array.js`. |
| `uiHost` | Region UI host | UI host such as `https://eu.posthog.com`. Defaults to `apiHost` when set without `region`. |
| `scriptUrl` | `https://eu-assets.i.posthog.com/static/array.js` | Loader URL override. Blank values fall back to the default. |
| `loadMode` | `'always'` | `'always'`, `'after-consent'`, or `'disabled'`. |
| `features.surveys` | Unset | `false` sets `disable_surveys: true` and skips `surveys.js`. |
| `features.heatmaps` | Unset | Sets `capture_heatmaps`. |
| `features.deadClicks` | Unset | Sets `capture_dead_clicks`. |
| `features.webVitals` | Unset | Sets `capture_performance: { web_vitals }`. |
| `features.featureFlags` | Unset | `false` sets `advanced_disable_feature_flags: true` and stops `/flags` requests. |
| `initOptions` | `{ cookieless_mode: 'on_reject', defaults: '2026-01-30' }` | Passed to `posthog.init`, merged over defaults and `features`. Set hosts with `apiHost` and `uiHost` instead. |

### Loading and revocation

| `loadMode` | When PostHog loads | Consent sync |
| --- | --- | --- |
| `'always'` | Every page, before consent | Calls `opt_in_capturing` or `opt_out_capturing` at load and on every change |
| `'after-consent'` | Only while `measurement` is allowed | Calls `opt_in_capturing` at load and `opt_out_capturing` on revocation |
| `'disabled'` | Never | None; returns an empty callback-only script |

With `'after-consent'`, if refusal arrives while `array.js` is still downloading, Inth removes the element and clears PostHog's queued init so no events fire or cookies write. Default `cookieless_mode: 'on_reject'` requires server hashing enabled in PostHog; see [PostHog's cookieless guide](https://posthog.com/tutorials/cookieless-tracking). Pass `cookieless_mode: 'never'` to stop capture on refusal.

### Turn off features you do not use

Disable unused PostHog modules through `features` to cut bundle size and network requests:

{/* example: fragment */}

```ts
posthog({
	id: 'phc_YOUR_PROJECT_TOKEN',
	region: 'eu',
	loadMode: 'after-consent',
	features: {
		surveys: false,
		heatmaps: false,
		deadClicks: false,
		webVitals: false,
		featureFlags: false,
	},
});
```

| Switch | `false` sets | What PostHog skips |
| --- | --- | --- |
| `surveys` | `disable_surveys: true` | `surveys.js`, about 29 KB brotli |
| `heatmaps` | `capture_heatmaps: false` | Heatmap capture; with `deadClicks: false`, also `dead-clicks-autocapture.js` |
| `deadClicks` | `capture_dead_clicks: false` | `dead-clicks-autocapture.js`, about 8 KB, when heatmaps are also off |
| `webVitals` | `capture_performance: { web_vitals: false }` | `web-vitals-with-attribution.js`, about 6 KB |
| `featureFlags` | `advanced_disable_feature_flags: true` | `/flags` requests; remote config still loads |

Option caveats:

- Use `advanced_disable_feature_flags: true`, not `advanced_disable_flags: true`, which disables remote config and stops Session Replay.
- Turning off feature flags stops flag-targeted surveys. Leave `featureFlags` unset and pass `advanced_only_evaluate_survey_feature_flags: true` in `initOptions` if you need them.
- `surveys.js` still downloads unless `surveys: false` is set. Both `heatmaps: false` and `deadClicks: false` are required to skip `dead-clicks-autocapture.js`.
- Pass `disable_product_tours: true` or `capture_exceptions: false` in `initOptions` to disable those modules regardless of project settings.

### Guard your own capture calls

`window.posthog` exists before the SDK loads, so check current `measurement` permission from your framework, such as `useConsent('measurement')` in React, before calling `capture`:

```ts title="src/track-signup.ts"
export function trackSignupStarted(measurementAllowed: boolean) {
	if (!measurementAllowed) return;
	window.posthog?.capture('signup_started');
}
```

### Use an existing PostHog SDK

If your app already bundles `posthog-js`, initialize it with `opt_out_capturing_by_default: true` and `cookieless_mode: 'never'`, then register a callback-only script instead of the helper:

```ts title="src/posthog-consent.ts"
import type { Script, ScriptCallbackInfo } from '@inth/react';

type PostHogConsentApi = {
	opt_in_capturing: () => unknown;
	opt_out_capturing: () => unknown;
};

export function posthogConsent(instance: PostHogConsentApi): Script {
	const sync = ({ hasConsent }: ScriptCallbackInfo) => {
		if (hasConsent) instance.opt_in_capturing();
		else instance.opt_out_capturing();
	};

	return {
		id: 'posthog-sdk-consent',
		category: 'measurement',
		callbackOnly: true,
		alwaysLoad: true,
		onBeforeLoad: sync,
		onConsentChange: sync,
	};
}
```

Add `posthogConsent(posthog)` to your `scripts` array. `callbackOnly: true` skips script injection, and `alwaysLoad: true` runs `sync` on first load even while denied. Pass module-disabling options from [turn off features you do not use](#turn-off-features-you-do-not-use) directly to your own `posthog.init`.

For banner experiment tracking in PostHog, forward `onSurfaceShown` and `onChoiceRecorded` as shown in [banner experiments](/docs/guides/banner-experiments#send-the-events-to-your-own-analytics-too).

### Verify PostHog

With `loadMode: 'after-consent'`, allow `measurement` and confirm `array.js` loads and capture requests reach your API host. Trigger a guarded event and verify it sends. With `loadMode: 'always'`, `array.js` loads immediately; confirm no capture requests fire while denied unless cookieless capture is enabled. If you disabled `features`, filter DevTools Network by `posthog` and confirm disabled modules and `/flags` are absent.

## Mobile

The bundled mobile helper keeps your configured PostHog client in sync with Inth's `measurement` category: opting in when granted and opting out while pending, denied, or closed.

**Prerequisites**
- Complete the [Swift](/docs/frameworks/swift/quickstart), [Android](/docs/frameworks/android/quickstart), or [React Native](/docs/frameworks/react-native/quickstart) quickstart. Mobile packages are in private prerelease; see mobile availability for [Swift](/docs/frameworks/swift/availability), [Android](/docs/frameworks/android/availability), or [React Native](/docs/frameworks/react-native/availability).
- Install PostHog using its [iOS](https://posthog.com/docs/libraries/ios), [Android](https://posthog.com/docs/libraries/android), or [React Native](https://posthog.com/docs/libraries/react-native) guide.
- Keep session replay, surveys, error capture, and lifecycle autocapture disabled initially until scoped separately.

### Startup rules

Set `optOut = true` in native config or `defaultOptIn: false` in React Native. Earlier persisted opt-ins override defaults, so reconcile with Inth on every launch.

Opt-out stops event capture, not remote config or `/flags` requests. If your policy forbids all PostHog traffic before consent, defer constructing the client behind a [native startup gate](/docs/frameworks/react-native/native-behaviour), then connect the helper once created. For Expo, rebuild the native binary; Expo Go does not load Inth's native engine.

### Connect a Swift app

Add `PostHogOwner.swift` to your app target:

<include src="../shared/examples/native/core-swift/AppleInstallation/swift-posthog-binding.mdx" />

Construct and retain one `PostHogOwner` on your app's service owner after installing Inth and configuring PostHog:

{/* example: fragment */}

```swift
import PostHog

let posthogOwner = PostHogOwner(
    core: core,
    optIn: { PostHogSDK.shared.optIn() },
    optOut: { PostHogSDK.shared.optOut() }
)
```

Pass the direct vendor calls without dispatching async tasks so grants and withdrawals stay ordered. Releasing the owner cancels observation and opts out.

### Connect an Android app

Add this helper to your Kotlin source directory:

<include src="../shared/examples/native/examples/consent-demo/android-posthog-integration.mdx" />

Call it after native installation and retain `posthogConsent` on your application or service owner, not an Activity:

{/* example: fragment */}

```kotlin
import com.posthog.PostHog

val posthogConsent = connectAppPostHog(
	optIn = { PostHog.optIn() },
	optOut = { PostHog.optOut() },
	onError = ::reportAnalyticsError,
)
```

`onError` receives vendor exceptions during consent updates and must not throw. Handle exceptions from construction, `sync()`, and `close()` at their call sites.

### Connect React Native or Expo

Add this helper to `posthog-consent.ts`:

<include src="../shared/examples/react-native-bare/rn-posthog-integration.mdx" />

Retain one app-lifetime connection and await `ready` during startup:

{/* example: fragment */}

```ts
const posthogConsent = connectAppPostHog(posthog, reportAnalyticsError);
await posthogConsent.ready;
```

When creating the React Native client, disable extra automatic features:

{/* example: fragment */}

```ts
import { PostHog } from 'posthog-react-native';

const posthog = new PostHog('YOUR_POSTHOG_PROJECT_TOKEN', {
	host: 'https://eu.i.posthog.com',
	defaultOptIn: false,
	preloadFeatureFlags: false,
	disableRemoteFeatureFlags: true,
	enableSessionReplay: false,
	captureAppLifecycleEvents: false,
	disableSurveys: true,
});
```

Handle errors in `onError` and on `ready`, `sync()`, and `disconnect()` promises. If opt-out fails, do not assume capture stopped.

### Reset, teardown, and verification

After calling PostHog's reset API, call `syncAfterReset()` in Swift, `sync()` in Kotlin, or `await posthogConsent.sync()` in React Native to reapply current permission without recording a new choice. For final teardown, call `stop()`, `close()`, or `disconnect()`. Opt-out does not delete historical or already-queued events.

Verify on a real build using mobile verification for [Swift](/docs/frameworks/swift/verify), [Android](/docs/frameworks/android/verify), or [React Native](/docs/frameworks/react-native/verify):

1. Launch with no saved choice and confirm capture stays opted out while pending and after Reject all.
2. Grant `measurement`, confirm opt-in, and capture a test event.
3. Withdraw `measurement` and confirm new capture calls are refused.
4. Relaunch after both grant and refusal to verify persisted PostHog state and native startup.
5. Reset PostHog, call `sync()`, and confirm permission reapplies without writing a new consent record.
