The `snapchatPixel` helper keeps the Snapchat Pixel off the page and leaves `window.snaptr` undefined until a visitor grants `marketing` consent. It sends no consent signal to Snapchat. On revocation, Inth removes the script element and reloads the page by default.

## Configure the Snapchat Pixel

Copy your pixel ID from Snapchat Ads Manager and remove any existing pixel snippet or tag manager entry, then install `@inth/integrations`:

<CommandTabs command="@inth/integrations" mode="install" />

{/* example: fragment */}

```ts title="src/consent-scripts.ts"
import { snapchatPixel } from '@inth/integrations/snapchat-pixel';

export const scripts = [snapchatPixel({ pixelId: 'YOUR_PIXEL_ID' })];
```

## Options

| Option | Default | Behavior |
| --- | --- | --- |
| `pixelId` | Required | Pixel ID passed to `snaptr('init', ...)`. Trimmed automatically; blank values log an error and skip loading. |
| `initOptions` | None | Object passed as the third argument to `snaptr('init', ...)`, such as `user_email`. Pass user data only when your app has permission to share it. |
| `trackPageView` | `true` | Queues `snaptr('track', 'PAGE_VIEW')` after `init`. Set `false` to send page views yourself. |
| `scriptUrl` | `https://sc-static.net/scevent.min.js` | Loader URL override. Blank values fall back to the default. |

## Loading and revocation

`snapchatPixel` gates on `marketing`. Before a visitor allows `marketing`, Inth defines no `window.snaptr` and makes no Snapchat request. Once allowed, the helper queues `init` and optional `PAGE_VIEW`, then loads `scevent.min.js`.

On revocation, Inth removes the script element without calling a Snapchat API, so `window.snaptr` stays defined until the default page reload unloads the pixel.

## Guard your own snaptr calls

Because `window.snaptr` stays defined after revocation, check current `marketing` permission from your framework, such as `useConsent('marketing')` in React, before sending events like `PURCHASE` or `SIGN_UP`:

```ts title="src/track-purchase.ts"
export function trackPurchase(marketingAllowed: boolean, orderId: string) {
	if (!marketingAllowed || typeof window.snaptr !== 'function') return;
	window.snaptr('track', 'PURCHASE', {
		client_dedup_id: orderId,
		currency: 'USD',
		price: 99,
		transaction_id: orderId,
	});
}
```

Set `client_dedup_id` to deduplicate against the Conversions API. `@inth/integrations/snapchat-pixel` also exports `snapchatPixelEvent`, a typed wrapper around `snaptr('track', ...)`. It no-ops until `snaptr` exists and does not check consent itself, so guard it with your permission check too.

## Verify the Snapchat Pixel

Allow `marketing` and confirm `scevent.min.js` loads from `sc-static.net` with one `PAGE_VIEW` request. If your router also sends `PAGE_VIEW`, confirm the initial page fires once. Trigger a guarded event and verify its request appears, then revoke `marketing` and confirm `trackPurchase` sends nothing before reload.
