The `vercelSpeedInsights` helper keeps the Vercel Speed Insights collector off the page until a visitor grants `measurement` consent. It registers a `beforeSend` callback that drops Web Vitals reports whenever `measurement` is denied, including after revocation while the collector stays in memory before reload.

## Configure Vercel Speed Insights

Enable Speed Insights for your project in Vercel, then remove any `SpeedInsights` component or `injectSpeedInsights()` call from `@vercel/speed-insights`. The collector initializes once per page, so a second copy loaded outside Inth keeps reporting before consent.

{/* example: fragment */}

```ts title="src/consent-scripts.ts"
import { vercelSpeedInsights } from '@inth/integrations/vercel-speed-insights';

export const scripts = [vercelSpeedInsights()];
```

## Options

| Option | Default | Behavior |
| --- | --- | --- |
| `dsn` | None | Project DSN for deployments outside Vercel, set as `data-dsn`. Sends reports to Vercel's vitals endpoint for that DSN. |
| `mode` | None | `'development'` loads the debug script. `'auto'` and `'production'` load the production script. The helper does not detect your environment. |
| `debug` | None | `true` loads `https://va.vercel-scripts.com/v1/speed-insights/script.debug.js`, which logs reports to the console without sending network requests. |
| `endpoint` | None | Custom vitals endpoint set as `data-endpoint`. |
| `scriptUrl` | `https://va.vercel-scripts.com/v1/speed-insights/script.js` | Loader URL override, such as `/_vercel/speed-insights/script.js` on Vercel. Takes precedence over `mode` and `debug`. |
| `sampleRate` | `1` | Share of page loads that report, from `0` to `1`, set as `data-sample-rate`. Out-of-range values throw a `TypeError`. |
| `beforeSend` | None | Edits or drops reports while `measurement` is allowed. Return the modified event or `null` to drop it. |

The helper sets `data-sdkn="inth"` on the script element. Without `dsn` or `endpoint`, the collector posts to `/_vercel/speed-insights/vitals` on your origin, which exists only on Vercel deployments with Speed Insights enabled.

## Loading and revocation

`vercelSpeedInsights` gates on `measurement`. On grant, the helper defines `window.siq` and `window.si` if absent, registers its `beforeSend` guard, and loads the collector.

Removing the script element does not stop the collector's listeners or queued `pagehide` reports. On revocation, Inth removes the script element and switches `beforeSend` to return `null`, blocking all reports including during reload. Regranting consent re-adds the script without starting a second collector and resumes reporting. Unmounting the owning consent provider also stops reports.

The collector supports one `beforeSend` callback. Pass yours through the helper's `beforeSend` option; calling `window.si('beforeSend', ...)` directly overwrites Inth's consent guard.

When a framework boots allowed scripts from server HTML, the collector starts before hydration and Inth attaches its callback at hydration. If you pass a custom `beforeSend` option, the collector waits for hydration so your callback inspects every report.

Reports cover page loads after consent only: the collector reads buffered paint and navigation timings, but misses interactions from before consent. Because the helper omits `data-route`, Vercel groups reports by URL rather than route patterns like `/blog/[slug]`.

## Verify Vercel Speed Insights

Filter DevTools Network by `speed-insights`:

1. Allow `measurement` and confirm `script.js` loads from `va.vercel-scripts.com` with `data-sdkn="inth"`.
2. Change routes or switch tabs and confirm a `POST` request goes to `/_vercel/speed-insights/vitals`. Automated browsers with `navigator.webdriver` load the script without sending reports, and `debug: true` or `mode: 'development'` logs reports to the console instead.
