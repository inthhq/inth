Use the [web integration](#web) for browser error monitoring, user data, and Session Replay. In [Swift, Android, React Native, and Expo apps](#mobile), the bundled helper controls manual Session Replay only while your app owns crash reporting, profiling, and user data.

## Web

With `dsn` and the default `loadMode: 'always'`, `sentry` loads the Sentry CDN bundle before consent under `necessary`. While `measurement` is denied, events omit user data, cookies, headers, and inferred IP, and Replay stays off. With `loadMode: 'after-consent'`, Sentry runs only while `measurement` is allowed.

### Use your own Sentry SDK

Supported browser SDKs are `^10.67.0 || ^11.0.0`, including framework SDKs. Version `10.67.0` added `stop({ flush: false })` to discard pending recordings on withdrawal.

Split Replay into its own module:

```ts title="src/sentry-replay.ts"
import { replayIntegration } from '@sentry/browser';

export const createReplay = () =>
	replayIntegration({ maskAllText: true, blockAllMedia: true });
```

Pass your SDK functions instead of `dsn` in `src/consent-scripts.ts`:

{/* example: fragment */}

```ts
import { getClient, init, setUser } from '@sentry/browser';

sentry({
	getClient,
	init,
	setUser,
	initOptions: {
		dsn: 'https://your-key@o0.ingest.sentry.io/0',
		replaysSessionSampleRate: 0.1,
		replaysOnErrorSampleRate: 1,
	},
	replay: {
		load: () => import('./sentry-replay').then((m) => m.createReplay()),
	},
});
```

Passing `init` protects startup captures. Use named imports from one Sentry package so Next.js and Vite split Replay; esbuild, Bun, and `import * as Sentry` keep it in the main bundle.

If your app calls `Sentry.init` independently, disable collection and strip users at startup, omitting `queues` on SDK `10.67`:

{/* example: fragment */}

```ts
maxBreadcrumbs: 0,
dataCollection: {
	userInfo: false,
	cookies: false,
	httpHeaders: { request: false, response: false },
	httpBodies: [],
	urlQueryParams: false,
	graphQL: { document: false, variables: false },
	genAI: { inputs: false, outputs: false },
	databaseQueryData: false,
	queues: false,
	stackFrameVariables: false,
	frameContextLines: 0,
},
beforeSend(event) {
	delete event.user;
	delete event.request;
	return event;
},
```

Check Inth permission in `beforeSend` to restore event users after consent.

### Options

| Option | Default | Behavior |
| --- | --- | --- |
| `dsn` | Required for CDN | Project DSN. Blank values log an error and load nothing. |
| `initOptions` | `{}` | Passed to `Sentry.init` with Inth's consent integration first. |
| `version` | `'11.4.0'` | Exact Sentry CDN release version. |
| `tracing` | `true` when sampled | Loads tracing bundle and adds `browserTracingIntegration()`. |
| `replay` | CDN when sampled | CDN: `{ category, options }` or `false`. SDK: `{ category, load }`. |
| `getClient` | Required for SDK | Your SDK's `getClient`. |
| `setUser` | None | Called with `null` when user data is denied. Required with `pii.user`. |
| `init` | None | Called once when `loadMode` allows. Required for SDK `'after-consent'`. |
| `replay.load` | None | Returns a new `replayIntegration()` on first grant. |
| `loadMode` | `'always'` | `'always'` runs errors pre-consent; `'after-consent'` gates everything on `measurement`. |
| `replay.category` | `'measurement'` | Consent condition for Replay; requires `pii.category` too. |
| `pii.category` | `'measurement'` | Condition for `dataCollection` and user data; `'necessary'` allows it while vendor `sentry` is enabled. |
| `pii.user` | None | Returns the user object for `setUser` once allowed. |
| `onError` | Active client | Receives CDN and Replay lifecycle errors. |

Replay's category registers only with SDK `replay.load` or a positive CDN sample rate.

### Loading, revocation, and CSP

Replay requires both `replay.category` and `pii.category` because recordings capture URL queries and fragments. Keep Replay out of `Sentry.init` so `replaysOnErrorSampleRate` cannot buffer early. On denial or final removal, Inth calls `stop({ flush: false })`, discards queued uploads, and blocks restarts. While PII is denied, Inth disables `dataCollection` and IP inference and strips users, feedback contacts, session visitor IDs, request data, and URL queries or fragments. Tracing is not gated; keep sensitive data out of messages, tags, extras, attachments, and paths.

The vendor slug is `sentry`; disabling it denies Replay, PII, and `'after-consent'` errors. See [vendor consent](/docs/integrations/overview#vendor-switches-and-cookie-cleanup). Keep callbacks stable; all active configs on one client must allow each feature, changed CDN options reinit the client while reusing Replay, and an app-initiated `Sentry.close()` stays closed.

Allow `worker-src blob:`, your ingest URL in `connect-src`, and `https://browser.sentry-cdn.com` in `script-src` for CDN mode. Provider or loader `nonce` applies to both bundles.

### Verify Sentry

In a private window with an opt-in policy and `replaysSessionSampleRate: 1`, filter Network by `sentry`:

1. Load the page. `bundle.min.js` loads and errors omit `user`, with no Replay requests. In `'after-consent'` mode, nothing loads.
2. Allow `measurement`. Replay loads without a reload and sends `replay_recording` requests.
3. Withdraw `measurement`. Inth reloads the page and no replay requests follow.

See [verify consent](/docs/guides/verify-consent).

## Mobile

The bundled Sentry Replay helper in `InthApple`, `inth-android`, and `@inth/react-native/integrations` starts manual Session Replay when its category, `measurement` by default, is allowed and stops it when pending or denied. Your app installs Sentry and owns crash reporting, profiling, and user data.

Complete the [Swift](/docs/frameworks/swift/quickstart), [Android](/docs/frameworks/android/quickstart), or [React Native](/docs/frameworks/react-native/quickstart) quickstart and add your replay category to your native config and Inth policy. See [mobile availability](/docs/guides/mobile-status). Checked versions are Sentry Cocoa `9.32.0`, Android `8.62.0`, and React Native `8.33.0`. Android Replay requires API 26+, while Inth supports API 24+. Set session and error replay sample rates to `0` before initializing Sentry, including native init before JavaScript, and keep default masking until tested.

### Connect Swift

<include src="../shared/examples/native/core-swift/AppleInstallation/swift-sentry-replay-binding.mdx" />

Set `sessionSampleRate = 0` and `onErrorSampleRate = 0`, then retain the owner on your app's service owner and call `stop()` on teardown:

{/* example: fragment */}

```swift
import Sentry

let replayOwner = SentryReplayOwner(
    core: core,
    start: { SentrySDK.replay.start() },
    stop: { SentrySDK.replay.stop() }
)
```

### Connect Android

<include src="../shared/examples/native/examples/consent-demo/android-sentry-replay-integration.mdx" />

Set `sessionSampleRate = 0.0` and `onErrorSampleRate = 0.0`, connect on your app or service owner, keep `onError` non-throwing, and call `close()` on teardown:

{/* example: fragment */}

```kotlin
import io.sentry.Sentry

val replayConsent = connectAppSentryReplay(
	start = { Sentry.replay().start() },
	stop = { Sentry.replay().stop() },
	onError = ::reportReplayError,
)
```

### Connect React Native or Expo

Set `replaysSessionSampleRate: 0` and `replaysOnErrorSampleRate: 0`, follow [Sentry's manual control guide](https://docs.sentry.io/platforms/react-native/session-replay/#manual-control), and keep `avoidForegroundResumeHang` disabled. Expo requires a custom native build, not Expo Go.

<include src="../shared/examples/react-native-bare/rn-sentry-replay-integration.mdx" />

Connect after Sentry initializes and retain the handle for the app lifetime:

{/* example: fragment */}

```ts
import * as Sentry from '@sentry/react-native';

const replay = Sentry.getReplay();
if (!replay) {
	throw new Error('Configure Sentry Session Replay before connecting Inth.');
}
const replayConsent = connectAppSentryReplay(replay, reportReplayError);
await replayConsent.ready;
```

### Reset, teardown, and verify

Call `syncAfterReset()` on Swift, `sync()` on Android, or `await replayConsent.sync()` on React Native after a vendor reset or new Sentry session. Call `stop()`, `close()`, or `disconnect()` only for final teardown. Stopping can still send a final segment and does not flush, delete historical recordings, or change crash reporting.

With both sample rates at `0`, verify pending and rejected launches buffer nothing, grant starts capture, withdrawal stops new capture, and masking works on sensitive screens. Complete [mobile verification](/docs/guides/mobile-verify).
