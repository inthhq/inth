The `gainsightPx` helper waits for `measurement` consent before creating `window.aptrinsic` or loading the Gainsight PX SDK, gating both product analytics and in-app engagements. On withdrawal, Inth disables the tag via PX's config API and requests a session reset.

## Configure Gainsight PX

Copy your product/channel key from **Administration > Products** in Gainsight PX. Remove any existing PX snippet or tag-manager copy so it loads only through Inth.

## Options

| Option | Default | Behavior |
| --- | --- | --- |
| `productKey` | Required | Product/channel key assigned to `aptrinsic.p` and the loader's `a` query param. Blank values log an error and skip loading. Changing it after startup throws until reload. |
| `category` | `'measurement'` | Consent category or condition for the SDK. Set `'experience'` if that matches your classification. |
| `config` | None | JSON-serializable PX startup config assigned to `aptrinsic.c`, such as `fullDomainCookie`, `localStorageCookie`, `usePOST`, and `htmlSanitization`. Changing it after startup throws until reload. Do not set `enableTag`; Inth owns it. |
| `user` | None | User identify payload with required `id`. Queued only after mapped consent. |
| `account` | None | Optional account identify payload with required `id`. Sent only when `user` is also provided. |
| `scriptUrl` | `https://web-sdk.aptrinsic.com/api/aptrinsic.js?a=<productKey>` | Loader URL override. Subsequent PX requests still use SDK-configured endpoints. |

Keep `config`, `user`, and `account` JSON-serializable, pass dates as epoch milliseconds, and use API attribute names from **Administration > Attributes**:

{/* example: fragment */}

```ts
// Options for gainsightPx in src/consent-scripts.ts.
{
	productKey: 'AP-PRODUCT-KEY-2',
	category: 'experience',
	config: { fullDomainCookie: true },
	user: { id: 'user-123', plan: 'paid' },
	account: { id: 'account-456' },
}
```

For logins or account changes after initial setup, gate your own `aptrinsic('identify', ...)` calls on current consent and vendor permission.

## Loading and revocation

Before mapped consent, the helper creates no `window.aptrinsic` global, loader element, cookies, or `localStorage` entries. It does not support an `enableTag: false` early-loading mode.

On grant, Inth creates the official `aptrinsic` queue with `p` and `c`, enables the tag, optionally queues `identify`, and inserts the async loader. PX may track anonymously before a queued `identify` completes.

On withdrawal, Inth calls `aptrinsic('config', 'enableTag', false)` and `aptrinsic('reset')`, removing the loader only if it is still downloading or failed to load. Once loaded, the element stays so a regrant (when `reloadOnConsentRevoked: false`) can call `enableTag: true` and re-identify without re-executing the bundle, which PX rejects. Pending loads aborted before execution rebuild a fresh queue from current options so stale `identify` calls are not replayed.

- **Server hydration.** Pass matching `productKey`, `config`, `user`, `account`, and `scriptUrl` on server and client (object property order does not matter). A mismatch throws before registration and keeps the existing setup intact; reload if identity changed before hydration.
- **Locked `productKey` and `config`.** Once started, both stay locked for the page lifetime, including after disposal. Reload to change them, because PX's async `tagKey` API can defer opt-out behind queued calls. Object-spread copies such as `{ ...gainsightPx(options), anonymizeId: false }` preserve the runtime reuse check.
- **Single SDK per page.** Mount one Gainsight PX configuration at a time. Disposal removes the loader element but does not disable PX; keep a consent owner mounted while PX runs.
- **Keep `reloadOnConsentRevoked` enabled.** Reloading ends PX timers and listeners and avoids duplicate-bundle races with detached downloads.

## Cookies and storage

| Name | Lifetime | Purpose |
| --- | --- | --- |
| `apt.uid` | 1 year | Persistent visitor identity. |
| `apt.sid` | 30 minutes of inactivity | Current session identity. |

`fullDomainCookie: true` scopes cookies to the exact hostname instead of the top-level domain, and `localStorageCookie: true` stores them in `localStorage`. Neither setting replaces the consent gate.

## Verify Gainsight PX

Test in a private window:

1. Deny analytics and confirm no requests go to `web-sdk.aptrinsic.com` or `esp.aptrinsic.com`, `window.aptrinsic` is undefined, and neither `apt.uid` nor `apt.sid` is set.
2. Allow the configured `category` and confirm the SDK loads and sends events to your PX product.
3. Withdraw that category and confirm the reloaded page makes no PX requests.

The helper already sends PX's opt-out command; add a custom stop callback only if you need extra cleanup.
