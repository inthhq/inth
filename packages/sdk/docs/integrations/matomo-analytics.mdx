The `matomoAnalytics` helper keeps Matomo off the page until `measurement` consent is granted. Set `defaultConsent` to load `matomo.js` on every page and drive Matomo's consent API instead, calling `requireConsent`, `setConsentGiven`, and `forgetConsentGiven` as consent changes.

## Configure Matomo Analytics

Copy your site ID and Matomo URL from your Matomo tracking code, then remove that snippet from your app so Matomo loads only through Inth. For Matomo Cloud, pass `cloudId` such as `'your-site.matomo.cloud'` instead of `matomoUrl`.

<CommandTabs command="@inth/integrations" mode="install" />

{/* example: fragment */}

```ts title="src/consent-scripts.ts"
import { matomoAnalytics } from '@inth/integrations/matomo-analytics';

export const scripts = [
	matomoAnalytics({ matomoUrl: 'https://analytics.example.com', siteId: 1 }),
];
```

## Options

| Option | Default | Behavior |
| --- | --- | --- |
| `matomoUrl` | None | Your Matomo server base URL. Loads `<matomoUrl>/matomo.js` and sends hits to `<matomoUrl>/matomo.php`. |
| `cloudId` | None | Matomo Cloud ID, used when `matomoUrl` is unset. Values ending in `.matomo.cloud` load `https://cdn.matomo.cloud/<cloudId>/matomo.js` and track to `https://<cloudId>/matomo.php`; other values resolve both to `https://cdn.matomo.cloud/<cloudId>`. |
| `trackerUrl` | `matomo.php` on the Matomo origin | Tracker endpoint override. |
| `scriptUrl` | `matomo.js` on the Matomo origin | Loader URL override. Without `matomoUrl` or `cloudId`, set both `trackerUrl` and `scriptUrl` or the helper logs an error and skips loading. |
| `siteId` | `1` | Site ID queued with `setSiteId`. |
| `trackPageView` | `true` | Queues `trackPageView` according to the mode table below. |
| `enableLinkTracking` | `false` | Queues `enableLinkTracking`. |
| `disableCookies` | `false` | Queues `disableCookies`. Does not change when Matomo loads. |
| `defaultConsent` | None | `'required'` or `'given'` switches to Matomo consent mode. |

## Loading and revocation

`matomoAnalytics` gates on the `measurement` category. `defaultConsent` selects the loading mode:

| `defaultConsent` | Loads | When `measurement` is allowed | On revocation |
| --- | --- | --- | --- |
| Omitted | After `measurement` is allowed, with `trackPageView` queued | Loads `matomo.js` | Removes the script element and calls no Matomo API |
| `'required'` | On every page, with `requireConsent` queued | Queues `setConsentGiven` and `trackPageView` | Keeps the script and queues `forgetConsentGiven` |
| `'given'` | On every page; queues `setConsentGiven` and `trackPageView` if allowed on load, otherwise `requireConsent` | Queues `setConsentGiven` and `trackPageView` | Keeps the script and queues `forgetConsentGiven` |

In both consent modes, Matomo holds tracking until `setConsentGiven`, which the helper queues only while `measurement` is allowed. For a visitor who already allowed `measurement` on load, `'given'` skips the initial `requireConsent`. The helper queues another `trackPageView` only when `measurement` changes from denied to allowed, so toggling another category sends no extra page view. Matomo separates [tracking consent from cookie consent](https://developer.matomo.org/guides/tracking-consent).

## Verify Matomo Analytics

Without `defaultConsent`, allow `measurement` and confirm `matomo.js` loads and a `matomo.php` request carries the page view.

<include src="../shared/integrations/vendor-revocation-and-verify.mdx" />

With `defaultConsent: 'required'` or `'given'`, test in a private window with an opt-in policy:

1. Load the page. `matomo.js` loads with no `matomo.php` request.
2. Open Privacy settings and allow `measurement`. A `matomo.php` request carries the page view without a reload.
3. Turn `measurement` off and save. Inth reloads the page, and `matomo.js` loads without a `matomo.php` request.

Under an opt-out policy, or after the visitor already allowed `measurement`, both modes send a `matomo.php` page view on load. See [consent verification](/docs/guides/verify-consent) for navigation and hosting checks.
