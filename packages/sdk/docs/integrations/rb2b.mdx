The `rb2b` helper keeps RB2B visitor identification off the page until `marketing` is granted. RB2B has no documented stop API, so on withdrawal Inth reloads the page to stop it.

## Configure RB2B

Authorize your domain first. Open [Script in RB2B](https://app.rb2b.com/script), select **Add a Domain**, enter your domain, and save. A root domain includes its subdomains; an individual hostname authorizes only that hostname.

Copy your account key from Script Setup where the snippet calls `reb2b.load`, then remove any direct snippet or tag-manager copy. This helper uses `marketing` consent even though some RB2B documentation labels its cookies functional.

## Options

| Option | Default | Behavior |
| --- | --- | --- |
| `accountKey` | Required | Public account key, trimmed and URL-encoded. Blank or invalid values log an error and skip loading. |
| `scriptUrl` | `https://ddwl4m2hdecbv.cloudfront.net/b/<key>/<key>.js.gz` | Override for the dashboard snippet URL. Blank values use the default; unsupported URLs log an error and skip loading. |

Supported HTTPS prefixes for `scriptUrl` are `ddwl4m2hdecbv.cloudfront.net/b/`, `s3-us-west-2.amazonaws.com/b2bjsstore/b/`, and `b2bjsstore.s3.us-west-2.amazonaws.com/b/`. The account segment must immediately follow the base path and match `accountKey` exactly after one percent-decode. Account keys are case-sensitive, while percent-escape hex digits can use either case. The pathname must end with a non-empty filename after the account separator. Extensionless filenames, query strings, and fragments are allowed, though a query or fragment cannot supply the filename. Serving an unchanged RB2B SDK from an arbitrary proxy fails RB2B's `document.currentScript.src` check.

## Loading and revocation

After consent, the helper loads the account script asynchronously without creating `window.reb2b`, a stub queue, or `rb2bConfig`. The account script creates `window.reb2b` itself and ignores calls queued beforehand, so do not add your own stub for early `identify` or `collect` calls. RB2B can delay startup by three seconds and sends once per script execution.

The loader stays registered across withdrawal and regrant to prevent duplicate execution. Because RB2B has no documented stop or opt-out API, keep `reloadOnConsentRevoked` enabled. Without a reload, active timers, identity lookups, and in-flight loads continue until navigation. Reloading does not clear RB2B storage.

CSP requirements depend on account settings. Observed hosts include your CloudFront or S3 loader, `b-code.liadm.com`, `pro.ip-api.com`, `a.usbrowserspeed.com`, `alocdn.com`, and account-specific `*.execute-api.us-west-2.amazonaws.com` endpoints.

## Page views in client-routed apps

[RB2B's installation guide](https://support.rb2b.com/en/articles/10126115-installing-your-rb2b-tracking-script) recommends running its script on every page view. This helper runs once per document load and does not rerun on client-side route transitions.

To record a new page view, use full-page navigation: render a native `<a href="/pricing">` instead of `next/link` or a Vue/Nuxt router link, or call `window.location.assign('/pricing')` for imperative navigation. Register Inth and the same `rb2b` configuration on every destination page so Inth checks `marketing` and vendor consent on each load.

Full-page navigation resets page-local state. Hash-only changes and back/forward cache restores do not trigger a new RB2B page view. If you keep client-side navigation, RB2B covers only the initial page load. Do not change `accountKey` or `scriptUrl`, delete `window.reb2b`, or call `reb2b.collect()` in a route hook; the SDK freezes its client and retains per-execution state.

## Cookies and storage

RB2B documents `_reb2bgeo`, `_reb2bloaded`, `_reb2bref`, `_reb2sessionID`, `_reb2buid`, `_reb2bfxf`, `_reb2btd`, `_reb2bli`, `_reb2bresolve`, and `_reb2butk`. Served scripts can also set `_reb2bsessionID`, `_reb2bsha`, `_reb2bec`, and `_reb2beid`, and mirror `_reb2buid`, `_reb2bref`, `_reb2bec`, `_reb2butk`, and `_reb2beid` in `localStorage`. Inspect your live account script in DevTools Application before configuring `clearOnRevocation`.

## Verify RB2B

In a fresh browser profile:

1. Deny consent and allow only an unrelated category. Confirm no RB2B requests, `window.reb2b` global, cookies, `localStorage`, or `sessionStorage` appear.
2. Grant `marketing` and confirm the loader URL matches your RB2B dashboard snippet.
3. Withdraw consent and confirm the page reloads with RB2B blocked.
