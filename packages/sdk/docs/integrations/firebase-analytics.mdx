The bundled Firebase Analytics helper in `InthApple`, `inth-android`, and `@inth/react-native/integrations` maps Inth permissions to Firebase's four Consent Mode v2 signals and collection switch. `measurement` drives `analytics_storage` and collection; `marketing` drives `ad_storage`, `ad_user_data`, and `ad_personalization`, matching the [web Google Tag mapping](/docs/integrations/google-tag#how-categories-map-to-google-consent-types). Pending permission denies every signal and keeps collection disabled.

Your app installs Firebase separately. For web apps, use [Google Tag](/docs/integrations/google-tag).

## Before you start

Complete the [Swift](/docs/frameworks/swift/quickstart), [Android](/docs/frameworks/android/quickstart), or [React Native](/docs/frameworks/react-native/quickstart) quickstart and add `measurement`, plus `marketing` if you run Google ads, to your Inth policy and native config. See [mobile availability](/docs/guides/mobile-status).

Install Firebase using the [Apple](https://firebase.google.com/docs/ios/setup), [Android](https://firebase.google.com/docs/android/setup), or [React Native Firebase](https://rnfirebase.io/analytics/usage) setup guides first. This helper updates Firebase Consent Mode only, not IAB, Google Mobile Ads, or ATT; see [mobile IAB and ads](/docs/guides/mobile-iab).

## Control native startup first

Disable Firebase Analytics collection by default in your native build config.

In iOS `Info.plist`:

{/* example: fragment */}

```xml title="Info.plist"
<key>FIREBASE_ANALYTICS_COLLECTION_ENABLED</key>
<false/>
```

In Android `AndroidManifest.xml`, inside `<application>`:

{/* example: fragment */}

```xml title="AndroidManifest.xml"
<meta-data
	android:name="firebase_analytics_collection_enabled"
	android:value="false" />
```

Firebase persists runtime collection grants across launches, overriding these defaults. Reconcile Inth permission early in native startup; see [Firebase's collection guide](https://firebase.google.com/docs/analytics/configure-data-collection).

### Deny Consent Mode signals by default

Set all four Consent Mode defaults to denied so nothing is granted at launch before Inth runs.

In iOS `Info.plist`:

{/* example: fragment */}

```xml title="Info.plist"
<key>GOOGLE_ANALYTICS_DEFAULT_ALLOW_ANALYTICS_STORAGE</key>
<false/>
<key>GOOGLE_ANALYTICS_DEFAULT_ALLOW_AD_STORAGE</key>
<false/>
<key>GOOGLE_ANALYTICS_DEFAULT_ALLOW_AD_USER_DATA</key>
<false/>
<key>GOOGLE_ANALYTICS_DEFAULT_ALLOW_AD_PERSONALIZATION_SIGNALS</key>
<false/>
```

In Android `AndroidManifest.xml`, inside `<application>`:

{/* example: fragment */}

```xml title="AndroidManifest.xml"
<meta-data
	android:name="google_analytics_default_allow_analytics_storage"
	android:value="false" />
<meta-data
	android:name="google_analytics_default_allow_ad_storage"
	android:value="false" />
<meta-data
	android:name="google_analytics_default_allow_ad_user_data"
	android:value="false" />
<meta-data
	android:name="google_analytics_default_allow_ad_personalization_signals"
	android:value="false" />
```

In bare React Native, set all five keys to `false` in `firebase.json`. On Android, React Native Firebase defaults omitted keys to `true`:

{/* example: fragment */}

```json title="firebase.json"
{
	"react-native": {
		"analytics_auto_collection_enabled": false,
		"analytics_default_allow_analytics_storage": false,
		"analytics_default_allow_ad_storage": false,
		"analytics_default_allow_ad_user_data": false,
		"analytics_default_allow_ad_personalization_signals": false
	}
}
```

In Expo, Inth's config plugin writes the four denied Consent Mode defaults with `tools:replace="android:value"` on every prebuild. Keep the [native startup gate](/docs/frameworks/react-native/native-behaviour) because JavaScript runs after native launch. Expo needs a custom native build, not Expo Go.

## Connect a Swift app

Add `FirebaseAnalyticsOwner.swift` to your app target:

<include src="../shared/examples/native/core-swift/AppleInstallation/swift-firebase-analytics-binding.mdx" />

After installing Inth and Firebase, construct and retain `firebaseOwner` for the app lifetime:

{/* example: fragment */}

```swift
import FirebaseAnalytics

let firebaseOwner = FirebaseAnalyticsOwner(
    core: core,
    setConsent: { consent in
        Analytics.setConsent([
            .analyticsStorage: consent.analyticsStorage ? .granted : .denied,
            .adStorage: consent.adStorage ? .granted : .denied,
            .adUserData: consent.adUserData ? .granted : .denied,
            .adPersonalization: consent.adPersonalization ? .granted : .denied,
        ])
    },
    setCollectionEnabled: { Analytics.setAnalyticsCollectionEnabled($0) }
)
```

Pass direct Firebase calls; async dispatch can reorder grants and withdrawals. The helper applies current permission before returning, and releasing it denies all signals and disables collection.

## Connect an Android app

Add this helper using your app's package name:

<include src="../shared/examples/native/examples/consent-demo/android-firebase-integration.mdx" />

Call it from `Application` startup and retain `firebaseConsent` on an application or service owner:

{/* example: fragment */}

```kotlin
import com.google.firebase.analytics.FirebaseAnalytics
import com.google.firebase.analytics.FirebaseAnalytics.ConsentStatus
import com.google.firebase.analytics.FirebaseAnalytics.ConsentType

val firebase = FirebaseAnalytics.getInstance(this)
val firebaseConsent = connectAppFirebaseAnalytics(
	setConsent = { consent ->
		firebase.setConsent(mapOf(
			ConsentType.ANALYTICS_STORAGE to
				if (consent.analyticsStorage) ConsentStatus.GRANTED else ConsentStatus.DENIED,
			ConsentType.AD_STORAGE to
				if (consent.adStorage) ConsentStatus.GRANTED else ConsentStatus.DENIED,
			ConsentType.AD_USER_DATA to
				if (consent.adUserData) ConsentStatus.GRANTED else ConsentStatus.DENIED,
			ConsentType.AD_PERSONALIZATION to
				if (consent.adPersonalization) ConsentStatus.GRANTED else ConsentStatus.DENIED,
		))
	},
	setCollectionEnabled = firebase::setAnalyticsCollectionEnabled,
	onError = ::reportAnalyticsError,
)
```

Callbacks run synchronously and disable collection before updating consent. `onError` must work while analytics is disabled and must not throw; construction, `sync()`, and `close()` can throw. The native core keeps applying consent until `close()`.

## Connect React Native or Expo

Copy the connection function into `firebase-consent.ts`:

<include src="../shared/examples/react-native-bare/rn-firebase-integration.mdx" />

Wrap React Native Firebase's modular functions in `firebase-vendor.ts`:

{/* example: fragment */}

```ts title="firebase-vendor.ts"
import {
	getAnalytics,
	setAnalyticsCollectionEnabled,
	setConsent,
} from '@react-native-firebase/analytics';

import { connectAppFirebaseAnalytics } from './firebase-consent';

export function connectFirebaseVendor(onError: (error: unknown) => void) {
	const analytics = getAnalytics();
	return connectAppFirebaseAnalytics(
		{
			setConsent: (settings) => setConsent(analytics, settings),
			setAnalyticsCollectionEnabled: (enabled) =>
				setAnalyticsCollectionEnabled(analytics, enabled),
		},
		onError
	);
}
```

Call `connectFirebaseVendor` once at startup, retain the handle across routes, and await `ready`:

{/* example: fragment */}

```ts
const firebaseConsent = connectFirebaseVendor(reportAnalyticsError);
await firebaseConsent.ready;
```

Handle errors in `onError` and the `ready`, `sync()`, and `disconnect()` promises. The helper serializes async calls and rereads native permission before enabling collection.

## Handle reset and teardown

After resetting Firebase settings, reapply permission without creating a consent record via `syncAfterReset()` on Swift, `sync()` on Android, or `await firebaseConsent.sync()` on React Native. For final teardown, call `stop()`, `close()`, or `await firebaseConsent.disconnect()`. Teardown disables collection but does not delete historical data.

## Check the integration

Test an opt-in policy with Firebase debug tools:

1. Launch pending and after Reject all; confirm all four signals stay denied and collection stays off.
2. Grant `measurement` only; confirm `analytics_storage` is granted, ad signals stay denied, and collection turns on.
3. Grant `marketing`; confirm all three ad signals become granted.
4. Withdraw both; confirm collection turns off and all four signals return to denied.
5. Relaunch after grant and refusal, verifying native startup before JavaScript.
6. Reset Firebase settings, call `sync()`, and verify permission reapplies without a new record.

Type-checked against React Native Firebase `27.1.0`. Complete [mobile verification](/docs/guides/mobile-verify) on real devices.
