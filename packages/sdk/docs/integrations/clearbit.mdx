The `clearbit` helper keeps Clearbit's `tags.js` off the page until visitors grant `marketing` consent, then removes the loader and reloads the page on withdrawal.

## Configure Clearbit

Copy the publishable key from your Clearbit tag installation. Never put a secret Clearbit API key in browser code.

<CommandTabs command="@inth/integrations" mode="install" />

{/* example: fragment */}

```ts title="src/consent-scripts.ts"
import { clearbit } from '@inth/integrations/clearbit';

export const scripts = [clearbit({ publishableKey: 'YOUR_PUBLISHABLE_KEY' })];
```

## Options

| Option | Default | Behavior |
| --- | --- | --- |
| `publishableKey` | Required | Publishable key, trimmed and URL-encoded into the default loader URL. Empty or non-string values log an error and skip loading. |
| `scriptUrl` | `https://tag.clearbitscripts.com/v1/<publishableKey>/tags.js` | Loader URL override. Blank values use the default. |

## Loading and revocation

`clearbit` gates on `marketing` instead of `measurement` because Clearbit enriches visitor and company identity. When `marketing` is allowed, Inth loads `tags.js` with `referrerpolicy="strict-origin-when-cross-origin"`. On withdrawal, Inth removes the script element without calling a Clearbit API and reloads the page by default.

## Verify Clearbit

Filter DevTools Network by `clearbitscripts.com`:

1. Allow only `measurement` and confirm nothing loads from Clearbit.
2. Allow `marketing` and confirm `tags.js` loads with your publishable key in its path.
