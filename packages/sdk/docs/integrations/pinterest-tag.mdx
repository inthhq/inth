The `pinterestTag` helper keeps the Pinterest Tag off the page and `window.pintrk` undefined until `marketing` is granted. On grant, it queues `load`, `pintrk('setconsent', true)`, and a page visit before loading `core.js`. On withdrawal, it calls `pintrk('setconsent', false)` and Inth reloads the page by default.

## Configure the Pinterest Tag

Copy your numeric tag ID from Pinterest Ads Manager. Remove Pinterest's base snippet and its `<noscript>` image; the helper omits that image because it fires without JavaScript and cannot be consent-gated.

## Options

| Option | Default | Behavior |
| --- | --- | --- |
| `tagId` | Required | Numeric tag ID passed to `pintrk('load', ...)`, trimmed. Blank values log an error and skip loading. |
| `loadOptions` | None | Third argument to `pintrk('load', ...)`, such as `em` or `external_id` for enhanced match. Pass user data only with appropriate permission. |
| `trackPageVisit` | `true` | Queues `pintrk('page')` after `load`. Set `false` to send page visits yourself. |
| `scriptUrl` | `https://s.pinimg.com/ct/core.js` | Loader URL override. Blank values use the default. |

## Loading and revocation

`pinterestTag` uses the `marketing` category. Before grant, Inth defines no `pintrk` global and makes no Pinterest requests. On grant, it queues `load`, `pintrk('setconsent', true)`, and the page visit, then loads `core.js`.

On revocation, the helper keeps the tag and calls `pintrk('setconsent', false)`, which Pinterest documents as stopping events and clearing first-party storage. If the visitor allows `marketing` again before reload, the helper calls `pintrk('setconsent', true)`.

## Guard your own pintrk calls

The helper sends only the initial page visit. Because `window.pintrk` remains defined after revocation, check `marketing` permission from your framework, such as `useConsent('marketing')` in React, before sending events like `checkout` or `lead`:

```ts title="src/track-checkout.ts"
export function trackCheckout(marketingAllowed: boolean, orderId: string) {
	if (!marketingAllowed || typeof window.pintrk !== 'function') return;
	window.pintrk('track', 'checkout', {
		currency: 'USD',
		event_id: orderId,
		order_id: orderId,
		value: 99.99,
		line_items: [{ product_id: '1414', product_quantity: 1 }],
	});
}
```

Include product details in `line_items` and set `event_id` to deduplicate against the Conversions API. Pinterest reports conversions only for its 20 standard event types and uses other event names for audience targeting.

`@inth/integrations/pinterest-tag` also exports `pinterestTagEvent`, a typed wrapper around `pintrk('track', ...)` whose optional third argument receives Pinterest's `(didInit, error)` callback. It does not check consent, so keep the same permission guard.

## Verify the Pinterest Tag

1. Allow `marketing` and confirm `core.js` loads from `s.pinimg.com` and Pinterest Tag Helper records the page visit.
2. Trigger one guarded conversion event and confirm Tag Helper records it.
3. Revoke `marketing` and confirm `trackCheckout` sends nothing before reload.
