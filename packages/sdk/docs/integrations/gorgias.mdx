The `gorgiasChat` helper waits for `functionality` consent before loading Gorgias Chat and disables its Segment analytics unless `measurement` is also allowed.

## Configure Gorgias Chat

Copy the public app key from your v3 Gorgias Chat snippet at `https://config.gorgias.chat/bundle-loader/YOUR_APP_KEY`. For a v2 snippet, pass its `applicationId` as `appKey` with `version: 2`.

Remove any existing Gorgias snippet, tag-manager tag, or store app auto-install first; an external copy loads before consent, and Gorgias skips duplicate installations.

## Options

| Option | Default | Behavior |
| --- | --- | --- |
| `appKey` | Required | Public v3 app key, or v2 `applicationId` when `version` is `2`, trimmed and URL-encoded. Blank values log `gorgiasChat: missing or invalid appKey` and skip loading. |
| `version` | `3` | Snippet version: `3` loads `https://config.gorgias.chat/bundle-loader/<appKey>`; `2` loads `https://config.gorgias.chat/gorgias-chat-bundle-loader.js?applicationId=<appKey>`. |

## Loading and revocation

Before consent, Inth adds no script, creates no globals, and writes no storage. The default category is `functionality`; overriding `category` gates the loader on that category plus the visitor's Gorgias vendor switch.

On grant, Inth listens for `gorgias-widget-loaded`, appends the loader to `<body>`, and also awaits `GorgiasChat.init()` if `window.GorgiasChat` is present when the loader finishes, acting on whichever resolves first. When ready, it checks the current `measurement` permission. Revocation, disposal, or a loader error cancels pending readiness listeners, though it cannot cancel Gorgias's own startup once executed. If `GorgiasChat.init()` rejects while consent remains allowed, Inth logs `gorgiasChat: chat initialization failed.` and stops waiting.

On withdrawal, Inth removes the loader and calls `disableSegment()` if the widget is ready, even while `measurement` stays allowed. Because Gorgias has no shutdown API and `close()` and `hideChat(true)` only hide the UI without stopping requests or clearing sessions, keep `reloadOnConsentRevoked` enabled.

## Measurement consent and Segment

When the widget becomes ready without `measurement` consent, or when a visitor withdraws `measurement` later, Inth calls `GorgiasChat.disableSegment()` per Gorgias's [analytics customization docs](https://docs.gorgias.com/en-US/html-snippets-for-chat-customization-460197).

Gorgias provides no API to re-enable Segment on the same page; regranting `measurement` restores default analytics only after a reload. Because `disableSegment()` runs after the widget initializes, inspect Network requests to verify nothing fires before the ready event.

## Cookies and storage

Gorgias does not publish a complete cookie and storage inventory. Probing Gorgias's public help-center installation observed `_dd_s` and `localStorage` keys `gorgias.ai-agent-state`, `gorgias.version`, `gorgias.storage-updated-at`, and `gorgias.language-loaded`, all persisting after revocation; actual keys vary by version and account. Reloading stops the widget without clearing stored data, so inspect storage before and after starting a chat and add cleanup rules as needed. Gorgias's [chat privacy disclosure](https://docs.gorgias.com/en-US/chat-add-a-privacy-disclosure-361578) explains data handling to visitors and does not replace the consent gate.

## Verify Gorgias Chat

Test with your real app key in a private window with an opt-in policy, filtering DevTools Network by `gorgias`:

1. Before choosing, and after rejecting `functionality` and reloading, confirm no Gorgias requests fire.
2. Grant `functionality` and confirm the loader requests your app key and the widget renders. A placeholder or deleted key still returns HTTP 200 with a warning, so verify the widget itself appears.
3. Leave `measurement` denied and check first-load and interaction requests for Segment traffic.
4. Revoke `functionality` and confirm the page reloads with no Gorgias requests, then inspect Application storage separately.
