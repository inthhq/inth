Sync Mixpanel tracking with Inth `measurement` consent using the [web script helper](#web) or the [mobile SDK helpers](#mobile) for Swift, Android, React Native, and Expo. Startup and queue behavior differ by platform.

## Web

The `mixpanelAnalytics` helper loads Mixpanel on every page with `alwaysLoad` and calls `mixpanel.opt_in_tracking()` or `mixpanel.opt_out_tracking()` from `measurement` consent. On withdrawal, it calls `opt_out_tracking()`, keeps the SDK mounted, and Inth reloads the page by default.

### Configure Mixpanel

Copy the 32-character project token from your Mixpanel `init` snippet, then remove that snippet from your app so Mixpanel loads only through Inth.

<CommandTabs command="@inth/integrations" mode="install" />

{/* example: fragment */}

```ts title="src/consent-scripts.ts"
import { mixpanelAnalytics } from '@inth/integrations/mixpanel-analytics';

export const scripts = [
	mixpanelAnalytics({ token: '0123456789abcdef0123456789abcdef' }),
];
```

The helper sets `opt_out_tracking_by_default` and `opt_out_persistence_by_default` to `true`, so visitors without consent stay opted out with no tracked events, including pre-load queued `track` calls, and no stored visitor ID. Mixpanel still writes and removes an empty `mp_*` cookie during startup.

### Options

| Option | Default | Behavior |
| --- | --- | --- |
| `token` | Required | 32-character hexadecimal project token, trimmed automatically. Any other value logs an error and skips loading. |
| `initOptions` | `{ opt_out_tracking_by_default: true, opt_out_persistence_by_default: true }` | Mixpanel config passed to `init`, merged over defaults. JSON-serializable values only. |
| `scriptUrl` | `https://cdn.mxpnl.com/libs/mixpanel-2-latest.min.js` | Loader URL override. |

### Loading and revocation

`mixpanelAnalytics` uses `measurement` with `alwaysLoad`. Before load, the helper queues `opt_in_tracking()` when `measurement` is allowed or `opt_out_tracking()` otherwise. Mixpanel runs that call during `init` before queued `track` calls, so returning visitors with consent keep early events. Later consent changes call the matching method without removing the SDK.

Before load, the helper queues `track`, `identify`, `reset`, `register`, `opt_in_tracking`, and `opt_out_tracking` on the default instance. Named instances and `people.*` calls are not queued.

### Verify Mixpanel

1. In a private window with an opt-in policy, load the page. `cdn.mxpnl.com` loads before you choose, and `mixpanel.has_opted_out_tracking()` returns `true`.
2. Click Reject and reload. `has_opted_out_tracking()` stays `true`, and `mixpanel.track('Test')` sends no request.
3. Open Privacy settings and allow `measurement`. Without a reload, `has_opted_out_tracking()` returns `false` and tracking requests appear.
4. Turn `measurement` off and save. Inth reloads the page with Mixpanel opted out.

See [consent verification](/docs/guides/verify-consent) for navigation and hosting checks.

## Mobile

The bundled Mixpanel helper in `InthApple`, `inth-android`, and `@inth/react-native/integrations` submits opt-in and opt-out commands from `measurement` consent by default. Pending or denied permission submits opt-out; an allowed category submits opt-in. Your app installs Mixpanel separately.

### Before you start

Complete the [Swift](/docs/frameworks/swift/quickstart), [Android](/docs/frameworks/android/quickstart), or [React Native](/docs/frameworks/react-native/quickstart) quickstart with `measurement` in your native configuration and Inth policy. Use the same installed engine for consent UI and analytics helpers. See [mobile availability](/docs/guides/mobile-status).

Install Mixpanel for [Swift](https://mixpanel.github.io/mixpanel-swift/), [Android](https://mixpanel.github.io/mixpanel-android/), or [React Native](https://github.com/mixpanel/mixpanel-react-native). Start opted out and disable automatic tracking before optional collection can begin. Because persisted state can override startup defaults on later launches, defer vendor initialization behind a [native startup gate](/docs/frameworks/react-native/native-behaviour) for strict startup control. A JavaScript connection cannot stop collection that started natively, and Expo requires a development or release build rather than Expo Go.

### Connect Swift

Add this owner to your app target:

<include src="../shared/examples/native/core-swift/AppleInstallation/swift-mixpanel-binding.mdx" />

After Inth installation and permitted vendor setup, connect the configured instance with your installed `ConsentCore`:

{/* example: fragment */}

```swift
@preconcurrency import Mixpanel

let mixpanel = Mixpanel.mainInstance()
let mixpanelOwner = MixpanelOwner(
    core: core,
    optInTracking: { mixpanel.optInTracking() },
    optOutTracking: { mixpanel.optOutTracking() }
)
```

Retain `mixpanelOwner` for the analytics lifetime. Swift 6 needs `@preconcurrency import Mixpanel` because this client does not declare `Sendable`. Call the Mixpanel methods directly in the callbacks; adding another dispatch queue can reorder grants and withdrawals.

### Connect Android

Add this function to your app and replace the sample package name:

<include src="../shared/examples/native/examples/consent-demo/android-mixpanel-integration.mdx" />

Connect the same initialized `MixpanelAPI` instance used for app events:

{/* example: fragment */}

```kotlin
val mixpanelConsent = connectAppMixpanel(
	optInTracking = { mixpanel.optInTracking() },
	optOutTracking = { mixpanel.optOutTracking() },
	onError = ::reportAnalyticsError,
)
```

Retain the connection on your `Application` or analytics service, not an `Activity`, because the native core keeps applying consent until `close()`. Keep `onError` safe while analytics is disabled and non-throwing. Automatic callback failures go to `onError`, while construction, `sync()`, and `close()` can throw directly.

### Connect React Native or Expo

Copy this function into `mixpanel-consent.ts`:

<include src="../shared/examples/react-native-bare/rn-mixpanel-integration.mdx" />

Connect your initialized Mixpanel instance at startup and retain the handle:

{/* example: fragment */}

```ts
const mixpanelConsent = connectAppMixpanel(mixpanel, reportAnalyticsError);
await mixpanelConsent.ready;
```

Handle callback errors in `onError` and rejections from `ready`, `sync()`, and `disconnect()`. In Mixpanel RN `4.0.0`, opt-in and opt-out return `void` and discard native promises. Inth serializes their submission, but its promises cannot confirm native queue completion or report dropped native errors. Guard app-side event calls on current permission.

### Handle opt-in, reset, and teardown

Mixpanel's opt-in API emits `$opt_in`. Inth skips unchanged permissions, while construction with an existing grant, a later grant, and explicit `sync()` submit opt-in. Call `sync()` after an app-owned vendor reset finishes, not on every render or navigation.

Swift queues commands internally without a completion barrier, and opt-out can flush older events and profile changes. Android opt-out clears pending event queues and local user data. Do not assume identical queue or identity behavior across platforms, and do not add a flush before withdrawal.

For teardown, call Swift `stop()`, Kotlin `close()`, or `await mixpanelConsent.disconnect()` to detach consent observation and submit opt-out. None of these delete data Mixpanel already received.

### Verify your app

Test pending permission and refusal before any optional event call, then grant, send an intentional event, and withdraw. Check relaunch after both grant and refusal. Run a vendor reset, call `sync()`, and inspect identity, `$opt_in` events, and queued versus newly accepted traffic.

Checked against Mixpanel Swift `7.0.0`, Android `8.11.1`, and RN `4.0.0`. Unit tests prove native authority and command ordering rather than delivery, native queue completion, or device startup traffic. Complete [mobile verification](/docs/guides/mobile-verify) on real vendor builds.
