[Expo Observe](https://docs.expo.dev/eas/observe/introduction/), formerly EAS
Observe, measures app startup and records events and crash reports on your
users' devices. The `expo-observe` package has no consent API and no way to
turn recording off. It does have a persisted switch that stops sending:
`Observe.configure({ dispatchingEnabled })`. This page connects that switch to
Inth's `measurement` category.

Recording on the device starts before React Native loads and keeps going
whatever you pass to `configure`. Inth decides whether Observe's queue leaves
the device. It cannot stop Observe from writing that queue.

## What Observe collects and sends

With `expo-observe` installed and your root component wrapped in
`ObserveRoot.wrap`, Observe records these without further calls:

- Cold launch, warm launch, bundle load and time to first render.
- Time to interactive, when your code calls `markInteractive()`.
- Frame, thermal, battery and network details on each time-to-interactive
  event, plus a summary of the network requests made during launch.
- Unhandled JavaScript errors (SDK 57 and later) and native crash reports.
- EAS Update download timings, for apps that use EAS Update.

Your code adds more through `Observe.logEvent`, `Observe.reportError`,
`ObserveErrorBoundary`, spans, the navigation integrations and the
`networkTraces` option.

Every event carries app, release, device and route context and the EAS
client ID (`expo.eas_client.id`). That ID is a random identifier for the
installation. Observe stores it in native preferences, and it stays the same
across launches and app updates. Expo's documentation says Observe collects no
personally identifiable information. The iOS privacy manifest in
`expo-observe` declares crash data, performance data, other diagnostic data,
a device ID and product interaction, all marked as not linked to the user and
not used for tracking. Whether that data needs consent where your app ships is
a question for your privacy counsel. Inth can't answer it for you.

Observe sends its data over OTLP to `https://o.expo.dev/<project id>`, or to
the `extra.eas.observe.endpointUrl` in your app config. It needs
`extra.eas.projectId` to send. Debug builds send only when
`dispatchInDebug` is `true`.

## When Observe starts

`expo-observe` has no config plugin. Expo autolinking adds its native modules
and app delegate hooks to every development and production build. On iOS,
recording starts when the app delegate begins initializing, before the
JavaScript bundle loads. Android records from its application and activity
lifecycle hooks. Observe writes everything to a local database and sends the
queue at these points:

| Platform | Observe sends the queue when |
| --- | --- |
| iOS | The app resigns active or is about to terminate |
| Android | An activity goes to the background. A WorkManager job sends once the device is online |
| Both | Your code calls `Observe.dispatchEvents()` |

At each send, Observe reads the configuration that the last `configure` call
saved. With `dispatchingEnabled: false`, it marks pending metrics and logs as
sent and deletes pending spans, without sending them. The saved value applies
to later launches until the next `configure` call. An install that has never
called `configure` sends.

Observe has no setting in the app config or the native project that starts a
build with sending off. It also has no API that delays recording until later.

## Choose the category

Use `measurement`, the Inth category for analytics and performance
measurement. `dispatchingEnabled` covers metrics, events, spans and errors
together. If your legal review lets crash reports run without consent, SDK 58
can send them alone: keep `dispatchingEnabled: true` and pass `sampleRate: 0`
with `errorSampleRate: 1` while measurement is denied. Observe then sends only
JavaScript errors and crash reports. SDK 57 and earlier have no
`errorSampleRate`, and `sampleRate` covers errors too, so there you can only
gate everything together.

## Gate sending with Inth

Complete the [Expo setup](/docs/frameworks/react-native/expo) and include
`measurement` in your Inth policy and the plugin's `consentCategories`. Then
follow Expo's setup for `expo-observe`. Create this component:

Render `<ObserveConsent />` once, inside `InthProvider`, in the root
component you wrap with `ObserveRoot.wrap`. For Expo Router, that is the
root `_layout.tsx`. Keep it mounted for the life of the app.

`useConsentDecision('measurement')` is `pending` until the native engine has
read stored consent and resolved the policy. While it is `pending`, a
returning user keeps the value the previous launch saved, so they do not lose
that launch's metrics even when the policy cannot load. A new user, for whom
`useInthBootstrap().hasStoredSnapshot` is `false`, has no grant to keep, so
the component turns sending off until they decide, even if the policy never
loads. The same happens when the decision goes back to `pending` later in the
session, for example after `reset()`, because the earlier grant no longer
holds. Under an opt-in policy the decision is `denied` until someone grants
measurement, and after a refusal; Observe then discards its queue at the next
send. When the decision changes, the
effect saves the new value after React renders, usually well before Observe's
next send; see the withdrawal race below.

`Observe.configure` replaces the whole configuration on every call. Fields you
leave out go back to their defaults, which include `sampleRate` and
`integrations`, plus `errorSampleRate`, `networkTraces` and
`errorHandlingEnabled` on SDK 58.
Remove any other `configure` call from your app and move its options into
`observeConfig`.

On SDK 55, `expo-observe` 0.2.x has a default export only. Import it with
`import Observe from 'expo-observe'` and type the options with its `Config`
type. `dispatchingEnabled` works the same way.

## What the gate does not cover

**The first launch.** Before JavaScript runs `ObserveConsent`, Observe uses
its default and sends. If someone opens the app for the first time and moves
it to the background before React mounts, Observe sends what it has recorded
so far. Later launches use the value the previous launch saved.

**Data recorded before a grant.** Observe keeps recording while sending is
off and discards the queue only at a send attempt. If someone grants
measurement before Observe has tried to send, the queue goes out with the
grant. That queue can include the startup metrics of the launch that showed
the consent prompt.

**A withdrawal right before the app leaves the screen.** The effect runs
after React renders, and Observe sends from native code when the app goes to
the background. If someone withdraws measurement and the app goes to the
background before the effect has run, Observe can still send with the earlier
saved value.

**Recording itself.** Observe writes metrics, events and crash reports to the
device whatever the consent state. Inth cannot change that.

If your app cannot accept these gaps, you have three honest options:

1. Leave `expo-observe` out of builds for the markets where you have no legal
   basis to run it before consent.
2. Ship it ungated where your legal basis covers performance and crash
   monitoring without consent. Say so in your privacy policy.
3. Ask Expo for a build-time setting that starts with sending off, or for a
   way to turn recording off, in the
   [Expo repository](https://github.com/expo/expo/issues).

## Check the gate

Test a release build, or set `dispatchInDebug: true` in `observeConfig` for
a development build. Watch requests to `o.expo.dev`, or your custom
endpoint, with a proxy such as Proxyman or Charles.

1. Install fresh and wait for the consent prompt before you background the
   app. Background it without choosing. No request should go to
   `/v1/metrics`, `/v1/logs` or `/v1/traces`.
2. Reject all and background the app. Observe should send nothing.
3. Grant measurement and background the app. Requests to `/v1/metrics` and
   `/v1/logs` should follow.
4. Withdraw measurement, use the app and background it. Observe should send
   nothing.
5. Relaunch after a refusal and background the app before you open privacy
   settings. Observe should send nothing.
