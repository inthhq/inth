The `wisepops` helper keeps Wisepops off the page, leaves `window.wisepops` undefined, and writes no storage until a visitor grants `marketing` consent. It queues `defaultConsent: 'denied'` before the SDK runs and calls `wisepops('consent', 'granted')` once the loader finishes with consent still active. Keep `reloadOnConsentRevoked` enabled because Wisepops cannot revoke consent programmatically.

## Configure Wisepops

Open **Settings > Install Wisepops** and copy your public site ID from the `h` query parameter in `https://wisepops.net/loader.js?v=3&h=YOUR_WISEPOPS_SITE_ID`. Remove any direct snippet, tag manager entry, or CMS plugin so Wisepops loads only through Inth. Use one site ID per document and reload if you switch site IDs.

## Options

| Option | Default | Behavior |
| --- | --- | --- |
| `siteId` | Required | Public site ID from the `h` parameter, trimmed and URL-encoded. Missing or blank values log an error and skip loading. |
| `category` | `'marketing'` | Consent category or condition required before setup. Set `'experience'` if your campaign policy uses it. |
| `options.autoPageview` | `'url'` | `'url'` checks campaigns on URL changes. `'init'` checks only after initialization. `false` disables automatic pageviews. |
| `options.browserStorage` | Omitted; cookies | `true` stores visitor data in localStorage instead of cookies and migrates existing cookies. Data stays scoped to one origin and does not cross subdomains. |
| `options.cookieMaxSize` | Under 3 KB | Cookie size limit in bytes, such as `1024` for 1 KB. Wisepops drops older visitor history past this limit. |
| `nonce` | None | CSP nonce for the Inth-managed loader. Does not apply to resources Wisepops creates. |

The helper always sets `defaultConsent: 'denied'`, has no `alwaysLoad` mode, and grants cookie consent only when both the category and Wisepops vendor pass consent. Set `options` before registering `scripts`; mutating them later does not update a running SDK.

### Single-page applications

The v3 loader's default `autoPageview: 'url'` detects route changes automatically. If you set `autoPageview: false`, call `window.wisepops?.('pageview')` after navigation only while both the mapped category and Wisepops vendor pass consent. Recheck permission on every manual call because `window.wisepops` stays defined after revocation. Do not trigger manual pageviews while automatic pageviews are enabled, and keep in mind that `autoPageview: false` does not stop a running SDK.

## Loading and revocation

Once consent passes, Inth creates `window.wisepops` with its snippet queue and timestamp, queues runtime options, appends the loader to `<head>`, and grants cookie consent after load. If revocation removes a downloading loader, Inth ignores its late load event and sends no grant. Do not install Wisepops separately to use its denied mode, which still renders campaigns and sets session cookies.

On revocation, Inth removes the loader and reloads the page by default. It does not call `wisepops('consent', 'denied')`, which Wisepops documents as an error, and Wisepops exposes no shutdown API. Disabling `reloadOnConsentRevoked` leaves running campaigns, timers, and listeners active until navigation, and removing a `<script>` tag cannot guarantee an in-flight download will not execute.

## Cookies and browser storage

Wisepops documents these first-party cookies on your site's domain:

| Cookie | Documented lifetime |
| --- | --- |
| `wisepops_session` | Session |
| `wisepops_visitor` | 750 days |
| `wisepops_noshow` | 2 years |
| `wisepops_props` | 2 years |
| `wisepops_visits` | 2 years |
| `wisepops_tld` | Session |
| `wisepops` | 2 years |

With `options.browserStorage: true`, Wisepops stores visitor data in localStorage. Reloading does not delete Wisepops cookies or localStorage, and client-side cleanup cannot remove HttpOnly cookies or server-side records. Because Wisepops can remember a previous grant in its stored state, keep Wisepops blocked on reload after revocation.

Wisepops integrates with Shopify Customer Privacy automatically, and Inth does not sync choices with Shopify. Review Wisepops' [Shopify consent behavior](https://support.wisepops.com/en/articles/12679556-cookie-consent-mode), contact Wisepops support if you need that integration disabled, and avoid loading Wisepops through a separate Shopify app.

## Verify Wisepops

In a private window with an opt-in policy, filter DevTools Network by `wisepops` and check Application storage:

1. Load the page before choosing, reject consent and reload, then allow an unrelated category like `measurement`. Confirm no Wisepops requests, `window.wisepops` global, or storage entries appear.
2. Allow the mapped category. Confirm `loader.js?v=3&h=...` loads without reload; it may redirect under `wisepops.net/h/<siteId>/`.
3. Navigate between routes to verify automatic pageviews, or confirm manual pageviews stay blocked when denied.
4. Withdraw the mapped category and save. Confirm Inth reloads the page and makes no Wisepops requests or queue setup.
5. Toggle the Wisepops vendor switch off inside an allowed category and confirm the page reloads with Wisepops blocked, then restore it to verify Wisepops loads again.
