The `pirsch` helper keeps `pa.js` and `pirsch-extended.js` off the page until `measurement` is granted. It sends no consent signal to Pirsch. On withdrawal, Inth removes the script element and reloads the page by default.

## Configure Pirsch

Copy the identification code from your Pirsch installation snippet; the helper sets it as `data-code`.

<CommandTabs command="@inth/integrations" mode="install" />

{/* example: fragment */}

```ts title="src/consent-scripts.ts"
import { pirsch } from '@inth/integrations/pirsch';

export const scripts = [
	pirsch({ identificationCode: 'YOUR_IDENTIFICATION_CODE' }),
];
```

## Options

| Option | Default | Behavior |
| --- | --- | --- |
| `identificationCode` | Required | Set as `data-code`. Blank values log an error and skip loading. |
| `domain` | None | Extra dashboard domains, each optionally as `domain:CODE`. Arrays become comma-separated `data-domain`. |
| `dev` | None | Hostname Pirsch reports instead of `localhost`, set as `data-dev` for local testing. |
| `hitEndpoint` | None | Page view endpoint, set as `data-hit-endpoint`. |
| `eventEndpoint` | None | Event endpoint, set as `data-event-endpoint`. |
| `disablePageViews` | None | `true` adds `data-disable-page-views` and disables automatic page views. |
| `extended` | None | `true` loads `https://api.pirsch.io/pirsch-extended.js` instead of `pa.js`. |
| `scriptUrl` | `https://api.pirsch.io/pa.js` | Loader URL override. Blank values use the default. |

Pirsch looks up its script tag by ID, so the helper sets the element ID to `pianjs`, or `pirschextendedjs` when `extended` is `true`.

## Loading and revocation

`pirsch` uses the `measurement` category and loads only while measurement is allowed. Because Pirsch binds custom events on `DOMContentLoaded`, which usually fires before consent arrives, the helper calls `window.pirschInit()` when loading on an already-parsed document.

On revocation, the helper removes the script element and calls no Pirsch API.

## Verify Pirsch

1. Allow `measurement` after the page finishes loading and confirm `pa.js` or `pirsch-extended.js` loads with `#pianjs` carrying your `data-code`.
2. Trigger a custom event and confirm its request fires.
3. If your code calls `window.pirsch` directly, check `measurement` permission before each call.
