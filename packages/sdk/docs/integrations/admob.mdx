The bundled AdMob helper in `InthApple`, `inth-android`, and `@inth/react-native/integrations` maps Inth's `marketing` consent to `ad_storage`, `ad_user_data`, and `ad_personalization`, matching the [web Google Tag mapping](/docs/integrations/google-tag#how-categories-map-to-google-consent-types). Pending permission denies all three. Your app installs Google Mobile Ads separately.

## What the helper changes

| Consent | Google Mobile Ads setting |
| --- | --- |
| `adStorage` denied | Sets `gad_has_consent_for_cookies` to `0`, enabling [limited ads](https://support.google.com/admob/answer/10105530) |
| `adStorage` granted | Removes `gad_has_consent_for_cookies` |
| `adUserData` or `adPersonalization` denied | Sets publisher privacy treatment to disabled and sets `gad_rdp` for [restricted data processing](https://developers.google.com/admob/android/privacy/us-states) |
| Both granted | Sets publisher privacy treatment to enabled and removes `gad_rdp` |

Google Mobile Ads reads `gad_has_consent_for_cookies` and `gad_rdp` from default `SharedPreferences` on Android and `UserDefaults.standard` on iOS when loading an ad. [Publisher privacy treatment](https://developers.google.com/admob/android/targeting#publisher_privacy_treatment) applies to all subsequent requests in the session. When multiple signals apply, Google uses the most restrictive one.

### EEA, UK, and Switzerland

In these regions, Google serves personalized or non-personalized ads only when the request includes a TC string from a [Google-certified CMP](https://developers.google.com/admob/android/privacy/ad-serving-modes). Otherwise it serves limited ads at most. Under an IAB policy, Inth's native core writes the `IABTCF_` keys Google reads. See [mobile IAB and ads](/docs/guides/mobile-iab).

## Before you start

Complete the [Swift](/docs/frameworks/swift/quickstart), [Android](/docs/frameworks/android/quickstart), or [React Native](/docs/frameworks/react-native/quickstart) quickstart and add `marketing` to your Inth policy and native config. See [mobile availability](/docs/guides/mobile-status). Install Google Mobile Ads using Google's [iOS](https://developers.google.com/admob/ios/quick-start), [Android](https://developers.google.com/admob/android/quick-start), or [React Native](https://docs.page/invertase/react-native-google-mobile-ads) guide.

Connect the helper before requesting the first ad. The helper does not request App Tracking Transparency.

## Connect a Swift app

Create and retain `AdMobConsent` for the app lifetime after installing Inth:

```swift title="AdMobConsent.swift"
import InthApple
import InthCore
import Foundation
import GoogleMobileAds

final class AdMobConsent {
    private let integration: AdMobIntegration

    init(core: ConsentCore) {
        integration = AdMobIntegration(core: core) { consent in
            let defaults = UserDefaults.standard
            if consent.adStorage {
                defaults.removeObject(forKey: "gad_has_consent_for_cookies")
            } else {
                defaults.set(0, forKey: "gad_has_consent_for_cookies")
            }
            let personalized = consent.adUserData && consent.adPersonalization
            if personalized {
                defaults.removeObject(forKey: "gad_rdp")
            } else {
                defaults.set(true, forKey: "gad_rdp")
            }
            MobileAds.shared.requestConfiguration.publisherPrivacyPersonalizationState =
                personalized ? .enabled : .disabled
        }
    }

    func stop() { integration.cancel() }
    func syncAfterReset() { integration.sync() }
}
```

The helper applies current permission before `init` returns and runs later updates on the consent-publishing thread. Releasing the owner denies all three advertising types.

## Connect an Android app

Create and retain the helper on your `Application` after installing Inth:

```kotlin title="AdMobConsent.kt"
import android.content.Context
import androidx.core.content.edit
import androidx.preference.PreferenceManager
import com.inth.android.integrations.AdMobIntegration
import com.inth.core.Inth
import com.google.android.gms.ads.MobileAds
import com.google.android.gms.ads.RequestConfiguration.PublisherPrivacyPersonalizationState

fun connectAdMobConsent(context: Context, onError: (Exception) -> Unit): AdMobIntegration {
	val core = checkNotNull(Inth.current) { "Install Inth before connecting AdMob" }
	val preferences = PreferenceManager.getDefaultSharedPreferences(context)
	return AdMobIntegration(
		core = core,
		setConsent = { consent ->
			val personalized = consent.adUserData && consent.adPersonalization
			preferences.edit {
				if (consent.adStorage) remove("gad_has_consent_for_cookies")
				else putInt("gad_has_consent_for_cookies", 0)
				if (personalized) remove("gad_rdp") else putInt("gad_rdp", 1)
			}
			MobileAds.setRequestConfiguration(
				MobileAds.getRequestConfiguration().toBuilder()
					.setPublisherPrivacyPersonalizationState(
						if (personalized) PublisherPrivacyPersonalizationState.ENABLED
						else PublisherPrivacyPersonalizationState.DISABLED,
					)
					.build(),
			)
		},
		onError = onError,
	)
}
```

Keep `onError` non-throwing. It handles automatic update errors while construction, `sync()`, and `close()` throw to their caller.

Wrap `react-native-google-mobile-ads` in `admob-vendor.ts`:

```ts title="admob-vendor.ts"
import mobileAds from 'react-native-google-mobile-ads';

import { connectAppAdMob } from './admob-consent';

export const connectAdMobVendor = (onError: (error: unknown) => void) =>
	connectAppAdMob(
		{
			setConsent: ({ adUserData, adPersonalization }) =>
				mobileAds().setRequestConfiguration({
					publisherPrivacyPersonalizationState:
						adUserData && adPersonalization ? 'enabled' : 'disabled',
				}),
		},
		onError
	);
```

Await `ready` before requesting ads. Pass `requestNonPersonalizedAdsOnly` on individual ad requests from the same permission when needed.

`react-native-google-mobile-ads` cannot write `gad_has_consent_for_cookies` or `gad_rdp`, so the JS helper cannot enable limited ads or restricted data processing. Use the Swift and Kotlin helpers in native code when you need those flags. Expo requires a custom native build, not Expo Go.

## Handle reset and teardown

Call `syncAfterReset()` on Swift, `sync()` on Android, or `await consent.sync()` on React Native to reapply permission without recording a new choice. For final teardown, call `stop()`, `close()`, or `await consent.disconnect()` to detach and deny all advertising types. Already-loaded ads stay as requested.

## Check the integration

1. Launch with no saved choice. Confirm `gad_has_consent_for_cookies` is `0`, `gad_rdp` is set, and ad requests carry disabled privacy treatment.
2. Grant `marketing`. Confirm both keys are removed and personalization is enabled.
3. Withdraw `marketing`. Confirm the denied settings return.
4. Toggle `measurement` only. Confirm nothing changes.

Inspect live requests with Google's [Ad Inspector](https://developers.google.com/admob/android/ad-inspector) or a proxy. Checked against `react-native-google-mobile-ads` `17.4.0`, Android `play-services-ads-api` `25.5.0`, and iOS Google Mobile Ads `13` docs. Complete [mobile verification](/docs/guides/mobile-verify) on real devices.
