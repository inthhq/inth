The `segment` helper keeps Segment Analytics.js off the page and `window.analytics` undefined until `measurement` is granted. On grant, it queues a `page()` call and loads Analytics.js. It sends no consent signal to Segment, and on withdrawal Inth removes the script element and reloads the page by default.

## Configure Segment

Copy the write key from your Segment JavaScript source. The helper builds the loader URL from it.

<CommandTabs command="@inth/integrations" mode="install" />

{/* example: fragment */}

```ts title="src/consent-scripts.ts"
import { segment } from '@inth/integrations/segment';

export const scripts = [segment({ writeKey: 'YOUR_SOURCE_WRITE_KEY' })];
```

## Options

| Option | Default | Behavior |
| --- | --- | --- |
| `writeKey` | Required | Source write key, trimmed. Blank values log an error and skip loading. |
| `loadOptions` | `{}` | Set as `window.analytics._loadOptions` before the loader runs. Analytics.js reads it on initialization. |
| `trackPageView` | `true` | Queues one `analytics.page()` call before the loader. Set `false` to send page views yourself. |
| `scriptUrl` | `https://cdn.segment.com/analytics.js/v1/<writeKey>/analytics.min.js` | Loader URL override. Blank values use the default. |

## Loading and revocation

`segment` uses the `measurement` category. Before grant, Inth defines no `window.analytics` and makes no Segment requests. On grant, it creates the `window.analytics` queue with `track`, `page`, `identify`, `group`, `alias`, and `reset`, sets `_loadOptions`, queues the page view, and loads Analytics.js. On revocation, the helper removes the script element and calls no Segment API.

Segment forwards events to every destination enabled on the source. A `measurement` grant does not cover a destination that requires `marketing` permission. Configure destination consent in Segment, or load that vendor with its own Inth helper instead.

## Guard your own Segment calls

The helper sends only the initial page view. Because `window.analytics` remains defined after revocation, check `measurement` permission from your framework, such as `useConsent('measurement')` in React, before calling `track`, `identify`, or client-side router `page()` calls:

```ts title="src/track-signup.ts"
export function trackSignup(measurementAllowed: boolean, plan: string) {
	if (!measurementAllowed || !window.analytics) return;
	window.analytics.track('Signup', { plan });
}
```

## Verify Segment

1. Allow `measurement` and confirm `analytics.min.js` loads from `cdn.segment.com` with your write key in the path and sends a page call to `api.segment.io`.
2. Confirm each browser destination enabled on the source loads only under the permission it requires.
3. Revoke `measurement` and confirm `trackSignup` sends nothing before the page reloads.
