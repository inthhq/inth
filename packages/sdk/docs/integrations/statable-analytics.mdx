The `statableAnalytics` helper keeps the Statable tracker off the page until a visitor grants `measurement` consent, even though Statable describes its analytics as cookieless. Because Statable provides no stop API, Inth reloads the page on withdrawal by default.

## Configure Statable

Copy your numeric site ID from **Site settings > Tracking Code** in Statable and replace `12345` below. This helper targets the standalone `/js/<siteId>/s.js` tracker available on paid plans and does not support the Hobby plan widget loader. Remove any existing Statable script tag or tag manager entry first.

## Options

| Option | Default | Behavior |
| --- | --- | --- |
| `siteId` | Required | Positive integer as a string or number, trimmed. Missing, blank, fractional, negative, non-decimal, or unsafe integer values log an error and skip loading. |
| `scriptUrl` | `https://statable.com/js/{siteId}/s.js` | Loader URL override. Replaces `{siteId}` with your site ID. Blank values use the default. |
| `trackingApi` | Loader origin plus `/api/event` | Full ingestion URL set as `data-tracking-api`. Blank values omit the attribute so Statable uses its default. |

If you serve the tracker from your own CDN and it does not serve or proxy `/api/event`, set `trackingApi` to the full ingestion URL:

<include src="../shared/examples/javascript/statable-proxy-scripts.mdx" />

A custom `scriptUrl` changes only where the browser fetches the script and does not proxy events. Because Statable relies on the visitor's connection to the ingestion server for reports, check Statable's guidance before proxying collection.

## Loading and revocation

When a visitor grants `measurement`, Inth inserts a deferred script with your site ID in the path and `data-id` attribute. The helper does not define `window.statable` or queue events. The tracker exposes `window.statable.t` after loading and does not replay earlier calls, so check `measurement` permission and `typeof window.statable?.t === 'function'` before sending custom events.

On withdrawal, Inth removes the script element without calling a Statable API. Keep `reloadOnConsentRevoked` enabled so running listeners and timers stop on unload.

## Cookies and storage

Statable reports no cookies and no persistent visitor ID in the browser, though its tracker reads the `analytics_ignore` key in local storage. It sends the full page URL to ingestion and strips query strings and fragments during processing; keep sensitive data out of URLs anyway.

For Content Security Policy, allow `https://statable.com` or your custom loader and ingestion hosts in `script-src` and `connect-src`.

## Verify Statable

Filter DevTools Network by `statable.com` and inspect Cookies, Local Storage, and Session Storage in Application:

1. With `measurement` denied or only `marketing` allowed, confirm no Statable requests or storage entries appear.
2. Allow `measurement`. Confirm one `/js/<siteId>/s.js` script loads and `typeof window.statable?.t === 'function'` returns `true`.
3. With a configured site, verify events post to `/api/event` or your `trackingApi` URL. Statable suppresses collection for automated browsers, Do Not Track, Global Privacy Control, and `analytics_ignore`, so a loaded API alone does not confirm dashboard delivery.

Sources: [tracking script reference](https://statable.com/docs/developers/tracking-script/), [JavaScript API reference](https://statable.com/docs/developers/javascript-api/), and [privacy policy](https://statable.com/privacy).
