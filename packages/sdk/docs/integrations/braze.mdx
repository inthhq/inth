The bundled Braze helper in `InthApple`, `inth-android`, and `@inth/react-native/integrations` keeps Braze disabled until the visitor grants its category, `marketing` by default. While Braze runs, it writes `$google_ad_user_data` and `$google_ad_personalization` custom attributes from the [Consent Mode mapping](/docs/integrations/google-tag#how-categories-map-to-google-consent-types) for Braze [Audience Sync](https://braze.com/docs/partners/canvas_audience_sync/google_audience_sync). Your app installs Braze separately. There is no web helper.

## What the helper changes

| Consent | Braze calls |
| --- | --- |
| Category denied or pending at startup | Disable the SDK |
| Category granted | Enable the SDK once per grant, then set both attributes |
| Marketing changes while category stays granted | Set both attributes |
| Category withdrawn | Disable the SDK only |

[Disabling Braze](https://www.braze.com/docs/developer_guide/analytics/managing_data_collection) cancels network requests and drops pending work. Android and Swift persist the disabled state across launches.

### Braze keeps the last attributes after withdrawal

When the visitor withdraws the category Braze runs under, the helper disables Braze right away and does **not** write `false` to the two attributes first. Disabling cancels in-flight requests, and `requestImmediateDataFlush` on Swift, Android, and React Native reports neither success nor failure, so Inth stops collection immediately rather than sending a write it cannot confirm.

Because Braze's servers keep the last saved values, Audience Sync can keep treating the user as consented. Close that gap in one of two ways:

- Run Braze under a non-marketing category, such as `functionality`, for push notifications and in-app messages. Withdrawing `marketing` leaves Braze running so the helper writes `false` through normal sync.
- When the user withdraws Braze's category, set `$google_ad_user_data` and `$google_ad_personalization` to `false` from your backend using Braze's [`/users/track` endpoint](https://www.braze.com/docs/api/endpoints/user_data/post_user_track), then remove the user from synced audiences per Braze's [Audience Sync guide](https://braze.com/docs/partners/canvas_audience_sync/google_audience_sync). Inth does not do this for you.

## Before you start

Complete the [Swift](/docs/frameworks/swift/quickstart), [Android](/docs/frameworks/android/quickstart), or [React Native](/docs/frameworks/react-native/quickstart) quickstart and add your chosen category to your Inth policy and native config. Install Braze Swift SDK 7.6 or later, the Android SDK, or `@braze/react-native-sdk`.

Push notifications and in-app messages require Braze to run. If you classify them as app functionality rather than marketing, pass `functionality` as the category. The DMA attributes still follow `marketing`.

## Connect a Swift app

```swift title="BrazeConsentOwner.swift"
import BrazeKit
import InthApple
import InthCore

final class BrazeConsentOwner {
    private let integration: BrazeIntegration

    init(core: ConsentCore, braze: Braze) {
        integration = BrazeIntegration(
            core: core,
            setEnabled: { braze.enabled = $0 },
            setGoogleAdsConsent: { consent in
                braze.user.setCustomAttribute(key: "$google_ad_user_data", value: consent.adUserData)
                braze.user.setCustomAttribute(key: "$google_ad_personalization", value: consent.adPersonalization)
            }
        )
    }

    func stop() { integration.cancel() }
    func syncAfterUserChange() { integration.sync() }
}
```

## Connect an Android app

```kotlin title="BrazeConsent.kt"
import android.content.Context
import com.braze.Braze
import com.inth.android.integrations.BrazeIntegration
import com.inth.core.Inth

fun connectBrazeConsent(context: Context, onError: (Exception) -> Unit): BrazeIntegration {
	val core = checkNotNull(Inth.current) { "Install Inth before connecting Braze" }
	return BrazeIntegration(
		core = core,
		enableSdk = { Braze.enableSdk(context) },
		disableSdk = { Braze.disableSdk(context) },
		setGoogleAdsConsent = { consent ->
			Braze.getInstance(context).getCurrentUser { user ->
				user.setCustomUserAttribute("\$google_ad_user_data", consent.adUserData)
				user.setCustomUserAttribute("\$google_ad_personalization", consent.adPersonalization)
			}
		},
		onError = onError,
	)
}
```

Braze requires a fresh `Braze.getInstance` after disabling, which the snippet fetches on each call. `disableSdk` reads `SharedPreferences`, so Braze recommends running it on a background thread.

Wrap `@braze/react-native-sdk` in `braze-vendor.ts`:

```ts title="braze-vendor.ts"
import Braze from '@braze/react-native-sdk';

import { connectAppBraze } from './braze-consent';

export const connectBrazeVendor = (onError: (error: unknown) => void) =>
	connectAppBraze(
		{
			disableSDK: () => Braze.disableSDK(),
			enableSDK: () => Braze.enableSDK(),
			setGoogleAdsConsent: ({ adUserData, adPersonalization }) => {
				Braze.setCustomUserAttribute('$google_ad_user_data', adUserData);
				Braze.setCustomUserAttribute(
					'$google_ad_personalization',
					adPersonalization
				);
			},
		},
		onError
	);
```

On iOS, Braze notes that `enableSDK` from React Native may take effect only on the next launch. Expo requires a custom native build with Braze's config plugin, not Expo Go.

## Handle user changes, reset, and teardown

The attributes belong to the active Braze user. After `changeUser`, call `syncAfterUserChange()` on Swift, `sync()` on Android, or `await consent.sync()` on React Native to record them on the new user. Calling `stop()`, `close()`, or `disconnect()` disables Braze without writing attributes. To clear device data, call Braze's `wipeData`.

## Check the integration

1. Launch with no saved choice. Confirm Braze sends no session.
2. Grant `marketing`. Confirm a session and both attributes set to `true` on the user's profile.
3. Withdraw `marketing`. Confirm Braze stops sending immediately and your backend updates both attributes to `false`.
4. With `category` set to `functionality`, withdraw `marketing` only. Confirm both attributes switch to `false` while Braze keeps running.
5. Relaunch after withdrawal. Confirm Braze stays disabled.

Checked against `@braze/react-native-sdk` `24.0.1`, `android-sdk-base` `45.0.0`, and Braze Swift SDK `19.2.0`. Complete [mobile verification](/docs/guides/mobile-verify) on real devices.
