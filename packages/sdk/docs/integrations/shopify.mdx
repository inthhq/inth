The Inth Shopify bridge forwards each consent choice to Shopify's Customer Privacy API so Shopify analytics, apps, and pixels follow your Inth banner. The bridge loads no scripts. Hydrogen's `ShopifyScripts` loads the Customer Privacy API, and the bridge's `setup` function holds Hydrogen's analytics events until Shopify accepts the visitor's choice.

The runnable storefront in `examples/shopify-nextjs`, listed in [examples](/docs/examples#shopify), runs the code on this page against mock.shop.

Inth's preference dialog shows only categories used on the page. Because Shopify loads through `ShopifyScripts` rather than Inth's `scripts` option, declare the mapped categories in `inth.config.ts` and include them in your policy scope. ## Serve the Storefront API route

The Customer Privacy API saves choices by posting to `/api/<version>/graphql.json` on your storefront. Call Hydrogen's `handleShopifyRoutes` from `proxy.ts` to forward that route and preserve Shopify's cookies:

<include src="../shared/examples/shopify-nextjs/shopify-proxy.mdx" />

The consent route needs no custom handlers. The example wires Hydrogen's cart handlers, keeps store domain and market config in `lib/shop.ts`, and passes a no-op session manager because it has no customer accounts. Pass your own session manager if your storefront signs customers in.

## How categories map

| Shopify consent | Inth source |
| --- | --- |
| `analytics` | `measurement` |
| `marketing` | `marketing` |
| `preferences` | `functionality` |
| `sale_of_data` | Opt-out record, else `marketing` and `measurement` in the active rule's scope |

`analytics`, `marketing`, and `preferences` are `true` only while their mapped Inth category is allowed in `effectivePermissions`, which includes policy restrictions. `sale_of_data` is `false` when an opt-out record is held or when either `marketing` or `measurement` (whichever are in the active rule's scope) is not permitted. Override the mapping for `analytics`, `marketing`, or `preferences` with `categories`:

{/* example: fragment */}

```ts
const shopifyPrivacy = createShopifyCustomerPrivacy({
	categories: { preferences: 'experience' },
});
```

Call `toShopifyConsent(snapshot, categories)` to compute the same four booleans in your own code.

## Options

| Option | Default | Behavior |
| --- | --- | --- |
| `categories` | Default table above | Overrides the Inth category for `analytics`, `marketing`, or `preferences`. |
| `onSync` | None | Runs after Shopify accepts an update, receiving all four values for a choice or the dropped grants for a revocation. |
| `onError` | Logs to the console | Runs when Shopify rejects a choice or `onSync` throws. |

The bridge returns `update(snapshot)`, `connect(source)`, and `setup()`. `connect` subscribes to any source with `getSnapshot` and `subscribe`, such as an Inth kernel, and returns an unsubscribe function.

## Loading and revocation

Shopify records consent only after a visitor acts, so the bridge sends nothing while `policyPending` is `true` or before a choice exists:

- **Opt-in or IAB policy.** `setup` waits until the visitor answers the banner, including Reject All, so Hydrogen holds events until then.
- **Opt-out policy.** `setup` resolves without recording a choice, and Shopify applies its region defaults, including Global Privacy Control, until the visitor saves a choice or records an opt-out in Inth, unless a stale grant must be revoked first.

After the first choice, the bridge sends each change once. When a visitor revokes a category, Inth reloads the page by default and the bridge sends the stored choice on load.

- **Stale grants.** If an earlier choice expired or a policy update prompts again, Shopify may still hold prior grants. When Inth denies any of them, the bridge sends `false` only for those dropped grants so Shopify keeps all other signals, including unset ones. It checks grants it sent plus `yes` values from `currentVisitorConsent()`, and resends the revocation if Shopify reports a dropped grant again from another tab. When `currentVisitorConsent()` is unavailable, it assumes a stored Inth choice may have granted all four values. Opt-in and IAB policies keep holding events until the visitor answers; opt-out resolves `setup` once Shopify accepts the revocation.
- **API loading and retries.** If the Customer Privacy API is not ready yet, the bridge waits for `consentTrackingApiLoaded` or `shopifyCustomerPrivacyApiLoaded`. `setup` resolves once Shopify accepts the latest choice, waits for newer choices if the visitor changes their mind mid-request, and never rejects because Hydrogen stops calling `setup` after a rejection. On rejection, the bridge keeps events blocked and retries after 1, 2, and 4 seconds, then waits for the next update. Pending policies cancel pending retries.

## Limits

- Checkout runs on Shopify's domain without your storefront code, and Shopify reads the stored choice there.
- Shopify analytics require a live store. `mock.shop` accepts consent requests without setting a consent cookie, so `currentVisitorConsent()` stays empty.
- The bridge maps consent categories only and does not translate IAB TCF choices.

## Verify the bridge

1. Load the page in a private window with an opt-in policy and confirm DevTools Network shows no `graphql.json` request containing `visitorConsent`.
2. Click Reject All and confirm one request fires with every value set to `false`.
3. Open Privacy settings, allow Marketing and Measurement, and save. Confirm one request fires with `analytics`, `marketing`, and `saleOfData` set to `true`.
4. On a live store, run `window.Shopify.customerPrivacy.currentVisitorConsent()` in the console and confirm it matches your saved choice.
