Inth gates YouTube videos by wrapping the iframe in your framework's `ConsentGate` or using `data-category` with the HTML script tag, instead of shipping a separate YouTube helper. Until a visitor grants the chosen category, the page contains no YouTube iframe and makes no request to YouTube. On withdrawal, `ConsentGate` unmounts the iframe, and `data-category` moves the URL back from `src` to `data-src`.

## Configure the video

Pick an embeddable video ID and the consent category that matches your policy. This example uses `marketing` because the YouTube player can set advertising identifiers; use `measurement` or another category if your policy requires it.

```ts title="src/embed-config.ts"
export const embedCategory = 'marketing' as const;
export const embedURL =
	'https://www.youtube-nocookie.com/embed/VIDEO_ID?playsinline=1';
export const embedTitle = 'Product walkthrough';
export const embedAspectRatio = '16 / 9';
```

Replace `VIDEO_ID` before running the example.

## Customize the player and placeholder

Pass supported [YouTube player parameters](https://developers.google.com/youtube/player_parameters) in `embedURL`, such as `start=36`, and reserve at least a 200-by-200-pixel player area.

React and Svelte `ConsentGate` render a default blocked-state placeholder with a consent action. Their `placeholder` APIs differ: React accepts a node, and Svelte accepts a snippet. The Vue and browser examples render that action explicitly. Keep a clear control to reopen preferences when customizing the placeholder. `loading="lazy"` defers loading for performance only and does not gate consent.

## Consent behavior

To let visitors disable YouTube while keeping the rest of the category on, add `data-vendor="youtube"` alongside `data-category` and declare a `youtube` vendor in your runtime `vendors` config or policy manifest. See [vendor consent for your framework](/docs/integrations/overview#vendor-switches-and-cookie-cleanup).

The `youtube-nocookie.com` host does not replace consent gating. If your policy requires zero YouTube traffic before consent, avoid loading remote YouTube thumbnails, preconnecting to YouTube domains, or loading the YouTube IFrame Player API separately. Revoking consent removes the iframe and its document, though requests already sent cannot be recalled.

## Verify YouTube

In a fresh opt-in session, confirm no YouTube iframe or network request exists before consent. Grant `marketing` and play the video, then revoke `marketing` and confirm the iframe disappears. Test both a narrow viewport and keyboard navigation across the placeholder and player. See [consent verification](/docs/guides/verify-consent).
