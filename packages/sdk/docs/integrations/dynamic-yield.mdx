The `dynamicYield` helper waits for `experience` consent before creating `window.DY`, setting `DY.userActiveConsent`, and loading `api_dynamic.js` followed by `api_static.js`.

## Configure Dynamic Yield

Copy the section ID and data center from your section's [installation snippet](https://dy.dev/docs/implement-script). Enable [Active Cookie Consent](https://dy.dev/docs/active-cookie-consent) with Dynamic Yield Support; Dynamic Yield ignores the consent API until that setting is enabled. Remove existing Dynamic Yield snippets, tag-manager tags, and preconnects so only Inth loads them.

## Options

| Option | Default | Behavior |
| --- | --- | --- |
| `sectionId` | Required | Public section ID, trimmed and URL-encoded as one path segment. Blank values log an error and skip loading. |
| `region` | `'us'` | `'us'` uses `cdn.dynamicyield.com`; `'eu'` uses `cdn-eu.dynamicyield.com`. Match your section's data center. |
| `recommendationContext` | Unset | Initial page context set before loading. Omit to keep a context your app sets itself. |
| `category` | `'experience'` | Consent category or condition gating both loaders and the consent signal. |
| `nonce` | None | CSP nonce for both loaders. Provider nonces forward to the second loader too. |

`recommendationContext.type` accepts `HOMEPAGE`, `CATEGORY`, `PRODUCT`, `CART`, `POST`, and `OTHER`; `data` holds category hierarchies, product SKUs, post IDs, or page IDs; `lng` selects a feed locale such as `en_GB`. Match your section's feed values per Dynamic Yield's [page context guide](https://dy.dev/docs/page-context). Inth sets only the initial context; update context on client-side navigation per the [context implementation guide](https://dy.dev/docs/code-context) and check consent before calling Dynamic Yield APIs.

## Loading and revocation

Before consent, Inth creates no Dynamic Yield globals, preconnects, requests, or storage. On grant, Inth creates `window.DY` if absent, sets `DY.userActiveConsent = { accepted: true }`, loads `api_dynamic.js`, and appends `api_static.js` after `api_dynamic.js` finishes. If a visitor withdraws consent while `api_dynamic.js` downloads, Inth skips `api_static.js`; regranting starts a new sequence. There is no `alwaysLoad` or denied-mode preloading option.

Dynamic Yield recommends synchronous `<head>` scripts to prevent flicker. Waiting for consent and loading sequentially means visitors can see the original page before campaigns apply, so verify rendering on pages with pre-paint experiments.

- **Shared registrations.** Equivalent options for the same section ID and region share both loader elements across renders. Because `window.DY` is page-global, configure one section and region per page.
- **Withdrawal and disposal.** `DY.userActiveConsent` stays `{ accepted: true }` while any Dynamic Yield registration has consent. Removing or revoking a section's last granted registration removes its loader elements; when no registration has consent, Inth sets `DY.userActiveConsent = { accepted: false }`.
- **Keep `reloadOnConsentRevoked` enabled.** Active Cookie Consent changes collection and personalization only when enabled for the section and does not unload running code or stop in-flight requests.

## Cookies and storage

Dynamic Yield's [cookie and storage inventory](https://dy.dev/docs/cookie-management) caps cookies at 365 days and includes:

| Cookie | Documented lifetime |
| --- | --- |
| `_dyid` | 30 days |
| `_dyjsession` | Browser session |
| `_dy_soct` | 1 year |
| `dy_fs_page` | Browser session |
| `_dy_cs_storage_items` | 30 days |
| `_dy_cs_cookie_items` | 30 days |

Browser storage keys also include `_dyuss_`, `_dy_tsrc`, `_dyaud_nchc`, `_dyaud_page`, `_dy_device`, `_dycst`, `_dy_csc`, `_dyrc`, `_dybatch`, `_dy_cs_session_items`, `_dy_cs_local_items`, and sessionStorage `_dyaud_sess`. Inth does not delete stored cookies or storage on withdrawal; configure cleanup for the keys your section writes.

## Verify Dynamic Yield

Filter DevTools Network by `dynamicyield.com`:

1. Grant `experience` and confirm `api_dynamic.js` finishes before `api_static.js` loads.
2. Inspect `DY.userActiveConsent.accepted` and your page context.
3. Revoke consent and confirm the reloaded page makes no Dynamic Yield requests.
