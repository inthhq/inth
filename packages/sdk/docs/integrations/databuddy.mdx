The `databuddy` helper waits for `measurement` consent before loading `databuddy.js`. Before a visitor allows measurement, the page sends zero requests to Databuddy and stores nothing. On withdrawal, the helper disables the tracker, stops session replay, and Inth reloads the page by default.

## Configure Databuddy

Copy the client ID from your Databuddy project. Remove any existing Databuddy or `replay.js` script tag, `<Databuddy />` component from `@databuddy/sdk`, and code that sets `window.databuddyConfig`; the helper seeds that global only when absent.

<CommandTabs command="@inth/integrations" mode="install" />

{/* example: fragment */}

```ts title="src/consent-scripts.ts"
import { databuddy } from '@inth/integrations/databuddy';

export const scripts = [
	databuddy({ clientId: 'YOUR_CLIENT_ID', features: { interactions: false } }),
];
```

## Options

| Option | Default | Behavior |
| --- | --- | --- |
| `clientId` | Required | Set as `data-client-id` and trimmed. Blank values log an error and skip loading. |
| `loadMode` | `'after-consent'` | `'after-consent'` or `'always'`. See [loading and revocation](#loading-and-revocation). |
| `features.interactions` | Unset, Databuddy default on | Sets `data-track-interactions`. |
| `features.webVitals` | Unset, Databuddy default off | Sets `data-track-web-vitals`. |
| `features.errors` | Unset, Databuddy default off | Sets `data-track-errors`. |
| `features.outgoingLinks` | Unset, Databuddy default off | Sets `data-track-outgoing-links`. |
| `replay` | `false` | `true` or an object loads `replay.js` while allowed. See [record sessions](#record-sessions). |
| `replay.maskText` | Unset, masks text | Sets `data-mask-text` on `replay.js`. Pass `false` to record page text. |
| `replay.recordIframes` | Unset, Databuddy default off | Sets `data-record-iframes` on `replay.js`. |
| `replay.scriptUrl` | `https://cdn.databuddy.cc/replay.js` | Replay URL override. Wins over `version`; blank counts as unset. |
| `configWhenGranted` | `{ apiUrl, clientId, disabled: false }` | Seeded to `window.databuddyConfig` before granted loads and on grant. |
| `configWhenDenied` | `{ apiUrl, clientId, disabled: true }` | `loadMode: 'always'` only. Seeded to `window.databuddyConfig` when denied. |
| `apiUrl` | `https://basket.databuddy.cc` | Collection endpoint, set as `data-api-url`. |
| `version` | Unset | Pins a Databuddy release such as `'2026-10-30.1'` for both scripts. See [pin a release](#pin-a-release). |
| `scriptUrl` | `https://cdn.databuddy.cc/databuddy.js` | Loader URL override. Wins over `version`; blank counts as unset. |

## Turn off features you do not use

Pass `features` switches to override Databuddy's defaults. Unset keys emit no `data-track-*` attribute. Because Databuddy reads `data-*` attributes after `window.databuddyConfig`, a `features` switch overrides the same key in `configWhenGranted` or `configWhenDenied`:

{/* example: fragment */}

```ts
databuddy({
	clientId: 'YOUR_CLIENT_ID',
	features: {
		interactions: false,
		webVitals: false,
		errors: false,
		outgoingLinks: false,
	},
});
```

| Switch | Databuddy default | What Databuddy collects |
| --- | --- | --- |
| `interactions` | On | Rage clicks, dead clicks, and abandoned forms |
| `webVitals` | Off | FCP, LCP, INP, CLS, TTFB, and FPS |
| `errors` | Off | JavaScript errors, with message and stack |
| `outgoingLinks` | Off | Clicks on links to other sites |

## Loading and revocation

| `loadMode` | When `databuddy.js` loads | Before measurement is allowed |
| --- | --- | --- |
| `'after-consent'` | Only while measurement is allowed | Zero requests to Databuddy and no storage |
| `'always'` | On every page, before consent | Script loads and stores a visitor ID in `localStorage` while `disabled: true` stops sending |

On withdrawal, the helper sets `window.databuddy.options.disabled = true` and `window.databuddyConfig.disabled = true`, or applies `configWhenDenied` in `'always'` mode, so in-flight downloads also start disabled. If [`replay`](#record-sessions) is enabled, it stops the recorder immediately, then Inth reloads the page by default. A later grant re-enables both.

Use `loadMode: 'always'` only where your policy permits storing a visitor ID before consent.

## Record sessions

Set `replay` to load Databuddy's separate `replay.js` recorder while measurement is allowed, even when `loadMode` is `'always'`:

{/* example: fragment */}

```ts
databuddy({ clientId: 'YOUR_CLIENT_ID', replay: true });
```

`replay: true` masks page text and typed input by default and reuses your `clientId` and `apiUrl`. Because `replay.js` ignores `options.disabled`, the helper calls `window.databuddyReplay.stop()` and removes the script tag on withdrawal, removal, or disposal without waiting for a reload.

Set `replay: { maskText: false }` only on pages with no personal data; typed input stays masked. Override masking per element with `data-replay-unmask` or hide an element with `data-replay-block`. Set `recordIframes: true` on both parent and framed pages to record embedded pages. See [Databuddy's session replay guide](https://www.databuddy.cc/docs/session-replay) for dashboard controls. Never load `replay.js` with a separate `<script>` tag, or it records before consent.

## Pin a release

By default, the helper loads Databuddy's unversioned `databuddy.js` and `replay.js`, which update with each Databuddy release. Pass `version`, such as `version: '2026-10-30.1'`, to pin both files to `https://cdn.databuddy.cc/databuddy.<version>.js` and `https://cdn.databuddy.cc/replay.<version>.js`.

For releases built into `@inth/integrations`, including `'2026-10-30.1'`, the helper adds an `integrity` attribute so the browser refuses modified CDN files. Other pinned versions and custom `scriptUrl` or `replay.scriptUrl` overrides, which win over `version`, load without an `integrity` attribute.

## Verify Databuddy

1. Open a private window under an opt-in policy. DevTools Network shows zero requests to `cdn.databuddy.cc` or `basket.databuddy.cc`, and Application shows no `did` key in `localStorage`.
2. Click **Reject All** and reload. Requests stay absent.
3. Open Privacy settings and allow measurement. `databuddy.js`, or `databuddy.<version>.js` with `integrity` for `'2026-10-30.1'`, loads from `cdn.databuddy.cc` with your `data-client-id`, and events post to `apiUrl`. With `replay` enabled, `replay.js` loads and posts to `/replay` after pointer or scroll activity.
4. Withdraw measurement and save. Inth reloads the page and sends zero requests to Databuddy.

See the [consent verification guide](/docs/guides/verify-consent) for full checks.
