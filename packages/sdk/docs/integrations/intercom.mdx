The `intercom` helper keeps the Intercom Messenger off the page until `functionality` consent is granted. Before consent, Inth does not define `window.Intercom` or `window.intercomSettings`. On withdrawal, Inth removes the script element without calling `shutdown`, and reloads the page by default to stop the Messenger.

## Configure Intercom

Copy `app_id` from your Intercom snippet and remove the original snippet from your app. Set `apiBase` if your workspace is hosted in the EU or Australia.

<CommandTabs command="@inth/integrations" mode="install" />

{/* example: fragment */}

```ts title="src/consent-scripts.ts"
import { intercom } from '@inth/integrations/intercom';

export const scripts = [intercom({ appId: 'YOUR_APP_ID' })];
```

## Options

| Option | Default | Behavior |
| --- | --- | --- |
| `appId` | Required | Trimmed and used for `app_id` and the loader URL. Empty or whitespace-only values log an error and skip loading. |
| `apiBase` | `https://api-iam.intercom.io` | Regional API base. `INTERCOM_API_BASES` from `@inth/integrations/intercom` exports `us`, `eu`, and `au`. |
| `settings` | None | Extra JSON-serializable fields merged into `window.intercomSettings`. `appId` and `apiBase` override any `app_id` or `api_base` here. |
| `scriptSrc` | `https://widget.intercom.io/widget/<appId>` | Loader URL override. Blank values use the default. |

## Loading and revocation

`intercom` gates on the `functionality` category. When `functionality` is allowed, the helper defines a queueing `window.Intercom` stub, writes `window.intercomSettings`, and loads the Messenger.

On withdrawal, the helper removes the script element without calling any Intercom API, including `shutdown`. The Messenger keeps running until Inth reloads the page.

## Guard your own Intercom calls

The helper writes `settings` once before the Messenger loads and does not update them on login or logout. Send identity changes through Intercom's API yourself, and check `functionality` permission first because `window.Intercom` stays defined after withdrawal:

```ts title="src/intercom-user.ts"
export function updateIntercomUser(
	functionalityAllowed: boolean,
	userId: string
) {
	if (!functionalityAllowed || typeof window.Intercom !== 'function') return;
	window.Intercom('update', { user_id: userId });
}
```

Pass the current `functionality` permission from your framework, such as `useConsent('functionality')` in React.

## Verify Intercom

Allow `functionality` and confirm `widget.intercom.io/widget/<appId>` loads and the Messenger opens. Log in and out of your app and verify the Messenger never displays a previous user's conversations.
