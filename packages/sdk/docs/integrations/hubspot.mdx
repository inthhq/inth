The `hubspot` helper keeps HubSpot's tracking loader off the page until `marketing` consent is granted. Because HubSpot links browsing history to CRM contacts and partner profiling, `measurement` or `functionality` alone does not load it. After consent, the helper disables HubSpot's banner and forwards Inth categories before inserting the loader.

## Configure HubSpot

Copy your numeric portal ID from the HubSpot tracking snippet filename. For `js-eu1.hs-scripts.com/123456.js`, `portalId` is `123456` and `region` is `eu1`. Both are public configuration.

Remove any hand-installed snippets, tag-manager copies, and WordPress plugin tracking code first. HubSpot-hosted CMS pages already inject the tracking code, and this helper cannot gate requests from another installation.

## Options

| Option | Default | Behavior |
| --- | --- | --- |
| `portalId` | Required | Numeric string or number. Trimmed; missing, blank, or non-numeric values log `hubspot: missing or invalid portalId` and load nothing. |
| `region` | None | Lowercase host code such as `na1` or `eu1`, used when `scriptUrl` is omitted or blank. Invalid values log an error and use `js.hs-scripts.com`. |
| `scriptUrl` | `https://js.hs-scripts.com/<portalId>.js`, or regional host | Custom loader URL. Blank values use the default. Does not proxy child scripts or other HubSpot requests. |
| `category` | `'marketing'` | `IntegrationConsentCondition` for the entire loader, such as `{ and: ['marketing', 'measurement'] }`. A weaker condition permits the loader and its child requests under that condition. |
| `chat` | `false` | Set `true` for automatic chat loading. Any active owner can opt in, but every active owner's consent must permit the widget. |
| `nonce` | None | CSP nonce for the loader. Pass it here when required; the provider nonce is not forwarded. Later explicit nonces must match the reserved nonce. |

The helper runs in the browser after hydration and inserts an `async defer` HTTPS script with ID `hs-script-loader`. Register one portal per page. The first registration reserves the portal ID, resolved loader URL, and nonce until reload. Conflicting registrations warn and cannot control the SDK. A matching external `hs-script-loader` is reused with a warning; a conflicting script or non-script element with that ID blocks startup until fixed and reloaded. Core load and error callbacks report controller setup, not the download.

## Consent categories

| Inth category | HubSpot field |
| --- | --- |
| `measurement` | `analytics` |
| `marketing` | `advertisement` |
| `functionality` | `functionality` |

`necessary` and `experience` have no field here because HubSpot manages necessary cookies separately.

Before startup is permitted, Inth creates no HubSpot globals or queues. On grant and changes, it pushes `_hsp.push(['setHubSpotConsent', ...])`. HubSpot does not save these values in its cookies, so Inth resends them on every consented load. When multiple registrations share the controller, every active owner must allow a field for it to be `true`; a failed loader or vendor gate denies all three fields for that owner.

HubSpot's loader can inject analytics, ads pixels, forms, surveys, and chat per portal settings. Its internal fields do not separately gate those network requests, and HubSpot documents anonymous aggregate analytics after refusal.

## Chat

The helper always sets `hsConversationsSettings.loadImmediately = false` before inserting the loader.

- **Automatic chat.** With `chat: true` on any active owner, the controller calls `HubSpotConversations.widget.load()` once every owner's loader condition, vendor permission, and `functionality` consent allow it. On denial or withdrawal, including when adopting an already-loaded widget, it removes the widget, calls `HubSpotConversations.clear({ resetWidget: false })`, and clears late `widgetLoaded` completions.
- **Manual chat.** With `chat: false` or omitted on all owners, Inth registers no chat listeners and never loads, removes, or clears the widget. Enforce consent on your manual calls.

Cleanup does not guarantee remote chat requests stop. For chat visitor identification tokens, see the [HubSpot conversations SDK docs](https://developers.hubspot.com/docs/api-reference/latest/conversations/chat-configuration/chat-widget-sdk).

## Withdrawal and page reload

When any granted HubSpot field becomes denied, the controller queues `revokeCookieConsent` synchronously and then sends the remaining grants. Because `revokeCookieConsent` resets all HubSpot categories with no category argument, a partial withdrawal can clear tracking or chat identity cookies for categories that stay granted.

Unmounting the last owner detaches chat listeners and forwards any real withdrawal saved before disposal. Save consent withdrawals before disposing the loader.

Inth keeps the loader element across withdrawal and remounts so HubSpot's bootstrap does not run twice. Keep `reloadOnConsentRevoked` enabled. `revokeCookieConsent` does not unload child scripts or clear all storage; reloading stops the running page and prevents a fresh load.

## Identification and route changes

HubSpot's script sends the initial page view. Gate your own `identify`, `setPath`, and `trackPageView` calls on current consent and vendor permission, and never use a shared placeholder email for anonymous visitors. See the [HubSpot tracking-code API](https://developers.hubspot.com/docs/api/events/tracking-code).

Check your portal's non-HubSpot forms, ads pixels, and Breeze Intelligence settings, as they control loaded modules. [Clearbit](/docs/integrations/clearbit) uses a separate helper and key.

## Verify HubSpot

Open a private window with DevTools Network open:

1. Before choosing, and with only `measurement` or `functionality` allowed, confirm no HubSpot requests fire.
2. Allow `marketing` and confirm one `hs-script-loader` request to your portal URL and no HubSpot banner.
3. Toggle `measurement` and `functionality`. With `chat: true`, confirm chat loads only when `functionality` is allowed and clears on withdrawal.
4. Withdraw `marketing` and confirm `revokeCookieConsent` queues before the updated consent state. Check actual cookies and requests, not just the queue.

HubSpot portals contact `*.hs-scripts.com`, `*.hs-analytics.net`, `*.hs-banner.com`, `*.hscollectedforms.net`, `*.usemessages.com`, `*.hsadspixel.net`, `*.hubspot.com`, `*.hubspotfeedback.com`, and `*.hubapi.com`. See [HubSpot's CSP guidance](https://knowledge.hubspot.com/domains-and-urls/ssl-and-domain-security-in-hubspot).
