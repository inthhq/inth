Fetch your Inth project's `/v1/consent/manifest` at build time and write a policy JSON resource that the iOS and Android SDKs load before the first network response.

## Command syntax

Run `mobile-manifest` during your native build so every binary ships with current policy rules:

```sh
npx @c15t/cli mobile-manifest \
  --backend-url https://your-project.inth.app \
  --out c15t-policy.json \
  --build release
```

Use `npx @c15t/cli` rather than `npx c15t` (`c15t` has no npm executable); if `@c15t/cli` is in `devDependencies`, `npx` runs your installed copy.

## Options

| Flag | Default | Purpose |
| --- | --- | --- |
| `--backend-url` | Required | Inth project URL, such as `https://your-project.inth.app`. |
| `--out` | `c15t-policy.json` | Output file path for the bundled JSON resource. |
| `--build` | `release` | `release` or `debug`. Sets how network failures behave. |
| `--allow-stale-manifest` | `false` | Reuse an existing file at `--out` for the same project URL when the fetch fails. |
| `--expires-in-days` | `30` | Days until devices emit `policyStale`. |
| `--languages` | English | Comma-separated language codes to bundle copy for. English is always included. |
| `--vendors` | All | Comma-separated IAB vendor IDs to keep in the bundled GVL. |
| `--dry-run` | `false` | Relax URL checks for debug `dryRun` builds while still fetching and writing the file. |

## Project URL and dry-run builds

The command validates `--backend-url` with the native SDK rules and binds the output to its normalized `https://your-project.inth.app` form (missing scheme defaults to `https`, trailing slashes are stripped, host is lowercased). Passing `http`, another host, a port, a path, query parameters, fragments, or credentials fails with `FLAG_INVALID`.

For debug builds using `dryRun` against staging or loopback servers, pass `--dry-run` to allow any `https` URL or `http` on `localhost`, `127.0.0.1`, or `[::1]`:

```sh
npx @c15t/cli mobile-manifest \
  --backend-url http://localhost:8787 \
  --out c15t-policy.json \
  --build debug \
  --dry-run
```

Never pass `--dry-run` on release builds, because release apps refuse `dryRun`. Expo's `bundleManifest` passes `--dry-run` automatically when `dryRun` is enabled.

## Failure behavior

Network errors and HTTP `5xx`, `408`, or `429` count as fetch failures:

- **Release builds** exit non-zero so releases never ship without a manifest.
- **Debug builds** warn, continue, and delete any existing file at `--out` to avoid shipping stale policy.
- **`--allow-stale-manifest`** reuses an existing file at `--out` matching `--backend-url` for air-gapped CI.

Configuration errors (`404`, non-manifest responses, invalid manifests, or missing conservative opt-in/IAB fallback with no preselected optional categories) fail every build. Expired manifests still prompt and save choices offline while emitting `policyStale`; see [mobile offline consent](/docs/guides/mobile-offline).

## Verify the output

1. Run the command with `--build release` against your Inth project URL and confirm exit code `0` and valid JSON at `--out`.
2. Re-run with `--build release` against an unreachable URL (without `--allow-stale-manifest`) and confirm a non-zero exit.
