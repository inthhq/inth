On every page load, Inth evaluates your project's policy, the visitor's stored choice, and live browser privacy signals to decide which consent categories can run right now.

## What Inth evaluates on load

Inth computes permissions from three inputs:

1. **Your project's policy.** Inth matches the visitor's country and region to a policy rule. The rule sets whether optional categories start denied under `opt-in` or allowed under `opt-out`, and whether to show a banner.
2. **The visitor's stored choice.** Inth reads the consent cookie and `localStorage` if a valid record exists under the matched policy.
3. **Live privacy signals.** Inth reads browser signals such as Global Privacy Control on every evaluation.

The result is a map of **permissions**, one boolean per category. Components, script loaders, iframe gates, and network rules read those permissions. While the policy loads, or if resolution fails, every optional category stays denied.

A banner is only the interface. It cannot stop a plain `<script>` tag or a vendor SDK you initialize yourself. Register third-party code with Inth so it waits for permission. See [integrations](/docs/integrations/overview).

## Categories

| Category | Use it for |
| --- | --- |
| `necessary` | Core features required to operate. Always allowed. |
| `functionality` | Optional features such as support chat. |
| `measurement` | Analytics and usage measurement. |
| `experience` | Personalization and experimentation. |
| `marketing` | Advertising, retargeting, and pixels. |

Assign categories by what the code does. Labeling analytics as `necessary` does not make it necessary. See [consent categories](/docs/concepts/consent-categories) for discovery and dialog rules.

## Policy models and prompts

| Model | Optional categories before a choice |
| --- | --- |
| `opt-in` | Denied until the visitor allows them. |
| `opt-out` | Allowed until the visitor refuses them or sends a privacy signal. |
| `iab` | Governed by an IAB TCF 2.4 consent string. |
| `none` | Allowed with no initial prompt. |

| Prompt | What the visitor sees |
| --- | --- |
| `choice` | A banner asking the visitor to accept, reject, or customize categories. |
| `notice` | A dismissible notice. Dismissing records an acknowledgement, not consent. |
| `none` | No banner on load. The rule can still require a preferences link. |

Configure policies in your [Inth](https://inth.com) project. Styling or client code does not override your hosted policy. See [policies](/docs/concepts/policies).

## A permission is not a recorded choice

Mixing up permissions and recorded choices is the most common consent integration bug.

| Concept | Read from | What it answers |
| --- | --- | --- |
| Permission | `effectivePermissions`, `useConsent('measurement')` | May this code run now? Can be `true` under `opt-out` before any action. |
| Recorded choice | `explicitChoice` | What did the visitor decide? Changes only on accept, reject, or save. |
| Prompt state | `promptRequirement` | Does the policy still require a banner or notice? |
| Active rule | `policyRule` | Which rule applies to this visitor? |
| Load status | `resolution.status` | Did the policy resolve to `'matched'`? |

Never copy a permission into a saved choice. Hydrating server state, reading a cookie, or mounting a component is not a visitor action. `onChoiceRecorded` fires only on visitor action. `onPermissionsChanged` also fires when a choice expires or a privacy signal changes.

## Notices and privacy signals

Dismissing a notice records an acknowledgement only. It grants no optional categories and leaves earlier refusals intact.

Global Privacy Control, or GPC, asks sites not to sell or share personal data. The first time Inth sees GPC under a policy that maps it, Inth records a durable opt-out. If the browser already holds an opt-out record from a click or an account when GPC is active under a policy that maps it, Inth sends one `gpc` opt-out request for that record without replacing the local record, and stores a local mark so reloads do not repeat the request until the record is cleared or GPC turns off. Under an opt-out policy, rejecting all or turning `marketing` off in preferences records a durable opt-out too (`measurement` decides when `marketing` is not in the rule's scope). Nothing under an opt-in policy records an opt-out. A durable opt-out switches off the categories the rule's `privacySignals.gpc.denyCategories` lists, whether GPC or the visitor recorded it; a rule that maps no GPC categories switches off `marketing` and `measurement`. The US presets map GPC to `marketing` only, because GPC opts out of sale, sharing and targeted advertising and says nothing about analytics. The browser stores those categories with the record, so a later policy that maps fewer categories never lifts one the visitor already opted out of; an opt-out recorded before the mapping was configurable keeps switching off both `marketing` and `measurement`. The opt-out stays in effect after the browser stops sending GPC, and survives reloads and policy changes. If a visitor turns `measurement` back on while `marketing` stays off, `measurement` stays allowed and the opt-out remains in effect. Turning `marketing` back on and saving under any policy model lifts a device-held opt-out once the browser stops sending GPC. Inth also receives the current GPC value on backend requests.

A `measurement` grant stands under an opt-out only while `marketing` holds an
explicit refusal. Inth does not compare the times of the two. This has two
consequences:

- After a one-click opt-out, `marketing` has no explicit choice yet. Saving
  `{ measurement: true }` alone does not turn `measurement` on. Save
  `{ marketing: false, measurement: true }` instead. The built-in preference
  surfaces already do this, because they save every category they display.
- A visitor who refused `marketing` and granted `measurement` before they
  opted out keeps `measurement` on after the opt-out.

## What happens when a visitor saves

When a visitor clicks Accept, Reject, or Save, Inth runs five steps:

1. Updates `effectivePermissions` and closes the banner or dialog in the same click, so gated scripts, embeds, and network rules react right away.
2. Writes the choice to the consent cookie and `localStorage`.
3. Sends the choice to `/v1/consent/records` with `keepalive: true` (when the UTF-8 body is at most 32 KiB) so a reload or tab close does not cancel it. If the save also records or lifts a durable opt-out, Inth sends the opt-out act to `/v1/consent/opt-outs` or `/v1/consent/opt-outs/lift` with `keepalive: true` as well. If a request fails or is interrupted, the local state stays in effect and the stored queue replays the request on the next page or when the browser comes back online. If the backend answers `404` on an opt-out route, Inth keeps opt-outs local without errors.
4. Applies any authoritative opt-out record returned by the backend (replacing the local timestamp, method, and holder) and persists it.
5. Reloads the page if the visitor revoked a previously allowed category, waiting up to one second, counted from when the choice is stored on the device, for in-flight save, opt-out, and lift requests, because already-executed code cannot be unloaded. A one-click opt-out reloads the same way when it turns off an allowed category and shows the opt-out confirmation view once on the new page. Because the new choice and opt-out record are already stored in cookies and `localStorage` and init carries no choices or opt-outs, the next page reflects the new state right away; a local opt-out's `rights` stay empty until the request finishes or replays after init. Privacy signals, expiry, policy changes, and backend-synced opt-outs do not reload. With `persistence: false`, nothing reloads because a reload would discard the choice it was for. Set `reloadOnConsentRevoked: false` to handle revocation yourself. The Google tag and Google Tag Manager load before consent by default with Consent Mode signals, so set `loadMode: 'after-consent'` if you want no request to Google from an opted-out visitor.

When `identify()` links the device to an account, the link response can carry the account's active opt-out (`heldBy: 'person'`). Inth adopts that record, switches off `marketing` and `measurement` in scope by default, and persists it across reloads. Lifting an account-held opt-out requires an `optIn()` call (or a save that grants `marketing`) with a verifying identity token; when the backend clears the opt-out and answers `optOut: null`, Inth removes the local record as well.
