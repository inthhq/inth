On every page load, Inth evaluates your project's policy, the visitor's stored choice, and live browser privacy signals to decide which consent categories can run right now.

## What Inth evaluates on load

Inth computes permissions from three inputs:

1. **Your project's policy.** Inth matches the visitor's country and region to a policy rule. The rule sets whether optional categories start denied under `opt-in` or allowed under `opt-out`, and whether to show a banner.
2. **The visitor's stored choice.** Inth reads the consent cookie and `localStorage` if a valid record exists under the matched policy.
3. **Live privacy signals.** Inth reads browser signals such as Global Privacy Control on every evaluation.

The result is a map of **permissions**, one boolean per category. Components, script loaders, iframe gates, and network rules read those permissions. While the policy loads, or if resolution fails, every optional category stays denied.

A banner is only the interface. It cannot stop a plain `<script>` tag or a vendor SDK you initialize yourself. Register third-party code with Inth so it waits for permission. See [integrations](/docs/integrations/overview).

## Categories

| Category | Use it for |
| --- | --- |
| `necessary` | Core features required to operate. Always allowed. |
| `functionality` | Optional features such as support chat. |
| `measurement` | Analytics and usage measurement. |
| `experience` | Personalization and experimentation. |
| `marketing` | Advertising, retargeting, and pixels. |

Assign categories by what the code does. Labeling analytics as `necessary` does not make it necessary. See [consent categories](/docs/concepts/consent-categories) for discovery and dialog rules.

## Policy models and prompts

| Model | Optional categories before a choice |
| --- | --- |
| `opt-in` | Denied until the visitor allows them. |
| `opt-out` | Allowed until the visitor refuses them or sends a privacy signal. |
| `iab` | Governed by an IAB TCF 2.4 consent string. |
| `none` | Allowed with no initial prompt. |

| Prompt | What the visitor sees |
| --- | --- |
| `choice` | A banner asking the visitor to accept, reject, or customize categories. |
| `notice` | A dismissible notice. Dismissing records an acknowledgement, not consent. |
| `none` | No banner on load. The rule can still require a preferences link. |

Configure policies in your [Inth](https://inth.com) project. Styling or client code does not override your hosted policy. See [policies](/docs/concepts/policies).

## A permission is not a recorded choice

Mixing up permissions and recorded choices is the most common consent integration bug.

| Concept | Read from | What it answers |
| --- | --- | --- |
| Permission | `effectivePermissions`, `useConsent('measurement')` | May this code run now? Can be `true` under `opt-out` before any action. |
| Recorded choice | `explicitChoice` | What did the visitor decide? Changes only on accept, reject, or save. |
| Prompt state | `promptRequirement` | Does the policy still require a banner or notice? |
| Active rule | `policyRule` | Which rule applies to this visitor? |
| Load status | `resolution.status` | Did the policy resolve to `'matched'`? |

Never copy a permission into a saved choice. Hydrating server state, reading a cookie, or mounting a component is not a visitor action. `onChoiceRecorded` fires only on visitor action. `onPermissionsChanged` also fires when a choice expires or a privacy signal changes.

## Notices and privacy signals

Dismissing a notice records an acknowledgement only. It grants no optional categories and leaves earlier refusals intact.

Global Privacy Control, or GPC, asks sites not to sell or share personal data. The first time Inth sees GPC under a policy that maps it, Inth records a durable opt-out. Under an opt-out policy, rejecting all or turning both `marketing` and `measurement` off in preferences records a durable opt-out too. A durable opt-out switches off `marketing` and `measurement` in scope, stays in effect after the browser stops sending GPC, and survives reloads and policy changes. Turning either `marketing` or `measurement` back on in preferences lifts a device-held opt-out once the browser stops sending GPC. Inth also receives the current GPC value on backend requests.

## What happens when a visitor saves

When a visitor clicks Accept, Reject, or Save, Inth runs five steps:

1. Updates `effectivePermissions` and closes the banner or dialog in the same click, so gated scripts, embeds, and network rules react right away.
2. Writes the choice to the consent cookie and `localStorage`.
3. Sends the choice to `/v1/consent/records`. If the save also records or lifts a durable opt-out, Inth sends the opt-out act to `/v1/consent/opt-outs` or `/v1/consent/opt-outs/lift` as well. If a request fails, the local state stays in effect and Inth retries automatically. If the backend answers `404` on an opt-out route, Inth keeps opt-outs local without errors.
4. Applies any authoritative opt-out record returned by the backend (replacing the local timestamp, method, and holder) and persists it.
5. Reloads the page if the visitor revoked a previously allowed category, because already-executed code cannot be unloaded. Set `reloadOnConsentRevoked: false` to handle revocation yourself.

When `identify()` links the device to an account, the link response can carry the account's active opt-out (`heldBy: 'person'`). Inth adopts that record, switches off `marketing` and `measurement` in scope, and persists it across reloads. Lifting an account-held opt-out requires an `optIn()` call (or a granting save) with a verifying identity token.
