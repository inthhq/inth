## Connect an Inth project

Inth serves your policies and records consent choices. For automated tests, switch to `testing()` so no network requests leave the test runner.

| Option | Use it when |
| --- | --- |
| [Inth project](https://inth.com/dashboard/sign-up) | Production, preview and local development. Every guide connects to an Inth project URL. |
| [`testing()`](/docs/concepts/modes#testing) | Automated tests. Resolves a policy locally with no network calls and throws in production builds. |

Create a project in the [Inth dashboard](https://inth.com/dashboard/sign-up) or with `@inth/cli`, configure regional policy rules, add your site's origin to trusted origins, and copy the project URL. The guides use `https://your-project.inth.app` as a placeholder; replace it with your project URL, including any path prefix.

## Server rendering or browser rendering

Where consent resolves controls what arrives in the first HTML response.

| Rendering | What the visitor gets |
| --- | --- |
| The server resolves consent for each request | The server reads the visitor's cookie and location headers, so the browser starts with the answer. The banner can arrive in server HTML. In Next.js, TanStack Start, Nuxt, SvelteKit and Angular, scripts the visitor already permitted start before hydration. |
| The browser resolves consent | Every visitor receives the same HTML. After the page loads, the browser resolves the policy, then shows the banner or starts gated scripts. |

A static or prerendered page cannot embed one visitor's consent because every visitor shares the same HTML. Static sites connect directly to Inth from the browser; a same-origin proxy route only works where a server runs it.

Cached routes shared across visitors, such as Next.js ISR or `'use cache'` pages, need browser resolution for the same reason. Cache the public policy manifest, never a response that carries one visitor's consent state.

## How the server gets the policy

Server-rendered frameworks default to `manifest()`. Their build integrations download your project's public policy snapshot once at build time so the server resolves each request locally without calling `/v1/consent/init`. Rebuild after you change policies, translations or vendors in Inth.

Single-page apps in React, Vue and Svelte have no application server, so their quickstarts default to `hosted()`. The browser calls `/v1/consent/init`, and Inth reads the visitor's location from that request.

If policy edits must reach a server-rendered deployment without a rebuild, switch to a runtime path:

- **Cached runtime manifest**, `manifest({ source: 'runtime' })`. Your server downloads and caches the public policy file, then resolves each visitor locally.
- **Direct `/v1/consent/init`**, `hosted()`. Every visit asks Inth to resolve the visitor directly.
