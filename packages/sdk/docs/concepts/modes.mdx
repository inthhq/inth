Every Inth provider needs `projectUrl`, such as `https://your-project.inth.app`, to save consent choices. Omit `mode` unless you want to override your framework's default.

| Mode | Policy resolution | First-visit requests to Inth | Default in |
| --- | --- | --- | --- |
| `manifest()` | Your server from a build snapshot. Browser in SPAs or with `resolve: 'browser'`. | Zero on the server. Saves post to `/v1/consent/records`. | Next.js, TanStack Start, Nuxt, SvelteKit, Astro, Angular SSR with `provideInthServer()` |
| `hosted()` | Inth `/v1/consent/init` | One `/v1/consent/init` per page load. | React, Vue, Svelte, Angular in browser, `@inth/sdk`, script tag |
| `testing()` | Browser from local rules | None. | Never. Import from `/testing` in tests only. |

`projectUrl` is required unless `mode` is `testing()` or `enabled` is `false`. Server-rendered frameworks also read it from an environment variable. See [set the project URL](#set-the-project-url) and [data fetching](/docs/concepts/data-fetching).

## Import the factories from your framework package

| Framework | `manifest()` and `hosted()` | `testing()` | Config location | Kind |
| --- | --- | --- | --- | --- |
| Next.js | `@inth/nextjs` | `@inth/nextjs/testing` | `mode` in `inth.config.ts` | Data |
| TanStack Start | `@inth/tanstack-start` | `@inth/tanstack-start/testing` | `resolveConsent({ mode })` | Data |
| Nuxt | `@inth/nuxt` | `@inth/nuxt/testing` | `inth.mode` in `nuxt.config.ts` | Data |
| Astro | `@inth/astro` | `@inth/astro/testing` | `inth({ mode })` in `astro.config.mjs` | Data |
| SvelteKit | `@inth/svelte/kit` | `@inth/svelte/testing` | `inthHandle({ mode })` in `src/hooks.server.ts` | Data |
| React | `@inth/react` | `@inth/react/testing` | `InthProvider` `options.mode` | Transport |
| Vue | `@inth/vue/vue-plugin` | `@inth/vue/testing` | `app.use(inth, { mode })` | Transport |
| Svelte | `@inth/svelte` | `@inth/svelte/testing` | `<InthProvider mode={...}>` | Transport |
| Angular | `@inth/angular` | `@inth/angular/testing` | `provideInth({ mode })` | Transport |
| JavaScript | `@inth/sdk` | `@inth/sdk/testing` | `init({ mode })` | Transport |
| Script tag | None | `inth.testing.js` | `data-mode="manifest"` on headless and IAB tags | Name |

- **Data factories** return plain objects like `{ type: 'manifest' }` so SSR frameworks serialize config across server and browser and lazy-load non-default transports with `import()`. Shared code can import data factories from `@inth/sdk/modes`.
- **Transport factories** return transport instances directly so SPA bundlers tree-shake unused modes. `hosted()` is a data factory everywhere because it takes no options and reads `projectUrl` from the provider.

## manifest()

`manifest()` resolves policies from your Inth project's public [consent manifest](/docs/concepts/data-fetching#what-is-a-consent-manifest) instead of calling `/v1/consent/init`.

| Option | Default | Behavior |
| --- | --- | --- |
| `source` | `'build'` | `'build'` reads the build snapshot and falls back to runtime fetch if missing. `'runtime'` always fetches at runtime so policy edits apply without rebuilding. |
| `snapshot` | None | Supplies a manifest object directly. Cannot be combined with `source`. |
| `resolve` | `'server'` | `'server'` resolves on your server and keeps the resolver out of browser bundles. `'browser'` resolves in the browser for static or cached pages. SSR frameworks only. |
| `manifestUrl` | Derived | Custom manifest URL. Defaults to `${projectUrl}/v1/consent/manifest` on the server, and `${routePrefix}/v1/consent/manifest` or `${projectUrl}/v1/consent/manifest` in the browser. |
| `geoUrl` | None | Same-origin endpoint returning `{ country, region }`. Browser resolution only. |
| `inputs` | None | Known `{ country, region }` from an edge worker or host header. Browser resolution only. |

SPA transport `manifest()` factories in `@inth/react`, `@inth/vue/vue-plugin`, `@inth/svelte`, `@inth/angular`, and `@inth/sdk` always resolve in the browser, omit `resolve`, and accept `projectUrl`, `headers`, `credentials`, `domain`, `fetch`, and `initFallback`. With no arguments, they use the generated build snapshot and URL.

When browser resolution needs a visitor's location for a regional policy, it calls `geoUrl` first, then falls back to `/v1/consent/init`. Set `initFallback: false` to resolve as an unknown location instead. The Vite `consentManifest()` plugins warn if an SPA bundles a regional policy without `inputs` or `geoUrl`.

### Fallback behavior

If a manifest cannot be read during build, on the server, or in the browser, Inth logs one warning per manifest URL and falls back to `/v1/consent/init`. Browser fetches retry the manifest on the next initialization. Invalid configuration, such as a malformed `manifestUrl`, still throws.

## hosted()

`hosted()` calls `GET ${projectUrl}/v1/consent/init` to resolve each visitor's policy and posts choices to `POST ${projectUrl}/v1/consent/records`. It takes no options in data-factory packages. It is the default in React, Vue, Svelte, browser Angular, `@inth/sdk`, and the script tag. Pass `hosted()` in an SSR framework to resolve every request directly through Inth.

## testing()

`testing()` resolves policies in the browser with no `projectUrl` and no network requests. Import it from `/testing` in tests only. It throws when `NODE_ENV` is `'production'` so test config never ships to visitors.

| Option | Default | Behavior |
| --- | --- | --- |
| `policy` | Recommended pack | One `PolicyRule` or an array of rules to evaluate instead of the built-in pack. |
| `iab` | Provider IAB setting | Uses the IAB TCF variant of the recommended rule pack. |

Use `overrides.country` and `overrides.region` to pick a rule from the recommended pack: EEA countries or `GB` show an opt-in banner, `DE` with IAB shows the TCF banner, US privacy states like `US`/`CA` run opt-out without a banner, and `JP` shows no banner. Pass `policy` for prompts not in the default pack, such as `prompt: 'notice'`:

{/* example: fragment */}

```tsx
import { InthProvider } from '@inth/react';
import { testing } from '@inth/react/testing';

<InthProvider
	options={{
		mode: testing({
			policy: {
				id: 'notice',
				match: { fallback: true, isDefault: true },
				model: 'opt-out',
				prompt: 'notice',
			},
		}),
	}}
/>;
```

Set `enabled: false` to bypass consent completely in app tests: every category is allowed, no UI renders, and no requests fire. Script-tag sites use `inth.testing.js`; production script files exclude the testing transport and rule pack.

## What each mode adds to first-load JavaScript

Server-rendered frameworks send resolved state in the HTML and lazy-load mode code only when needed:

| Mode | First-load JavaScript | Lazy-loaded via `import()` |
| --- | --- | --- |
| `manifest()` | Save client and init request builder | Hosted `/v1/consent/init` path if the browser must re-init |
| `manifest({ resolve: 'browser' })` | Save client | Browser resolver, English copy, and manifest fetch; other locales load per language |
| `hosted()` | Save client | Hosted `/v1/consent/init` path |
| `testing()` | Nothing mode-specific | Testing transport, rule pack, and copy |

Server-resolved `manifest()` keeps the snapshot, resolver, rule pack, and inactive languages out of browser bundles.

Single-page apps bundle only the imported mode:

| Mode | Included in bundle |
| --- | --- |
| `manifest()` | Build snapshot if downloaded, save client, and English copy. Resolver loads on run unless location needs `/v1/consent/init`; other locales load on demand. |
| `hosted()` or omitted | Hosted transport |
| `testing()` | Testing transport, recommended rule pack, and copy |

## Set the project URL

Store your public Inth project URL in `.env` or your host's build settings. The URL is public configuration, not a secret.

| Framework | Primary variable | Legacy variable |
| --- | --- | --- |
| Next.js | `NEXT_PUBLIC_INTH_PROJECT_URL` | `NEXT_PUBLIC_C15T_BACKEND_URL` |
| Nuxt | `NUXT_PUBLIC_INTH_PROJECT_URL` | `NUXT_PUBLIC_C15T_BACKEND_URL` |
| Astro | `PUBLIC_INTH_PROJECT_URL` | `PUBLIC_C15T_BACKEND_URL` |
| SvelteKit and Svelte | `PUBLIC_INTH_PROJECT_URL`, then `VITE_INTH_PROJECT_URL` | `PUBLIC_C15T_BACKEND_URL`, then `VITE_C15T_BACKEND_URL` |
| TanStack Start, React, Vue, and Vite JS | `VITE_INTH_PROJECT_URL` | `VITE_C15T_BACKEND_URL` |
| Script tag | `data-project-url` attribute | None |

Use `*_INTH_PROJECT_URL` for new projects so other Inth SDKs read the same value. Resolution checks `projectUrl` in code first, then `*_INTH_PROJECT_URL`, then legacy `*_C15T_BACKEND_URL` as a fallback, checking process env, `.env.[mode].local`, `.env.[mode]`, `.env.local`, and `.env` for each variable. Next.js inlines `NEXT_PUBLIC_` variables at build time, so updates require a rebuild.

## Download the manifest at build time

`manifest()` with default `source: 'build'` reads a snapshot fetched from `${projectUrl}/v1/consent/manifest` by your build integration:

| Framework | Build integration | Log prefix |
| --- | --- | --- |
| Next.js | `withConsentManifest()` from `@inth/nextjs/build` in `next.config.ts` | `@inth/nextjs/build` |
| TanStack Start | `consentManifest()` from `@inth/tanstack-start/build` | `@inth/tanstack-start/build` |
| React | `consentManifest()` from `@inth/react/build` | `@inth/sdk/build` |
| JavaScript | `consentManifest()` from `@inth/sdk/build` | `@inth/sdk/build` |
| Vue | `consentManifest()` from `@inth/vue/vite` | `@inth/vue/vite` |
| Svelte and SvelteKit | `consentManifest()` from `@inth/svelte/vite` | `@inth/svelte/vite` |
| Nuxt | `@inth/nuxt` module | `@inth/nuxt` |
| Astro | `inth()` integration | `@inth/astro` |

The integration fetches the manifest on build or dev start with a 10-second timeout and writes nothing into your source tree. App code reads generated values from `/generated`, such as `@inth/react/generated` or `@inth/sdk/generated`:

{/* example: fragment */}

```ts
import { projectUrl, snapshot } from '@inth/react/generated';
```

Both exports are `undefined` when no snapshot exists so fresh checkouts compile. In SSR browser bundles, `snapshot` is always `undefined`, and Next.js fails the build if a Client Component imports `@inth/nextjs/generated`. Rebuild after editing policies, translations, or vendors in Inth, and bypass stale CI build caches.

## What happens when the download fails

By default, `onBuildError` is `'runtime'`: a failed download or missing project URL logs a warning and continues without a snapshot, so your server or browser fetches `/v1/consent/manifest` at runtime and falls back to `/v1/consent/init` if needed.

| `onBuildError` | Behavior |
| --- | --- |
| `'runtime'` | Default. Warns and continues. Pass explicitly to turn a missing URL warning into a notice. |
| `'fail'` | Stops both build and dev with an error. |

Configure `onBuildError` on `withConsentManifest()`, `consentManifest({ onBuildError })`, `inth.onBuildError` in `nuxt.config.ts`, or `inth({ onBuildError })` in Astro. Override it in CI with `INTH_ON_BUILD_ERROR`:

```sh
INTH_ON_BUILD_ERROR=fail npm run build
```

Values other than `fail` or `runtime` stop the command. In Turborepo strict mode, add `INTH_ON_BUILD_ERROR` to `passThroughEnv`. In Astro and Nuxt, `manifest()` mode, including `manifest({ snapshot })`, still requires a project URL during dev so the browser can save choices.

Downloads skip without error when no snapshot applies:

- Relative project URLs like `/api/inth`, unless `onBuildError: 'fail'` is set.
- Next.js `output: 'export'`.
- Next.js, Nuxt, or Astro configured with `hosted()`, `testing()`, `manifest({ snapshot })`, or `manifest({ source: 'runtime' })`.
- Vite SPAs in React, Vue, Svelte, or JavaScript that do not import `manifest()`. SvelteKit and TanStack Start select mode at runtime, so their builds always fetch.

Failed downloads never reuse an older snapshot. See [troubleshooting manifest downloads](/docs/guides/troubleshooting#why-does-the-build-fail-to-download-the-manifest).
