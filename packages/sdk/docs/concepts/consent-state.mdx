This reference documents the runtime state machine, storage rules, and edge cases behind [how consent works](/docs/concepts/how-consent-works). Use it when building custom UI, sharing consent across subdomains, or debugging state across tabs.

## Snapshot fields

`getSnapshot()` and every `subscribe` listener return a frozen object. Unchanged fields keep reference equality with `===`.

| Field | Type | Meaning |
| --- | --- | --- |
| `effectivePermissions` | `Record<category, boolean>` | Current allow/deny map. Gate scripts, embeds, and features on this. |
| `restrictions` | Per-category list | Active denial reasons: `'explicit-denial'`, `'strict-scope'`, or `'gpc'`. |
| `privacySignals.gpc` | `{ detected, override, active }` | Browser GPC signal, test override, and enforced live value. |
| `explicitChoice` | `{ version, categories } \| null` | Visitor's recorded decisions with `value` and `confirmedAt`. `null` until accept, reject, or save. |
| `noticeDismissal` | `{ dismissedAt, fingerprint } \| null` | Recorded notice acknowledgement. Never grants optional categories. |
| `vendorChoice` | `{ denied, confirmedAt } \| null` | Non-IAB vendors explicitly denied by the visitor. |
| `subject` | `{ subjectId?, externalId?, identityProvider? } \| null` | Visitor identity. Present in browser memory before any choice, so alone it is not consent. |
| `promptRequirement` | `{ kind, reason? }` | Owed interaction: `'choice'`, `'notice'`, or `'none'`, with reason `'missing'`, `'expired'`, or `'policy-changed'`. |
| `resolution` | `{ status, policy }` | Policy status: `'matched'`, `'no-match'`, `'failed'`, or `'unconfigured'`. `policy` is set only when `'matched'`. |
| `policyPending` | `boolean` | `true` until the first transport response. Stock UI stays hidden while `true`. |
| `policyRule` | Resolved rule | Active rule, or strict opt-in fallback while pending or failed. |
| `activeUI` | `'banner' \| 'dialog' \| 'none' \| null` | Active surface to render. |
| `policySnapshotToken` | `string \| null` | Signed token sent with saves so Inth verifies the policy version. |
| `iab` | Object or `null` | IAB TCF vendor list, TC string, and purpose/vendor choices under an IAB policy. |
| `nextDeadline` | `number \| null` | Epoch milliseconds when the next choice or notice expires. |
| `revision` | `number` | Monotonic counter incremented on every state change. |

## Resolution lifecycle and subject ID

Check `resolution.status === 'matched'` before treating `policyRule` as your project's policy. While `policyPending` is `true` or after failure, `policyRule` holds a strict opt-in fallback so optional code stays blocked.

Every browser runtime generates a `sub_...` subject ID in `snapshot.subject.subjectId`:

- **Before the first save.** Lives in memory only. Inth writes no cookie or `localStorage` entry pre-choice, so reloads generate a new ID.
- **After the first save.** Persists with the consent record across reloads and server renders.
- **After clearing or revoking.** `clearRecords()` deletes stored records and keeps the ID in memory for the current page. Revoking consent is a save and keeps the ID. Call `set.subjectId(null)` to issue a new ID.

## When a choice is saved

Saves update the browser optimistically before sending to Inth. Stock surfaces and client methods `acceptAll()`, `rejectAll()`, and `save()` close without waiting on the network.

| Step | Timing | Action |
| --- | --- | --- |
| 1 | Click task | Updates `explicitChoice` and `effectivePermissions`, runs `onChoiceRecorded` and `onPermissionsChanged`, updates gated scripts, embeds, and network rules, and closes the surface while its exit animation plays. |
| 2 | Next task | Writes the record to the consent cookie and `localStorage`. |
| 3 | After write queues | Posts the consent payload to Inth. |
| 4 | On network settle | Emits `command:save:completed` and settles promises from `kernel.commands.save()`, `performAction()`, and `saveConsents()`. |
| 5 | Next task on revocation | If a save or one-click opt-out turned off a previously allowed category or vendor, runs `onBeforeConsentRevocationReload` and reloads the page after the last in-flight save or opt-out command settles. When a one-click opt-out triggers a reload, the confirmation view opens once on the new document instead of flashing before the reload. Privacy signals, expiry, policy changes, and backend-synced opt-outs do not reload. Set `reloadOnConsentRevoked: false` to handle revocation yourself. |

### Surface transitions

- After a save or closing the dialog without saving, stock UI shows the banner only while the policy still requires a choice or notice, and nothing once satisfied, pending, or failed.
- Reopened banners and unchanged saves close on success unless another surface opened or another save started.
- Under IAB, the surface closes in the click task, while the choice records once the TC string encodes. If local encoding fails, the surface reopens.

### Offline retries and failed saves

- Before sending, Inth queues the payload in `localStorage`, or in memory if storage is blocked.
- Failed requests never roll back local state or reopen the banner. They emit `command:error`, reaching `onError`, and keep the payload queued.
- Queued saves replay after the next successful init and on reconnect, up to 10 attempts over 7 days, keeping the original timestamp and `policySnapshotToken`. Duplicate replays resolve to the same record.
- Transient replay failures emit `save:replayed` with `ok: false` without repeating `command:error`.
- Permanent rejections like an expired snapshot token, 10 failed attempts, or 7 days elapsed drop the item, emit `command:error` once, and log a `[inth]` warning in development. The choice stays stored locally only.

## Sync durable opt-outs

A local opt-out takes effect in the browser at once with `rights: []` and blocks `marketing` and `measurement` in scope before any network call. When the transport supports opt-outs (`hosted()` and `manifest()`), every local opt-out act syncs to Inth:

- `POST /v1/consent/opt-outs` runs when `commands.optOut()` records an opt-out, a save under an opt-out policy refuses `marketing` (or `measurement` when `marketing` is not in scope), a live browser kernel detects GPC under a policy that maps it, or once when GPC is active under a policy that maps it while the browser already holds an opt-out record it has not yet reported GPC for. The held-record request does not change `snapshot.optOut` locally or emit `opt-out:recorded`; Inth stores a local mark beside the opt-out record when it queues a `gpc` request and clears that mark when the record is cleared or GPC turns off. The body carries `subjectId`, `property`, `method` (`'button'` or `'gpc'`), `givenAt`, a per-act UUID `idempotencyKey`, optional identity fields, and snapshot context (`policyId`, `country`, `region`, `language`, `policySnapshotToken`). The SDK omits `rights`: the backend derives which rights apply from the visitor's location and returns them in `optOut.rights`.
- `POST /v1/consent/opt-outs/lift` runs when `commands.optIn()` lifts an opt-out or a save under any policy model grants `marketing` (or `measurement` when `marketing` is not in scope) while an opt-out is active. The body carries `subjectId`, `property`, `givenAt`, `idempotencyKey`, optional identity fields, `policySnapshotToken` when held, and `uiSource`, omitting `rights` so all device-held rights lift. With a verified identity token, the server also clears opt-outs recorded by click on that person's other devices and can answer `optOut: null`, which clears the locally held record.
- `POST /v1/consent/records` and `POST /v1/subjects/:id/link` can also return an effective `optOut` object.

Local device acts queue in `localStorage` under `inth-pending-opt-outs:v1` before the request starts, separate from pending consent saves. Queued acts replay in strict order on the next init and on reconnect, without narrowing or supersession, and are never dropped for policy or snapshot-token changes. Identity tokens are never written to storage; a replay reads the token from the current user if set. A `409 subject_conflict` moves the visitor to a new subject ID and resends once; `413` and `400 invalid_request` drop the entry.

If the transport has no `optOut` method (such as `testing()`, the offline transport, or a custom transport without one), Inth records all three rights (`sale`, `share`, `targeted_ads`) locally. If the backend answers `404` on either opt-out route, Inth treats the backend as not storing opt-outs. It empties the opt-out queue, fills an empty local `rights` list with all three rights through `opt-out:synced` without overwriting backend-supplied rights, creates later local records on that kernel with all three rights, stops sending opt-out requests, and reports no error or warning.

When any response carries a valid `optOut` (or a lift returns `optOut: null`), Inth stores the backend's authoritative record (using the server's `rights`, `recordedAt`, `method`, and `heldBy`), emits `opt-out:synced`, and writes the updated record to storage without sending another request. Stale answers that arrive after a newer local opt-out act, a records clear, or a subject switch are ignored.

## Storage persistence and conflict rules

Inth writes consent records to both a cookie for SSR and `localStorage`.

| Rule | Behavior |
| --- | --- |
| Cookie authority | A well-formed cookie wins even when expired, so a local copy cannot revive a grant the cookie dropped. |
| Denials win | On same-millisecond conflicts, denial wins. If a cookie write fails, such as exceeding cookie size limits, while `localStorage` succeeds, newer local denials layer onto the cookie while newer local grants do not. `<storageKey>-cookie-miss` tracks dropped cookie writes until the next cookie write or clear. |
| Storage full | If `localStorage` rejects a write that the cookie accepts, the stale `localStorage` copy is removed. |
| Notice records | Stored in v1 format in `<key>-notice`, with subject bound in `<key>-notice-subject` by matching timestamp and fingerprint. Rewritten on subject ID changes and protected from wildcard cleanup. |
| Vendor denials | A `localStorage` vendor copy at least as new as the cookie adds denials without lifting cookie denials. With `crossSubdomain`, a vendor-only visitor keeps the local subject ID until a later vendor save updates the shared cookie. |

### Clearing records and clear epochs

`clearRecords()` drops queued save retries, deletes stored records, and writes the clear timestamp to `inth-epoch`, or `<storageKey>-epoch`, in both `localStorage` and a cookie. Later records embed that epoch as `&e=<time>` in the cookie and `epoch` in `localStorage`.

- Decisions confirmed before the epoch are void across tabs, hydration, and `readStoredRecordsFromCookieHeader`. A same-millisecond decision counts only if written by a tab that already saw the clear.
- Each clear advances the epoch by at least 1 ms even if the device clock moved backward. Epochs cap at 1 hour ahead of the clock; epochs further ahead read as `0` so corrupt values never grant permission.
- Pre-clear records read as epoch `0`. If cookie writes fail during `clearRecords()` or use a different `domain`, the browser applies the clear from `localStorage` while SSR sees the old cookie until the next cookie write succeeds.
- Deploy the current SDK across every page before enabling clears. Older builds reject epoch-tagged records and treat visitors as undecided.

## Keep open tabs in step

Same-origin tabs share the consent cookie and `localStorage`. A rejection or clear in one tab updates `effectivePermissions`, notifies subscribers once, and fires `onPermissionsChanged` in every open tab without reloading.

| Event | Reconciliation action |
| --- | --- |
| `storage` | Reconciles stored records into memory on same-origin `localStorage` edits. |
| `visibilitychange` | Reconciles stored records when the tab becomes visible. |
| `focus` | Reconciles stored records when the window regains focus. |
| `online` | No storage read. Retries failed init and queued saves only. |

Rapid events coalesce into one reconciliation task. Cross-subdomain tabs sharing a cookie and browsers with `localStorage` blocked receive no `storage` event, so they sync on `focus`, `visibilitychange`, or a manual reconcile call. Inth does not poll cookies or use `BroadcastChannel`.

### Merge and ordering rules

- **Categories.** Merge per category by newer `confirmedAt`. Same-millisecond ties keep the first stored decision.
- **Notice and vendor records.** Replace memory when the stored record is at least as new.
- **Subject ID.** Considered only when its carrying record changes. Replaces a local startup ID and emits `subject:resolved` with `previousSubjectId`. A server-resolved ID changes only on a strictly newer stored choice; `identify()` is never replaced.
- **Removals.** Records deleted from storage since this tab last saw them are cleared. Records never seen in storage, like an `identify()` merge, stay. Unreadable storage changes nothing.
- **Pending writes.** Tabs flush queued writes before reading so reconciliation never undoes the latest click. Simultaneous writes from two tabs re-merge on the next reconciliation.
- **Superseded saves.** When another tab updates while a local save is pending, unsent saves drop and responses to already-sent requests are ignored.

### Manual reconciliation and disabling sync

Call reconcile directly after a `Set-Cookie` update or cross-subdomain change:

```ts
// Runtime handle; returns true if any record changed
runtime.reconcileStorage();

// Persistence module handle
persistence.reconcile();
```

Use `persistence: { sync: false }` to disable automatic listeners while keeping manual calls working, or `persistence: false` to disable storage entirely. `dispose()` removes listeners and cancels scheduled reconciliations.

## Categories under an IAB policy

Under an IAB TCF policy, visitors choose TCF purposes and Inth derives each category from purposes that listed vendors declare on a consent legal basis:

| Category | TCF purposes |
| --- | --- |
| `marketing` | 2, 3, 4 |
| `measurement` | 7, 8, 9 |
| `experience` | 5, 6 |
| `functionality` | 10, 11 |

`necessary` is always granted. Purpose 1, device storage, maps to no category.

### Accept All and uncovered categories

TCF Policies prohibit signaling consent for purposes not shown to the visitor, so Accept All grants only purposes declared by listed or `customVendors`. Any category with no listed consent purposes stays denied after Accept All. For example, if vendors declare only purposes 1 to 4 and 7, `experience` and `functionality` stay denied.

If your scripts need an uncovered category, declare a custom vendor with those purposes via `customVendors`, or gate the script on a covered category or `necessary`.

### Gating IAB targets

Any script, iframe, or network rule naming `vendorId` or IAB purposes runs only while a confirmed TC string grants its `iabPurposes`, `iabLegIntPurposes`, and `iabSpecialFeatures`, and every named category is free of restrictions like GPC or strict scope.

Exception: a refused category does not block an IAB target processing solely on legitimate interest after publisher restrictions. Objection toggles control legitimate interest, while `effectivePermissions` stays `false` for non-LI targets.

### Multi-tab TC string sync

- `@inth/sdk/iab` adopts newer stored TC strings from `euconsent-v2` and `inth-iab-authority-v1` across same-origin tabs while keeping unsaved local drafts.
- Conflicting, stale, or removed TC strings withdraw before `__tcfapi` publishes. Partial IAB selections keep their TC string.
- On same-millisecond ties, the stricter TC string wins; if each grants something the other denies, both tabs withdraw and delete the stored receipt until the next save.
- TC strings belong to one origin. After a save on a sibling subdomain sharing the consent cookie, this origin reports no consent through `__tcfapi` until it saves again.

## Server hydration

- Forward server helper records, policy metadata, and evaluation timestamps intact. Copying an opt-out permission into a receipt invents a grant and loses confirmation time.
- With default `skipHydration` on SSR seeds, the server cookie stays authoritative on mount and only newer or same-millisecond `localStorage` denials apply on top. Setting `persistence: { skipHydration: false }` reads storage over the seed and stops server HTML from starting gated scripts early.
- Valid v2 records work without a startup rewrite; the visitor's next action writes v3. See [keeping visitors' existing choices](/docs/migrate-from-c15t#keep-visitors-existing-choices).
