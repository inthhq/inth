Inth injects only the CSS each rendered component needs, without a render-blocking stylesheet in `<head>`. Override rules with plain CSS, import `styles.css` yourself, or remove stock classes with `noStyle`.

## How each framework delivers styles

| Framework | How styles arrive |
| --- | --- |
| Next.js, TanStack Start, React | Each stock component renders `<style>` elements for its own rules. |
| Nuxt, Vue | Each Vue component imports its own stylesheet. |
| Astro | `<ConsentScript />` inlines banner rules and links dialog CSS on open. On Tailwind CSS 3, the integration adds `@inth/astro/styles.css` to every page. |
| Svelte | Each stock component inserts `<style data-inth-styles>` into `<head>` once per page. |
| SvelteKit | `inthHandle` from `@inth/svelte/kit` writes server-rendered banner rules into `<head>`; other surfaces insert theirs in the browser. |
| HTML, JavaScript | `inth.js` and `init()` bundle the stylesheet inside the UI shadow root. |

Inlining removes a render-blocking stylesheet round trip before first paint. Enable HTTP compression on your host to minimize HTML size, or switch to a cached stylesheet with `styles: false` if warm visits matter more. In SvelteKit, mount `inthHandle` in `src/hooks.server.ts` so server-rendered banners stay styled before hydration.

### Per-surface sheets and deferred dialog CSS

Inth splits rules so initial HTML carries only visible surfaces:

| Component | Sheets loaded |
| --- | --- |
| `ConsentBanner` in a Card | `inth-tokens`, `inth-button`, `inth-surface`, `inth-card` |
| `ConsentBanner` in a Banner | `inth-tokens`, `inth-button`, `inth-surface`, `inth-banner` |
| `ConsentBanner` in a Drawer | `inth-tokens`, `inth-button`, `inth-surface`, `inth-drawer` |
| Options Customize opens | `inth-expand`, `inth-dialog`, when the visitor opens them |
| `ConsentDialog` | `inth-tokens`, `inth-button`, `inth-expand`, `inth-dialog` |
| `ConsentDialogTrigger` | `inth-tokens`, `inth-trigger` |
| `ConsentGate` placeholder | `inth-tokens`, `inth-button`, `inth-consent-gate` |
| `ConsentWidget`, opt-in and opt-out confirmations | `inth-tokens`, `inth-button`, `inth-parts`, `inth-widget`, and in Svelte `inth-primitives` |

A page renders only the container it shows, so a Card page carries no Banner or Drawer rules. A page that cannot know its container before the policy resolves inlines `inth-first-paint`, which holds every container.

Dialog CSS stays out of first paint:

- **React, Next.js, TanStack Start, Svelte, SvelteKit.** `inth-expand` and `inth-dialog` load lazily with the dialog chunk. React 19 hoists `<style data-precedence="inth">` into `<head>`. React 18, and React 19 with `nonce`, render styles next to the component to keep the nonce.
- **Nuxt and Vue.** The dialog component imports its stylesheet when the dialog chunk loads.
- **Astro.** Inth adds the dialog's rules when a visitor hovers, focuses, or activates a trigger, and waits for them before opening. No island links a stylesheet for the preferences dialog. The IAB dialog links its rules when it opens, and Inth keeps them across `ClientRouter` navigation.
- **IAB TCF.** `IABConsentBanner` and `IABConsentDialog` inject their own IAB rules automatically. Streamed React IAB banners stay hidden until card markup finishes parsing to prevent layout shift.

## Order the cascade layer against your CSS

Inth puts component rules in `@layer components`, while tokens, CSS variables, and keyframes stay unlayered. Every injected `<style>` and published stylesheet starts with Tailwind CSS 4's layer order:

{/* example: fragment */}

```css
@layer properties, theme, base, components, utilities;
```

Layers rank by first declaration, so Inth sits above Tailwind's `base` preflight and below `utilities` regardless of load order.

- Any unlayered rule in your CSS beats Inth rules without `!important`.
- A rule in your own layer beats Inth only if declared after `components`.
- Tokens are unlayered. Override them through [theme tokens](/docs/customization/tokens).

Declare any custom `@layer` order before Inth loads. To put Inth in a named layer, set `styles: false` and import `@import '@inth/react/styles.css' layer(inth)`, which nests rules under `inth.components`.

## Import the stylesheet yourself

Set `styles: false` and import `styles.css` when using Tailwind CSS 3, a named cascade layer, or an HTTP-cached external stylesheet.

| Framework | Option | Stylesheets |
| --- | --- | --- |
| Next.js | `options.styles: false` in `inth.config.ts` or `InthProvider` | `@inth/nextjs/styles.css`, `@inth/nextjs/iab/styles.css` |
| TanStack Start | `options.styles: false` on `InthProvider` | `@inth/tanstack-start/styles.css`, `@inth/tanstack-start/iab/styles.css` |
| React | `options.styles: false` on `InthProvider` | `@inth/react/styles.css`, `@inth/react/iab/styles.css` |
| Svelte, SvelteKit | `styles={false}` on `InthProvider` | `@inth/svelte/styles.css`, `@inth/svelte/iab/styles.css` |
| Astro | `styles: false` in `inth()` options | See [Load Astro's stylesheets yourself](#load-astros-stylesheets-yourself) |

{/* example: fragment */}

```ts title="inth.config.ts"
import { defineConsentConfig } from '@inth/nextjs';

export default defineConsentConfig({ options: { styles: false } });
```

`styles: false` turns off only default stylesheets; theme tokens and slot classes still apply. In manual mode, `styles.css` includes the dialog rules, and IAB TCF also needs `iab/styles.css`. Remove `styles.css` imports if automatic styling is on, or styles ship twice and block first paint. For Tailwind CSS 3, see [Set up Tailwind CSS 3](/docs/customization/tailwind#set-up-tailwind-css-3).

## Load Astro's stylesheets yourself

Set `styles: false` in `inth()` and import Astro's stylesheets after your layer order statement:

{/* example: fragment */}

```css title="src/styles/global.css"
@import '@inth/astro/styles.css';
/* Required with default ui: 'svelte'. */
@import '@inth/astro/primitives.css';
/* Required when iab is enabled. */
@import '@inth/astro/iab/styles.css';
```

With `styles: false`, Inth inlines no banner CSS and links no dialog CSS on open. Keep Inth's rules loaded when restyling so the banner's `hidden` attribute still overrides its `display` rule. Remove any `@inth/astro/dialog.css` import, as that file is empty.

## Style the script tag shadow root

The HTML script tag and `init()` from `@inth/sdk` render inside a shadow root. Configure options other than `data-shadow` via `inth.push(['config', { ui: { ... } }])`.

| Option | Behavior |
| --- | --- |
| `ui.theme` | Writes theme tokens after the stylesheet inside the shadow root. |
| `ui.css` | Appends raw CSS inside the shadow root. |
| `ui.stylesheetUrls` | Links external CSS inside the shadow root with the client `nonce`. Also link on the page for `@property` rules. |
| `::part()` | Targets parts from page CSS, such as `[data-inth-ui]::part(consentBannerCard)`. |
| `ui.shadow: false` or `data-shadow="false"` | Renders into the light DOM so page CSS applies alongside Inth's stylesheet. |
| `ui.styles: false` | Drops the injected stylesheet. With `shadow: false`, import `@inth/sdk/styles.css` or link `dist/inth.css`. |

## Run without default styles

`noStyle` removes stock classes from markup, and in the script tag drops the bundled stylesheet. Your slot classes, `data-testid`, and `data-*` attributes stay, and you own all layout, focus, and responsive CSS. See [Remove default classes with noStyle](/docs/customization/slots#remove-default-classes-with-nostyle).

## Keep fixed elements still during scroll lock

Blocking prompts lock page scroll with `scrollbar-gutter: stable`. Where that does not hold, such as Chromium on macOS with `::-webkit-scrollbar`, Inth pads `<body>` and sets `--inth-scroll-lock-gap` on `<html>`. Apply it to `position: fixed` elements:

{/* example: fragment */}

```css
.site-header {
  position: fixed;
  inset-inline: 0;
  top: 0;
  padding-right: var(--inth-scroll-lock-gap, 0px);
}
```

## Check the result

1. Clear site data and reload with DevTools Network open. Confirm no Inth stylesheet request blocks first paint and `<head>` holds Inth `<style>` tags.
2. Open the preference dialog and confirm it renders styled on its first frame.
3. Inspect a banner part in DevTools Styles. Default rules appear under `@layer components`, and unlayered rules win.
4. With `styles: false`, confirm your imported `styles.css` loads once with no injected `<style>` tags.
