Use Inth alongside Tailwind CSS 4 with zero extra CSS config, or add the PostCSS plugin for Tailwind CSS 3 so preflight does not strip banner styles.

| Version | Extra Inth setup | Utility override syntax |
| --- | --- | --- |
| Tailwind CSS 4 | None. Inth `@layer components` sits above `base` and below `utilities`. | Plain utilities such as `p-2` win without `!important`. |
| Tailwind CSS 3 | Set `styles: false`, add `<package>/postcss-tailwind3` before `tailwindcss`, and import `styles.css` first. | Prefix overrides with `!`, such as `!p-2`. |

## Set up Tailwind CSS 4

Install Tailwind 4 for your build tool. Do not import an Inth stylesheet alongside Tailwind 4; stock components inject layered rules automatically, and a manual import blocks first paint.

## Set up Tailwind CSS 3

Tailwind 3 treats `@layer components` as a directive and its unlayered preflight overrides Inth's layered `<style>` tags. Every package exports `<package>/postcss-tailwind3` to unwrap Inth's layers before Tailwind 3 runs.

1. Set `styles: false` in provider options for Next.js, TanStack Start, React, Svelte, and SvelteKit. Skip in Vue, Nuxt, and Astro.
2. Add `<package>/postcss-tailwind3` before `tailwindcss` in your PostCSS config using object syntax to preserve order.
3. Import `<package>/styles.css` above `@tailwind` directives. Skip in Vue, Nuxt, and Astro; Astro detects Tailwind 3 and adds `@inth/astro/styles.css` automatically. Placing `@import` below `@tailwind` breaks Turbopack and warns in Vite.
4. Set `darkMode: 'class'` so `dark:` matches Inth's `dark` class.

Prefix utility overrides on Inth parts with `!`, such as `!bg-red-500` and `hover:!bg-red-500`. For Create React App or toolchains that cannot add PostCSS plugins, use CRACO, switch to Vite, or import the pre-unlayered `styles.tw3.css` and `iab/styles.tw3.css` from `@inth/react`, `@inth/nextjs`, or `@inth/tanstack-start`.

## Use the dark variant

Configure `@custom-variant dark (&:where(.dark, .dark *));` in Tailwind 4 or `darkMode: 'class'` in Tailwind 3. Inth reads the same `.dark` class on `<html>` so one toggle switches both. Astro and the script tag follow system color scheme by default. See [Dark mode](/docs/customization/dark-mode).

## Check the result

1. Build and open the site in a private window. Verify the banner card keeps its background, border, and button padding.
2. Inspect a customized part in DevTools Styles. Your utility applies and Inth's rule is crossed out.
3. Add `dark` to `<html>` and confirm both `dark:` utilities and Inth dark tokens apply.
4. Open the preference dialog and confirm its styles load.
