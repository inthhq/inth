Customize Inth's consent banner and preference dialog from a single prop up to full custom markup while keeping policy enforcement intact.

## Pick the smallest customization step

Each step preserves what the step below it provides. Stop at the first one that fits:

1. **Props and presentation.** Set banner shape, position, button order, or blocking. Inth keeps its markup, CSS, and policy behavior.
2. **Theme tokens.** Change colors, fonts, radius, spacing, shadows, and motion across all surfaces. Dark mode uses a second token set.
3. **Parts and classes.** Add classes or inline styles to one part, such as the banner card. Tailwind CSS, CSS Modules, and CSS-in-JS fit here.
4. **Compose.** Arrange Inth's parts in your own layout while Inth renders required policy actions.
5. **Headless.** Render your own markup from Inth's state and actions. You own layout, focus handling, and labels.

Most brand work only needs theme tokens and a few part classes. See [banner designs](/docs/customization/recipes) for five tested banners across these steps.

Part keys vary by adapter. React uses `components.banner.card`, Vue adds `class`, and Svelte, Angular, Astro, and HTML use `theme.slots.consentBannerCard`. Check your framework's customize guide before porting config.

## Keep behavior and appearance separate

Presentation controls shape, position, and blocking. Your Inth policy controls which actions and rights a visitor receives. Changing colors or button order never alters saved consent or policy scope.

A choice wall always blocks. A notice never blocks, so `variant: 'wall'` on a notice falls back to a floating card. The preference dialog stays centered regardless of banner position. If a composed layout omits a policy-required action, Inth inserts it.
