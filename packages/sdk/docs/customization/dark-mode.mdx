Switch Inth's banner and preference dialog to dark mode with `colorScheme`, custom `theme.dark` tokens, or your site's `.dark` class, without a light flash on SSR.

## Configure `colorScheme`

Inth switches `--inth-*` color tokens to dark values when `<html>` has `.dark` or `.inth-dark`. `colorScheme` controls whether Inth manages `inth-dark` itself:

| `colorScheme` | Behavior |
| --- | --- |
| `'light'` | Removes `inth-dark` once |
| `'dark'` | Adds `inth-dark` once |
| `'system'` | Follows `prefers-color-scheme` and updates live |
| Unset | Mirrors `.dark` on `<html>` into `inth-dark` and tracks changes |
| `null` or `'none'` | Leaves `inth-dark` untouched so your app controls it |

`'light'` only removes `inth-dark`. If your site still sets `.dark` on `<html>`, dark tokens stay active. Astro and the HTML script tag use `'none'` in place of `null`.

| Framework | Where to set `colorScheme` | Default |
| --- | --- | --- |
| Next.js, TanStack Start | `options.colorScheme` on `InthProvider` and `colorScheme` on `ConsentTheme` | Unset |
| React | `colorScheme` in `InthProvider` options and on `ConsentTheme` | Unset |
| Nuxt | `inth.colorScheme` in `nuxt.config.ts` or `app/app.config.ts` | Unset |
| Vue | `colorScheme` in `inth` options | Unset |
| Astro | `colorScheme` in `inth()` integration options | `'system'` |
| Svelte, SvelteKit | `colorScheme` on `InthProvider` | Unset |
| Angular | `colorScheme` in `provideInth()` | Unset |
| HTML | `data-color-scheme` attribute on the script tag | `system` |
| JavaScript | `ui.colorScheme` in `init()` | `'system'` |

In Nuxt, set `colorScheme: null` under `inth` in `nuxt.config.ts` or `app/app.config.ts`. Nuxt drops `null` in inline `modules: [['@inth/nuxt', { colorScheme: null }]]` options, which behaves like unset.

## Follow Tailwind or `next-themes` `.dark` classes

In React, Next.js, TanStack Start, Vue, Nuxt, Svelte, SvelteKit, and Angular, leave `colorScheme` unset and toggle `.dark` on `<html>` with Tailwind CSS or `next-themes`. Inth mirrors `.dark` into `inth-dark` automatically. Pass `colorScheme: null` if your app toggles `inth-dark` directly.

In Astro, set `colorScheme: 'none'` and toggle `inth-dark` alongside your class. With `ClientRouter`, reapply it on `astro:after-swap` because navigation replaces `<html>` attributes.

With the script tag, set `data-color-scheme="none"`. With `init()`, pass `ui: { colorScheme: null }`. Because the UI renders inside a shadow root, Inth mirrors `.dark` and `.inth-dark` from `<html>` onto the shadow host.

## Customize dark colors with `theme.dark`

Colors set in `colors` stay active in dark mode unless `theme.dark` overrides them. Define both sets together:

{/* example: fragment */}

```ts title="consent-theme.ts"
export const theme = {
	colors: { primary: '#2f6f4e', primaryHover: '#24563c', surface: '#fbf8f3' },
	dark: { primary: '#7fd1a8', primaryHover: '#9fdcbd', surface: '#1b1f1d' },
};
```

Pass `theme` to `<ConsentTheme theme={theme} />` or `generateThemeCSS(theme, colorScheme)` from `@inth/react/utils` in React frameworks, `theme` in Vue, Nuxt, and Astro options, `generateThemeCSS(theme, colorScheme)` from `@inth/svelte`, `generateThemeCSS(theme)` from `@inth/angular`, or `ui.theme` in HTML and JavaScript.

This Nuxt snippet follows the OS scheme and overrides only the dark primary color:

To override dark colors in plain CSS instead, target both classes:

```css
:root.dark,
:root.inth-dark {
  --inth-primary: #7fd1a8;
  --inth-surface: #1b1f1d;
}
```

Generated themes from `ConsentTheme` or `generateThemeCSS()` write dark values onto `:root:root.dark` and `:root:root.inth-dark`, which outrank single `:root` rules. Put dark values in your theme object or repeat `:root:root`. See [theme tokens](/docs/customization/tokens) for every color token.

## Prevent a light-mode flash on SSR

Match your framework's server rendering path so dark tokens arrive on the first frame:

| Framework | Flash-free dark first paint |
| --- | --- |
| Next.js, TanStack Start | Render `<ConsentTheme theme={theme} colorScheme="system" />` on the server matching `options.colorScheme`. `'dark'` emits dark defaults and `'system'` emits a `prefers-color-scheme` query before hydration. With `colorScheme` unset, include `.dark` on `<html>` in server HTML. |
| React | Render `<ConsentTheme colorScheme="system" />` next to `InthProvider`, or on the server in SSR apps, matching the provider's `colorScheme`. |
| Nuxt | For `'dark'` and `'system'`, `@inth/nuxt` injects a `<head>` script with your `nonce` to set `inth-dark` before first paint. With `colorScheme` unset, include `.dark` in server HTML. |
| Vue | `app.use(inth, ...)` applies `colorScheme` and writes tokens before first render. |
| Astro | Keep `ConsentScript` in `<head>`. It sets `inth-dark` before first paint and after `ClientRouter` swaps. |
| Svelte, SvelteKit | Call `generateThemeCSS(theme, 'system')` in your server load and render it in `<svelte:head>`. With `colorScheme` unset, include `.dark` in server HTML. |
| Angular | Include `.dark` or `.inth-dark` on `<html>` in SSR HTML, or embed `generateThemeCSS(theme)` on the server. |
| HTML, JavaScript | Inth applies `colorScheme` before mounting any surface. |

## Verify dark mode

1. Open the page in a private window with dark OS appearance, or add `.dark` to `<html>`.
2. Reload with DevTools Network throttled and confirm the banner paints dark on frame one.
3. Open the preference dialog and confirm it shares the same dark tokens.
4. Toggle your theme switch or OS appearance live and verify both surfaces update with readable button contrast.
