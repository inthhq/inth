Find the part key, `data-testid`, and `data-*` state attributes for every stock Inth UI element.

## Which part API your framework uses

Frameworks use nested `components` keys or flat `theme.slots` keys. Keys do not interchange across vocabularies.

| Framework | Part API | Class key |
| --- | --- | --- |
| Next.js, TanStack Start | `options.components` in `inth.config.ts` or `InthProvider` | `className` |
| React | `components` on `InthProvider` | `className` |
| Nuxt, Vue | `components` in `inth` options (`nuxt.config.ts`, `app/app.config.ts`, or `app.use(inth, ...)`) | `class` |
| Astro | `theme.slots` in `inth()` options | String or `className` |
| Svelte, SvelteKit | `theme.slots` on `InthProvider` | String or `className` |
| HTML, JavaScript | `ui.theme.slots` | String or `className` |

React and Vue also map `theme.slots` onto `components`, combining classes and merging inline styles with `components` winning per property. Vue and Nuxt bind objects via `v-bind`, so use `class` instead of `className`. Svelte stock components and Astro's `ConsentBanner`, `IABConsentBanner`, and `ConsentDialogTrigger` also accept a root `class` prop.

{/* example: fragment */}

```tsx
components: { banner: { card: { className: 'brand-card' }, title: { style: { fontWeight: 600 } } } },
```

{/* example: fragment */}

```ts
theme: { slots: { consentBannerCard: 'brand-card', consentBannerTitle: { className: 'brand-title' } } },
```

See [Class names and CSS-in-JS](/docs/customization/class-names) and [Tailwind CSS](/docs/customization/tailwind).

## Style shadow root parts with ::part()

In the script tag and `init()`, every `theme.slots` key is exposed via `part`:

{/* example: fragment */}

```css
[data-inth-ui]::part(consentBannerCard) { border: 3px solid #6943a3; }
```

## Select on state attributes

| Element | Attributes |
| --- | --- |
| Banner root | `data-prompt`, `data-model`, `data-variant`, `data-position`, `data-blocking` |
| Action buttons | `data-action` with `accept`, `reject`, `customize`, `dismiss`, or `save`; `data-variant`; `data-mode` |
| Footer, groups | `data-direction`, `data-fill`, `data-split` |
| Right links | `data-action="right"`, `data-right` |
| Dialog | `data-state` with `open` or `closed`, see [motion](/docs/customization/motion#animate-your-own-rules-on-dialog-state) |
| Switch | `data-state`, `data-disabled` |

The script tag banner root exposes only `data-variant`, `data-position`, and `data-blocking`, and its right links use `data-action="customize"`. Notice prompts render `data-action="dismiss"`.

The banner card does not inherit root attributes. In Tailwind, add `group` to `banner.root` and style children with `group-data-[variant=bar]:rounded-none`.

## Do not target generated class names

Stock CSS Module classes end in a build hash like `inth-ui-card-lgjVq` that changes across builds and disappears under `noStyle`. Target part APIs, `data-testid`, `data-*`, or `::part()`.

## Remove default classes with noStyle

`noStyle` strips stock classes while keeping markup, behavior, part classes, `data-testid`, and `data-*` attributes. You own all layout, spacing, focus, and responsive CSS.

| Framework | Where to set `noStyle` |
| --- | --- |
| Next.js, TanStack Start, React | Provider options or component `noStyle` prop including IAB |
| Svelte, SvelteKit | Provider options or component `noStyle` prop |
| Astro | `noStyle` prop on `ConsentBanner` and `IABConsentBanner` |
| HTML, JavaScript | `ui.noStyle`, which also drops the bundled stylesheet |
| Vue, Nuxt | `noStyle` prop on `ConsentWidget`, `PreferenceItemRoot`, `PreferenceItemContent` |

Per-slot `{ noStyle: true }` in `theme.slots` works in Svelte, Astro's banner, and the script tag; React and Vue ignore it. Use compound components or the headless API to change markup.
