## Which part API your framework uses

Frameworks use nested `components` keys or flat `theme.slots` keys. Keys do not interchange across vocabularies.

| Framework | Part API | Class key |
| --- | --- | --- |
| Next.js, TanStack Start | `options.components` in `inth.config.ts` or `InthProvider` | `className` |
| React | `components` on `InthProvider` | `className` |
| Nuxt, Vue | `components` in `inth` options (`nuxt.config.ts`, `app/app.config.ts`, or `app.use(inth, ...)`) | `class` |
| Astro | `theme.slots` in `inth()` options | String or `className` |
| Svelte, SvelteKit | `theme.slots` on `InthProvider` | String or `className` |
| HTML, JavaScript | `ui.theme.slots` | String or `className` |

React and Vue also map `theme.slots` onto `components`, combining classes and merging inline styles with `components` winning per property. Vue and Nuxt bind objects via `v-bind`, so use `class` instead of `className`. Svelte stock components other than `ConsentDialog`, and Astro's `ConsentBanner`, `IABConsentBanner`, and `ConsentDialogTrigger`, also accept a root `class` prop.

{/* example: fragment */}

```tsx
components: { banner: { card: { className: 'brand-card' }, title: { style: { fontWeight: 600 } } } },
```

{/* example: fragment */}

```ts
theme: { slots: { consentBannerCard: 'brand-card', consentBannerTitle: { className: 'brand-title' } } },
```

See [Class names and CSS-in-JS](/docs/customization/class-names) and [Tailwind CSS](/docs/customization/tailwind).

## Banner parts

The banner renders in a Card, a Banner or a Drawer, as `container` sets. Every container uses the same parts.

| Visible card | `banner.card` | `consentBannerCard` | `consent-banner-card` |

The backdrop is the dialog's root, so `dialog.root`, `dialog.container` and `dialog.overlay` all style the same element. In the same way, every framework and the script tag merge `consentDialogOverlay` onto that root with `consentDialog`. The Preferences row is an accordion on desktop and opens a sheet on phones. The dialog has no branding tag, so `tag.dialog` and `consentDialogTag` style nothing.

## Style shadow root parts with ::part()

In the script tag and `init()`, every `theme.slots` key is exposed via `part`:

{/* example: fragment */}

```css
[data-inth-ui]::part(consentBannerCard) { border: 3px solid #6943a3; }
```

## Select on state attributes

| Element | Attributes |
| --- | --- |
| Banner root | `data-variant` with `choice`, `us-consent` or `notice`; `data-placement`, such as `card-start`, `banner-bottom` or `drawer-end`; `data-flow` with `expand-in-place` or `all-in-one`; `data-edge-style` with `inset` or `flush`; `data-blocking`; `data-expanded`; `data-state` with `open` or `closed`; `data-animation="off"` |
| Action buttons | `data-action` with `accept`, `reject`, `customize`, `dismiss`, or `save`; `data-variant`; `data-mode` |
| Rights row options | `data-right-option` |
| Dialog root | `data-regime` with `eu` or `us`; `data-layout` with `desktop` or `phone`; `data-edge-style`; `data-animation="off"` |
| Dialog card | `data-state` with `open` or `closed`, see [motion](/docs/customization/motion#animate-your-own-rules-on-dialog-state); `data-nested` on a phone sheet |
| Switch | `data-state`, `data-disabled` |

`data-placement` names the container and where it sits, so one selector covers every Card or every Drawer: `[data-placement^='drawer-']`. Notice banners render `data-action="dismiss"`.

The banner card does not inherit root attributes. In Tailwind, add `group` to `banner.root` and style children with `group-data-[placement=banner-bottom]:rounded-none`.

## Do not target generated class names

Stock CSS Module classes end in a build hash like `inth-ui-card-lgjVq` that changes across builds and disappears under `noStyle`. Target part APIs, `data-testid`, `data-*`, or `::part()`.

## Remove default classes with noStyle

`noStyle` strips stock classes while keeping markup, behavior, part classes, `data-testid`, and `data-*` attributes. You own all layout, spacing, focus, and responsive CSS.

| Framework | Where to set `noStyle` |
| --- | --- |
| Next.js, TanStack Start, React | Provider options or component `noStyle` prop including IAB |
| Svelte, SvelteKit | Provider options or component `noStyle` prop |
| Astro | `noStyle` prop on `ConsentBanner` and `IABConsentBanner` |
| HTML, JavaScript | `ui.noStyle`, which also drops the bundled stylesheet |
| Vue, Nuxt | `noStyle` prop on `ConsentWidget`, `PreferenceItemRoot`, `PreferenceItemContent` |

Per-slot `{ noStyle: true }` in `theme.slots` works in every framework and drops that part's stock classes. To change markup, build your own UI on the headless API.
