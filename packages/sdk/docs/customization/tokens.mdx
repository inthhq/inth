Style every Inth banner, preference dialog, and trigger from one place using `defineTheme()`, `ConsentTheme`, or `--inth-*` CSS variables.

## Define a theme with `defineTheme()`

Every `@inth/*` web framework package exports `defineTheme()`. Pair primary colors with hover and foreground colors so buttons stay readable in every state:

{/* example: fragment */}

```ts
import { defineTheme } from '@inth/react';

export const theme = defineTheme({
	colors: {
		primary: '#2f6f4e',
		primaryHover: '#24563c',
		textOnPrimary: '#ffffff',
	},
	radius: { lg: '4px', md: '4px' },
	consentActions: {
		primary: { variant: 'primary', mode: 'filled' },
		dismiss: { variant: 'neutral', mode: 'stroke' },
	},
});
```

| Framework | Tokens | `consentActions` |
| --- | --- | --- |
| Next.js, TanStack Start, React | `<ConsentTheme theme={theme} />`, server-rendered when available | Provider `theme` option |
| Nuxt, Vue | `theme` or `tokens` in module or plugin options | Not available |
| Astro | `theme` in `inth()` integration options | Same `theme` object |
| Svelte, SvelteKit | `generateThemeCSS(theme)` in `<style>`, or `--inth-*` CSS | `theme` on provider or root |
| Angular | Global `--inth-*` CSS or `generateThemeCSS(theme)` | `theme` in `provideInth()` |
| HTML, JavaScript | `ui.theme` | Not available |

React, Svelte, and Angular providers read only `consentActions` and slot styles from `theme`. They do not emit token CSS, and warn in development if `theme` sets tokens without a `<style id="inth-theme">` element.

`consentActions` styles buttons by action role. A per-action entry overrides `primary`, which overrides `default`.

## Override generated tokens with CSS

`ConsentTheme`, `generateThemeCSS()`, Astro's `theme`, and `ui.theme` emit variables on `:root:root` and `.inth-theme-root.inth-theme-root`, outranking Inth defaults regardless of load order. Plain `:root` rules lose to generated themes, so put overrides in your theme object or match `:root:root`:

```css
:root:root {
  --inth-primary: #2f6f4e;
}
```

Scoped rules like `[data-prompt] { --inth-primary: #2f6f4e; }` set the variable on the banner element directly and override `:root:root` inside it.

## Token reference

Theme objects use nested keys like `radius.lg`, Vue and Nuxt `tokens` omit `--` as `'inth-radius-lg'`, and stylesheets use `--inth-radius-lg`. See [dark mode](/docs/customization/dark-mode), [motion](/docs/customization/motion), and [stylesheets](/docs/customization/stylesheets) for dark overrides, timing, and load order.

<include src="../shared/reference/theme-tokens.mdx" />

`radius.lg` rounds cards, dialogs, `ConsentGate` placeholders, and the floating trigger. `radius.md` rounds buttons, accordions, tabs, and vendor lists. `radius.sm` rounds inner controls. Set both `radius.lg` and `radius.md` for matching card and button corners. Style fixed properties like button padding through [component parts](/docs/customization/slots).

## Scope tokens and adjust sizing

Target specific prompts with rendered `data-*` attributes instead of internal class names:

```css
[data-prompt][data-model='opt-in'] {
  --inth-primary: #2f6f4e;
  --inth-primary-hover: #24563c;
  --inth-text-on-primary: #ffffff;
}
```

The script tag omits `data-prompt` and `data-model`. Because the preference dialog renders in a portal, tokens scoped to `[data-prompt]` do not reach it. Test both surfaces.

| Size variable | Default | Target |
| --- | --- | --- |
| `--consent-banner-max-width` | `440px` | Floating card |
| `--consent-banner-widget-max-width` | `20rem` | Widget |
| `--consent-banner-wall-max-width` | `30rem` | Choice wall |
| `--consent-banner-padding-mobile` | `var(--inth-space-md)` | Floating card and choice wall inset below 640px |
| `--consent-banner-padding` | `var(--inth-space-lg)` | Floating card and choice wall inset at 640px and up |
| `--consent-dialog-card-padding-mobile` | `var(--inth-space-md)` | Dialog inset and outer gap below 640px |
| `--consent-dialog-card-padding` | `var(--inth-space-lg)` | Dialog inset and outer gap at 640px and up |

Bar and widget variants ignore both `--consent-banner-padding*` variables. Banner footers wrap actions by card width, not viewport width. Under the default `compact` profile, cards narrower than `22rem` place Reject and Accept on one row with Customize full-width below.

## Control stacking order with z-index

Lower these variables when a navbar, drawer, or chat widget should sit above the banner:

| Variable | Default | Target |
| --- | --- | --- |
| `--consent-banner-z-index` | `999998` | Banner |
| `--consent-banner-overlay-z-index` | `999997` | Blocking banner backdrop |
| `--iab-consent-banner-z-index` | `999998` | IAB TCF banner |
| `--iab-consent-banner-overlay-z-index` | `999997` | IAB TCF backdrop |
| `--consent-dialog-z-index` | `999999` | Preference dialog |
| `--consent-dialog-overlay-z-index` | `999998` | Preference dialog backdrop |

```css
:root {
  --consent-banner-z-index: 40;
  --consent-banner-overlay-z-index: 39;
}
```

Keep each surface z-index above its overlay, and keep the dialog above the banner. Non-blocking banners only capture clicks on the card and branding tag, so clicks around them pass through to your page.

## Style the "Consent by" tag

Declare branding tag variables on `:root` so both the banner and the portaled dialog inherit them:

| Variable | Default | Target |
| --- | --- | --- |
| `--consent-branding-tag-background-color` | `var(--inth-primary)` | Tag background |
| `--consent-branding-tag-border-color` | `--inth-primary` mixed 14% toward black | Tag border |
| `--consent-branding-tag-text-color` | `var(--inth-text-on-primary, #fff)` | "Consent by" text and wordmark |
| `--consent-branding-tag-mark-color` | Tag text color | Inth logo mark |
| `--consent-branding-tag-shadow` | Inset highlight and 1px shadow | Tag shadow |
| `--consent-branding-tag-attached-edge-width` | `0px` | Border meeting the card |

Inth leaves these variables undeclared so defaults resolve on the tag and follow a scoped `--inth-primary`. Set `--consent-branding-tag-attached-edge-width: 1px` to draw a single border where the tag meets the card without doubling borders:

```css
:root {
  --consent-branding-tag-background-color: var(--inth-surface);
  --consent-branding-tag-border-color: var(--inth-border);
  --consent-branding-tag-text-color: var(--inth-text-muted);
  --consent-branding-tag-mark-color: var(--inth-primary);
  --consent-branding-tag-shadow: none;
}
```
