Pass consent from a Swift, Kotlin, or React Native app into your website inside a WebView so web Inth follows the app's choice without showing a second banner.

The app remains the consent authority. The web page gets a read-only copy, shows no banner or dialog, writes no cookie, and sends no consent records. A "Cookie settings" link on the page opens the app's native preferences screen.

## What crosses into the page

Only consent state crosses into the WebView; subject ID, external ID, location, and records stay in the app.

| Field | Value |
| --- | --- |
| `ready` | `true` once stored consent loads and a policy resolves |
| `permissions` | Effective permissions (optional categories stay `false` until `ready`) |
| `model` | `opt-in`, `opt-out`, `none`, or `iab` |
| `tcString` | Committed IAB TC String when running native IAB TCF, else `null` |
| `gppString` | IAB GPP string when GPP is on and a section applies, else `null` |
| `revision` | Snapshot revision number |

## Allowlist trusted origins

List the origins permitted to receive consent, such as `https://www.example.com`. Only the top frame of a listed origin receives consent; unlisted origins and iframes behave like a normal browser.

Each entry must be `https://host` or `https://host:port`. Plain `http://` is allowed only for `localhost`, `127.0.0.1`, and `[::1]`. Paths, wildcards, non-ASCII hosts (use punycode `xn--`), and empty lists throw an error.

## Configure the website

Pass `webViewConsentSource()` as `consentSource` in your web Inth options. Inside a configured WebView it returns the native source; in a normal browser or during SSR it returns `undefined` and Inth runs normally. Import it from your framework's `/engine` entry (`@inth/react/engine` or `@inth/sdk/engine`):

{/* example: fragment */}

```ts
import { webViewConsentSource } from '@inth/react/engine';

const options = {
	consentSource: webViewConsentSource(),
	// ...your existing options, such as projectUrl and mode
};
```

Pages that render a banner in server HTML will flash that banner until hydration because the server cannot detect a WebView. Resolve consent in the browser for pages opened in your app to avoid that flash.

For IAB TCF, the page does not mount `__tcfapi` from the app's TC String; read `webViewConsentSource()?.getState()?.tcString` directly if needed.

## Configure the native app

Attach the helper before loading the first URL and keep the handle alive with the WebView.

### Swift

`ConsentWebView` in `InthApple` adds a main-frame user script to `WKUserContentController` and pushes updates when consent changes:

```swift
import InthApple
import InthCore
import WebKit

final class SiteViewController: UIViewController {
    private let webView = WKWebView()
    private var consentSync: ConsentWebView?

    override func viewDidLoad() {
        super.viewDidLoad()
        view = webView
        guard let core = Inth.current else { return }
        do {
            consentSync = try ConsentWebView(
                webView: webView,
                core: core,
                allowedOrigins: ["https://www.example.com"]
            ) { [weak self] in
                self?.presentConsentPreferences()
            }
        } catch {
            assertionFailure("\(error)")
        }
        webView.load(URLRequest(url: URL(string: "https://www.example.com/")!))
    }
}
```

The initializer throws on invalid origins or if the `WKUserContentController` already serves a different core or allowlist (one controller equals one scope). The callback runs on the main actor; call `close()` to stop syncing while keeping the WebView open.

### Kotlin

`ConsentWebView` in `com.inth.android` uses `WebViewCompat.addDocumentStartJavaScript`:

```kotlin
import com.inth.android.ConsentWebView
import com.inth.core.Inth

class SiteActivity : AppCompatActivity() {
    private var consentSync: ConsentWebView? = null

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        val webView = WebView(this).apply { settings.javaScriptEnabled = true }
        setContentView(webView)
        val core = Inth.current ?: return
        consentSync = ConsentWebView.attach(webView, core, listOf("https://www.example.com")) {
            showConsentPreferences()
        }
        webView.loadUrl("https://www.example.com/")
    }

    override fun onDestroy() {
        consentSync?.close()
        super.onDestroy()
    }
}
```

`attach` throws `IllegalArgumentException` on invalid origins and returns `null` when `ConsentWebView.isSupported()` is `false`. Re-attaching replaces the previous helper.

### React Native

Call `useWebViewConsent()` under `InthProvider` and spread its props onto `WebView` from `react-native-webview`:

{/* example: fragment */}

```tsx
import { useWebViewConsent } from '@inth/react-native';
import { WebView } from 'react-native-webview';

export function Site({ onOpenPrivacy }: { onOpenPrivacy: () => void }) {
	const consent = useWebViewConsent({
		allowedOrigins: ['https://www.example.com'],
		onPreferencesRequested: onOpenPrivacy,
	});

	return <WebView {...consent} source={{ uri: 'https://www.example.com/' }} />;
}
```

If your `WebView` sets `onMessage`, forward events to `consent.onMessage(event)`. Rebuild the native app after updating `@inth/react-native`.

## Preferences and security

- **One-way flow.** Calls like `acceptAll()` are refused on the page. Opening preferences triggers `onPreferencesRequested` using a top-frame token so iframes cannot call it.
- **Revocation.** Updating consent in the app updates the open page; withdrawing an active category reloads the page unless `reloadOnConsentRevoked: false`.
- **Tamper resistance.** State is injected before page scripts run, cannot be redefined, and only accepts updates matching the WebView's random token. Closing the helper or removing an origin revokes optional categories on the page. See `packages/native-protocol/CONTRACT.md` for wire details.

## Verify the sync

1. Save a choice in the app, then open a listed origin in the WebView.
2. Confirm no banner shows. In Safari Web Inspector (iOS) or `chrome://inspect` (Android), run `window.__inthNativeConsent.getState()` and compare `permissions`.
3. Change consent in the app while the page stays open. Confirm `getState().revision` increments and allowed scripts start.
4. Open an unlisted origin. Confirm `window.__inthNativeConsent` is `undefined` and the site's own banner shows.
