Run A/B tests on consent banner layout, position, actions, and theme tokens while keeping policy rules and copy identical across every arm.

**Prerequisites**

- An Inth project whose policy prompts for at least one category. Under `scopeMode: 'permissive'`, declare categories via `consentCategories`, `scripts`, or `vendors`. Without declared categories, clicks record notice acknowledgements instead of choices and `onChoiceRecorded` never fires.

## Define the experiment

Your existing `presentation` option is the `control` arm (or the stock banner if omitted). Each key in `arms` lists only the overrides. Add `experiment` to your provider and pass the arm resolved by your feature flag:

<include src="../shared/examples/react/experiment-consent.mdx" />

`defineExperiment()` from your framework's `/engine` entry (`@inth/react/engine` or `@inth/sdk/engine`) returns its input and checks arm names in `arm` and `split`. Narrow flag strings with `ExperimentArmName`:

{/* example: fragment */}

```ts
import type { ExperimentArmName } from '@inth/react';

type BannerArm = ExperimentArmName<typeof bannerExperiment>;

const armFromFlag = (value: string | undefined): BannerArm | undefined =>
	value === 'control' || value === 'wall' ? value : undefined;
```

| Field | Purpose |
| --- | --- |
| `id` | Stable experiment ID recorded with every impression and choice |
| `arms` | Overrides merged over `presentation` (omit `control`) |
| `arm` | Arm from your flag (`control` or a key of `arms`). Omit for built-in assignment |
| `split` | Relative arm weights for built-in assignment (equal by default) |
| `acknowledgeDiagnostics` | Run an arm that trips a presentation diagnostic and record your review |

The same `experiment` option works in `@inth/nextjs`, `@inth/react`, `@inth/vue`, `@inth/svelte`, `@inth/astro`, `@inth/tanstack-start`, and `@inth/sdk`. Inth reads `experiment` once at mount; remount the provider (for example with a React `key`) to switch experiments. Assignment code loads in a separate chunk only on pages that configure `experiment`.

### Vary theme tokens

Include `theme` overrides next to an arm's presentation fields to merge one token group deep over your host `theme`:

```ts
experiment: {
	id: 'button-style',
	arms: {
		bold: {
			theme: { colors: { primary: '#0a0a0a' }, radius: { lg: '4px' } },
		},
	},
}
```

Render `<ConsentTheme theme={useResolvedTheme()} />` inside the React provider, or `<ConsentTheme theme={resolveExperimentTheme(theme, experiment, { arm })} />` in a Server Component. Other frameworks expose `useResolvedTheme(theme)` in Vue, `getConsentManager().theme` in Svelte, and `client.theme` in `@inth/sdk`.

### Acknowledge presentation diagnostics

Inth validates each arm against the visitor's policy. An arm that triggers a diagnostic (such as `equivalent-prominence-overridden`) is skipped and logged while the visitor sees the base banner. Set `acknowledgeDiagnostics: true` to run it anyway and record `acknowledgedDiagnostics: true` on choices. Catch rejected arms in CI with `validateExperiment()`:

{/* example: fragment */}

```ts
import { validateExperiment } from '@inth/react/engine';

test('banner-shape arms pass under the EU policy', () => {
	validateExperiment(bannerExperiment, euPolicy, { presentation });
});
```

## Assign visitors to an arm

### Use a feature flag provider

Pass the resolved arm as `arm`. Inth records `assignedBy: 'host'` and never reassigns the visitor. An invalid `arm` logs an error and runs no experiment without breaking the page.

On server-rendered pages in Next.js, TanStack Start, or SvelteKit, resolve the flag on the server and pass `experiment` to `resolveConsent()`. The server reports `{ id, arm }` with `/v1/consent/init` and renders the arm in server HTML:

<include src="../shared/examples/nextjs/experiment-layout.mdx" />

If you pass `resolveConsent()` to `InthProvider` without awaiting it (streaming layout), pass the same `experiment` to the client options because the client mounts before the streamed state arrives.

In Astro, set `middleware: false` in `inth()` and resolve the arm per request in `src/middleware.ts` (return `undefined` to exclude a request; prerendered routes cannot resolve per-request arms):

{/* example: fragment */}

```ts title="src/middleware.ts"
import { consentMiddleware } from '@inth/astro/middleware';

export const onRequest = consentMiddleware({
	experimentArm: async (context) => await bannerExperimentFlag(context),
});
```

For browser-side async flag SDKs such as PostHog, wait briefly (such as 1 second) before mounting the provider so the arm is ready at mount, then fall back so a blocked flag request never hides the banner.

### Let Inth assign the arm

Omit `arm` and optionally set `split` weights to let Inth pick the arm before `/v1/consent/init`:

```ts
experiment: {
	id: 'banner-shape',
	arms: { wall: { prompt: { variant: 'wall' } } },
	split: { control: 60, wall: 40 },
}
```

Inth records `assignedBy: 'inth'`, holds the banner until assignment completes, and persists `{ id, arm }` under `inth-experiment-v1` in localStorage (or a cookie fallback) once shown. Nothing is stored when no banner shows or when a flag assigns the arm.

- **SSR pages.** Built-in assignment runs after hydration, so it does not render in server HTML or attach to a server `/v1/consent/init`. Use a server-side flag on SSR pages. Built-in assignment is unavailable in Astro.
- **Early `/v1/consent/init` prefetch.** Pass `experiment` to `consentManifest({ initPrefetch })`, `consentPrefetchHead`, or `buildPrefetchScript` for built-in assignment. Omit it when a feature flag picks the arm so prefetch does not send a mismatched `/v1/consent/init`.

Change `id` for a new test instead of editing arms on a running experiment.

## Send the events to your own analytics too

`onSurfaceShown` and `onChoiceRecorded` receive `experiment: { id, arm, assignedBy, acknowledgedDiagnostics }` once the banner shows the arm on the current page. Check `if (experiment)` before forwarding, because it is `undefined` outside the test and when returning visitors reopen preferences from a footer link.

The React example above pushes `inth_surface_shown` and `inth_choice_recorded` to `window.dataLayer`. For PostHog or another tool, call `posthog.capture()` with `experiment.id`, `experiment.arm`, and `surface` or `consentAction`.

Impressions fire before consent. If your analytics tool waits for consent, it misses decliners' impressions and inflates opt-in rates. Use Inth's backend counts for accurate opt-in rates.

## Read state and results

Read the active arm via `useExperiment()`, `useResolvedPresentation()`, and `useResolvedTheme()` in React, `useExperiment()` in Vue, `getConsentManager().experiment` in Svelte, or `snapshot.experiment` everywhere.

Inth attaches `{ id, arm }` to `/v1/consent/init` (and `POST /v1/consent/sessions` in manifest mode) for undecided visitors, and records `metadata.experiment` and `metadata.timeToDecisionMs` on every `POST /v1/consent/records` choice. Experiment summaries, opt-in rates, and median time to decision per arm are available in your Inth dashboard and API.

Compare median `timeToDecisionMs` rather than mean so idle tabs do not skew results. Under `opt-out` with `prompt: 'notice'`, compare `opt_out` choices per visitor owed the banner. Copy is excluded from experiments because `copyRevision` hashes into the prompt fingerprint and re-prompts returning visitors.

## Verify and end the experiment

1. Open your site in a private window with DevTools **Network** open.
2. Confirm the expected arm renders and `snapshot.experiment` reports the right `id`, `arm`, and `assignedBy`.
3. Verify `/v1/consent/init` carries `experiment=<id>=<arm>` (or server `resolveConsent` received the arm).
4. Accept or reject the banner and confirm `POST /v1/consent/records` includes `metadata.experiment` and `metadata.timeToDecisionMs`, and your callbacks fired.

To end the test, copy the winning arm into `presentation` (and its `theme` into `theme`) and remove `experiment`. Existing visitors keep their consent.
