Diagnose and fix common Inth setup, build, and runtime problems across web frameworks.

## Start with three checks

1. **Check the runtime.** Run `window.inth` in the browser console. It prints `{ version, pkg, mode, hosting }`. `undefined` means no Inth provider mounted; `window.c15tStore` means the page still loads v2. On script-tag pages, `window.inth` is the full browser API.
2. **Inspect network requests.** Filter DevTools **Network** by your Inth project URL and inspect `/v1/consent/init` or `/v1/consent/manifest`. A CORS error means your origin is missing from trusted origins.
3. **Inspect consent state.** Mount the Inth DevTools panel from your framework guide to view the active policy, prompt state, permissions, and managed scripts.

Check your framework's troubleshooting page for adapter-specific errors such as Next.js prerendering or SvelteKit hydration.

## `Can't resolve '@inth/...'` or missing exports

**Cause.** You installed the wrong framework package (`@inth/nextjs`, `@inth/react`, `@inth/vue`, `@inth/svelte`, `@inth/angular`, `@inth/astro`, `@inth/tanstack-start`, or `@inth/sdk`), or your lockfile mixes versions across `@inth/*` packages.

**Fix.** Install the package for your framework and align every `@inth/*` package, including `@inth/integrations`, on one release.

**Confirm.** Rebuild and confirm all imports resolve cleanly.

## Why is there no banner?

| What DevTools shows | Cause | Fix |
| --- | --- | --- |
| `/v1/consent/init` or `/v1/consent/manifest` failed or threw a CORS error | Wrong project URL or untrusted origin | Copy your exact Inth project URL and add your site origin (`https://www.example.com`, `http://localhost:3000`) to trusted origins. |
| Requests go to `your-project.inth.app` | Guide placeholder left in code | Replace with your actual Inth project URL. |
| No request to Inth | No provider mounted, `testing()` active, or bundled non-regional manifest | Check `window.inth`. `mode: 'manifest'` with no request is normal for non-regional policies; otherwise set your framework's project URL variable ([consent modes](/docs/concepts/modes#set-the-project-url)). |
| Policy resolved with no prompt required | Region maps to a no-prompt rule | Expected. Test from an opt-in region via VPN or server `country` override (remove before deploying). |
| Policy resolved with a stored choice | Returning visitor | Expected. Clear site data or use a private window. |
| Banner is in the DOM but invisible or unstyled | `styles: false`, CSP blocking `<style>`, Tailwind v3 preflight, or missing `inthHandle` in SvelteKit | Load your framework's stylesheet; see [stylesheets and CSS layers](/docs/customization/stylesheets). |

Never bypass a missing banner by disabling Inth or granting all categories. Unresolved policies keep optional categories denied so scripts cannot fire early.

## Scripts load before the visitor gives consent

**Cause.** Another loader runs outside Inth (`<script>` tags, `@next/third-parties`, `@nuxt/scripts`, `nuxt-gtag`, GTM page-view triggers, or ungated iframes), an `opt-out` policy allows optional categories before choice, or Google Tag / GTM uses its default Consent Mode `loadMode`.

**Fix.** Remove duplicate loaders and register vendors through [integrations](/docs/integrations/overview). For framework plugins, follow [migrate from `@next/third-parties`](/docs/frameworks/next/scripts#migrate-from-nextthird-parties), [migrate from `@nuxt/scripts`](/docs/frameworks/nuxt/scripts#migrate-from-nuxtscripts), or [migrate from `nuxt-gtag`](/docs/frameworks/nuxt/scripts#migrate-from-nuxt-gtag). To block Google Tag / GTM requests before consent, set `loadMode: 'after-consent'` ([Google Tag Manager](/docs/integrations/google-tag-manager#choose-when-the-container-loads)).

**Confirm.** Reload in a private window with **Disable cache** on; optional vendor domains stay absent until allowed.

## Saved choices disappear on reload

**Cause.** `persistence: false` is set, the browser blocks storage (sandboxed iframe or strict privacy mode), the origin/subdomain changed between visits, or the policy updated since the visitor chose.

**Fix.** Remove `persistence: false` in production and serve from one origin (or share cookies across subdomains). Never auto-save consent on load.

**Confirm.** Save a choice, check DevTools **Application** for the `inth` cookie and localStorage entry, and reload. The banner stays closed.

## Page reloads after saving preferences

**Cause.** The visitor revoked an allowed category or vendor; running scripts cannot be unloaded cleanly, so Inth reloads to start fresh.

**Fix.** Keep this default, or set `reloadOnConsentRevoked: false` and handle cleanup yourself ([vendor switches and cookie cleanup](/docs/integrations/overview#vendor-switches-and-cookie-cleanup)).

**Confirm.** Revoke an active category and verify the page behaves as configured.

## Hydration mismatch between server HTML and browser

**Cause.** Server-resolved consent state was mutated before reaching the provider, server and browser used different project URLs, or consent state was cached in a module-level server variable.

**Fix.** Pass the server helper's return value unchanged, align server and client `projectUrl`, and resolve consent per request.

**Confirm.** Reload and verify zero console hydration warnings.

## Why does the build fail to download the manifest?

By default (`onBuildError: 'runtime'`), a failed manifest download warns and falls back to runtime fetching. Builds stop when `onBuildError: 'fail'` or `INTH_ON_BUILD_ERROR=fail` is set, or when either setting has an invalid value. Every integration (`@inth/nextjs/build`, `@inth/sdk/build`, `@inth/tanstack-start/build`, `@inth/vue/vite`, `@inth/svelte/vite`, `@inth/nuxt`, `@inth/astro`) logs the same messages:

| Message | Cause | Fix |
| --- | --- | --- |
| `could not fetch the consent manifest ... (fetch failed: ...)` | Build cannot reach Inth (`ENOTFOUND`, `ECONNREFUSED`) | Allow outbound HTTPS, or override `onBuildError: 'fail'` with `INTH_ON_BUILD_ERROR=runtime`. |
| `... (no response within 10 seconds)` | Request timed out | Check network reachability or retry. |
| `... (/v1/consent/manifest responded 404 Not Found)` | Wrong URL or `your-project.inth.app` placeholder | Copy the exact URL from your Inth project settings. |
| `... (/v1/consent/manifest responded 402: ...)` | Project rejected the request | Follow the error message returned by Inth. |
| `... (/v1/consent/manifest returned an invalid consent manifest.)` | URL returned HTML or non-manifest JSON | Point `projectUrl` at your project URL, not your site or dashboard. |
| `no backend URL is set, so the build cannot fetch the consent manifest.` | Missing `projectUrl` and env var | Set your framework's env var ([consent modes](/docs/concepts/modes#set-the-project-url)). |
| `skipped the consent manifest fetch because "/api/inth" is not an absolute http(s) URL` | Relative project URL | Pass your absolute Inth project URL. Fails when `onBuildError: 'fail'`. |
| `INTH_ON_BUILD_ERROR must be 'runtime' or 'fail'` | Invalid `INTH_ON_BUILD_ERROR` or `onBuildError` value | Use `'runtime'`, `'fail'`, or unset it. |

In Vite SPAs using `manifest({ manifestUrl })` or `manifest({ source: 'runtime' })`, pass `source: 'runtime'` to `consentManifest()` to skip downloading an unused snapshot. Failed downloads never reuse an older snapshot. See [consent modes](/docs/concepts/modes#what-happens-when-the-download-fails).

**Confirm.** Re-run your production build and confirm zero manifest warnings or errors.

## `the consent policy depends on the visitor's location`

**Cause.** `consentManifest()` in a Vite SPA downloaded a regional policy that the browser cannot resolve without geo data.

**Fix.** Pass `manifest({ inputs })` or `manifest({ geoUrl })`, or switch to `hosted()` to avoid bundling an unused snapshot.

**Confirm.** Rebuild and confirm the `@inth/sdk/build` warning clears.

## `` `projectUrl` is required `` or invalid `mode`

**Cause.** Missing `projectUrl` outside `testing()` or `enabled: false`, passing a string like `"hosted"` instead of a factory in `@inth/sdk`, or importing a transport factory from `@inth/react` inside an SSR root.

**Fix.** Set `projectUrl` or your framework's env var ([consent modes](/docs/concepts/modes#set-the-project-url)), call a mode factory (`hosted()`, `manifest()`, `testing()`), and import modes from your framework's own package.

**Confirm.** Reload and check `window.inth` in the console to confirm the active `mode`.

## Static build fails when `dev` works

**Cause.** Static hosts serve files only, so dev proxies and relative `/api/inth` paths return 404.

**Fix.** Set `projectUrl` to your absolute Inth project URL and follow your framework's static setup in [Choose your setup](/docs/concepts/choose-your-setup).

**Confirm.** Serve the built directory with `vite preview` or `npx serve` and verify consent requests succeed.

## `ERR_BLOCKED_BY_CLIENT` hides the banner

**Cause.** An ad blocker blocked your project host or legacy chunk names (`consent-dialog-*.js`).

**Fix.** Update `@inth/*` packages to the latest release (which uses neutral chunk names) and rebuild. If the host itself is blocked, optional categories stay denied by design.

**Confirm.** Reload with the blocker on and inspect **Network** to confirm chunks load.

## Theme tokens or custom styles have no effect

**Cause.** Missing Inth stylesheet (`styles: false`), selector targeting the wrong element (`data-variant` sits on the root, not the card), or Tailwind / CSS layer order.

**Fix.** Verify stylesheets load, inspect DOM attributes, and check layer order in [customization](/docs/customization/overview).

**Confirm.** Inspect computed styles on the banner in DevTools **Elements**.
