Verify in a production build that optional scripts wait for permission, choices survive reloads, preferences reopen, and regional rules apply before you deploy.

Run every check against a production build (`next build && next start`, `vite preview`, or your framework's equivalent). Dev servers load modules differently and hide bundling or manifest issues.

## Prepare the browser

1. Open a private window so no prior choice is stored.
2. Open DevTools **Network** and enable **Disable cache** and **Preserve log**.
3. List every vendor domain your site uses, such as `posthog.com`, `googletagmanager.com`, `connect.facebook.net`, or `youtube-nocookie.com`.

Remove duplicate loaders before testing: raw `<script>` tags, framework analytics plugins, tag manager page-view triggers, and ungated embeds. Inth only controls scripts and embeds registered through it.

## Walk through the visitor flow

| Step | What to verify |
| --- | --- |
| Fresh opt-in visit | The banner appears. Filter **Network** by each optional vendor domain and confirm zero requests. |
| Click Reject | The banner closes. Optional vendor domains still show zero requests. |
| Reload and open a new tab | The banner stays closed and vendor domains stay silent. DevTools **Application** shows an `inth` cookie and an `inth` localStorage entry. |
| Open preferences from your footer link | The dialog opens with rejected categories toggled off. |
| Enable one category and save | Only vendors in that category make network requests. Other categories stay silent. |
| Revoke that category and save | The page reloads (unless `reloadOnConsentRevoked: false`) and the revoked vendor does not load after the reload. |
| Navigate between pages | Each allowed vendor loads once, not once per client-side navigation. |

Google Tag and Google Tag Manager load before consent by default to send Google Consent Mode signals. Verify their request parameters switch from denied to granted when a visitor consents, or set `loadMode: 'after-consent'` to block their requests until consent. See [Google Tag Manager](/docs/integrations/google-tag-manager).

## Check regional rules and GPC

Test at least three visitor contexts:

- **Opt-in region** (such as Germany or the UK): banner appears and optional vendors wait.
- **No-prompt or opt-out region** (such as a US state matching your rules): policy behaves as configured.
- **Unknown location** (no geo headers): your fallback rule applies.

Use a VPN, your host's geolocation preview, or the `country` option on your server helper while testing, and remove test overrides before deploying.

To verify Global Privacy Control, enable GPC in your browser (on by default in Brave and DuckDuckGo, or under Privacy settings in Firefox). Reload and confirm categories restricted for GPC are denied without clicking. Open preferences and confirm the status line reads "Opt-out preference signal honored" and the restricted switches are off and disabled with the GPC notice below each row. Turn GPC off, reload, and confirm the recorded opt-out keeps `marketing` and `measurement` denied and shown off in preferences until the visitor turns either one back on and saves. Under an opt-out policy, clicking the opt-out link (or a `data-inth-action="opt-out"` link) records an opt-out in one click and opens a confirmation view reading "Opt-out request honored". Rejecting all or turning both `marketing` and `measurement` off in preferences records an opt-out too.

## Check the production manifest and failure behavior

If you use `manifest()` with build-time bundling, inspect **Network** on a fresh load:

- Server-rendered apps make no browser `/v1/consent/init` request.
- Single-page apps with a non-regional policy make no `/v1/consent/init` request.
- Confirm the banner copy, categories, and vendors match your latest Inth project settings. Rebuild if they are stale.

Next, force initialization to fail and reload:

- **Browser request** (`/v1/consent/init`, `/v1/consent/manifest`, or same-origin init route): right-click the request in **Network**, select **Block request URL**, and reload.
- **Server-resolved consent**: point `projectUrl` at an unreachable URL for one local run and reload.

Confirm no banner appears and no consent-gated vendor makes a request. A missing banner must never grant consent. Undo the block and confirm the page recovers.

## Check keyboard access and layout

- Tab through the banner and dialog with keyboard only. Focus stays trapped inside modal dialogs and returns to the trigger button on close.
- Test at 375 px width in a language with long labels such as German.
- Confirm text contrast and visible focus rings after applying your theme.

If any step fails, run the three diagnostic checks in [Troubleshooting](/docs/guides/troubleshooting).
