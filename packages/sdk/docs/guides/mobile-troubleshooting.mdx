Diagnose native installation, policy, protected storage, presenter, and IAB issues in Swift and Kotlin apps. Keep optional collection disabled while consent is unavailable.

## Consent screen never appears

**Cause.** Either `policyPending` is `true`, a choice is already stored, the matched policy requires no prompt (or is notice-only), or the presenter was attached to a different core or unmounted host view.

**Fix.** Check that the installed core is ready and `policyPending` is `false`. If policy is pending, inspect `/v1/consent/init` against your exact HTTPS Inth project URL and selected country and language. Confirm you passed the same core instance to the presenter and mounted its view in the active host. Use Privacy settings to reopen saved preferences.

**Confirm.** Reset consent or test on a fresh install in an opt-in region and verify the prompt presents.

## `protectedStorageUnavailable` on Swift installation

**Cause.** The Apple installer probes Keychain before installing the core. Protected data is not yet available (for example before first unlock or while backgrounded), or an unsigned simulator build cannot access Keychain.

**Fix.** Retry installation after protected data becomes available or the app becomes active, and enable working signing on simulator builds. Do not switch to memory or plaintext stores in production; those are development-only tools.

**Confirm.** Launch on a signed simulator or device and confirm `InthApple.install` succeeds without throwing.

## Gradle cannot resolve `com.inth` artifacts

**Cause.** The Maven repository was declared inside `pluginManagement.repositories` instead of dependency repositories, artifact versions do not match across `inth-core`, `inth-android`, and `inth-consent-ui`, or a remote build worker (such as EAS) cannot reach a local repository on your machine.

**Fix.** Add the versioned Maven repository to dependency repositories, align all three artifacts on one native version, and pass repository URL and credentials via build environment variables reachable from CI and build workers. Never commit credentials or place them in app resources.

**Confirm.** Run a clean Gradle sync and release build.

## Save fails or preferences stay open

**Cause.** A commit operation can refuse a save and return a failure reason while leaving the draft open.

| Reason | Fix |
| --- | --- |
| `policy-pending` | Resolve policy before granting optional consent |
| `queue-write-failed` | Recover durable storage; do not confirm a save |
| `concurrent-change` | Reload current state and ask the visitor to review again |
| Missing or stale IAB disclosures | Refresh the authoritative GVL and provider data |

A network failure after a durable local save is a delivery issue, not a save failure. It never restores an earlier permission or drops a withdrawal.

**Confirm.** Fix the reported cause, retry the save action, and verify the commit succeeds and closes the dialog.

## Ad SDK starts before consent

**Cause.** The vendor SDK starts automatically through an Android manifest initializer, an iOS app-delegate hook, a build plugin, or an auto-collection flag before Inth installs.

**Fix.** Disable optional auto-start in the vendor SDK, install Inth before initializing vendors, and retain a native gate subscription so later withdrawals reconfigure or stop collection.

**Confirm.** Inspect startup logs and proxy traffic on a fresh install and verify zero optional vendor requests occur before consent.

## Categories work, but IAB choices fail to save

**Cause.** The matched policy is not an IAB policy, or native CMP and publisher configuration was not installed before creating the first engine. Category scope and vendor filtering alone do not enable IAB.

**Fix.** Configure an IAB policy in Inth and install native CMP settings before startup; see [mobile IAB setup](/docs/guides/mobile-iab).

**Confirm.** Save an IAB choice and rerun the relevant checks in [Verify mobile consent](/docs/guides/mobile-verify).
