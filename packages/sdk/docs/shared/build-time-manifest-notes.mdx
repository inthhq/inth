The snapshot is fixed at build time:

- Rebuild after changing policies, translations or vendors. If your CI caches
  build output, force a fresh build.
- Consent choices still go to Inth.

The build reads the project URL from your framework's public environment
variable when the config omits `projectUrl`: `NEXT_PUBLIC_INTH_PROJECT_URL`
in Next.js, `NUXT_PUBLIC_INTH_PROJECT_URL` in Nuxt,
`PUBLIC_INTH_PROJECT_URL` in Astro, Svelte and SvelteKit, and
`VITE_INTH_PROJECT_URL` in TanStack Start and other Vite apps. The legacy
`*_C15T_BACKEND_URL` variable is read as a fallback when `*_INTH_PROJECT_URL`
is unset. See
[set the project URL](/docs/concepts/modes#set-the-project-url).

The fetch waits at most 10 seconds. When it fails, or no project URL is set,
every framework does the same thing:

| Command | Default when the fetch fails |
| --- | --- |
| Production build: `next build`, `vite build`, `nuxt build`, `astro build` | A warning, and the server or browser fetches the policy at runtime. |
| Dev: `next dev`, `vite dev`, `nuxt dev`, `astro dev` | A warning, and the server or browser fetches the policy at runtime. |

Set `onBuildError` to change that behavior. `'fail'` stops both build and dev
with an error. `'runtime'` lets builds finish and falls back to runtime
fetching. The `INTH_ON_BUILD_ERROR` environment variable overrides the option,
so you can change behavior in CI without a code change:

```sh
INTH_ON_BUILD_ERROR=fail npm run build
```

Turborepo's strict environment mode hides undeclared variables from tasks, so
list `INTH_ON_BUILD_ERROR` in the build task's `passThroughEnv` there.

The build skips the fetch without an error when it can't use a snapshot,
for example when the project URL is relative. With `onBuildError: 'fail'`, a
relative URL stops the build. [Consent modes](/docs/concepts/modes#what-happens-when-the-download-fails)
lists every case.
