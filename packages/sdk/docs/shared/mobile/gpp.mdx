## What GPP does on a device

With GPP enabled, the native engine builds an IAB Global Privacy Platform string for the visitor's current state, exposes it as `snapshot.gppString`, and writes standard `IABGPP_*` keys to `UserDefaults` on iOS and default `SharedPreferences` on Android alongside `IABTCF_*`. Ad SDKs such as Google Mobile Ads and Prebid Mobile read `IABGPP_HDR_GppString` and `IABGPP_GppSID`.

The device encodes two sections:

- **US National (`usnat`, section 7).** MSPA US National version 2. US state sections such as `usca` are not encoded on mobile; every US visitor receives US National.
- **TCF EU (`tcfeuv2`, section 2).** The committed TC String unchanged.

GPP stays off until you enable it. Enabling a US section declares that your app displays sale, sharing, and targeted advertising opt-out notices.

## Turn GPP on

Enable GPP for your platform with the default options:

**Expo.** Add `gpp: true` to the plugin config and rebuild:

```json title="app.json"
["@inth/react-native", { "projectUrl": "https://your-project.inth.app", "gpp": true }]
```

**Bare React Native.** Add Boolean `com.inth.gpp` (`true`) to `Info.plist`, and `<meta-data android:name="com.inth.GPP" android:value="true" />` inside `<application>` in `AndroidManifest.xml`.

**Swift.** Pass `GPPOptions()` to `InthAppleConfiguration(gpp:)`:

```swift
let configuration = InthAppleConfiguration(
    backendURL: "https://your-project.inth.app",
    gpp: GPPOptions()
)
```

**Kotlin.** Pass `GppOptions()` in `NativeConfig`:

```kotlin
NativeConfig(backendUrl = "https://your-project.inth.app", gpp = GppOptions())
```

Replace `https://your-project.inth.app` with your Inth project URL.

## GPP options

| Option | Default | Expo field | iOS `Info.plist` key | Android metadata |
| --- | --- | --- | --- | --- |
| Turn GPP on | off | `gpp: true` or object | `com.inth.gpp` (Boolean) | `com.inth.GPP` |
| `mspaMode` | unset | `gpp.mspaMode` | `com.inth.gpp.mspaMode` | `com.inth.GPP_MSPA_MODE` |
| `optOutCategories` | `marketing` | `gpp.optOutCategories` | `com.inth.gpp.optOutCategories` (array) | `com.inth.GPP_OPT_OUT_CATEGORIES` (comma-separated) |
| `tcf` | `true` | `gpp.tcf` | `com.inth.gpp.tcf` (Boolean) | `com.inth.GPP_TCF` |

- **`mspaMode`.** Accepts `opt-out-option` or `service-provider`. Set it only if you signed the IAB Multi-State Privacy Agreement; the transaction is then reported as covered. In `service-provider` mode, opt-outs and notices are reported as not applicable. Expo prebuild fails on any other value; native keys ignore unrecognized values.
- **`optOutCategories`.** Lists categories whose refusal signals opt-out of sale, sharing, and targeted advertising (defaults to `marketing`). Pass an empty list (`[]` in Expo, `<array/>` in `Info.plist`, or `none` on Android) so no category triggers opt-out. `necessary` is always granted and never drives opt-outs.
- **`tcf: false`.** Omits the TCF EU section under an `iab` policy.

## How the policy selects a section

Nothing is written until the engine is ready and matches a policy rule:

| Matched rule and visitor | Section |
| --- | --- |
| `iab` rule, after the visitor saved an IAB choice | TCF EU (2), using the committed TC String |
| `iab` rule, before any IAB choice or with `tcf: false` | None |
| Any other rule with `preferences` or `opt-out` right, visitor in the US | US National (7) |
| A `none` rule without those rights, or visitor outside the US | None |

Every `opt-in` and `opt-out` rule includes the `preferences` right. Country comes from the app's `country` override if set, otherwise from `/v1/consent/init`. When no section applies, `gppString` is `null` and the engine clears every `IABGPP_*` key.

## What US National reports

- `SaleOptOut`, `SharingOptOut`, and `TargetedAdvertisingOptOut` are `1` (opted out) when any opt-out category is not permitted (via refusal, a GPC-mapped rule, or an ungranted opt-in rule), otherwise `2`.
- All three opt-out notices are `1` (given).
- `SharingNotice` is `1` when the rule has the `disclosure` right, otherwise `2`.
- `Gpc` mirrors `snapshot.privacySignals.gpc.active`.
- `MspaCoveredTransaction` is `2` (not covered) unless `mspaMode` is set.
- Sensitive data, known-child, personal data consents, and sensitive data notices are `0` (not applicable). Collect and signal those separately if your app processes sensitive data.

Both web and mobile Inth encode US National version 2 for compatibility with current IAB reference decoders.

## The `IABGPP_*` keys

| Key | Type | Value |
| --- | --- | --- |
| `IABGPP_HDR_Version` | String | `"1"` |
| `IABGPP_HDR_Sections` | String | Section IDs joined with `_`, such as `"7"` |
| `IABGPP_HDR_GppString` | String | Full GPP string |
| `IABGPP_GppSID` | String | Active section IDs, matching `IABGPP_HDR_Sections` |
| `IABGPP_2_String`, `IABGPP_7_String` | String | Individual section strings |
| `IABGPP_2_TCString` | String | TC String under the TCF EU section key |
| `IABGPP_TCFEU2_*` | Integer or String | `IABTCF_*` consent values mapped to GPP naming |

IAB defines no per-field keys for US National. Read `IABGPP_7_String` or decode the full GPP string.

## Verify the signal

Read the string with `useGPPString()` in `@inth/react-native` or `snapshot().gppString` in Swift and Kotlin. Both return `null` when GPP is off or no section applies.

For a US visitor under an `opt-out` rule with no refusals, the string is `DBABLA~CVQqAAAAAACA.QA` and `IABGPP_GppSID` is `"7"`. After refusing `marketing`, it updates to `DBABLA~CVQVAAAAAACA.QA` (`SaleOptOut` changes from `2` to `1`).

GPP communicates user choices to ad SDKs; it does not block SDK execution on its own. Continue gating SDKs with native consent gates.
