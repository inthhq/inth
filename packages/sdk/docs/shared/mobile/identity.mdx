<section id="link">

Account identity, consent state, and OS tracking permission have separate lifetimes. Always update consent through the native engine so stored decisions, platform signals, and the delivery queue stay in sync.

## Link an app account

</section>

<section id="link-swift">

Call `identify(KernelUser(externalId: userId))` once the user signs in and `logout()` when they sign out, then recheck native gates before resuming optional collection.

</section>

<section id="link-android">

Call `identify(KernelUser(externalId = userId))` once the user signs in and `logout()` when they sign out, then recheck native gates before resuming optional collection.

</section>

<section id="link-react-native">

Call `identify(externalId)` once the user signs in and `logout()` when they sign out. Await each call and recheck native gates before resuming optional collection.

</section>

<section id="link-account">

The Inth subject identifies the consent record; an external ID links that subject to an app account. Calling `logout()` detaches the account without creating a new subject or deleting backend audit records. Category receipts stay with the subject, while IAB identity transitions retire existing authority and keep required withdrawal obligations.

## Withdraw optional consent

</section>

<section id="withdraw-swift">

Record an explicit refusal or withdrawal with the `.necessary` commit intent. Check the commit status before confirming the save. Stock presenters keep drafts open if storage refuses a write.

</section>

<section id="withdraw-android">

Record an explicit refusal or withdrawal with `CommitIntent.Necessary`. Check the native commit result before confirming the save. Stock presenters keep drafts open if storage refuses a write.

</section>

<section id="withdraw-react-native">

Record an explicit refusal or withdrawal with `saveConsents('none')`. Check `CommitResult.ok` before confirming the save. Stock presenters keep drafts open if storage refuses a write.

</section>

<section id="reset">

Withdrawal applies locally immediately, even offline, and queues delivery to Inth. Never delete app storage, clear the queue, or edit IAB keys directly instead of recording a withdrawal.

## Reset to a new prompt

Reset clears local consent authority so policy resolves again and the app can re-prompt. It preserves the subject and configuration and does not mean reject-all, account erasure, or backend deletion.

</section>

<section id="reset-swift">

Call `reset()` on the installed `ConsentCore`.

</section>

<section id="reset-android">

Call `reset()` on the installed kernel (`Inth.current`). `Inth.uninstall()` only tears down the process singleton and leaves stored consent untouched.

</section>

<section id="reset-react-native">

Call `useConsentActions().reset()`.

</section>

<section id="deletion">

Reset preserves pending IAB withdrawal obligations. If storage refuses a reset, surface the error and keep optional collection off.

## Handle deletion separately

Implement account deletion and backend erasure in your app and server workflows; `reset()` does not delete remote records.

</section>

<section id="deletion-ios">

On iOS, Keychain items can persist after uninstalling the app, so uninstalling is not a reliable reset.

</section>
