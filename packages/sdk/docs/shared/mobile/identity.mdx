Account identity, consent state, and OS tracking permission have separate lifetimes. Always update consent through the native engine so stored decisions, platform signals, and the delivery queue stay in sync.

## Link an app account

Call `identify(externalId)` once the user signs in and `logout()` when they sign out. Await each call and recheck native gates before resuming optional collection.

The Inth subject identifies the consent record; an external ID links that subject to an app account. Calling `logout()` detaches the account without creating a new subject or deleting backend audit records. Category receipts stay with the subject, while IAB identity transitions retire existing authority and keep required withdrawal obligations.

## Withdraw optional consent

Record an explicit refusal or withdrawal with `saveConsents('none')` in React Native, `.necessary` in Swift, or `CommitIntent.Necessary` in Kotlin. Check the commit result (`CommitResult.ok` in React Native, commit status in Swift, or native commit result in Kotlin) before confirming the save. Stock presenters keep drafts open if storage refuses a write.

Withdrawal applies locally immediately, even offline, and queues delivery to Inth. Never delete app storage, clear the queue, or edit IAB keys directly instead of recording a withdrawal.

## Reset to a new prompt

Reset clears local consent authority so policy resolves again and the app can re-prompt. It preserves the subject and configuration and does not mean reject-all, account erasure, or backend deletion.

| Platform | Reset command |
| --- | --- |
| React Native | `useConsentActions().reset()` |
| Swift | `reset()` on the installed `ConsentCore` |
| Kotlin | `reset()` on the installed kernel (`Inth.current`) |

Kotlin's `Inth.uninstall()` only tears down the process singleton and leaves stored consent untouched.

Reset preserves pending IAB withdrawal obligations. If storage refuses a reset, surface the error and keep optional collection off.

## Handle deletion separately

Implement account deletion and backend erasure in your app and server workflows; `reset()` does not delete remote records. On iOS, Keychain items can persist after uninstalling the app, so uninstalling is not a reliable reset.
