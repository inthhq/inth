## Choose an offline policy source

Saved consent choices already survive restarts offline. The native engine restores its protected record before returning from installation and keeps optional SDKs off whenever authority is unresolved or invalid.

The mobile SDKs connect to your Inth project to fetch policy and deliver consent records. Fresh installations have no cached policy yet. If a first launch must prompt while offline, ship a policy at build time:

| Policy source | Source of rules | When to use |
| --- | --- | --- |
| [Bundled manifest](#bundle-the-manifest-at-build-time) | Exported from your Inth project at build time | Production. Matches your dashboard policy and supports IAB TCF. |
| [In-code policy](#define-the-policy-in-code) | Rules checked into source control | When you keep code and dashboard rules in sync manually. No IAB TCF. |

Do not combine both sources. With either source, the engine saves choices locally, queues records, and delivers them to Inth on reconnect.

Without an in-code policy, the SDK resolves policy in this order:

1. Live `/v1/consent/init` response.
2. Last cached live response on the device.
3. Bundled manifest shipped in the binary (a newer bundled manifest replaces an older bundled one, never a cached live response).

With an in-code policy, the device evaluates rules locally and never calls `/v1/consent/init`. For local development and CI without sending records, use [`dryRun`](#run-without-sending-records).

## Define the policy in code

Define rules using Inth's `PolicyRule` fields (`id`, `match`, `model`, `prompt`, `categories`, `scopeMode`, `preselectedCategories`, `actions`, `validity`, `privacySignals`, `copyRevision`). The device matches rules in backend order (`region`, `country`, `regionFallbacks`, `fallback`, `isDefault`) and still sends consent records to `projectUrl`.

Inth validates submitted records against your project's live policy and rejects mismatches with HTTP `422` (`decision-mismatch`). Keep in-code rules identical to your dashboard policy, or prefer a bundled manifest for production. Because an in-code policy never calls `/v1/consent/init` to learn location, always include a `match.fallback` or `match.isDefault` rule.

```ts title="app.config.ts"
export default {
	plugins: [
		[
			'@inth/react-native',
			{
				projectUrl: 'https://your-project.inth.app',
				consentCategories: ['necessary', 'measurement', 'marketing'],
				policy: {
					rules: [
						{
							id: 'germany',
							match: { countries: ['DE'] },
							model: 'opt-in',
							prompt: 'choice',
						},
						{
							id: 'everywhere_else',
							match: { fallback: true, isDefault: true },
							model: 'opt-in',
							prompt: 'choice',
						},
					],
				},
			},
		],
	],
};
```

```swift title="Swift"
let policy = try ConsentPolicy(rules: [
    PolicyRule(id: "germany", match: PolicyMatch(countries: ["DE"]), model: .optIn, prompt: .choice),
    PolicyRule(id: "everywhere_else", match: PolicyMatch(fallback: true, isDefault: true),
               model: .optIn, prompt: .choice),
])
let core = try InthApple.install(InthAppleConfiguration(
    backendURL: "https://your-project.inth.app",
    policy: policy
))
```

```kotlin title="Kotlin"
val policy = ConsentPolicy(listOf(
    PolicyRule("germany", PolicyMatch(countries = listOf("DE")), ConsentModel.OPT_IN, PolicyPrompt.CHOICE),
    PolicyRule("everywhere_else", PolicyMatch(fallback = true, isDefault = true), ConsentModel.OPT_IN, PolicyPrompt.CHOICE),
))
InthAndroid.install(
    context,
    NativeConfig(backendUrl = "https://your-project.inth.app", policy = policy),
)
```

Both native cores also load JSON (`{"rules": [...]}`) via `ConsentPolicy(json:)` in Swift and `ConsentPolicy.fromJson` in Kotlin. Expo writes that file and registers `com.inth.policy.rules` (`Info.plist`) and `com.inth.POLICY_RULES` (`AndroidManifest.xml`).

Validation rules match the backend: partial `categories` require `scopeMode`, `actions` must include `accept` and `reject`, at most one rule sets `fallback` and one sets `isDefault`, `'*'` is valid only in `categories`, and unknown fields fail validation. Invalid rules at launch keep optional categories off and emit `policy-invalid` until a valid build ships. Bump `copyRevision` to re-prompt returning users when wording changes; `validity.choiceDays` and `validity.noticeDays` control choice and notice expiry separately.

In-code policies do not support `iab` (which requires the Global Vendor List) and cannot be combined with `policyResource`, `bundleManifest`, or `bundledPolicy`.

## Bundle the manifest at build time

Fetch the latest manifest during each build so releases ship with current rules. When Inth is unreachable, release builds fail and debug builds warn and continue without a bundled copy (unless `allowStaleManifest` reuses the last valid copy for air-gapped CI). Invalid manifests fail every build.

In Expo, add `@c15t/cli` to `devDependencies` and configure `bundleManifest`:

```ts title="app.config.ts"
export default {
	plugins: [
		[
			'@inth/react-native',
			{
				projectUrl: 'https://your-project.inth.app',
				bundleManifest: { allowStaleManifest: false, languages: ['de'] },
			},
		],
	],
};
```

Prebuild runs `c15t mobile-manifest` and embeds the output in both native projects. Any build configuration whose name does not contain `debug` is treated as `release` (override with `INTH_MANIFEST_BUILD=debug`). Top-level `vendors` narrows the bundled GVL.

Without Expo, run [`c15t mobile-manifest`](/docs/cli/commands/mobile-manifest) in your native build pipeline:

```sh title="Xcode Run Script phase, after Copy Bundle Resources"
case "$CONFIGURATION" in
  *[Dd][Ee][Bb][Uu][Gg]*) BUILD=debug ;;
  *) BUILD=release ;;
esac
npx @c15t/cli mobile-manifest --backend-url https://your-project.inth.app \
  --out "$TARGET_BUILD_DIR/$UNLOCALIZED_RESOURCES_FOLDER_PATH/inth-policy.json" \
  --build "$BUILD"
```

```groovy title="android/app/build.gradle"
abstract class InthManifestTask extends DefaultTask {
    @Input abstract Property<String> getBuild()
    @Internal abstract DirectoryProperty getAppRoot()
    @OutputDirectory abstract DirectoryProperty getOutputDir()
    @Inject abstract ExecOperations getExecOperations()

    @TaskAction
    void fetch() {
        def out = new File(outputDir.get().asFile, 'inth-policy.json')
        execOperations.exec {
            workingDir appRoot.get().asFile
            commandLine 'npx', '@c15t/cli', 'mobile-manifest',
                '--backend-url', 'https://your-project.inth.app',
                '--out', out.path, '--build', build.get()
        }
    }
}

androidComponents {
    onVariants(selector().all()) { variant ->
        def fetch = tasks.register("inthManifest${variant.name.capitalize()}", InthManifestTask) {
            build = (variant.buildType ?: '').toLowerCase().contains('debug') ? 'debug' : 'release'
            appRoot = rootProject.layout.projectDirectory.dir('..')
        }
        variant.sources.assets.addGeneratedSourceDirectory(fetch) { it.outputDir }
    }
}
```

On iOS, write straight into the built app bundle (and list the output path in Output Files if user script sandboxing is enabled) so debug builds that skip fetching do not copy an old file.

Manifest export requires a conservative opt-in or IAB fallback rule with no preselected optional categories. For scoped IAB apps, pass `--vendors` with comma-separated vendor IDs. Export also includes custom (non-IAB) vendors and fails if two custom vendors share an ID. Pass `--dry-run` on debug builds pointing at staging or loopback hosts. Repository maintainers re-export example app fixtures with `bunx tsx scripts/export-mobile-policy.ts`, which takes an explicit `--expires-at`.

## Include the resource in the app

| Platform | Resource location | Configuration |
| --- | --- | --- |
| Swift | App target Copy Bundle Resources | Load `BundledPolicyResource` and pass as `bundledPolicy` |
| Bare RN (iOS) | App target Copy Bundle Resources | Set `com.inth.policy.resource` in `Info.plist` |
| Kotlin or bare RN (Android) | `app/src/main/assets/inth-policy.json` | Pass JSON as `NativeConfig.bundledPolicy` or set `com.inth.POLICY_RESOURCE` |
| Expo | Beside `app.config.ts` or custom path | Set `policyResource` in the plugin config and rebuild |

Use the same project URL at export and launch. The JSON is a public artifact; never store secrets in it.

## When the bundled manifest expires

An expired bundled manifest still prompts and records choices offline while emitting `policyStale`. Optional categories stay denied until the user chooses, and the next live `/v1/consent/init` replaces the stale manifest.

| Platform | Event | Current state |
| --- | --- | --- |
| Swift | `CoreEvent.policyStale(authority)` on `eventStream` | `ConsentCore.isPolicyStale` |
| Kotlin | `ConsentCore.onPolicyStale { authority -> }` | `ConsentCore.isPolicyStale` |

Manifests bound to a different project URL or issued in the future are rejected, leaving optional SDKs off. IAB disclosures expire separately from their original GVL or provider-list source date (default 7 days); an expired list cannot authorize new IAB grants.

Rejection and withdrawal always work offline. Verify local commit success before dismissing settings. On reconnect, queued records never overwrite a newer withdrawal with an earlier grant. See [identity and reset](/docs/guides/mobile-identity).

## Run without sending records

Enable `dryRun` in development and CI to test prompts, storage, gates, and signals without queueing or sending records to Inth. Identity calls update local state only, and any prior queued records are dropped on the first dry-run save. The app still fetches `/v1/consent/init` unless paired with a bundled manifest or in-code policy.

| Platform | How to enable |
| --- | --- |
| Expo | `dryRun: true` in the config plugin |
| Bare RN | `com.inth.dryRun` (`true`) in `Info.plist`, `com.inth.DRY_RUN` in Android metadata |
| Swift | `InthAppleConfiguration(backendURL:dryRun:)` inside `#if DEBUG` |
| Kotlin | `NativeConfig(backendUrl = ..., dryRun = true)` or `com.inth.DRY_RUN` metadata |

Release builds reject `dryRun` (`dryRunInReleaseBuild` in Swift, `IllegalStateException` in Kotlin, and deny-all from metadata hooks). In debug builds, `dryRun` accepts any `https` URL or `http` on `localhost`, `127.0.0.1`, or `[::1]`.

## Check that it works

1. Install a build with a valid bundled policy and launch offline with no stored choice. Confirm the prompt appears and optional SDKs stay off.
2. Reject, stop the app, and relaunch offline. Confirm the refusal persists.
3. Reconnect and confirm the queued record arrives in your Inth project.
4. Repeat with an expired bundle and confirm the prompt appears, optional SDKs stay off, and `policyStale` fires.
5. Repeat with a bundle exported for another project URL and confirm no prompt appears and optional SDKs stay off.

Because bundled manifests live inside the native binary, rebuild and ship a new binary after updating them; JavaScript OTA updates do not replace native resources.
