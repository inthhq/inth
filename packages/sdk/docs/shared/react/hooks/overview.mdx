<section id="read-state">
  Call hooks inside the consent provider. `useConsent` reads effective permission, which can be `true` under an opt-out policy before the visitor records a choice.

  | Need | Hook |
  | --- | --- |
  | One category's current permission | `useConsent(category)` |
  | All current permissions | `useConsents()` |
  | Recorded per-category choices | `useExplicitChoice()` |
  | Whether one declared vendor may run | `useVendorAllowed(id)` |
  | Whether a prompt is required | `usePromptRequirement()` |
  | Honored opt-out status and lock state | `useOptOutState()` |
  | Record an opt-out in one click and confirm it | `useOptOut()` |
  | Active policy and resolution | `usePolicyRule()`, `usePolicyResolution()` |
  | Save an explicit choice | `useSaveConsents()` |
  | Open or close a consent surface | `useSetActiveUI()` |
  | Acknowledge a notice | `useDismissNotice()` |
</section>

<section id="save-guidance">
  This is an isolated action example, not a complete policy-aware banner. Use the built-in UI or headless surface actions for a full prompt. Never call save on mount to persist state derived from permissions.

  Use focused hooks for feature gates. For a custom prompt or preference center, use `useHeadlessConsentUI()` for surface actions and `useConsentDraft()` for staged choices inside one `ConsentDraftProvider` so saving commits the same draft. Inth replaces `useConsentManager()` with focused selector hooks; see [Migrate from c15t](/docs/migrate-from-c15t) for moving c15t v2 hook calls to Inth hooks. Read [how consent works](/docs/concepts/how-consent-works#a-permission-is-not-a-recorded-choice) before treating a callback as proof of a recorded choice.
</section>
