<section id="containers">
  The policy decides which actions appear. The container decides where the prompt sits. All three containers show the same copy and the same choices.

  | Container | Positions | Default | Shape |
  | --- | --- | --- | --- |
  | `{ type: 'card', position }` | `start`, `end`, `center` | `start` | A floating card in a bottom corner, or centred over a backdrop. |
  | `{ type: 'banner', edge }` | `bottom`, `top` | `bottom` | A full-width banner along one edge. |
  | `{ type: 'drawer', side }` | `bottom`, `top`, `start`, `end` | `bottom` | A panel that slides in from one side and shows every choice at once on desktop. |

  `start` and `end` are logical, like CSS `inset-inline-start`. On a right-to-left page, `start` is the bottom-right corner.

  ```tsx
  <ConsentBanner container={{ type: 'banner', edge: 'bottom' }} edgeStyle="flush" />
  ```

  Customize opens the choices inside the same container. The visitor does not leave the banner to make a choice. On phones, a `start` or `end` Drawer becomes a bottom Drawer.

  Set a container in three places. The first one that is set wins:

  1. The `container` prop on `ConsentBanner`.
  2. `presentation.prompt.container` in the provider options.
  3. The policy rule's `surface.container`, set in the dashboard. Script-tag installs, which have no props, use this one.

  `edgeStyle` follows the same order, with `surface.edgeStyle` last.

  **Blocking.** `blockUntilChoice` dims the page, locks scroll, and keeps focus inside the prompt until the visitor chooses. A centred Card always blocks. A notice never blocks, and neither does a prompt under an opt-out model. Where blocking is not possible, a centred Card moves to the `start` corner. The policy's `surface.blocking` is a hard rule: `forbidden` never blocks, and `required` always blocks a choice prompt. A blocking prompt has `role="dialog"` and `aria-modal="true"`. A non-blocking prompt is a labelled region and leaves the page interactive.
</section>

<section id="data-attributes">
  The root element exposes these attributes for CSS or Tailwind targeting:

  | Attribute | Values |
  | --- | --- |
  | `data-placement` | `card-start`, `card-end`, `card-center`, `banner-bottom`, `banner-top`, `drawer-bottom`, `drawer-top`, `drawer-start`, `drawer-end` |
  | `data-flow` | `expand-in-place`, `all-in-one` |
  | `data-variant` | `choice`, `us-consent`, `notice` |
  | `data-edge-style` | `inset`, `flush` |
  | `data-blocking` | `true`, present only while blocking |
  | `data-expanded` | `true`, present while Customize shows the choices |
  | `data-state` | `open`, `closed` |

  Each action button sets `data-action`.
</section>
