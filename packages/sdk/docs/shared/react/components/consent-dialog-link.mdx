<section id="props">
  ## Props

  | Prop | Type | Default | Description |
  | --- | --- | --- | --- |
  | `children` | `ReactNode` | required | The visible label, such as "Privacy settings" or "Manage preferences". Also sets the accessible name. |
  | `asChild` | `boolean` | `false` | Renders your own element, such as an anchor, instead of a `button`, and attaches the click handler to it. |
  | `noStyle` | `boolean` | `true` | Omits Inth button classes. Native browser styles remain unless your CSS resets them. Pass `false` to render it as an Inth button with `variant` and `mode`. |
  | `onClick` | `(event) => void` | none | Runs before the dialog opens. Call `event.preventDefault()` to keep it closed. |

  Other `button` attributes such as `className`, `style`, `id`, and `aria-*` pass through to the rendered element.
</section>

<section id="behavior">
  ## Behavior

  `ConsentDialogLink` renders a `button` with `type="button"` and no Inth styling by default. Clicking it sets `dialog` as the active surface, opening a mounted `ConsentDialog`. It saves nothing and changes no permissions.

  The element carries `data-inth-rights` listing the active policy rule's rights, such as `disclosure opt-out preferences` under a US opt-out rule or `disclosure preferences` under an opt-in rule, so CSS or a `::after` label can adapt the wording by region.

  Without a resolved policy rule, the link renders nothing and appears as soon as a rule resolves without remounting. A rule with `model: 'none'` and an empty `rights` list hides the link; a `none` rule with any right such as `['disclosure']` displays the link and opens the dialog as a settings route.

  Mount one `ConsentDialog` inside the same provider. Without one, clicking the link still switches the active surface: nothing opens, and any visible banner closes because the active surface is no longer `banner`.

  With `asChild`, the child's `onClick` runs first; calling `event.preventDefault()` keeps the dialog closed. Inth does not block the child's native behavior, so an anchor still follows its `href`. Use a fragment or the current page URL, or render a `button`.

  ### ConsentDialogLink or ConsentDialogTrigger

  Both open the same dialog and expose `data-inth-rights`. Use `ConsentDialogLink` inside your own layout, such as a footer, privacy page, or settings menu; it adds no positioning, icon, or visibility rules. Use `ConsentDialogTrigger` for a floating, draggable corner button that can wait until the visitor answers the first prompt.
</section>

<section id="accessibility">
  ## Accessibility

  The rendered `button` is keyboard-focusable and activates with Enter and Space. Its accessible name comes from `children`, so use clear wording instead of "click here". Because the dialog carries its own title and returns focus to the link when closing while blocking, no extra `aria-haspopup` or `aria-controls` is added; a non-blocking dialog does not move focus back. With `asChild`, focusability comes from your element, so pass a `button` or an anchor with an `href`.
</section>

<section id="verify">
  ## Verify

  Scroll to the footer. With your footer button reset applied, the link matches your footer typography without default button chrome. Click it or press Enter and confirm the preference center opens as a centered dialog. Press Escape and confirm focus returns to the link under the default blocking dialog. Inspect the element in DevTools and check `data-inth-rights`: switching to a US opt-out region adds `opt-out`, and switching to a rule with `model: 'none'` and no rights removes the link.
</section>
