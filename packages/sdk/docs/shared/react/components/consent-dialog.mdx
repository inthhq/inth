<section id="props">
  ## Props

  | Prop | Type | Default | Description |
  | --- | --- | --- | --- |
  | `open` | `boolean` | follows active surface | Controls the open state. When set, Escape and the dialog's Save Settings, Accept All, and Reject All buttons no longer close it; update the prop instead. A missing policy or unlisted model still keeps it closed. |
  | `showTrigger` | `boolean \| ConsentDialogTriggerProps` | `false` | Renders a floating `ConsentDialogTrigger` next to the dialog. Pass an object to configure the trigger. |
  | `models` | `Model[]` | `['opt-in', 'opt-out', 'none']` | Policy models the dialog handles. Under an unlisted model such as `iab`, it stays closed. |
  | `legalLinks` | `(keyof LegalLinks)[] \| null` | none | Selects which links from provider `options.legalLinks` render after the description. Omitting the prop renders none; `null` hides them. |
  | `hideBranding` | `boolean` | `false` | Hides the "Secured by" tag in the card. |
  | `uiSource` | `string` | `'dialog'` | Source identifier recorded with saves made from this dialog. |
  | `scrollLock`, `trapFocus` | `boolean` | from `blocking` | Deprecated. Setting either to `false` makes the dialog non-blocking unless the provider sets `presentation.preferences.blocking`, which wins. Prefer the provider option. |
  | `disableAnimation` | `boolean` | `false` | Skips enter and exit animations for the backdrop and card. |
  | `noStyle` | `boolean` | `false` | Removes built-in styling from every part. |
</section>

<section id="behavior">
  ## Behavior

  The dialog wraps the preference center in a modal. Its card contains a header with `consentManagerDialog.title`, `consentManagerDialog.description`, and optional legal links, followed by the same category accordion and Reject All, Accept All, and Save Settings actions rendered by `ConsentWidget`, plus the branding tag. It mounts into `document.body` through a portal after hydration, so it never appears in server HTML.

  Without an `open` prop, the dialog follows the active surface and opens when it becomes `dialog`. These triggers set that surface:

  - The Customize button on `ConsentBanner`, and the "Manage preferences" or "Do Not Sell or Share My Personal Information" button on a notice.
  - `ConsentDialogLink` and `ConsentDialogTrigger`.
  - The button inside a `ConsentGate` placeholder.
  - `useSetActiveUI()('dialog')` in your component, or `openDialog()` from `useHeadlessConsentUI()` on the headless subpath.

  Inth splits the dialog code into its own chunk so it stays out of the first page load. It renders nothing until the chunk loads, which starts at the first of these events:

  - The browser's first idle period after the page `load` event while the banner is visible or a `ConsentDialogLink`, `ConsentDialogTrigger`, `ConsentGate` button, or other opener is mounted. This covers visitors who tap or press Enter without hovering first. Browsers without `requestIdleCallback`, such as Safari, wait 200 ms after `load`.
  - Hover or focus on a button that opens the dialog.
  - The dialog opening.

  Passing `open={true}` or `showTrigger` loads the chunk on mount. A returning visit with saved consent and no opener on the page never downloads it.

  Inth skips idle loading when Save-Data is on (`navigator.connection.saveData`), on `2g` or `slow-2g` connections, and while offline; hover and focus still trigger the download. To load the chunk only on hover, focus, or open, set `preloadDialog: 'intent'` in the provider options. The default is `'idle'`. In Next.js, pass it through `InthProvider`'s `options` prop.

  If a preload fails while offline, nothing is cached and the next hover, focus, or open retries the download.

  The dialog CSS travels inside the same chunk and applies before the dialog renders, keeping the first page load limited to banner rules.

  Without an `open` prop, Escape closes the dialog without saving. If the policy still owes a choice, the banner returns. Save Settings, Accept All, and Reject All close the dialog as soon as the browser records the choice in the same click task, while the exit animation plays. The network request to Inth runs afterwards and never reopens the dialog: a failed request keeps the local choice, reports through `onError`, and retries later. See [when a choice is saved](/docs/concepts/consent-state#when-a-choice-is-saved) for the exact order. A draft that went stale after a policy change keeps the dialog open for review. With `open={true}`, those actions leave the dialog open until the parent sets `open={false}`. Clicking the backdrop does not close it. Closing discards unsaved toggles so the next open starts from the recorded choice. After saving from an uncontrolled dialog, all consent UI hides unless the policy still owes a notice prompt, in which case the banner returns.

  The preference center is blocking by default, combining a backdrop, body scroll lock, and focus trap. Set `presentation.preferences.blocking` to `false` in the provider options to turn off all three; the deprecated `scrollLock` and `trapFocus` props do the same for one dialog. `variant` and `position` apply only to prompts. Setting them under `presentation.preferences` logs an `invalid-variant` diagnostic in development and has no effect; the dialog is always centered.

  The dialog never opens without a resolved policy rule, even when the active surface is already `dialog`; it appears as soon as a rule resolves without remounting. A rule with `model: 'none'` and no rights owes no consent UI, so the dialog stays closed. When a `none` rule lists any right, such as `rights: ['disclosure']` or `rights: ['preferences']`, the dialog opens as a settings route and Save finishes without writing a consent record.

  Copy comes from `consentManagerDialog.title`, `consentManagerDialog.description`, `common.acceptAll`, `common.rejectAll`, `common.save`, and `consentTypes.<category>.title` and `.description` for each row.
</section>

<section id="accessibility">
  ## Accessibility

  The panel carries `role="dialog"`, `aria-labelledby="consent-dialog-title"`, `aria-describedby="consent-dialog-description"`, and `aria-modal="true"` while blocking. Its `dir` attribute matches the active language.

  While blocking, opening moves focus to the first tabbable control inside the panel so keyboard users see a focus ring on a control rather than the whole card, while `aria-labelledby` and `aria-describedby` let screen readers announce the title and description. Tab and Shift+Tab wrap inside the panel, and closing returns focus to the element that opened it. A non-blocking dialog does not move focus on open or close. The backdrop has `aria-hidden` and is not focusable.

  Each category switch uses the category title as its accessible name. The `necessary` switch is disabled and always on. A saved grant overridden by the policy or a privacy signal displays a note under its row linked through `aria-describedby`.
</section>

<section id="composition">
  ## Composition

  Every part is available as `ConsentDialog.<Part>`: `Root`, `Overlay`, `Card`, `Header`, `HeaderTitle`, `HeaderDescription`, `Content`, `Footer`, and `ConsentCustomizationCard`. `Root` owns the portal, open state, focus trap, scroll lock, and backdrop, and accepts `open`, `models`, `noStyle`, `disableAnimation`, `scrollLock`, `trapFocus`, `uiSource`, and `overlay`. Pass `overlay={false}` to omit the backdrop, or pass a node to replace it.

  ```tsx
  <ConsentDialog.Root>
    <ConsentDialog.Card>
      <ConsentDialog.Header>
        <ConsentDialog.HeaderTitle>Your privacy choices</ConsentDialog.HeaderTitle>
        <ConsentDialog.HeaderDescription legalLinks={['privacyPolicy']} />
      </ConsentDialog.Header>
      <ConsentDialog.Content>
        <ConsentWidget />
      </ConsentDialog.Content>
      <ConsentDialog.Footer hideBranding />
    </ConsentDialog.Card>
  </ConsentDialog.Root>
  ```

  Keep `ConsentWidget` inside `Content`: it owns the draft, switches, and policy actions, and inherits the dialog's `uiSource`. `Footer` renders the branding tag unless you pass children or `hideBranding`.

  The positioner carries `data-slot="dialog-positioner"`, and both it and the panel carry `data-blocking="true"` while blocking. Provider component slots for the built-in layout are `dialog.root`, `dialog.container`, `dialog.card`, `dialog.header`, `dialog.title`, `dialog.content`, `dialog.overlay`, `description.dialog`, `manager.footer`, and `tag.dialog`.

  `ConsentDialog` from the package root and `@inth/react/consent-dialog` is the deferred component described under Behavior, and each `ConsentDialog.<Part>` loads from the same chunk. `@inth/react/components/consent-dialog` exports the dialog without deferral plus each part as a named export (`Card`, `Header`, `Overlay`, `Root`, and the rest). Importing from that subpath puts the dialog code in the initial bundle so the first open needs no download, at the cost of shipping it to every visitor.
</section>

<section id="verify">
  ## Verify

  Test with the default blocking, uncontrolled dialog and an optional in-scope category not restricted by policy or GPC. Open the dialog from the banner's Customize button or a preferences link. Confirm a centered card opens over a dimmed backdrop, background scroll locks, and Tab stays inside the card. Press Escape and confirm the dialog closes and focus returns to the trigger. Reopen it, enable a category, and click Save. Confirm the dialog closes and `useConsent('<category>')` returns `true`; under a choice prompt the banner stays closed, while a `notice` prompt stays visible until acknowledged. Reload the page and reopen the dialog to confirm the switch preserves the saved choice.
</section>
