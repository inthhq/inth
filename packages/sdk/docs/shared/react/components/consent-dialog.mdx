<section id="props">
  ## Props

  | Prop | Type | Default | Description |
  | --- | --- | --- | --- |
  | `open` | `boolean` | follows active surface | Controls the open state. `true` asks Inth to show the dialog; Close and Escape then close it, and `open` must turn `false` and back to `true` to ask again. `false` hides it. A missing policy or unlisted model still keeps it closed. |
  | `showTrigger` | `boolean \| ConsentDialogTriggerProps` | `false` | Renders a floating `ConsentDialogTrigger` next to the dialog. Pass an object to configure the trigger. |
  | `models` | `Model[]` | `['opt-in', 'opt-out', 'none']` | Policy models the dialog handles. Under an unlisted model such as `iab`, it stays closed. |
  | `legalLinks` | `(keyof LegalLinks)[] \| null` | shown | The footer shows the Cookie Policy under a choice regime and the Privacy Policy under an opt-out regime. `null` hides it; an array shows it only when its key is listed. |
  | `uiSource` | `string` | `'dialog'` | Source identifier recorded with saves made from this dialog. |
  | `scrollLock`, `trapFocus` | `boolean` | `true` | Apply to the opt-out and opt-in confirmations this dialog hosts. The dialog itself always blocks the page. |
  | `disableAnimation` | `boolean` | `false` | Skips enter and exit animations. |
  | `noStyle` | `boolean` | `false` | Removes built-in styling from every part. |
</section>

<section id="behavior">
  ## Behavior

  The dialog is the full consent manager: "Your Privacy Choices". It is centred on desktop and a bottom sheet on phones. Its content follows the policy regime:

  - **Choice regime** (opt-in, and opt-out rules that ask for a choice): one switch per category in scope, with its vendors, and Reject All, Accept All, and Save. Save stays disabled until a switch differs from the recorded choice.
  - **Opt-out regime** (opt-out rules with a notice): the sale-and-sharing row with Protect and Allow, the receipt of the recorded choice, a Preferences row for the category switches, and Done. Allowing again after an opt-out asks to confirm first (11 CCR §7028(a)).

  Without an `open` prop, the dialog follows the active surface and opens when it becomes `dialog`. These set that surface:

  - [`PrivacyChoicesLink`](./privacy-choices-link), `ConsentDialogLink`, and `ConsentDialogTrigger`.
  - The opt-out link on a notice when `presentation.optOutLink` is `'privacy-choices'` or `'california-privacy-choices'`.
  - The button inside a `ConsentGate` placeholder.
  - `useSetActiveUI()('dialog')` in your component, or `openDialog()` from `useHeadlessConsentUI()` on the headless subpath.

  The banner's Customize button does not open the dialog. It opens the choices inside the banner.

  Inth splits the dialog code into its own chunk so it stays out of the first page load. It renders nothing until the chunk loads, which starts at the first of these events:

  - The browser's first idle period after the page `load` event while the banner is visible or a `ConsentDialogLink`, `ConsentDialogTrigger`, `ConsentGate` button, or other opener is mounted. This covers visitors who tap or press Enter without hovering first. Browsers without `requestIdleCallback`, such as Safari, wait 200 ms after `load`.
  - Hover or focus on a button that opens the dialog.
  - The dialog opening.

  Passing `open={true}` or `showTrigger` loads the chunk on mount. A returning visit with saved consent and no opener on the page never downloads it.

  Inth skips idle loading when Save-Data is on (`navigator.connection.saveData`), on `2g` or `slow-2g` connections, and while offline; hover and focus still trigger the download. To load the chunk only on hover, focus, or open, set `preloadDialog: 'intent'` in the provider options. The default is `'idle'`. In Next.js, pass it through `InthProvider`'s `options` prop.

  If a preload fails while offline, nothing is cached and the next hover, focus, or open retries the download.

  The dialog CSS travels inside the same chunk and applies before the dialog renders, keeping the first page load limited to banner rules.

  The dialog CSS travels inside the same chunk and applies before the dialog renders, keeping the first page load limited to banner rules.

  Escape and Close close the dialog without saving. If the policy still owes a choice, the banner returns. Reject All, Accept All, and Save close the dialog as soon as the browser records the choice, in the same click task. The network request to Inth runs afterwards and never reopens the dialog: a failed request keeps the local choice, reports through `onError`, and retries later. See [when a choice is saved](/docs/concepts/consent-state#when-a-choice-is-saved). Clicking the backdrop does not close it. Closing discards unsaved switches, so the next open starts from the recorded choice.

  The dialog always blocks the page: backdrop, scroll lock, and focus trap.

  The dialog never opens without a resolved policy rule, even when the active surface is already `dialog`; it appears as soon as a rule resolves, without remounting. A rule with `model: 'none'` and no rights owes no consent UI, so the dialog stays closed. When a `none` rule lists a right, such as `rights: ['preferences']`, the dialog opens as a settings route, and closing it writes no consent record.

  Copy comes from the `privacyChoices` translation section and `consentTypes.<category>.title` and `.description` for each category.

  While Global Privacy Control is active under a policy that maps it, the signal-restricted categories stay off and their switches are disabled with the GPC note. Read the same state and receipt with `useOptOutState()`.
</section>

<section id="accessibility">
  ## Accessibility

  The dialog carries `role="dialog"`, `aria-modal="true"`, and `aria-labelledby` pointing at its title. Its `dir` attribute matches the active language. Opening moves focus inside the dialog, Tab and Shift+Tab wrap inside it, and closing returns focus to the element that opened it. Status messages, such as the saved cue, use a `role="status"` region.

  Each category switch uses the category title as its accessible name. The `necessary` switch is disabled and always on. On phones, the Preferences row and each category's vendor list open as a nested sheet with its own title and close button.
</section>

<section id="customize">
  ## Customize

  Style the dialog with [theme tokens](/docs/customization/tokens) and these provider component slots: `dialog.root`, `dialog.container`, `dialog.card`, `dialog.header`, `dialog.title`, `dialog.content`, `dialog.footer`, `dialog.sheet`, `dialog.categoryGroup`, `dialog.rightsRow`, `dialog.receipt`, `dialog.preferencesRow`, `dialog.saveButton`, `dialog.doneButton`, and `description.dialog`. `dialog.overlay` styles the backdrop, which is the dialog's root element.

  The root carries `data-regime` (`eu` or `us`) and `data-layout` (`desktop` or `phone`).

  `ConsentDialog` from the package root and `@inth/react/consent-dialog` is the deferred component described under Behavior. `@inth/react/components/consent-dialog` exports the dialog without deferral. Importing from that subpath puts the dialog code in the initial bundle so the first open needs no download, at the cost of shipping it to every visitor. For your own markup, use `ConsentWidget` or the headless hooks.
</section>

<section id="verify">
  ## Verify

  Test with an opt-in policy and an optional in-scope category not restricted by policy or GPC. Open the dialog from a `PrivacyChoicesLink`. Confirm a centred card opens over a dimmed backdrop, background scroll locks, and Tab stays inside the card. Press Escape and confirm the dialog closes and focus returns to the link. Reopen it, turn on a category, and click Save. Confirm the dialog closes and `useConsent('<category>')` returns `true`. Reload the page and reopen the dialog to confirm the switch keeps the saved choice.
</section>
