<section id="intro">
  `DevTools` is a floating panel for the Inth consent kernel. Use it in development to inspect consent values, scripts, location, the resolved policy, IAB state, events, and consent actions. The framework adapter reads the kernel from the nearest `InthProvider` and never discovers a store through a window global.

  <Callout type="warn">
    Load DevTools only in development. A conditional JSX check stops it from mounting in production, but a static import can still bundle it. Use a development-only dynamic import as shown below. The component renders nothing into the React tree and mounts its panel in `document.body`.
  </Callout>

  ## Installation

  You do not need an extra package. The framework package ships the panel and its engine.
</section>

<section id="customization">
  ## Configuration

  ```tsx
  <DevTools
    position="bottom-right"
    defaultOpen={false}
    defaultTab="consents"
    maxEvents={100}
    disabled={false}
  />
  ```

  `position` accepts `top-left`, `top-right`, `bottom-left`, or `bottom-right`. Set `defaultOpen` to open the panel initially and `defaultTab` to select the starting tab. `maxEvents` caps captured kernel and script events. Set `disabled` to prevent mounting without removing the component. The panel mounts inside a shadow root by default so page CSS does not affect it; pass `shadow={false}` to render it in the light DOM with its stylesheet in `<head>`.

  ## Open DevTools from the consent trigger

  While `ConsentDialogTriggerToolbar` or the built-in `ConsentDialogTrigger` is visible, the trigger displays a DevTools button and DevTools hides its own floating launcher so only one control sits in the corner. The button appears at the end of the toolbar farthest from its corner. The panel opens just past the toolbar, aligned with its outer edge, and follows it when a visitor drags the toolbar to another corner. `position` applies again once no trigger is visible.

  `ConsentDialogTrigger` renders as a two-button toolbar while DevTools is mounted. A trigger composed from `ConsentDialogTrigger.Root` keeps its own markup, and DevTools keeps its floating launcher beside it.

  DevTools restores its launcher whenever no trigger is visible, such as while `showWhen="after-prompt"` waits for a choice. A production build that loads DevTools only in development shows no DevTools button in the trigger.

  With the imperative engine, call `devTools.dock({ position, inline, block })` to hide the launcher and anchor the panel `inline` and `block` pixels from the viewport edges of `position`'s corner. Call `devTools.dock(null)` to restore the launcher.

  ## Panels

  Accept and reject apply only to categories displayed by the provider, leaving hidden consent values unchanged. `necessary` stays enabled. The React adapter uses the current policy categories by default.

  For an imperative integration with a narrower UI, pass `getConsentCategories: () => ['necessary', 'measurement']` to `createDevTools`. DevTools reads the getter again whenever an action runs. Headless UI actions can call `kernel.commands.save('all', { categories: displayed })` or `kernel.commands.save('none', { categories: displayed })`. Scoped bulk saves use a `custom` transport action when they cover only part of the policy, while actions covering the whole policy keep `all` or `necessary`. Without an explicit scope or policy categories, bulk saves cover all known categories.

  | Panel | What it shows |
  | --- | --- |
  | **Consents** | Inspect and save categories, accept all, or reject optional categories |
  | **Scripts** | Configured scripts, loading status, search, and external page resources |
  | **Location** | Resolved country and region, and location overrides |
  | **Policy** | Resolved policy and UI configuration |
  | **IAB** | Edit vendors, purposes, legitimate interests, and special features; save and copy TC strings |
  | **Events** | Timeline of consent changes, kernel events, and script lifecycle events |
  | **Actions** | Show the banner, open preferences, hide consent UI, or refresh consent data |

  ### Script inspection

  Set `defaultTab="scripts"` to open script inspection first. It reads all script loaders attached to the current provider's kernel, including loaders created before DevTools mounts. Search by script ID, category, URL, or status, then expand a script to inspect its configuration and latest lifecycle event.

  `loading` means an external script was inserted; `loaded` means its browser load event fired, or an inline script or callback-only integration mounted. `error` reports a loader error. `blocked` means consent requirements were not met, and `pending` means an eligible script has not mounted yet. `present` means the loader reused an existing element without a confirmed load result. `retained` means consent was revoked while `persistAfterConsentRevoked` kept the element. Retained scripts still receive `onConsentChange` with `hasConsent: false` so their integrations can send vendor revocation commands. `alwaysLoad` bypasses the loading gate, not consent: callbacks still receive the real consent state and updates across categories for integrations such as Google Consent Mode.

  Script details distinguish `allowedToLoad` from `consentGranted`. An `alwaysLoad` integration can be allowed to load while its consent is denied. Diagnostics expose these as `eligible` and `hasConsent`.

  Lifecycle diagnostics work even when legacy debug forwarding is disabled. The page scan lists external scripts and iframes present in the DOM; it does not prove that they loaded successfully or were consent-gated.

  For custom inspection tools, import `getScriptDiagnostics(kernel)` and `subscribeScriptDiagnostics(kernel, listener)` from `@inth/sdk/modules/script-loader`. The subscription reports loader registration, updates, disposal, and lifecycle events. Read a fresh snapshot after changes and call the returned unsubscribe function on cleanup.

  ### IAB editing

  Under an IAB policy, the Consents tab is read-only. Edit and save vendors and purposes in the IAB tab so derived categories and the TC string stay aligned.

  The IAB panel connects to the `@inth/sdk/iab` module attached to the provider's kernel. It does not create a second CMP or replace `__tcfapi`. Controls become available after initialization when the active policy uses IAB and the vendor list has loaded.

  Choose Vendors, Purposes, or Special features, then search by name or ID. Vendors include the provider's custom vendors. Long lists show 20 entries per page. Legitimate-interest controls appear for declared legitimate interests. Search filters the view only; Accept all IAB and Reject all IAB apply to all configured choices, including custom vendors.

  Toggles update live IAB state and script gating immediately. Use Save IAB consent to generate a fresh TC string and run the configured save transport. The panel shows the last generated string and excludes unsaved edits. Copy TC string confirms success or reports clipboard failures. Raw IAB data stays available in an expandable section.

  IAB saves normally write the TC string to its standard cookie and localStorage. For an in-memory playground, set `persistence: false` in the IAB module options alongside disabling the provider's core persistence. That option stops TC-string storage writes without disabling the save transport or deleting previously stored values.

  Save and refresh actions show pending, success, and failure feedback, disabling controls while a request is in flight. A failed save does not roll back live choices; retry to record them.

  For custom inspection tools, `@inth/sdk/engine` exports `getIABControls(kernel)` and `subscribeIABControls(kernel, listener)`. The getter returns `undefined` before module initialization and after disposal. A snapshot without an attached IAB module is read-only in DevTools.

  ## TanStack Devtools

  Each embedded panel owns its event history and subscriptions. Unmounting destroys the instance; remounting starts a fresh history. Keep the Inth panel mounted if you want to capture events while switching plugins.

  The React DevTools entry exports `InthTanStackDevtoolsPanel` and `inthDevtools` matching TanStack Devtools' plugin API:

  {/* example: fragment */}

  ```tsx
  import * as React from 'react';
  import { useRouter } from '@tanstack/react-router';
  import { TanStackDevtools } from '@tanstack/react-devtools';
  import { ReactQueryDevtoolsPanel } from '@tanstack/react-query-devtools';
  import { TanStackRouterDevtoolsPanel } from '@tanstack/react-router-devtools';
  import { inthDevtools } from '@inth/react/devtools';

  export function AppDevtools() {
    const router = useRouter();

    return (
      <TanStackDevtools
        plugins={[
          {
            name: 'TanStack Query',
            render: <ReactQueryDevtoolsPanel />,
          },
          {
            name: 'TanStack Router',
            render: <TanStackRouterDevtoolsPanel router={router} />,
          },
          inthDevtools(),
        ]}
      />
    );
  }
  ```

  In a Next.js app, import `inthDevtools` from `@inth/nextjs/devtools` instead.

  The Inth panel follows TanStack Devtools' light or dark theme instead of your app's consent theme. If you write the plugin entry yourself, pass the theme through a render function to `InthTanStackDevtoolsPanel`:

  {/* example: fragment */}

  ```tsx
  import { InthTanStackDevtoolsPanel } from '@inth/react/devtools';

  const inthPlugin = {
    name: 'Consent',
    render: (_element: HTMLElement, { theme }: { theme: 'light' | 'dark' }) => (
      <InthTanStackDevtoolsPanel theme={theme} />
    ),
  };
  ```

<section id="props">
  ## Props

  `DevTools`, `ConsentDevTools`, and `InthDevTools` all accept `ConsentDevToolsProps`:

  | Prop | Type | Default | Description |
  | --- | --- | --- | --- |
  | `disabled` | `boolean` | `false` | Prevents the DevTools engine from mounting. |
  | `position` | `'bottom-right' \| 'bottom-left' \| 'top-right' \| 'top-left'` | `'bottom-right'` | Corner placement for the floating launcher and panel. |
  | `defaultOpen` | `boolean` | `false` | Opens the panel initially on mount. |
  | `defaultTab` | `'consents' \| 'scripts' \| 'location' \| 'policy' \| 'iab' \| 'events' \| 'actions'` | `'consents'` | Initial panel tab shown when DevTools opens. |
  | `maxEvents` | `number` | `100` | Maximum number of captured kernel and script events. |
  | `shadow` | `boolean` | `true` | Mounts the panel inside a shadow root to isolate its styles from page CSS. |
  | `embedded` | `boolean` | `false` | Inherited from `DevToolsOptions`. Ignored by floating `DevTools`; use `InthTanStackDevtoolsPanel` or `createDevTools({ embedded: true })` to embed a panel. |
  | `getConsentCategories` | `() => readonly (keyof ConsentState)[]` | Provider policy categories | Returns the categories displayed by the provider for scoped accept and reject actions. |
  | `getPresentation` | `() => ConsentPresentation \| undefined` | Provider presentation | Returns host presentation settings for diagnostics. |
  | `clearRecords` | `() => void` | Provider persistence handler | Clears stored consent records through the host persistence handle. |
