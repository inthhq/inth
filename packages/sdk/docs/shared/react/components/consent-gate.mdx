<section id="props">
  ## Props

  | Prop | Type | Default | Description |
  | --- | --- | --- | --- |
  | `category` | `AllConsentNames` | required | The consent category whose effective permission gates the children, such as `'marketing'` or `'functionality'`. |
  | `children` | `ReactNode` | required | The embed. Stays unmounted until the category is allowed so it sends no requests before permission. |
  | `placeholder` | `ReactNode` | built-in placeholder | Replaces the built-in title and button while the category is denied. Falsy values (`null`, `false`, `0`, empty string) fall back to the built-in placeholder. Pass `<></>` to render nothing. |

  Other `div` attributes such as `className`, `style`, and `ref` apply to the wrapper element kept in both states. `ConsentGateProps` declares `noStyle` and `theme`, though the component does not apply them yet; style the wrapper with `className`, and style the built-in placeholder through its parts in the provider options.
</section>

<section id="behavior">
  ## Behavior

  `ConsentGate` renders a `div` wrapper. When effective permission for `category` is granted, it renders its children; otherwise it renders the placeholder. Permission matches `useConsent(category)`, so an opt-out rule can grant it before a visitor chooses, and a privacy signal can override a recorded grant.

  While permission is denied, the children stay out of the DOM so an iframe or third-party widget sends no requests. If the visitor later revokes consent, the children unmount and the embed disappears. `ConsentGate` does not rely on the network blocker or iframe blocker; use those only for markup you cannot wrap in a component.

  The built-in placeholder shows `consentGate.title`, `Accept {category} consent to view this content.`, with `{category}` replaced by `consentTypes.<category>.title`, and a button labelled `consentGate.actionButton`, `Enable {category} consent`. Clicking the button opens the preference center; it does not grant consent on its own because the visitor still has to save. Mount `ConsentDialog` in the same provider so the button has a dialog to open.

  Under a policy with `scopeMode: 'strict'`, a category outside the rule's scope cannot be granted. The built-in placeholder shows `consentGate.policyBlocked`, "This content is unavailable under your region's consent policy.", without a button, and any stored grant for that category stays blocked.

  When the provider starts from a server-resolved snapshot, the server renders the placeholder for a denied category and an empty wrapper for a granted category. Children mount after hydration finishes so an iframe loads once even inside a streamed `Suspense` boundary. A grant in the request cookie allows the embed only when policy and privacy signals permit it, and browser privacy signals detected during hydration can still revoke it. In a browser-only setup, `ConsentGate` renders the placeholder until policy resolves on the client, then swaps in the embed if granted.

  For complete vendor embed examples with sizing and accessible titles, see [YouTube](/docs/integrations/youtube) and [Google Maps](/docs/integrations/google-maps).
</section>

<section id="composition">
  ## Composition

  Use `ConsentGate.Root`, `ConsentGate.Title`, and `ConsentGate.Button` to build a custom placeholder that keeps the built-in copy and behavior. `ConsentGate.Title` and `ConsentGate.Button` accept `category` to fill in translated text, or children to replace it.

  ```tsx
  <ConsentGate
    category="marketing"
    placeholder={
      <ConsentGate.Root>
        <ConsentGate.Title category="marketing" />
        <p>The video is also available on our channel.</p>
        <ConsentGate.Button category="marketing">Choose cookies</ConsentGate.Button>
      </ConsentGate.Root>
    }
  >
    <iframe src="https://www.youtube-nocookie.com/embed/..." title="Product tour" />
  </ConsentGate>
  ```

  To restyle the built-in placeholder without replacing it, configure its parts under `components['consent-gate']` in the provider options: `root` targets the card, and `title` and `button` target its text and button. The `consentGate`, `consentGateTitle`, and `consentGateButton` theme slots target the same parts. The button part layers on top of `button.primary`.

  {/* example: fragment */}

  ```tsx
  components: {
    'consent-gate': {
      root: { className: 'rounded-none' },
      button: { className: 'font-semibold' },
    },
  },
  ```

  The built-in placeholder sets `data-testid="consent-gate-placeholder"`, its title sets `data-testid="consent-gate-title"`, and its button sets `data-testid="consent-gate-button"`.
</section>

<section id="accessibility">
  ## Accessibility

  The placeholder is plain text and a `button`, so it stays readable and keyboard-operable without the embed. Give the iframe a descriptive `title`, and keep a transcript, address, or direct link outside `ConsentGate` for visitors who decline the category. Policy rules can lock a category off, so opening the preference center does not guarantee the visitor can enable it.
</section>

<section id="verify">
  ## Verify

  Test with an optional in-scope category not restricted by policy or GPC. Load the page with the category denied: confirm the placeholder names the category and DevTools Network shows no requests to the embed host. With a server snapshot, confirm the server HTML contains the placeholder when denied and neither placeholder nor embed when granted, with one iframe document request after hydration. In a browser-only setup, the placeholder renders before policy resolves and swaps to the embed if granted. Click the placeholder button to open the preference center, enable the category, and click Save: the embed replaces the placeholder and loads. Revoke the category in the preference center and confirm the embed unmounts.
</section>
