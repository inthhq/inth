## What Inth adds to the page

Your Content Security Policy must allow each resource Inth or your vendors add to the page:

| Inth does | Directive | Allow |
| --- | --- | --- |
| Requests the policy from `/v1/consent/init` and saves choices to `/v1/consent/records` | `connect-src` | Your Inth project origin. `'self'` covers a same-origin route such as `/api/inth`. |
| Adds a `<script>` element for each allowed entry in `scripts` | `script-src` | Each vendor's script host, or the provider's `nonce`. |
| Lets vendor scripts load more scripts, pixels and requests | `script-src`, `img-src`, `connect-src` | The hosts each vendor documents. |
| Sets `src` on gated iframes, or mounts `ConsentGate` children | `frame-src` | Each embed's host, such as `https://www.youtube-nocookie.com`. |
| Adds its rules to `<head>` as `<style>` elements | `style-src` | The provider's `nonce`. With `styles={false}` and an imported `@inth/svelte/styles.css`, `'self'`. |
| Fetches the Global Vendor List under an IAB policy | `connect-src` | The vendor list host the policy names, when it is not your own origin. |

The dev tools panel attaches a stylesheet to its shadow root. Keep the panel out of production builds so your production policy does not need to allow it.

## Stamp a nonce on vendor scripts

If your server creates a nonce per response and sets it in `Content-Security-Policy` as `'nonce-<value>'`, pass the same value to the provider:

{/* example: fragment */}

```svelte
<!-- Svelte: src/App.svelte -->
<InthProvider mode={manifest()} {scripts} nonce={cspNonce}>

<!-- SvelteKit: src/routes/+layout.svelte -->
<InthProvider state={data.consent} {scripts} nonce={cspNonce}>
```

The script loader stamps that nonce on every `<script>` element it inserts, for both `src` and inline `textContent` scripts. A `nonce` on a single `scripts` entry overrides it for that script. The components also stamp it on the `<style>` elements they add. The provider reads `nonce` once when created.

The nonce covers only elements Inth creates. Scripts loaded dynamically by a vendor script do not receive it; allow that host in `script-src`, or add `'strict-dynamic'` so scripts loaded by a trusted script are trusted too. With `'strict-dynamic'`, browsers ignore host allowlists in `script-src`, so every script on the page needs a nonce or hash.

## Verify the policy

Enforce the policy (not report-only) and open the console with site data cleared:

1. The banner renders with its styles, and no `Refused to` message mentions an Inth element, a `<style data-inth-styles>` element, or `@inth/svelte/styles.css`. Open the preference dialog and check again.
2. Allow a category. Its vendor scripts load with no violations. A refused script from a vendor's host means that host is missing from `script-src`.
3. Save a choice. The request to `/v1/consent/records` succeeds; a `connect-src` violation means your Inth project origin is missing.
4. Allow the category of a gated embed. It loads; a `frame-src` violation names the host to add.
