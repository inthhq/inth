## How the dialog loads

`ConsentDialog` is not part of the first page load. The component you render
is a small loader; the dialog itself is a separate chunk that it imports:

- In browser idle time after the page's `load` event, while the banner shows
  or a button that opens the dialog is mounted. Those buttons are
  `PrivacyChoicesLink`, `ConsentDialogLink`, `ConsentDialogTrigger`, the
  `ConsentGate` placeholder and `ConsentButton` with
  `action="open-consent-dialog"`.
- When such a button is hovered or focused.
- At the latest, when the dialog opens.

Set the provider's `preloadDialog` to `'intent'` to skip the idle load and
load only on hover, focus or open. Idle loading is also skipped when the
browser asks to save data, on 2G connections and offline. Every
`ConsentDialog` on the page shares one import. If the import fails, the
surface the dialog replaced comes back, and the next hover, focus or open
retries. The dialog's CSS travels with that chunk and goes into `<head>`
before the dialog renders. With `styles={false}`, it comes from your imported
`@inth/svelte/styles.css`.

## Props

| Prop | Type | Default | Behavior |
| --- | --- | --- | --- |
| `open` | `boolean` | follows the consent state | `true` asks Inth to show the dialog; Close and Escape then close it, and `open` must turn `false` and back to `true` to ask again. `false` hides it. |
| `showTrigger` | `boolean` or trigger props | `false` | Renders a floating `ConsentDialogTrigger` with the dialog. Pass an object for `defaultPosition`, `persistPosition`, `showWhen`, `size`, `ariaLabel`, `noStyle` and `class`. |
| `legalLinks` | array of `LegalLinks` keys, or `null` | shown | The footer shows the Cookie Policy under a choice regime and the Privacy Policy under an opt-out regime. `null` hides it; an array shows it only when its key is listed. |
| `models` | `Model[]` | every model | Policy models the dialog opens for. |
| `scrollLock`, `trapFocus` | `boolean` | provider's value, else `true` | Apply to the opt-in confirmation this dialog hosts. The dialog itself always blocks the page. |
| `noStyle` | `boolean` | provider's `noStyle` | Drops Inth's classes. |
| `disableAnimation` | `boolean` | provider's value | Opens and closes without a transition. |

`ConsentDialog` has no text props. Its copy comes from the `privacyChoices`
translations and each category's `consentTypes` title and description; see
[translations](../translations).

The trigger from `showTrigger` loads in a chunk of its own and appears right
after hydration. To keep a trigger in server HTML, render
`ConsentDialogTrigger` next to the dialog instead.

## What the dialog contains

The dialog is the full consent manager, "Your Privacy Choices". It is centred
on desktop and a bottom sheet on phones. Its content follows the policy
regime:

- **Choice regime** (opt-in, and opt-out rules that ask for a choice): one
  switch per category in scope, with its vendors, and Reject All, Accept All
  and Save. Save stays disabled until a switch differs from the recorded
  choice.
- **Opt-out regime** (opt-out rules with a notice): the sale-and-sharing row
  with Protect and Allow, the receipt of the recorded choice, a Preferences
  row for the category switches, and Done. Allowing again after an opt-out
  asks to confirm first (11 CCR §7028(a)).

Categories come from the provider's `consentCategories`, limited to the
policy's scope. `necessary` is always on and shows no switch.

An opt-out recorded elsewhere, from a one-click opt-out link or after a
revocation reload, opens the dialog on its receipt. A standalone
`OptOutConfirmation` you render still shows it itself.

While Global Privacy Control is active under a policy that maps it, the
signal-restricted categories stay off and their switches are disabled with
the GPC note. Read the same state and receipt from
`getConsentManager().optOutState`.

## Open and close the dialog

Anything that sets the active surface to `'dialog'` opens it:
`PrivacyChoicesLink`, `ConsentDialogLink`, `ConsentDialogTrigger`, the
button inside a `ConsentGate` placeholder,
`getConsentManager().setActiveUI('dialog')` or
`getHeadlessConsent().openDialog()`. The banner's Customize button does not
open the dialog: it opens the choices inside the banner.

Escape and Close close the dialog without saving. If the policy still owes a
choice, the banner comes back. Reject All, Accept All and Save close the
dialog as soon as the browser records the choice, in the same click task. The
network request runs afterwards and never reopens the dialog. Clicking the
backdrop does not close it. Closing discards unsaved switches, so the next
open starts from the recorded choice.

The dialog never opens without a resolved policy rule. A rule with
`model: 'none'` and no rights owes no consent UI, so the dialog stays closed.
When a `none` rule lists a right, such as `rights: ['preferences']`, the
dialog opens as a settings route.

## Accessibility

- The dialog carries `role="dialog"`, `aria-modal="true"` and
  `aria-labelledby` pointing at its title.
- Opening moves focus inside the dialog, Tab and Shift+Tab wrap inside it,
  and closing returns focus to the element that opened it. The page behind
  is inert and does not scroll.
- Each category switch uses the category title as its accessible name. On
  phones, the Preferences row and each category's vendor list open as a
  nested sheet with its own title and close button.
- Status messages, such as the saved cue, use a `role="status"` region.
- The root sets `dir` from the active language.

## Style the dialog

`ConsentDialog` reads these theme slots: `consentDialog` (the root, which is
also the backdrop), `consentDialogOverlay` (the same element),
`consentDialogCard`, `consentDialogHeader`, `consentDialogTitle`,
`consentDialogDescription` (the intro), `consentDialogContent`, `consentDialogFooter`,
`consentDialogSheet`, `consentDialogCategoryGroup`, `consentDialogVendorTable`,
`consentDialogPreferencesRow` and `consentDialogSaveButton`.

The root carries `data-testid="consent-dialog-root"`, `data-regime` (`eu` or
`us`) and `data-layout` (`desktop` or `phone`).

`ConsentDialog` from the package root is the deferred component described
above. `ConsentDialogPanel` from `@inth/svelte/dialog-panel` is the dialog
without deferral, for a surface that is itself loaded on demand.
