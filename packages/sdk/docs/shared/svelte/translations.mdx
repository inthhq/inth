## Where the copy comes from

The banner, dialog, widget, gate placeholder, and IAB surfaces read their text from one set of translations for the visitor's language. The source depends on the provider's `mode`:

| Mode | Copy comes from | Languages |
| --- | --- | --- |
| `hosted()` | Inth's `/v1/consent/init` response in the requested language, with the provider's `i18n` messages for that language on top | Every language Inth bundles: ar, bg, bn, cs, cy, da, de, el, en, es, et, fi, fr, ga, gu, he, hi, hr, ht, hu, id, is, it, ja, kn, ko, lb, lt, lv, ml, mr, ms, mt, nb, nl, nn, pa, pl, pt, rm, ro, ru, sk, sl, sv, ta, te, th, tr, ur, vi, yi, and zh |
| `manifest()` | The manifest's translations over the base copy for the visitor's language, with the provider's `i18n` messages on top (resolved on the server in SvelteKit, in the browser in Svelte) | English base copy is bundled; another language's base copy loads the first time a visitor needs it |
| `testing()` | The provider's `i18n` prop, merged over bundled English | English, plus any language you supply in full |

The browser bundle carries English only. Other languages arrive from Inth or from messages you pass.

## Change the copy for one banner

`ConsentBanner` accepts `title`, `description`, `acceptButtonText`, `rejectButtonText`, `customizeButtonText`, and `dismissButtonText`. These props override copy in every mode:

{/* example: fragment */}

```svelte
<ConsentBanner
	title="Cookies on this site"
	rejectButtonText="Reject optional"
/>
```

These props replace text in every language, so pass strings in the page's language or compute them from your own i18n library.

## Change the copy site-wide

Pass `i18n` to the provider. `messages` holds partial translations per language; keys you omit keep Inth's copy:

<include src="../examples/storybook-svelte/consent-i18n.mdx" />

`locale` selects the starting language (`en` by default).

In `hosted()` mode, Inth's copy for the visitor's language is the base, and your `i18n` messages for that language replace it key by key. Keys you omit keep the copy from your Inth project. The same applies to copy SvelteKit's `loadConsent` resolves on the server. Inth picks messages for the exact language first, then for its primary language, so `de-AT` falls back to your `de` messages when no `de-AT` entry exists. Messages for other languages are ignored.

A key overrides Inth's copy only when your text differs from the built-in wording for that language. Passing stock bundles from `@inth/svelte/translations/all` to enable languages keeps Inth dashboard edits visible, while any key you reworded stays pinned in code. Core bundles only English; for other languages, import `@inth/svelte/translations/all` so Inth recognizes its stock wording.

In `testing()` mode, `i18n` is the only source of copy and applies from the first render.

## Common message keys

| Key | Where it shows |
| --- | --- |
| `cookieBanner.title`, `cookieBanner.description` | Choice banner heading and body. |
| `cookieBanner.noticeTitle`, `cookieBanner.noticeDescription` | Notice banner heading and body. |
| `common.acceptAll`, `common.rejectAll`, `common.customize`, `common.save` | Banner and dialog buttons. |
| `common.acknowledge` | The notice's dismiss button. |
| `common.securedBy` | The "Consent by" tag. |
| `consentManagerDialog.title`, `consentManagerDialog.description` | Preference dialog heading and body. |
| `consentTypes.<category>.title`, `consentTypes.<category>.description` | A category's name and description, such as `consentTypes.measurement.title`. |
| `consentGate.title`, `consentGate.actionButton` | The `ConsentGate` placeholder. `{category}` is replaced by the category title. |

[Copy and translations](/docs/customization/translations) covers wording for each action and testing long labels.

## Switch the language

`getConsentManager().setLanguage(code)` switches the language and resolves the policy again, so Inth returns copy in the new language and your `i18n` messages for that language apply on top. Call it from your language switcher's event handler. Otherwise, the visitor's language comes from the `Accept-Language` header or `overrides.language` on the provider.

The root of the banner, dialog, and widget sets `dir` from the active language, so right-to-left languages such as Hebrew lay out properly.

## Verify the copy

Open the page with the browser language set to each language you support. Confirm the banner, the dialog's category names, and the gate placeholder use that language. Narrow the window and zoom to 200% to verify long labels wrap without clipping.
