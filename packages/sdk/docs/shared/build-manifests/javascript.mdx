Add `consentManifest` from `@inth/sdk/build` to your Vite plugins:

{/* example: fragment */}

```ts title="vite.config.ts (plugins option)"
import { consentManifest } from '@inth/sdk/build';

export default {
	plugins: [
		// Keep your existing framework plugins here.
		consentManifest({ projectUrl: 'https://your-project.inth.app' }),
	],
};
```

Without `projectUrl`, the plugin reads `VITE_INTH_PROJECT_URL` (falling back to `VITE_C15T_BACKEND_URL` if unset). The plugin
fetches the policy during `vite build`, or in `vite dev` when the app first
loads it, and serves it as `snapshot` from `@inth/sdk/generated`. A build fetches
only when the app uses `manifest()`. In your browser entry point, pass
`manifest()` as the mode of the existing `init()` call. It reads the snapshot
and project URL from `@inth/sdk/generated`:

{/* example: fragment */}

```ts title="src/main.ts"
import { init, manifest } from '@inth/sdk';

init({ mode: manifest() });
```

Keep your scripts and UI options. The browser resolves the snapshot without
a manifest request when the policy does not need geography, or the required
country and region are known through `overrides`. When required
geography is missing, it calls Inth `/v1/consent/init` and uses the resolved
policy and translations. Those visitors wait for a network round trip
and can receive a newer policy than the build snapshot.

When the build has no snapshot, as in `vite dev` after a failed fetch,
`snapshot` is `undefined`, and the browser fetches
`${projectUrl}/v1/consent/manifest` instead.

A script-tag site without a build step cannot run this hook.

For policy updates without a rebuild, use `hosted()`, which calls Inth's
`/v1/consent/init` on each page load, or `manifest({ source: 'runtime' })`, which fetches
the manifest at runtime. Both keep reading the project URL from the plugin.
