The default mode, `manifest()`, bundles the manifest. The module reads
`NUXT_PUBLIC_INTH_PROJECT_URL` (falling back to `NUXT_PUBLIC_C15T_BACKEND_URL`
if unset) when the `inth` key sets no `projectUrl`, so `nuxt.config.ts` only
needs the module:

<include src="../examples/nuxt/nuxt-config.mdx" />

The module fetches the snapshot during `nuxt build` and when `nuxt dev`
starts, and embeds it in the server bundle. `nuxt prepare` skips the fetch, so
dependency installation and type generation work offline. The consent route and
server render read the snapshot, keeping it out of runtime config and the
browser bundle. Only `manifest({ resolve: 'browser' })` adds the snapshot to
the browser bundle, because the browser resolves the policy itself. Starting
the production server does not fetch another manifest.

The module skips the fetch for `manifest({ source: 'runtime' })`, a
`manifest({ snapshot })` you supply, and the `hosted()` and `testing()`
modes. It also skips a relative project URL unless `onBuildError` is `'fail'`.

<include src="../build-time-manifest-notes.mdx" />

Set `onBuildError` under the `inth` key in `nuxt.config.ts`. By default, a
failed fetch logs a warning and leaves the server without a snapshot, so the
server fetches and caches the policy at runtime. Set `onBuildError: 'fail'` or
`INTH_ON_BUILD_ERROR=fail` to stop the build instead.

For policy updates without a rebuild, set
`mode: manifest({ source: 'runtime' })`. The server then fetches and caches
the policy at runtime and refreshes it in the background.
