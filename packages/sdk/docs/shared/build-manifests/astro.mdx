`manifest()`, the default mode, bundles the manifest. The integration fetches it when `astro build` or `astro dev` starts and embeds it in its generated server options. Both the middleware and the consent route read that snapshot. The browser options omit it; only `manifest({ resolve: 'browser' })` serves it to the browser, as the prerendered `/api/inth/v1/consent/manifest`. No generated file or extra import is needed. `astro check` and `astro sync` skip the fetch, so type checks pass offline. `astro preview` serves the completed build and never fetches a new snapshot.

The build fetches only from an absolute project URL or `manifestUrl`, because it cannot fetch a route inside the app it is still compiling. Without a `projectUrl` option, `inth()` reads `PUBLIC_INTH_PROJECT_URL` (falling back to `PUBLIC_C15T_BACKEND_URL` if unset). With a relative URL, `manifest({ source: 'runtime' })`, `manifest({ snapshot })`, `hosted()`, or `testing()`, the integration skips the fetch. By default, if the fetch fails, `astro build` and `astro dev` log a warning, and the server fetches and caches the policy at runtime. The config is read once at build time, so the built server keeps the project URL and snapshot it was built with.

To stop builds when the snapshot cannot be fetched, set `onBuildError: 'fail'`, or build with `INTH_ON_BUILD_ERROR=fail`:

{/* example: fragment */}

```js title="astro.config.mjs"
inth({ onBuildError: 'fail' });
```

`onBuildError: 'fail'` stops `astro dev` too, and stops the build on a relative URL.
