Wrap your Next.js config in `withConsentManifest`. Pass an existing config
object or function as the first argument, unchanged:

<include src="../examples/nextjs/next-config.mdx" />

`next build`, `next dev` and `next typegen` download `${projectUrl}/v1/consent/manifest`
into `node_modules/.cache/inth/`, outside your source tree, so nothing needs to
go in `.gitignore`. `next start` serves that bundled snapshot with no policy
fetch. Without a `projectUrl` option, the build reads `projectUrl` from
`inth.config.ts`, then `NEXT_PUBLIC_INTH_PROJECT_URL` (falling back to
`NEXT_PUBLIC_C15T_BACKEND_URL` if unset).

The wrapper reads `inth.config.ts` (or `.mts`, `.js`, `.mjs`) at the project
root, next to `next.config.ts`, and aliases `@inth/nextjs/generated` to the
cache in Turbopack and webpack. `InthProvider`, `resolveConsent` and the consent
route read both automatically. Server code can import `snapshot` directly from
`@inth/nextjs/generated`, while importing it in a Client Component fails the
build via `server-only`. The wrapper also adds `@inth/sdk` and `@inth/nextjs`
to `transpilePackages` so Pages Router server bundles apply the aliases;
packages listed in `serverExternalPackages` stay external and fetch policy at
runtime.

`withConsentManifest` skips the fetch for `mode: hosted()`, `mode: testing()`,
`manifest({ snapshot })`, `manifest({ source: 'runtime' })`, relative URLs and
`output: 'export'`. If `inth.config.ts` fails to load at build time, for
example because of a non-Node import, the build warns and fetches as for
`manifest()`.

If the fetch fails or no project URL is set, `next build` and `next dev` log a
warning and leave `snapshot` as `undefined`, so the server falls back to
[runtime manifest caching](/docs/frameworks/next/optimization#reuse-cached-policy-data).
To stop the build on a failed fetch, missing URL or relative URL instead, set
`onBuildError: 'fail'` or `INTH_ON_BUILD_ERROR=fail`:

{/* example: fragment */}

```ts title="next.config.ts"
export default withConsentManifest(nextConfig, { onBuildError: 'fail' });
```
