## Register scripts in inth.config.ts

Add vendor helpers to `scripts` in `inth.config.ts`, next to `next.config.ts`.
This example holds PostHog back until `measurement` consent is granted. Replace
`phc_your_project_key` with your key or another
[integration](/docs/integrations/overview):

<include src="./examples/nextjs/quickstart-config.mdx" />

Keep `cookieless_mode: 'never'` so PostHog does not switch to cookieless
capture after a rejection, and remove any other PostHog loader from
`next/script` or a tag manager.

`withConsentManifest` finds `inth.config.ts` automatically and `InthProvider`
reads its `scripts` in the browser, so your Server Component layout passes only
`state`. The browser bundle includes this file, so keep secrets out of it.

You can also pass `scripts`, `vendors`, `clearOnRevocation`, `networkBlocker`,
`persistence`, `scriptLoader` and `options` directly as props on `InthProvider`,
where props override the config. Because functions cannot cross from a Server
Component to a Client Component, pass function props only from a `'use client'`
file.
