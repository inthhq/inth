---
title: Check a consent-gated vendor helper
description: Browser verification steps and revocation behavior for Inth vendor helpers that wait for consent.
group: integrations
---

Test in a private window with an opt-in policy. Open DevTools Network, disable the cache, and filter by the vendor's domain:

1. Load the page. No request goes to the vendor before you make a choice.
2. Click Reject, then reload. Still no request goes to the vendor.
3. Open Privacy settings and allow the helper's category. The vendor script loads without a page reload.
4. Turn the category off again and save. Inth reloads the page, and the reloaded page makes no vendor request.

Inth reloads on revocation because removing a `<script>` element does not stop code that already ran. Listeners, timers, and queued events stay active until the page unloads. If you set `reloadOnConsentRevoked: false`, stop the vendor yourself by registering a callback-only script whose `onConsentChange` calls the vendor's opt-out API, as shown in [custom integrations](/docs/integrations/building-integrations), and checking permission before your own event calls.

Reloading does not delete cookies the vendor already wrote. Configure cookie cleanup with [clear on revocation for your framework](/docs/integrations/overview#vendor-switches-and-cookie-cleanup).

The helper lists its vendor in the preference dialog so visitors can switch it off inside an allowed category. See [vendor consent for your framework](/docs/integrations/overview#vendor-switches-and-cookie-cleanup). For navigation and expiry checks, see [consent verification](/docs/guides/verify-consent).
