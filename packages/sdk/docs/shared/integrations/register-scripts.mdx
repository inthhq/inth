## Register the scripts

<section id="registration">
  Complete your [framework quickstart](/docs/frameworks) first, and remove the vendor's original snippet, SDK initializer, or tag manager entry so the vendor loads only through Inth.

  The vendor guides put helpers in `src/consent-scripts.ts`. If your quickstart already defines a `scripts` array, add the helper to that array instead. Pass `scripts` to your existing Inth provider below rather than mounting a second provider.

  <Tabs items={['Next.js', 'TanStack Start', 'React', 'Nuxt', 'Vue', 'Astro', 'Svelte', 'SvelteKit', 'Angular', 'HTML', 'JavaScript']}>
    <Tab value="Next.js">
      Add `scripts` to `inth.config.ts`, next to `next.config.ts`:

      {/* example: fragment */}

      ```ts title="inth.config.ts"
      import { defineConsentConfig } from '@inth/nextjs';
      import { scripts } from './src/consent-scripts';

      export default defineConsentConfig({ scripts });
      ```

      Keep your existing options, such as `mode` and `routePrefix`, in the same call. `InthProvider` reads this file in the browser for App Router, Pages Router, and static export, so your layout keeps passing only `state`. See [Next.js scripts and embeds](/docs/frameworks/next/scripts).
    </Tab>

    <Tab value="TanStack Start">
      Import `scripts` in your root route and pass them as a top-level prop on your existing `InthProvider`. Keep the loader from the [TanStack Start quickstart](/docs/frameworks/tanstack-start/quickstart):

      ```tsx title="src/routes/__root.tsx"
      import { scripts } from '../consent-scripts';

      <InthProvider state={consent} scripts={scripts}>
      ```

      Import vendor helpers in the root route module, not in a server function, because script configurations carry callbacks that cannot be serialized. See [TanStack Start scripts](/docs/frameworks/tanstack-start/scripts).
    </Tab>

    <Tab value="React">
      Pass `scripts` alongside `mode` in your existing `InthProvider` options:

      ```tsx title="src/consent.tsx"
      import { scripts } from './consent-scripts';

      <InthProvider options={{ mode, scripts }}>
      ```

      `mode` is the `manifest()` value from the [React quickstart](/docs/frameworks/react/quickstart). Keep your banner, dialog, and preferences link inside the provider. See [React scripts and embeds](/docs/frameworks/react/scripts).
    </Tab>

    <Tab value="Nuxt">
      Register `scripts` under `inth` in `app/app.config.ts`. Adjust the import path to match where you created `consent-scripts.ts`:

      ```ts title="app/app.config.ts"
      import { scripts } from '../src/consent-scripts';

      export default defineAppConfig({
        inth: { scripts },
      });
      ```

      The Nuxt module merges this over `nuxt.config.ts` and starts one script loader in the browser after hydration. Keep `scripts` out of `nuxt.config.ts`, which serializes to JSON and strips vendor callbacks. See [Nuxt scripts and embeds](/docs/frameworks/nuxt/scripts).
    </Tab>

    <Tab value="Vue">
      Pass `scripts` to your existing `inth` plugin registration in `src/main.ts`:

      {/* example: fragment */}

      ```ts title="src/main.ts"
      import { inth, manifest } from '@inth/vue/vue-plugin';
      import { scripts } from './consent-scripts';

      app.use(inth, {
        mode: manifest(),
        scripts,
      });
      ```

      Keep your existing `mode` and other options. The plugin owns the script loader, so do not call `createScriptLoader` from a component. See [Vue scripts and embeds](/docs/frameworks/vue/scripts).
    </Tab>

    <Tab value="Astro">
      Export `scripts` from the client entrypoint `src/inth.client.ts` created in the [Astro quickstart](/docs/frameworks/astro/quickstart). If it already exports scripts, merge the arrays. Leave `astro.config.mjs` unchanged.

      {/* example: fragment */}

      ```ts title="src/inth.client.ts"
      import type { InthClientOptionsExtension } from '@inth/astro';
      import { scripts } from './consent-scripts';

      export default { scripts } satisfies InthClientOptionsExtension;
      ```

      Do not place vendor helpers in `astro.config.mjs`, which serializes options into the page and drops callbacks. The integration attaches this client entrypoint to the shared runtime across pages and `ClientRouter` navigation.
    </Tab>

    <Tab value="Svelte">
      Import `scripts` in the component that renders your existing provider and pass them as a top-level prop:

      {/* example: fragment */}

      ```svelte title="src/app.svelte"
      <script lang="ts">
        import { InthProvider, manifest } from '@inth/svelte';
        import { scripts } from './consent-scripts';
      </script>

      <InthProvider mode={manifest()} {scripts}>
        <!-- Keep your application, consent UI and preferences link here. -->
      </InthProvider>
      ```

      Keep the styles and consent UI from the [Svelte quickstart](/docs/frameworks/svelte/quickstart). The provider owns and disposes the script loader.
    </Tab>

    <Tab value="SvelteKit">
      Pass `scripts` to your existing `InthProvider` in the root layout. Keep the handle and layout load from the [SvelteKit quickstart](/docs/frameworks/sveltekit/quickstart):

      {/* example: fragment */}

      ```svelte title="src/routes/+layout.svelte"
      <script lang="ts">
        import { InthProvider } from '@inth/svelte/kit';
        import { scripts } from '../consent-scripts';

        let { children, data } = $props();
      </script>

      <InthProvider state={data.consent} {scripts}>
        {@render children()}
        <!-- Keep your consent UI and preferences link here. -->
      </InthProvider>
      ```

      Import vendor helpers in the layout component, not in `+layout.server.ts`, because server load functions cannot return callbacks. Prerendered, static, and SPA pages use the same `scripts` prop. If you pass an external `runtime`, register `scripts` when creating that runtime instead.
    </Tab>

    <Tab value="Angular">
      Pass `scripts` to your existing `provideInth()` call in `src/app/app.config.ts`, next to `mode`:

      <include src="../examples/angular/integration-register.mdx" />

      Keep your mode, styles, and consent UI from the [Angular quickstart](/docs/frameworks/angular/quickstart). Keep `provideInth()` in `app.config.ts`, which the server config merges, rather than in a server-only file. See [Angular scripts](/docs/frameworks/angular/scripts).
    </Tab>

    <Tab value="HTML">
      `@inth/integrations` helpers are ES modules that require a bundler. On a plain HTML page using the Inth script tag, paste the vendor's snippet inside an inert `<script type="text/plain">` element:

      ```html
      <script type="text/plain" data-inth-category="measurement">
        // The vendor's snippet, unchanged
      </script>
      ```

      Use the category listed for the vendor on this page. Inth runs the snippet once that category is allowed and reloads the page on withdrawal. Helper options such as `loadMode` do not apply to pasted snippets. See [HTML scripts](/docs/frameworks/html/scripts).
    </Tab>

    <Tab value="JavaScript">
      Pass `scripts` to `init()` from `@inth/sdk`, alongside `mode`:

      {/* example: fragment */}

      ```ts
      import { init, manifest } from '@inth/sdk';
      import { scripts } from './consent-scripts';

      const consent = init({
        mode: manifest(),
        scripts,
      });
      ```

      With `createConsentRuntime` from `@inth/sdk/runtime`, pass `scripts` there instead. If you construct a kernel manually, attach one loader from `@inth/sdk/modules/script-loader`. See [JavaScript scripts](/docs/frameworks/javascript/scripts).
    </Tab>
  </Tabs>
</section>
