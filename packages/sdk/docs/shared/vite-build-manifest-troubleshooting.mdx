## Why does the build fail to download the manifest?

**Check.** By default (`onBuildError: 'runtime'`), both `vite build` and `vite dev`
log a warning from `consentManifest` and continue with `snapshot` set to
`undefined`, so the browser fetches the policy at runtime. With
`onBuildError: 'fail'` or `INTH_ON_BUILD_ERROR=fail`, `vite build` stops with an
error that starts with the plugin's name, such as
`@inth/sdk/build: could not fetch the consent manifest from <url> during the
build`. The name is `@inth/sdk/build` for `@inth/react/build` and
`@inth/sdk/build`, and `@inth/vue/vite` for `@inth/vue/vite`. The part in parentheses names the cause:

| Message | Cause | Fix |
| --- | --- | --- |
| `fetch failed`, with `ENOTFOUND`, `ECONNREFUSED` or another network error | The build cannot reach Inth | Build where your Inth project URL is reachable |
| `no response within 10 seconds` | Inth did not answer in time | Check network connectivity or build where the URL is reachable |
| `/v1/consent/manifest responded 404` | The URL is not your project's URL, such as the `https://your-project.inth.app` placeholder or a URL missing its path prefix | Copy the project URL exactly as Inth shows it, or set `VITE_INTH_PROJECT_URL` |
| `/v1/consent/manifest returned an invalid consent manifest.` | The URL answered with something other than a consent manifest, such as an HTML page | Point `projectUrl` at your Inth project URL, not your site or a dashboard page |

A failed download never reuses an old snapshot. To deploy while Inth
is unreachable when `onBuildError: 'fail'` is set, override it with
`INTH_ON_BUILD_ERROR=runtime`. `snapshot` is then `undefined`, and the browser
fetches the policy at runtime.

Only a build that uses `manifest()` downloads the manifest. The plugin
fetches after Vite has dropped the code the app does not use, so a `hosted()`
or `testing()` build never contacts Inth and never fails this way.

An error or warning that says `no backend URL is set` means the plugin found
no `projectUrl` option and no environment variable. Set `VITE_INTH_PROJECT_URL`
(falling back to `VITE_C15T_BACKEND_URL` if unset) in `.env` or the build
environment, or pass the absolute URL from your Inth project. The
[troubleshooting guide](/docs/guides/troubleshooting#why-does-the-build-fail-to-download-the-manifest)
lists every message.

A notice that the build `skipped the consent manifest fetch` means the project
URL is relative, such as `/api/inth`. Pass the absolute project URL instead.
With `onBuildError: 'fail'`, this stops the build with `build-time manifests
require an absolute upstream URL`.

## Why is snapshot undefined?

**Check.** `snapshot` from the `generated` entry, such as
`@inth/react/generated`, is `undefined`, and the browser
requests `${projectUrl}/v1/consent/manifest` on page load.

**Fix.** `snapshot` is `undefined` when Vite has no policy to serve:

- `consentManifest` is missing from `plugins` in `vite.config.ts`. Without the
  plugin, the `generated` entry still resolves, but exports `undefined`.
- The fetch failed during `vite build` or `vite dev` under the default
  `'runtime'` mode or `INTH_ON_BUILD_ERROR=runtime`. The terminal shows a
  `could not fetch the consent manifest` warning.
- The project URL is relative, so the plugin skipped the fetch.
- `consentManifest({ source: 'runtime' })` is set, so the plugin never
  fetches.

Fix the cause, then restart `vite dev` or rebuild. The plugin fetches once
when Vite starts.
