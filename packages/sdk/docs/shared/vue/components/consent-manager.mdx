<section id="behavior">
  ## What ConsentManager renders

  `ConsentManager` is the preference dialog (equivalent to `ConsentDialog` in
  React). It opens while `activeUI` is `'manager'`, triggered by the banner's
  Customize button, `ConsentDialogLink`, `ConsentDialogTrigger`, or your own
  code. It renders nothing until the visitor's policy resolves or when the
  policy requires no consent UI.

  The dialog renders the same controls as `ConsentWidget`: each category the
  policy offers with a switch, description, and declared vendors, plus a
  footer with Reject All, Accept All, and Save Settings (primary). Necessary
  stays on.

  - Save records the current switches. Accept All and Reject All record a
    choice for every unlocked category in the policy.
  - When a durable opt-out is held, the widget inside the dialog shows a status
    line (`role="status"`) above the category list and keeps opted-out
    categories off. While Global Privacy Control is active under a policy that
    maps it, those switches stay off and disabled with the GPC notice below
    each row, and Save Settings and Accept All skip locked categories. When an
    account holds the opt-out and GPC is off, the account notice appears below
    each row and the switches stay usable. Read the same state with
    `useOptOutState()`.
  - After a save, the dialog closes. The banner reappears only if the policy
    still requires a choice.
  - Pressing Escape closes the dialog without saving. The banner reappears if
    the policy still requires a choice.
  - If the policy changes while the dialog is open, the dialog shows "Privacy
    choices have changed." with a button to reload the switches, and blocks
    Save until reviewed.

  The title comes from `consentManagerDialog.title` in your Inth translations.
  `dialogLegalLinks` selects which `legalLinks` appear under the description.
  The dialog takes no props, slots, or text props.
</section>

<section id="accessibility">
  ## Accessibility and focus

  The dialog renders in `document.body` with `role="dialog"`, labeled by its
  title and described by its description. By default it is modal: it shows a
  backdrop, sets `aria-modal="true"`, locks scrolling, moves focus to the
  first control inside, and traps Tab. When closed, focus returns to the
  triggering element. Set `presentation.preferences.blocking` to `false` for a
  non-modal dialog without a backdrop.

  Each category switch is a `button` with `role="switch"`, `aria-checked`, and
  the category title as its label. Each row expands with a button setting
  `aria-expanded` and `aria-controls`.
</section>

<section id="styling">
  ## Style the dialog

  `components.dialog` binds attributes to `root`, `overlay`, `container`,
  `card`, `header`, `title`, and `content`. The category list inside uses
  `components.manager`, `components.accordion`, `components['accordion-item']`,
  `components.switch`, and `components['vendor-list']`. See
  [component parts](/docs/customization/slots). `presentation.preferences`
  configures footer `layout`, `primaryActions`, `direction`, `uiProfile`, and
  `blocking`.

  `dialogHideBranding`, or `hideBranding` for every surface, hides the
  "Secured by" tag. `disableAnimation` turns off transitions.
</section>

<section id="verify">
  ## Verify

  Open preferences, toggle one optional category on, and click Save Settings.
  Reload and reopen preferences to confirm the switch stays on. Press Escape
  while open and confirm the dialog closes and returns focus to the button
  that opened it.
</section>
