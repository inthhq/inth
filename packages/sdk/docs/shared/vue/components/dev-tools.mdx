<section id="behavior">
  ## What ConsentDevTools renders

  `ConsentDevTools` mounts a floating inspection panel in `document.body` for
  your app's consent runtime. Render it inside the app where Inth is
  installed, or it throws `[inth] Kernel not found`.

  | Panel | What it shows |
  | --- | --- |
  | Consents | Category permissions with save, accept all, and reject actions. |
  | Scripts | Registered `scripts`, their loading status, and scripts and iframes in the page. |
  | Location | Resolved country and region. |
  | Policy | Resolved policy and presentation settings. |
  | IAB | Vendors, purposes, and the TC String under an IAB policy. |
  | Events | Timeline of consent changes and script events. |
  | Actions | Show the banner, open preferences, hide consent UI, or re-resolve the policy. |

  Accept and reject in Consents apply only to categories the policy covers,
  filtered by `consentCategories`. Necessary stays on. `DevTools` and
  `InthDevTools` are aliases for the same component.

  ## Open DevTools from the consent trigger

  While `ConsentDialogTrigger` is visible, it becomes a two-button toolbar
  with a DevTools button, and DevTools hides its own launcher so one control
  occupies the corner. The panel opens adjacent to the toolbar and follows it
  when dragged. When the trigger hides, such as while
  `triggerShowWhen: 'after-consent'` awaits a choice, DevTools restores its
  launcher at `position`. Production builds that load DevTools only in
  development show only the trigger button.
</section>

<section id="props">
  ## Props

  | Prop | Type | Default | Behavior |
  | --- | --- | --- | --- |
  | `position` | `'top-left' \| 'top-right' \| 'bottom-left' \| 'bottom-right'` | `'bottom-right'` | Corner for the launcher button. |
  | `defaultOpen` | `boolean` | `false` | Opens the panel on load. |
  | `defaultTab` | `'consents' \| 'scripts' \| 'location' \| 'policy' \| 'iab' \| 'events' \| 'actions'` | `'consents'` | Panel shown first. |
  | `maxEvents` | `number` | `100` | Maximum events kept in the Events panel. |
  | `getConsentCategories` | `() => readonly ConsentCategory[]` | `consentCategories` | Narrows categories acted on in Consents without adding categories outside the policy. |
  | `getPresentation` | `() => ConsentPresentation \| undefined` | Your `presentation` option | Presentation resolved in the Policy panel. |
  | `clearRecords` | `() => void` | Clears stored consent records | Runs when clearing records from the panel. |
  | `shadow` | `boolean` | `true` | Mounts inside a shadow root with isolated styles. Pass `:shadow="false"` to mount in light DOM and add styles to `<head>`. |

  Changing any prop recreates the panel and clears its event history.
</section>

<section id="embedded-panel">
  ## Embed the panel in your own page

  `ConsentDevToolsPanel` from `@inth/vue/devtools` fills its parent container
  instead of floating. It has no launcher or close button and starts open.
  Give the parent a height:

  {/* example: fragment */}

  ```vue
  <script setup lang="ts">
  import { ConsentDevToolsPanel } from '@inth/vue/devtools';
  </script>

  <template>
    <div style="height: 32rem">
      <ConsentDevToolsPanel default-tab="events" />
    </div>
  </template>
  ```

  It accepts `defaultTab`, `maxEvents`, `getConsentCategories`,
  `getPresentation`, and `clearRecords`, and must render inside the app that
  provides the consent kernel.
</section>
