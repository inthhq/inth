<section id="behavior">
  ## What ConsentBanner renders

  `ConsentBanner` renders the consent prompt while `activeUI` is `'banner'`:
  a Card, a Banner, or a Drawer. It renders nothing until the visitor's
  policy resolves, when the policy asks for no prompt, or when
  `bannerModels` or `models` excludes the policy's model. Each container
  loads in a chunk of its own with its stylesheet, so a page downloads only
  the container it shows.

  The policy decides which buttons appear:

  - An EU `choice` prompt shows Reject All, Accept All, and Customize.
  - A US opt-in prompt asks before anything turns on, with Don't allow,
    Allow, and a button that opens the choices.
  - A `notice` prompt shows OK and a "Your Privacy Choices" link that opens
    the choices in place.
  - A policy with prompt `none` shows no banner.

  Customize opens the choices inside the same container, with Save. It no
  longer opens the dialog. Accept All and Reject All record a choice for
  every category in the policy and close the banner. Accept never lifts an
  opt-out the visitor already holds; that takes the dialog or the widget and
  its own confirmation. OK records a notice dismissal, grants nothing, and
  leaves earlier refusals in place. After a choice, the outcome is announced
  and focus moves to `PrivacyChoicesLink`, the floating dialog trigger, or
  `ConsentDialogLink`.

  <include src="../../privacy-choices-link.mdx" />

  Copy comes from the resolved Inth translations. `bannerLegalLinks` chooses
  which `legalLinks` appear below the description. The banner has no slots
  or text props.

  `ConsentBanner` moves itself into `document.body` after mounting. During
  server rendering it renders in place so the banner can ship in server
  HTML. A tap on the server-rendered banner before the page hydrates is
  replayed by the banner once the consent engine loads; nothing commits
  before that.

  ## Containers

  The policy decides which actions appear. The container decides where the
  prompt sits. All three containers show the same copy and the same
  choices.

  | Container | Positions | Default | Shape |
  | --- | --- | --- | --- |
  | `{ type: 'card', position }` | `start`, `end`, `center` | `start` | A floating card in a bottom corner, or centred over a backdrop. |
  | `{ type: 'banner', edge }` | `bottom`, `top` | `bottom` | A full-width banner along one edge. |
  | `{ type: 'drawer', side }` | `bottom`, `top`, `start`, `end` | `bottom` | A panel that slides in from one side and shows every choice at once on desktop. |

  `start` and `end` are logical, like CSS `inset-inline-start`. On a
  right-to-left page, `start` is the bottom-right corner. On phones, a
  `start` or `end` Drawer becomes a bottom Drawer.

  Set a container in three places. The first one that is set wins:

  1. The `container` prop on `ConsentBanner`.
  2. `presentation.prompt.container` in the `inth` options.
  3. The policy rule's `surface.container`, set in the dashboard.

  `edgeStyle` follows the same order, with `surface.edgeStyle` last.

  **Blocking.** `blockUntilChoice` dims the page, locks scroll, and keeps
  focus inside the prompt until the visitor chooses. A centred Card always
  blocks. A notice never blocks, and neither does a prompt under an opt-out
  model. Where blocking is not possible, a centred Card moves to the
  `start` corner. The policy's `surface.blocking` is a hard rule:
  `forbidden` never blocks, and `required` always blocks a choice prompt.
</section>

<section id="props">
  ## Props

  | Prop | Type | Default | Behavior |
  | --- | --- | --- | --- |
  | `container` | `ConsentContainer` | `presentation.prompt.container`, else the policy's `surface.container`, else `{ type: 'card', position: 'start' }` | The Card, Banner, or Drawer, and where it sits. |
  | `edgeStyle` | `'inset' \| 'flush'` | `presentation.prompt.edgeStyle`, else `'inset'` | `inset` floats a Banner or Drawer off the viewport edges. `flush` runs it edge to edge. A Card is always inset. |
  | `blockUntilChoice` | `boolean` | `presentation.prompt.blockUntilChoice`, else `false` | Blocks the page until the visitor chooses. |
  | `disableAnimation` | `boolean` | the config's `disableAnimation` | Skips enter and exit animations. |

  Explicit props override `presentation.prompt`. Leave a prop unset to
  follow your Inth options. `ConsentContainer` and `ConsentEdgeStyle` are
  exported as types from `@inth/vue`.
</section>

<section id="accessibility">
  ## Accessibility and focus

  - A non-blocking prompt is a `region` labeled by its title. It does not
    trap focus or lock scrolling.
  - A blocking prompt puts `role="dialog"` and `aria-modal="true"` on the
    shell around the card, shows a backdrop, locks page scrolling, moves
    focus to the card, and keeps Tab inside it.
  - Escape folds the choices Customize opened. It does not dismiss the
    prompt: the visitor responds with one of its buttons.
  - Every action is a native `button`, and `dir` matches the resolved
    language.
</section>

<section id="styling">
  ## Style the banner

  [Theme tokens](/docs/customization/tokens) control colors, type, radius,
  spacing, and motion. `components.banner` binds attributes such as `class`
  or `style` to `root`, `overlay`, `cardShell`, `card`, `header`, `title`,
  `footer`, `actionGroup`, `rightLink`, `expand`, `rightsRow`, and
  `saveButton`. `components.description.banner` and `components.tag.banner`
  target the description and branding tag. See
  [component parts](/docs/customization/slots).

  The root element exposes these data attributes for CSS selectors:

  | Attribute | Values |
  | --- | --- |
  | `data-placement` | `card-start`, `card-end`, `card-center`, `banner-bottom`, `banner-top`, `drawer-bottom`, `drawer-top`, `drawer-start`, `drawer-end` |
  | `data-flow` | `expand-in-place`, `all-in-one` |
  | `data-variant` | `choice`, `us-consent`, `notice` |
  | `data-edge-style` | `inset`, `flush` |
  | `data-blocking` | `true`, present only while blocking |
  | `data-expanded` | `true`, present while Customize shows the choices |
  | `data-state` | `open`, `closed` |

  `bannerHideBranding`, or `hideBranding` for every surface, hides the
  "Consent by" tag. `disableAnimation` turns off enter and exit transitions.
</section>

<section id="verify">
  ## Verify

  Open the page in a private window under a policy that asks for a choice.
  Confirm Reject All and Accept All appear side by side and every button is
  reachable with Tab. Click Customize to open the choices in place, then
  reject and reload to confirm the banner stays closed. In Elements, confirm
  the root element carries the `data-placement` you set.
</section>
