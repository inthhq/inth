<section id="behavior">
  ## What ConsentBanner renders

  `ConsentBanner` renders the first-layer banner while `activeUI` is
  `'banner'`. It renders nothing until the visitor's policy resolves, when the
  policy asks for no prompt, or when `bannerModels` or `models` excludes the
  policy's model.

  The policy decides which buttons appear:

  - A `choice` prompt shows Reject All, Accept All, and Customize. Customize
    uses the primary style by default so Accept All and Reject All have equal
    weight.
  - A `notice` prompt shows an OK button. When the policy grants an opt-out
    right, the banner adds an underlined link whose action follows
    `presentation.optOutLink`. With the default `'do-not-sell'` ("Do Not Sell
    or Share My Personal Information"), activating the link records the opt-out
    in one click and opens `OptOutConfirmation` (reloading first when that
    turns off a running category and `reloadOnConsentRevoked` is enabled). With
    `'privacy-choices'` ("Your Privacy Choices") or
    `'california-privacy-choices'` ("Your California Privacy Choices"), the
    link renders with the California Privacy Protection Agency opt-out icon and
    opens `ConsentManager` without recording an opt-out. Programmatic calls to
    `useOptOut()` still opt out in one step whatever `presentation.optOutLink`
    is set to. When only the `preferences` right is shown, the link opens
    `ConsentManager`.
  - A policy with prompt `none` shows no banner.

  <include src="../../privacy-choices-link.mdx" />

  Accept All and Reject All record a choice for every category in the policy
  and close the banner. Customize sets `activeUI` to `'manager'`, opening
  `ConsentManager` if mounted. OK records a notice dismissal, grants nothing,
  and leaves earlier refusals in place.

  Copy comes from the resolved Inth translations: `cookieBanner.title` and
  `cookieBanner.description` for a choice, `cookieBanner.noticeTitle` and
  `cookieBanner.noticeDescription` for a notice, and `common.acceptAll`,
  `common.rejectAll`, `common.customize`, and `common.acknowledge` for
  buttons. `bannerLegalLinks` chooses which `legalLinks` appear below the
  description. The banner has no slots or text props.

  `ConsentBanner` moves itself into `document.body` after mounting. During
  server rendering it renders in place so the banner can ship in server HTML.

  ## Variants and positions

  The policy decides the actions; the variant decides the layout.

  | Variant | Shape | Positions | Default position |
  | --- | --- | --- | --- |
  | `floating` | Card in a corner or centered on an edge (default). | `bottom-left`, `bottom-right`, `top-left`, `top-right`, `bottom-center`, `top-center` | `bottom-left` |
  | `bar` | Full-width bar along the top or bottom edge. | `top`, `bottom` | `bottom` |
  | `widget` | Compact card with smaller type. | `bottom-left`, `bottom-right`, `top-left`, `top-right` | `bottom-right` |
  | `wall` | Centered card over a blocking backdrop. | `center` | `center` |

  The policy has final authority. A choice `wall` always blocks. A notice
  never blocks, and a notice `wall` falls back to `floating`. An invalid
  position falls back to the variant's default. Each fallback logs a `[inth]`
  warning in the console.

  Right-to-left languages keep the same corner or edge; only text direction
  changes.
</section>

<section id="props">
  ## Props

  | Prop | Type | Default | Behavior |
  | --- | --- | --- | --- |
  | `variant` | `'floating' \| 'bar' \| 'widget' \| 'wall'` | `presentation.prompt.variant`, else `'floating'` | Banner layout shape. |
  | `position` | `PromptPosition` | `presentation.prompt.position`, else the variant's default | Banner placement. Must be valid for the variant. |
  | `blocking` | `boolean` | `presentation.prompt.blocking`, else `true` for `wall` only | Enables backdrop, scroll lock, and focus trap together. |

  Explicit props override `presentation.prompt`. Leave a prop unset to follow
  your Inth options. `PromptVariant` and `PromptPosition` are exported as
  types from `@inth/vue`.
</section>

<section id="accessibility">
  ## Accessibility and focus

  - A non-blocking banner renders as a `region` labeled by its title. It does
    not trap focus or lock scrolling.
  - A blocking banner renders as a `dialog` with `aria-modal="true"`. It shows
    a backdrop, locks page scrolling, moves focus to the banner card, and
    traps Tab inside the card.
  - The banner has no close button, and Escape does not dismiss it. The
    visitor responds with one of its action buttons.
  - Every action is a native `button`, and `dir` matches the resolved
    language.
</section>

<section id="styling">
  ## Style the banner

  [Theme tokens](/docs/customization/tokens) control colors, type, radius,
  spacing, and motion. `components.banner` binds attributes such as `class` or
  `style` to `root`, `overlay`, `cardShell`, `card`, `header`, `title`,
  `footer`, `actions`, `actionGroup`, `rights`, and `rightLink`.
  `components.description.banner` and `components.tag.banner` target the
  description and branding tag. See [component parts](/docs/customization/slots).

  The root element exposes these data attributes for CSS selectors:

  | Attribute | Values |
  | --- | --- |
  | `data-variant` | `floating`, `bar`, `widget`, `wall` |
  | `data-position` | The resolved position |
  | `data-prompt` | `choice`, `notice` |
  | `data-model` | `opt-in`, `opt-out`, `iab` |
  | `data-blocking` | `true`, present only while blocking |

  `bannerHideBranding`, or `hideBranding` for every surface, hides the
  "Secured by" tag. `disableAnimation` turns off enter and exit transitions.
</section>

<section id="verify">
  ## Verify

  Open the page in a private window under a policy that asks for a choice.
  Confirm Reject All and Accept All appear side by side and every button is
  reachable with Tab. Click Customize to open preferences, then reject and
  reload to confirm the banner stays closed. In Elements, confirm the root
  element carries your `data-variant` and `data-position`.
</section>
