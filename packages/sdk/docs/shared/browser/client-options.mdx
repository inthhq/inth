<section id="connection">
  ## Connection and policy

  Every entry needs `projectUrl`, your Inth project URL, unless `mode` is
  `testing()` or `enabled` is `false`. The ES modules take `mode` as
  `hosted()`, `manifest()` or `testing()`. The script-tag builds take a mode
  name and the manifest options below. `inth.js` and `@inth/sdk/hosted`
  accept hosted mode only. `inth.testing.js` takes no backend options and
  resolves `policy` instead.

  | Option | Type | Default | What it does |
  | --- | --- | --- | --- |
  | `projectUrl` | `string` | none | Your Inth project URL. Required unless `mode` is `testing()` or `enabled` is `false`. |
  | `mode` | `hosted()`, `manifest()` or `testing()`. Script-tag builds also take `'hosted'` or `'manifest'`. | `hosted` | See [consent modes](/docs/concepts/modes). In the script-tag builds, `manifest` when `manifest` or `manifestUrl` is set, otherwise `hosted`. |
  | `manifest` | `ConsentManifest` | none | Script-tag builds. Your project's policy manifest, inlined in the page, for manifest mode. In the ES modules, `manifest({ snapshot })`. |
  | `manifestUrl` | `string` | none | Script-tag builds. Where manifest mode fetches the manifest. A URL that ends in `/v1/consent/manifest` also gives the project URL; any other URL needs `projectUrl` too. In the ES modules, `manifest({ manifestUrl })`. |
  | `policy` | array of policy rules or preset names | recommended rules | `inth.testing.js` only. A preset name such as `'europeOptIn'` stands for that preset in `policyRulePresets`. An unknown name throws. The `data-policy` attribute sets it. In the ES modules, `testing({ policy })` with rule objects. |
  | `overrides` | `{ country?, region?, language?, gpc? }` | none | The visitor's location, language or GPC signal, when the page knows it. Policy matching uses these instead of detection. |
  | `prefetch` | kernel configuration | none | A server-resolved init answer. When it carries a resolved policy, the client renders from it and does not call `/v1/consent/init`. |
  | `enabled` | `boolean` | `true` | `false` grants every category, shows no UI and loads every configured script at once. |
</section>

<section id="gating">
  ## Scripts, blockers and data

  | Option | Type | Default | What it does |
  | --- | --- | --- | --- |
  | `scripts` | `Script[]` | `[]` | Vendor scripts to load once their category is allowed. Each entry needs `id`, `category`, and `src` or `textContent`. |
  | `consentCategories` | category names | categories your scripts, iframes and rules use | The categories the preference dialog offers, within the policy's scope. `necessary` is always included. |
  | `networkBlocker` | `{ rules, enabled?, logBlockedRequests?, onRequestBlocked? }` or `false` | off | Hold `fetch` and `XMLHttpRequest` calls that match a rule until the rule's category is allowed. |
  | `iframeBlocker` | `{ disableAutomaticBlocking? }` or `false` | on | Gate iframes that carry `data-category` or `data-vendor`. `false` turns it off. With `disableAutomaticBlocking: true`, Inth checks iframes only when you call `processIframes()`. |
  | `nonce` | `string` | none | Content Security Policy nonce for the stock UI's `<style>` element and every `<script>` the `scripts` option loads. A script's own `nonce` wins. With a nonce set, Inth runs only the `<script type="text/plain" data-inth-category>` tags that carry the same `nonce`. |
  | `scriptLoader` | `{ onDebug? }` | none | `onDebug` receives every script loader lifecycle event. |
  | `vendors` | `Vendor[]` | none | Vendors offered for vendor-level consent outside IAB. The preference dialog lists a switch for each. They merge with vendors from Inth, `vendor` fields on scripts and rules, and `data-inth-vendor` on gated tags. |
  | `clearOnRevocation` | cookies and storage keys per category | off | Delete named cookies and storage keys when their category is denied. Read once, at start. |
  | `reloadOnConsentRevoked` | `boolean` | `true` | Reload the page after an accept, reject, save or one-click opt-out turns off a category or vendor that was allowed, waiting up to one second, counted from when the choice is stored on the device, for in-flight requests. Privacy signals and backend-synced opt-outs do not reload. With `persistence: false`, nothing reloads because a reload would discard the choice it was for. |
  | `callbacks` | `{ onChoiceRecorded?, onPermissionsChanged?, onError?, onBeforeConsentRevocationReload? }` | none | Functions Inth calls on consent events. |
  | `storageConfig` | `{ storageKey?, crossSubdomain?, defaultDomain?, defaultExpiryDays? }` | key `inth`, current host, 365 days | The name, domain and lifetime of the consent cookie and localStorage key. |
  | `persistence` | `boolean` or `{ storageConfig?, skipHydration?, sync? }` | `true` | Read and write choices in the cookie and localStorage, and follow other tabs. `false` keeps choices in memory only. `{ sync: false }` stops following other tabs. |
  | `user` | `{ externalId, identityProvider?, identityToken?, externalIdType?, properties? }` | none | An identified visitor, sent with consent records. `identityToken` verifies the link on the server. Links only a subject the next save creates; use `identify()` for an existing one. |
  | `iab` | IAB options or `false` | none | CMP settings such as `cmpId` and `vendors`. Only the IAB build accepts it; the other builds throw when it is set. |
</section>

<section id="presentation">
  ## Presentation and copy

  | Option | Type | Default | What it does |
  | --- | --- | --- | --- |
  | `ui` | UI options or `false` | stock UI on | Theme tokens, CSS, surfaces and mounting. `false` starts the client with no UI. See [UI options](#ui-options). |
  | `presentation` | `{ prompt?, preferences?, optOutLink? }` | a Card in the `start` corner, `'do-not-sell'` | The banner's container, edge style and button layout, blocking, and the opt-out link form (`'do-not-sell'`, `'privacy-choices'` or `'california-privacy-choices'`), within what the policy allows. With `'do-not-sell'`, clicking an opt-out link records an opt-out in one click. Both `'privacy-choices'` and `'california-privacy-choices'` always render with the California Privacy Protection Agency opt-out icon and open the preference dialog without recording an opt-out. Programmatic `client.optOut()` still opts out in one step whatever `optOutLink` is set to. |
  | `i18n` | `{ locale?, messages }` | English | The language to start in, and messages per language that override the bundled, Inth or manifest copy key by key for that language. |
  | `legalLinks` | `{ privacyPolicy?, cookiePolicy?, termsOfService? }` | none | Each link is `{ href, label?, target?, rel? }`. The banner and dialog show only the links their `legalLinks` option lists. |

<section id="ui">
  ## UI options

  These go under `ui`. The headless builds ignore them.

  | Option | Type | Default | What it does |
  | --- | --- | --- | --- |
  | `theme` | theme tokens | none | Colors, radius, typography, spacing and motion. The same token object every Inth package takes. |
  | `css` | `string` | none | CSS added after the bundled stylesheet, in the same root as the UI. |
  | `colorScheme` | `'light'`, `'dark'` or `'system'` | `'system'` | Which token set to use. `system` follows the visitor's setting and updates when it changes. |
  | `shadow` | `boolean` | `true` | Render inside a shadow root. `false` renders into the page, where your stylesheet applies. |
  | `styles` | `boolean` | `true` | Include the bundled stylesheet. Set `false` with `shadow: false` when the page loads the stylesheet itself. |
  | `noStyle` | `boolean` | `false` | Render markup with no `inth` classes and no bundled stylesheet, for fully custom CSS. `theme` and `css` still apply. |
  | `disableAnimation` | `boolean` | the visitor's reduced motion setting | Show and hide surfaces without transitions. |
  | `container` | element or CSS selector | `document.body` | Where the UI host element is appended. A selector that matches nothing throws. |
  | `banner` | `boolean` or banner options | `true` | `false` renders no banner. An object sets copy and behavior; see the banner options. |
  | `dialog` | `boolean` or dialog options | `true` | `false` renders no preference dialog. |
  | `trigger` | `boolean` or trigger options | `false` | Render the floating button that reopens the dialog. |
  | `iab` | `{ loadErrorText?, saveErrorText?, moreVendorsText? }` | translated copy | Copy for the IAB vendor list states. IAB build only. |
</section>

<section id="banner">
  ## Banner options

  These go under `ui.banner`.

  | Option | Type | Default | What it does |
  | --- | --- | --- | --- |
  | `title` | `string` | translated title | Heading. A notice uses the notice title by default. |
  | `description` | `string` | translated description | Body text. A notice uses the notice description by default. |
  | `acceptButtonText` | `string` | "Accept All" | Label of the accept button. |
  | `rejectButtonText` | `string` | "Reject All" | Label of the reject button. |
  | `customizeButtonText` | `string` | "Customize" | Label of the button that opens the dialog. |
  | `legalLinks` | list of `privacyPolicy`, `cookiePolicy`, `termsOfService`, or `null` | none | Which configured legal links to show after the description. `null` or `[]` shows none. |
  | `container` | `{ type: 'card', position }`, `{ type: 'banner', edge }` or `{ type: 'drawer', side }` | `presentation.prompt.container`, then the policy's | The Card, Banner or Drawer, and where it sits. See [containers](#containers). |
  | `edgeStyle` | `'inset'` or `'flush'` | `'inset'` | `inset` floats a Banner or Drawer 12px off the viewport edges with rounded corners. `flush` runs it edge to edge. A Card is always inset. |
  | `blockUntilChoice` | `boolean` | `false` | Block the page until the visitor chooses: backdrop, scroll lock, focus trap, and no outside dismissal. A centred Card always blocks. |
  | `hideBranding` | `boolean` | `false` | Hide the "Consent by" tag. The IAB banner always keeps it. |
  | `scrollLock`, `trapFocus` | `boolean` | from `presentation` | IAB banner only. Block the page while it is up. `presentation.prompt.blocking` wins over both. |

  The dismiss button of a notice always uses the translated
  `common.acknowledge` label. Change it through `i18n`.
</section>

<section id="containers">
  ## Containers

  The policy decides which actions appear. The container decides where the banner sits. All three containers show the same copy and the same choices.

  | Container | Positions | Default | Shape |
  | --- | --- | --- | --- |
  | `{ type: 'card', position }` | `start`, `end`, `center` | `start` | A floating card in a bottom corner, or centred over a backdrop. |
  | `{ type: 'banner', edge }` | `bottom`, `top` | `bottom` | A full-width banner along one edge. |
  | `{ type: 'drawer', side }` | `bottom`, `top`, `start`, `end` | `bottom` | A panel that slides in from one side and shows every choice at once on desktop. |

  `start` and `end` are logical, like CSS `inset-inline-start`. On a right-to-left page, `start` is the bottom-right corner. Customize opens the choices inside the same container. On phones, a `start` or `end` Drawer becomes a bottom Drawer.

  Set a container in three places. The first one that is set wins:

  1. `ui.banner.container`.
  2. `presentation.prompt.container`.
  3. The policy rule's `surface.container`, set in the dashboard.

  `edgeStyle` and `blockUntilChoice` follow the same order. `blockUntilChoice` dims the page, locks scroll and keeps focus inside the banner until the visitor chooses. A centred Card always blocks. A notice never blocks, and neither does a banner under an opt-out model; where blocking is not possible, a centred Card moves to the `start` corner. The policy's `surface.blocking` is a hard rule: `forbidden` never blocks, and `required` always blocks a choice prompt.
</section>

<section id="dialog">
  ## Dialog options

  These go under `ui.dialog`.

  | Option | Type | Default | What it does |
  | --- | --- | --- | --- |
  | `legalLinks` | list of `privacyPolicy`, `cookiePolicy`, `termsOfService`, or `null` | the regime's link | The dialog's footer shows one link: the Cookie Policy in the EU, the Privacy Policy in the US. A list shows it only when the list names it; `null` hides it. |
  | `hideBranding` | `boolean` | `false` | IAB dialog only. Hide the "Consent by" tag at the bottom of the dialog. |

  The dialog's title, description, category names and button labels come
  from translations. Change them through `i18n`.
</section>

<section id="trigger">
  ## Trigger options

  `ui.trigger: true` shows the trigger with its defaults. An object sets these:

  | Option | Type | Default | What it does |
  | --- | --- | --- | --- |
  | `position` | `'bottom-right'`, `'bottom-left'`, `'top-right'` or `'top-left'` | `'bottom-right'` | The corner the button starts in. |
  | `size` | `'sm'`, `'md'` or `'lg'` | `'md'` | Button size. |
  | `showWhen` | `'always'` or `'after-consent'` | `'always'` | `after-consent` hides the button until the visitor has answered the prompt. |
  | `ariaLabel` | `string` | "Open privacy settings" | The button's accessible name. It has no visible text. |
  | `persistPosition` | `boolean` | `true` | Remember the corner a visitor dragged the button to, in localStorage. A remembered corner wins over `position`. |
</section>

<section id="page-actions">
  | Value | What a click does |
  | --- | --- |
  | `accept` | Like the banner's accept button, allows every category the dialog offers without IAB. Under an IAB policy it confirms the vendors' declared processing through the CMP. Optional categories without declared consent purposes remain denied. See [categories under an IAB policy](/docs/concepts/consent-state#categories-under-an-iab-policy). |
  | `reject` | Rejects every optional category the dialog offers. |
  | `customize` | Opens the preference dialog. Records nothing. |
  | `opt-out` | Under an opt-out policy, follows `presentation.optOutLink` (`data-opt-out-link`): `'do-not-sell'` records an opt-out in one click and opens the confirmation view, while `'privacy-choices'` and `'california-privacy-choices'` open the preference dialog and record nothing. Under any other policy, opens the preference dialog. |
  | `dismiss` | Dismisses a notice. This records an acknowledgement, not consent, and does nothing unless the policy shows a notice. |
  | `banner` | Shows the banner again. Records nothing. |
  | `close` | Closes the banner or dialog. Records nothing. |
</section>

<section id="events">
  | Event | Payload | When it fires |
  | --- | --- | --- |
  | `ready` | the snapshot | The policy has resolved and the UI can render. For a returning visitor, `hasConsented()` is reliable from here. |
  | `consent` | the snapshot | Permissions, the recorded choice, the vendor switches or the opt-out changed. This includes a stored choice restored at start, a save, an expiry, a GPC change, a one-click opt-out and a backend answer that changes what the opt-out covers. Read the opt-out with `getOptOutState()`. |
  | `ui` | `'banner'`, `'dialog'` or `'none'` | The surface Inth wants shown changed. |
  | `error` | the error | A backend call failed, or an IAB step failed. |

  A `ready` listener added after the policy resolved runs at once with the
  snapshot from that moment. A `ui` listener added after that runs at once
  with the current surface. `consent` and `error` listeners only hear later
  changes.
</section>
