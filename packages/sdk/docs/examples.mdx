Run complete starter apps, product showcases and acceptance tests locally from your Inth workspace checkout.

## Run an example locally

The examples live in the `examples` directory of your Inth workspace checkout. They build against workspace packages rather than npm, so install dependencies and build the SDK packages first:

```sh
pnpm install
pnpm sdk:build
```

Then start any example by directory:

```sh
pnpm --dir examples/nextjs dev
```

Each example includes a README listing the key files and how to point it at your Inth project. To add Inth to an existing app instead, follow your [framework quickstart](/docs/frameworks). You can also create and manage Inth projects from the terminal with the `inth` command from `@inth/cli`.

## Starters

Each starter shows the smallest production setup for one framework and rendering mode. Every starter connects to Inth, renders the stock banner and dialog, keeps a **Privacy settings** link on the page, and loads PostHog only after the visitor allows measurement.

| Framework | Directory | What it shows |
| --- | --- | --- |
| Next.js | `examples/nextjs` | App Router with a build-time manifest and streamed SSR |
| Next.js | `examples/nextjs-pages-router` | Pages Router with `getServerSideProps` |
| TanStack Start | `examples/tanstack-start` | Request middleware, a server function and the root route |
| React | `examples/react` | Vite single-page app |
| Nuxt | `examples/nuxt` | Nuxt module with build-time manifest resolved on the server |
| Nuxt | `examples/nuxt-static` | `nuxt generate` with the manifest resolved in the browser |
| Vue | `examples/vue` | Vue plugin in a Vite single-page app |
| Astro | `examples/astro` | Server output with the Node adapter |
| Astro | `examples/astro-static` | Static output with prerendered pages |
| Svelte | `examples/svelte` | `@inth/svelte` in a Vite single-page app |
| SvelteKit | `examples/sveltekit` | Server hooks and server-rendered layouts |
| HTML | `examples/html` | Single script tag on plain HTML pages |
| JavaScript | `examples/javascript` | `@inth/sdk` with a bundler |

Starters that download a manifest at build time commit a `.env` pointing at a demo project so they build on a fresh clone. To connect your own project, set your project URL in `.env.local`, such as `NEXT_PUBLIC_INTH_PROJECT_URL` in Next.js or `NUXT_PUBLIC_INTH_PROJECT_URL` in Nuxt, add the local origin to your project's trusted origins, and replace or remove the placeholder PostHog key.

## Showcases

Showcases are apps for Northwind Coffee, a sample coffee roaster. Each app focuses on one capability inside a realistic layout. All except the Nuxt theme showcase use Next.js.

| Showcase | Directory | What it shows |
| --- | --- | --- |
| Custom banner | `examples/showcase-custom-banner` | Banner and preferences sheet built with headless hooks and no Inth stylesheet |
| Preference center | `examples/showcase-preference-center` | Dedicated account privacy page with categories, vendors and last saved time |
| Gated embeds | `examples/showcase-gated-embeds` | YouTube, Google Maps and support chat behind placeholders that load in place |
| Analytics | `examples/showcase-analytics` | Google Tag Manager with Consent Mode v2, GA4, PostHog and Meta Pixel, vendor switches and DevTools |
| IAB TCF | `examples/showcase-iab` | Publisher ad slots filled from the TC string, with GPP |
| Banner experiment | `examples/showcase-experiment` | A/B test between two banner layouts with exposure and choice events per arm |
| Multilingual | `examples/showcase-multilingual` | Banner language from the route and policy from the visitor's region |
| Nuxt theme | `examples/showcase-nuxt-theme` | Stock Nuxt banner and dialog styled in brand colors, layout and dark mode |

Point any showcase at your Inth project by setting `NEXT_PUBLIC_INTH_PROJECT_URL` in `.env.local`, or `NUXT_PUBLIC_INTH_PROJECT_URL` for `examples/showcase-nuxt-theme`.

Vendor switches are optional. The analytics showcase enables them in the preference dialog, the preference center lists them inline, and the IAB showcase lists TCF vendors from a demo `public/vendor-list.json`. Its README notes what to change for production.

## Verify an example

Replace the placeholder PostHog key in `examples/showcase-analytics/lib/scripts.ts` with your own, then open the showcase in a private window with DevTools Network open:

1. Before you choose, confirm no PostHog request appears.
2. Click **Reject All** and reload. Confirm the banner stays closed and PostHog stays absent.
3. Open **Privacy settings** and enable **Analytics**, the `measurement` category. Confirm PostHog loads.
4. Withdraw **Analytics**. The page reloads without PostHog so code that already ran stops.

Run the Playwright starter smoke tests or full acceptance fixtures from the repository root:

```sh
pnpm dlx playwright@1.61.1 install chromium
STARTER_TARGET=nextjs pnpm --dir internals/fixtures/acceptance test:starters
```

```sh
EXAMPLE_TARGET=nextjs pnpm --dir internals/fixtures/acceptance test
```

Pass a comma-separated list such as `react,tanstack-start`, or `all`. See [verify consent](/docs/guides/verify-consent) for the release checklist against your own project and vendors.
