Configure your Content Security Policy so `@inth/nuxt` can apply theme tokens,
run pre-hydration helper scripts, call Inth and `/api/inth`, and load
permitted vendor scripts.

## What Inth adds to the page

| What | Directive |
| --- | --- |
| `<style id="inth-css-vars">` theme token tag in `<head>` | `style-src` |
| Component CSS (Nuxt inline `<style>` tags for SSR banners plus bundled stylesheets) | `style-src` |
| Inline `<script>` in `<head>` prefetching `/v1/consent/init` on `ssr: false` pages in `hosted()` mode | `script-src` |
| Inline `<script>` before SSR banner buttons capturing pre-hydration taps | `script-src` |
| Inline `<script>` at the end of `<body>` starting already-permitted vendor helpers before hydration | `script-src` |
| Browser calls to `/api/inth/v1/consent/init` and `/api/inth/v1/consent/manifest` in default `manifest()` mode | `connect-src 'self'` |
| Consent saves to Inth's `/v1/consent/records` (plus `/v1/consent/init` in `hosted()` mode) | `connect-src` |
| Code-split chunks such as the browser resolver and non-English copy | `script-src 'self'` |
| `<script>` elements created by the script loader | `script-src` |
| Vendor scripts, frames, images, and API calls | `script-src`, `frame-src`, `img-src`, `connect-src` per vendor |

If your CSP forbids Nuxt's default inline styles for SSR banners, disable them
with `features: { inlineStyles: false }` in `nuxt.config.ts` so Nuxt links
banner CSS as external stylesheets instead.

## Allow the theme token style tag

`@inth/nuxt` writes `tokens` into `<style id="inth-css-vars">` on every page.
Without `'unsafe-inline'` in `style-src`:

1. Load a page with your CSP enforced.
2. Copy the `sha256-...` hash from the browser's `Refused to apply inline
   style` console error into `style-src`.
3. Update the hash whenever you change `tokens`.

When `inth.nonce` is set, `<style id="inth-css-vars">` carries that nonce as
well.

## Allow the early init script

On `ssr: false` pages in `hosted()` mode, the module injects an inline
`<script>` in `<head>` to start `/v1/consent/init` before app JavaScript loads.

- **With `nuxt-security`:** the script receives a per-request nonce
  automatically.
- **With `inth.nonce`:** the script carries your configured nonce.
- **With hashes:** copy the `sha256-...` hash from `Refused to execute inline
  script` into `script-src` (update it if you change `projectUrl` or upgrade).

Disable the script with `initPrefetch: false` under `inth`. If blocked, the
app still sends `/v1/consent/init` after loading.

A server-rendered banner also writes a static inline `<script>` before its
buttons to capture pre-hydration taps. It supports `inth.nonce` and hashes; if
blocked, taps start working once hydration completes.

## Allow the server start script

When stored consent or `alwaysLoad` already permits vendor helpers during SSR,
an inline `<script>` at the end of `<body>` starts their tags before
hydration. Because its content varies per visitor, hashes cannot allow it:

- **With `nuxt-security`:** the script and inserted tags receive per-request
  nonces automatically.
- **With `inth.nonce`:** the script and inserted tags carry that nonce (a
  per-script `nonce` overrides it).

If blocked, the script loader starts those entries after hydration instead.

## Allow your Inth project

In default `manifest()` mode, browser `/api/inth/v1/consent/init` calls stay on `'self'`,
while saves post to your Inth project origin. Add your Inth project host (and
any custom `manifestUrl` or `geoUrl` origin) to `connect-src`:

```txt title="Content-Security-Policy (partial)"
connect-src 'self' https://<your-inth-project-host>;
```

Server-side fetches made by Nitro during SSR are not subject to browser CSP.

## Allow scripts

List each vendor's script host in `script-src` (each
[integration guide](/docs/integrations/overview) names its hosts). Because
`inth.nonce` is fixed at build time, prefer host allowlists or per-request
nonces via `nuxt-security`.

## Verify

Enforce your CSP (not report-only) and load a page. Confirm your theme colors
render and no `Refused to apply inline style`, `Refused to connect`, or
`Refused to load the script` error mentions Inth or an allowed vendor. Click
**Accept All** and confirm vendor scripts load and `POST /v1/consent/records` succeeds.
