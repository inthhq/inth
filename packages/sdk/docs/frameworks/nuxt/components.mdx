`@inth/nuxt` registers core consent components globally so you use them in
templates without imports, and exports optional surfaces by path. Every
component ships its own styles.

## Component reference

| Component | In Nuxt | What it renders |
| --- | --- | --- |
| [`InthProvider`](/docs/frameworks/nuxt/components/inth-provider) | Global | Server-rendered banner and preference dialog (switches to IAB surfaces under an IAB policy when `iab` is set). |
| [`ConsentWidget`](/docs/frameworks/nuxt/components/consent-widget) | Global | Inline category switches and save buttons for a privacy page. |
| [`ConsentDialogLink`](/docs/frameworks/nuxt/components/consent-dialog-link) | Global | Button that reopens preferences. |
| [`ConsentDialogTrigger`](/docs/frameworks/nuxt/components/consent-dialog-trigger) | Global | Floating, draggable button that reopens preferences. |
| [`ConsentGate`](/docs/frameworks/nuxt/components/consent-gate) | Global | Default slot while a category is allowed, otherwise its `placeholder` slot. |
| [`ConsentBanner`](/docs/frameworks/nuxt/components/consent-banner) | `@inth/nuxt/components/consent-banner` | First-layer banner on its own. |
| [`ConsentDialog`](/docs/frameworks/nuxt/components/consent-dialog) | `@inth/nuxt/components/consent-dialog` | Preference dialog on its own. |
| [`IABConsentBanner`](/docs/frameworks/nuxt/components/iab-consent-banner) | `@inth/nuxt/components/iab-consent-banner` | IAB TCF first layer. |
| [`IABConsentDialog`](/docs/frameworks/nuxt/components/iab-consent-dialog) | `@inth/nuxt/components/iab-consent-dialog` | IAB TCF preference center. |
| [`ConsentDevTools`](/docs/frameworks/nuxt/components/dev-tools) | `@inth/nuxt/devtools` | Development inspection panel. |

Import non-global components inside `<script setup>`:

{/* example: fragment */}

```ts
import ConsentBanner from '@inth/nuxt/components/consent-banner';
```

## InthProvider or the parts

`InthProvider` renders `ConsentBanner` and `ConsentDialog` (or the IAB
components when `iab` is enabled) automatically for each visitor's policy.
Mount either `InthProvider` or individual surfaces, never both, so visitors do
not see two banners. Always use the global Nuxt `InthProvider` rather than the
plain Vue export from `@inth/vue/vue-plugin` so the banner renders on the
server.

## Use the components in Vue Vapor

Nuxt 4.6+ supports Vue Vapor with Vue 3.6 enabled via `vue.vapor`:

<include src="../../shared/examples/nuxt/vapor-nuxt-config.mdx" />

In `<script setup vapor>` components, Nuxt renders Inth's virtual-DOM consent
components through its interop layer. `InthProvider`, `ConsentGate`,
`ConsentDialogLink`, and all composables work normally:

<include src="../../shared/examples/nuxt/vapor-embed.mdx" />

Because the consent surfaces still use the virtual DOM, Vapor interop ships
both runtimes (roughly 18% more client JavaScript in our `nuxt-vapor` fixture
compared to standard Vue).

## Building blocks

Smaller building blocks are exported under `@inth/nuxt/components/`:
`consent-button`, `consent-switch`, `consent-actions`, `consent-link`,
`consent-legal-links`, `consent-description`, `consent-tag`, and
`consent-branding-icon`. For custom markup, use the
[headless composables](/docs/frameworks/nuxt/headless) instead.
