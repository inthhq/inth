Register `@inth/nuxt` in `nuxt.config.ts` to add server-side policy
resolution, global consent components, auto-imported composables, and a local
consent route to your Nuxt app.

## Register the module

Add `@inth/nuxt` to `modules` in `nuxt.config.ts` and configure options under
the `inth` key:

<include src="../../shared/examples/nuxt/nuxt-config.mdx" />

`@inth/nuxt` needs no separate plugin package and no `app.use()`. See the
[quickstart](/docs/frameworks/nuxt/quickstart) for the complete setup.

## What the module registers

| What | Details |
| --- | --- |
| Components | `InthProvider`, `ConsentWidget`, `ConsentDialogLink`, `ConsentDialogTrigger`, and `ConsentGate`, registered globally. See [components](/docs/frameworks/nuxt/components). |
| Composables | Every composable exported by `@inth/vue/vue-plugin`, auto-imported. See [composables](/docs/frameworks/nuxt/composables). |
| Nuxt plugin | Creates the consent runtime per request on the server and once in the browser, resolves the visitor's policy during SSR, and writes `tokens` into `<head>`. |
| Server route | In default `manifest()` mode, adds `${routePrefix}/**` serving `GET /api/inth/v1/consent/init` and `GET /api/inth/v1/consent/manifest`. `routePrefix: false`, `hosted()`, and `testing()` add no route. |
| `#inth/composables` alias | Exposes composables that are not auto-imported. |

In the browser, the plugin starts consent modules after mount (or before mount
on `ssr: false` pages where no server HTML hydrates). Starting reads stored
choices, applies Global Privacy Control, and activates the script loader,
`clearOnRevocation`, network blocker, iframe blocker, and IAB module when
enabled.

In `hosted()` mode, the module injects a small inline script into `<head>` on
`ssr: false` pages to start `/v1/consent/init` while HTML parses.

## nuxt.config.ts or app.config.ts

The module merges `inth` from `app/app.config.ts` over `inth` in
`nuxt.config.ts` and combines arrays from both files. Both files are typed
automatically.

| File | Put these options here |
| --- | --- |
| `nuxt.config.ts` | Serializable data (`projectUrl`, `tokens`, `presentation`, `components`, `legalLinks`, trigger options, network blocker `rules`) and build-only options (`mode`, `routePrefix`, `onBuildError`, `initPrefetch`, `devtools`). |
| `app/app.config.ts` | Options containing functions: `scripts`, `callbacks`, and `networkBlocker.onRequestBlocked`. |

Module options serialize to JSON via `runtimeConfig.public` and strip
functions, whereas `app.config.ts` ships in the browser bundle with functions
intact.

Changes to `app.config.ts` via `updateAppConfig()` or HMR update `scripts`,
`networkBlocker`, `iframeBlocker`, `vendors`, `consentCategories`,
`callbacks`, and `reloadOnConsentRevoked` live. Storage, project URL, and
experiment options are read once at load; `mode` and `routePrefix` are fixed
at build time.

## Change the project URL at runtime

Nuxt overrides `runtimeConfig.public` from `NUXT_PUBLIC_*` environment
variables at server startup. Point a built server at a different Inth project
URL without rebuilding:

```sh
NUXT_PUBLIC_INTH_PROJECT_URL=https://your-project.inth.app \
  node .output/server/index.mjs
```

`NUXT_PUBLIC_INTH_PROJECT_URL` wins over any legacy
`NUXT_PUBLIC_C15T_BACKEND_URL`, which is read as a fallback if unset. Keep
`projectUrl` in `nuxt.config.ts` (not `app.config.ts`), because bundled
`app.config.ts` values override runtime config.

When a build bundles a snapshot, the consent route serves that bundled policy,
so changing the runtime URL only redirects consent saves. Rebuild to switch
policies, or use `manifest({ source: 'runtime' })`.

To reach your Inth endpoint from the Nitro server via a different internal
URL, set `NUXT_INTH_PROJECT_URL` (or legacy `NUXT_C15T_BACKEND_URL`); only the
server consent route reads it.
`nuxt generate` bakes config into static files, so changing the URL requires
regenerating.

## Options

### Backend and rendering

| Option | Default | What it does |
| --- | --- | --- |
| `projectUrl` | `NUXT_PUBLIC_INTH_PROJECT_URL`, then `NUXT_PUBLIC_C15T_BACKEND_URL` | Your Inth project URL. Used for manifest downloads and consent saves. |
| `mode` | `manifest()` | Policy source imported from `@inth/nuxt` (`manifest()`, `hosted()`, or `testing()`). `nuxt.config.ts` only; runtime overrides of `mode.type` or `mode.resolve` are ignored with a warning, while `NUXT_PUBLIC_INTH_MODE_MANIFEST_URL` and `NUXT_PUBLIC_INTH_MODE_PROJECT_URL` still apply at runtime. See [modes](#modes). |
| `routePrefix` | `'/api/inth'` | Mount path for `${routePrefix}/v1/consent/init` and `${routePrefix}/v1/consent/manifest` in `manifest()` mode. Set `false` to disable the route. `'/'` fails the build. `nuxt.config.ts` only. |
| `onBuildError` | `'runtime'` | Controls failed build-time manifest downloads in `manifest()` mode. `'runtime'` logs a warning and falls back to runtime fetching; `'fail'` stops `nuxt build` and `nuxt dev`. A missing project URL still stops `manifest()` mode because the browser needs it to save choices. `INTH_ON_BUILD_ERROR` overrides this option. Timeout is 10 seconds. |
| `timeoutMs` | `500` | Maximum wait in milliseconds for policy resolution during SSR. `false` or `Infinity` disables the timeout. |
| `initPrefetch` | `true` | Injects an early `/v1/consent/init` script on `ssr: false` pages in `hosted()` mode. Skipped when `consentSource`, `experiment`, or `hosted({ headers })` is set, or when Nitro auto-imports are off. Disable globally with `false` or per route with `inth: { initPrefetch: false }`. See [Content Security Policy](/docs/frameworks/nuxt/content-security-policy#allow-the-early-init-script). |
| `devtools` | `true` | Adds an Inth tab to Nuxt DevTools in development. Excluded from production builds. See [DevTools](/docs/frameworks/nuxt/components/dev-tools). |

### Modes

| Mode | Where the policy comes from |
| --- | --- |
| `manifest()` | Default. Downloads the manifest at build time and resolves policies on the server with no snapshot or resolver in the browser bundle. |
| `manifest({ source: 'runtime' })` | Fetches, caches, and background-refreshes the manifest on the server so policy edits apply without rebuilding. |
| `manifest({ snapshot })` | Uses a manifest object you import in `nuxt.config.ts`. Still requires `projectUrl` for saving choices. |
| `manifest({ resolve: 'browser' })` | Bundles the snapshot for browser resolution on `nuxt generate` static sites. Accepts `geoUrl` and `inputs`. Pair with `routePrefix: false`. |
| `hosted()` | Calls Inth's `/v1/consent/init` on every server render and on pages the server did not resolve. |
| `testing()` | Evaluates local rules in the browser without a project URL. Pass `testing({ policy })` to override defaults. Throws in production builds. |

`manifest()` also accepts `manifestUrl` (defaults to `${projectUrl}/v1/consent/manifest`).
See [rendering and deployment](/docs/frameworks/nuxt/rendering).

### Consent and storage

| Option | Default | What it does |
| --- | --- | --- |
| `consentCategories` | Policy categories | Limits categories shown in the dialog and widget within the policy's scope. |
| `vendors` | Unset | Lists declared vendors under their category with per-vendor switches. See [vendor consent](/docs/frameworks/nuxt/vendor-consent). |
| `storageConfig` | `{ storageKey: 'inth' }` | Cookie and localStorage key name, `crossSubdomain`, `defaultDomain`, and `defaultExpiryDays`. Keep identical across `nuxt.config.ts` and `app.config.ts`. |
| `reloadOnConsentRevoked` | `true` | Reloads the page when a save or one-click opt-out withdraws a granted category or vendor. Privacy signals and backend-synced opt-outs do not reload. With `persistence: false`, nothing reloads because a reload would discard the choice it was for. |
| `clearOnRevocation` | Unset | Deletes first-party cookies and storage keys for withdrawn categories. See [clear on revocation](/docs/frameworks/nuxt/clear-on-revocation). |
| `iab` | Off | Enables IAB TCF (`{}` is enough) and accepts publisher settings such as `publisherRestrictions`. Set it in `nuxt.config.ts` so pages prefetch the IAB banner. Unset, `false`, or `{ enabled: false }` causes `IABUnavailableError` under IAB policies with a vendor list. See [IAB TCF](/docs/frameworks/nuxt/iab). |

### Scripts, blocking, and events

| Option | Default | What it does |
| --- | --- | --- |
| `scripts` | Unset | Vendor scripts gated by consent category (`app.config.ts` only). See [scripts](/docs/frameworks/nuxt/scripts). |
| `networkBlocker` | Off | Holds matching `fetch` and XHR calls until allowed. See [network blocker](/docs/frameworks/nuxt/network-blocker). |
| `iframeBlocker` | On | Gates iframes carrying `data-src` and `data-category`. Set `false` to disable. See [embeds](/docs/frameworks/nuxt/embeds). |
| `nonce` | Unset | CSP nonce for loaded scripts and `<style id="inth-css-vars">`. See [Content Security Policy](/docs/frameworks/nuxt/content-security-policy). |
| `callbacks` | Unset | App-wide callbacks (`app.config.ts` only). See [callbacks](/docs/frameworks/nuxt/callbacks). |

### Appearance

| Option | Default | What it does |
| --- | --- | --- |
| `tokens` | Default theme | CSS variables written to `<style id="inth-css-vars">` in `<head>`. See [customize](/docs/frameworks/nuxt/customize#set-theme-tokens). |
| `presentation` | Policy defaults | The banner's `container`, `edgeStyle`, `blockUntilChoice` and action layout, under `presentation.prompt`. |
| `components` | Unset | Vue attributes such as `class` and `style` for named component parts. |
| `legalLinks`, `bannerLegalLinks`, `dialogLegalLinks` | None shown | Privacy policy links and which surfaces display them. |
| `hideBranding` and per-surface forms | `false` | Hides the "Consent by" tag. |
| `showTrigger` and `trigger*` | `false` | Configures the floating trigger. See [ConsentDialogTrigger](/docs/frameworks/nuxt/components/consent-dialog-trigger). |
| `disableAnimation` | `false` | Disables banner and dialog transitions. |
| `models`, `bannerModels`, `iabBannerModels`, `iabDialogModels` | Every model | Limits which policy models render each surface. |

## Verify

Run `nuxt dev` and request `/api/inth/v1/consent/init` in default `manifest()` mode to
confirm JSON returns the resolved policy. View the source of a page under an
opt-in policy and confirm `data-testid="consent-banner-root"` is in the HTML.
