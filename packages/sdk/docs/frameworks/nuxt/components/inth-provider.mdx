Render the globally registered `InthProvider` once in `app/app.vue` to serve
the right consent surfaces for each visitor's policy from SSR onward.

## Render `InthProvider` in `app.vue`

`@inth/nuxt` registers `InthProvider` globally, so add it beside `<NuxtPage />`
without an import:

<include src="../../../shared/examples/nuxt/root.mdx" />

`InthProvider` reads the runtime provided by the Nuxt module and ships its own
styles. Keep it in `app/app.vue` so it stays mounted across route changes.

The Nuxt module plugin already provides the runtime to every component;
`InthProvider` renders the stock consent UI surfaces. Render `<InthProvider />`
as a sibling rather than wrapping `<NuxtPage />`. Always use Nuxt's global
`InthProvider`, not the `@inth/vue/vue-plugin` export, so the banner renders
during SSR.

## What InthProvider renders

`InthProvider` picks surfaces based on the visitor's policy:

| Policy | Banner | Preferences |
| --- | --- | --- |
| Standard, opt-in, or opt-out | [`ConsentBanner`](/docs/frameworks/nuxt/components/consent-banner) | [`ConsentDialog`](/docs/frameworks/nuxt/components/consent-dialog) |
| IAB TCF with vendor list | [`IABConsentBanner`](/docs/frameworks/nuxt/components/iab-consent-banner) | [`IABConsentDialog`](/docs/frameworks/nuxt/components/iab-consent-dialog) |

It also renders [`ConsentDialogTrigger`](/docs/frameworks/nuxt/components/consent-dialog-trigger)
when `showTrigger: true` is configured.

In default `manifest()` or `hosted()` mode, the banner ships in the first
server HTML with no post-hydration layout shift. On prerendered and cached
routes, it mounts after browser resolution. See
[rendering](/docs/frameworks/nuxt/rendering).

IAB surfaces activate only when `iab` is enabled and the policy uses `iab`.
The banner, dialog, trigger, and IAB surfaces load as separate chunks: Nuxt
inlines SSR banner styles with `features.inlineStyles` so no external consent
stylesheet blocks first paint, loads the dialog chunk when the visitor
reaches for a banner button or the dialog opens (and keeps it mounted after
opening for close animations), and loads the trigger
chunk only when `showTrigger: true`.

## Theme tokens

The Nuxt plugin writes `tokens` (including defaults) into
`<style id="inth-css-vars">` in `<head>` on every page, carrying your `nonce`
if configured. Set token values in module options rather than a `:root` CSS
rule. See [set theme tokens](/docs/frameworks/nuxt/customize#set-theme-tokens).

## Props

| Prop | Type | Default | Behavior |
| --- | --- | --- | --- |
| `country` | `string` | Location from request headers | Overrides country and re-resolves the policy. |
| `region` | `string` | Location from request headers | Overrides region (such as `CA`) and re-resolves the policy. |
| `language` | `string` | Browser language | Overrides language and re-resolves to fetch copy in that language. |

Use `country` and `region` to preview regional policies locally (such as
`<InthProvider country="DE" />`), and bind `language` to your site's locale.
See [translations](/docs/frameworks/nuxt/translations).

## Compose the surfaces yourself

To place or configure `ConsentBanner`, `ConsentDialog`, and IAB components
directly, render them instead of `InthProvider`. See
[ConsentBanner](/docs/frameworks/nuxt/components/consent-banner#import-the-banner-in-place-of-inthprovider).
Never mount both `InthProvider` and individual surfaces together, or visitors
see two banners.

## Verify

Run `nuxt build` and `node .output/server/index.mjs`, then view page source
under an opt-in policy. Confirm `data-testid="consent-banner-root"` and
`<style id="inth-css-vars">` are in the HTML, Customize opens the choices in
the banner, and
rejecting stays closed after reload.
