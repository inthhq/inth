Add a consent banner to a server-rendered Nuxt app. Your server resolves each
visitor's policy in the first HTML response, and analytics wait until consent
allows them.

<Prompt title="Add Inth consent to this Nuxt app" description="Paste into Claude Code, Codex, Cursor or another coding agent at the root of your app.">
  Add Inth consent management to this server-rendered Nuxt app.

  1. Check that the app runs on a Nuxt server (`nuxt build`). If it uses `nuxt generate` for static hosting or sets `ssr: false`, stop and tell me.
  2. Install `@inth/nuxt` and `@inth/integrations`. Read `node_modules/@inth/nuxt/AGENTS.md`, then follow the Nuxt quickstart it links to, in order. Do not guess the API from memory.
  3. Set `NUXT_PUBLIC_INTH_PROJECT_URL` in `.env`. Ask me for my project URL. `NUXT_PUBLIC_INTH_PROJECT_URL` wins over any legacy `NUXT_PUBLIC_C15T_BACKEND_URL`.
  4. Register `'@inth/nuxt'` in `modules` in `nuxt.config.ts`. Keep `scripts` and `callbacks` out of `nuxt.config.ts`.
  5. Add `InthProvider` and `ConsentDialogLink` to `app/app.vue`, outside `<NuxtPage />`. Wrap third-party iframes in `ConsentGate`.
  6. Register every analytics and marketing script under `inth.scripts` in `app/app.config.ts` with the matching helper from `@inth/integrations`, carry over settings such as PostHog's `region` or `apiHost`, and remove old loaders including `@nuxt/scripts` trackers and `nuxt-gtag`. If a vendor has no helper, tell me.
  7. Run `nuxt build` and `node .output/server/index.mjs`. Check that `data-testid="consent-banner-root"` is in the server HTML, no vendor request fires before consent, rejecting survives a reload, and granting analytics loads PostHog.

  Then list the files you changed, any script still outside consent, and how you checked the requests.
</Prompt>

## Prerequisites

- A Nuxt app running on a Nuxt server (`nuxt build`). For `nuxt generate` or
  `ssr: false`, follow
  [deploy to static hosting](/docs/frameworks/nuxt/rendering#deploy-to-static-hosting).
  Not on Nuxt? See the [framework list](/docs/frameworks).
- An [Inth project](https://inth.com/dashboard/sign-up?framework=nuxt) with
  your site's origin in its trusted origins.

## Install the SDK

<CommandTabs command="@inth/nuxt @inth/integrations" mode="install" />

The components ship their own styles, so there is no stylesheet to import.

## Set the project URL

Add your Inth project URL (including any path prefix) to `.env` and your
host's build settings:

```sh title=".env"
NUXT_PUBLIC_INTH_PROJECT_URL=https://your-project.inth.app
```

This URL is public.
`NUXT_PUBLIC_INTH_PROJECT_URL` wins over any legacy
`NUXT_PUBLIC_C15T_BACKEND_URL`, which is read as a fallback if unset.

## Check it works

Run `nuxt build` and `node .output/server/index.mjs`, then open the site in a
private window on the DevTools Network tab.

1. Under an opt-in policy, view source and confirm
   `data-testid="consent-banner-root"` is in the HTML. No requests go to
   `posthog.com` or `youtube-nocookie.com`.
2. Click **Reject All** and reload. The banner stays closed and vendor
   requests stay absent.
3. Click **Privacy settings**, enable **Analytics**, and click **Save
   Settings**. PostHog loads and the video appears.
4. Open **Privacy settings**, disable **Analytics**, and save. The page
   reloads without PostHog or the video.

Inspect requests in the Network tab to confirm blocking; a visible banner
alone proves nothing. To preview an EU policy locally, pass
`<InthProvider country="DE" />` temporarily. See
[troubleshooting](/docs/frameworks/nuxt/troubleshooting) and
[verify consent](/docs/guides/verify-consent).
