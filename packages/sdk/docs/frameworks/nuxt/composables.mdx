Use `@inth/nuxt`'s auto-imported composables to check permissions, record
choices, or build custom consent UI across server and browser renders.

## Use composables without imports

Call consent composables directly inside `<script setup>` without importing
them:

Use `v-if`, not `v-show`, when gated content loads third-party resources. For
iframes use [`ConsentGate`](/docs/frameworks/nuxt/components/consent-gate),
and for vendor scripts configure `scripts` in `app/app.config.ts`. See
[scripts](/docs/frameworks/nuxt/scripts).

Import non-auto-imported composables (`useHasConsentPolicy()`,
`useHasConsentUi()`, `useHasConsentPreferences()`, `useIabTranslations()`)
from `#inth/composables`:

{/* example: fragment */}

```ts
import { useHasConsentPreferences } from '#inth/composables';
```

## Composables on the server

Composables work during SSR. In default `manifest()` or `hosted()` mode, they
return the visitor's resolved policy and stored choice so server HTML matches
hydration. On prerendered, cached, and `ssr: false` routes, they start with
optional categories denied and `useConsentSnapshot().value.policyPending` set
to `true` until browser resolution completes.
