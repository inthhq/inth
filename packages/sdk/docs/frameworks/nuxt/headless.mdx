Replace Inth's stock banner and dialog with your own Nuxt components while
keeping server-side policy resolution, script gating, and consent storage.

## When to go headless

Check [customize](/docs/frameworks/nuxt/customize) first if you only need
different colors, layout, or classes. Go headless when the consent UI must use
your own markup or design system components.

Headless replaces only the UI. `@inth/nuxt` still resolves policies, stores
choices, loads `scripts` from `app.config.ts`, and gates iframes.

## Write the consent UI

Render a banner while `activeUI` is `'banner'` and a preference form while it
is `'dialog'`. The module auto-imports every composable used here:

<include src="../../shared/examples/nuxt/headless-prompt.mdx" />

`useConsentSave()` records Accept All or Reject All and closes the banner by
setting `activeUI` to `null`. `useConsentDraft()` holds preference switches in
`values`, lists selectable categories in `displayedCategories`, and records
them on `save()`. Close preferences yourself after `save()` resolves. See
[build a preference form](/docs/frameworks/nuxt/composables#build-a-preference-form)
for every draft property.

Add focus trapping, a close button, and styles before shipping.

## Mount it instead of InthProvider

Replace `<InthProvider />` in `app/app.vue` with your component and keep a
control such as `ConsentDialogLink` to reopen preferences:

{/* example: fragment */}

```vue title="app/app.vue"
<template>
	<ConsentPrompt />
	<NuxtPage />
	<footer>
		<ConsentDialogLink />
	</footer>
</template>
```

When SSR resolves the policy (default `manifest()` or `hosted()`), your custom
component renders on the server with the visitor's policy just like
`InthProvider`.

## Show the buttons the policy requires

Policies vary in which buttons they require or forbid. A notice prompt
requires a dismiss action instead of Accept and Reject. Read `primaryActions`
and `actionGroups` from `useConsentPolicyActions('prompt')` rather than
hard-coding buttons, and call `useDismissNotice()` for notice prompts
(recording an acknowledgement, not consent).

Use `usePromptRequirement()` to check whether the policy asks for `'choice'`,
`'notice'`, or `'none'`.

## Verify the custom UI

Run through [verify consent](/docs/guides/verify-consent). Confirm Reject All
is as easy to reach as Accept All, preferences list the policy's categories,
and rejections persist across reloads.
