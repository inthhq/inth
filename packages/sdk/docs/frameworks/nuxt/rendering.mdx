Choose how `@inth/nuxt` resolves policies across server-rendered routes,
cached routes, static exports, and single-page apps.

## Pick the setup for your deployment

Configure `mode` (`manifest()`, `hosted()`, or `testing()` from `@inth/nuxt`)
and `routePrefix` under `inth` in `nuxt.config.ts`:

| Your deployment | `inth` options | Banner in first HTML |
| --- | --- | --- |
| Nuxt server rendering each request (`nuxt build`) | None (`mode` defaults to `manifest()` and `routePrefix` to `'/api/inth'`). See the [quickstart](/docs/frameworks/nuxt/quickstart). | Yes |
| Nuxt server with prerendered or cached routes (`prerender`, `swr`, `isr`, `cache`) | Same defaults. See [prerendered and cached routes](#prerendered-and-cached-routes). | No on cached routes, yes elsewhere |
| Policy edits without rebuilding | `mode: manifest({ source: 'runtime' })`. See [fetch the manifest at runtime](#fetch-the-manifest-at-runtime). | Yes |
| Static hosting (`nuxt generate`) | `mode: manifest({ resolve: 'browser' })` and `routePrefix: false`, or `mode: hosted()`. See [deploy to static hosting](#deploy-to-static-hosting). | No |
| Single-page app (`ssr: false`) | Same as static hosting. See [build a single-page app](#build-a-single-page-app-with-ssr-false). | No |

Set `mode` and `routePrefix` in `nuxt.config.ts` only; `app.config.ts` cannot
override them. Import mode factories from `@inth/nuxt` so they serialize as
plain data; passing browser transports throws during setup.

## Render each request on the server

By default, every server render reads the visitor's consent cookie and
location headers, resolves their policy from the bundled snapshot, and sends
the result with the HTML. The browser hydrates without an extra policy
request, and the browser bundle carries no resolver, snapshot, or policy
rules. The [quickstart](/docs/frameworks/nuxt/quickstart) and `examples/nuxt`
use this setup.

Server renders never set cookies; the visitor's subject ID (`sub_...`) is
written on their first save and read from cookies afterward.

When a visitor's stored choice or policy already allows vendor helper entries
in `scripts` (or for `alwaysLoad` entries when no prompt is required), SSR
appends an inline script at the end of `<body>` that starts those tags after
first paint, before hydration, and the script loader adopts them. Built-in
`@inth/integrations` helpers support this except Cloudflare Zaraz and Sentry,
which start after hydration along with custom scripts. Prerendered routes and
pages showing a prompt start nothing from HTML. Set
`scriptLoader: { serverStart: false }` under `inth` to start all scripts after
hydration instead.

The module mounts `${routePrefix}/**` (`/api/inth/**` by default), serving
`GET /api/inth/v1/consent/init` and `GET /api/inth/v1/consent/manifest`. SSR resolves through it
in-process via Nitro's local fetch, and the browser calls it on prerendered
routes or after an SSR timeout. Customize the path with `routePrefix`.

SSR waits up to `timeoutMs` (default 500 ms) for policy resolution. If runtime
fetching times out or fails, the page renders without consent UI, optional
categories stay denied, and the browser resolves the policy after hydration.

Because a server-rendered banner appears before hydration finishes, the stock
banner includes a small inline script before its buttons that captures any
Accept All, Reject All, dismiss, or Customize tap made during hydration.
Accept, reject, and dismiss hide the banner immediately; once hydrated, Inth
records the choice with the original tap timestamp and loads allowed scripts
(or opens the dialog for Customize).

### When the consent engine loads

When SSR prompts a new visitor to choose, the browser hydrates from server
state without loading the consent engine on initial load. Composables read
server state right away, and the engine (plus interactive banner code) loads
at the earliest of:

- All `<img fetchpriority="high">` elements finishing (or `window` `load` if
  none exist).
- The first pointer press, key press, or scroll outside the banner.
- App code calling an engine-only method such as `kernel.set.overrides()` or
  `clearRecords()`.
- 10 seconds after hydration.

Tapping Accept All or Reject All before the engine loads updates composable
state and starts allowed scripts in the same task, then stores the record,
fires `onChoiceRecorded` and `onPermissionsChanged`, and lets the engine send
the save once loaded. Clicking Customize loads the dialog without waiting for
the engine.

The browser loads the engine immediately (and SSR preloads it) for returning
visitors, notice prompts, privacy signals, IAB, experiments, `consentSource`,
`gpp`, `networkBlocker`, immediately runnable non-HTML scripts, and
prerendered, cached, or `ssr: false` routes.

First-load Inth code is grouped into one client chunk when building with
Rolldown 1.2+ and no custom `codeSplitting`, `advancedChunks`, or
`manualChunks` config.

### Without the consent route

Set `routePrefix: false` to omit the Nitro route. SSR still resolves from the
bundled snapshot, while browser fallbacks call Inth's `/v1/consent/init` directly.

### Ask the backend on every render

Set `mode: hosted()` to call Inth's `/v1/consent/init` on every server render without
bundling a snapshot or adding a server route:

{/* example: fragment */}

```ts title="nuxt.config.ts"
import { hosted } from '@inth/nuxt';

export default defineNuxtConfig({
	inth: { mode: hosted() },
	modules: ['@inth/nuxt'],
});
```

SSR forwards location, language, GPC, `user-agent`, and (over HTTPS or
loopback) the consent cookie alone. Because every render waits on Inth up to
`timeoutMs`, prefer `manifest()` or `manifest({ source: 'runtime' })`.

## Fetch the manifest at runtime

Set `manifest({ source: 'runtime' })` to skip the build-time fetch and let the
server fetch, cache, and background-refresh `${projectUrl}/v1/consent/manifest` so policy
edits apply without rebuilding:

{/* example: fragment */}

```ts title="nuxt.config.ts"
import { manifest } from '@inth/nuxt';

export default defineNuxtConfig({
	inth: { mode: manifest({ source: 'runtime' }) },
	modules: ['@inth/nuxt'],
});
```

Pass `manifest({ manifestUrl })` to fetch from a custom URL. The consent route
and SSR share the cache; only the first request after a cold start waits up to
`timeoutMs`.

## Prerendered and cached routes

Routes using `prerender`, `swr`, `isr`, or `cache` route rules serve shared
HTML to all visitors, so the module renders them without visitor cookies,
headers, or a banner. After hydration, the browser calls `/api/inth/v1/consent/init`
(or Inth's `/v1/consent/init` with `hosted()` or `routePrefix: false`), reads stored
choices, and displays the banner if required:

{/* example: fragment */}

```ts title="nuxt.config.ts"
export default defineNuxtConfig({
	routeRules: { '/blog/**': { swr: 3600 }, '/about': { prerender: true } },
});
```

Unmatched routes continue rendering per request with the banner in server
HTML. Until browser resolution completes, optional categories stay denied. If
localStorage holds a newer denial than the cookie read on the server, the
browser applies the denial.

## Deploy to static hosting

`nuxt generate` produces static files with no Nitro server, so `/api/inth`
does not exist and default `manifest()` logs a warning. Choose a browser
resolution mode instead:

- **`manifest({ resolve: 'browser' })` with `routePrefix: false`.** Embeds the
  manifest and English copy in the browser bundle (non-English copy loads on
  demand).
- **`hosted()`.** Calls Inth's `/v1/consent/init` directly from the browser so Inth
  resolves location.

<include src="../../shared/examples/nuxt-static/static-config.mdx" />

Run `nuxt generate` and deploy `.output/public`. Pages render without a banner
in static HTML and resolve in the browser after hydration.

With `manifest({ resolve: 'browser' })`, if your policy depends on location
and neither `inputs` nor `geoUrl` is set, the browser falls back to Inth's
`/v1/consent/init` on first visit rather than applying the unknown-location rule. To
resolve locally, pass `manifest({ resolve: 'browser', geoUrl: '/geo' })`
pointing to a same-origin endpoint returning `{ "country": "DE", "region": "BE" }`,
or use `hosted()`. Add your site's origin to your Inth project's trusted
origins so browser saves succeed.

## Build a single-page app with ssr: false

`ssr: false` disables server rendering so every page renders in the browser.
On static hosts, use the [static hosting](#deploy-to-static-hosting) setup
above (`examples/nuxt-static` demonstrates this). With a Nuxt server, default
`manifest()` also works by calling `/api/inth/v1/consent/init` from the browser.

In `hosted()` mode, the module injects a small inline `<head>` script on
`ssr: false` pages to start `/v1/consent/init` while HTML parses. Disable it globally
with `initPrefetch: false` or per route with
`routeRules: { '/path': { inth: { initPrefetch: false } } }` if a client
plugin modifies Inth options on that route.

See [Nuxt module](/docs/frameworks/nuxt/module#backend-and-rendering) for

## Verify your deployment

- **Request-time SSR.** View source under an opt-in policy and confirm
  `data-testid="consent-banner-root"` is present. Reject, reload, and confirm
  it stays closed.
- **Prerendered or cached routes.** Confirm `consent-banner-root` is absent
  from HTML source, the browser calls `/api/inth/v1/consent/init`, and rejection persists
  across reloads.
- **Static hosting.** Serve `.output/public` and check the Network tab:
  browser-resolved `manifest()` sends no `/v1/consent/manifest`, `/v1/consent/init`, or `/api/inth`
  request when location is unneeded; `hosted()` calls `/v1/consent/init` once per load.
  Finish with [verify consent](/docs/guides/verify-consent).
