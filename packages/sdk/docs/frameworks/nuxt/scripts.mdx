Register analytics and marketing scripts under `inth.scripts` in
`app/app.config.ts` so Inth loads them only while their category is allowed.

## Register vendor scripts

A consent banner does not stop `<script>` tags, `useHead`, or vendor Nuxt
modules. Remove those loaders and register `@inth/integrations` helpers in
`app/app.config.ts` instead. If you use `@nuxt/scripts` or `nuxt-gtag`, see
[migrate from `@nuxt/scripts`](#migrate-from-nuxtscripts) or
[migrate from `nuxt-gtag`](#migrate-from-nuxt-gtag).

<include src="../../shared/examples/nuxt/app-config.mdx" />

The module starts one script loader after hydration once stored choices and
privacy signals apply. Do not also call `createScriptLoader()`, or scripts
load twice. When consent or `alwaysLoad` already permits a built-in helper on
a server-rendered page, SSR starts that script before hydration and the loader
adopts its tag. See
[render each request on the server](/docs/frameworks/nuxt/rendering#render-each-request-on-the-server).

Always put `scripts` in `app/app.config.ts`, never `nuxt.config.ts`, because
module options serialize to JSON and strip functions. See
[integrations](/docs/integrations/overview) for every vendor helper.

## Register scripts from a component

For scripts determined at runtime, such as a tenant tag or route-specific
script, call the auto-imported `useScriptLoader()`. It shares the app's single
loader, prevents duplicates, and removes scripts on unmount. Pass a ref or
getter to reconcile updates automatically:

<include src="../../shared/examples/nuxt/script-loader.mdx" />

The returned handle provides `updateScripts(next)` and `dispose()`. Revocation
triggers a reload just like `app.config.ts` scripts. Under deferred first load
(see [rendering](/docs/frameworks/nuxt/rendering)), a runnable script loads
the consent engine immediately, and tapping Accept before the engine loads
still starts plain scripts right away.

## Embeds and other requests

- [Embeds](/docs/frameworks/nuxt/embeds): gate iframes with `ConsentGate` or
  the iframe blocker.
- [Network blocker](/docs/frameworks/nuxt/network-blocker): hold matching
  `fetch` and XHR calls until their category is allowed.

## When a visitor withdraws consent

Removing a `<script>` tag cannot stop code already running in memory. When a
save withdraws a granted category or vendor, Inth reloads the page so only
permitted code runs. Set `reloadOnConsentRevoked: false` to handle revocation
yourself, or use
[`onBeforeConsentRevocationReload`](/docs/frameworks/nuxt/callbacks#before-a-revocation-reload)
to run cleanup before reload.

Configure `clearOnRevocation` in `nuxt.config.ts` to delete first-party
cookies and storage keys when a category is denied. See
[clear on revocation](/docs/frameworks/nuxt/clear-on-revocation).

## Let visitors turn off one vendor

To let visitors allow a category while toggling individual vendors off,
declare them in `vendors`. Built-in `@inth/integrations` helpers already
include their vendor slug. See
[vendor consent](/docs/frameworks/nuxt/vendor-consent).

## Content Security Policy

Allow each vendor's script host in `script-src`. Because the module's `nonce`
option is fixed at build time, prefer host allowlists or per-request nonces
from `nuxt-security`. See
[Content Security Policy](/docs/frameworks/nuxt/content-security-policy).

## Migrate from `@nuxt/scripts`

`@nuxt/scripts` loads registry scripts on its own triggers regardless of Inth
consent, including `useScriptGoogleAnalytics()`, `scripts.registry` entries,
and components like `ScriptYouTubePlayer`. Move tracking vendors to Inth's
`scripts` and keep `@nuxt/scripts` only for
[necessary scripts](#keep-nuxtscripts-for-necessary-scripts).

### Remove useScriptTriggerConsent

Delete every `useScriptTriggerConsent` call and its `accept()` or `revoke()`
handlers so consent is never tracked in two places that can disagree or ignore
Global Privacy Control. Also remove `defaultConsent` and `consent.update()` on
Google registry scripts, because `gtag` and `googleTagManager` emit Consent
Mode v2 commands automatically.

### Keep your event calls

Stop calling registry composables for their `proxy` (doing so loads the script
via `@nuxt/scripts`) and call the vendor global from browser handlers or
`onMounted`:

| Before | After |
| --- | --- |
| `proxy.gtag(...)` from `useScriptGoogleAnalytics()` | `window.gtag?.(...)` |
| `proxy.dataLayer.push(...)` from `useScriptGoogleTagManager()` | `window.dataLayer?.push(...)`, or `window[name]` for a custom `dataLayer` |
| `proxy.fbq('track', ...)` from `useScriptMetaPixel()` | `metaPixelEvent(...)` from `@inth/integrations/meta-pixel` after checking marketing permission |

<include src="../../shared/examples/nuxt/nuxt-scripts-events.mdx" />

Before Inth loads a vendor, its global is undefined and optional chaining
safely drops the call.

### Move YouTube and Google Maps embeds

`ScriptYouTubePlayer` adds `dns-prefetch` or `preconnect` links to
`i.ytimg.com` and fetches thumbnails before consent; `ScriptGoogleMaps` adds a
`dns-prefetch` link to `maps.googleapis.com`. For standard embeds, wrap an
iframe in `ConsentGate` as in [embeds](/docs/frameworks/nuxt/embeds),
[YouTube](/docs/integrations/youtube), and
[Google Maps](/docs/integrations/google-maps). If you need the YouTube Player
API or Maps JavaScript API, wrap the `@nuxt/scripts` component inside
`ConsentGate` so its tags and requests wait for consent.

### Keep @nuxt/scripts for necessary scripts

You can keep `@nuxt/scripts` for strictly necessary first-party scripts or
essential checkout SDKs such as Stripe that do not require consent under your
policy.

## Migrate from `nuxt-gtag`

`nuxt-gtag` injects `gtag.js` on load unless `initMode: 'manual'` is set,
bypassing Inth. Replace its config and composables with `gtag`:

| `nuxt-gtag` | Inth |
| --- | --- |
| `gtag.id` in `nuxt.config.ts` | `gtag({ id, category: 'measurement' })` in `app/consent-scripts.ts` |
| `gtag.config` | `config` option on `gtag` |
| `gtag.tags` with multiple IDs | One `gtag` helper with extra destinations configured in Google tag settings, or see [tags with their own settings](#tags-with-their-own-settings) |
| `gtag.initCommands` with `consent` `default` | Delete; the helper sends Consent Mode `default` automatically |
| `initMode: 'manual'` and `useGtag().initialize()` | Delete; for dynamic runtime IDs use a [custom integration](/docs/integrations/building-integrations) |
| `useGtag().gtag(...)` | `window.gtag?.(...)` |
| `useTrackEvent(name, params)` | `window.gtag?.('event', name, params)` |
| `useGtag().disableAnalytics()` and `enableAnalytics()` | Delete and set `loadMode: 'after-consent'` if you want zero requests before consent. See [stop all requests until consent](#stop-all-requests-until-consent) |
| `enabled: false` per environment | Omit the helper from `scripts` in that environment |
| `url`, `loadingStrategy` | No equivalent; loads `gtag.js` asynchronously from `googletagmanager.com` |

Register only one `gtag` helper (every `gtag` helper shares script ID `gtag`):

<include src="../../shared/examples/nuxt/nuxt-gtag-scripts.mdx" />

Register `scripts` in `app/app.config.ts` as in
[register vendor scripts](#register-vendor-scripts), pick a
[load mode](#choose-when-google-loads), remove `'nuxt-gtag'` and `gtag` from
`nuxt.config.ts`, and uninstall `nuxt-gtag`. Run `nuxt typecheck` to find any
remaining `useGtag` or `useTrackEvent` calls, and call `window.gtag` only in
browser code.

### Stop all requests until consent

While `disableAnalytics()` set `ga-disable-<ID>` to silence Analytics, `gtag`
defaults to `loadMode: 'always'`, which loads `gtag.js` early with denied
Consent Mode v2 defaults (sending cookieless pings). Turning Google off with
[vendor consent](/docs/frameworks/nuxt/vendor-consent) sends the same denied
signals. To send zero Google requests before opt-in, set
`loadMode: 'after-consent'`.

### Tags with their own settings

The built-in `gtag` helper sends one `config` command and gates on one
`category`. If you have multiple `gtag.tags` with distinct `config` objects or
mix Analytics with Google Ads or Floodlight IDs that need separate categories,
replace `gtag` with a
[custom integration](/docs/integrations/building-integrations) following
[load before consent and signal the vendor](/docs/integrations/building-integrations#load-before-consent-and-signal-the-vendor).
To hold `gtag.js` until either category is granted, omit `alwaysLoad` and set
`category: { or: ['measurement', 'marketing'] }`, mapping `measurement` to
`analytics_storage` and `marketing` to `ad_storage`, `ad_user_data`, and
`ad_personalization`.

## Send your own analytics events

`useEventDispatcher()` is auto-imported. It routes events to registered
`scripts` and checks consent before sending. Watch `route.fullPath` to send
pageviews:

<include src="../../shared/examples/nuxt/analytics-events.mdx" />

Call `events.track('sign_up', { method: 'email' })` from event handlers.
`track` forwards to every registered integration with an event API and drops
events while measurement is denied. `pageview` targets only integrations in
`pageviews`, records the initial path without sending, and shares history
across dispatchers. See
[send events only to allowed integrations](/docs/integrations/overview#send-events-only-to-allowed-integrations).

## Verify gating

Open a page in a private window with the Network tab open under an opt-in
policy. Confirm vendor requests stay absent, allow one category and confirm
only its vendors load, then withdraw it and confirm the page reloads without
the vendor. See [verify consent](/docs/guides/verify-consent).
