Diagnose and fix Nuxt-specific SSR, manifest, script loading, and static
deployment issues with `@inth/nuxt`.

## Why is there no banner?

**Check.** Open [DevTools](/docs/frameworks/nuxt/components/dev-tools) to
inspect the matched policy (`useConsentSnapshot().value.policyRule.prompt`)
and check the init request in the Network tab.

**Fix.** Check these causes in order:

1. **The matched policy requires no banner.** Policies with `prompt: 'none'`
   (common in opt-out regions) show no banner. See
   [why the banner may be absent](/docs/concepts/policies#why-the-banner-may-be-absent).
2. **`InthProvider` unmounts on navigation.** Place `<InthProvider />` in
   `app/app.vue`, outside `<NuxtPage />`.
3. **Policy resolution failed.** Confirm `/api/inth/v1/consent/init` (default
   `manifest()`) or Inth's `/v1/consent/init` (`hosted()`) returns 200. While resolution
   fails, Inth hides the UI and denies optional categories.
4. **A choice is already stored.** Clear the `inth` cookie and localStorage
   key, or test in a private window.

## The page throws IABUnavailableError

**Check.** Nuxt renders its error page with code `INTH_IAB_UNAVAILABLE`
("inth: this visitor's policy uses IAB TCF, but `iab` is not set."). The
visitor matched an `iab` policy returning a vendor list, but `iab` is unset,
`false`, or `{ enabled: false }`. SSR fails with HTTP 500; prerendered and
`ssr: false` pages show the error page after browser resolution.

**Fix.** Set `inth: { iab: {} }` in `nuxt.config.ts` if your site uses IAB
TCF (see [IAB TCF](/docs/frameworks/nuxt/iab)). Otherwise, remove the `iab`
model from that regional policy in Inth.

## The banner is not in the server HTML

**Check.** Only request-time SSR with `manifest()` or `hosted()` puts the
banner in server HTML. `manifest({ resolve: 'browser' })`, `testing()`,
prerendered/cached routes (`prerender`, `swr`, `isr`, `cache`), `nuxt
generate`, and `ssr: false` resolve in the browser. Also check server logs for
SSR timeouts (default `timeoutMs` is 500 ms).

**Fix.** Render the route at request time with `manifest()` or `hosted()`, or
raise `timeoutMs` if runtime fetching is slow.

## The banner comes back after a visitor rejects

**Check.** Look for a failed `POST /v1/consent/records` request in the Network tab, a
mismatched `storageConfig.storageKey` between `nuxt.config.ts` and
`app.config.ts`, or an upstream CDN caching SSR HTML without a Nuxt route
rule.

**Fix.** Add your site's origin to your Inth project's trusted origins if
CORS fails, use identical `storageKey` values in both config files, and bypass
CDN HTML caching or configure
[prerendered and cached routes](/docs/frameworks/nuxt/rendering#prerendered-and-cached-routes).

## Scripts never load, or load before consent

**Check.** Verify `scripts` is not inside `nuxt.config.ts` (which strips
functions), confirm placeholder vendor IDs like `phc_your_project_key` are
replaced, and search for leftover loaders such as `@nuxt/scripts`,
`nuxt-gtag`, or `useHead`.

**Fix.** Move `scripts` into `app/app.config.ts`, set real vendor IDs, and
remove duplicate loaders.

## `nuxt build` or `nuxt dev` can't fetch the manifest

**Check.** In default `manifest()` mode, the module fetches
`${projectUrl}/v1/consent/manifest` with a 10-second timeout. By default
(`onBuildError: 'runtime'`), a failed fetch logs a warning starting with
`could not fetch the consent manifest from <url>` and falls back to runtime
fetching; with `onBuildError: 'fail'` or `INTH_ON_BUILD_ERROR=fail`, it stops
the build. Check the cause in parentheses:

- `fetch failed` or `no response within 10 seconds`: the build environment
  cannot reach your Inth project URL.
- `/v1/consent/manifest responded 404` (or another status): verify your project URL and
  any path prefix.
- `returned an invalid consent manifest`: the URL did not return a valid
  manifest.
- `manifest() needs a backend URL` (or `manifest({ snapshot }) still needs a
  backend URL`): neither `projectUrl` nor `NUXT_PUBLIC_INTH_PROJECT_URL` (falling
  back to `NUXT_PUBLIC_C15T_BACKEND_URL`) is set. Both `nuxt build` and `nuxt dev`
  stop because the browser needs a URL to save choices.
- `build-time manifests require an absolute upstream URL`: `projectUrl` or
  `manifestUrl` is relative while `onBuildError: 'fail'` is set.

**Fix.** Set `NUXT_PUBLIC_INTH_PROJECT_URL` (falling back to
`NUXT_PUBLIC_C15T_BACKEND_URL` if unset) or `inth.projectUrl` to your absolute
Inth project URL. To deploy during an outage when `onBuildError: 'fail'` is
set, run with `INTH_ON_BUILD_ERROR=runtime`, or switch to
`mode: manifest({ source: 'runtime' })`. `nuxt prepare` skips the fetch so
installs work offline.

## Policy edits don't show up

**Check.** Bundled manifests fix the policy at build time; changing
`NUXT_PUBLIC_INTH_PROJECT_URL` on a running server redirects consent saves,
not the bundled policy.

**Fix.** Rebuild (bypassing CI build caches) after editing policies,
translations, or vendors in Inth, or set
`mode: manifest({ source: 'runtime' })`.

## Static hosting returns 404 for /api/inth/v1/consent/init

**Check.** Static hosts have no Nitro server, so `/api/inth/v1/consent/init` does not
exist after `nuxt generate`.

**Fix.** Configure `mode: manifest({ resolve: 'browser' })` with
`routePrefix: false`, or `mode: hosted()`, as shown in
[deploy to static hosting](/docs/frameworks/nuxt/rendering#deploy-to-static-hosting),
and add your site's origin to your Inth project's trusted origins.

## The module throws "`inth.mode` in nuxt.config.ts is a transport"

**Check.** `nuxt.config.ts` imported `manifest`, `hosted`, or `testing` from
`@inth/vue/vue-plugin` instead of `@inth/nuxt`.

**Fix.** Import mode factories from `@inth/nuxt`, which returns serializable
plain data.

## Old module options have no effect

**Check.** `nuxt.config.ts` uses removed options such as `manifest`,
`manifestUrl`, `manifestSnapshot`, `buildManifest`, `geoUrl`, `initRoute`, or
`manifestRoute`.

**Fix.** Replace them with `mode` and `routePrefix`:

| Old option | Current option |
| --- | --- |
| `manifest: 'server'` | Omit (`manifest()` is default) |
| `manifest: 'client'` | `mode: manifest({ resolve: 'browser' })` |
| `manifest: false` | `mode: hosted()` |
| `manifestUrl`, `geoUrl`, `manifestSnapshot` | `manifest({ manifestUrl })`, `manifest({ geoUrl })`, `manifest({ snapshot })` |
| `buildManifest: false` | `mode: manifest({ source: 'runtime' })` |
| `buildManifest: true` | `onBuildError: 'fail'` |
| `initRoute`, `manifestRoute` | `routePrefix` |
| `NUXT_PUBLIC_C15T_MANIFEST_URL`, `NUXT_C15T_MANIFEST_URL` | `mode: manifest({ manifestUrl })` in `nuxt.config.ts` |
| `domain` | Omit (saves use page hostname) |
| `ConsentPreferencesLink` | `ConsentDialogLink` |
| `ConsentFrame` | `ConsentGate` |

For shared package and API renames, see [migrate from c15t](/docs/migrate-from-c15t).

## Every first visit calls /v1/consent/init on a static site

**Check.** With `manifest({ resolve: 'browser' })`, the browser has no geo
headers, so regional policies fall back to Inth's `/v1/consent/init` on first visit.

**Fix.** Pass `geoUrl` to `manifest()` pointing to a same-origin endpoint
returning `{ country, region }`, or switch to `hosted()`.

## A composable throws "Kernel not found"

**Check.** A composable ran outside the Nuxt app context, such as in a
`server/` route or plain module.

**Fix.** Call consent composables inside a component's `setup`.

## Every visitor resolves the same location

**Check.** No trusted geo header reached Nuxt, or a test middleware added
`x-inth-country`.

**Fix.** Configure trusted platform headers at your CDN or edge as described
in [geography headers](/docs/frameworks/nuxt/geography-headers).
