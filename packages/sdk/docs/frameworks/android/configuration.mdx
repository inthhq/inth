Pass `NativeConfig` to `InthAndroid.install` once during app startup. The [Android quickstart](/docs/frameworks/android/quickstart) uses hosted Inth policy with Android's default storage and lifecycle services.

## Set your Inth project URL

The Android SDK connects to Inth hosted projects only. Set `backendUrl` to the project URL from your Inth dashboard, such as `https://your-project.inth.app`. The app fetches policy from that project and sends consent records to it.

`InthAndroid.install` normalizes `backendUrl` to `https://your-project.inth.app`:

- A missing scheme defaults to `https`, so `your-project.inth.app` works.
- Trailing slashes and surrounding whitespace are trimmed, and scheme and host are lowercased.
- Any other host, `http`, a port, a path, a query, a fragment, or credentials are refused.

An invalid value throws `InthProjectUrlException` with `reason` (`empty`, `malformed`, `scheme`, `credentials`, `host`, `port`, `path`, or `query`) and a descriptive message:

{/* example: fragment */}

```txt
backendUrl must be the project URL from your Inth dashboard, such as https://your-project.inth.app. Got "https://consent.example.com": the host must be a project host under inth.app.
```

The installer handles HTTP transport, foreground refresh, and reconnect retry. With an [offline policy](/docs/frameworks/android/offline), it queues offline choices and delivers them on reconnect.

## Run without sending records

Set `NativeConfig(dryRun = true)` in development and CI. Prompts, storage, gates, and consent signals work normally, while consent records are dropped instead of queued or sent. `identify` and `logout` update local state only, and saves return `ok = true` with `queued = false`.

The app still fetches live policy from `/v1/consent/init` unless paired with `bundledPolicy` or `policy`:

{/* example: fragment */}

```kotlin
InthAndroid.install(
	context,
	NativeConfig(
		backendUrl = "https://your-project.inth.app",
		dryRun = BuildConfig.DEBUG,
	),
)
```

Read your app's own `BuildConfig.DEBUG` because the SDK ships as release AARs. At runtime, the installer checks `FLAG_DEBUGGABLE`; non-debuggable builds throw `IllegalStateException` and install no engine. In debuggable builds, `dryRun` also allows any `https` URL or `http` on `localhost`, `127.0.0.1`, or `[::1]` with a port and path.

## Set the categories your app uses

Available `ConsentCategory` values:

| Value | Purpose |
| --- | --- |
| `NECESSARY` | Required app functions (always permitted). |
| `FUNCTIONALITY` | Optional functionality. |
| `EXPERIENCE` | Optional experience features. |
| `MEASUREMENT` | Analytics and usage measurement. |
| `MARKETING` | Advertising and marketing features. |

`consentCategories` declares your app's scope; the resolved policy controls what is offered and permitted. When omitted or empty, strict policies offer their full scope while permissive policies offer `NECESSARY` with an acknowledgement notice. Declare explicit categories whenever your app integrates optional SDKs.

## Use manifest startup instead

For category consent with default platform services, the bundled AndroidX Startup initializer can install Inth before the first Activity. Add metadata in `AndroidManifest.xml` instead of calling `InthAndroid.install`:

{/* example: fragment */}

```xml title="app/src/main/AndroidManifest.xml"
<application>
	<meta-data android:name="com.inth.BACKEND_URL" android:value="https://your-project.inth.app" />
	<meta-data android:name="com.inth.CATEGORIES" android:value="necessary,measurement,marketing" />
</application>
```

Without a valid project URL, the initializer leaves Inth inactive and optional gates closed.

Use explicit installation in `Application.onCreate` when configuring IAB identity or custom startup options. Repeated installation keeps the first engine without updating configuration. To disable automatic startup while keeping other AndroidX Startup initializers intact, remove `InthInitializer`:

{/* example: fragment */}

```xml title="app/src/main/AndroidManifest.xml"
<provider
	android:name="androidx.startup.InitializationProvider"
	android:authorities="${applicationId}.androidx-startup"
	tools:node="merge">
	<meta-data android:name="com.inth.android.InthInitializer" tools:node="remove" />
</provider>
```

Add `xmlns:tools="http://schemas.android.com/tools"` to the manifest root. Disabling `InthInitializer` does not affect vendor auto-initializers; disable those separately.

## Native configuration reference

| Setting | Purpose |
| --- | --- |
| `backendUrl` | Required. Project URL from your Inth dashboard. |
| `dryRun` | Development and CI switch that drops consent records (default `false`; refused in non-debuggable builds). |
| `domain` | Domain reported with consent records (defaults to the project URL host). |
| `consentCategories` | App category scope. |
| `vendors` | Optional IAB vendor scope (omitting keeps the served list). |
| `iab` | Registered CMP identity and publisher settings for an IAB policy. |
| `iabListMaxAgeMs` | Maximum age of IAB disclosures (default 7 days). |
| `bundledPolicy` | Build-time manifest used when no live or cached `/v1/consent/init` response exists. |
| `policy` | In-code `ConsentPolicy` resolved on-device without calling `/v1/consent/init`; records still go to `backendUrl`. Cannot mix with `bundledPolicy`. |
| `overrides` | Country, region, language, or GPC inputs for QA. |
| `detectedGpc` | Real platform GPC signal input. |
| `extraHeaders` | App-owned HTTP transport headers. |
| `maxPendingSaves` | Durable delivery queue cap (up to 20). |
| `platform` | Platform label sent in `x-inth-platform` as `<platform>-><sdkVersion>` (defaults to `android`). |

Keep `platform` as `android` in Kotlin and Java apps. In a React Native app that disables `AUTO_BOOTSTRAP` and installs natively, set `platform = InthProtocol.PLATFORM_REACT_NATIVE` (`rn`); automatic React Native startup sets `rn` automatically. Pass `null` to omit the header.

Matching manifest keys use the `com.inth.` prefix: `BACKEND_URL`, `DRY_RUN`, `BACKEND_DOMAIN`, `CATEGORIES`, `POLICY_RESOURCE` (bundled asset path), and `POLICY_RULES` (in-code JSON asset path; never declare both).

Manifest startup rejects invalid project URLs, `DRY_RUN` in non-debuggable builds, and retired keys (`com.inth.MODE`, `com.inth.BACKEND_INIT_URL`). It logs an error under the `inth` tag and leaves the engine uninstalled (every read answers deny-all). Remove retired keys and use `com.inth.DRY_RUN` in debug builds.

## Handle identity and reset

`Inth.identify(KernelUser(...))` links the installation to an external account, and `Inth.logout()` detaches it without creating a new subject or deleting backend audit records. Recheck gates after identity transitions because IAB authority may retire.

For explicit withdrawal, save `CommitIntent.Necessary` and check the commit result. To reset local consent and re-resolve policy, call `Inth.current?.reset()`. `Inth.uninstall()` only clears the process singleton without touching stored consent. Neither is a backend account-deletion API.

## Handle policy or storage failures

`Inth.decision(category)` distinguishes `PENDING`, `DENIED`, and `GRANTED`. Keep optional collection off while policy or storage is unavailable, keep necessary features usable, and register a retained `onError` callback. Never show a save confirmation after a durable write failure. See [Save a category form](/docs/frameworks/android/headless#save-a-category-form) and [Verify mobile consent](/docs/frameworks/android/verify).
