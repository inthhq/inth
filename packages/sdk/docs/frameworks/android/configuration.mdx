Pass `NativeConfig` to `InthAndroid.install` once during app startup. The
[quickstart](/docs/frameworks/android/quickstart) uses hosted Inth policy and
Android's default storage and lifecycle services.

## Set your Inth project URL

The Android SDK works only with Inth hosted projects. `backendUrl` is the
project URL from your Inth dashboard, such as `https://your-project.inth.app`.
The app fetches policy from that project and sends consent records to it.
There is no self-hosted backend, no mode without a backend and no `initUrl`
on mobile.

`InthAndroid.install` checks the value and uses its normal form,
`https://your-project.inth.app`:

- A missing scheme means `https`, so `your-project.inth.app` works.
- Trailing slashes and surrounding whitespace are dropped, and the scheme and
  host are lowercased.
- Another host, `http`, a port, a path, a query, a fragment, or a username or
  password is refused.

A refused value throws `InthProjectUrlException`. Its `reason` is one of
`empty`, `malformed`, `scheme`, `credentials`, `host`, `port`, `path` or
`query`, and its message quotes your value:

{/* example: fragment */}

```txt
backendUrl must be the project URL from your Inth dashboard, such as https://your-project.inth.app. Got "https://consent.example.com": the host must be a project host under inth.app.
```

The installer handles HTTP transport, foreground refresh and reconnect retry.
With an [offline policy](/docs/guides/mobile-offline), it delivers queued
choices and refreshes policy when the app reconnects.

## Run without sending records

`NativeConfig(dryRun = true)` is for development and CI. The prompt, storage,
gates and consent signals work as normal. The engine drops consent records
instead of queueing or sending them, and `identify` and `logout` change local
state and send nothing. A save returns `ok` true with `queued` false.

The app still fetches policy from `/init`, so you see your project's real
policy. With `bundledPolicy` or `policy`, a dry-run launch needs no network.

{/* example: fragment */}

```kotlin
InthAndroid.install(
	context,
	NativeConfig(
		backendUrl = "https://your-project.inth.app",
		dryRun = BuildConfig.DEBUG,
	),
)
```

Use your app's own `BuildConfig`. The SDK ships as release AARs, so it cannot
read its own build type. It checks the host app's `FLAG_DEBUGGABLE` at
runtime. An app that is not debuggable refuses `dryRun`:
`InthAndroid.install` throws `IllegalStateException` and installs no engine.

In a debuggable app, `dryRun` also lets `backendUrl` be any `https` URL, or
`http` on `localhost`, `127.0.0.1` or `[::1]`, with a port and a path.

## Set the categories your app uses

The quickstart declares necessary, measurement and marketing. The available
`ConsentCategory` values are:

| Value | Use |
| --- | --- |
| `NECESSARY` | Required app functions. Always permitted. |
| `FUNCTIONALITY` | Optional functionality. |
| `EXPERIENCE` | Optional experience features. |
| `MEASUREMENT` | Analytics and usage measurement. |
| `MARKETING` | Advertising and marketing features. |

`consentCategories` declares your app's scope. The resolved policy still
controls what is offered and permitted. Declaring measurement does not grant it.

When scope is absent or empty, strict policies offer their full scope;
permissive policies offer necessary-only scope with an acknowledgement prompt.
Use an explicit list when the app integrates known optional categories.

## Use manifest startup instead

For category consent with default platform services, the bundled AndroidX
Startup initializer can install Inth before the first Activity. In that setup,
provide application metadata instead of the quickstart's explicit
`installConsent` call:

{/* example: fragment */}

```xml title="app/src/main/AndroidManifest.xml"
<application>
	<meta-data android:name="com.inth.BACKEND_URL" android:value="https://your-project.inth.app" />
	<meta-data android:name="com.inth.CATEGORIES" android:value="necessary,measurement,marketing" />
</application>
```

Change the project URL before building. The library manifest supplies the Inth
initializer registration. With no usable project URL, the initializer leaves
Inth inactive and optional gates closed.

Use explicit installation when the app supplies IAB identity or other
app-owned configuration. Repeated installation retains the first
engine; it does not update its configuration. Remove only Inth's initializer
metadata if you need to suppress automatic installation, preserving other
AndroidX Startup users:

{/* example: fragment */}

```xml title="app/src/main/AndroidManifest.xml"
<provider
	android:name="androidx.startup.InitializationProvider"
	android:authorities="${applicationId}.androidx-startup"
	tools:node="merge">
	<meta-data android:name="com.inth.android.InthInitializer" tools:node="remove" />
</provider>
```

Declare `xmlns:tools="http://schemas.android.com/tools"` on the manifest root
when using this override. Disabling Inth's initializer does not disable vendor
initializers. Configure each optional SDK's startup separately.

## Native configuration reference

| Setting | Purpose |
| --- | --- |
| `backendUrl` | Required. The project URL from your Inth dashboard. |
| `dryRun` | Development and CI switch that drops consent records. Defaults to false. A build that is not debuggable refuses it. |
| `property` | Property each consent record names. Defaults to the application ID, and is sent in lowercase. |
| `consentCategories` | App category scope. |
| `vendors` | Optional IAB vendor scope. Absent or empty keeps the served list. |
| `iab` | Registered CMP identity and publisher settings for an IAB policy. |
| `iabListMaxAgeMs` | Maximum age of IAB disclosures, seven days by default. |
| `bundledPolicy` | Manifest bundled at build time, used when no live or cached `/init` response is available. |
| `policy` | `ConsentPolicy` kept in source control. The device resolves it and never calls `/init`; records still go to `backendUrl`. It does not mix with `bundledPolicy`. |
| `overrides` | Country, region, language or GPC inputs for controlled QA. |
| `detectedGpc` | A GPC signal supplied by a real platform integration. |
| `extraHeaders` | App-owned transport headers. |
| `maxPendingSaves` | Durable delivery queue limit, up to 20. |
| `platform` | The app type the backend records for each request. Defaults to `android`. |

`platform` labels requests in the `x-inth-platform` header, as
`<platform>-><sdkVersion>`. Keep the default `android` in a Kotlin or Java app.
In a React Native app that installs the engine itself, with `AUTO_BOOTSTRAP`
off, set `platform = InthProtocol.PLATFORM_REACT_NATIVE` (`rn`). A React Native
app that keeps the automatic startup already sends `rn`. Set `null` to send no
platform header. The value is attribution only and changes no consent decision.

The corresponding manifest keys are `com.inth.BACKEND_URL`, `DRY_RUN`,
`BACKEND_PROPERTY`, `CATEGORIES`, `POLICY_RESOURCE` and `POLICY_RULES`, with the
same `com.inth.` prefix. `POLICY_RESOURCE` names a bundled manifest in app
assets, and `POLICY_RULES` names an asset holding in-code policy rules as
JSON. Declare one of the two, never both. Native configuration supports more
options than manifest startup.

Manifest startup refuses a project URL that breaks the rule above, `DRY_RUN`
in an app that is not debuggable, and the retired keys `com.inth.MODE` and
`com.inth.BACKEND_INIT_URL`. It logs one error under the `inth` tag and
leaves the engine uninstalled, so every read answers deny-all. Remove the
retired keys. Use `com.inth.DRY_RUN` in development and CI in place of
`com.inth.MODE`. `com.inth.BACKEND_INIT_URL` has no replacement, because the
app fetches policy from the project URL.

## Handle identity and reset

`Inth.identify(KernelUser(...))` associates the installation with your app's
external account. `Inth.logout()` detaches that identity. Neither creates a new
Inth subject or deletes the backend audit trail. Recheck current gates after
identity changes; IAB authority may be retired and a new choice required.

For an explicit withdrawal, save `CommitIntent.Necessary` and inspect the commit
result. For a start-over control, call the installed kernel's
`Inth.current?.reset()`. This resets local consent and resolves policy again.
`Inth.uninstall()` only drops the singleton for teardown and leaves persisted
consent unchanged. Neither operation is a backend account-deletion API.

## Handle a policy or storage failure

`Inth.decision(category)` distinguishes `PENDING`, `DENIED` and `GRANTED`.
Keep optional collection off while policy or storage is unavailable. Let the
person continue using necessary app functions and offer retry where appropriate.

Listen for native errors using a retained `onError` callback. Do not replace a
failed durable save with an in-memory success message. See
[headless saves](/docs/frameworks/android/headless#save-a-category-form) for
the result contract and [mobile verification](/docs/guides/mobile-verify) for
failure and recovery checks.
