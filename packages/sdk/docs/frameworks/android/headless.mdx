Build custom Compose consent screens using the unstyled headless blocks in `com.inth.consentui.headless`. They decide when a prompt is owed, manage drafts and saves, supply translated copy, and wire TalkBack and hardware Back while leaving layout, typography, color, and motion to your app.

## Install before optional SDKs

Follow the dependency and installation steps in the [Android quickstart](/docs/frameworks/android/quickstart). The headless blocks ship in `inth-consent-ui` alongside the stock screens; release code shrinking removes unused stock screens automatically. Call `InthAndroid.install` before starting optional SDKs and disable vendor auto-initializers.

Omit `InthConsent` and `attachConsent` when rendering your own UI. Your app owns the layout, privacy policy link, and standing Privacy settings entry.

## Gate content on a permission

`ConsentGate` renders its content only while the committed decision allows it. An unresolved policy evaluates as not allowed:

{/* example: fragment */}

```kotlin
ConsentGate(ConsentCategory.MARKETING, fallback = { AdPlaceholder() }) { AdBanner() }
ConsentGate(vendorId = 755, purposeId = 1) { GoogleAds() }
ConsentGate({ it.isCustomVendorAllowed("internal-ads") }) { HouseAds() }
```

Use the first form for a category, the second for an IAB vendor and purpose (with optional `basis` for legitimate interest), and the third for any predicate on the core (such as a single purpose, custom partner, or Additional Consent provider). `ConsentReady` renders once a policy has resolved.

## Show your own first prompt

Create one `ConsentDraft` and pass it to both blocks. `HeadlessConsentPrompt` renders its content only while the resolved policy owes a prompt:

<include src="../../shared/examples/native/examples/consent-demo/android-headless-prompt.mdx" />

`ConsentPromptScope` supplies the copy and actions to wire:

| Member | Purpose |
| --- | --- |
| `isNotice` | `true` for a notice to acknowledge, `false` for a consent choice. |
| `title`, `description`, `detail`, `reason` | Localized copy in the policy language (`reason` explains re-prompts). |
| `iab` | Required IAB first-layer copy under a TCF policy. |
| `acceptAll()`, `rejectAll()`, `acknowledge()` | One-tap saves that dismiss the prompt after storage succeeds. |
| `openPreferences()` | Calls your `onOpenPreferences` callback. |
| `isStale`, `reload()` | Set when another surface saved after this prompt loaded. Show `iabCopy.appSettingsChanged` and wire `reload()`. |
| `listUnavailable`, `listOutdated`, `refresh()` | Set when the IAB vendor list is stale or offline. Show `listOutdated`, keep Reject all, hide Accept all, and wire `refresh()`. |
| `acceptAllLabel`, `rejectAllLabel`, `customizeLabel`, `acknowledgeLabel`, `privacyPolicyLabel` | Localized button and link labels. |

The block intercepts hardware Back while a save runs and on an IAB first layer, and defers Back to an open preferences block sharing the same draft. `rememberConsentDraft()` keeps the draft in composition; construct `ConsentDraft(core, viewModelScope)` in a ViewModel to survive rotation, calling `close()` in `onCleared`.

## Build a preferences screen with a draft

`HeadlessConsentPreferences` wraps your preferences screen and exposes `categories` with titles, descriptions, lock state, and switch bindings:

<include src="../../shared/examples/native/examples/consent-demo/android-headless-preferences.mdx" />

Hide the switch when `locked` is `true` and render `lockedLabel` ("Always on" for `necessary`, or "Off" plus `note` when GPC or a strict policy restricts the category). `enabled` turns `false` while saving, while stale, or while an IAB list is uneditable.

Edits stay in the draft until `save()`. The draft seeds from recorded choices (not effective permissions) and tracks updates while clean. Handle each save state:

| State | Meaning | UI action |
| --- | --- | --- |
| `draft.isSaving` | A save is in progress. | Disable controls. `savingAction` names the active button; `showProgress` turns true after 400 ms. |
| `draft.errorMessage` | Storage refused the write; edits remain intact. | Display the error and wire `retry()` (omit retry when `listUnavailable` is true; use `refresh()` instead). |
| `draft.isStale` | Another surface saved after this draft opened. | Show `iabCopy.appSettingsChanged` and wire `draft.reset()`. |
| `draft.listUnavailable` | The IAB vendor list is stale or offline. | Show `iabCopy.appListOutdated` and wire `draft.refresh()`. |
| `confirmDiscard` | The user tried to dismiss with unsaved edits. | Show a confirmation wired to `discard()` and `keepEditing()`. |

Each save passes the snapshot revision the draft read. The core rejects stale writes with `concurrent-change` and keeps edits visible for review. A successful save confirms durable device storage and queues backend delivery. Hardware Back routes through `requestClose()`, asking before discarding edits and never interrupting a running save.

## Build your own IAB screen

Under a TCF policy, `iab` on the scope (or `draft.iab`) exposes an `IabDraftHandle` with disclosure rows and draft commands:

<include src="../../shared/examples/native/examples/consent-demo/android-headless-iab.mdx" />

| Member | Contents |
| --- | --- |
| `firstLayer` | Description with partner count, partner link range, purpose/stack summary, and legitimate-interest, scope, and withdrawal statements. |
| `purposes` | Declared purposes with descriptions, legal text, illustrations, partner counts, consent switches, and legitimate-interest switches where declared. |
| `specialFeatures` | Declared special features with opt-in switches. |
| `specialPurposes`, `features` | Non-toggleable partner declarations. Show `specialPurposesExplanation` and `featuresExplanation` alongside them and on vendor detail screens. |
| `stacks` | Vendor list stacks with grouped purposes and special features. |
| `vendors`, `vendors(purposeId)`, `vendor(id)` | Registered partners in vendor list order (sort by name for display) with legal bases after publisher restrictions, switches, status, and `details`. |
| `customVendors` | Non-IAB partners with `customVendorsHeading` and `customVendorsNotice`. |
| `adTechProviders` | Google Additional Consent providers with `adTechProvidersHeading` and `adTechProvidersNotice`. |
| `publisherRestrictions` | Policy publisher restrictions (already applied to vendor rows). |
| `consentStorage` | Maximum retention period of the TC String on the device. |

Render a switch only when `consent` or `legitimateInterest` is non-`null`. The core rejects saves that enable an empty basis. Setting `legitimateInterest` to `false` records an objection; purposes 1 and 3 through 6 never use legitimate interest.

`acceptAll()` and `rejectAll()` stage choices without saving until `save()`. First decisions open with every consent off, registered vendors' legitimate interests unobjected, and custom partners' legitimate interests off. The core validates every ID and basis, encodes the TC String and Additional Consent string, and writes `IABTCF_*` keys. Gate ad SDKs on committed decisions (`ConsentGate` or `isIabAllowed`), never on draft rows.

### Required IAB disclosures

The core satisfies IAB Europe signal checks from `packages/native-protocol/iab/tcf-policy-checks.json` (T1, T3, T4, T6 to T13, P13, P21, P29). Complete CMP registration (T5) with IAB Europe and render the remaining UI checks:

| Check | Required UI |
| --- | --- |
| P1, P2 | Cover most of the screen on the first layer, leaving terms and privacy policy accessible. |
| P3, P4, P5, P12 | Render `firstLayer.description` including the partner count. |
| P6 | Make `firstLayer.partnersLink` open your partner list. |
| P7 | Render every item in `firstLayer.summary`. |
| P8, P9 | Render `firstLayer.scope` and `firstLayer.withdraw`. |
| P10, P11, P32 | Give Accept all and Reject all equal styling and at least 5:1 contrast, plus Customize (`ConsentActions` keeps widths equal). |
| T2 | Wire Reject all to `rejectAll()` on the scope to withdraw every consent. |
| P14, P15 | Render purpose and feature names, descriptions, and illustrations unchanged, with no switch on features. |
| P16 | Place `adTechProviders` and `customVendors` in separate sections with their headings and notices. |
| P17, P22 | Render `firstLayer.legitimateInterest`, `legitimateInterestExplanation`, and each vendor's `details.legitimateInterestPurposes`. |
| P18, P23 | Render `rightToObject` and legitimate-interest switches on each purpose and vendor. |
| P19 | Per vendor: `details.privacyPolicyUrl`, consent and LI purpose lists, special purposes, features, special features, and consent switches. |
| P20 | Render a switch for each row in `specialFeatures`. |
| P25 | Show `partnersNote` or both partner counts on each purpose. |
| P26 | Show `details.legitimateInterestClaimUrl`. |
| P27, P28 | Show `details.retention` and `details.dataCategories`. |
| P30 | Show `consentStorage`. |
| P31 | Keep a standing Privacy settings entry in your app's settings. |

## Keep custom screens accessible

Both headless blocks announce save results and errors to TalkBack once, even when multiple blocks share a draft. Add these modifiers to complete accessibility:

| API | Purpose |
| --- | --- |
| `Modifier.consentPane(title)` | Names the surface so TalkBack announces it and moves focus in (place on a node with no `clickable` ancestor). |
| `Modifier.consentInitialFocus()` | Gives the heading keyboard and switch-access focus on open (place on text, not on a button or switch). |
| `ConsentActions { }` | Gives paired actions equal width and stacks them when labels overflow or text is large. |
| `consentUsesLargeText()` | Returns `true` from font scale 1.5, where stock screens move actions into the scrolling page. |

Size text in `sp`, let rows expand, and test at font scale 2.

`examples/native/consent-demo/android` includes a complete custom UI in `custom-consent-ui.kt` built with no Material components. Install the debug app with `./gradlew :consent-demo:installDebug` from `packages/android`, enable **Custom consent UI** on the setup screen, and choose a local fixture.

## Read the current permission

`Inth.isAllowed(ConsentCategory.MEASUREMENT)` performs a synchronous memory read returning `false` for both refusals and unresolved policies. Use `Inth.decision(ConsentCategory.MEASUREMENT)` to distinguish all three states:

| Decision | Integration action |
| --- | --- |
| `PENDING` | Keep collection off until policy resolves. |
| `DENIED` | Keep collection off. |
| `GRANTED` | Enable only work covered by that category. |

Read `snapshot.explicitChoice` when you need to distinguish an explicit recorded choice from an effective policy default.

## Keep analytics in sync

Retain a gate for the lifetime of each analytics integration so it receives the initial decision and every grant, withdrawal, or policy change. Create `MeasurementConsentGate.kt` to forward changes onto the main thread:

<include src="../../shared/examples/native/examples/consent-demo/android-measurement-gate.mdx" />

Construct `MeasurementConsentGate` after installation, passing the vendor's enable/disable function as `setCollectionEnabled`. Hold the handle in your app-wide owner and call `close()` only when that owner ends (not on Activity rotation). Ensure the vendor starts disabled; Inth does not intercept network traffic or cancel already-queued work.

Use `gateDecision` when you need `PENDING` vs `DENIED`. Every observer (`gate`, `gateDecision`, `onChange`, `onError`) returns a `Subscription` that keeps firing until `close()` is called. Marshal UI updates from worker callbacks onto the main thread.

## Show consent state in Compose

Import Kotlin flows from `com.inth.android`:

| API | Behavior |
| --- | --- |
| `core.snapshotFlow` | `StateFlow<ConsentSnapshot>` holding the latest snapshot. |
| `core.decisionFlow(category)` | `StateFlow<ConsentDecision>` emitting only when that category's decision changes. |

Both return stable instances across recompositions and run in the collector's coroutine context (`Compose`, `lifecycleScope`, or `viewModelScope` stay on the main thread). Because `StateFlow` conflates, use `onChange` if you must react to every revision. The [Android quickstart](/docs/frameworks/android/quickstart) uses `decisionFlow` directly.

## Save a category form

When building a custom form directly on the core APIs, seed editable controls from `snapshot.explicitChoice` and capture the snapshot revision. Create `save-measurement-choice.kt` and call it only on explicit Save:

<include src="../../shared/examples/native/examples/consent-demo/android-category-save.mdx" />

Omitted categories keep their previous receipts. Use `CommitIntent.All` for Accept all and `CommitIntent.Necessary` for Reject all or withdrawal. Inspect `CommitResult` before closing the form:

| Result | UI action |
| --- | --- |
| `ok == true` | Confirm durable local storage on this device. |
| `ok == false` | Keep the form open and show `error`. |
| `error?.code == "concurrent-change"` | Prompt the user to reload current settings and review edits. |
| `queued == true` | Delivery is queued durably for retry on reconnect. |
| `delivered == false` | Local save may still succeed; do not claim backend receipt yet. |

`awaitSave` and `awaitFlushPending` run on `Dispatchers.IO` (cancelling the caller does not abort an in-flight save). `awaitRefresh` returns after `/v1/consent/init` updates `snapshotFlow`. Disable duplicate submissions while saving, announce errors to TalkBack, and keep retry reachable.

## Use IAB authority for advertising

Call `iabPresentation()` to inspect retained disclosures and open a revision-bound draft (`canEdit` indicates whether edits are permitted). Commit the full draft with its expected revision, and gate ad SDKs on native vendor/purpose/basis and Additional Consent checks rather than `marketing == true` or a non-empty TC String. See [Mobile IAB and ads](/docs/frameworks/android/iab).
