Add a native consent prompt and Privacy settings entry to a Kotlin Android app with Jetpack Compose. Inth persists choices locally, loads policy from your project, and exposes synchronous SDK gates at launch.

## Prerequisites

- Android API 24+, compile SDK 36+, JDK 17, Jetpack Compose, and Material 3.
- An [Inth project](https://inth.com) with regional policies, `measurement` category, and its HTTPS project URL (`https://your-project.inth.app`).
- Your app's HTTPS privacy policy URL.
- Private prerelease Maven access for `com.inth` (`3.0.0-alpha.1`); see [mobile availability](/docs/guides/mobile-status).

## Add the dependencies

Add your Maven repository in `settings.gradle.kts` inside `dependencyResolutionManagement.repositories`, scoped to `com.inth`:

{/* example: fragment */}

```kotlin title="settings.gradle.kts"
exclusiveContent {
	forRepository {
		maven {
			url = uri(providers.gradleProperty("inth.repository").get())
			if (url.scheme == "https") {
				credentials {
					username = providers.environmentVariable("INTH_MAVEN_USERNAME").orNull
					password = providers.environmentVariable("INTH_MAVEN_TOKEN").orNull
				}
			}
		}
	}
	filter { includeGroup("com.inth") }
}
```

Set `inth.repository` in Gradle properties and export credentials for authenticated repositories. Add the dependencies in `app/build.gradle.kts` (omit `inth-consent-ui` for [custom UI](/docs/frameworks/android/headless)):

{/* example: fragment */}

```kotlin title="app/build.gradle.kts"
implementation("com.inth:inth-android:3.0.0-alpha.1")
implementation("com.inth:inth-consent-ui:3.0.0-alpha.1")
```

`InthAndroid.install` hydrates saved choices synchronously and starts policy resolution before optional SDKs boot (disable vendor auto-initializers). `InthConsent` presents an owed prompt across rotations; place **Privacy settings** in your app settings calling `ConsentPrompt.of(core).presentPreferences()`. Enable [`dryRun`](/docs/frameworks/android/configuration#run-without-sending-records) in debug builds to drop outgoing records.

## Register the manifest entries

Add permissions and register your classes in `AndroidManifest.xml`:

{/* example: fragment */}

```xml title="app/src/main/AndroidManifest.xml"
<uses-permission android:name="android.permission.INTERNET" />
<uses-permission android:name="android.permission.ACCESS_NETWORK_STATE" />

<application android:name="com.inth.demo.ConsentApplication">
	<activity android:name="com.inth.demo.ConsentActivity" android:exported="true" />
</application>
```

## Gate analytics

Wire each optional SDK to a retained [measurement gate](/docs/frameworks/android/headless#keep-analytics-in-sync) so collection starts on `GRANTED` and stops on withdrawal.

## Check it works

Launch against an opt-in policy:

1. Fresh install: prompt opens; analytics stays off.
2. Tap **Reject all** and relaunch: prompt stays closed; analytics stays off.
3. Open **Privacy settings**, enable Analytics, and save: gate opens.
4. Disable Analytics, save, and relaunch: collection stays off.
5. Reject offline, then reconnect: refusal persists and delivers on reconnect.

Offline first launches require an [offline policy](/docs/guides/mobile-offline).
