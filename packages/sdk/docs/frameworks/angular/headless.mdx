Replace the stock banner or preference dialog with your own Angular templates
while `provideInth()` continues to resolve policies, store choices and gate
scripts.

## Choose how much to replace

Try [customization](/docs/frameworks/angular/customize) first: tokens, slots,
the banner's container inputs, `presentation` and translations cover most
visual changes without custom markup. Go headless when you need markup the stock
components cannot produce.

| Goal | Approach |
| --- | --- |
| Keep the markup, drop Inth's styles | Set `noStyle` in `provideInth()` or on one component, and style `data-*` attributes and slot classes. |
| Custom banner, stock dialog | Use `HeadlessConsent` for the banner and `<inth-consent-dialog>` for preferences. |
| Custom dialog too | Add `ConsentManager` for the category list and draft, plus [primitives](./components/primitives) for accessible parts. |

`provideInth()`, scripts, `<inth-consent-gate>` and stored choices work the
same in every option.

## Build a banner with HeadlessConsent

`HeadlessConsent` exposes banner and dialog state with the policy's
presentation resolved, plus one method per action. Inject it in any component
below `provideInth()`.

| Member | Purpose |
| --- | --- |
| `banner()`, `dialog()` | Signals with the resolved presentation (`ResolvedConsentPresentation`) for each surface, plus `isVisible`. |
| `banner().actionGroups`, `banner().orderedActions` | Allowed actions, grouped or flat, in policy order. |
| `banner().requiredActions`, `banner().primaryActions` | Actions you must show, and actions to emphasize. |
| `banner().container` | The resolved layout for `desktop` and `phone`: `type`, `placement`, `flow`, `edgeStyle` and `blocking`. `null` on `dialog()`. |
| `banner().blocking` | Whether the prompt blocks the page. Match it with a focus trap and scroll lock. |
| `activeUI()` | `'banner'`, `'dialog'` or `'none'`. |
| `performAction(action)` | `accept`, `reject`, `dismiss`, `save` or `customize`. `customize` opens the dialog, since a custom banner has no choices of its own to unfold. |
| `openBanner()`, `openDialog()`, `closeUI()` | Show or hide a surface. |
| `optOut()` | Under an opt-out policy, record an opt-out in one click and show its receipt in `<inth-consent-dialog>` (or a standalone `<inth-opt-out-confirmation>`). Under other models, open the dialog. |
| `saveCustomPreferences()` | Record the dialog's draft. |

Render from `actionGroups` or `orderedActions` instead of a fixed button
list. Policies may require a reject button next to accept or show only a
dismiss button for a notice.

`banner().container` lets a custom banner sit where the stock one would, so a
placement set in `presentation.prompt.container` or the policy's
`surface.container` still applies. The stock banner traps focus and locks
scroll while it blocks. To do the same, put `[inthFocusTrap]` and
`[inthScrollLock]` from `@inth/angular` on your banner, bound to
`banner().isVisible && banner().blocking`.

`resolvePromptCopy` and `resolveActionLabels` from `@inth/angular` return the
banner title, description and button labels in the active language with
English fallbacks. Under a notice, `resolvePromptCopy` reads notice copy and
`banner().primaryActions` contains `dismiss`. `resolvePreferenceControlLabels`
labels an opt-out or preferences button.

## Build your own preferences

For a custom dialog or settings page, read the category list and unsaved
draft from `ConsentManager`. This form binds the headless switch with
`[ngModel]`, so it imports `FormsModule`:

<include src="../../shared/examples/angular/own-preferences.mdx" />

`setConsent` updates the draft only. `saveConsents('custom')` records it. If
the policy changes while the draft is open, `draft.isStale()` turns `true`
and saving throws, so disable Save and display a message. Translated category
titles and descriptions live in `translationConfig()`.
[ConsentManager](./services#work-with-the-draft) covers the draft API.

## Verify a custom UI

Run the same checks as the stock components: reject, reload and confirm no
optional vendor requests; allow one category and confirm only its vendors
load; reopen preferences from your footer link. Test keyboard navigation and
screen reader output on your custom markup.
[Verify consent](/docs/guides/verify-consent) has the full checklist.
