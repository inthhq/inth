Change consent copy across your Angular app or switch languages at runtime.

## Where the copy comes from

The banner, dialog, widget, gate placeholder and IAB components read their
text from one translation set for the visitor's language. Which set depends on
the `mode` you pass to `provideInth()`:

| Mode | Copy comes from | Languages |
| --- | --- | --- |
| `hosted()` | Inth's `/v1/consent/init` response in the requested language, with your `i18n` messages on top | Every language Inth bundles: ar, bg, bn, cs, cy, da, de, el, en, es, et, fi, fr, ga, gu, he, hi, hr, ht, hu, id, is, it, ja, kn, ko, lb, lt, lv, ml, mr, ms, mt, nb, nl, nn, pa, pl, pt, rm, ro, ru, sk, sl, sv, ta, te, th, tr, ur, vi, yi and zh |
| `manifest()` | Manifest translations over base copy for the visitor's language, with your `i18n` messages on top | English base copy is bundled; other languages load on first need |
| `testing()` | The `i18n` option merged over bundled English | English, plus any language you supply in full |

The browser bundle includes English only. Other languages load from Inth or
from messages you pass.

## Change the copy for one banner

`<inth-consent-banner>` takes `heading`, `description`, `acceptButtonText`,
`rejectButtonText`, `customizeButtonText` and `dismissButtonText` inputs. They
win in every mode:

{/* example: fragment */}

```html
<inth-consent-banner
	heading="Cookies on this site"
	rejectButtonText="Reject optional"
/>
```

Inputs replace the text in every language, so pass localized values from
`$localize` or your i18n library. For markup inside the title or description,
use the `inthConsentBannerTitle` and `inthConsentBannerDescription` templates;
see [ConsentBanner](./components/consent-banner#replace-the-title-description-or-buttons).

## Change the copy site-wide

Pass `i18n` to `provideInth()`. `messages` holds partial translations per
language; omitted keys keep Inth's copy:

<include src="../../shared/examples/angular/consent-i18n.mdx" />

`locale` selects the starting language (`en` by default). `provideInth()`
reads `i18n` once at startup.

In `hosted()` mode, Inth's copy for the visitor's language is the base, and
your `i18n` messages override it key by key. Unlisted keys keep the copy from
your Inth project. Inth checks the exact language first, then its primary
language, so `de-AT` uses your `de` messages when no `de-AT` entry exists.

A key overrides Inth only when your text differs from the built-in wording for
that language. Passing stock bundles from `@inth/angular/translations/all`
keeps project edits visible while pinning keys you reworded. Core bundles only
English; for other languages, import `@inth/angular/translations/all` so Inth
recognizes its stock wording.

In `testing()` mode, `i18n` is the only source of copy and applies from the
first render.

## Common message keys

| Key | Where it shows |
| --- | --- |
| `cookieBanner.title`, `cookieBanner.description` | Choice banner heading and body. |
| `cookieBanner.noticeTitle`, `cookieBanner.noticeDescription` | Notice banner heading and body. |
| `common.acceptAll`, `common.rejectAll`, `common.customize`, `common.save` | Banner and dialog buttons. |
| `common.acknowledge` | The notice's dismiss button. |
| `common.securedBy` | The "Secured by" tag. |
| `consentManagerDialog.title`, `consentManagerDialog.description` | Preference dialog heading and body. |
| `consentTypes.<category>.title`, `consentTypes.<category>.description` | Category name and description, such as `consentTypes.measurement.title`. |
| `consentGate.title`, `consentGate.actionButton` | `<inth-consent-gate>` placeholder. `{category}` becomes the category title. |

[Copy and translations](/docs/customization/translations) covers wording for
each action and testing long labels.

## Switch the language

`ConsentManager.setLanguage(code)` switches the language and resolves the
policy again, fetching copy in the new language and applying your `i18n`
messages on top. Call it from your language switcher:

<include src="../../shared/examples/angular/language-switcher.mdx" />

Otherwise the visitor's language comes from `Accept-Language` or
`overrides.language` in `provideInth()`. With Angular's `@angular/localize`,
pass the build's `LOCALE_ID` as `overrides: { language }` so consent copy
matches the page.

The banner, dialog and widget set `dir` from the active language so
right-to-left languages lay out properly.

## Verify the copy

Open the page with the browser language set to each language you support.
Confirm the banner, dialog category names and gate placeholder render in that
language. Narrow the window and zoom to 200% to confirm long labels wrap
cleanly.
