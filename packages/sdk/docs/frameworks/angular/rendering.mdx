## Pick the setup for your deployment

| Your app | Setup |
| --- | --- |
| Browser-only Angular app served as static files | `provideC15t()` with `hosted()`, as in the [quickstart](/docs/frameworks/angular/quickstart). The banner mounts after the app bootstraps. |
| Angular with `@angular/ssr` and a Node server | `provideC15tServer()` and `createConsentRoute()` from `@inth/angular/ssr`. The banner is in the first HTML, and the browser only talks to your origin. This page. |
| Prerendered routes (`RenderMode.Prerender`) | Every visitor gets the same HTML, so it carries no visitor's consent. The browser resolves consent after hydration. See [prerendered and cached pages](#prerendered-and-cached-pages). |
| Tests with no backend | `testing()` from `@inth/angular/testing`, which the server resolves from its own rules. Throws in production builds. |

`@inth/angular/ssr` needs `@angular/ssr` and `@angular/platform-server`
20, 21 or 22. An app created with `ng new --ssr`, or after `ng add @angular/ssr`,
has both. They are optional peer dependencies of `@inth/angular`, so a
browser-only app does not install them.

## How server rendering works

`provideC15tServer()` runs before each server render. It reads the request
through Angular's `REQUEST` token, resolves the visitor's consent with the
`mode` you gave `provideC15t()`, and stores the result in `TransferState`:

- `hosted()` asks the backend's `/init`, forwarding the visitor's cookie,
  location headers and language. With `route`, a backend on your own consent
  route is resolved in-process, with no network request.
- `testing()` resolves the policy from its rules and the request's location
  headers.
- `manifest()` resolves from the backend's manifest.
- A transport factory of your own gives the server nothing to call. The stored cookie still seeds
  the state, and the browser resolves the policy after hydration.

`ConsentManager` reads that state on the server, so the render includes the
banner for a visitor who owes a choice and leaves it out for one who already
chose. In the browser it reads the same state, and the snapshot the server
rendered with, back from `TransferState`, so hydration matches, the browser
makes no `/init` request, and the consent engine can load after the page's
largest image; see
[when the runtime starts](/docs/frameworks/angular/provide-c15t#when-the-runtime-starts).

The server render never fails because of consent. An unreachable or slow
upstream gives the cookie-only state after `timeoutMs`, 500 milliseconds by
default, and the browser resolves the policy after hydration.

When the visitor's stored consent already allows some of your `scripts`, the
server adds their start to the end of `<body>`, so they run before the app
hydrates instead of after the script loader's chunk. When the page has the
stock banner, a small script in `<head>` holds a tap on it made before
hydration, and the banner records that choice once it hydrates.

## Add the consent route

`createConsentRoute()` serves the consent endpoints from your own server, so
the browser never needs a CORS exception or a connection to another origin.
Create it in a server-only module:

<include src="../../shared/examples/angular/consent-route.mdx" />

The route answers `/manifest` and `/init` below `/api/c15t`, resolved
in-process from the backend's manifest. With `proxy: true` it also forwards
consent writes, such as saves to `/subjects`, to `projectUrl`. Only an
allowlist of paths is forwarded, so the route is never an open proxy. Without
`proxy`, anything but `GET` and `HEAD` gets `405`.

`C15T_BACKEND_URL` is read at runtime, on the server only. Set it to your Inth
project's backend URL in the server's environment.

| Option | Default | Behavior |
| --- | --- | --- |
| `routePrefix` | `'/api/c15t'` | Where the route is mounted. Must be a path other than `/`. |
| `projectUrl` | none | The c15t backend. The manifest is read from `${projectUrl}/manifest`; session reports and the proxy go here. Must not name this route. |
| `manifestUrl` | `${projectUrl}/manifest` | A full manifest URL, such as a CDN copy. |
| `snapshot` | none | A manifest to resolve with. Nothing is fetched. |
| `proxy` | `false` | Forward consent writes to `projectUrl`. |
| `trustForwardedHeaders` | `false` | Believe `Forwarded` and `X-Forwarded-*` headers. Only behind a proxy that sets them and drops incoming ones. |
| `fetch`, `fetchGvl` | `globalThis.fetch` | Fetch for the manifest and for the Global Vendor List under an IAB policy. |
| `waitUntil` | none | Keeps manifest refreshes and session reports alive past the response, on runtimes that stop work once a response is sent. |

| Option | Default | Behavior |
| --- | --- | --- |
| `route` | none | The route from `createConsentRoute()`. A relative backend below its prefix is resolved in-process. |
| `cookieName` | `'c15t'` | The cookie holding stored consent. Set it only when `storageConfig` in `provideC15t()` uses another key; they must match. |
| `country`, `region`, `language` | from the request | Replace what the request's geo headers and `Accept-Language` say. |
| `forwardHeaders` | none | Extra request headers to forward upstream in hosted mode, such as a token a private backend needs. `cookie` and forwarding headers cannot be named. |
| `trustForwardedHeaders` | `false` | Resolve a relative backend against the request's forwarding headers and forward the visitor IP. Only behind a proxy that sets those headers. |
| `fetch` | `globalThis.fetch` | Fetch for a backend on another origin. |
| `timeoutMs` | `500` | Longest the render waits for the policy, in milliseconds. `false` waits for the upstream. |
| `waitUntil` | none | Keeps session reports and late upstream work alive past the response. |
| `shared` | `false` | The HTML is served to more than one visitor. No cookie, geo header or clock is read. |

`provideC15tServer()` does nothing when `provideC15t()` has a `prefetch` you
set yourself or an external `runtime`.

For a fetch-style server that uses `AngularAppEngine`, such as one on an edge
runtime, answer with the route first and fall back to the page:

{/* example: fragment */}

```ts
const response =
	(await consentRoute.fetch(request)) ?? (await angularApp.handle(request));
```

`consentRoute.fetch` returns `null` for a request outside its prefix.

## Prerendered and cached pages

A page built with `RenderMode.Prerender`, or served from a shared cache,
reaches every visitor with the same HTML. `provideC15tServer()` treats a
render without a request as shared: it reads no cookie, geo header or clock,
and resolves only `testing()` mode. Pass `shared: true` for a server-rendered
page you cache. The browser then resolves the visitor's consent after
hydration, so the banner appears after the first paint. Never cache a page
that a request-specific render produced.

## Verify server rendering

Build with `ng build`, start the server with `node dist/<app>/server/server.mjs`
and open a private window:

1. View the page source. The banner's markup and `<style data-c15t-styles>`
   elements are in the HTML.
2. The Network panel has no `/init` request from the browser, and no request
   to your Inth backend's origin.
3. Select **Accept All** and reload. The page source has no banner.
4. Select **Privacy settings** and save. The save goes to `/api/c15t` on
   your origin.

The console shows no Angular hydration errors. If it does, see
[troubleshooting](./troubleshooting#the-server-html-and-the-browser-disagree).
