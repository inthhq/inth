Render the Inth consent banner in your server HTML with `@angular/ssr`, or
choose the right setup for prerendered and browser-only Angular deployments.

## Pick the setup for your deployment

| Your app | Setup |
| --- | --- |
| Browser-only Angular app served as static files | `provideInth()` with `hosted()`, as in the [quickstart](/docs/frameworks/angular/quickstart). The banner mounts after the app bootstraps. |
| Angular with `@angular/ssr` and a Node server | `provideInthServer()` and `createConsentRoute()` from `@inth/angular/ssr`. The banner is in the first HTML, and the browser only talks to your origin. This page. |
| Prerendered routes (`RenderMode.Prerender`) | Every visitor gets the same HTML, so it carries no visitor's consent. The browser resolves consent after hydration. See [prerendered and cached pages](#prerendered-and-cached-pages). |
| Tests with no backend | `testing()` from `@inth/angular/testing`, which the server resolves from its own rules. Throws in production builds. |

`@inth/angular/ssr` needs `@angular/ssr` and `@angular/platform-server`
20, 21 or 22. An app created with `ng new --ssr`, or after `ng add @angular/ssr`,
has both. They are optional peer dependencies of `@inth/angular`, so a
browser-only app does not install them.

## How server rendering works

`provideInthServer()` runs before each server render. It reads the request
through Angular's `REQUEST` token, resolves the visitor's consent with the
`mode` you gave `provideInth()`, and stores the result in `TransferState`:

- `hosted()` calls Inth's `/v1/consent/init`, forwarding the visitor's cookie,
  location headers and language. With `route`, a relative URL on your own
  consent route resolves in-process with no network hop.
- `testing()` resolves the policy from its rules and the request's location
  headers.
- `manifest()` resolves from your project's consent manifest.

`ConsentManager` reads that state on the server, so the render includes the
banner for a visitor who owes a choice and omits it for one who already
chose. In the browser it reads the same state back from `TransferState`, so
hydration matches, the browser makes no `/v1/consent/init` request, and the consent
engine can defer until after the page's largest image; see
[when the runtime starts](/docs/frameworks/angular/provide-inth#when-the-runtime-starts).

The server render never fails because of consent. An unreachable or slow
upstream gives the cookie-only state after `timeoutMs` (500 milliseconds by
default), and the browser resolves the policy after hydration.

When the visitor's stored consent already allows some of your `scripts`, the
server adds their start to the end of `<body>`, so they run before the app
hydrates. When the page has the stock banner, a small script in `<head>`
captures any click made before hydration and records that choice once the
banner hydrates.

## Add the consent route

`createConsentRoute()` serves the consent endpoints from your own server, so
the browser never needs a CORS exception or a connection to another origin.
Create it in a server-only module:

<include src="../../shared/examples/angular/consent-route.mdx" />

The route answers `/v1/consent/manifest` and `/v1/consent/init` below `/api/inth`, resolved
in-process from your project's manifest. With `proxy: true` it also forwards
consent writes, such as saves to `/v1/consent/records`, to `projectUrl`. Only an
allowlist of paths is forwarded, so the route is never an open proxy. Without
`proxy`, anything other than `GET` and `HEAD` returns `405`.

Set `INTH_PROJECT_URL` in the server environment to your Inth project URL. It
is read at runtime on the server only.

| Option | Default | Behavior |
| --- | --- | --- |
| `routePrefix` | `'/api/inth'` | Where the route is mounted. Must be a path other than `/`. |
| `projectUrl` | none | Your Inth project URL. The manifest loads from `${projectUrl}/v1/consent/manifest`; session reports and proxied writes go here. Must not name this route. |
| `manifestUrl` | `${projectUrl}/v1/consent/manifest` | A full manifest URL, such as a CDN copy. |
| `snapshot` | none | A manifest to resolve with. Nothing is fetched. |
| `proxy` | `false` | Forward consent writes to `projectUrl`. |
| `trustForwardedHeaders` | `false` | Trust `Forwarded` and `X-Forwarded-*` headers. Only behind a proxy that sets them and strips incoming ones. |
| `fetch`, `fetchGvl` | `globalThis.fetch` | Fetch for the manifest and for the Global Vendor List under an IAB policy. |
| `waitUntil` | none | Keeps manifest refreshes and session reports alive past the response on edge runtimes. |

Render consent routes on the server, not as prerendered pages:

| Option | Default | Behavior |
| --- | --- | --- |
| `route` | none | The route from `createConsentRoute()`. A relative URL below its prefix resolves in-process. |
| `cookieName` | `'inth'` | The cookie holding stored consent. Set it only when `storageConfig` in `provideInth()` uses another key; they must match. |
| `country`, `region`, `language` | from the request | Replace what the request's geo headers and `Accept-Language` say. |
| `forwardHeaders` | none | Extra request headers to forward upstream in hosted mode. `cookie` and forwarding headers cannot be named. |
| `trustForwardedHeaders` | `false` | Resolve a relative URL against the request's forwarding headers and forward the visitor IP. Only behind a proxy that sets those headers. |
| `fetch` | `globalThis.fetch` | Fetch for a backend on another origin. |
| `timeoutMs` | `500` | Longest the render waits for the policy, in milliseconds. `false` waits for the upstream. |
| `waitUntil` | none | Keeps session reports and late upstream work alive past the response. |
| `shared` | `false` | The HTML is served to more than one visitor. Reads no cookie, geo header or clock. |

`provideInthServer()` does nothing when `provideInth()` has a `prefetch` you
set yourself or an external `runtime`.

{/* example: fragment */}

```ts
const response =
	(await consentRoute.fetch(request)) ?? (await angularApp.handle(request));
```

`consentRoute.fetch` returns `null` for a request outside its prefix.

## Prerendered and cached pages

A page built with `RenderMode.Prerender`, or served from a shared cache,
reaches every visitor with the same HTML. `provideInthServer()` treats a
render without a request as shared: it reads no cookie, geo header or clock,
and resolves only `testing()` mode. Pass `shared: true` for a server-rendered
page you cache. The browser then resolves the visitor's consent after
hydration, so the banner appears after the first paint. Never cache a page
that a request-specific render produced.

## Verify server rendering

Build with `ng build`, start the server with `node dist/<app>/server/server.mjs`
and open a private window:

1. View the page source. The banner's markup and `<style data-inth-styles>`
   elements are in the HTML.
2. The Network panel has no `/v1/consent/init` request from the browser, and no request
   to your Inth project's origin.
3. Click **Accept All** and reload. The page source has no banner.
4. Click **Privacy settings** and save. The save goes to `/api/inth` on
   your origin.

The console shows no Angular hydration errors. If it does, see
[troubleshooting](./troubleshooting#the-server-html-and-the-browser-disagree).
