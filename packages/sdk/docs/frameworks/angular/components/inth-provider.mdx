Render `<inth-consent-banner>` and `<inth-consent-dialog>` together with a
single `<inth-provider>` tag.

## Render the stock UI in one tag

Import `InthProvider` from `@inth/angular/provider` and place it in your
root component:

{/* example: fragment */}

```html
<inth-provider [legalLinks]="['privacyPolicy', 'cookiePolicy']" />
```

`<inth-provider>` is UI only; `provideInth()` in your application config
owns consent state. The preference dialog code still lazy-loads on demand;
see [ConsentDialog](./consent-dialog#how-the-dialog-loads).

## Inputs

| Input | Type | Default | Behavior |
| --- | --- | --- | --- |
| `legalLinks` | array of `LegalLinks` keys, or `null` | all configured links | Legal links shown on both surfaces. |
| `hideBranding` | `boolean` | `false` | Hides the "Consent by" tag on both surfaces. |
| `showTrigger` | `boolean` or `ConsentDialogTriggerOptions` | `false` | Renders a floating `<inth-consent-dialog-trigger>` with the dialog. |
| `noStyle` | `boolean` | provider `noStyle` | Drops `inth` classes on both surfaces. |
| `disableAnimation` | `boolean` | provider value | Disables transitions on both surfaces. |

To pass banner-specific inputs such as `variant` or copy, or to use banner
`ng-template` slots, render `<inth-consent-banner>` and
`<inth-consent-dialog>` separately.

## Verify it

Open the page in a private window. The banner appears once the policy
resolves, and Customize opens the dialog. In DevTools Elements, both surfaces
portal into `<body>`.
