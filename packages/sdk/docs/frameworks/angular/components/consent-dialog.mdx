Render the preference dialog where visitors manage consent categories in
Angular using `<inth-consent-dialog>`.

## Render the dialog

Import `ConsentDialog` and render `<inth-consent-dialog>` once in your root
component next to `<inth-consent-banner>`:

<include src="../../../shared/examples/angular/app-component.mdx" />

Do not wrap it in `@if`: the dialog stays closed until opened. Use
[`<inth-provider>`](./inth-provider) to render banner and dialog in one
tag.

## How the dialog loads

`ConsentDialog` from `@inth/angular/consent-dialog` is a lightweight host.
The dialog body (widget and primitives) loads as a separate chunk:

- During browser idle time after `load` when a dialog opener is rendered
  (banner Customize button, `inthConsentDialogLink`,
  `<inth-consent-dialog-trigger>`, `<inth-consent-gate>` placeholder or
  `ConsentButton` with `action="customize"`).
- When any of those buttons is hovered or focused.
- On open at the latest.

Set `preloadDialog: 'intent'` in `provideInth()` to skip idle preloading and
load only on hover, focus or open. Idle loading also skips on Save-Data, 2G
and offline connections. If loading fails while opening, the previous surface
returns (or `openChange` emits `false` for controlled dialogs) and the next
attempt retries.

Dialog CSS loads alongside the chunk as a `<style>` element stamped with the
CSP nonce. With `styles: false`, rules come from `@inth/angular/styles.css`.

## Inputs

| Input | Type | Default | Behavior |
| --- | --- | --- | --- |
| `open` | `boolean` | follows consent state | Controlled visibility. Bind `[(open)]` so Escape and saves close it. |
| `showTrigger` | `boolean` or `ConsentDialogTriggerOptions` | `false` | Renders a floating `<inth-consent-dialog-trigger>` with the dialog. |
| `legalLinks` | array of `LegalLinks` keys, or `null` | all configured links | Legal links shown after the description. |
| `hideBranding` | `boolean` | `false` | Hides the "Consent by" tag. |
| `models` | `Model[]` | `['opt-in', 'opt-out', 'none']` | Policy models handled. IAB uses `<inth-iab-consent-dialog>`. |
| `noStyle` | `boolean` | provider `noStyle` | Drops `inth` classes. |
| `disableAnimation` | `boolean` | provider value | Disables open and close transitions. |
| `rootClass` | `string` | none | Extra class on the dialog element. |

`openChange` emits `false` on Escape, after saving, accepting or rejecting,
or if the dialog chunk fails to load.

Title and description come from `consentManagerDialog` translations; see
[translations](../translations). Passing `showTrigger` loads the dialog chunk
immediately on mount; render `<inth-consent-dialog-trigger>` separately to
avoid that eager load.

## What the dialog contains

The dialog displays the heading, description with legal links, and a
[`<inth-consent-widget>`](./consent-widget) listing categories within the
policy's scope (`necessary` is always enabled and locked). Switches edit a
shared draft until the visitor saves, accepts or rejects (accept and reject
record every unlocked category).

Under an `opt-out` policy, the widget inside the dialog renders a
sale-and-sharing block first, above the category list and outside any
accordion item. Before the visitor opts out, the block shows the configured
opt-out link title, a neutral status sentence and an **Opt out** button that
records the opt-out in one click without touching switches or Save. Once a
durable opt-out is held, the button disappears and the block shows the status
line (`role="status"`), receipt sentence, recorded time and local reference.
When the backend confirms the refused rights, the heading updates to name
them. When Global Privacy Control (GPC) is not locking the opt-out, the block
also shows an **Opt back in…** link. Under an `opt-in` policy, no block
renders.

Under an `opt-out` policy while an opt-out is held, opting back in uses a
two-step confirmation dialog. Clicking **Opt back in…**, clicking Accept All,
or turning `marketing` back on and clicking Save opens a separate modal dialog
instead of saving right away (`measurement` decides when `marketing` is not in
scope). Focus starts on the cancel button, both buttons have equal prominence,
and Escape cancels without saving. Confirming lifts a device opt-out, or asks
the backend to lift an account opt-out, which stays in force until the backend
confirms it. Turning `measurement` on while `marketing` stays off allows
`measurement` without lifting the opt-out and skips confirmation. Under an
`opt-in` policy, Accept still lifts a held opt-out in one step.

While GPC is active under a policy that maps it, signal-restricted switches
and `marketing` (or `measurement` when `marketing` is not in scope) stay off
and disabled with the GPC notice below each locked row, no **Opt back in…**
link renders, and Save and Accept All skip locked categories. When an account
holds the opt-out and GPC is off, the account notice appears below `marketing`
(or `measurement` when `marketing` is not in scope) and the switches stay
usable. Read the same state and receipt from `ConsentManager.optOutState()`.

`<inth-consent-dialog>` also hosts `<inth-opt-out-confirmation>` lazily. After
a one-click opt-out, the confirmation view shows the title, status line,
receipt sentence (covering this browser or the account, naming rights only
when confirmed by the backend), recorded time, local reference when this
browser recorded it, Done and Manage preferences.

If the policy changes while open, the widget alerts the visitor to review
before saving.

## Open and close the dialog

Setting active UI to `'dialog'` opens it (via Customize,
`inthConsentDialogLink`, `<inth-consent-dialog-trigger>`,
`ConsentManager.setActiveUI('dialog')` or `HeadlessConsent.openDialog()`).

Escape closes the dialog without saving; outside clicks do not close it so
unsaved switches are not lost. Focus returns to the opener or restored banner.

When controlling visibility with `open`, use two-way binding so Escape and
saves update your state:

```html
<inth-consent-dialog [(open)]="preferencesOpen" />
```

## Accessibility

- Uses `aria-labelledby` and `aria-describedby` pointing to title and
  description.
- Blocking mode (default) traps focus and locks background scroll.
- Category controls expose `role="switch"` and set `dir` from the active
  language.
- Under an `opt-out` policy, the sale-and-sharing block renders as a `section`
  labelled by its heading above the category list.

## Style the dialog

`<inth-consent-dialog>` reads `consentDialog`, `consentDialogCard`,
`consentDialogHeader`, `consentDialogTitle`, `consentDialogDescription`,
`consentDialogContent`, `consentDialogTag` and `consentDialogOverlay` theme
slots. The root carries `data-testid="consent-dialog-root"` and
`data-blocking="true"` while blocking.
