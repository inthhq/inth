Build custom consent dialogs and preference forms in Angular with the same
keyboard, ARIA and focus behavior as Inth's stock components using
`@inth/angular/primitives`.

## When to use the primitives

Use primitives when building your own preference UI with
[`ConsentManager` and `HeadlessConsent`](../headless). The directives know
nothing about consent; bind them to `ConsentManager` signals yourself.

Each primitive is an attribute directive on your own HTML elements. Parent
directives expose state via `model()`, supporting `[(open)]`, `[(checked)]`
and `[(value)]`. Import directives from `@inth/angular/primitives`; class
names drop the `inth` prefix (for example, `[inthSwitch]` is `Switch`).

If you rely on stock primitive CSS classes without rendering
`<inth-consent-dialog>`, add `@inth/angular/styles.css` to `angular.json` and
set `styles: false` in `provideInth()`.

## Directives

| Primitive | Directives | Root inputs |
| --- | --- | --- |
| Dialog | `[inthDialog]` (export `inthDialog`), `[inthDialogBackdrop]`, `[inthDialogPositioner]`, `[inthDialogContent]`, `[inthDialogTitle]`, `[inthDialogDescription]`, `[inthDialogClose]` | `open` (`false`), `closeOnEscape` (`true`), `closeOnInteractOutside` (`true`), `trapFocus` (`true`), `preventScroll` (`false`), `lazyMount` (`false`), `unmountOnExit` (`false`) |
| Switch | `[inthSwitch]` on `<button>` (export `inthSwitch`), `[inthSwitchControl]`, `[inthSwitchThumb]`, `input[inthSwitchHiddenInput]` | `checked` (`false`), `disabled`, `type` (`'button'`) |
| Tabs | `[inthTabs]` (export `inthTabs`), `[inthTabsList]`, `[inthTabsTrigger]`, `[inthTabsContent]` (export `inthTabsContent`) | `value`, `orientation` (`'horizontal'`), `loop` (`true`), `disabled` |
| Accordion | `[inthAccordion]`, `[inthAccordionItem]`, `[inthAccordionTrigger]`, `[inthAccordionContent]` | `type` (`'single'` or `'multiple'`), `value`, `collapsible` (`false`) |
| Collapsible | `[inthCollapsible]`, `[inthCollapsibleTrigger]`, `[inthCollapsibleContent]`, `[inthCollapsibleIndicator]` | `open` (`false`), `disabled` |
| PreferenceItem | `[inthPreferenceItem]`, `[inthPreferenceItemHeader]`, `[inthPreferenceItemTrigger]`, `[inthPreferenceItemLeading]`, `[inthPreferenceItemTitle]`, `[inthPreferenceItemMeta]`, `[inthPreferenceItemAuxiliary]`, `[inthPreferenceItemControl]`, `[inth-preference-item-content]`, `ng-template[inthPreferenceItemBody]` | `open` (`false`), `disabled`, `noStyle` |

Place `[inthDialog]` on `<ng-container>` or a wrapper and render its parts
while `dialog.shouldRender()` is `true`. Focus returns to the previous
element on close. See [build your own dialog](../headless#build-your-own-dialog).

Inactive tab panels stay in the DOM with `hidden`; wrap in
`@if (panel.selected())` to unmount them. Use
`<ng-template inthPreferenceItemBody>` (`PreferenceItemBody`) to defer large
preference item bodies until first open, or set `forceMount` to render eagerly.

## Use the switch with Angular forms

`inthSwitch` implements `ControlValueAccessor` for `[(ngModel)]`,
`formControlName`, `[formControl]` and `[(checked)]`. Add
`inthSwitchHiddenInput` for native form submission:

<include src="../../../shared/examples/angular/switch-ngmodel.mdx" />

`inthSwitch` sets `role="switch"`, `aria-checked` and `data-state`
(`"checked"` or `"unchecked"`), toggles on Click, Enter and Space, and needs
`aria-label` or `aria-labelledby`.

## Focus trap, scroll lock and portal

| Directive | Usage | Input |
| --- | --- | --- |
| `[inthFocusTrap]` | `[inthFocusTrap]="open()"` | `boolean` or `{ enabled, initialFocus }`. Keeps Tab inside the element. |
| `[inthScrollLock]` | `[inthScrollLock]="open()"` | `boolean`. Locks background scroll. |
| `[inthPortal]` | `inthPortal` or `inthPortal="#modals"` | Target element or selector (default `<body>`). Moves the element after first browser render. |

All three are no-ops on the server so SSR hydration stays intact.

## Check your custom dialog

Navigate with keyboard only: confirm Tab stays trapped inside, Escape
closes the dialog and restores focus, and each switch announces its name and
state to a screen reader. See [headless](../headless) for consent state
wiring.
