Show the first-layer consent prompt in Angular with `<inth-consent-banner>`.

## Render the banner

Import `ConsentBanner` and render `<inth-consent-banner>` once in your root
component next to `<inth-consent-dialog>` so its Customize button can open
preferences:

<include src="../../../shared/examples/angular/app-component.mdx" />

Do not wrap it in `@if`: the banner decides when to show from the resolved
policy. It portals into `<body>` via `inthPortal` after the first browser
render to avoid stacking and overflow clipping while preserving SSR hydration.

## Change the shape

Set `variant` and `position` on the banner, or configure them globally via
`presentation` in `provideInth()`. Component inputs override provider
defaults:

<include src="../../../shared/examples/angular/bottom-bar.mdx" />

| `variant` | Positions |
| --- | --- |
| `floating` | `bottom-left` (default), `bottom-right`, `top-left`, `top-right`, `bottom-center`, `top-center` |
| `bar` | `bottom` (default), `top` |
| `widget` | `bottom-right` (default), `bottom-left`, `top-left`, `top-right` |
| `wall` | `center` |

Notices default to `bar` and choice prompts default to `floating`. Invalid
positions fall back to the variant default with a dev warning. In
right-to-left languages with no explicit position, corner positions flip
horizontally.

## Inputs

| Input | Type | Default | Behavior |
| --- | --- | --- | --- |
| `variant` | `'floating'`, `'bar'`, `'widget'` or `'wall'` | from policy | Banner shape. |
| `position` | see table above | variant default | Banner placement. |
| `blocking` | `boolean` | `false` | Adds backdrop, locks scroll, traps focus and ignores outside clicks. `wall` is always blocking; notices never are. |
| `layout` | `ConsentBannerLayout` | from policy | Button order and grouping, such as `[['reject', 'accept'], 'customize']`. |
| `primaryButton` | one action or array | from policy | Buttons that receive primary styling. |
| `heading`, `description` | `string` | translated copy | Override heading and body for this banner. |
| `acceptButtonText`, `rejectButtonText`, `customizeButtonText`, `dismissButtonText` | `string` | translated copy | Override individual button labels. |
| `legalLinks` | array of `LegalLinks` keys, or `null` | all configured links | Legal links shown after description. `null` hides all. |
| `hideBranding` | `boolean` | `false` | Hides the "Secured by" tag. |
| `models` | `Model[]` | `['opt-in', 'opt-out']` | Policy models rendered by this banner. IAB uses `<inth-iab-consent-banner>`. |
| `noStyle` | `boolean` | provider `noStyle` | Drops `inth` classes while keeping markup and behavior. |
| `disableAnimation` | `boolean` | provider value | Disables fade-in transition. |
| `scrollLock`, `trapFocus` | `boolean` | from `presentation` | Lock scroll or trap focus while open. |
| `rootClass` | `string` | none | Extra class on the root element. |

Where `layout` or `primaryButton` conflicts with the policy, the policy wins.
For site-wide copy changes, see [translations](../translations).

## Replace the title, description or buttons

Pass `ng-template` slots inside `<inth-consent-banner>` and import their
directives:

<include src="../../../shared/examples/angular/banner-templates.mdx" />

| Directive | Replaces | Template context |
| --- | --- | --- |
| `ng-template[inthConsentBannerTitle]` (`ConsentBannerTitle`) | Title text inside `<h2>` | `$implicit` (title), `notice` |
| `ng-template[inthConsentBannerDescription]` (`ConsentBannerDescription`) | Description text (legal links stay) | `$implicit` (description), `notice` |
| `ng-template[inthConsentBannerAction]` (`ConsentBannerAction`) | Each action button | `$implicit` (action id), `label`, `primary`, `variant`, `mode`, `testId` |

Templates are strictly typed: `let-action` is a `ConsentBannerButton` and
binds cleanly to `[action]` on `ConsentButton`. Preserve `testId` if your
tests query stock test IDs.

## When the banner shows

`<inth-consent-banner>` renders when:

- A policy has resolved and requires a prompt.
- The visitor has not recorded a choice, or the policy requires re-prompting.
- `activeUI()` is `'banner'`.
- The resolved model is listed in `models`.

See [why the banner may be absent](/docs/concepts/policies#why-the-banner-may-be-absent)
when no banner appears.

Choice prompts show Accept, Reject and Customize in policy order. Notices show
a dismiss button using `noticeTitle` and `noticeDescription`; dismissing a
notice records acknowledgement rather than consent.

When the policy grants the `opt-out` right, the banner shows an underlined
opt-out link whose action follows the resolved `presentation.optOutLink` title
in `provideInth()`. With the default `'do-not-sell'` ("Do Not Sell or Share My
Personal Information"), activating the link records the opt-out in one click
and opens `<inth-opt-out-confirmation>` (reloading first when that turns off a
running category and `reloadOnConsentRevoked` is enabled; rendered lazily by
`<inth-consent-dialog>` or a standalone `<inth-opt-out-confirmation>`). The
confirmation view displays a receipt with the status line, what the opt-out
covers (naming rights only when confirmed by the backend), the recorded time,
the local reference when this browser recorded it, Done and Manage
preferences. With `'privacy-choices'` or `'california-privacy-choices'`, the
link renders with the California Privacy Protection Agency opt-out icon and
opens `<inth-consent-dialog>` without recording an opt-out. Programmatic calls
to `ConsentManager.requestOptOut()` still opt out in one step whatever
`presentation.optOutLink` is set to. When only the `preferences` right is
shown, the link opens `<inth-consent-dialog>`.

<include src="../../../shared/privacy-choices-link.mdx" />

Accept and Reject record the choice and close the banner immediately, then
send the request to Inth in the background. Under an `opt-out` policy while an
opt-out is held, Accept opens the two-step opt-in confirmation dialog before
saving.

## Accessibility

- Renders as a `region` labelled by its `<h2>` title, or a `dialog` with
  `aria-modal="true"` and focus trap when `blocking` is enabled.
- Uses native `<button type="button">` controls.
- Does not steal focus on mount unless focus trapping is active.
- Respects `prefers-reduced-motion` and sets `dir` from the active language.

## Style the banner

`<inth-consent-banner>` reads these `theme.slots` keys: `consentBanner`,
`consentBannerCard`, `consentBannerHeader`, `consentBannerTitle`,
`consentBannerDescription`, `consentBannerFooter`,
`consentBannerFooterSubGroup`, `consentBannerRights`,
`consentBannerRightLink`, `consentBannerTag` and `consentBannerOverlay`. See
[customize](../customize).

The root carries `data-testid="consent-banner-root"` and these attributes:

| Attribute | Value |
| --- | --- |
| `data-prompt` | `choice` or `notice` |
| `data-model` | `opt-in`, `opt-out` or `iab` |
| `data-variant` | resolved variant |
| `data-position` | resolved position |
| `data-blocking` | `true` when blocking |

Each button carries `data-action` set to `accept`, `reject`, `customize` or
`dismiss`.
