## Gate an embed

`<inth-consent-gate>` renders its content only while one consent category is
allowed, and a placeholder otherwise. Import `ConsentGate` and the
template directives you use:

<include src="../../../shared/examples/angular/youtube-embed.mdx" />

The permission is `ConsentManager.effectivePermissions()[category]`, the value
`has(category)` reads. It can be granted before the visitor chooses, under an
opt-out policy, and Global Privacy Control can override a recorded grant.
When the visitor withdraws the category, the content is destroyed without a
reload.

## Inputs and templates

| Input or template | Type | Default | Behavior |
| --- | --- | --- | --- |
| `category` | `AllConsentNames` | required | The category the content needs, such as `'measurement'` or `'marketing'`. |
| `vendor` | `string` | none | A vendor id the content also needs. The content waits for both the category and `isVendorAllowed(vendor)`. |
| `noStyle` | `boolean` | provider's `noStyle` | Drops Inth's classes from the built-in placeholder. |
| `ng-template[inthConsentGateContent]` | template | none | The gated content, created only while allowed. |
| `ng-template[inthConsentGatePlaceholder]` | template | built-in placeholder | Replaces the placeholder while the category is denied. |

Without a `inthConsentGateContent` template, the gate projects its children.
Angular creates projected nodes with the parent view even while the gate
keeps them out of the document, so an `<iframe>` loads nothing, but a
component inside still runs its constructor. Use the template for anything
with side effects.

The placeholder template's context has `$implicit` and `category`, the gate's
category, and `openDialog`, a function that opens the preference dialog:

{/* example: fragment */}

```html
<ng-template inthConsentGatePlaceholder let-category let-open="openDialog">
	<p>Allow {{ category }} to load this video.</p>
	<button type="button" (click)="open()">Choose video permissions</button>
</ng-template>
```

## Server rendering

The host element stays in the page in every state. Until the gate has
rendered in the browser it is empty, so the server HTML holds neither the
content nor the placeholder, and the browser fills it one frame after the
first render. For gated content in the server HTML, use
[`*inthIfConsent`](../embeds#render-content-only-while-consent-holds).

## The built-in placeholder

The built-in placeholder shows the `consentGate.title` copy and a button
labelled with `consentGate.actionButton`, with the category's translated
title in place of `{category}`. The button opens the preference dialog; it
does not grant the category, so render `<inth-consent-dialog>` too. Under a
policy that blocks the category, the button is left out, since preferences
cannot allow it.

`<inth-consent-gate>` does not add its category to the preference dialog.
Keep the category in your policy's scope, and in `consentCategories` if you
set that option.

## Accessibility

The built-in placeholder is plain text and a `<button>`, so it works without
the embed. Give the iframe a descriptive `title`, and give visitors who
decline another way to the content, such as a link to the video's page or a
store address next to the map.

## Style the placeholder

Set `class` on `<inth-consent-gate>` to size the wrapper to the embed, for
example an `aspect-ratio` for a video, so the page does not shift when the
embed replaces the placeholder.

To restyle the built-in placeholder, set the `consentGate` slot for the card,
`consentGateTitle` and `consentGateButton` in `theme.slots`.
`consentGateButton` applies on top of `buttonPrimary`.

The built-in placeholder carries `data-testid="consent-gate-placeholder"`,
its title `data-testid="consent-gate-title"` and its button
`data-testid="consent-gate-button"`.
