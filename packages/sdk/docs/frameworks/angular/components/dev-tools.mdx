## Add the panel

`@inth/angular/devtools` exports the panel two ways. Render
`<inth-consent-dev-tools>` once, anywhere below `provideInth()`:

<include src="../../../shared/examples/angular/dev-tools.mdx" />

The component renders nothing itself. The panel mounts in its own shadow root
on `<body>` in the browser, and is removed with the component. On the server
it does nothing.

Or mount it with the application, without a component, after
`provideInth()`:

<include src="../../../shared/examples/angular/dev-tools-provider.mdx" />

## What the panel shows

The panel is a floating inspector for the application's consent runtime. Its
tabs:

| Tab | Shows |
| --- | --- |
| `consents` | Effective permissions and the recorded choice per category, with switches to stage and save a test choice. |
| `scripts` | Each registered script and its loading state. |
| `location` | The country, region and language the policy resolved for, with overrides to test another location. |
| `policy` | The resolved policy rule, its model, prompt, scope and rights. |
| `iab` | The TCF state, when IAB is on. |
| `events` | The consent runtime's events and script lifecycle events. |
| `actions` | Buttons to open the banner or dialog, reset the draft, clear stored records and resolve the policy again. |

Clearing records from the panel calls `ConsentManager.clearRecords()`, which
respects a custom `storageConfig`. Location overrides from the panel change
the current page only.

## Inputs

`provideInthDevTools()` takes the same fields as one options object.

| Input | Type | Default | Behavior |
| --- | --- | --- | --- |
| `position` | `'bottom-right'`, `'bottom-left'`, `'top-right'` or `'top-left'` | `'bottom-right'` | Corner of the panel's toggle. |
| `defaultOpen` | `boolean` | `false` | Opens the panel on load. A bare `defaultOpen` attribute counts as `true`. |
| `defaultTab` | one of the tabs above | `'consents'` | The tab it opens on. |
| `maxEvents` | `number` | `100` | How many events the `events` tab keeps. |
| `getConsentCategories` | `() => AllConsentNames[]` | `ConsentManager.consentCategories()` | Categories the `consents` tab lists. |
| `getPresentation` | `() => ConsentPresentation` | the provider's `presentation` | Presentation used for the panel's diagnostics. |
| `clearRecords` | `() => void` | `ConsentManager.clearRecords()` | Replaces what the clear action does. |
| `shadow` | `boolean` | `true` | `false` mounts the panel without a shadow root and puts its stylesheet in `<head>`. A bare `shadow` attribute counts as `true`. |

## Open DevTools from the consent trigger

While `<inth-consent-dialog-trigger>` is visible, it becomes a two-button
toolbar with a DevTools button, and DevTools hides its own floating launcher,
so one control occupies the corner. The panel opens next to the toolbar and
follows it when a visitor drags the toolbar to another corner. `position`
applies again once no trigger is visible.

## Keep it out of production

The panel can clear consent and change the location the policy resolves for.
Render it in development only. `isDevMode()` is a runtime check, so on its own
it does not remove the panel's code from a production bundle. In the component
example, `@defer` moves `ConsentDevTools` and the panel's engine into
a separate chunk that the browser fetches only when the `@if` is true.
`provideInthDevTools()` in `app.config.ts` keeps the panel in the main bundle
even behind `isDevMode()`; to drop it, provide it from a development-only
file swapped in with `fileReplacements` in `angular.json`.

## Verify it

Run `ng serve`. The DevTools launcher appears in its corner, and the
`consents` tab matches the banner's state. Run `ng build` and check that the
browser loads no DevTools chunk in production.
