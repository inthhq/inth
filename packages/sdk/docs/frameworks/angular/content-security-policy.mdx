## Set the policy where you serve the app

The policy comes from a `Content-Security-Policy` header, or a
`<meta http-equiv="Content-Security-Policy">` tag in `index.html`. A
browser-only Angular app served as static files cannot put a fresh nonce in
each response, so allow each vendor's script host in `script-src`, and set
`styles: false` in `provideInth()` with `@inth/angular/styles.css` in the
`styles` array of `angular.json`. `'self'` then covers Inth's stylesheet.

A server-rendered app can create a nonce per response. Angular reads it from
the `ngCspNonce` attribute on your root element, or from the `CSP_NONCE`
token, and stamps it on the `<style>` elements Angular itself adds. Angular's
`autoCsp` build option covers its own inline scripts by hash instead. Test the
policy against `ng build` output, not `ng serve`, which adds its own scripts
and styles.

## What Inth adds to the page

A Content Security Policy has to allow each thing Inth or your vendors put on
the page:

| Inth does | Directive | Allow |
| --- | --- | --- |
| Requests the policy from `/v1/consent/init` and saves choices to `/v1/consent/records` | `connect-src` | Your backend's origin. `'self'` covers a same-origin route such as `/api/inth`. |
| Adds a `<script>` element for each allowed entry in `scripts` | `script-src` | Each vendor's script host, or the provider's `nonce`. |
| Lets vendor scripts load more scripts, pixels and requests | `script-src`, `img-src`, `connect-src` | The hosts each vendor documents. |
| Sets `src` on gated iframes, or creates `<inth-consent-gate>` content | `frame-src` | Each embed's host, such as `https://www.youtube-nocookie.com`. |
| Adds its rules to `<head>` as `<style>` elements | `style-src` | The nonce. With `styles: false` and the imported stylesheet, `'self'`. |
| Writes theme slot `style` objects, and the trigger's position while it is dragged, as `style` attributes | `style-src-attr` | `'unsafe-inline'`, if you use slot `style` objects or a draggable `<inth-consent-dialog-trigger>`. Without it the browser refuses those attributes; slot class names and the stock look are unaffected. |
| With server rendering, adds a script that starts allowed `scripts` and one that holds early taps on the banner | `script-src` | The nonce. |
| Fetches the Global Vendor List under an IAB policy | `connect-src` | The vendor list host the policy names, when it is not your own origin. |

The dev tools panel attaches a stylesheet to its shadow root. Keep the panel
out of production builds, as [its page](./components/dev-tools) describes,
and a production policy does not need to allow it.

## Pass the nonce to Inth

Inth's `<style>` and `<script>` elements use the `nonce` option of
`provideInth()`, and fall back to Angular's `CSP_NONCE`. An app that already
sets `ngCspNonce` on its root element needs no more setup. If the nonce comes
from somewhere else, provide `CSP_NONCE` yourself, and Angular and Inth both
use it:

<include src="../../shared/examples/angular/csp-nonce.mdx" />

The script loader then sets that nonce on every `<script>` it adds, for both
`src` and inline `textContent` scripts. A `nonce` on one `scripts` entry wins
for that script.

The nonce covers only the elements Inth creates. A script that a vendor's
script loads by itself does not get it; allow that host in `script-src`, or
add `'strict-dynamic'` so scripts loaded by a trusted script are trusted too.
With `'strict-dynamic'`, browsers ignore host allowlists in `script-src`, so
every script on the page needs the nonce or a hash.

## Verify the policy

Enforce the policy, not report-only, and open the console with site data
cleared:

1. The banner renders with its styles, and no `Refused to` message mentions a
   Inth element, a `<style data-inth-styles>` element or
   `@inth/angular/styles.css`. Open the preference dialog and check again.
2. Allow a category. Its vendor scripts load, and none are refused. A refused
   script from a vendor's own host means that host is missing from
   `script-src`.
3. Save a choice. The request to `/v1/consent/records` succeeds; a `connect-src`
   violation means the backend's origin is missing.
4. Allow the category of a gated embed. It loads; a `frame-src` violation
   names the host to add.
