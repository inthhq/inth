Change the colors, container, button styles and copy of Inth's Angular
components using CSS variables, theme slots and component inputs.

## Pick the right tool

| Change | Use |
| --- | --- |
| Brand colors, radius, type, spacing | `--inth-*` variables in a global stylesheet |
| One part of one component | `theme.slots` in `provideInth()` |
| Button styles by action | `theme.consentActions` |
| Container, edge style, blocking, button order | `<inth-consent-banner>` inputs or `presentation.prompt` |
| Wording and languages | Banner text inputs, or [translations](/docs/frameworks/angular/translations) |
| Different markup | [Headless](/docs/frameworks/angular/headless) |

[Customization](/docs/customization/overview) explains how these layers fit
together across frameworks.

## Set brand colors and radius

Write the `--inth-*` variables on `:root` in a global stylesheet. Inth's
default tokens carry zero specificity, so your rule overrides them regardless
of load order:

<include src="../../shared/examples/angular/theme-css.mdx" />

Add the file to the `styles` array of your build target in `angular.json`,
or `@import` it from `src/styles.css`. Do not put it in a component's
`styles`: Angular scopes component styles, and the variables must sit on
`:root`.

Pair a hover color and text color with the primary color so buttons remain
readable in each state. [Theme tokens](/docs/customization/tokens) lists
every variable and its default. The defaults are a `#2563eb` primary
(`#2f66df` in dark mode), a 16px `--inth-radius-lg` and a 10px
`--inth-radius-md`.

If your stylesheet already sets the `--consent-banner-*` and
`--consent-dialog-*` variables, keep them: each part reads its own variable
first, then the matching `--consent-banner-*` or `--consent-dialog-*` one,
then the theme token. [Classic variable compatibility](/docs/customization/tokens#classic-variable-compatibility)
lists which variable reaches which part, and the few that no longer apply.

Do not put colors, radius or other design tokens in the `theme` option. In
the browser, `theme` applies slots and `consentActions` only; design tokens
in it are ignored. In development, `ConsentTheme` warns when `theme` carries
tokens without a `<style id="inth-theme">` element.

If your tokens come from runtime data, `generateThemeCSS(theme)` from
`@inth/angular` converts a theme object into CSS. Render the result inside a
`<style id="inth-theme">` element. Its selectors outrank stock defaults and
plain `:root` rules, so write manual overrides on `:root:root` if you mix
both.

## Switch to dark tokens

`colorScheme` toggles the `inth-dark` class on `<html>`: `'dark'` always,
`'system'` when the OS prefers dark, `'light'` never. Left unset,
`ConsentTheme` mirrors a `dark` class on `<html>` into `inth-dark`, so apps
with an existing dark mode toggle work automatically. Pass `null` if your app
manages `inth-dark` directly. Override dark tokens under `:root.dark` and
`:root.inth-dark` in your stylesheet. [Dark mode](/docs/customization/dark-mode)
covers dark first paint.

## Style one part with theme slots

The `theme` option applies slot styles in the browser. A slot takes a class
name or `{ className, style, noStyle }`:

<include src="../../shared/examples/angular/theme.mdx" />

Pass it as `theme` to `provideInth()`. Define slot classes in a global
stylesheet, because consent components render outside your component's view
encapsulation. Angular components read these slots:

| Component | Slots |
| --- | --- |
| `<inth-consent-banner>` | `consentBanner`, `consentBannerOverlay`, `consentBannerCard`, `consentBannerHeader`, `consentBannerTitle`, `consentBannerDescription`, `consentBannerExpand`, `consentBannerRightsRow`, `consentBannerSaveButton`, `consentBannerFooter`, `consentBannerFooterSubGroup`, `consentBannerRightLink`, `consentBannerTag` |
| `<inth-consent-dialog>` | `consentDialog` (the backdrop), `consentDialogOverlay` (the same element), `consentDialogCard`, `consentDialogSheet`, `consentDialogHeader`, `consentDialogTitle`, `consentDialogDescription`, `consentDialogContent`, `consentDialogFooter`, `consentDialogCategoryGroup`, `consentDialogVendorTable`, `consentDialogRightsRow`, `consentDialogReceipt`, `consentDialogPreferencesRow`, `consentDialogSaveButton`, `consentDialogDoneButton` |
| `<inth-consent-widget>` | `consentWidget`, `consentWidgetOptOut`, `consentWidgetOptOutStatus`, `consentWidgetAccordion`, `consentWidgetFooter`, `consentWidgetFooterSubGroup`, `consentWidgetTag` |
| `<inth-consent-dialog-trigger>` | `consentDialogTrigger`, `consentDialogTriggerIcon`, and with dev tools `consentDialogTriggerToolbar`, `consentDialogTriggerToolbarItem`, `consentDialogTriggerToolbarIcon` |
| `<inth-iab-consent-banner>` | `iabConsentBanner`, `iabConsentBannerCard`, `iabConsentBannerHeader`, `iabConsentBannerFooter`, `iabConsentBannerTag`, `iabConsentBannerOverlay` |
| `<inth-iab-consent-dialog>` | `iabConsentDialog`, `iabConsentDialogCard`, `iabConsentDialogHeader`, `iabConsentDialogFooter`, `iabConsentDialogTag`, `iabConsentDialogOverlay` |
| `<inth-consent-gate>` | `consentGate`, `consentGateTitle`, `consentGateButton` |
| Buttons in every component | `buttonPrimary`, `buttonSecondary` |

Slot names differ from React's `components.banner.card` keys. Use slots to
style one part and tokens to change values globally. The banner's root
carries `data-placement`, so a slot class can target one container, such as
`[data-placement='banner-bottom'] .brand-banner-card`.
[Component parts](/docs/customization/slots) documents data attributes, and
[Tailwind CSS](/docs/customization/tailwind) covers Tailwind 4 and 3.

## Change button styles by action

`theme.consentActions` styles each button by action regardless of button
order. A per-action entry overrides `primary`, which overrides `default`. The
policy decides which action is primary.

## Choose the banner's container

The banner renders as a Card, a full-width Banner or a Drawer. Set the
container on the banner, or for the whole app as
`presentation.prompt.container` in `provideInth()`. Without either, the
policy rule's `surface.container` applies, so a region's placement can live
in the dashboard instead of your code:

<include src="../../shared/examples/angular/bottom-bar.mdx" />

| Container | Positions |
| --- | --- |
| `{ type: 'card', position }` | `start` (default), `end`, `center` |
| `{ type: 'banner', edge }` | `bottom` (default), `top` |
| `{ type: 'drawer', side }` | `bottom` (default), `top`, `start`, `end` |

`start` and `end` follow the writing direction, so the same setting puts the
Card in the right corner on a right-to-left page. `edgeStyle` (`inset` or
`flush`) decides whether a Banner or Drawer floats off the viewport edges or
runs edge to edge.

`blockUntilChoice` adds a backdrop, locks scroll, traps focus and blocks
outside clicks until the visitor chooses. A centred Card always blocks. A
notice, an opt-out prompt, and a policy whose `surface.blocking` is
`forbidden` never block. [ConsentBanner](./components/consent-banner#containers)
covers every container and when blocking applies.

`layout` sets button order and grouping. Where it conflicts with the policy,
the policy wins: a policy that requires a reject button keeps it.

Text inputs such as `heading` and `rejectButtonText` replace copy for that
banner in every language. For site-wide copy, pass `i18n`; see
[translations](./translations). For markup the stock banner cannot produce,
build your own with [headless](./headless) state.

## Turn off animations

`disableAnimation` in `provideInth()` disables banner and dialog transitions,
and the same input on `<inth-consent-banner>`, `<inth-consent-dialog>`,
`<inth-iab-consent-banner>` or `<inth-iab-consent-dialog>` overrides it per
surface. When unset, components follow `prefers-reduced-motion`.
[Motion and animation](/docs/customization/motion) covers duration and easing
tokens.

## Remove Inth's styles

Set `noStyle` on one component or in `provideInth()` to keep the stock markup
and behavior without `inth` classes. Style the `data-*` attributes and slot
classes yourself. For fully custom markup, see [headless](./headless).
