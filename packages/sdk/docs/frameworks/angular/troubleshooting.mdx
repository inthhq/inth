Diagnose and fix common Inth setup issues in Angular applications.

## Why is there no banner?

**Check.** Inspect `consent.policyRule().prompt` and `consent.location()`
from an injected `ConsentManager`, or open [Dev tools](./components/dev-tools).
Check the `/v1/consent/init` request in the Network panel.

**Fix.**

1. **The policy requires no prompt.** Regions without a consent requirement
   and silent opt-out policies show no banner. See
   [why the banner may be absent](/docs/concepts/policies#why-the-banner-may-be-absent).
2. **A choice is already stored.** Clear site data for your origin or reset
   in DevTools, then reload.
3. **The request to Inth failed.** A CORS error means your origin is missing
   from the project's trusted origins. A 404 means `projectUrl` is wrong.
   While `/v1/consent/init` fails, optional categories stay denied and no banner renders.
4. **The component is not imported.** Angular reports
   `'inth-consent-banner' is not a known element` at build time. Add
   `ConsentBanner` to the component's `imports`.
5. **The policy uses IAB without the `iab` option.** The console shows
   `IABUnavailableError`. Add `iab` to `provideInth()` and render
   `<inth-iab-consent-banner>`; see [IAB TCF](./iab).

## NullInjectorError: No provider for ConsentManager

**Check.** A component, directive or `injectEventDispatcher()` ran outside an
injector with `provideInth()`.

**Fix.** Add `provideInth()` to `providers` in `ApplicationConfig`. If you
provide it on a lazy route, render every consent component inside that route.
With SSR, keep `provideInth()` in `app.config.ts` so `app.config.server.ts`
merges it.

If `provideInth()` is already registered, confirm the app resolves a single
copy of `@inth/angular` (duplicate linked copies create distinct
`ConsentManager` tokens), then run `ng cache clean`.

## Theme colors are ignored

**Check.** The `theme` option applies slot styles and `consentActions` only;
design tokens in `theme` are not converted to CSS in the browser.

**Fix.** Define `--inth-*` variables on `:root` in a global stylesheet, or
inject `generateThemeCSS()` output in `<style id="inth-theme">`. See
[customize](./customize).

If you placed variables in a component's `styles`, move them to `src/styles.css`
or a file in `angular.json` `styles` because Angular scopes component styles.
If a generated theme still wins over your `:root` rule, write your override on
`:root:root`.

## A slot class has no effect

**Check.** The class lives in a component's `styles`. Angular's emulated view
encapsulation scopes it to an attribute that Inth's elements do not carry.

**Fix.** Move slot classes to a global stylesheet.

## The dialog or banner has no styles

**Check.** Look for `<style data-inth-styles>` elements in `<head>` and check
the console for Content Security Policy errors.

**Fix.**

- If no `<style data-inth-styles>` exists, check whether `provideInth()` sets
  `styles: false` or `noStyle`. With `styles: false`, add
  `@inth/angular/styles.css` to `styles` in `angular.json`.
- If CSP blocked inline styles, set `ngCspNonce`, provide `CSP_NONCE`, or set
  `styles: false` and import the stylesheet; see
  [Content Security Policy](./content-security-policy).
- If IAB components are unstyled with `styles: false`, add
  `@inth/angular/iab/styles.css` after `@inth/angular/styles.css`.

## The server HTML and the browser disagree

**Check.** The console logs an Angular hydration error (`NG0500` or similar)
near a consent component, or the banner flashes after load.

**Fix.** Confirm `provideClientHydration()` is in `app.config.ts` and
`provideInthServer()` is in `app.config.server.ts`. Routes built with
`RenderMode.Prerender` share one HTML document across all visitors; use
`RenderMode.Server` for per-visitor consent HTML. See [rendering](./rendering).

## A vendor loads before consent, or twice

**Check.** Clear site data and watch the Network panel before clicking
anything. If the vendor still loads, another loader exists in `index.html`,
`angular.json`, a tag manager or a direct SDK import.

**Fix.** Remove the duplicate loader and register the vendor only in `scripts`.

## The page reloads after saving

**Check.** Withdrawing a previously granted category triggers a reload so
already-running vendor code stops. This is expected behavior.

**Fix.** Set `reloadOnConsentRevoked: false` in `provideInth()` only when
every registered vendor stops itself via its own consent API.
