React to consent choices, permission changes and banner impressions in Angular
using `provideInth()` callbacks, script callbacks or `ConsentManager` signals.

## Pick the right callback

| You want to | Use |
| --- | --- |
| Send a choice to your analytics or CRM when the visitor makes one | `callbacks.onChoiceRecorded` |
| Start or stop code when effective permissions change | `callbacks.onPermissionsChanged` |
| Count banner and dialog impressions | `callbacks.onSurfaceShown` |
| Report failed backend requests | `callbacks.onError` |
| Show a message or flush data before a withdrawal reloads the page | `callbacks.onBeforeConsentRevocationReload` |
| Call a vendor's consent API after its script loads | The script's `onConsentChange` |
| React to consent inside one component | A `ConsentManager` signal in `computed()` or `effect()` |

## onChoiceRecorded or onPermissionsChanged

`onChoiceRecorded` runs only when the visitor accepts, rejects or saves.
`onPermissionsChanged` runs whenever effective permissions change for any
reason:

| Event | `onChoiceRecorded` | `onPermissionsChanged` |
| --- | --- | --- |
| Visitor accepts, rejects or saves | Yes | Yes, if a permission changed |
| Policy resolves under opt-out and allows categories before a choice | No | Yes |
| Global Privacy Control overrides a grant | No | Yes |
| A recorded choice expires | No | Yes |
| Visitor dismisses a notice | No | No |

Use `onChoiceRecorded` for consent logs and audit trails. Use
`onPermissionsChanged` to start or stop features. Never treat
`onPermissionsChanged` as proof that the visitor agreed to something.

## Pass callbacks to the provider

Define the callbacks in a separate module:

Pass them in `src/app/app.config.ts`:

{/* example: fragment */}

```ts title="src/app/app.config.ts (partial)"
provideInth({ mode, scripts, callbacks });
```

Callbacks run as plain functions outside Angular's injection context, so they
cannot call `inject()`. To reach an Angular service, read `ConsentManager`
signals in an `effect()` instead.

| Callback | Payload |
| --- | --- |
| `onChoiceRecorded` | `snapshot` (state after choice), `confirmed` (categories recorded), `actionAt` (timestamp). |
| `onPermissionsChanged` | `snapshot` (state after change), `previous` (permissions before change). |
| `onSurfaceShown` | `surface`, `shownAt`, `snapshot`, `experiment` (assigned arm if any). Fires once per opening, never for hydrated records or server renders. |
| `onError` | `error`, a message string. |
| `onBeforeConsentRevocationReload` | `preferences`, permissions after withdrawal. |

Callbacks run after Inth updates its state, so `snapshot` and `ConsentManager`
already hold the new values. Because the runtime does not start on the server,
callbacks run in the browser only.

`onBeforeConsentRevocationReload` runs synchronously right before the reload.
Keep it brief because the page is about to unload. It does not fire when
`reloadOnConsentRevoked` is `false`.

## Script callbacks

Each entry in `scripts` accepts lifecycle callbacks:

| Callback | Runs |
| --- | --- |
| `onBeforeLoad` | Before the loader inserts the script. |
| `onLoad` | After the script finishes loading. |
| `onError` | When the script fails to load. |
| `onConsentChange` | When consent changes after load. Call the vendor's consent API here. |
| `onDispose` | When the script configuration is removed or the app destroys. |

Helpers from `@inth/integrations` configure these for each vendor.
[Building integrations](/docs/integrations/building-integrations) shows how to
write custom ones.

## React inside one component

Inside a component, read `ConsentManager` signals. `computed()` derives
template state and `effect()` runs side effects with automatic cleanup. To
subscribe to kernel events, register the listener inside an `effect()` with
`onCleanup`. [ConsentManager](./services#listen-to-consent-events) shows an
example.

## Verify the callbacks

Open the console, clear site data and reload:

1. The banner appears. `onSurfaceShown` logs `banner`.
2. Accept in the banner. Both `onChoiceRecorded` and `onPermissionsChanged`
   log.
3. Dismiss a notice, if your policy shows one. Neither logs.
4. Withdraw an allowed category. `onBeforeConsentRevocationReload` logs, then
   the page reloads.
