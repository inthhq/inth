Register vendor scripts with `provideInth()` so they load only after the
visitor allows their consent category, and dispatch analytics events safely.

## Register scripts on the provider

Pass the array from `src/scripts.ts` to `provideInth()` as `scripts`. The
[quickstart](/docs/frameworks/angular/quickstart) creates this file:

<include src="../../shared/examples/angular/scripts.mdx" />

Replace the placeholder PostHog project key with your own.

The script loader loads as a separate chunk, shared with the
[network blocker](./network-blocker). The runtime downloads it only when
`scripts` is non-empty or the blocker has rules. With
[server rendering](./rendering), the server starts scripts the visitor's
stored consent already allows before hydration.

## How registered scripts load

Each script configuration declares a category. The loader inserts the script
when its category becomes allowed and removes it when the category is
withdrawn. Optional scripts never load while the policy is resolving or after
a fetch failure.

Helpers in `@inth/integrations`, such as `posthog()` from
`@inth/integrations/posthog`, return a configuration with the right category
and vendor consent calls. [Integrations](/docs/integrations/overview) lists
every helper. For an SDK without a helper, write a configuration with `id`,
`category` and `src`; see
[building integrations](/docs/integrations/building-integrations).

Remove the vendor's original `<script>` tag from `index.html`, its entry in
`angular.json`, and any direct SDK import before registering it. A banner
cannot block code loaded another way, and a vendor loaded twice sends
duplicate events.

To add or remove scripts after bootstrap, call
`ConsentManager.updateOptions({ scripts })` with the full updated array.

## Script options

Helpers fill these in for you. For a custom script, pass an object with these
fields:

| Option | Default | Behavior |
| --- | --- | --- |
| `id` | required | Unique name. The loader uses it to add and remove the script once. |
| `category` | required | Category or condition, such as `'measurement'` or `{ and: ['measurement', 'marketing'] }`, that must be allowed. |
| `src` or `textContent` | none | Script URL or inline code. |
| `callbackOnly` | `false` | `true` or a zero-argument predicate returning `true` adds no `<script>` element and runs callbacks only. Keep predicates side-effect-free and server-safe. |
| `alwaysLoad` | `false` | Loads immediately regardless of consent. Use only for scripts that enforce consent themselves, such as a tag manager with Consent Mode. |
| `persistAfterConsentRevoked` | `false` | `true` keeps the element after withdrawal, including pending downloads. `'loaded'` keeps only elements whose load event completed; pending and failed loads are removed. |
| `target` | `'head'` | Where to insert the element: `'head'` or `'body'`. |
| `async`, `defer`, `fetchPriority`, `attributes`, `nonce` | none | Attributes set on the `<script>` element. |
| `anonymizeId` | `true` | Assigns a random element `id` so ad blockers do not match it by name. |
| `vendor` | none | Also waits for this vendor to be allowed, for vendor-level consent outside IAB. |
| `onBeforeLoad`, `onLoad`, `onError`, `onConsentChange`, `onDispose` | none | Lifecycle callbacks. See [callbacks](./callbacks#script-callbacks). |

## Send your own analytics events

`injectEventDispatcher()` from `@inth/angular/consent-gate` returns the
application's event dispatcher. It sends to the provider's `scripts` and
checks consent before dispatching. Call it in an injection context, such as a
field initializer, and send a page view on each `NavigationEnd`:

<include src="../../shared/examples/angular/analytics-events.mdx" />

Call `track('sign_up', { method: 'email' })` from an event handler for custom
events. `track` forwards to every registered script with an event API and
drops events while measurement is denied. `pageview` sends only to the
integrations named in `pageviews`, and the first call records the initial path
without sending. All dispatchers under the provider share one pageview
history, so re-created components do not replay a navigation.
`injectEventDispatcher()` throws outside an injection context or without
`provideInth()`. See
[send events only to allowed integrations](/docs/integrations/overview#send-events-only-to-allowed-integrations)
for supported vendors.

## Gate embeds and your own content

Iframes are not scripts. Wrap them in `<inth-consent-gate>` to keep the
iframe out of the DOM until its category is allowed:

<include src="../../shared/examples/angular/youtube-embed.mdx" />

For content without a placeholder, use the `*inthIfConsent` structural
directive. For iframes from a CMS or `[innerHTML]`, use the iframe blocker's
`data-category` and `data-src` attributes. [Embeds](./embeds) covers all
three.

## Block requests from code already on the page

`networkBlocker` holds `fetch` and `XMLHttpRequest` calls to domains you list
until their category is allowed. Use it as a backstop for code you cannot
move into `scripts`. [Network blocker](./network-blocker) covers rule syntax
and limits.

## What happens when consent is withdrawn

Removing a script tag cannot stop code that already ran. When a save withdraws
a previously granted category, the runtime reloads the page after the save
finishes so the page restarts with only permitted code. Set
`reloadOnConsentRevoked: false` in `provideInth()` if you handle withdrawal
yourself, such as through a vendor's opt-out call in `onConsentChange`.

`<inth-consent-gate>` and `*inthIfConsent` content destroys without a reload.
To delete first-party cookies a vendor set, configure `clearOnRevocation`; see
[clear on revocation](./clear-on-revocation).

## Let visitors turn off one vendor

A visitor can allow marketing and still switch off one vendor in it. Pass
`vendors` to `provideInth()`; helpers from `@inth/integrations` already carry
their vendor slug. See [vendor consent](./vendor-consent).

## Verify vendor loading

Open DevTools, clear site data for your origin and reload:

1. With the banner visible, the Network panel has no requests to your vendors,
   and gated iframes are absent from the Elements panel.
2. Allow one category in preferences. Only that category's vendors load, and
   its iframes appear.
3. Reject, reload, and confirm the vendor requests stay absent.
4. Withdraw an allowed category. The page reloads and its vendors no longer
   load.

[Verify consent](/docs/guides/verify-consent) covers automated checks.
