## Pick a way to gate the embed

A YouTube video, a map or a social post in an iframe contacts its vendor as
soon as it loads. c15t offers three ways to keep it from loading before
consent:

| Your markup | Use | Placeholder |
| --- | --- | --- |
| A component template you write | `<c15t-consent-gate>` around the iframe | Built in, or your own `ng-template` |
| A template where you want your own fallback, or a condition on several categories | `*c15tIfConsent` on the iframe | Your `else` template, or none |
| HTML you do not control, such as CMS content or `[innerHTML]` | The iframe blocker with `data-category` and `data-src` | None; the iframe stays empty |

All three use the visitor's effective permission, and all three remove the
embed again when the visitor withdraws it.

## Wrap the iframe in c15t-consent-gate

<include src="../../shared/examples/angular/youtube-embed.mdx" />

The iframe is in an `ng-template c15tConsentGateContent`, so Angular creates
it only while measurement is allowed and destroys it when measurement is
withdrawn. The browser never requests it before. The
`c15tConsentGatePlaceholder` template replaces the built-in placeholder and
includes a `c15tConsentDialogLink` button, so a visitor can allow the category
from the embed's own spot. Keep `<c15t-consent-dialog>` rendered for that
button. [c15t-consent-gate](./components/consent-gate) lists its inputs.

Use the content template for anything with side effects. Without it, the gate
projects its children with `<ng-content>`: Angular creates projected nodes
with the parent view even while the gate keeps them out of the document, so an
`<iframe>` loads nothing, but a component inside still runs its constructor.

Pick the category the vendor's embed needs. YouTube and maps usually fit
`measurement` or `marketing`; check what each vendor sets.

## Render content only while consent holds

`*c15tIfConsent` works like `@if` with a consent condition. It takes a
category name, or a condition such as `{ and: ['functionality', 'marketing'] }`,
and an optional `else` template:

<include src="../../shared/examples/angular/if-consent.mdx" />

The directive renders on the server too, from the state the server resolved,
so its output can be in the first HTML. `<c15t-consent-gate>` renders an
empty host on the server and fills it one frame after the first browser
render.

## Gate iframes you do not render

The iframe blocker is on by default. It watches the page for iframes with a
`data-category` attribute:

{/* example: fragment */}

```html
<iframe
  title="Store locations"
  data-category="functionality"
  data-src="https://www.google.com/maps/embed?pb=..."
></iframe>
```

- While the category is denied, the iframe has no `src`, so it loads nothing.
- When the category is allowed, the blocker copies `data-src` to `src`.
  Only `http` and `https` URLs are used.
- When the category is withdrawn, the blocker removes `src` again.

Iframes without `data-category` or `data-vendor` are never touched. Put
`data-src` in the HTML instead of `src`; an iframe that arrives with `src`
already starts loading before the blocker sees it. Add `data-vendor` with a
vendor slug to also keep the iframe empty while the visitor has that vendor
turned off. Angular's sanitizer keeps `data-*` attributes in `[innerHTML]`
but drops `<iframe>` elements, so CMS HTML with iframes needs
`DomSanitizer.bypassSecurityTrustHtml()` for content you trust.

The blocker has no placeholder. Style the empty iframe, or place a note and a
`c15tConsentDialogLink` button next to it.

Pass `iframeBlocker: false` to `provideC15t()` to turn the blocker off.

## Verify the embeds

Clear site data and reload with DevTools open:

1. The Network panel has no request to the embed's host, and the Elements
   panel shows the placeholder or an iframe without `src`.
2. Allow the category in preferences. The embed loads without a page reload.
3. Withdraw the category. The embed disappears, or its iframe loses `src`.
