Hold YouTube videos, maps and other third-party iframes until the visitor
allows their consent category.

## Pick a way to gate the embed

An iframe contacts its vendor as soon as it loads. Inth offers three ways to
hold it until consent allows it:

| Your markup | Use | Placeholder |
| --- | --- | --- |
| A component template you write | `<inth-consent-gate>` around the iframe | Built in, or your own `ng-template` |
| A template where you want your own fallback, or a condition on several categories | `*inthIfConsent` on the iframe | Your `else` template, or none |
| HTML you do not control, such as CMS content or `[innerHTML]` | The iframe blocker with `data-category` and `data-src` | None; the iframe stays empty |

All three check effective permission and remove the embed when the visitor
withdraws consent.

## Wrap the iframe in inth-consent-gate

<include src="../../shared/examples/angular/youtube-embed.mdx" />

The iframe sits in an `ng-template inthConsentGateContent`, so Angular creates
it only while measurement is allowed and destroys it when measurement is
withdrawn. The `inthConsentGatePlaceholder` template replaces the built-in
placeholder and includes a `inthConsentDialogLink` button so visitors can
enable the category inline. Keep `<inth-consent-dialog>` rendered for that
button. [inth-consent-gate](./components/consent-gate) lists its inputs.

Use the content template for anything with side effects. Without it, the gate
projects children with `<ng-content>`: Angular instantiates projected
components with the parent view even while hidden, so an `<iframe>` loads
nothing, but a component inside still runs its constructor.

Pick the category the vendor's embed requires. YouTube and maps usually fit
`measurement` or `marketing`.

## Render content only while consent holds

`*inthIfConsent` works like `@if` with a consent condition. Pass a category
name or a condition such as `{ and: ['functionality', 'marketing'] }`, plus
an optional `else` template:

The directive renders on the server from the server-resolved state, so its
output appears in the first HTML. `<inth-consent-gate>` renders an empty host
on the server and fills it one frame after the first browser render.

## Gate iframes you do not render

The iframe blocker is on by default. It watches the page for iframes with a
`data-category` attribute:

{/* example: fragment */}

```html
<iframe
  title="Store locations"
  data-category="functionality"
  data-src="https://www.google.com/maps/embed?pb=..."
></iframe>
```

- While the category is denied, the iframe has no `src` and loads nothing.
- When the category is allowed, the blocker copies `data-src` to `src` (only
  `http` and `https` URLs).
- When the category is withdrawn, the blocker removes `src`.

Iframes without `data-category` or `data-vendor` are untouched. Put
`data-src` in the HTML instead of `src`; an iframe that arrives with `src`
starts loading before the blocker sees it. Add `data-vendor` with a vendor
slug to also block the iframe when the visitor switches that vendor off.
Angular's sanitizer drops `<iframe>` elements in `[innerHTML]`, so trusted
CMS HTML with iframes needs `DomSanitizer.bypassSecurityTrustHtml()`.

The blocker renders no placeholder. Style the empty iframe, or place a note
and a `inthConsentDialogLink` button next to it. Pass `iframeBlocker: false`
to `provideInth()` to disable the blocker.

## Verify the embeds

Clear site data and reload with DevTools open:

1. The Network panel has no request to the embed's host, and the Elements
   panel shows the placeholder or an iframe without `src`.
2. Allow the category in preferences. The embed loads without a page reload.
3. Withdraw the category. The embed disappears, or its iframe loses `src`.
