`ConsentManager` exposes consent state as Angular signals and provides methods
to update and save choices. `provideInth()` provides it. Inject it in any
component, directive or service:

<include src="../../shared/examples/angular/consent-status.mdx" />

Every readable field is a `Signal`, so it works in templates, `computed()` and
`effect()` and updates `OnPush` components without `markForCheck()`. Call each
signal to read it: `consent.activeUI()`, not `consent.activeUI`. Methods such
as `has()` and `isVendorAllowed()` read signals too, so a template or
`computed()` that calls them updates when consent changes.

## Read a permission or a recorded choice

| Member | Value |
| --- | --- |
| `has(condition)` | `true` while a category, or a condition such as `{ and: ['measurement', 'marketing'] }`, `{ or: [...] }` or `{ not: ... }`, is allowed now. |
| `effectivePermissions()` | What each category may do now, after the policy, stored choice and privacy signals. |
| `explicitChoice()` | The visitor's recorded choice, or `null` before one. |
| `noticeDismissal()` | The record of a dismissed notice. A dismissal is not a grant. |
| `optOutState()` | Derived opt-out display state: whether an opt-out is available, whether one is honored, how it was recorded and whether GPC or an account locks it. |
| `privacySignals()` | Global Privacy Control and other signals. |
| `isVendorAllowed(id)` | `true` while one vendor may load. See [vendor consent](./vendor-consent). |
| `vendorChoice()` | The vendors the visitor turned off. |

`has()` and `effectivePermissions()` can be `true` before the visitor
chooses under an opt-out policy, and Global Privacy Control can turn a
recorded grant off. Use `explicitChoice()` to check whether the visitor
actually chose, never `has()`.

## Read the policy and the UI state

| Member | Value |
| --- | --- |
| `hasPolicy()` | Whether a policy rule has resolved for this visitor. Stock components render nothing until it is `true`. |
| `policyPending()` | Whether a policy is still resolving. |
| `policyRule()` | The resolved rule: `model`, `prompt`, `rights`, scope and more. |
| `model()` | `'iab'` under an IAB policy, else the rule's model: `opt-in`, `opt-out` or `none`. |
| `hasConsentUi()` | Whether the rule owes any consent UI. |
| `hasConsentPreferences()` | Whether Inth or an external CMP offers a way back to preferences. `inthConsentDialogLink` hides its host while this is `false`. |
| `activeUI()` | `'banner'`, `'dialog'` or `'none'`. |
| `location()`, `resolution()` | The visitor's resolved location, and how the policy resolved. |
| `consentCategories()`, `consentTypes()` | The categories the preference UI shows, and their metadata. |
| `presentation()`, `theme()`, `experiment()` | The configured presentation and theme, with the assigned experiment arm merged in. |
| `translations()`, `translationConfig()` | The resolved copy in the active language, and the full configuration components read. |
| `legalLinks()` | The provider's `legalLinks`. |
| `options()` | The provider's options, as changed by `updateOptions()`. |
| `snapshot()` | The whole kernel snapshot. Each field above is a slice of it. |

The other snapshot fields are signals too: `restrictions()`,
`promptRequirement()`, `nextDeadline()`, `subject()`, `user()`, `vendors()`,
`overrides()`, `revision()`, `evaluatedAt()` and `evaluationPolicy()`.

## Record a choice

| Method | Effect |
| --- | --- |
| `saveConsents('all')` | Grants every category in the policy's scope and closes the surface. |
| `saveConsents('necessary')` | Denies every optional category and closes the surface. |
| `saveConsents('custom')` | Records the draft. Throws when the draft is stale. |
| `dismissNotice()` | Records that the visitor dismissed a notice. |
| `setActiveUI(ui)` | Opens `'banner'` or `'dialog'`, or closes with `'none'`. |
| `setLanguage(code)` | Switches the copy and resolves the policy again. See [translations](./translations). |
| `clearRecords()` | Clears receipts, identity and stored records, for tests and dev tools. |
| `updateOptions(patch)` | Changes provider options after bootstrap. See [provideInth](./provide-inth#change-options-after-bootstrap). |

`saveConsents()` closes the surface in the same task once the kernel records
the choice, and sends the request to Inth afterward. Failed requests retry
without reopening the banner. `saveConsents()` rejects when the save fails, so
`await` it and handle errors in custom UI.

## Work with the draft

The preference dialog, `<inth-consent-widget>` and custom preference UIs
stage changes on one draft before saving:

| Member | Value or effect |
| --- | --- |
| `draft.values()`, also `selectedConsents()` | The staged value per category. |
| `draft.vendors()`, also `selectedVendors()` | The staged grant per declared vendor. |
| `draft.isStale()` | `true` when the policy changed since the draft started. Saving then throws. |
| `setConsent(name, value)`, also `draft.set()` | Stage one category. |
| `setSelectedVendor(id, granted)`, also `draft.setVendor()` | Stage one vendor. |
| `draft.reset()` | Drop every staged edit. |
| `getDisplayedConsents()` | Metadata for the categories to show, in order. |
| `getDisplayedVendors(category)` | The vendors to list under one category. |

The draft module loads lazily on the first read of `draft.values()`,
`draft.vendors()` or `draft.isStale()` in the browser. Until it arrives,
those signals read empty and `false`, and `setConsent()` calls queue in
order. [Headless](./headless#build-your-own-preferences) has a full example.

`selectedConsentTypes()` and `setSelectedConsent()` are older names for
`selectedConsents()` and `setConsent()`.

## Read and change IAB TCF consent

`iab()` is the live IAB state, or `null` when IAB is off. `iabUnavailable()`
is `true` when the resolved policy needs IAB and `provideInth()` has no
`iab` option.

| Member | Value or effect |
| --- | --- |
| `config.enabled`, `config.cmpId` | Whether the add-on is on, and the CMP ID. |
| `gvl`, `isLoadingGVL` | The Global Vendor List, and whether it is still loading. |
| `purposeConsents`, `vendorConsents`, `specialFeatureOptIns` | The visitor's TCF choices, staged or saved. |
| `tcString` | The saved TC String, or `null`. |
| `nonIABVendors` | Custom vendors outside the IAB list. |
| `acceptAll()`, `rejectAll()` | Stage every TCF signal on, or off. |
| `setPurposeConsent(id, value)`, `setPurposeLegitimateInterest(id, value)` | Change one purpose. |
| `setVendorConsent(id, value)`, `setVendorLegitimateInterest(id, value)` | Change one vendor. |
| `setSpecialFeatureOptIn(id, value)` | Change one special feature. |
| `setAdTechProviderConsent(id, value)` | Change one Google ad tech provider (Additional Consent). |
| `save()` | Writes the TC String and records the choice. |
| `preferenceCenterTab`, `setPreferenceCenterTab(tab)` | The tab `<inth-iab-consent-dialog>` shows. |

Until the TCF add-on finishes loading, action methods queue and replay.
`whenIABReady()` from `@inth/angular` resolves once it has loaded. See
[IAB TCF](./iab) for setup.

## Listen to consent events

For values you render, read signals. For side effects on an event, such as an
analytics call when a choice is recorded, subscribe to the kernel's events in
an `effect()` so cleanup follows the component:

<include src="../../shared/examples/angular/consent-events.mdx" />

`kernel()` is a signal because the provider swaps the kernel when `enabled`
changes. The `effect()` re-subscribes when it does.
`subscribeToConsentChanges(listener)` calls `listener` with the effective
permissions after each change and returns an unsubscribe function for code
outside Angular's reactivity.

## Verify the state you read

Open the page with DevTools and a component that renders
`consent.effectivePermissions() | json`:

1. Before a choice under an opt-in policy, optional categories are `false`
   and `explicitChoice()` is `null`.
2. Accept. The rendered permissions change without a reload, and
   `explicitChoice()` holds the choice.
3. Reload. The same values render from the stored choice.
