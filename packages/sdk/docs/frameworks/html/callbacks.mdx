React to policy resolution, recorded choices, permission changes and errors
on a plain HTML page through `window.inth` events, `inth:*` DOM events or
`config` callbacks.

## Pick the hook for the job

| You want to | Use |
| --- | --- |
| Start or stop code when permissions change | `consent` event or `callbacks.onPermissionsChanged` |
| Know when a visitor clicked accept, reject or save | `callbacks.onChoiceRecorded` |
| Wait until permissions resolve | `ready` event or `inth.ready()` |
| Show, hide or switch a custom banner | `ui` event |
| Report failed network calls | `error` event or `callbacks.onError` |
| Flush data right before a withdrawal reload | `callbacks.onBeforeConsentRevocationReload` |
| Listen from code that does not touch `window.inth` | `inth:*` events on `document` |

Prefer [gated scripts](/docs/frameworks/html/components/gated-script) for
vendor tags because they block scripts before custom JavaScript runs.

## Listen for events

Queue `on` calls before `inth.js` so listeners catch the initial `ready` and
`consent` events:

{/* example: fragment */}

```html
<script>
  window.inth = window.inth || [];
  inth.push(['on', 'consent', (snapshot) => {
    if (snapshot.effectivePermissions.measurement) {
      startAnalytics();
    }
  }]);
</script>
```

After load, call `inth.on(event, listener)` directly; it returns an
unsubscribe function.

## Listen on document

Each event also dispatches on `document` as a `CustomEvent` (`inth:ready`,
`inth:consent`, `inth:ui`, `inth:error`) with the payload in `event.detail`:

{/* example: fragment */}

```html
<script>
  document.addEventListener('inth:consent', (event) => {
    const allowed = event.detail.effectivePermissions;
    console.log('measurement allowed:', allowed.measurement);
  });
</script>
```

Unlike `inth.on()`, `document` listeners do not replay past events. Attach
them before `inth.js` runs or inspect `inth.getSnapshot()` afterward.

## Config callbacks

Pass lifecycle callbacks under `callbacks` in a queued `config` call:

{/* example: fragment */}

```html
<script>
  window.inth = window.inth || [];
  inth.push(['config', {
    callbacks: {
      onChoiceRecorded: ({ snapshot, confirmed }) => {
        console.log('visitor confirmed', confirmed, snapshot.explicitChoice);
      },
      onPermissionsChanged: ({ snapshot, previous }) => {
        console.log('permissions', previous, '->', snapshot.effectivePermissions);
      },
      onError: ({ error }) => console.warn('Inth:', error),
    },
  }]);
</script>
```

| Callback | Payload | When it runs |
| --- | --- | --- |
| `onChoiceRecorded` | `{ snapshot, confirmed, actionAt }` | Visitor accepted, rejected or saved. |
| `onPermissionsChanged` | `{ snapshot, previous }` | Effective permissions changed for any reason. |
| `onError` | `{ error }` (message string) | A backend request or command failed. |
| `onBeforeConsentRevocationReload` | `{ preferences }` | Synchronously right before a withdrawal reload. Keep it brief. |

## A recorded choice is not a permission change

`onChoiceRecorded` fires only on explicit visitor actions (never on restored
stored choices), making it suitable for consent analytics and audit logs.
`onPermissionsChanged` fires whenever permitted behavior changes (saves,
restored choices, policy resolution, expiry or GPC), making it the hook to
start and stop code. Dismissing a notice fires neither. See
[a permission is not a recorded choice](/docs/concepts/how-consent-works#a-permission-is-not-a-recorded-choice).

## Follow every change with subscribe

`inth.subscribe(listener)` runs with the full snapshot on every state change,
including UI and policy transitions. Queue it like `on`.

## Errors thrown by your listeners

An error in one listener logs to `console.error` without aborting the consent
action, subsequent listeners or `inth:*` DOM events. Keep listeners fast
because they run synchronously.

## Check it works

1. Register a `consent` listener logging `effectivePermissions` and an
   `onChoiceRecorded` callback logging `confirmed`.
2. Open the page in a private window under an opt-in policy; neither logs.
3. Click **Accept All**; both log.
4. Reload; `consent` logs restored permissions while `onChoiceRecorded` stays
   silent.
