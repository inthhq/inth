The preference dialog rendered by `inth.js` lets visitors review and toggle
individual consent categories and vendors without extra markup.

## What the dialog shows

The dialog stays closed until opened by:

- the banner's **Customize** button;
- a [`data-inth-action="customize"` button](/docs/frameworks/html/components/action-buttons);
- a [link to `#inth-preferences`](/docs/frameworks/html/components/preferences-link);
- the [floating trigger](/docs/frameworks/html/components/trigger);
- `inth.openDialog()` in JavaScript.

Opening the dialog records nothing and changes no permissions.

## Which categories it lists

`necessary` appears first (always on, locked), followed by optional
categories used on the page within the policy's scope:

- categories referenced on `<script type="text/plain" data-inth-category>`,
  `<iframe data-category>`, `scripts` entries and network blocker rules;
- categories listed in `data-categories` on the tag or `consentCategories` in
  `config`.

If the page declares no categories, the dialog lists every category in the
policy scope. Use `data-categories` when a tag manager or external script
needs a category not present in page tags:

{/* example: fragment */}

```html
<script
  src="https://your-project.inth.app/inth.js"
  data-categories="measurement,marketing"
  defer
></script>
```

See [consent categories](/docs/concepts/consent-categories) and
[vendor consent](/docs/frameworks/html/vendor-consent).

## What the switches start at

Each switch initializes in this precedence order:

1. unsaved changes toggled while this dialog is open;
2. off when an active durable opt-out or Global Privacy Control (GPC) signal restricts that category, even when a stored choice granted it;
3. the visitor's recorded choice;
4. `presentation.preferences.defaults`, if configured;
5. on under opt-out or preselected policy categories, otherwise off.

Closing without saving discards unsaved switch changes.

## Sale-and-sharing opt-out block and locked switches

Under an `opt-out` policy, the dialog renders a sale-and-sharing block first,
above the category list and outside any accordion item. Under any other policy
model, no block renders.

- Before the visitor opts out, the block displays the configured opt-out link
  title (`presentation.optOutLink`), a neutral status sentence, and an **Opt
  out** button. One click records the opt-out through the same shared action as
  the opt-out link, without touching category switches or **Save Settings**.
- Once a durable opt-out is held, the button is removed and the block shows the
  status line (`role="status"`): "Opt-out request honored" for a visitor
  request, or "Opt-out preference signal honored" when Global Privacy Control
  recorded or enforces it. Below the status line, it renders the receipt
  sentence, recorded time, and local reference. When the backend confirms the
  refused rights, the heading updates to name them (`sale` and `share`, `sale`
  and `targeted_ads`, or all three); before confirmation, it keeps the
  configured link title. When GPC is not locking the opt-out, an **Opt back
  in…** link appears below the receipt.
- While the browser's GPC signal is active under a policy that maps it, the
  signal-restricted switches and `marketing` (or `measurement` when `marketing`
  is not in scope) stay off and disabled, and no **Opt back in…** link appears.
  A notice below each locked row explains why and is linked to the switch with
  `aria-describedby`. **Save Settings** and **Accept All** do not present or
  grant locked categories.
- When an account holds the opt-out and GPC is off, the notice appears below
  `marketing` (or `measurement` when `marketing` is not in scope) to explain
  that the account has opted out, and the switches remain usable. Turning
  `marketing` back on and saving, clicking **Accept All**, or clicking **Opt
  back in…** opens a separate confirmation dialog first. Confirming asks the
  backend to lift the account opt-out, and a refused request leaves it in place.
- When the opt-out is device-held and GPC is off, opting back in uses a
  two-step confirmation dialog under an `opt-out` policy (11 CCR §7028(a)).
  Turning `marketing` back on and saving, clicking **Accept All**, or clicking
  **Opt back in…** opens a separate modal dialog instead of saving right away
  (`measurement` decides when `marketing` is not in scope). Focus starts on
  **Stay opted out**, both buttons have equal prominence, and Escape cancels
  with nothing saved. Confirming lifts the opt-out and applies the pending
  save. Turning `measurement` back on while `marketing` stays off keeps
  `measurement` allowed, skips confirmation, and leaves the opt-out in place.
  Saving without changing a switch keeps the opt-out in place. Under an
  `opt-in` policy, **Accept All** still lifts a held opt-out in one step.

## Buttons

The dialog displays Reject All, Accept All and Save Settings. All three are
policy-required and close both the dialog and any underlying banner. Layout
options live under `presentation.preferences`.

## Options

Setting `ui: { dialog: false }` disables the stock dialog. Use it only when
rendering your own dialog with [headless](/docs/frameworks/html/headless).

## Keyboard and screen readers

- Renders as `role="dialog"` with `aria-labelledby` and `aria-describedby`.
- Blocking by default (focus trap and scroll lock); disable with
  `presentation.preferences.blocking: false`.
- Escape closes without saving and restores the banner if a choice is still
  due. Clicking the backdrop does not close it.
- Each category header expands its description and pairs with a
  `role="switch"` control (`necessary` is disabled).
- Sets `lang` and `dir` from the resolved language.

## Style it

Shared theme tokens apply automatically (see
[customize](/docs/frameworks/html/customize)). Target specific parts in
`ui.css` by `data-testid`:

| `data-testid` | Element |
| --- | --- |
| `consent-dialog-root` | Dialog element. |
| `consent-dialog-card`, `consent-dialog-header`, `consent-dialog-content` | Card and inner sections. |
| `consent-dialog-title`, `consent-dialog-description` | Heading and description. |
| `consent-widget-opt-out` | Sale-and-sharing opt-out block (`consentWidgetOptOut` slot / `::part`). |
| `consent-widget-opt-out-heading`, `consent-widget-opt-out-description` | Opt-out block heading and status or receipt sentence. |
| `consent-widget-opt-out-button` | Direct one-click opt-out button before opting out. |
| `consent-widget-opt-out-status` | Honored opt-out status line (`role="status"`). |
| `consent-widget-opt-out-receipt`, `consent-widget-opt-out-recorded-at`, `consent-widget-opt-out-reference` | Receipt list, recorded time, and local reference while opted out. |
| `consent-widget-opt-in-link` | "Opt back in…" link shown below the receipt while opted out and not locked by GPC. |
| `opt-in-confirmation-root`, `opt-in-confirmation-card`, `opt-in-confirmation-title`, `opt-in-confirmation-description` | Separate modal confirmation dialog for two-step opt-in under an `opt-out` policy. |
| `opt-in-confirmation-cancel-button`, `opt-in-confirmation-confirm-button` | Equal-prominence cancel ("Stay opted out") and confirm ("Opt back in") buttons. |
| `consent-widget-accordion-item-<category>` | Category row (for example, `measurement`). |
| `consent-widget-switch-<category>` | Category switch. |
| `consent-widget-restriction-<category>` | GPC or account lock notice below a restricted category row. |
| `consent-widget-vendor-list-<category>` | Category vendor list. |
| `consent-widget-vendor-switch-<category>-<vendor>` | Individual vendor switch. |
| `consent-widget-footer` | Button row. |
| `consent-widget-footer-accept-all-button`, `consent-widget-reject-button`, `consent-widget-footer-save-button` | Action buttons. |
| `consent-dialog-branding` | "Consent by" tag. |
| `consent-dialog-overlay` | Backdrop. |

## Check it works

1. Click a **Privacy settings** link. The dialog opens with focus on its
   first control.
2. Enable **Analytics** (`measurement`) only and click **Save Settings**.
   Measurement vendors load while marketing stays blocked.
3. Reopen the dialog and confirm **Analytics** is on and **Marketing** is
   off.
4. Toggle **Marketing** on, press Escape and reopen. **Marketing** remains
   off.
