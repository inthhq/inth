Configure the stock first-layer consent banner rendered automatically by
`inth.js` on plain HTML pages.

## What the banner shows

`inth.js` renders the banner when the resolved policy requires a choice or
notice and the visitor has not answered it. Returning visitors with a valid
choice and visitors under no-prompt policies see no banner.

No page markup is required beyond the
[quickstart](/docs/frameworks/html/quickstart) script tag:

## Which buttons it shows

The active policy determines the buttons:

| Policy prompt | Buttons |
| --- | --- |
| Choice | Policy-allowed actions (by default Reject All and Accept All at equal size, plus Customize). |
| Choice with opt-out right and no reject action | Allowed actions plus "Do Not Sell or Share My Personal Information", which records an opt-out in one click and shows a confirmation view. |
| Notice | "OK" (acknowledgement) plus any other policy-allowed action, including the opt-out link under an opt-out policy. |

Accept and Reject record consent and close the banner immediately. Customize
opens the [preference dialog](/docs/frameworks/html/components/dialog)
without saving. Dismissing a notice records acknowledgement, not consent; see
[notices and privacy signals](/docs/concepts/how-consent-works#notices-and-privacy-signals).

`presentation.prompt` can reorder or group buttons, but Inth restores any
policy-required button and preserves equal prominence rules.

## Choose the opt-out link title

Under a policy that carries the `opt-out` right, a notice renders an opt-out
link, "Do not sell or share my data". It opens the sale-and-sharing rights row
inside the banner, where the visitor can opt out. It never records an opt-out
on its own and does not open the dialog.

`presentation.optOutLink` (or `data-opt-out-link` on the script tag) sets the
title and action of the other opt-out controls: the floating trigger and
`data-inth-action="opt-out"` elements. With the
default `'do-not-sell'`, clicking one under an opt-out policy records a durable
opt-out in one step and switches off `marketing` and `measurement` in scope.
When that turns off a category that was running and `reloadOnConsentRevoked` is
enabled, Inth waits for the opt-out request, reloads the page, and opens the
focused confirmation view once on the new page. When no reload happens, the
confirmation view opens immediately. It shows the link title, a status line
(`role="status"`), a receipt naming the covered scope and backend-confirmed
rights, the recorded time, a selectable local reference when this browser
created the opt-out, a **Done** button and a **Manage preferences** link.
Programmatic calls to `inth.optOut()` (`client.optOut()`) also opt out in one
step. Under a non-opt-out policy, these links open the preference dialog.

| `presentation.optOutLink` | Title | Icon | Click under opt-out policy |
| --- | --- | --- | --- |
| `'do-not-sell'` (default) | "Do Not Sell or Share My Personal Information" | None | Records opt-out in one step and opens confirmation |
| `'privacy-choices'` | "Your Privacy Choices" | California Privacy Protection Agency opt-out icon | Opens the preference dialog and records nothing |
| `'california-privacy-choices'` | "Your California Privacy Choices" | California Privacy Protection Agency opt-out icon | Opens the preference dialog and records nothing |

Both "Your Privacy Choices" and "Your California Privacy Choices" always
render with the official California Privacy Protection Agency opt-out icon in
its fixed blue and white colors across light and dark themes. There is no
option to show either title without the icon.

{/* example: fragment */}

```html
<script
  src="https://your-project.inth.app/inth.js"
  data-opt-out-link="privacy-choices"
  defer
></script>
```

## Change the text

Queue a `config` call before `inth.js` with `ui.banner`:

{/* example: fragment */}

```html
<script>
  window.inth = window.inth || [];
  inth.push(['config', {
    ui: {
      banner: {
        title: 'Cookies on this site',
        description: 'We use cookies to measure traffic. Choose what can run.',
        rejectButtonText: 'Reject optional',
      },
    },
  }]);
</script>
```

These strings override text in every language. For localized copy, see
[translations](/docs/frameworks/html/translations).

## Change the layout

Configure the container and the button layout under `presentation.prompt`:

{/* example: fragment */}

```html
<script>
  window.inth = window.inth || [];
  inth.push(['config', {
    presentation: {
      prompt: {
        container: { type: 'card', position: 'end' },
        layout: [['reject', 'accept'], 'customize'],
      },
    },
  }]);
</script>
```

<import src="../../../shared/browser/client-options.mdx#containers" />

| `presentation.prompt` option | What it does |
| --- | --- |
| `container` | The Card, Banner or Drawer, and where it sits. |
| `edgeStyle` | `'inset'` (default) or `'flush'` for a Banner or Drawer. |
| `blockUntilChoice` | Dims the page, locks scroll and traps focus until the visitor chooses. |
| `layout` | Button order; nested arrays group buttons together. |
| `primaryActions` | Actions rendered with primary button styling. |
| `uiProfile` | `'compact'` (default) sizes to label width; `'balanced'` and `'strict'` stretch and stack groups. |

## Show legal links

Add URL attributes to the script tag so both banner and dialog display them:

{/* example: fragment */}

```html
<script
  src="https://your-project.inth.app/inth.js"
  data-privacy-policy-url="/privacy"
  data-cookie-policy-url="/cookies"
  defer
></script>
```

To show different links per surface, define `legalLinks` in `config` and pass
keys to `ui.banner.legalLinks` and `ui.dialog.legalLinks`.

## Keyboard and screen readers

- Non-blocking banners render as `role="region"` named by title; blocking
  banners render as modal `role="dialog"` with focus trap and scroll lock.
- Sets `lang` and `dir` from the resolved language.
- Uses native `<button>` controls and has no close button so prompts cannot
  be dismissed without answering.
- Respects `prefers-reduced-motion` (override with `ui.disableAnimation`).

## Style it

Use theme tokens for global styling (see
[customize](/docs/frameworks/html/customize)) or target parts by
`data-testid` in `ui.css`:

| `data-testid` | Element |
| --- | --- |
| `consent-banner-root` | Positioned wrapper carrying `data-placement` (such as `card-start` or `banner-bottom`), `data-flow`, `data-variant` (`choice`, `us-consent` or `notice`), `data-edge-style`, `data-blocking`, `data-expanded` and `data-state`. |
| `consent-banner-card` | The Card, Banner or Drawer. |
| `consent-banner-title`, `consent-banner-description` | Heading and body text. |
| `consent-banner-legal-link-privacyPolicy` (and other link keys) | Legal links. |
| `consent-banner-footer` | Button row. |
| `consent-banner-accept-button`, `consent-banner-reject-button`, `consent-banner-customize-button`, `consent-banner-dismiss-button` | Action buttons. |
| `consent-banner-branding` | "Consent by" tag. |
| `consent-banner-overlay` | Backdrop for blocking banners. |
| `consent-banner-body` | The choices Customize opens in place. |

## Turn the banner off

`ui: { banner: false }` suppresses the stock banner. Render a replacement
using [headless](/docs/frameworks/html/headless) whenever the policy requires
a prompt.

## Check it works

Open the page in a private window:

1. The banner appears once the policy resolves with policy-required buttons.
2. Press Tab to reach every button in order.
3. Click **Reject All** and reload. The banner stays closed.
4. Change the region in the DevTools Location tab and re-init to verify
   regional policy behavior.
