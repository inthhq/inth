Let visitors reopen the preference dialog from any footer link, CMS menu item,
or page builder without writing JavaScript by linking to `#inth-preferences`.

## Add a privacy settings link

Point an anchor's `href` to `#inth-preferences`:

<include src="../../../shared/examples/html/preferences-link.mdx" />

Add it to the shared footer or legal menu rendered on every page. Because it
uses a plain URL fragment, it works inside CMS menu editors where you cannot
set `data-inth-*` attributes.

## How the link behaves

- Inth matches any `a[href]` ending in `#inth-preferences`. A path such as
  `/about#inth-preferences` also opens the dialog on the current page without
  navigating.
- Clicking opens the dialog without saving, and calls `preventDefault()` so
  the URL and scroll position do not change.
- Links inserted after page load work through document-level click
  delegation.
- Loading a URL that already contains `#inth-preferences` does not open the
  dialog; only clicks do.

You can also use `<button data-inth-action="customize">`; see
[action buttons](/docs/frameworks/html/components/action-buttons).

## Word the link for your visitors

Use "Privacy settings" or "Cookie settings" for a link that opens the
preference dialog. For a US state privacy opt-out link such as "Do Not Sell or
Share My Personal Information" or "Your Privacy Choices", add
`data-inth-action="opt-out"` so one click records the opt-out under an opt-out
policy and opens the confirmation view instead of requiring extra steps in the
preference dialog. See
[action buttons](/docs/frameworks/html/components/action-buttons). Inth does
not rewrite your link text by region.

## When the dialog is off

With `ui: { dialog: false }` or `inth.headless.js`, clicking the link emits
`'dialog'` on the `ui` event without rendering stock UI. Render your own
dialog in response; see [headless](/docs/frameworks/html/headless).

## Check it works

1. Click the link on any page. The dialog opens and the URL stays unchanged.
2. Change a category and save. The dialog closes.
3. Verify the link works across every page template on your site.
