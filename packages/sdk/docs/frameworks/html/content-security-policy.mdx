Configure your Content Security Policy directives so `inth.js`, its styles,
Inth API requests, gated scripts and embeds work securely with nonces or host
allowlists.

## What Inth needs from your policy

| Directive | Allow | Why |
| --- | --- | --- |
| `script-src` | Host serving `inth.js` (such as `https://your-project.inth.app`), plus `https://cdn.jsdelivr.net` for CDN bundles, `inth.gpp.js` or `inth.devtools.js`. | Inth script bundles. |
| `script-src` | Nonce or hash for inline scripts | Queued `config`/`on` blocks and inline gated snippets. |
| `script-src` | Each vendor script origin | Gated `<script src>` tags and `scripts` entries. |
| `connect-src` | Your Inth project origin (`https://your-project.inth.app`) | `/v1/consent/init`, `/v1/consent/records`, and `/v1/consent/manifest` in manifest mode. |
| `style-src` | Matching nonce or the host serving `inth.css` | Stock UI `<style>` element or external stylesheet. |
| `frame-src` | Each embed origin (such as `https://www.youtube-nocookie.com`) | Gated iframes. |
| `img-src`, `connect-src` | Vendor telemetry endpoints | Requests sent by vendors after consent. |

A missing `connect-src` entry is the most common failure: `/v1/consent/init` is blocked,
no policy resolves, and no banner appears.

## Use a nonce

Stamp the per-response nonce on the Inth script tag, inline queue scripts and
every gated `<script type="text/plain">`:

{/* example: fragment */}

```html
<script nonce="RANDOM_PER_RESPONSE">
  window.inth = window.inth || [];
  inth.push(['config', { legalLinks: { privacyPolicy: { href: '/privacy' } } }]);
</script>
<script
  nonce="RANDOM_PER_RESPONSE"
  src="https://your-project.inth.app/inth.js"
  defer
></script>
<script nonce="RANDOM_PER_RESPONSE" type="text/plain" data-inth-category="measurement">
  // The vendor's snippet
</script>
```

Send the same nonce in your response header (for example,
`Content-Security-Policy: script-src 'nonce-RANDOM_PER_RESPONSE' 'strict-dynamic'; style-src 'nonce-RANDOM_PER_RESPONSE'`).
Static hosts that cannot vary responses per request should allowlist origins
and hashes instead.

Inth reads its tag's `nonce` (or `data-nonce`, which takes precedence) and
applies it to the stock UI's `<style>` element and scripts loaded via
`config.scripts`. Once a nonce is set, Inth executes only gated `text/plain`
tags carrying that exact nonce, marking others `data-inth-activated="untrusted"`
so injected HTML cannot run under `'strict-dynamic'`. Inth copies each valid
gated tag's `nonce` onto the active `<script>` it creates.

## Allow the stock UI's styles

`inth.js` injects its CSS (including theme tokens and `ui.css`) into a
`<style>` element inside the shadow root carrying the tag's nonce, so
`style-src 'nonce-RANDOM_PER_RESPONSE'` works without `'unsafe-inline'`.

Without per-request nonces, render into light DOM and load the stylesheet as
a file from the same package version:

{/* example: fragment */}

```html
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@inth/sdk/lib/browser/dist/inth.css" />
<script>
  window.inth = window.inth || [];
  inth.push(['config', { ui: { shadow: false, styles: false } }]);
</script>
```

With `styles: false` and no `theme` or `css` option, Inth injects no
`<style>` element; put token overrides in your own stylesheet.
`inth.headless.js` injects no styles at all. Remove `inth.devtools.js` before
enforcing a strict production policy.

## IAB TCF

`inth.iab.js` fetches the Global Vendor List through your Inth project in
hosted mode (covered by `connect-src`) and injects `dist/inth.iab.css` into
the same nonced `<style>` element.

## Check it works

1. Start with `Content-Security-Policy-Report-Only` and watch the Console.
2. Confirm no CSP violations fire for `inth.js`, `/v1/consent/init` or banner styles.
3. Grant each category and verify vendor scripts and requests pass.
4. Switch to enforcing `Content-Security-Policy` and re-test.
