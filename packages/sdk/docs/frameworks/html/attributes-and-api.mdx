## Script files

Inth serves `inth.js`, `inth.headless.js` and `inth.iab.js` directly from
your project URL (`https://your-project.inth.app/inth.js`), preconfigured
with your project URL (headless and IAB routes also inline your policy
manifest). Load files not served per project, such as `inth.devtools.js` or
`inth.testing.js`, from
`https://cdn.jsdelivr.net/npm/@inth/sdk@<version>/lib/browser/dist/<file>` (or unpkg).

| File | What it contains |
| --- | --- |
| `inth.js` | Default hosted tag. Small loader that starts `/v1/consent/init`, shows the stock banner and loads `inth.hosted.js`. Requires a project URL. |
| `inth.hosted.js` | Full consent engine and remaining stock UI (such as the trigger). Loaded automatically by `inth.js`. |
| `inth.dialog.js` | Preference dialog and vendor list. Loaded automatically on Customize or first open. |
| `inth.commit.js` | Persists an Accept or Reject click made on the initial banner. Loaded automatically by `inth.js`. |
| `inth.records.js` | Reads stored consent for returning visitors to start permitted scripts immediately. Loaded automatically by `inth.js`. |
| `inth.testing.js` | Test pages only. Stock UI with `testing()` and built-in policy presets, with no network requests. |
| `inth.headless.js` | Runtime and `window.inth` API without stock UI or CSS; see [headless](/docs/frameworks/html/headless). |
| `inth.iab.js` | Replaces `inth.js` for IAB TCF policies; see [IAB TCF](/docs/frameworks/html/iab). |
| `inth.devtools.js` | DevTools panel loaded as a second tag; see [DevTools](/docs/frameworks/html/dev-tools). |

Load only one runtime bundle (`inth.js`, `inth.testing.js`,
`inth.headless.js` or `inth.iab.js`) per page. `inth.iab.js` throws if
another bundle loaded first; the other bundles leave an existing instance in
place.

## How inth.js loads inth.hosted.js

`inth.js` runs early during page load to keep first-load JavaScript small:

1. Installs a proxy `window.inth` that queues calls (`init`, `on`,
   `subscribe`, `openDialog`) and answers `getSnapshot()` and `has()` from
   current state.
2. Starts `/v1/consent/init` immediately (or when `inth.init()` runs with `data-manual`).
3. Renders the stock banner with banner-only CSS as soon as `/v1/consent/init` answers.
4. Handles immediate Accept or Reject clicks, starting allowed gated scripts
   right away and persisting the choice via `inth.commit.js` (buffered in
   `localStorage` under `inth-pending-tap` if the visitor navigates away).
5. Opens the preference dialog immediately on Customize via `inth.dialog.js`
   before the full engine arrives.
6. For returning visitors, loads `inth.records.js` immediately to start
   allowed gated scripts without waiting for `/v1/consent/init`, checking against the
   last policy stored in `inth-init-policy`.

`inth.js` then loads `inth.hosted.js` after `fetchpriority="high"` images
load (or window `load`), on first user interaction, or after 10 seconds. It
hands off cleanly without re-sending `/v1/consent/init` or flashing the banner.

`inth.js` loads the full engine immediately when custom options require it
(`theme`, `css`, `stylesheetUrls`, `i18n`, `container`, `data-shadow="false"`,
`noStyle`, a `privacy-choices` or `california-privacy-choices` opt-out link,
`experiment`, `storageConfig`, `persistence`, `consentSource`,
`vendors`, `user`, `prefetch`, `headers` or `fetch`). Until the engine loads,
`inth.client` is `null` and `inth.isVendorAllowed()` throws; use
`inth.onInit((client) => ...)` to access the full client.

`inth.js` resolves `inth.hosted.js`, `inth.commit.js`, `inth.records.js` and
`inth.dialog.js` beside its own URL with `?v=<version>`. If copying files to
your own server, copy all five together, or point to custom URLs with
`data-hosted-src`, `data-commit-src`, `data-records-src` and
`data-dialog-src`. Allow all of them in `script-src` under CSP.

`dist/inth.css` and `dist/inth.iab.css` are the standalone stylesheets when
using `data-shadow="false"` and `styles: false`.

## Script tag attributes

Attributes are read once on startup. `inth.js` uses hosted mode and requires
`data-project-url` unless served from your project URL or configured via
`config`. `inth.testing.js` rejects project URLs and manifest options.

| Attribute | What it does |
| --- | --- |
| `data-project-url` | Your Inth project URL. Selects hosted mode. (`data-backend` is accepted as a legacy alias.) |
| `data-mode` | Optional `hosted`. Headless and IAB also accept `manifest` (picked automatically when `data-manifest-url` is set). |
| `data-manifest-url` | Manifest URL for headless or IAB in manifest mode; see [choose a mode](#choose-a-mode). |
| `data-policy` | `inth.testing.js` only. Comma-separated presets from `policyRulePresets` (such as `europeOptIn,usPrivacyStatesOptOut,worldNone`). See [policies](/docs/concepts/policies). |
| `data-categories` | Comma-separated categories to display in the preference dialog (such as `measurement,marketing`). |
| `data-country`, `data-region` | Explicit visitor location when your server injects it. |
| `data-language` | Force a language instead of browser detection; see [translations](/docs/frameworks/html/translations). |
| `data-privacy-policy-url`, `data-cookie-policy-url`, `data-terms-url` | Show legal links in the banner and dialog. |
| `data-color-scheme` | `light`, `dark` or `system` (default `system`). |
| `data-trigger` | Show the [floating trigger](/docs/frameworks/html/components/trigger). |
| `data-hide-branding` | Hide the "Secured by" tag (the IAB banner always keeps it). |
| `data-opt-out-link` | `do-not-sell` (default), `privacy-choices` ("Your Privacy Choices") or `california-privacy-choices` ("Your California Privacy Choices"). The two "Privacy Choices" forms always render with the California Privacy Protection Agency opt-out icon, and commit your site to covering the right to limit as well: see [Choose the opt-out link title](/docs/frameworks/html/components/banner#choose-the-opt-out-link-title). |
| `data-shadow="false"` | Render into the page DOM so page CSS applies; see [style it with your own stylesheet](/docs/frameworks/html/customize#style-it-with-your-own-stylesheet). |
| `data-no-ui` | Run without stock UI (load `inth.headless.js` instead to omit UI bytes). |
| `data-hosted-src`, `data-commit-src`, `data-records-src`, `data-dialog-src` | Custom URLs for companion files loaded by `inth.js`. |
| `data-manual` | Wait for `inth.init()` instead of starting automatically; see [start Inth yourself](/docs/frameworks/html/api#start-inth-yourself). |
| `data-nonce` | CSP nonce for stock UI `<style>` and loaded scripts (overrides tag's `nonce`); see [Content Security Policy](/docs/frameworks/html/content-security-policy). |

Boolean flag attributes enable when present unless set to `"false"`. Every
attribute option can also be passed in a queued `config` call; see
[configuration](/docs/frameworks/html/configuration).

## DevTools tag attributes

Place these on the `inth.devtools.js` tag:

| Attribute | What it does |
| --- | --- |
| `data-open` | Open the panel on load (`data-open="false"` keeps it closed). |
| `data-tab` | Initial tab: `consents`, `scripts`, `location`, `policy`, `iab`, `events` or `actions`. |
| `data-position` | Corner: `bottom-right`, `bottom-left`, `top-right` or `top-left`. |

## Attributes on your own markup

| Markup | What it does | Page |
| --- | --- | --- |
| `data-inth-action="accept"`, `"reject"`, `"customize"`, `"dismiss"`, `"banner"` or `"close"` | Runs the action on click. | [Action buttons](/docs/frameworks/html/components/action-buttons) |
| Link whose `href` ends in `#inth-preferences` | Opens the preference dialog on click. | [Preferences link](/docs/frameworks/html/components/preferences-link) |
| `<script type="text/plain" data-inth-category="...">` | Runs the script once allowed (`data-inth-vendor` adds a vendor gate). | [Gated scripts](/docs/frameworks/html/components/gated-script) |
| `<iframe data-src="..." data-category="...">` | Sets `src` once allowed (`data-vendor` adds a vendor gate). | [Embeds](/docs/frameworks/html/embeds) |

Inth sets these read-only attributes for CSS and testing:

| Attribute | Where | Meaning |
| --- | --- | --- |
| `data-inth-activated` | Gated `<script>` | `true` once run, `invalid` for unknown category, `untrusted` for missing nonce. |
| `data-inth-paused` | Gated `<iframe>` | Inth stripped an initial `src`. |
| `data-inth-ui` | UI host `<div>` | Container for banner, dialog and trigger. |
| `data-testid` | Stock UI elements | Stable selectors for CSS and tests. |

## Choose a mode

| Mode | Set it with | What happens |
| --- | --- | --- |
| Hosted | `inth.js` from your project URL or with `data-project-url` | Calls `/v1/consent/init` per fresh visit and saves choices to Inth. |
| Manifest | `inth.headless.js` or `inth.iab.js` with `data-manifest-url` or inline `manifest` in `config` | Resolves policy from your public `/v1/consent/manifest` and saves choices to Inth. |
| Testing | `inth.testing.js` on test pages only | Resolves `data-policy` or recommended rules locally with no network calls. |

In manifest mode, a `data-manifest-url` ending in `/v1/consent/manifest` supplies the
project URL automatically; otherwise also pass `data-project-url`. Regional
policies without visitor location fall back to `/v1/consent/init`; see
[data fetching](/docs/concepts/data-fetching).
