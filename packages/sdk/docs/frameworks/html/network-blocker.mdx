Hold `fetch` and `XMLHttpRequest` requests to tracking domains on a plain
HTML page until their consent category is allowed.

## When you need it

Use network blocker rules as a backstop when a bundled theme script, plugin
or inline code sends tracking requests you cannot convert into a
`type="text/plain"` tag. Gate normal scripts and iframes with
[gated scripts](/docs/frameworks/html/components/gated-script) and
[embeds](/docs/frameworks/html/embeds).

## Add rules

Queue a `config` call with `networkBlocker` before `inth.js`:

{/* example: fragment */}

```html
<script>
  window.inth = window.inth || [];
  inth.push(['config', {
    networkBlocker: {
      rules: [
        { id: 'collector', domain: 'collect.example.com', category: 'measurement' },
        {
          id: 'events',
          domain: 'example.com',
          pathIncludes: '/api/track',
          methods: ['POST'],
          category: 'measurement',
        },
      ],
      onRequestBlocked: ({ method, url, rule }) => {
        console.info('Inth blocked', method, url, rule?.id);
      },
    },
  }]);
</script>
```

The first rule blocks every request to `collect.example.com` and its
subdomains until `measurement` is allowed. The second blocks only `POST`
requests to `example.com` paths containing `/api/track`.

## Rule fields

| Field | Required | What it does |
| --- | --- | --- |
| `domain` | Yes | Host to match, including subdomains (`example.com` covers `www.example.com`). |
| `category` | Yes | Category or condition such as `{ and: ['measurement', 'marketing'] }`. |
| `pathIncludes` | No | Matches URLs whose path contains this string. |
| `methods` | No | Restricts matching to listed HTTP methods (all methods when omitted). |
| `id` | No | Rule identifier shown in logs and `onRequestBlocked`. |
| `vendor` | No | Also blocks when the visitor switched this vendor off. |
| `vendorId`, `iabPurposes`, `iabLegIntPurposes`, `iabSpecialFeatures` | No | IAB TCF conditions, evaluated only under an IAB policy. |

## Blocker options

| Option | Default | What it does |
| --- | --- | --- |
| `rules` | required | Rules table above. |
| `enabled` | `true` | `false` keeps configuration without blocking. |
| `logBlockedRequests` | `true` | Logs each blocked request with `console.warn`. |
| `onRequestBlocked` | none | Receives `{ method, url, rule }` for every blocked request. |

## What a blocked request sees

- Blocked `fetch` calls resolve with HTTP status `451` (check `response.ok`).
- Blocked `XMLHttpRequest` calls fire an `error` event.
- Requests issued before the policy resolves wait, then proceed or block once
  permissions resolve (blocked if policy loading fails).
- Unmatched requests proceed immediately.

Rule categories are added to the preference dialog automatically.

## What it cannot block

The blocker patches `fetch` and `XMLHttpRequest` once `inth.js` executes. It
cannot intercept:

- `navigator.sendBeacon`, WebSockets or `EventSource`;
- `<img>`, `<script>`, `<link>` or `<iframe>` requests;
- requests fired before `inth.js` ran (with `defer`, inline scripts run
  earlier; load `inth.js` without `defer` at the top of `<head>` if inline
  code sends requests during parsing);
- requests from other frames or service workers.

## Check it works

1. Open the page in a private window with Console and Network open.
2. Trigger the tracked request. Console logs the blocked rule and Network
   shows no outgoing request.
3. Allow `measurement` and trigger it again. The request succeeds.
