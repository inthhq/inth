## Gate tags and iframes by vendor

Add `data-inth-vendor` alongside `data-inth-category` on a gated
`<script type="text/plain">` tag:

<include src="../../shared/examples/html/vendor-gated-scripts.mdx" />

Add `data-vendor` to a gated iframe:

<include src="../../shared/examples/html/vendor-gated-embed.mdx" />

| Target | Field |
| --- | --- |
| Gated `<script type="text/plain">` tag | `data-inth-vendor="x-pixel"` next to `data-inth-category` |
| Gated iframe | `data-vendor="x-pixel"` |
| `scripts` entry in `config` | `vendor: 'x-pixel'` |
| Network blocker rule | `vendor: 'x-pixel'` |

`data-inth-vendor` has no effect without `data-inth-category`. On pages with
a CSP nonce, keep the matching `nonce` on each
[gated tag](/docs/frameworks/html/components/gated-script#gated-tags-on-a-page-with-a-nonce).
An iframe with `data-vendor` and no `data-category` gates on the vendor
alone.

A `data-inth-vendor` slug counts as declared so stored denials apply
immediately, though the preference dialog renders a switch only once a
declaration supplies `name` and `privacyPolicyUrl`.

## What the preference dialog shows

The stock dialog in `inth.js` renders each declared vendor under its category
with a switch. `inth.headless.js` renders no dialog; record vendor toggles
via `save()`.

## Read and record vendor choices from your own script

`window.inth` and `inth.client` expose three vendor read methods:

| Method | Returns |
| --- | --- |
| `getDeclaredVendors()` | Merged vendors from `vendors`, Inth, scripts, gated tags and iframes (empty under IAB). |
| `getVendorChoice()` | Recorded vendor decision (`denied` lists switched-off slugs), or `null` before any vendor decision. |
| `isVendorAllowed(id)` | `true` when the vendor is declared, its category is allowed and it is not switched off. |

Call read methods after `inth.ready()` or from an event listener because
reads cannot be queued.

<import src="../../shared/scripts/vendor-consent.mdx#undeclared" />

`save()` accepts a `vendors` map alongside categories. Omitted vendors keep
their stored state, and `save` can be queued:

{/* example: fragment */}

```html
<script>
  window.inth = window.inth || [];
  inth.push(['save', { marketing: true, vendors: { 'x-pixel': false } }]);
</script>
```

Call `save` only from a visitor action, never on page load. Vendor-only saves
still fire `consent` and re-evaluate gated tags; see
[window.inth API](/docs/frameworks/html/api) and
[events and callbacks](/docs/frameworks/html/callbacks).

## Verify vendor consent

Open the page in a private window with DevTools Network filtered to
`ads-twitter.com`:

1. Declare `x-pixel` and gate X Pixel with `data-inth-category="marketing"`
   and `data-inth-vendor="x-pixel"`. Open **Privacy settings** and confirm
   the marketing row shows an X Pixel switch.
2. Allow marketing and save. `uwt.js` loads.
3. Open **Privacy settings**, switch X Pixel off and save. Inth reloads the
   page; `uwt.js` stays absent while other marketing tags run.
4. Reload again. `inth.isVendorAllowed('x-pixel')` returns `false`.
5. Turn marketing off. The X Pixel switch disables.
6. Open **Privacy settings** and click **Accept All**. `uwt.js` loads again.
