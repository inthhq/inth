Diagnose and fix common issues when running the Inth script tag on plain HTML
pages, CMS themes and static sites.

## Inspect consent with DevTools

Add `inth.devtools.js` temporarily while debugging to view resolved policy,
gated scripts, events and test other countries; see
[DevTools](/docs/frameworks/html/dev-tools). Remove it before publishing.

## Why is there no banner?

**Check.** Look for the `/v1/consent/init` request in DevTools Network.

**Fix.**

- **CORS error.** Add your site's exact origin (including `https://` and any
  `www`) to your Inth project's trusted origins.
- **200 response with no banner.** Your region's policy may require no prompt.
  Test `DE` in the DevTools Location tab.
- **No `/v1/consent/init` request.** Verify the script URL loads, no earlier script
  threw, `data-manual` is absent, and CSP allows the script host in
  `script-src` and your project origin in `connect-src`; see
  [Content Security Policy](/docs/frameworks/html/content-security-policy).
- **Stored choice exists.** Open a private window or clear the `inth` cookie
  and `localStorage` key.

## Why does a vendor script run before a choice?

**Check.** Search page source for the vendor domain. Only tags with
`type="text/plain"` and `data-inth-category` are held back.

**Fix.** Remove active duplicates added by theme settings, plugins or tag
managers. If an optimizer rewrote `type="text/plain"` on your published page,
exclude `inth.js` and `data-inth-category` tags; see
[caching and optimization plugins](/docs/frameworks/html/platforms#caching-and-optimization-plugins).
Note that opt-out policies allow optional categories until the visitor opts
out.

## Why does a gated script never run on a page with a nonce?

**Check.** Look in the Console for a warning that Inth skipped a
`data-inth-category` script, and check Elements for
`data-inth-activated="untrusted"`.

**Fix.** Add the exact per-response `nonce` attribute to every gated
`<script type="text/plain">`, including dynamically inserted tags; see
[gated tags on a page with a nonce](/docs/frameworks/html/components/gated-script#gated-tags-on-a-page-with-a-nonce).

## Why is the banner unstyled or missing its colors?

**Check.** Look for a CSP `style-src` error in the Console blocking the stock
UI `<style>` element.

**Fix.** Pass the `style-src` nonce on `inth.js` (`nonce` or `data-nonce`),
or load `inth.css` as a file; see
[allow the stock UI's styles](/docs/frameworks/html/content-security-policy#allow-the-stock-uis-styles).

## Why does the preferences link do nothing?

**Check.** Confirm the link `href` ends in `#inth-preferences` and `inth.js`
is loaded. Under `inth.headless.js` or `ui: { dialog: false }`, the link
emits `'dialog'` on `ui` without rendering stock UI.

**Fix.** Fix the `href` or mount your own dialog on the `ui` event; see
[headless](/docs/frameworks/html/headless).

## Why does the console say "call inth.init() first"?

**Check.** Code called a `window.inth` method before the client started
(either before `inth.js` ran, or with `data-manual` before `inth.init()`).

**Fix.** Queue the call with `inth.push()`, wait for `inth.ready()`, or run
it in an `on('ready', ...)` listener; see
[which calls you can queue](/docs/frameworks/html/api#which-calls-you-can-queue).

## Why does the console say a queued call "was skipped"?

**Check.** `inth.push()` received a synchronous read method (`has`,
`getSnapshot`, `dispose`) or an unknown method name.

**Fix.** Call read methods inside `inth.onInit()` or after `inth.ready()`.

## Why is my queued configuration ignored?

**Check.** Look for `window.inth = [...]` overwriting earlier queued calls,
or a `config` call executed after `inth.js` started.

**Fix.** Always use `window.inth = window.inth || []` with `inth.push(...)`,
and run `config` before the tag (or pass options to `inth.init()` with
`data-manual`).

## Why does the page throw "Load inth.iab.js instead of inth.js"?

**Check.** Two Inth script bundles are loaded on the same page.

**Fix.** Keep only `inth.iab.js` for IAB policies and remove `inth.js`,
`inth.testing.js` or `inth.headless.js`.

## Why did the banner change after a release?

**Check.** Your CDN script URL omits a pinned version.

**Fix.** Pin an exact `@inth/sdk@<version>` in the CDN URL so updates happen
only when you deploy.

## Why does the banner or dialog fail to load?

**Check.** Open the console. `@inth/sdk: the consent banner failed to load`
or `@inth/sdk: the preference centre failed to load` means the browser could
not download `inth.choices.js` or `inth.choices-dialog.js`, for example
during a dropped connection, or because the file is not served where
`inth.hosted.js` looks for it. In DevTools Network, look for the file's
request and its status.

After a failed download the page stays as it is and nothing is recorded. A
dialog that failed closes, and the banner comes back while a choice is still
owed. The next time the page needs the file (the next banner, Customize, or
dialog open) Inth requests it again at a URL of its own, with
`inth-retry=<n>` in its query, so an error response the browser cached does
not answer the retry. These files are classic scripts, so every retry is a
new request in every browser. `inth.hosted.js` itself is tried three times,
the same way. Inth never reloads the page to recover, because a reload would
discard what the visitor typed into your page.

**Fix.** If every request fails, serve `inth.choices.js` and
`inth.choices-dialog.js` next to `inth.hosted.js`, or set
`data-choices-src` and `data-choices-dialog-src`; see
[load the files from your own server](/docs/frameworks/html/attributes-and-api#how-inthjs-loads-inthhostedjs).
Allow the files in `script-src` under CSP. A server or CDN that rejects
unknown query parameters must accept `v` and `inth-retry`.
