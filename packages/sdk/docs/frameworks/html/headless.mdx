Render your own HTML banner and preference controls with `inth.headless.js`
while Inth resolves policies, persists choices and gates scripts.

## When to go headless

Use `inth.headless.js` when tokens and CSS cannot produce the markup you
need. It includes:

- policy resolution, persistence and saves to Inth;
- gated scripts, gated iframes and the network blocker;
- `window.inth`, consent events and `data-inth-action` hooks.

It omits the stock banner, dialog, trigger and stylesheet. Check
[customize](/docs/frameworks/html/customize) first, because headless markup
makes you responsible for policy compliance and accessibility.

## Follow the surface Inth wants shown

Listen to the `ui` event to decide which surface to show:

| `ui` payload | What your page shows |
| --- | --- |
| `'banner'` | First prompt. Check `promptRequirement.kind` for `'choice'` versus `'notice'`. |
| `'dialog'` | Preferences view triggered by `data-inth-action="customize"`, `#inth-preferences` or `inth.openDialog()`. |
| `'none'` | Hide all consent surfaces. |

Listeners registered after policy resolution receive the current surface
immediately. Switch surfaces manually with `inth.showBanner()`,
`inth.openDialog()`, `inth.closeDialog()` or `data-inth-action` buttons
(none of these record consent).

## Read the prompt the policy requires

Read `inth.getSnapshot()` to render policy-compliant controls:

| Field | What it tells your UI |
| --- | --- |
| `promptRequirement.kind` | `'choice'` needs a decision, `'notice'` needs acknowledgement, `'none'` needs no prompt. |
| `policyRule.actions.required` | Buttons the policy requires on the first prompt (such as `accept` and `reject`). |
| `policyRule.actions.allowed` | Every button allowed on the first prompt. |
| `policyRule.rights` | Visitor rights such as `preferences` and `opt-out`. |
| `policyRule.scope` | Categories governed by the policy. |
| `effectivePermissions` | Current permission per category. |
| `explicitChoice` | Recorded visitor choice, if any. |

Initialize checkboxes with `inth.has(category)` and save them with
`inth.save({ measurement: true, marketing: false })`.

## What your UI must handle

- **Every prompt kind.** Render choices for `choice`, an acknowledgement for
  `notice`, and nothing for `none`.
- **Required actions.** Show every action in `policyRule.actions.required`
  with equal prominence where required.
- **A way back.** Keep a
  [preferences link](/docs/frameworks/html/components/preferences-link) on
  every page.
- **Visitor actions only.** Call `save()`, `acceptAll()`, `rejectAll()` and
  `dismissNotice()` only from user interaction.
- **Accessibility.** Manage focus, keyboard navigation, labels, error states
  and narrow viewports using native buttons and labelled regions or dialogs.

See [how consent works](/docs/concepts/how-consent-works) for permissions
versus recorded choices.

## Keep the stock dialog with your own banner

To replace only the banner while keeping the stock dialog, load `inth.js` and
disable its banner:

{/* example: fragment */}

```html
<script>
  window.inth = window.inth || [];
  inth.push(['config', { ui: { banner: false } }]);
</script>
```

Your custom banner listens to `ui` for `'banner'`, and its customize control
opens the stock dialog.

## Check it works

Open the page in a private window with DevTools Network open:

1. The bar appears once the policy resolves with the required buttons, and no
   vendor requests fire.
2. Click **Reject all** and reload. The bar stays hidden and vendors stay
   blocked.
3. Click **Privacy settings**, allow Measurement only and click **Save**.
   Only measurement vendors load.
4. Tab through the bar and confirm every control is reachable and labelled.
