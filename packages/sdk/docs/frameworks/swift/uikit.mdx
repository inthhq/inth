UIKit apps use the same native core, Keychain storage and consent screens as
SwiftUI apps. Wrap your root view controller in `ConsentRootViewController` and
the prompt appears when a choice is needed. React Native and JavaScript are not
required.

## Add the package

Follow [Add the Swift package](/docs/frameworks/swift/quickstart#add-the-swift-package)
to link `C15tCore`, `C15tApple` and `C15tConsentUI`. Use the project URL from
your Inth dashboard and the app's HTTPS privacy-policy URL. Your project needs the
policy and categories described in the
[quickstart prerequisites](/docs/frameworks/swift/quickstart#before-you-start).

Replace both placeholder URLs and `ContentView` with your own root view
controller. `ContentView` is the SwiftUI view from the
[quickstart](/docs/frameworks/swift/quickstart#keep-privacy-settings-reachable);
any `UIViewController` works as `root`. Keep one `@main` entry point in the
target.

The app must have scene support enabled in its Application Scene Manifest. This
delegate supplies `SceneDelegate` programmatically and clears the scene
storyboard. If your app uses a storyboard or a named scene configuration, keep
its lifecycle and wrap the root view controller it creates instead.

`ConsentRootViewController` installs the engine when its view loads, then
presents the prompt once the policy is ready, once per owed prompt. It keeps
the prompt above your content. Touches outside the notice card reach your
views. Status bar and home indicator appearance come from your `root`.

Every scene shares one engine and one prompt. A second window or a reconnected
scene shows the same session instead of a new one. `UIHostingController` draws
the native SwiftUI screens. It does not add a web view, a JavaScript runtime or
a second consent record.

To present the prompt yourself, pass `autoPresent: false` and call
`ConsentPrompt.current?.presentPrompt()` when you are ready.

## Open privacy settings from UIKit

Call `ConsentPrompt.current?.presentPreferences()` on the main actor from your
Privacy settings action. It opens the same stored choices that SDK gates read,
and does nothing while a prompt or settings session is already open.

To update a UIKit label, create a `PublishedConsent` for `C15t.current` and
subscribe to `decisionPublisher(for: .measurement)`. It delivers the current
decision and then each change, on the main thread. Keep the returned
`AnyCancellable` in the controller.

## Handle startup and unlock

If your app starts optional SDKs during launch, install the engine first in
`application(_:didFinishLaunchingWithOptions:)` with
`try? C15tApple.install(configuration)`, using the same configuration. The root
view controller then reuses that engine, and saved consent is available before
optional SDK startup.

If Keychain is locked at launch, installation fails and optional collection
stays off. `ConsentRootViewController` retries after protected data becomes
available or the app becomes active. It never replaces the store with memory or
a plaintext file.

For a UIKit vendor integration, use the same standing
[native gate subscription](/docs/frameworks/swift/headless#keep-sdk-gates-current)
as a SwiftUI app. A permission read during launch alone does not handle later
withdrawal.

## Check the UIKit journey

Run the app with a policy that asks for a choice. Reject optional use, navigate
to your app's settings, reopen Privacy settings and save a different choice.
Relaunch and confirm that the same choice is restored and the prompt stays
closed. Repeat after background and foreground transitions, and confirm only
one prompt is ever on screen.

The maintained UIKit demo lives in `examples/native/consent-demo/ios`. Its
`C15tUIKitDemo` scheme hosts the same stock presenter and has local category
and IAB demonstrations. Those sample policies are separate from your hosted
project and its review configuration.

See [Customize](/docs/frameworks/swift/customize) for styling and
[mobile verification](/docs/guides/mobile-verify) for the full app checks.
