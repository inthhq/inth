Host Inth's native consent prompt and privacy settings inside a UIKit app with `ConsentRootViewController`. UIKit uses the same native core, Keychain storage, and SwiftUI screens as SwiftUI apps without a web view or JavaScript runtime.

## Add the package

Follow [Add the Swift package](/docs/frameworks/swift/quickstart#add-the-swift-package) to link `InthCore`, `InthApple`, and `InthConsentUI`. Configure your Inth project URL and HTTPS privacy policy URL as listed in [Before you start](/docs/frameworks/swift/quickstart#before-you-start).

Replace both placeholder URLs and swap `ContentView` (from the [Swift quickstart](/docs/frameworks/swift/quickstart#keep-privacy-settings-reachable)) for your root `UIViewController`. Keep one `@main` entry point per target.

Your app must declare Application Scene Manifest support. If your app uses a storyboard or named scene configuration, keep its lifecycle and wrap the root view controller it creates.

`ConsentRootViewController` installs the engine when its view loads and presents an owed prompt once the policy resolves. It layers the prompt above your views, passes touches outside the notice card through to your app, and inherits status bar and home indicator styles from `root`. Every scene shares one engine and one prompt so multiple windows never open duplicate sessions.

Pass `autoPresent: false` to control timing yourself and call `ConsentPrompt.current?.presentPrompt()` when ready.

## Open privacy settings from UIKit

Call `ConsentPrompt.current?.presentPreferences()` on the main actor from your Privacy settings button. It edits the same stored choices that SDK gates read and is a no-op while another session is open.

To bind a UIKit view to consent changes, create `PublishedConsent` for `Inth.current` and subscribe to `decisionPublisher(for: .measurement)`. It emits the current decision and every update on the main thread. Retain the returned `AnyCancellable` on your controller.

## Handle startup and device unlock

If your app starts optional SDKs during launch, install the engine first in `application(_:didFinishLaunchingWithOptions:)` with `try? InthApple.install(configuration)` using the same configuration. `ConsentRootViewController` reuses that engine, making saved consent available before optional SDKs initialize.

If Keychain is locked at launch, installation fails and optional collection stays off. `ConsentRootViewController` retries once protected data becomes available or the app becomes active, and never falls back to memory or plaintext files.

For third-party SDKs, retain a [native gate subscription](/docs/frameworks/swift/headless#keep-sdk-gates-current) so withdrawals stop collection after launch.

## Verify the UIKit flow

Run the app under a policy that requires a choice:

1. Reject optional consent, navigate to your app's settings, reopen **Privacy settings**, and save a new choice.
2. Relaunch and confirm the choice persists while the prompt stays closed.
3. Background and foreground the app to confirm only one prompt ever appears.

The runnable UIKit demo lives in `examples/native/consent-demo/ios` under the `InthUIKitDemo` scheme, with local category and IAB fixtures separate from your hosted project.

See [Customize](/docs/frameworks/swift/customize) for styling and [Verify mobile consent](/docs/frameworks/swift/verify) for the full release checklist.
