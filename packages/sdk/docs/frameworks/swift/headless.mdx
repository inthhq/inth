Build custom SwiftUI consent screens using the unstyled headless blocks in `InthConsentUI`. They track whether a prompt is owed, hold drafts, save choices, supply translated copy, and wire VoiceOver while leaving layout, typography, color, and motion to your app.

Link `InthCore`, `InthApple`, and `InthConsentUI`. Call `InthApple.install(_:)` during launch with the same `InthAppleConfiguration` used in the [Swift quickstart](/docs/frameworks/swift/quickstart), and omit `.inth`. Your app owns the layout, privacy policy link, and standing Privacy settings entry.

## Gate content on a permission

`ConsentGate` renders its content only while the committed decision allows it. An unresolved policy evaluates as not allowed:

{/* example: fragment */}

```swift
ConsentGate(.marketing) { AdBanner() } fallback: { AdPlaceholder() }
ConsentGate(vendorId: 755, purposeId: 1) { GoogleAds() }
ConsentGate(allowed: { $0.isCustomVendorAllowed("internal-ads") }) { HouseAds() }
```

Use the first form for a category, the second for an IAB vendor and purpose (with optional `basis:` for legitimate interest), and the third for any predicate on the core (such as a single purpose, custom partner, or Additional Consent provider). `ConsentReady` renders once a policy has resolved.

| Member | Purpose |
| --- | --- |
| `isNotice` | `true` for a notice to acknowledge, `false` for a consent choice. |

## Build a preferences screen with a draft

`HeadlessConsentPreferences` wraps your preferences screen and exposes `categories` with titles, descriptions, lock state, and switch bindings:

<include src="../../shared/examples/native/core-swift/custom-consent/swift-headless-preferences.mdx" />

Hide the switch when `locked` is `true` and render `lockedLabel` ("Always on" for `necessary`, or "Off" plus `note` when GPC or a strict policy restricts the category). `isEnabled` becomes `false` while saving, while stale, or while an IAB list is uneditable.

Edits stay in the draft until `save()`. The draft seeds from recorded choices (not effective permissions) and tracks updates while clean. Handle each save state:

| State | Meaning | UI action |
| --- | --- | --- |
| `draft.isSaving` | A save is in progress. | Disable controls and dismissal. `savingAction` names the active button; `showProgress` turns true after 400 ms. |
| `draft.errorMessage` | Storage refused the write; edits remain intact. | Display the error and wire `retry()` (omit retry when `listUnavailable` is true; use `refresh()` instead). |
| `draft.isStale` | Another surface saved after this draft opened. | Show `iabCopy.appSettingsChanged` and wire `draft.reset()`. |
| `draft.listUnavailable` | The IAB vendor list is stale or offline. | Show `iabCopy.appListOutdated` and wire `draft.refresh()`. |
| `confirmDiscard` | The user tried to dismiss with unsaved edits. | Show a confirmation wired to `discard()` and `keepEditing()`. |

Each save passes the snapshot revision the draft read. The core rejects stale writes with `concurrent-change` and retains your edits so the user can review against updated settings. A successful save confirms durable device storage and queues backend delivery; `save(_:)` also offers an `async` overload returning whether storage succeeded.

## Build your own IAB screen

Under a TCF policy, `iab` on the scope (or `draft.iab`) exposes an `IABDraftHandle` with disclosure rows and draft commands:

<include src="../../shared/examples/native/core-swift/custom-consent/swift-headless-iab.mdx" />

| Member | Contents |
| --- | --- |
| `firstLayer` | Description with partner count, partner link text, purpose/stack summary, and legitimate-interest, scope, and withdrawal statements. |
| `purposes` | Declared purposes with descriptions, legal text, illustrations, partner counts, consent switches, and legitimate-interest switches where declared. |
| `specialFeatures` | Declared special features with opt-in switches. |
| `specialPurposes`, `features` | Non-toggleable partner declarations. Show `specialPurposesExplanation` and `featuresExplanation` alongside them and on vendor detail views. |
| `stacks` | Vendor list stacks with grouped purposes and special features. |
| `vendors`, `vendors(purposeId:)`, `vendor(_:)` | Registered partners sorted by name with legal bases after publisher restrictions, switches, status, and `details`. |
| `customVendors` | Non-IAB partners with `customVendorsHeading` and `customVendorsNotice`. |
| `adTechProviders` | Google Additional Consent providers with `adTechProvidersHeading` and `adTechProvidersNotice`. |
| `publisherRestrictions` | Policy publisher restrictions (already applied to vendor rows). |
| `consentStorage` | Maximum retention period of the TC String on the device. |

Render a switch only when a vendor's `consent` or `legitimateInterest` is non-`nil`. The core rejects saves that enable an empty basis. Setting `legitimateInterest` to `false` records an objection; purposes 1 and 3 through 6 never use legitimate interest.

`acceptAll()` and `rejectAll()` on the draft stage choices without saving until `save()`. First decisions open with every consent off, registered vendors' legitimate interests unobjected, and custom partners' legitimate interests off. The core validates every ID and basis, encodes the TC String and Additional Consent string, and mirrors `IABTCF_*` keys. Gate ad SDKs on committed decisions (`ConsentGate` or `isIABAllowed`), never on draft rows.

### Required IAB disclosures

The core satisfies IAB Europe signal checks from `packages/native-protocol/iab/tcf-policy-checks.json` (T1, T3, T4, T6 to T13, P13, P21, P29). Complete CMP registration (T5) with IAB Europe and render the remaining UI checks:

| Check | Required UI |
| --- | --- |
| P1, P2 | Cover most of the screen on the first layer, leaving terms and privacy policy accessible. |
| P3, P4, P5, P12 | Render `firstLayer.description` including the partner count. |
| P6 | Render `firstLayer.partnersLink` as a link opening your partner list. |
| P7 | Render every item in `firstLayer.summary`. |
| P8, P9 | Render `firstLayer.scope` and `firstLayer.withdraw`. |
| P10, P11, P32 | Give Accept all and Reject all equal styling and at least 5:1 contrast, plus Customize (`ConsentActions` keeps widths equal). |
| T2 | Wire Reject all to `rejectAll()` on the scope to withdraw every consent. |
| P14, P15 | Render purpose and feature names, descriptions, and illustrations unchanged, with no switch on features. |
| P16 | Place `adTechProviders` and `customVendors` in separate sections with their headings and notices. |
| P17, P22 | Render `firstLayer.legitimateInterestNotice`, `legitimateInterestExplanation`, and each vendor's legitimate-interest purposes in `details`. |
| P18, P23 | Render `rightToObject` and legitimate-interest switches on each purpose and vendor. |
| P19 | Per vendor `details`: privacy policy link, consent and LI purpose lists, special purposes, features, special features, and consent switches. |
| P20 | Render a switch for each row in `specialFeatures`. |
| P25 | Show `partnersNote` or both partner counts on each purpose. |
| P26 | Show the legitimate-interest claim link in `details`. |
| P27, P28 | Show retention and data categories in `details`. |
| P30 | Show `consentStorage`. |
| P31 | Keep a standing Privacy settings entry in your app's settings. |

## Keep custom screens accessible

Both headless blocks announce save results and errors to VoiceOver once, even when multiple blocks share a draft. `HeadlessConsentPreferences` also routes the VoiceOver escape gesture through `requestClose()`. Add these modifiers to finish accessibility:

| API | Purpose |
| --- | --- |
| `.consentPane(_:)` | Announces a new screen and moves VoiceOver focus into it. |
| `.consentInitialFocus()` | Focuses the heading or first control when the screen opens. |
| `ConsentActions { }` | Gives paired actions equal width and stacks them at accessibility Dynamic Type sizes or narrow widths. |

Use Dynamic Type styles, let rows expand, and test at the largest accessibility text size.

## Keep SDK gates current

`isAllowed(.measurement)` performs a synchronous cached Boolean read. Use `decision(for: .measurement)` when you need to distinguish `.pending` from `.denied`. Keep optional work disabled in both states.

For an SDK that must start and stop as consent changes, retain a gate subscription for the service's lifetime:

<include src="../../shared/examples/native/core-swift/swiftui-consent/swiftui-observe.mdx" />

The gate delivers the current decision immediately on registration and on every change. Retain the returned `ConsentSubscription` while you want updates; releasing it or calling `cancel()` ends the subscription. Capture owners weakly inside closures to avoid retain cycles.

Gate callbacks can run on any queue, so synchronize access to your service state. For UI state, observe `PublishedConsent` (or `ObservableConsent` on iOS 17+), which publishes on the main actor:

<include src="../../shared/examples/native/core-swift/swiftui-consent/swiftui-snapshot.mdx" />

UIKit controllers can subscribe to `decisionPublisher(for:)` on the main thread. Always disable vendor auto-initializers and invoke the vendor's disable, stop, or reset API on withdrawal.

## Start a draft from recorded choices

When building a custom form directly on the core APIs, seed controls from `snapshot.explicitChoice` and record the snapshot revision:

<include src="../../shared/examples/native/core-swift/swiftui-consent/swiftui-draft.mdx" />

Switch changes edit the draft only; nothing saves until the user taps Save or Reject. Enable editing only when the core is ready, the category is in scope, and no restriction blocks it. Do not use a category-only form under an IAB policy.

## Save without losing refused drafts

Commit on a background worker and dismiss the form only when the native result is `.committed`:

<include src="../../shared/examples/native/core-swift/swiftui-consent/swiftui-save.mdx" />

Passing `expectedRevision` prevents stale drafts from overwriting newer choices. On `concurrent-change`, keep edits visible and prompt the user to reload settings. On storage errors, retain the draft and offer Retry. Disable duplicate saves and dismissal while a save is active.

`.committed` confirms durable local storage; observe `eventStream` for `.saveDelivered` or `.saveReplayed` to track backend delivery separately.
