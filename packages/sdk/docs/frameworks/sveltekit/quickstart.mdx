Add a consent banner and preference dialog to a SvelteKit app. Your server resolves each visitor's consent from a build-time manifest, and analytics wait until consent allows them.

<Prompt title="Add Inth consent to this SvelteKit app" description="Paste into Claude Code, Codex, Cursor or another coding agent at the root of your app.">
  Add Inth consent management to this SvelteKit app.

  1. Check that the app runs on a SvelteKit server (SvelteKit 2.63+ with Svelte 5.20+). If it uses `adapter-static`, prerendered-only pages, or SPA mode, stop and tell me.
  2. Install `@inth/svelte` and `@inth/integrations`. Read `node_modules/@inth/svelte/AGENTS.md`, then follow the SvelteKit quickstart it links to, in order. Do not guess the API from memory.
  3. Set `PUBLIC_INTH_PROJECT_URL` in `.env`. Ask me for my project URL, and use `https://example-inth.inth.app` only for a demo. `PUBLIC_INTH_PROJECT_URL` wins over any legacy `PUBLIC_C15T_BACKEND_URL`.
  4. Add `consentManifest()` from `@inth/svelte/vite` to `plugins` in `vite.config.ts`. Add nothing to `.gitignore`: the plugin writes no files to the project.
  5. Export `inthHandle()` from `@inth/svelte/kit` in `src/hooks.server.ts`, type `locals.inth` in `src/app.d.ts`, and export `loadConsent as load` from `@inth/svelte/kit` in `src/routes/+layout.server.ts`.
  6. In `src/routes/+layout.svelte`, render `InthProvider` with `state={data.consent}`, `ConsentBanner`, `ConsentDialog`, and a footer `ConsentDialogLink`. Move analytics and marketing scripts into `InthProvider`'s `scripts` prop using `@inth/integrations`, and remove old `<script>` tags or SDK imports. If a vendor has no helper, tell me.
  7. Run `vite build` and `vite preview`. Confirm `data-testid="consent-banner-root"` is in the page source, no vendor request fires before consent, rejection survives reload, and granting analytics loads the vendor.

  Then list the files you changed, any script still outside consent, and how you checked the requests.
</Prompt>

## Prerequisites

- A server-rendered SvelteKit 2.63+ app with Svelte 5.20+. For prerendered, static, or SPA apps, see [Use another rendering mode](#use-another-rendering-mode). Not on SvelteKit? See the [framework list](/docs/frameworks).
- An [Inth project](https://inth.com/dashboard/sign-up?framework=sveltekit) with your app's origin in its trusted origins.

## Install the SDK

<CommandTabs command="@inth/svelte @inth/integrations" mode="install" />

Components inject their own styles and `inthHandle` inlines banner styles into `<head>`. On Tailwind CSS 3, [import the stylesheet yourself](/docs/customization/stylesheets#import-the-stylesheet-yourself).

## Set the project URL

Add your Inth project URL, including any path prefix, to `.env` and your host's build settings:

```sh title=".env"
PUBLIC_INTH_PROJECT_URL=https://example-inth.inth.app
```

The URL is public, not a secret. `https://example-inth.inth.app` is a demo project. Rebuild after changing it. `PUBLIC_INTH_PROJECT_URL` wins over any legacy `PUBLIC_C15T_BACKEND_URL`, which is read as a fallback if unset.

## Check it works

Run `vite build` and `vite preview`, then open the app in a private window with DevTools open.

1. View page source: under an opt-in policy, it contains `data-testid="consent-banner-root"` and `<style data-inth-styles>`.
2. In the Network panel, no PostHog or `/v1/consent/init` request fires.
3. Click **Reject All**, then reload. The banner is absent and PostHog does not load.
4. Open **Privacy settings**, turn on **Analytics**, and click **Save Settings**. PostHog loads.
5. Turn **Analytics** off and click **Save Settings**. The page reloads and PostHog does not load.

See [SvelteKit troubleshooting](/docs/frameworks/sveltekit/troubleshooting) and [Verify consent](/docs/guides/verify-consent).
