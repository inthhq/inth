## Import server helpers only in server files

`@inth/svelte/kit` holds the SvelteKit helpers. Import them from
`hooks.server.ts`, `+layout.server.ts`, `+page.server.ts` and `+server.ts`
only. Imported into a component, they add the manifest resolver and every
bundled translation to the browser bundle. Components import from
`@inth/svelte`.

| Export | From | Use it in | Page |
| --- | --- | --- | --- |
| `inthHandle(options)` | `@inth/svelte/kit` | `hooks.server.ts` | [inthHandle](#inthhandle) |
| `loadConsent` | `@inth/svelte/kit` | `+layout.server.ts`, as `load` | [loadConsent](#loadconsent) |
| `createConsentRoute(options)` | `@inth/svelte/kit` | `+server.ts` | [createConsentRoute](#createconsentroute) |
| `manifest()`, `hosted()`, `testing()` | `@inth/svelte/kit` | `hooks.server.ts`, as `inthHandle({ mode })` | [Rendering](./rendering#pick-a-rendering-path) |
| `consentManifest(options)` | `@inth/svelte/vite` | `vite.config.ts` | [consentManifest](#consentmanifest) |

The modes from `@inth/svelte/kit` return plain data that reaches the browser
through `loadConsent`.

## inthHandle

`inthHandle(options?)` returns a SvelteKit `Handle` that holds the consent
config for the app. Register it in `src/hooks.server.ts`. For every request
it:

1. reads the location, language and GPC inputs from the headers,
2. writes them back as `x-inth-country`, `x-inth-region`, `accept-language`
   and `sec-gpc`, so later code sees one normalized form,
3. reads the consent cookie, and the subject ID its records carry,
4. stores the result and its own options on `event.locals.inth`,
5. writes a server-rendered banner's styles into the page `<head>`, and
6. on pages whose provider has `scripts` or network blocker rules, links
   the chunk that holds both with `<link rel="modulepreload">`, once
   `consentManifest()` has written its URL into the build.

The handle sets no cookie. While SvelteKit prerenders, it reads no cookie or
headers either: the page goes to every visitor.

| Option | Type | Default | Behavior |
| --- | --- | --- | --- |
| `mode` | `ConsentMode` | `manifest()` | How `loadConsent` resolves the visitor. `manifest()` or `hosted()` from `@inth/svelte/kit`, or `testing()` from `@inth/svelte/testing`. A transport factory throws; pass it to `InthProvider`'s `mode` prop instead. |
| `routePrefix` | `string` | none | Where `createConsentRoute()` is mounted, such as `/api/inth`. The browser then resolves consent on pages the server did not, through that route. Without it, the browser asks the backend's `/v1/consent/init`. `'/'` throws ``@inth/svelte: `routePrefix` can't be '/': a consent route at the site root would catch every page. Use a path such as '/api/inth'.`` when the hook is created. |
| `projectUrl` | `string` | the URL `consentManifest()` read | The backend. Consent saves go here, unless `proxy` is on. |
| `proxy` | `boolean` | `false` | Sends the browser's consent saves to the route at `routePrefix`, which forwards them to `projectUrl` with `createConsentRoute({ proxy: true })`. Throws without `routePrefix`. See [save consent through your own origin](./rendering#save-consent-through-your-own-origin). |
| `snapshot` | `ConsentManifest` | the manifest `consentManifest()` downloaded | A manifest to resolve with. `createConsentRoute()` reads it too. |
| `cookieName` | `string` | `inth` | The consent cookie. Match the provider's `storageConfig.storageKey`. |
| `country`, `region`, `language` | `string` | from headers | Forces the input for every request. |

`event.locals.inth` has this shape, exported as `InthLocals`:

| Field | Value |
| --- | --- |
| `config` | The `ConsentState` from the cookie and request inputs, without a resolved policy. |
| `inputs` | `{ country?, region?, language?, gpc? }` for this request. |
| `mode` | The handle's mode, as data. |
| `projectUrl`, `proxy`, `routePrefix`, `snapshot`, `cookieName` | The handle's options, when you passed them. |
| `shared` | `true` while SvelteKit prerenders. |

Some runtimes refuse to change request headers. The handle then skips step
2, and `event.locals.inth.inputs` still carries the values. Compose it with
your own handles through `sequence()` from `@sveltejs/kit/hooks`. Type
`event.locals.inth` by adding
`/// <reference types="@inth/svelte/kit/locals" />` to `src/app.d.ts`.

## loadConsent

`loadConsent(event, options?)` returns `Promise<{ consent }>`. Export it as
the root layout's `load`, and pass `data.consent` to `InthProvider` as
`state`:

<include src="../../shared/examples/sveltekit/layout-server.mdx" />

It reads the consent cookie, the location and language headers and Global
Privacy Control, then resolves the policy with the handle's `mode`:

| Mode | How it resolves |
| --- | --- |
| `manifest()` | From the snapshot `consentManifest()` downloaded, or the handle's `snapshot`, with this visitor's inputs. No policy request. |
| `manifest({ source: 'runtime' })` | From the manifest at `${projectUrl}/v1/consent/manifest`, or `manifestUrl`, fetched and cached in memory. |
| `manifest({ resolve: 'browser' })` | Reads the cookie only. The browser resolves the policy. |
| `hosted()` | Calls the backend's `/v1/consent/init`. |
| `testing()` | From the mode's `policy`, or Inth's recommended rules. |

`consent` holds the resolved state, the mode as data, the backend URL and the
handle's `routePrefix`. It is plain, serializable data; pass it to
`InthProvider` unchanged.

While SvelteKit prerenders, `loadConsent` reads its `building` flag and
returns no stored consent, clock, GPC signal or policy, and makes no backend
request. Any stored records in the page would stop the browser reading the
visitor's own cookie, and a build-time clock would age every record against
it. The browser resolves the visitor after hydration.

To pass options, call it from your own `load`:

{/* example: fragment */}

```ts title="src/routes/+layout.server.ts"
import { loadConsent } from '@inth/svelte/kit';

export const load = (event) => loadConsent(event, { timeoutMs: 1000 });
```

| Option | Type | Default | Behavior |
| --- | --- | --- | --- |
| `timeoutMs` | `number` or `false` | `500` | Longest wait for the backend or the manifest, in milliseconds. `false` or `Infinity` waits as long as it takes; any other value that is not a finite, non-negative number uses the default. |
| `experiment` | `ServerExperiment` | none | The banner experiment with this request's arm. While the visitor has no stored choice, the backend counts the arm; the state carries the experiment to `InthProvider`. |
| `onBackgroundRevalidate` | `(promise, event) => void` | platform hook when available | Keeps session reports and unfinished requests alive after the response. `event.platform.context.waitUntil` takes precedence; this callback is the fallback. See [keep background work alive](./rendering#keep-background-work-alive-after-the-response). |
| `cookieName` | `string` | the handle's, or `inth` | The consent cookie. Match the provider's `storageConfig.storageKey`. |
| `country`, `region`, `language` | `string` | from the handle or headers | Forces one input for this call. |
| `forwardHeaders` | `string[]` | none | Extra request headers to send to the backend's `/v1/consent/init`, only over `https`, to a loopback host, or in-process. `cookie`, `forwarded` and `x-forwarded-*` cannot be named. |
| `trustForwardedHeaders` | `boolean` | `false` | Resolves a relative backend URL against the request's forwarding headers instead of `event.url`, and sends the visitor IP to the backend as `x-forwarded-for`. |
| `fetch` | `typeof fetch` | global `fetch` | The fetch for a backend on another origin. A URL on the request's own origin always goes through `event.fetch`. A custom fetch keeps the vendor list inline. |

`loadConsent` resolves a relative backend URL against `event.url`. Any URL
on the request's own origin, relative or absolute, is called with
`event.fetch`, so SvelteKit answers it in-process and the request never
leaves the server. A client's `x-forwarded-host` does not change it.
`adapter-node` builds that origin from `paths.origin` in SvelteKit 3 (the
`ORIGIN` variable in SvelteKit 2), or from its `PROTOCOL_HEADER` and
`HOST_HEADER` settings. SvelteKit 3's `adapter-node` ignores `ORIGIN` without
a warning; move it to `paths.origin` when you upgrade.
`trustForwardedHeaders: true` resolves against the forwarding headers
instead. Set it only when your proxy overwrites those headers.

In `hosted()` mode, the backend's `/v1/consent/init` gets the resolved location,
language and GPC, the `user-agent` and, while the visitor has no stored
choice, the experiment arm. A backend on another origin, over `https` or a
loopback host, also gets the consent cookie (`cookieName`, never the rest of
the cookie jar) and any `forwardHeaders`. Nothing identifying crosses plain
HTTP to a remote host.

`loadConsent` never throws. When the backend fails, answers with an error or
takes longer than `timeoutMs`, it returns the stored choice without a policy.
The page then renders without a banner in the HTML, optional categories stay
denied, and the browser resolves the policy after hydration. A manifest fetch
that runs out of time keeps running in the background and fills the manifest
cache for the next request.

When `inthHandle` ran for the request, `loadConsent` reuses the inputs it
normalized. Passing `country`, `region` or `language` makes it read the
headers again for that call.

## createConsentRoute

`createConsentRoute(options?)` returns the request handlers for the consent
route. Export them from a catch-all route such as
`src/routes/api/inth/[...path]/+server.ts`, and set
`inthHandle({ routePrefix: '/api/inth' })` so the browser uses it. Only pages
the server did not resolve, such as prerendered ones, need it. The route
reads the snapshot, backend URL and mode `inthHandle()` stored on
`event.locals.inth`, so you set them once, on the handle. Options you pass to
the route win.

An app that mounts one `+server.ts` per route instead of a catch-all must move
them under `v1/consent/`, or the browser's requests answer 404:
`src/routes/api/inth/init/+server.ts` becomes
`src/routes/api/inth/v1/consent/init/+server.ts`, and the same for `manifest`.
A catch-all route needs no change.

<include src="../../shared/examples/sveltekit/route-handlers.mdx" />

| Returned | Serves |
| --- | --- |
| `GET` | `v1/consent/init` below the rest parameter: the visitor's resolved policy, like the backend's `/v1/consent/init`, with `Cache-Control: private, no-store`. Under an IAB policy it also serves the Global Vendor List. `v1/consent/manifest`: the manifest, with the backend's `Cache-Control` and `ETag`, answering `If-None-Match` with `304`. Any other path is forwarded with `proxy` on and answers `404` without it. |

With `proxy` on, it also returns `POST`, `PATCH`, `PUT`, `DELETE` and
`OPTIONS`, which forward writes to the backend.

| Option | Type | Default | Behavior |
| --- | --- | --- | --- |
| `projectUrl` | `string` | the handle's: `inthHandle({ projectUrl })`, then the URL `consentManifest()` read from `PUBLIC_INTH_PROJECT_URL` | The backend's base URL, absolute or `/`-relative. The manifest is at `<projectUrl>/v1/consent/manifest` when there is no snapshot. |
| `manifestUrl` | `string` | the handle's `manifest({ manifestUrl })`, unless it is on this route | A manifest URL of its own, such as a CDN. Wins over `projectUrl`. Absolute or `/`-relative. |
| `snapshot` | `ConsentManifest` | the handle's: the mode's `snapshot`, then `inthHandle({ snapshot })`, then the manifest `consentManifest()` downloaded; none for `source: 'runtime'` or an absolute `manifestUrl` | A manifest to resolve with. The route and `loadConsent` pick the same one. |
| `proxy` | `true` or `{ paths?, cookieNames? }` | off | Forwards consent writes to `projectUrl`. See [save consent through your own origin](./rendering#save-consent-through-your-own-origin). |
| `onBackgroundRevalidate` | `(promise, event) => void` | `event.platform.context.waitUntil`, when the adapter provides it | Keeps background manifest refreshes and session reports alive on runtimes that stop work after the response. SvelteKit 3's Cloudflare and Vercel adapters provide none; see [keep background work alive](./rendering#keep-background-work-alive-after-the-response). |
| `fetchGvl` | `({ reference, language, fetch }) => Promise<GlobalVendorList \| null>` | the shared server cache, with a five-second deadline | Fetches the Global Vendor List under an IAB policy. A rejection fails the init request instead of answering `gvl: null`. |
| `fetch` | `typeof fetch` | global `fetch` | The fetch used for an absolute `projectUrl` or `manifestUrl`, and for the vendor list. |

An absolute `projectUrl` or `manifestUrl` is fetched over the network with
`fetch`. A `/`-relative one, such as `/api/inth`, names a route in this app. The handlers request it through
`event.fetch`, which SvelteKit answers in-process, so it is never resolved
against `event.url` or the request's `Host` header. The proxy forwards to a
relative `projectUrl` the same way. Do not point it at the route the handlers
serve, such as `/api/inth`, or the route requests itself. The route skips a
`inthHandle()` `projectUrl` that names its own path for this reason. A relative
`projectUrl` also turns off session reports, which need an absolute backend.

With runtime fetching, the manifest is cached in memory per server process
for as long as its `s-maxage` allows. After that, within the backend's
`stale-while-revalidate` window, the handlers serve the stale copy while it
refreshes in the background. Past that window, the next request waits for a
fresh copy.
The `manifest` handler passes upstream only a `language` query parameter that
looks like a language tag; the visitor's other parameters never reach the
backend. When the manifest cannot be read and `projectUrl` is set, `init` asks
the backend's own `/v1/consent/init`, which covers backends without `/v1/consent/manifest`.

These handlers are built on the consent route handler in `@inth/sdk/server`,
shared with the Next.js, TanStack Start, Astro and Nuxt adapters. A
resolution that did not match carries no snapshot token, vendor list, CMP ID
or custom vendors.

### Trace consent requests

Use this recipe with SvelteKit 3.1 or later when your app already collects
server traces. A trace shows where a request spends time. Each timed operation
in that trace is a span.

SvelteKit 3.1 adds a `sveltekit.endpoint` span for each `+server.ts` handler
when `tracing.server` is enabled. The consent route receives that span
automatically. Follow SvelteKit's
[observability guide](https://svelte.dev/docs/kit/observability) to enable tracing
and configure a collector for your deployment. Enabling tracing alone does not
send traces anywhere.

The consent route uses one catch-all path for initialization, the manifest,
and consent writes. Add an operation name so your collector can distinguish
those requests. Also record the returned HTTP status. Inth returns `502` when
it cannot reach the backend, `504` when the proxy times out, and forwards other
upstream HTTP errors. These are responses, so SvelteKit's exception reporting
does not mark the endpoint span as failed.

Add this helper to your app. `SPAN_STATUS_ERROR` is OpenTelemetry's error status,
`2`. The helper uses the span SvelteKit provides and needs no runtime
OpenTelemetry import:

<include src="../../shared/examples/sveltekit/trace-consent.mdx" />

Wrap the handlers in `src/routes/api/inth/[...path]/+server.ts`. This example
uses the [consent proxy](./rendering#save-consent-through-your-own-origin).
Keep the backend URL and `routePrefix` configured on `inthHandle` as described
there. The helper reads the `path` rest parameter, so keep that parameter name
when you copy the route:

<include src="../../shared/examples/sveltekit/traced-route-handlers.mdx" />

The example uses `#lib/*` mapped to `./src/lib/*` in your `package.json`
`imports`. If your app uses another alias, change the helper import to match.

For a read-only route, keep `createConsentRoute()` without `proxy` and export
only the wrapped `GET` handler.

SvelteKit also uses `GET` for `HEAD` requests when the route exports no `HEAD`
handler. The helper labels those consent reads as `init` or `manifest` too.

In your collector, check these requests:

| Request | `inth.operation` | `http.response.status_code` | Endpoint span status |
| --- | --- | --- | --- |
| `GET /api/inth/v1/consent/init` | `init` | `200` | Unchanged |
| `GET /api/inth/v1/consent/manifest` | `manifest` | `200`, or `304` for a cached copy | Unchanged |
| `POST /api/inth/v1/consent/records` | `proxy` | The backend's status | Error for `500` or higher |
| A proxy request with an unreachable backend | `proxy` | `502` | Error |
| A proxy request that times out | `proxy` | `504` | Error |

The operation attribute has only three values. The helper does not add request
bodies, cookies, subject IDs, or query parameters to the span. It returns the
original response, including its streaming body and headers. Thrown errors
continue to SvelteKit's exception handling.

With tracing disabled, the helper calls the handler without writing span
attributes. Inth continues to support SvelteKit 2.63 and later in version 2,
and SvelteKit 3.0. Those versions expose the same tracing API, but do not create
a separate endpoint span. If you use the helper there with tracing enabled,
its attributes describe the enclosing framework span. Upgrade to 3.1 or later
for the endpoint spans shown in this recipe.

This recipe covers requests to the consent route. Consent resolved during
server rendering runs through `loadConsent` in `+layout.server.ts`, under
SvelteKit's load tracing. Browser hydration, vendor scripts, and background
manifest refreshes need separate instrumentation.

## consentManifest

`consentManifest(options)` from `@inth/svelte/vite` returns the Vite plugins
that download `<projectUrl>/v1/consent/manifest` during the build. `loadConsent`,
`createConsentRoute()` and `manifest()` from `@inth/svelte` read the result
without an import. The plugin writes no file into your project.

| Option | Type | Default | Behavior |
| --- | --- | --- | --- |
| `projectUrl` | `string` | `PUBLIC_INTH_PROJECT_URL`, then `VITE_INTH_PROJECT_URL` | Absolute `http` or `https` backend URL. The plugin appends `/v1/consent/manifest`. |
| `onBuildError` | `'fail' \| 'runtime'` | Unset | What a failed fetch does. Unset, `vite build` stops and `vite dev` logs a warning. A missing backend URL counts as a failed fetch. The `INTH_ON_BUILD_ERROR` environment variable overrides it. |

The plugin detects `sveltekit()` and keeps the snapshot on the server: the
browser bundle never holds it. A Svelte app without SvelteKit gets it in the
browser, for `manifest()`. The backend URL is public and reaches both.

The plugin fetches once Vite has resolved its config: for `vite build`,
`vite dev` and, on SvelteKit 3, `svelte-kit sync`. `vite preview` does not
run it. The fetch waits at most 10 seconds. When it fails, `vite build` stops.
`vite dev` logs a warning instead, and `loadConsent` fetches the policy at
runtime. In a SvelteKit build the plugin also writes the URL of the chunk
that holds the script loader and the network blocker, which `inthHandle`
preloads.

With Vite 8, which bundles with Rolldown, the plugin also puts the small Inth
modules that `InthProvider`'s first load shares with the consent engine into
one chunk named `inth`. Rolldown would otherwise give each of them a file of
its own, about a dozen requests of a few hundred bytes each. The page loads
the same code in fewer files. The plugin leaves the chunks alone when your
config sets `manualChunks` or `advancedChunks` or turns code splitting off,
and it adds its group after any `codeSplitting.groups` of yours.

Server code that needs the manifest itself, such as a `resolveConsent` call,
imports `snapshot` and `projectUrl` from `@inth/svelte/generated`. Without the
plugin, that module still resolves and exports `undefined` for both. It ships
its own types, so `svelte-check` passes on a fresh checkout without running
Vite first.

## ConsentState

`resolveConsent` and `event.locals.inth.config` return a `ConsentState`:
plain, serializable data a load can return. It holds the stored records, the request's location,
language and GPC, the resolved policy and translations when the backend
answered, and the IAB state for an IAB policy. It holds no computed
permissions. Pass it on unchanged; do not build one yourself or edit its
fields.
