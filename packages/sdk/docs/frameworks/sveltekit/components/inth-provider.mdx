## Mount InthProvider in the root layout

Export `loadConsent` as the root layout's server load, then pass its
`consent` to `InthProvider` from `@inth/svelte/kit` as `state`:

<include src="../../../shared/examples/sveltekit/layout-server.mdx" />

<include src="../../../shared/examples/sveltekit/layout.mdx" />

Pass `data.consent` through unchanged. It holds the visitor's
server-resolved consent, the mode `inthHandle()` was given, the backend URL
and the consent route's prefix. `InthProvider` starts consent from it, on
the server and in the browser, so both render the same banner and the
browser makes no second policy request. The [quickstart](../quickstart)
explains `inthHandle` and `loadConsent`.

`InthProvider` turns the mode into a transport that loads each policy path
only when it runs. A page the server resolved ships a small transport that
saves choices, and no resolver, policy rules, snapshot or other languages.
The code to resolve the policy again in the browser, such as after a
language change or on a prerendered page, loads when it is needed.

To use a transport of your own, pass your transport factory as
`InthProvider`'s `mode` prop. `inthHandle()` takes only data modes.

Keep the provider in the root `+layout.svelte`. A layout stays mounted across
client-side navigation, so the runtime, the loaded scripts and the dialog
survive page changes. A provider in a page component would start again on
every navigation.

Create `scripts` and `callbacks` in the layout component, not in
`+layout.server.ts`. They hold functions, which a server load cannot send to
the browser.

### Props only this component takes

| Prop | Type | Default | Behavior |
| --- | --- | --- | --- |
| `state` | `InthProviderState` from `@inth/svelte/kit` | required | `data.consent` from `loadConsent` in `+layout.server.ts`: the visitor's server-resolved consent, the mode `inthHandle()` was given, the backend URL and the consent route's prefix. Read once, when the component mounts. |
| `mode` | a transport factory | the mode in `state` | A transport of your own, in place of the mode `inthHandle()` was given. Read once, when the component mounts. |
| `children` | `Snippet` | none | Your app. |

This component creates, starts and disposes of its own consent runtime, so it
takes no `runtime`. To share one runtime across component trees, render
`InthProvider` from `@inth/svelte` and pass it a runtime from
`createConsentRuntime()` as `runtime`.
