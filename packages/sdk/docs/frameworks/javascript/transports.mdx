## Compare the transports

A transport tells the kernel which policy applies to this visitor and where
to record their choice.

| Transport | Policy comes from | Choices go to | Use it when |
| --- | --- | --- | --- |
| `manifest()` with a build-time snapshot, recommended | Public policy bundled during the build, resolved in the browser | The backend's `/v1/consent/records` | You use Vite and can rebuild after policy edits. Regional policies may still request location. |
| `hosted()` | The backend's `/v1/consent/init`, per visit | The backend's `/v1/consent/records` | Policy changes must apply without rebuilding, or you need backend resolution on every visit. |
| `manifest()` at runtime | The backend's public `/v1/consent/manifest`, resolved in the browser | The backend's `/v1/consent/records` | You want the banner to render without a per-visit `/v1/consent/init` request and cannot bundle the policy. |
| `testing()` | A policy you pass, or the recommended rules, resolved in the browser | Nowhere; the browser only | Tests. It throws in production builds. |

Every setup needs `projectUrl`, your Inth project URL, unless the mode is
`testing()`. With no `mode`, a JavaScript app asks the backend's `/v1/consent/init`.

[Consent modes](/docs/concepts/modes) covers the same factories in every
framework, and [data fetching](/docs/concepts/data-fetching) compares the
paths in more depth, including what each one sends.

## Pass a transport

Each setup takes the transport in a slightly different form:

| Setup | Where it goes |
| --- | --- |
| `@inth/sdk` | `init({ projectUrl, mode })`. `mode` is optional: `manifest()` or `hosted()` from `@inth/sdk`, or `testing()` from `@inth/sdk/testing`. |
| `createConsentRuntime` | `projectUrl`, and an optional `mode` from the same entries. |
| Script tag | `data-project-url`, and `data-mode="hosted"` or `"manifest"` on the headless and IAB scripts. Tests load `inth.testing.js`. |
| `createConsentKernel` | `transport`, the transport object itself, such as `createV1HostedTransport({ projectUrl })`. |

A factory is created once. To switch transports, dispose the client or
runtime and create a new one.

`init()` from `@inth/sdk` bundles the hosted transport, and the manifest
and testing code only when you import them. Passing a mode name throws:

```txt
@inth/sdk: `mode` must be hosted() or manifest() from @inth/sdk, or testing() from @inth/sdk/testing. Mode names like "hosted" work only in the script-tag builds.
```

Leaving out `projectUrl` throws:

```txt
@inth/sdk: `projectUrl` is required. Set it to your Inth project URL, or use `mode: testing()` from @inth/sdk/testing in tests.
```

## Hosted

With `projectUrl` and no mode, or with `mode: hosted()`, the runtime asks your
Inth backend's `/v1/consent/init` for each visitor and saves to its `/v1/consent/records`:

<include src="../../shared/examples/javascript/runtime.mdx" />

`hosted()` takes no options; it uses the `projectUrl` you pass. For a kernel you
create yourself, `createV1HostedTransport({ projectUrl })` from
`@inth/sdk/transports` takes these options:

| Option | What it does |
| --- | --- |
| `projectUrl` | Your Inth project URL. Relative URLs such as `/api/inth` work behind a same-origin consent route. |
| `headers` | Request headers to forward on `/v1/consent/init`: `accept-language`, the geo headers and `sec-gpc`. Meant for server code forwarding a visitor's request. |
| `fetch` | A `fetch` implementation, for tests or unusual runtimes. |
| `property` | The host name or app ID recorded with each save. Defaults to the page's host name. |
| `initUrl` | Send `/v1/consent/init` somewhere else, such as a same-origin route, while saves still go to `projectUrl`. Saves then assert the policy they were made against. |
| `assertDecisionInputs` | Send the resolved policy inputs with each save, so the backend can reject a save made against a stale policy. Defaults to `false`; `hosted()` turns it on when `initUrl` is set. |

Add your app's origin to the Inth project's trusted origins, or the browser
blocks consent saves with a CORS error.

A cross-origin `/v1/consent/init` is a CORS simple request: the overrides and
experiment arm go in the query string, and the request carries no cookies, so
the browser sends it without an `OPTIONS` preflight.
Saves still go out with cookies and still need the trusted origin.

## Manifest

`manifest()` from `@inth/sdk` resolves the policy in the browser from the
backend's public manifest. With no options it uses the snapshot and backend
URL `consentManifest()` downloaded; without a snapshot it fetches
`${projectUrl}/v1/consent/manifest` once. When the manifest is unavailable, it asks the
backend's `/v1/consent/init` and logs a warning. It works with `init()` and with
`createConsentRuntime`:

<include src="../../shared/examples/javascript/transport-manifest.mdx" />

| Option | What it does |
| --- | --- |
| `manifestUrl` | Where to fetch the manifest when the page loads. The build's snapshot is not used, but saves still go to the build's backend URL. Without one, a URL that ends in `/v1/consent/manifest` also gives the backend URL. |
| `snapshot` | The manifest object itself, inlined into the page. No manifest request at all. Defaults to the build's snapshot unless you set `manifestUrl`. |
| `source` | `'runtime'` ignores the build's snapshot and fetches the manifest. You can pass `snapshot` or `source`, not both. |
| `projectUrl` | Where saves go. Defaults to the build's backend URL. Required otherwise, unless `manifestUrl` ends in `/v1/consent/manifest`. `''` means this origin. |
| `inputs` | `{ country, region }` known ahead of time, such as a country your edge injected into the page. |
| `geoUrl` | A same-origin route that answers `{ country, region }`, asked when the policy needs a location the page doesn't have. |
| `initFallback` | `false` resolves for an unknown location instead of asking the backend's `/v1/consent/init`. Defaults to `true`. |
| `fetch` | A `fetch` implementation. |

When some locations get a different banner than others, or no banner, and
neither the page nor `geoUrl` supplies a country, the transport asks the
backend's `/v1/consent/init` instead, so the answer stays correct. That visitor's banner
waits for the round trip. Rules keyed by country or region that all give the
same banner (same model, prompt, categories, copy and GPC handling, only the
rule id differs) resolve in the browser, so the banner shows without a
request. Such a manifest needs a default rule, plus a fallback rule when it
has region rules, so that every location matches one. When the location is
unknown, an IAB policy behind country or region rules still goes to `/v1/consent/init`.
`manifestNeedsLocation(manifest)` from `@inth/sdk` tells you in advance.

The browser bundle carries English base copy. Another language's base copy
loads the first time a visitor needs it, and the manifest's own translations
apply on top.

A manifest resolved in the browser without a known location reports no
location: `getSnapshot().location` and `useLocation()` have a `null` country
and region. Code that reads the visitor's country should supply it through
`inputs`, or use `/v1/consent/init`. IAB GPP needs it for its US state sections, so when
GPP is on, through the runtime's `gpp` option, `<ConsentGPP>` or `mountGPP()`,
an unknown location goes to `/v1/consent/init` even when every location gets the same
banner. The script-tag build counts GPP as on, because `inth.gpp.js` can load
after `init()`; pass `gpp: false` to `inth.init()` to resolve in the browser on
pages that do not load it.

`createV1ManifestTransport` from `@inth/sdk/transports/manifest` is for server
code only. It bundles every language. Browser code uses `manifest()`, or
`createBrowserManifestTransport` from `@inth/sdk/transports/manifest-browser`.

## Testing

`testing()` from `@inth/sdk/testing` resolves a policy in the browser and
sends nothing. It needs no `projectUrl`, and it throws in production builds,
so a test configuration that reaches production fails on load.

{/* example: fragment */}

```ts title="src/consent.test.ts"
import { init } from '@inth/sdk';
import { policyRulePresets } from '@inth/sdk/engine';
import { testing } from '@inth/sdk/testing';

init({
	mode: testing({
		policy: [policyRulePresets.europeOptIn(), policyRulePresets.worldNone()],
	}),
	overrides: { country: 'DE' },
});
```

| Option | Default | What it does |
| --- | --- | --- |
| `policy` | the recommended rules | A `PolicyRule` or an array of them, resolved instead of the recommended pack. |
| `iab` | whether `iab` is configured | Resolve the IAB TCF variant of the recommended pack. |

The recommended rules are strict opt-in for Europe, the UK, Quebec and unknown
locations, opt-out for US states with a privacy law, and no prompt elsewhere.
The browser cannot see the visitor's country, so set `overrides.country` to
pick a rule. [Policies](/docs/concepts/policies) lists the presets.

A test page with no bundler loads `inth.testing.js`, which takes preset names
in `data-policy`; see [Modes](/docs/concepts/modes#testing).

## Check it works

1. With hosted mode, the Network tab shows one `/v1/consent/init` request per fresh
   visit and a `/v1/consent/records` request after a choice.
2. With a build-time manifest, it shows no `/v1/consent/manifest` request. With runtime
   manifest mode, it shows a `/v1/consent/manifest` request. Neither calls `/v1/consent/init`, unless
   the policy needs a country the page did not supply.
3. In a test with `testing()`, it shows no Inth request at all, and the
   choice survives a reload.
