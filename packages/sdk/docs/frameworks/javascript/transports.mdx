A transport tells the Inth consent kernel where to resolve a visitor's policy and where to record consent choices.

## Compare the transports

| Transport | Policy source | Choice destination | Use it when |
| --- | --- | --- | --- |
| `manifest()` with build snapshot | Public policy bundled in Vite, resolved in browser | `${projectUrl}/v1/consent/records` | You use Vite and rebuild after policy edits. Regional rules may still need location. |
| `hosted()` | `${projectUrl}/v1/consent/init`, per visit | `${projectUrl}/v1/consent/records` | Policy edits apply without rebuilding, or you want server resolution per visit. |
| `manifest()` at runtime | Public `${projectUrl}/v1/consent/manifest`, resolved in browser | `${projectUrl}/v1/consent/records` | You want to avoid per-visit `/v1/consent/init` calls without bundling the policy. |
| `testing()` | Local policy rules, resolved in browser | Browser storage only | Tests. Throws in production builds. |

Every transport except `testing()` requires `projectUrl`, your Inth project URL. When you omit `mode`, a JavaScript app defaults to `hosted()` and calls `/v1/consent/init`. See [consent modes](/docs/concepts/modes) and [data fetching](/docs/concepts/data-fetching) for cross-framework defaults and request flows.

## Pass a transport

| Setup | How to pass the transport |
| --- | --- |
| `@inth/sdk` | `init({ projectUrl, mode })`. `mode` is optional: `manifest()` or `hosted()` from `@inth/sdk`, or `testing()` from `@inth/sdk/testing`. |
| `createConsentRuntime` | `projectUrl` and optional `mode` from the same entries. |
| Script tag | `data-project-url`, plus `data-mode="hosted"` or `"manifest"` on headless and IAB tags. Tests load `inth.testing.js`. |
| `createConsentKernel` | `transport`, such as `createV1HostedTransport({ projectUrl })`. |

Transports are created once; dispose the client or runtime to switch transports. `init()` bundles only `hosted()` by default, loading manifest and testing code only when imported. Passing a string mode name throws:

```txt
@inth/sdk: `mode` must be hosted() or manifest() from @inth/sdk, or testing() from @inth/sdk/testing. Mode names like "hosted" work only in the script-tag builds.
```

Omitting `projectUrl` outside `testing()` throws:

```txt
@inth/sdk: `projectUrl` is required. Set it to your Inth project URL (data-project-url on a script tag), or use testing() from @inth/sdk/testing in tests.
```

## Hosted

With `projectUrl` and no `mode`, or with `mode: hosted()`, the runtime resolves policies from `${projectUrl}/v1/consent/init`, posts choices to `${projectUrl}/v1/consent/records`, and syncs durable opt-outs through `${projectUrl}/v1/consent/opt-outs` and `${projectUrl}/v1/consent/opt-outs/lift` (the backend derives which rights apply from the visitor's location; if a backend answers `404` on those opt-out routes, Inth keeps opt-outs local with all three rights without errors):

<include src="../../shared/examples/javascript/runtime.mdx" />

`hosted()` takes no options and reads `projectUrl` from the client or runtime. When building a kernel directly, `createV1HostedTransport({ projectUrl })` from `@inth/sdk/transports` accepts:

| Option | Behavior |
| --- | --- |
| `projectUrl` | Your Inth project URL. Relative paths such as `/api/inth` work behind a same-origin consent route. |
| `headers` | Forwarded init headers, `accept-language`, geo headers, and `sec-gpc`, when server code forwards a visitor request. |
| `fetch` | Custom `fetch` implementation for tests or non-standard runtimes. |
| `property` | Hostname or app ID recorded with each save. Defaults to the page hostname. |
| `initUrl` | Alternate URL for `/v1/consent/init`, such as a same-origin route, while saves still post to `projectUrl`. |
| `assertDecisionInputs` | Sends resolved policy inputs with each save so Inth rejects saves against a stale policy. Defaults to `false`; `hosted()` enables it when `initUrl` is set. |

Add your app's origin to your Inth project's trusted origins, or browsers block consent saves with a CORS error. Cross-origin `/v1/consent/init` requests pass overrides and experiment arms in the query string without cookies, avoiding an `OPTIONS` preflight; saves include cookies and require the trusted origin.

Requests to `/v1/consent/records`, `/v1/consent/opt-outs` and
`/v1/consent/opt-outs/lift` pass `keepalive: true` to `fetch` when their UTF-8
body is at most 32 KiB, so a revocation reload or tab close does not cancel
them. Larger bodies go out without `keepalive`, and any request the browser
rejects or drops stays in the localStorage queue for replay on the next page.
To the backend, a keepalive request is an ordinary `POST` request and needs no
server-side changes.

## Manifest

`manifest()` from `@inth/sdk` resolves policies in the browser from your project's public manifest. With no options, it uses the build snapshot and project URL from `consentManifest()`. Without a snapshot, it fetches `${projectUrl}/v1/consent/manifest` once and falls back to `/v1/consent/init` with a warning if unavailable:

<include src="../../shared/examples/javascript/transport-manifest.mdx" />

| Option | Behavior |
| --- | --- |
| `manifestUrl` | Runtime manifest URL. Ignores the build snapshot; derives `projectUrl` when ending in `/v1/consent/manifest`. |
| `snapshot` | Inlined manifest object with zero manifest requests. Defaults to the build snapshot unless `manifestUrl` is set. |
| `source` | `'runtime'` ignores the build snapshot and fetches `/v1/consent/manifest` at runtime. Mutually exclusive with `snapshot`. |
| `projectUrl` | Save destination. Defaults to the build's project URL, or the base of `manifestUrl`. Pass `''` for the current origin. |
| `inputs` | `{ country, region }` known ahead of time, such as edge-injected values. |
| `geoUrl` | Same-origin endpoint returning `{ country, region }`, queried when the policy needs a location. |
| `initFallback` | Set `false` to resolve for an unknown location instead of calling `/v1/consent/init`. Defaults to `true`. |
| `fetch` | Custom `fetch` implementation. |

When rules vary by region and neither `inputs` nor `geoUrl` supplies a country, the transport calls `/v1/consent/init` to match the visitor's region. Regional rules with identical banners resolve locally when the manifest has a default rule and region fallback. Unknown-location IAB policies and pages with IAB GPP, via `gpp`, `<ConsentGPP>`, `mountGPP()`, or the script tag without `gpp: false`, still call `/v1/consent/init`. Check ahead of time with `manifestNeedsLocation(manifest)` from `@inth/sdk`.

The browser bundle includes English base copy and lazy-loads other languages before applying manifest translations. Without location inputs, `getSnapshot().location` and `useLocation()` report `null` for country and region.

Server code uses `createV1ManifestTransport` from `@inth/sdk/transports/manifest` with all languages bundled. Browser code uses `manifest()` or `createBrowserManifestTransport` from `@inth/sdk/transports/manifest-browser`.

## Testing

`testing()` from `@inth/sdk/testing` resolves policies locally with zero network requests and requires no `projectUrl`. It throws in production builds so test configurations never ship live.

{/* example: fragment */}

```ts title="src/consent.test.ts"
import { init } from '@inth/sdk';
import { policyRulePresets } from '@inth/sdk/engine';
import { testing } from '@inth/sdk/testing';

init({
	mode: testing({
		policy: [policyRulePresets.europeOptIn(), policyRulePresets.worldNone()],
	}),
	overrides: { country: 'DE' },
});
```

| Option | Default | Behavior |
| --- | --- | --- |
| `policy` | Recommended rules | A `PolicyRule` or array of rules resolved instead of the recommended pack. |
| `iab` | Matches `iab` config | Resolves the IAB TCF variant of the recommended pack. |

The recommended pack uses opt-in for Europe, the UK, Quebec, and unknown locations, opt-out for US states with privacy laws, and no prompt elsewhere. Pass `overrides.country` to test a specific region. See [policies](/docs/concepts/policies) for all presets, or load `inth.testing.js` with `data-policy` on pages without a bundler; see [modes](/docs/concepts/modes#testing).

## Check it works

1. In hosted mode, DevTools Network shows one `/v1/consent/init` request per fresh visit and a `POST` to `/v1/consent/records` after a choice.
2. With a build-time manifest, DevTools Network shows zero `/v1/consent/manifest` requests; with runtime manifest mode, it shows one `/v1/consent/manifest` request. Neither calls `/v1/consent/init` unless the policy needs a location the page did not supply.
3. With `testing()`, DevTools Network shows zero Inth requests and saved choices survive a reload.
