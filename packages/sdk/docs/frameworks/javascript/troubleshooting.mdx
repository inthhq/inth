Diagnose and fix common issues when running `@inth/sdk` or
`@inth/sdk/runtime` in a bundled JavaScript app.

## Why do scripts load twice or before consent?

**Check.** Look for a leftover vendor snippet in `index.html`, a second
`init()` call, or a manual script loader attached to a kernel that
`@inth/sdk` or `createConsentRuntime` already owns.

**Fix.** Call `init()` or create the runtime once in your browser entry point
and register every vendor through its `scripts` array.

## Why does the page reload when a visitor saves?

**Check.** Withdrawing a previously granted category triggers a reload so
already-running vendor code stops. Granting categories never reloads.

**Fix.** Pass `reloadOnConsentRevoked: false` only if every vendor stops
itself through its own consent API; see
[when a visitor withdraws permission](/docs/frameworks/javascript/scripts#when-a-visitor-withdraws-permission).

## Why is my custom banner empty?

**Check.** Confirm you subscribed before calling `runtime.start()`, wait for
`resolution.status === 'matched'`, and handle `promptRequirement.kind` values
`'choice'` and `'notice'`.

**Fix.** Render strictly from the snapshot; see
[what your UI must handle](/docs/frameworks/javascript/headless#what-your-ui-must-handle).

## Why does /init fail with a CORS or CSP error?

**Check.** A CORS error means your origin is missing from your Inth project's
trusted origins. A CSP error means `connect-src` blocks your project origin.

**Fix.** Add the exact origin (including port in development) to trusted
origins in Inth, and allow your project origin in `connect-src`; see
[Content Security Policy](/docs/frameworks/javascript/content-security-policy).

## Why does a gated script in my HTML never run?

**Check.** When `nonce` is set, `@inth/sdk` executes only
`<script type="text/plain" data-inth-category>` tags carrying the same
`nonce` and marks others `data-inth-activated="untrusted"`.

**Fix.** Stamp the per-response `nonce` on every gated tag, including tags
inserted later; see
[Content Security Policy](/docs/frameworks/javascript/content-security-policy).

## Why is the stock banner unstyled?

**Check.** Your Content Security Policy `style-src` blocks the `<style>`
element injected by the stock UI.

**Fix.** Pass the `style-src` nonce via `nonce`, or import
`@inth/sdk/styles.css` with `ui: { shadow: false, styles: false }`; see
[allow the stock UI's styles](/docs/frameworks/javascript/content-security-policy#allow-the-stock-uis-styles).

## Why does a fetch return status 451?

**Check.** A
[network blocker](/docs/frameworks/javascript/modules/network-blocker) rule
matched the request while its category is denied (Console logs
`[inth] blocked` with the rule ID).

**Fix.** Adjust the rule's `domain` or `pathIncludes` if the request should
not match.

## Inspect the active policy

Pass `consent.kernel`, `runtime.kernel` or a manual kernel to this helper to
log policy resolution and permission updates without recording consent:

```ts title="src/observe-consent-policy.ts"
import type { ConsentKernel } from '@inth/sdk/engine';

export function observeConsentPolicy(kernel: ConsentKernel) {
	const report = () => {
		const snapshot = kernel.getSnapshot();
		const resolution = snapshot.resolution;

		console.log({
			status: resolution.status,
			policy: resolution.status === 'matched' ? resolution.policy.id : null,
			prompt: snapshot.promptRequirement,
			permissions: snapshot.effectivePermissions,
			location: snapshot.location,
			privacySignals: snapshot.privacySignals,
		});
	};

	report();
	return kernel.subscribe(report);
}
```

Call the returned unsubscribe function on teardown. In production code, read
`kernel.getSnapshot().effectivePermissions` right before running an optional
feature.
