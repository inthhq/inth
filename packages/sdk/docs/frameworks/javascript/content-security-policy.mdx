Allow Inth API requests, stock UI styles, vendor scripts and gated embeds
under a strict Content Security Policy in a bundled JavaScript app.

## What Inth needs from your policy

Because `@inth/sdk` ships inside your app bundle, `script-src` already covers
it. Add rules for the remaining resources:

| Directive | Allow | Why |
| --- | --- | --- |
| `connect-src` | Your Inth project origin (`https://your-project.inth.app`) | `/v1/consent/init`, `/v1/consent/records`, and `/v1/consent/manifest` in manifest mode. |
| `script-src` | Vendor script origins or a per-response nonce | Dynamically inserted `scripts` and gated `text/plain` tags. |
| `style-src` | A nonce or your bundled CSS origin | Stock UI `<style>` element or external stylesheet. |
| `frame-src` | Embed origins | Iframes unlocked by the iframe blocker. |
| `img-src`, `connect-src` | Vendor telemetry origins | Requests sent by vendors after consent. |

A missing `connect-src` entry blocks `/v1/consent/init`, preventing the banner from
appearing.

## Put a nonce on created scripts and styles

Pass the per-response `nonce` to `init()`, `createConsentClient()` or
`createConsentRuntime()`. Inth applies it to every `<script>` inserted by the
script loader and to the stock UI's `<style>` element:

{/* example: fragment */}

```ts
init({ mode: manifest(), scripts, nonce });
```

A script-level `nonce` overrides the global one. With `nonce` configured,
`@inth/sdk` executes only `<script type="text/plain" data-inth-category>`
tags carrying the exact same `nonce`, marking others
`data-inth-activated="untrusted"`. Pass `{ nonce }` as the third argument to
`activateGatedScripts(snapshot, root, { nonce })` for the same check.

## Allow the stock UI's styles

By default, stock UI styles, theme tokens and `ui.css` inject into a
nonced `<style>` element inside the shadow root, working with
`style-src 'nonce-...'` without `'unsafe-inline'`.

Without per-response nonces, render into light DOM and import the stylesheet
so your bundler emits a CSS file:

{/* example: fragment */}

```ts
import '@inth/sdk/styles.css';

init({ mode: manifest(), ui: { shadow: false, styles: false } });
```

With `styles: false` and no `theme` or `css`, Inth injects no `<style>`
element (also import `@inth/sdk/iab/styles.css` under IAB). Headless entries
and `createConsentRuntime` inject no styles; keep DevTools out of production
builds.

## Check it works

1. Deploy `Content-Security-Policy-Report-Only` first and inspect the
   Console.
2. Confirm no CSP errors fire for `/v1/consent/init`, `/v1/consent/records` or banner styles.
3. Grant each category and verify vendor scripts load without violations.
4. Switch to enforcing `Content-Security-Policy` and re-test.
