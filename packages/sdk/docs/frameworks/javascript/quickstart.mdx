Add a consent banner, preference dialog and script gating to a Vite or
bundled JavaScript app. Your build bundles the policy manifest, and analytics
wait until consent allows them.

<Prompt title="Add Inth consent to this JavaScript app" description="Paste into Claude Code, Codex, Cursor or another coding agent at the root of your app.">
  Add Inth consent management to this JavaScript app.

  1. Check that the app uses Vite or another JS bundler without a UI framework adapter (React, Vue, Svelte, Astro, Angular). If it uses a UI framework, stop and tell me.
  2. Install `@inth/sdk` and `@inth/integrations`. Read `node_modules/@inth/sdk/AGENTS.md`, then follow the JavaScript quickstart it links to, in order. Do not guess the API from memory.
  3. Set `VITE_INTH_PROJECT_URL` in `.env`. Ask me for my Inth project URL. `VITE_INTH_PROJECT_URL` wins over any legacy `VITE_C15T_BACKEND_URL`.
  4. Add `consentManifest()` from `@inth/sdk/build` to `plugins` in `vite.config.ts`. Add nothing to `.gitignore`.
  5. In the browser entry file (such as `src/main.ts`), call `init({ mode: manifest(), scripts })` from `@inth/sdk`, moving every analytics and marketing script into `scripts` using `@inth/integrations` helpers. Remove duplicate loaders from `index.html`.
  6. Gate third-party iframes with `data-src` and `data-category`, and add `<a href="#inth-preferences">Privacy settings</a>` in the footer.
  7. Run a production build and preview it in a private browser window. Confirm no vendor request fires before consent, rejecting survives a reload, and granting analytics from Privacy settings loads the vendor.

  Then list the files you changed, any script still outside consent, and how you checked the requests.
</Prompt>

## Prerequisites

- A JavaScript app built with Vite or another bundler. For a UI framework or
  plain HTML site, see the [framework list](/docs/frameworks).
- An [Inth project](https://inth.com/dashboard/sign-up?framework=javascript)
  with your app's origin in trusted origins.

## Install the SDK

<CommandTabs command="@inth/sdk @inth/integrations" mode="install" />

`@inth/sdk` ships the Vite plugin at `@inth/sdk/build` and mounts styles in a
shadow root, so no stylesheet import is needed.

## Set the project URL

Add your public Inth project URL to `.env` and your host's build settings:

```sh title=".env"
VITE_INTH_PROJECT_URL=https://your-project.inth.app
```

Vite reads this at build time, so rebuild after changes. `VITE_INTH_PROJECT_URL`
wins over any legacy `VITE_C15T_BACKEND_URL`, which is read as a fallback if
`VITE_INTH_PROJECT_URL` is unset.

`vite build` and `vite dev` fetch `/v1/consent/manifest` and expose `snapshot` from

Inth (pass `hosted()` instead to fetch `/v1/consent/init` on each visit). Replace
`phc_your_project_key` with your key (add `region: 'us'` for US cloud), keep
`cookieless_mode: 'never'`, and remove duplicate PostHog tags from
`index.html`. Withdrawing an allowed category reloads the page; see
[scripts](/docs/frameworks/javascript/scripts).

## Check it works

Build and preview in a private window with DevTools Network open:

1. Under an opt-in policy, the banner appears, no `posthog` requests fire,
   and the YouTube iframe has no `src`.
2. Click **Reject All** and reload. The banner stays closed and PostHog does
   not load.
3. Click **Privacy settings**, turn on **Analytics** (`measurement`) and
   save. PostHog and YouTube load.
4. Turn **Analytics** off and save. The page reloads and neither loads again.

If no banner appears, check
[why is there no banner](/docs/guides/troubleshooting#why-is-there-no-banner)
and [verify consent](/docs/guides/verify-consent).
