Hold third-party iframes until their consent category is allowed using
`data-src`, `data-category` and the iframe blocker included in `@inth/sdk`
and `createConsentRuntime`.

## Gate an embed

Move the embed URL from `src` to `data-src` and set `data-category`:

<include src="../../../shared/examples/javascript/embed.mdx" />

Without `src`, the browser sends no request before consent. Inth sets `src`
when the category is allowed and clears it on withdrawal. Both `@inth/sdk`
and `createConsentRuntime` enable the blocker by default.

## Attributes

| Attribute | What it does |
| --- | --- |
| `data-src` | Embed URL (`http:` and `https:` only; relative URLs resolve against the page). |
| `data-category` | Category name (unknown names warn and stay blocked). |
| `data-vendor` | Optional vendor slug for vendor-level consent. |
| `data-inth-paused` | Set by Inth when stripping an initial `src`. |

Always author gated iframes with `data-src` instead of `src` so the browser
cannot start loading before the blocker runs.

## Iframes your code adds

The blocker observes `document` for dynamically added iframes and attribute
changes, working across client routers such as Turbo and script-in-`<head>`
setups. Alternatively, create iframes conditionally from
`snapshot.effectivePermissions` as shown in the
[headless guide](/docs/frameworks/javascript/headless).

## Show a placeholder

Hide blocked iframes and show your own placeholder with CSS, wiring a button
to `consent.openDialog()`:

{/* example: fragment */}

```css
iframe[data-category]:not([src]) { display: none; }
iframe[src] + .placeholder { display: none; }
```

## Configure it

| `iframeBlocker` value | Effect |
| --- | --- |
| omitted or `{}` | Automatically gates every iframe with `data-category` or `data-vendor`. |
| `{ disableAutomaticBlocking: true }` | Updates iframes only when you call `processIframes()`; see [check iframes on demand](#check-iframes-on-demand). |
| `false` | Disables the blocker (`data-src` iframes never load). |

Categories on gated iframes are added to the preference dialog automatically.

## Check iframes on demand

With `iframeBlocker: { disableAutomaticBlocking: true }`, call
`processIframes()` after inserting iframes and on consent updates:

{/* example: fragment */}

```ts
consent.on('consent', () => consent.processIframes());
```

Available as `consent.processIframes()` on `@inth/sdk` and
`runtime.processIframes()` on `createConsentRuntime`.

## Check it works

1. Before choosing, confirm the iframe has no `src` and Network shows no
   request to the embed host.
2. Allow the category and verify `src` populates and the embed loads.
3. Insert a `data-src` iframe from Console after load and confirm it follows
   active permissions.
