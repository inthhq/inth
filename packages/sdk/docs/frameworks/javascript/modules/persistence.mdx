Control how Inth persists consent records across reloads, subdomains and
open browser tabs in a JavaScript app.

## Where choices are stored

Persistence writes recorded choices to a first-party cookie (readable by SSR
servers) and `localStorage`, restoring them synchronously on page load. Both
`@inth/sdk` and `createConsentRuntime` enable persistence by default.

| Stored item | Default name |
| --- | --- |
| Category choice | `inth` cookie and `localStorage` key (reads legacy `c15t` as fallback) |
| Notice acknowledgement | `inth-notice` |
| Vendor choice | `inth-vendors` |
| Queued unsent saves | Separate `localStorage` queue |

## The subject ID

Every session receives a subject ID (`sub_...`) in `snapshot.subject.subjectId`:

- Before a visitor acts, the ID lives only in memory so Inth writes zero
  cookies or storage before consent.
- The first choice, vendor switch or notice dismissal persists the ID with
  that record.
- `clear()` deletes records while keeping the ID in memory; call
  `kernel.set.subjectId(null)` to generate a new ID.
- Across multiple open tabs, tabs that have not saved adopt the ID saved by
  another tab and emit `subject:resolved` with `previousSubjectId`.

Legacy `c15t-sid` entries from earlier releases are cleaned up on startup
(migrating their ID first if an older stored record lacked one).

## When records are read and written

Stored records hydrate synchronously on startup so returning visitors never
see a banner flash. The writer/reconciler chunk lazy-loads during idle time
once a banner or dialog appears (or immediately on first save/reconcile).
Until that chunk loads, saves wait to persist before sending the network
request or triggering a revocation reload, retrying after 1, 4 and 16 seconds
if offline. `clear()` runs synchronously without waiting for the chunk.

## Name, domain and lifetime

Configure cookie naming, subdomain sharing and expiry with `storageConfig`:

| Option | Default | What it does |
| --- | --- | --- |
| `storageKey` | `'inth'` | Cookie and `localStorage` key prefix. |
| `crossSubdomain` | `false` | Sets the cookie on the root domain so subdomains share choices. |
| `defaultDomain` | current host | Explicit cookie domain (such as `'.example.com'`); overrides `crossSubdomain`. |
| `defaultExpiryDays` | `365` | Cookie lifetime in days (policy validity still governs expiration). |

Pass identical `storageConfig` across every subdomain sharing the cookie:

{/* example: fragment */}

```ts
storageConfig: { crossSubdomain: true },
```

## Keep open tabs in step

Same-origin tabs sync immediately via `localStorage` `storage` events.
Subdomain tabs sharing only the cookie reconcile on visibility or focus
change. Call `runtime.reconcileStorage()` (or
`client.runtime.reconcileStorage()`) to reconcile manually, or set
`persistence: { sync: false }` to disable automatic syncing. See
[keep open tabs in step](/docs/concepts/consent-state#keep-open-tabs-in-step).

## Turn it off

Set `persistence: false` on `init()` or `createConsentRuntime()` to keep
choices and subject IDs in memory only (every reload starts fresh).

## Attach it to your own kernel

Attach persistence before `commands.init()` on a manual kernel:

`createPersistence({ kernel, storageConfig?, skipHydration?, sync? })`
returns:

| Member | What it does |
| --- | --- |
| `hydrate()` | Re-reads storage; returns whether any record was found. |
| `reconcile()` | Merges changes stored by another tab or runtime; returns whether anything changed. |
| `clear()` | Deletes all consent records and resets kernel records (keeps `subjectId` in memory). |
| `dispose()` | Stops writing and removes tab listeners without deleting stored records. |

Pass `skipHydration: true` when SSR already seeded `initialRecords`.

## Check it works

1. Open DevTools Application on a fresh visit: the banner shows and no `inth`
   cookie or `localStorage` key exists yet.
2. Click **Accept All**: both `inth` cookie and `localStorage` entry appear.
3. Reload: the banner stays closed.
4. Open a second tab, reject all there, and switch back: the first tab
   reflects the rejection.
