Customize the stock banner, preference dialog and floating trigger mounted by
`init()` from `@inth/sdk`.

## Pick the right option

| Change | Option |
| --- | --- |
| Colors, radius, fonts, spacing | `ui.theme` |
| One part's CSS | `ui.theme.slots` with `ui.stylesheetUrls`, `::part()`, or `ui.css` |
| Your own stylesheet | `ui: { shadow: false }` |
| Banner shape, position, button layout, blocking | `presentation.prompt` |
| Banner text | `ui.banner` |
| Wording and languages everywhere | `i18n`; see [translations](/docs/frameworks/javascript/translations) |
| Legal links | `legalLinks` with `ui.banner.legalLinks` and `ui.dialog.legalLinks` |
| Floating reopen button | `ui.trigger` |
| Custom markup | [Headless](/docs/frameworks/javascript/headless) |

See the [design gallery](/docs/customization/recipes) for five ready banner
designs.

## Change colors, radius and fonts

Pass design tokens under `ui.theme`:

The banner, dialog and trigger share the same token object documented in
[theme tokens](/docs/customization/tokens). `ui.colorScheme` selects
`'light'`, `'dark'`, `'system'` (default) or `null` (follows a `dark` or
`inth-dark` class on `<html>`). See [dark mode](/docs/customization/dark-mode).

## Add CSS inside the shadow root

By default the stock UI renders inside a shadow root with its own stylesheet.
Append targeted rules after the bundled stylesheet with `ui.css`:

{/* example: fragment */}

```ts
ui: {
  css: '[data-testid="consent-banner-card"] { border: 3px solid #6943a3; }',
},
```

Target parts via `data-testid` (`consent-banner-card`,
`consent-banner-accept-button`, `consent-dialog-root`,
`consent-widget-switch-measurement`, `consent-dialog-trigger`). To use
classes from an external stylesheet such as Tailwind or CSS Modules, assign
classes in `ui.theme.slots` with `ui.stylesheetUrls`, or style parts from
page CSS via `[data-inth-ui]::part(consentBannerCard)`. See
[class names and CSS-in-JS](/docs/customization/class-names),
[Tailwind CSS](/docs/customization/tailwind) and
[component parts](/docs/customization/slots).

## Use your own stylesheet

Set `ui: { shadow: false }` to render into the page DOM. To bundle the
stylesheet instead of injecting a `<style>` element, import it and set
`styles: false`:

{/* example: fragment */}

```ts
import '@inth/sdk/styles.css';

const consent = init({
	mode: manifest(),
	ui: { shadow: false, styles: false },
});
```

With Tailwind 3, add `@inth/sdk/postcss-tailwind3` before `tailwindcss` in
your PostCSS config (`{ '@inth/sdk/postcss-tailwind3': {}, tailwindcss: {} }`)
so Tailwind 3 does not drop rules or reset buttons. Set
`ui: { shadow: false, noStyle: true }` to render unstyled markup keeping all
`data-testid` hooks.

## Change the banner's layout

Set the container and the button arrangement under `presentation.prompt`:

{/* example: fragment */}

```ts
presentation: {
  prompt: {
    container: { type: 'banner', edge: 'bottom' },
    uiProfile: 'balanced',
  },
},
```

<import src="../../shared/browser/client-options.mdx#containers" />

`layout`, `primaryActions`, `direction`, `uiProfile` and `blocking` also work
on `presentation.preferences` (plus `defaults` for initial switch states).
Policy requirements always win over conflicting layout options.

## Show legal links

Define URLs once and select which appear on each surface:

{/* example: fragment */}

```ts
legalLinks: {
  privacyPolicy: { href: '/privacy' },
  cookiePolicy: { href: '/cookies' },
},
ui: {
  banner: { legalLinks: ['privacyPolicy', 'cookiePolicy'] },
  dialog: { legalLinks: ['privacyPolicy'] },
},
```

## Add the floating trigger

Set `ui: { trigger: true }` to display a draggable corner button that reopens
the dialog. When [DevTools](/docs/frameworks/javascript/dev-tools) is
mounted, the trigger combines both controls in one corner.

## Mount the UI somewhere else

Set `ui.container` to an element or CSS selector instead of `document.body`.
Call `consent.mountUI(options)` to remount the UI with updated options (such
as after switching themes); pass every `ui` option you want to keep because
it replaces the prior `ui` config:

{/* example: fragment */}

```ts
consent.mountUI({ colorScheme: 'dark', theme });
```

## Keyboard and screen readers

Blocking banners and the dialog trap focus and lock page scroll. Escape
closes the dialog without saving. Surfaces set `lang` and `dir` from the
resolved language and follow `prefers-reduced-motion` (override via
`ui.disableAnimation` or per-surface `disableAnimation`); see
[motion and animation](/docs/customization/motion).

## Check it works

1. Open the app in a private window and verify tokens and layout apply.
2. Open the dialog and confirm shared tokens and legal links render.
3. Toggle OS light/dark mode and verify `colorScheme: 'system'` updates.
