## Add rules

Use the network blocker for browser `fetch` and `XMLHttpRequest` beacons that
bypass script loading. Register vendor SDKs through
[`scripts`](/docs/frameworks/next/scripts) first so they never execute before
consent.

Declare `networkBlocker` in `inth.config.ts` alongside your `scripts` (it can
include `onRequestBlocked` functions because the config bundles into the
browser):

{/* example: fragment */}

```ts title="inth.config.ts"
import { defineConsentConfig } from '@inth/nextjs';

export default defineConsentConfig({
	networkBlocker: {
		rules: [
			{
				id: 'google-analytics',
				domain: 'google-analytics.com',
				category: 'measurement',
			},
			{
				id: 'meta-pixel',
				domain: 'facebook.com',
				pathIncludes: '/tr',
				category: 'marketing',
			},
		],
	},
});
```

Blocking starts when `InthProvider` renders in the browser, so keep page content
inside it. Module top-level requests evaluated before `InthProvider` and
server-side requests in Server Components, Route Handlers or
`getServerSideProps` are not intercepted.

## Verify the blocked requests

Open your production build in a private window with DevTools Network open under
an opt-in policy:

1. Confirm requests matching a rule do not appear in Network and log as blocked
   in the console.
2. Grant the rule's category and save: matching requests succeed.
3. Reject, reload and confirm those requests stay blocked.
