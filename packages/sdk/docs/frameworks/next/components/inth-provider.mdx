## Mount one root

`@inth/nextjs`'s `InthProvider` wraps `@inth/react`'s provider, reads `inth.config.ts` via
`withConsentManifest`, and connects server-resolved consent state to your app.
Mount it once in your root layout ([quickstart](/docs/frameworks/next/quickstart),
[App Router](/docs/frameworks/next/app-router)) or `pages/_app.tsx`
([Pages Router](/docs/frameworks/next/pages-router)) and keep it mounted across
navigation. Server Components pass only `state`.

## Props

| Prop | Purpose |
| --- | --- |
| `state` | Resolved `ConsentState` or pending promise from `resolveConsent()`, or `pageProps.consent` from `withConsentProps`. Omit for browser-only resolution. |
| `config` | Explicit `defineConsentConfig` object when `inth.config.ts` is unavailable (for example in tests). Cannot be passed from a Server Component if it contains functions. |
| `scripts` | Consent-managed script configurations. |
| `vendors` | Per-vendor toggles merged with backend declarations ([Vendor consent](/docs/frameworks/next/vendor-consent)). |
| `clearOnRevocation` | Cookies and Web Storage keys cleared on denial. Initial-only ([Clear on revocation](/docs/frameworks/next/clear-on-revocation)). |
| `scriptLoader` | Script-loader options (such as `{ serverStart: false }`). |
| `networkBlocker` | [Network blocker](/docs/frameworks/next/network-blocker) rules, or `false` to disable. |
| `persistence` | Browser persistence options (defaults to `true`). |
| `options` | Provider options such as `nonce`, `callbacks`, `theme`, `i18n` and `mode`. |

Props override matching keys in `inth.config.ts`. `options` merges key by key
and `options.callbacks` merges callback by callback, so passing
`options={{ nonce }}` keeps your config's callbacks and other options.

### Which mode does InthProvider use?

`InthProvider` uses `mode` from `inth.config.ts` (`manifest()` by default) or
`options.mode`, lazy-loading only that mode's code:

- `manifest()`: applies `state` with no browser fetch, or calls
  `${routePrefix}/v1/consent/init` (else `${projectUrl}/v1/consent/init`) when initializing in the
  browser.
- `manifest({ resolve: 'browser' })`: lazy-loads the browser resolver and
  fetches `${routePrefix}/v1/consent/manifest` (else `${projectUrl}/v1/consent/manifest`).
- `hosted()`: calls `${projectUrl}/v1/consent/init` when browser initialization is needed.
- `testing()`: resolves local test rules in the browser without saving to Inth
  ([testing configuration](/docs/frameworks/next/data-fetching-reference#testing-configuration)).

Every mode except `testing()` posts saves to `${projectUrl}/v1/consent/records`. Without
a project URL in `inth.config.ts`, `NEXT_PUBLIC_INTH_PROJECT_URL` or
`NEXT_PUBLIC_C15T_BACKEND_URL`, `InthProvider` throws. Use mode factories from
`@inth/nextjs` (not `@inth/react` transports, which bundle into first-load JS).
See [consent modes](/docs/concepts/modes).

## Provider options

Pass `scripts`, `vendors`, `clearOnRevocation`, `persistence` and
`networkBlocker` at the top level, not inside `options`.

| Option | Purpose |
| --- | --- |
| `mode` | Overrides `mode` from `inth.config.ts`. |
| `callbacks` | `onChoiceRecorded`, `onPermissionsChanged`, `onError`, `onBeforeConsentRevocationReload`. |
| `theme`, `components` | Action button styles and slot overrides (tokens render via `ConsentTheme`). |
| `presentation` | Default banner and dialog layout options. |
| `experiment` | Banner A/B test arm read once at mount ([Banner experiments](/docs/guides/banner-experiments)). |
| `preloadDialog` | Deferral strategy for `ConsentDialog`: `'idle'` (default) or `'intent'` ([ConsentDialog](/docs/frameworks/next/components/consent-dialog#behavior)). |
| `i18n` | Language overrides and message dictionary. |
| `storageConfig` | Browser cookie/storage configuration (`storageKey` must match `resolveConsent` `cookieName`). |
| `enabled` | Set `false` only to bypass consent enforcement completely (never use to hide errors in production). |
| `reloadOnConsentRevoked` | Reload page when a save or one-click opt-out revokes a granted category or vendor. Privacy signals and backend-synced opt-outs do not reload. Defaults to `true`. |

## Managing an external runtime

Keep `InthProvider` from `@inth/nextjs` for standard Next.js apps (both
[browser initialization](/docs/frameworks/next/client-side) and
[server rendering](/docs/frameworks/next/rendering)). Import `InthProvider`
from `@inth/react` directly only when managing your own external `runtime`
lifecycle.

## Reload after revocation

Removing a `<script>` tag cannot stop vendor listeners or timers already
running. When a visitor saves a choice that revokes a granted category or
vendor, `InthProvider` waits for the save to settle, calls
`onBeforeConsentRevocationReload`, and reloads the page. Expiry, policy updates
and privacy signals do not reload. Set `options.reloadOnConsentRevoked: false`
only when every gated vendor stops cleanly via its own opt-out API.

## Clear data when consent is denied

Declare `clearOnRevocation` at the top level of `inth.config.ts` or as a prop
on `InthProvider` (if using `@inth/react`'s `InthProvider` directly, pass it
inside `options`). Cleanup runs in the browser after policy resolution and is
initial-only. See [Clear on revocation](/docs/frameworks/next/clear-on-revocation).
