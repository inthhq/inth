## Add the trigger next to the banner

`ConsentDialogTrigger` is a draggable floating button that opens
`ConsentDialog`. Mount it inside `InthProvider` from your
[quickstart](/docs/frameworks/next/quickstart) alongside the banner and dialog:

{/* example: fragment */}

```tsx title="components/privacy-trigger.tsx"
'use client';

import { ConsentDialogTrigger } from '@inth/nextjs';

export function PrivacyTrigger() {
	return <ConsentDialogTrigger showWhen="after-prompt" />;
}
```

`showWhen="after-prompt"` hides the trigger until the visitor answers the
banner (default is `always`). The trigger hides automatically when no rule has
resolved or under `model: 'none'` (unless `rights: ['preferences']` is set),
and carries `data-inth-rights` and `data-right` (`"opt-out"` or
`"preferences"`) for styling.

## Configurable toolbar

Use `ConsentDialogTriggerToolbar` inside a `'use client'` component to place
app-owned actions beside the built-in preferences trigger:

{/* example: fragment */}

```tsx title="components/site-toolbar.tsx (partial)"
import { ConsentDialogTriggerToolbar } from '@inth/nextjs';

<ConsentDialogTriggerToolbar
	ariaLabel="Site controls"
	actions={[
		{
			id: 'theme',
			label: isDark ? 'Switch to light theme' : 'Switch to dark theme',
			icon: isDark ? <SunIcon /> : <MoonIcon />,
			pressed: isDark,
			onSelect: toggleColorScheme,
		},
		{
			id: 'support',
			label: 'Open support chat',
			icon: <ChatIcon />,
			onSelect: openSupportChat,
		},
	]}
	preferences={{ icon: 'fingerprint', label: 'Manage privacy settings' }}
/>;
```

App-owned `actions` always render regardless of policy state, while `showWhen`
(`'always'`, `'after-prompt'` or `'never'`) controls only the built-in
preferences button. The preferences button uses "Do not sell or share my data"
under opt-out rules and "Manage preferences" otherwise (override with
`preferences.label`). Set `orientation="vertical"` to stack actions vertically:

```tsx
<ConsentDialogTriggerToolbar orientation="vertical" actions={toolbarActions} />;
```

### Toolbar styling

Override toolbar slots in `options.components.trigger` (`toolbar`,
`toolbarItem`, `toolbarIcon`), pass `className` directly on the toolbar or
individual actions, or pass `noStyle` and style via `data-corner`,
`data-dragging` and `data-snapping`:

```ts
const triggerSlots = {
	toolbar: { className: 'my-toolbar' },
	toolbarItem: { className: 'my-toolbar-item' },
	toolbarIcon: { className: 'my-toolbar-icon' },
};

// In options.components:
// trigger: triggerSlots
```
