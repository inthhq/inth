## Render the banner inside `InthProvider`

Mount one `ConsentBanner` inside `InthProvider` in your
[App Router](/docs/frameworks/next/app-router) root layout or
[Pages Router](/docs/frameworks/next/pages-router) `pages/_app.tsx`:

<include src="../../../shared/examples/nextjs/quickstart-layout.mdx" />

Server Components can render `ConsentBanner` directly when passing serializable
props; move function props like `renderAction` into a `'use client'` component.

With the default streamed layout, the banner arrives in a later chunk before
hydration (disable with `options={{ streamBanner: false }}`). With the
[awaited layout](/docs/frameworks/next/app-router#render-the-banner-in-the-server-html)
or Pages Router `getServerSideProps`, it ships in the initial server HTML:

- **`choice` prompt:** shows equal-prominence Reject and Accept actions plus
  Customize when offered by the rule (or a "Manage preferences" button if
  Customize is omitted).
- **`notice` prompt:** shows an "OK" button and an underlined
  "Do Not Sell or Share My Personal Information" button that opens preferences. Notices never
  lock scroll or trap focus, and acknowledging records a dismissal without
  changing permissions.
- **`prompt: 'none'` or unresolved policy:** renders nothing. Opt-out rules
  with `prompt: 'none'` keep preferences reachable; `model: 'none'` hides all
  surfaces unless the rule adds `rights: ['preferences']`.

## Per-policy buttons

Read `usePolicyRule()` in a Client Component to override `layout`,
`primaryButton` or `variant` per policy ID:

{/* example: fragment */}

```tsx title="components/regional-banner.tsx"
'use client';

import { ConsentBanner, usePolicyRule } from '@inth/nextjs';
import type { ConsentBannerProps } from '@inth/nextjs';

const banners: Record<
	string,
	Pick<ConsentBannerProps, 'layout' | 'primaryButton' | 'variant'>
> = {
	europe_opt_in: {
		layout: [['reject', 'accept'], 'customize'],
		primaryButton: 'customize',
	},
	us_privacy_states: {
		layout: ['dismiss'],
		primaryButton: 'dismiss',
		variant: 'bar',
	},
};

export function RegionalBanner() {
	const policy = usePolicyRule();
	return <ConsentBanner {...(policy ? banners[policy.id] : undefined)} />;
}
```

Required actions omitted from `layout` are restored automatically, and Accept
and Reject keep equivalent default prominence. Style the primary action via
`options.theme` in `inth.config.ts`:

```ts
const theme = {
	colors: { primary: '#2f6f4e', primaryHover: '#24563c' },
	consentActions: { primary: { variant: 'primary', mode: 'filled' } },
} as const;
```

See [Customize](/docs/frameworks/next/customize) for tokens and slots, and
[Policies](/docs/concepts/policies) for rule IDs.

## Variants

Set `variant` and `position` on `ConsentBanner` or globally via
`options.presentation.prompt` (component props win):

| Variant | Shape | Positions | Default |
| --- | --- | --- | --- |
| `floating` (default) | Corner or centered floating card | `bottom-left`, `bottom-right`, `top-left`, `top-right`, `bottom-center`, `top-center` | `bottom-left` |
| `bar` | Full-width top or bottom bar (single row at 1024px+) | `top`, `bottom` | `bottom` |
| `widget` | Compact card with smaller type | `bottom-left`, `bottom-right`, `top-left`, `top-right` | `bottom-right` |
| `wall` | Centered modal card over a blocking backdrop | `center` | `center` |

Invalid positions fall back to the variant default (`invalid-position`
diagnostic in dev). `blocking` controls backdrop, scroll lock and focus trap
together (replacing deprecated `scrollLock`/`trapFocus`): choice `wall` always
blocks (`role="dialog"`, `aria-modal="true"`), while notices never block
(asking for a notice `wall` falls back to `floating`). Exported types:
`PromptVariant`, `PromptPosition` and `useConsentBannerSurface()`.

## Composition

Compose custom layouts inside a `'use client'` file with `ConsentBanner.<Part>`:

{/* example: fragment */}

```tsx title="components/compact-banner.tsx"
'use client';

import { ConsentBanner } from '@inth/nextjs';

export function CompactBanner() {
	return (
		<ConsentBanner.Root>
			<ConsentBanner.Card>
				<ConsentBanner.Header>
					<ConsentBanner.Title />
					<ConsentBanner.Description />
				</ConsentBanner.Header>
				<ConsentBanner.PolicyActions />
			</ConsentBanner.Card>
		</ConsentBanner.Root>
	);
}
```

- `ConsentBanner.PolicyActions` renders preference links followed by policy
  action groups (pass children to replace the preference links).
- `ConsentBanner.AcceptButton`, `RejectButton`, `CustomizeButton` and
  `DismissButton` render individual actions.
- `ConsentBanner.Rights` and `ConsentBanner.RightLink` (`right="opt-out"` or
  `"preferences"`, supports `asChild`) render preference links. Under an
  `opt-out` policy, activating `right="opt-out"` follows the resolved
  `presentation.optOutLink` title: `'do-not-sell'` (the default) records the
  opt-out in one click and opens `OptOutConfirmation` (reloading first when
  that turns off a running category and `reloadOnConsentRevoked` is enabled),
  while `'privacy-choices'` and `'california-privacy-choices'` render with the
  California Privacy Protection Agency opt-out icon and open the preference
  center without recording an opt-out. Under other models it opens the
  preference center. Programmatic calls to `useOptOut()` still opt out in one
  step whatever `presentation.optOutLink` is set to.
- `useBannerCopy()` returns `title`, `description` and prompt kind for custom
  headers.

## Data attributes

Target the root element (`data-state` sits on the card) from CSS or Tailwind:

| Attribute | Values |
| --- | --- |
| `data-prompt` | `choice`, `notice` |
| `data-model` | `opt-in`, `opt-out`, `iab` |
| `data-variant` | `floating`, `bar`, `widget`, `wall` |
| `data-position` | Resolved position for the variant |
| `data-blocking` | `true` (present only while blocking) |

Action buttons carry `data-action`; right links carry `data-action="right"` and
`data-right`.
