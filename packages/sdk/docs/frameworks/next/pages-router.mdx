Set up Inth in a Next.js Pages Router app on a Next.js server. Your build
bundles your project's public policy manifest, `withConsentProps` resolves
consent in `getServerSideProps`, and static pages resolve in the browser
through a local consent API route.

## Prerequisites

- An [Inth project](https://inth.com) with your site's origin added to its
  trusted origins.
- A Next.js server. For `output: 'export'`, see
  [Static export](/docs/frameworks/next/static-export). For tests without a
  backend, see
  [testing configuration](/docs/frameworks/next/data-fetching-reference#testing-configuration).
  [Rendering and deployment](/docs/frameworks/next/rendering) compares all
  paths.
- Trusted location headers from your host for region-specific policies; see
  [Geography headers](/docs/frameworks/next/geography-headers).

## Install the SDK

<CommandTabs command="@inth/nextjs @inth/integrations" mode="install" />

## Set the project URL

Add your Inth project URL (including any path prefix) to `.env.local` and your
host's build settings:

```sh title=".env.local"
NEXT_PUBLIC_INTH_PROJECT_URL=https://your-project.inth.app
```

Next.js inlines `NEXT_PUBLIC_` variables at build time, so rebuild after
changing the URL. `NEXT_PUBLIC_INTH_PROJECT_URL` wins over any legacy
`NEXT_PUBLIC_C15T_BACKEND_URL`, which is read as a fallback if unset.

## Add the consent API route

Create a catch-all API route under `routePrefix`:

<include src="../../shared/examples/nextjs-pages-router/pages-consent-route.mdx" />

The route answers `GET /api/inth/v1/consent/init` and
`GET /api/inth/v1/consent/manifest` from the
bundled snapshot (or runtime cache), returns 404 for other paths and 405 for
non-`GET`/`HEAD` requests. Name the file `[...inth].ts`, or pass a custom
parameter name as the second argument, such as
`createPagesConsentRoute({}, 'path')` for `[...path].ts`.

## Resolve consent in getServerSideProps

Export `withConsentProps()` from `@inth/nextjs/pages` as `getServerSideProps`:

<include src="../../shared/examples/nextjs-pages-router/pages-ssr.mdx" />

It resolves consent from `inth.config.ts`, strips `undefined` fields for
Next.js serialization and passes `props.consent` so the banner renders in the
server HTML with no browser `/v1/consent/init` request.

To combine it with your own `getServerSideProps`, wrap your function:

{/* example: fragment */}

```ts title="pages/posts/[slug].tsx (partial)"
export const getServerSideProps = withConsentProps(async ({ params }) => ({
	props: { post: await loadPost(params?.slug) },
}));
```

Consent resolves in parallel with your handler, `redirect` and `notFound` pass
through unchanged, and `resolveConsent` options (such as `timeoutMs` or a
custom `cookieName` matching `storageConfig.storageKey`) go in the second
argument. Never resolve consent in `getStaticProps`, which has no visitor
request. If a runtime manifest fetch fails or exceeds `timeoutMs` (500 ms
default), the page renders without a policy and the browser retries on mount.

## Use backend init instead of the manifest

To resolve via `${projectUrl}/v1/consent/init` per visit, set `mode: hosted()` in
`inth.config.ts` and remove `routePrefix` and `pages/api/inth/[...inth].ts`.
Keep `withConsentManifest` in `next.config.ts` so the SDK finds
`inth.config.ts`; it skips the manifest download in `hosted()` mode. For a
browser-only setup, see
[Client-side initialization](/docs/frameworks/next/client-side). Same-origin
proxying with
[`proxy: true`](/docs/frameworks/next/optimization#keep-browser-consent-requests-on-your-origin)
is optional with either mode.

## Verify the setup

Run `next build` and `next start`, then open a `withConsentProps` page in a
private window with DevTools open:

1. View page source and confirm `data-testid="consent-banner-root"` is present.
2. Under an opt-in policy, confirm no PostHog request fires. Click
   **Reject All** and reload; the banner stays closed and PostHog stays blocked.
3. Open **Privacy settings** and enable **Analytics** (`measurement`). PostHog
   loads.
4. Navigate via Next.js `Link` and reopen **Privacy settings** to confirm the
   choice persists.
5. Open a static page directly and confirm it resolves the same choice through
   `/api/inth/v1/consent/init`.

Confirm `withConsentProps` pages make no `/v1/consent/init` request and saves post to
`${projectUrl}/v1/consent/records`. See [Scripts](/docs/frameworks/next/scripts) and
[Verify consent](/docs/guides/verify-consent).
