Forward visitor country, region and Global Privacy Control headers from Next.js
proxy or middleware to Server Components and Route Handlers when your host
strips platform geo headers before rendering.

## When do I need the proxy?

Inth reads visitor geography from platform headers (Cloudflare, Vercel,
CloudFront or generic proxy headers). Some hosts expose those headers in
`proxy.ts` or `middleware.ts` but strip them before Server Components and Route
Handlers run, causing `resolveConsent` and `/api/inth/v1/consent/init` to fall back to
your unknown-location rule.

Test your deployment by logging `(await headers()).get('x-vercel-ip-country')`
(or your host's equivalent) in a Server Component. If the header is already
present there, skip this page. If it is missing while present in `proxy.ts`,
add `inthProxy`.

`inthProxy` resolves country, region and GPC from incoming headers and forwards
them as `x-inth-country`, `x-inth-region` and `sec-gpc`, which take highest
precedence. It supports Next.js 15 and 16 and does not apply to a
[static export](/docs/frameworks/next/static-export).

## Add the proxy (Next.js 16)

Create `proxy.ts` at the project root (or inside `src/`):

{/* example: fragment */}

```ts title="proxy.ts"
import { inthProxy } from '@inth/nextjs/proxy';
import type { NextRequest } from 'next/server';

export function proxy(request: NextRequest) {
	return inthProxy(request);
}

export const config = {
	matcher: ['/((?!_next/static|_next/image|favicon.ico).*)'],
};
```

`inthProxy` returns `NextResponse.next()` with the forwarded request headers.
If you already have a proxy, call `inthProxy(request)` instead of
`NextResponse.next()` and attach your response headers or cookies to the
returned response. Make sure `config.matcher` covers every page rendering
`InthProvider` and `/api/inth/:path*` if you mount the consent route.

## Add the middleware (Next.js 15)

On Next.js 15, export `middleware` from `middleware.ts`:

{/* example: fragment */}

```ts title="middleware.ts"
import { inthMiddleware } from '@inth/nextjs/middleware';
import type { NextRequest } from 'next/server';

export function middleware(request: NextRequest) {
	return inthMiddleware(request);
}

export const config = {
	matcher: ['/((?!_next/static|_next/image|favicon.ico).*)'],
};
```

`inthMiddleware` is an alias for `inthProxy`. Both imports (`InthMiddlewareOptions`
and `InthProxyOptions`) work on Next.js 15 and 16.

## Persist geography in cookies

On runtimes where forwarded request headers do not reach Server Components,
pass `cookie: true` to set `HttpOnly`, `SameSite=Lax` cookies (`inth-country`
and `inth-region` by default; customize via
`cookie: { countryName: 'geo-country', regionName: 'geo-region' }`):

{/* example: fragment */}

```ts title="proxy.ts"
import { inthProxy } from '@inth/nextjs/proxy';
import type { NextRequest } from 'next/server';

export function proxy(request: NextRequest) {
	return inthProxy(request, { cookie: true });
}
```

Cookies apply starting on the second request and are never cleared when a
header disappears. Because Inth server helpers read headers rather than these
cookies, pass the cookie explicitly as `country` (`resolveConsent` has no
`region` override):

{/* example: fragment */}

```tsx title="app/layout.tsx (partial)"
import { InthProvider } from '@inth/nextjs';
import { resolveConsent } from '@inth/nextjs/server';
import { cookies } from 'next/headers';

async function resolveVisitorConsent() {
	const country = (await cookies()).get('inth-country')?.value;
	return resolveConsent({ country });
}

// Inside your synchronous root layout:
<InthProvider state={resolveVisitorConsent()}>{children}</InthProvider>;
```

With the
[awaited layout](/docs/frameworks/next/app-router#render-the-banner-in-the-server-html),
await `resolveVisitorConsent()` inside `Suspense`.

**Security warning.** `HttpOnly` prevents page scripts from reading a cookie,
not a client from forging `Cookie: inth-country=US` to pick a weaker policy.
Pass the cookie to `resolveConsent({ country })` only if your edge overwrites
those incoming cookies on every request or you sign and verify the value.
Otherwise use the cookie only for non-policy display defaults.

## Which headers are read?

Within each row, the first non-empty header wins:

| Input | Headers (highest precedence first) | Source |
| --- | --- | --- |
| Country | `x-inth-country`, `cf-ipcountry`, `x-vercel-ip-country`, `x-amz-cf-ipcountry`, `x-country-code`, `x-country` | Inth override, Cloudflare, Vercel, CloudFront, generic |
| Region | `x-inth-region`, `cf-region-code`, `x-vercel-ip-country-region`, `x-region-code` | Inth override, Cloudflare, Vercel, generic |
| Global Privacy Control | `x-inth-gpc`, `sec-gpc` | Inth override, browser signal |
| Language | `accept-language` | Browser |

CloudFront's `CloudFront-Viewer-Country` and `CloudFront-Viewer-Country-Region`
headers are not read by default. Forward them with an origin request policy,
strip all recognized geo headers first so clients cannot spoof fallbacks, and
map them before calling `inthProxy`:

{/* example: fragment */}

```ts title="proxy.ts"
import { inthProxy } from '@inth/nextjs/proxy';
import { NextRequest } from 'next/server';

export function proxy(request: NextRequest) {
	const headers = new Headers(request.headers);
	for (const name of [
		'x-inth-country',
		'cf-ipcountry',
		'x-vercel-ip-country',
		'x-amz-cf-ipcountry',
		'x-country-code',
		'x-country',
		'x-inth-region',
		'cf-region-code',
		'x-vercel-ip-country-region',
		'x-region-code',
	]) {
		headers.delete(name);
	}
	const country = headers.get('cloudfront-viewer-country');
	const region = headers.get('cloudfront-viewer-country-region');
	if (country) headers.set('x-inth-country', country);
	if (region) headers.set('x-inth-region', region);
	return inthProxy(new NextRequest(request, { headers }));
}
```

GPC accepts only `1` or `0` and is normalized onto `sec-gpc`. Because
`x-inth-country`, `x-inth-region` and `x-inth-gpc` (and the `country`, `region`
and `gpc` query params on `/v1/consent/init`) always take precedence, strip client-sent
values at the edge that terminates public traffic.

## Verify

1. Deploy with `inthProxy` and test from two regions with different policies
   (for example via VPN). Confirm each region gets its expected policy and
   `(await headers()).get('x-inth-country')` matches the platform header.
2. Temporarily remove `inthProxy` and reload: if both regions fall back to the
   unknown-location rule, your host strips geo headers and requires the proxy.
3. If using the consent route, confirm `/api/inth/v1/consent/init` returns the right
   `policyResolution` per region. With `cookie: true`, confirm
   `Set-Cookie: inth-country=...` includes `HttpOnly` and `SameSite=Lax`.
