Inth loads banner, dialog, widget and gate copy from your Inth project's
translations so wording updates without a deploy. Override copy in code with
`options.i18n` (globally) or text props on `ConsentBanner` (for one banner).
See [Copy and translations](/docs/customization/translations) for all message
keys.

## How Inth picks the language

In the [App Router](/docs/frameworks/next/app-router) and
[Pages Router](/docs/frameworks/next/pages-router) setups, `resolveConsent()`
reads `Accept-Language` and resolves translations on the server (pass
`language` to override it from a `[lang]` route segment). In
[client-side rendering](/docs/frameworks/next/client-side) and
[static export](/docs/frameworks/next/static-export), the browser `/v1/consent/init`
request sends `Accept-Language`. Unmatched languages fall back to your Inth
project's fallback language. Right-to-left languages such as Arabic and Hebrew
automatically set `dir="rtl"` while keeping banner position unchanged.

## Change the copy in code

Define message overrides in a module and pass them under `options.i18n` in
`inth.config.ts`:

<include src="../../shared/examples/nextjs/i18n.mdx" />

{/* example: fragment */}

```ts title="inth.config.ts"
import { defineConsentConfig } from '@inth/nextjs';

import { i18n } from './lib/consent-i18n';

export default defineConsentConfig({ options: { i18n } });
```

`InthProvider` reads `i18n` once on mount (on both server and browser) and
merges keys for the active language over your project's copy. Set `i18n.locale`
(default `'en'`) when no backend supplies a language, such as in `testing()`.

## Change one banner's copy

Pass `title`, `description`, `acceptButtonText`, `rejectButtonText`,
`customizeButtonText` or `dismissButtonText` to `ConsentBanner` (these replace
text in every language):

{/* example: fragment */}

```tsx
<ConsentBanner
	title="Cookies on this site"
	rejectButtonText="Reject optional"
/>;
```

## Switch the language at runtime

Call `useSetLanguage()` followed by `useInit()` in your language switcher to
fetch and apply the new language's copy (also pass the locale as `language` to
`resolveConsent()` to keep server HTML aligned):

## Verify

1. Request a dynamic page with `curl -H 'Accept-Language: de' <your-url>` and
   confirm translated banner copy appears in the HTML.
2. Open the page in a browser and confirm your `i18n` overrides appear.
3. Switch languages and confirm a new `/v1/consent/init` request updates the UI without a
   page reload.
