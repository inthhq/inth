Set up Inth in a Next.js App Router app running on a Next.js server. Your build
bundles your project's public policy manifest, your server resolves consent per
visitor, and the browser posts choices to Inth.

## Prerequisites

- An [Inth project](https://inth.com) with your site's origin added to its
  trusted origins.
- A Next.js server. For `output: 'export'`, see
  [Static export](/docs/frameworks/next/static-export). For static, ISR,
  `'use cache'` or Cache Components, see
  [Rendering and deployment](/docs/frameworks/next/rendering). For tests without
  a backend, see
  [testing configuration](/docs/frameworks/next/data-fetching-reference#testing-configuration).
- Trusted location headers from your host for region-specific policies. Check
  [Geography headers](/docs/frameworks/next/geography-headers) before deploying.

## Set the project URL

Add your Inth project URL (including any path prefix) to `.env.local` and your
host's build settings:

```sh title=".env.local"
NEXT_PUBLIC_INTH_PROJECT_URL=https://your-project.inth.app
```

Next.js inlines `NEXT_PUBLIC_` variables at build time, so rebuild after
changing the URL. `NEXT_PUBLIC_INTH_PROJECT_URL` wins over any legacy
`NEXT_PUBLIC_C15T_BACKEND_URL`, which is read as a fallback if unset. You can
also pass `projectUrl` in code to both `defineConsentConfig` and
`withConsentManifest`.

## Add the consent config

Create `inth.config.ts` at the project root next to `next.config.ts` and export
the config as the default export:

<include src="../../shared/examples/nextjs/quickstart-config.mdx" />

`withConsentManifest` wires this file into `InthProvider`, `resolveConsent` and
the consent route automatically. Because the browser bundle includes it, it can
hold `scripts` and callbacks, but never secrets.

| Option | Default | Behavior |
| --- | --- | --- |
| `projectUrl` | `NEXT_PUBLIC_INTH_PROJECT_URL` (`NEXT_PUBLIC_C15T_BACKEND_URL` fallback) | Inth base URL. Choices post to `${projectUrl}/v1/consent/records`. |
| `mode` | `manifest()` | `manifest()`, `hosted()` or `testing()` from `@inth/nextjs`. See [consent modes](/docs/concepts/modes). |
| `routePrefix` | none | Mount path for the [consent route](#initialize-in-the-browser) when some pages resolve in the browser. |
| `proxy` | `false` | Route browser saves through the consent route too. See [Performance](/docs/frameworks/next/optimization#keep-browser-consent-requests-on-your-origin). |
| `journey` | `'page'` | Consent journey scope. |
| `scripts`, `vendors`, `clearOnRevocation`, `networkBlocker`, `persistence`, `scriptLoader`, `options` | none | Browser options. Matching props on `InthProvider` override them. |

Replace `phc_your_project_key` with your PostHog key or another
[integration](/docs/integrations/overview). Keep `cookieless_mode: 'never'` to
prevent cookieless capture after rejection, and remove any existing PostHog
loader from `next/script` or a tag manager.

## Start consent resolution in the root layout

Render `InthProvider` in `app/layout.tsx` and pass `resolveConsent()` without
awaiting it:

<include src="../../shared/examples/nextjs/quickstart-layout.mdx" />

The root layout stays a Server Component with no `'use client'` wrapper. Mount
a single `InthProvider` in the root layout (do not also mount `@inth/react`'s
`InthProvider`, because `@inth/nextjs`'s `InthProvider` already wraps it).

Next.js streams the page immediately and sends the resolved consent in a later
chunk of the same response, so the banner appears before hydration without
making a browser `/v1/consent/init` request. To mount the banner after hydration instead,
set `options={{ streamBanner: false }}`. Until consent resolves, optional
categories stay denied, `ConsentGate` shows its placeholder and gated scripts
stay blocked.

If a runtime manifest fetch fails or exceeds `timeoutMs` (500 ms default),
`resolveConsent` returns a baseline state so the page renders and the browser
retries on mount. Pass `onError` to monitor failures; see
[Troubleshooting](/docs/frameworks/next/troubleshooting). With
`cacheComponents: true`, this layout stays synchronous and keeps page content
in the static shell; see
[Cache Components](/docs/frameworks/next/rendering#use-cache-components).

The banner arrives decided in the HTML and never shifts after hydration, while

<include src="../../shared/examples/nextjs/consent-route.mdx" />

`createConsentRoute()` answers `GET /api/inth/v1/consent/init` and
`GET /api/inth/v1/consent/manifest` from the snapshot and returns 404 for other paths. To
forward saves through your origin too, set `proxy: true` in both
`inth.config.ts` and `createConsentRoute({ proxy: true })`; see
[Performance](/docs/frameworks/next/optimization#keep-browser-consent-requests-on-your-origin).
Without `routePrefix`, browser-initialized pages call `${projectUrl}/v1/consent/init`. See
[static, ISR and cached pages](/docs/frameworks/next/rendering#render-static-isr-and-cached-pages)
to mix static and dynamic routes.

## Use backend init instead of the manifest

Set `mode: hosted()` in `inth.config.ts` to resolve via `${projectUrl}/v1/consent/init`
per visit instead of a manifest:

{/* example: fragment */}

```ts title="inth.config.ts"
import { defineConsentConfig, hosted } from '@inth/nextjs';

export default defineConsentConfig({ mode: hosted() });
```

Keep `withConsentManifest` in `next.config.ts` so the SDK finds
`inth.config.ts`; it skips the manifest download in `hosted()` mode. For a
browser-only setup with no server helpers, see
[Client-side initialization](/docs/frameworks/next/client-side). To keep
manifests while picking up policy changes without rebuilding, use
`manifest({ source: 'runtime' })` as shown in
[Performance](/docs/frameworks/next/optimization#reuse-cached-policy-data).

## Verify the setup

Run `next build` and `next start`, then open the site in a private window with
DevTools Network open:

1. Under an opt-in policy, the banner appears and no PostHog request fires.
2. Click **Reject All** and reload. The banner stays closed and PostHog does
   not load.
3. Open **Privacy settings** in the footer and enable **Analytics**
   (`measurement`). PostHog loads.
4. Open **Privacy settings**, turn **Analytics** off and save. The page reloads
   and PostHog stays blocked.
5. Confirm there is no `/v1/consent/init` request and saves post to
   `${projectUrl}/v1/consent/records`.

See [Scripts](/docs/frameworks/next/scripts) for vendor contracts and
[Verify consent](/docs/guides/verify-consent) for the release checklist.
