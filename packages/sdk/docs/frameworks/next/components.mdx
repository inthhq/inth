`@inth/nextjs` exports `InthProvider` and re-exports every React component and
hook from `@inth/react`. Every component except `ConsentTheme` is a Client
Component that can still be rendered directly from a Server Component as long
as its props are serializable.

## Component reference

| Component | Renders | Runs as | Reference |
| --- | --- | --- | --- |
| `InthProvider` | Consent runtime seeded with `resolveConsent()` state | Client Component | [InthProvider](/docs/frameworks/next/components/inth-provider) |
| `ConsentBanner` | Consent banner when required by the policy | Client Component | [ConsentBanner](/docs/frameworks/next/components/consent-banner) |
| `ConsentDialog` | Preference center modal | Client Component | [ConsentDialog](/docs/frameworks/next/components/consent-dialog) |
| `ConsentWidget` | Inline preference center for a privacy page | Client Component | [ConsentWidget](/docs/frameworks/next/components/consent-widget) |
| `ConsentDialogLink` | Unstyled button opening the dialog, for footers | Client Component | [ConsentDialogLink](/docs/frameworks/next/components/consent-dialog-link) |
| `ConsentDialogTrigger` | Floating, draggable button opening the dialog (`ConsentDialogTriggerToolbar` adds custom actions) | Client Component | [ConsentDialogTrigger](/docs/frameworks/next/components/consent-dialog-trigger) |
| `ConsentGate` | Children when a category is allowed, otherwise a placeholder | Client Component | [ConsentGate](/docs/frameworks/next/components/consent-gate) |
| `ConsentTheme` | `<style>` element declaring theme tokens | Server-safe | [Customize](/docs/frameworks/next/customize) |
| `DevTools` (`@inth/nextjs/devtools`) | Development panel for state, scripts and events | Client Component | [DevTools](/docs/frameworks/next/components/dev-tools) |

Mount every component except `ConsentTheme` inside a single `InthProvider` from
`@inth/nextjs`. Do not also mount `@inth/react`'s `InthProvider`, because
`@inth/nextjs`'s `InthProvider` already wraps it.

## Server and Client Components

- **`InthProvider`:** reads `inth.config.ts` in the browser, so Server
  Components pass only `state`. Put function options such as callbacks in
  `inth.config.ts`.
- **UI components:** render directly from Server Components when passing plain
  props and JSX. Move components that pass function props (such as toolbar
  `onSelect` handlers) or call [hooks](/docs/frameworks/next/hooks) into a
  `'use client'` file.
- **`ConsentTheme`:** has no `'use client'` directive; render it from a Server
  Component layout to keep the theme generator out of browser JavaScript.
- **`DevTools`:** load only in development via `next/dynamic` with
  `ssr: false`.

## IAB TCF and other entry points

For IAB TCF policies, import `IABProvider`, `IABConsentBanner` and
`IABConsentDialog` from `@inth/react/iab` and mount them inside `InthProvider`
next to the stock components. See [IAB TCF](/docs/frameworks/next/iab).

| Import | Exports | Use |
| --- | --- | --- |
| `@inth/nextjs/components/consent-dialog-link` | `ConsentDialogLink` only | Load the footer link without the rest of the adapter |
| `@inth/nextjs/headless` | Headless hooks | Custom banner and dialog markup ([Headless](/docs/frameworks/next/headless)) |
| `@inth/nextjs/server` | `resolveConsent` and server helpers | Server Components and Route Handlers |
| `@inth/nextjs/devtools` | `DevTools` | Development debugging panel |

## Check the components

Open the site in a private window under an opt-in policy:

1. Confirm the banner renders and no vendor requests fire in DevTools Network.
2. Click `ConsentDialogLink` to open the dialog with optional categories off.
3. Grant a category and save: its scripts load and any matching `ConsentGate`
   mounts its children.
4. Reload: the banner stays closed and `ConsentDialogLink` still reopens the
   dialog. With an
   [awaited layout](/docs/frameworks/next/app-router#render-the-banner-in-the-server-html),
   page source contains `data-testid="consent-banner-root"` only before a
   choice is saved.
