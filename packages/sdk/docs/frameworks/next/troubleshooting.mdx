Fix Next.js-specific errors in `@inth/nextjs`. For cross-framework issues such
as a missing banner, CORS errors or choices disappearing on reload, see
[Troubleshooting](/docs/guides/troubleshooting).

## Page renders without a banner when server prefetch fails

**Cause.** When a manifest or `/v1/consent/init` request fails or exceeds `timeoutMs`,
`resolveConsent` returns a baseline state so the page still renders with
optional categories denied and no banner while the browser retries on mount.
Server fetches do not appear in browser DevTools.

**Fix.** Pass `onError` to `resolveConsent` to log failures in production
(without it, warnings log outside production only). If your consent route calls
itself in a loop, set `projectUrl` or `NEXT_PUBLIC_INTH_PROJECT_URL` to your
absolute Inth project URL and use `proxy: true` with `routePrefix` for
same-origin browser requests; see
[Performance](/docs/frameworks/next/optimization#keep-browser-consent-requests-on-your-origin).

## `@inth/nextjs/build: could not fetch the consent manifest`

**Cause.** `withConsentManifest` fetches `${projectUrl}/v1/consent/manifest` during
`next build`, `next dev` and `next typegen` (10 s timeout). By default
(`onBuildError: 'runtime'`), a failed fetch or missing URL logs a warning and
leaves `snapshot` as `undefined` so the server fetches at runtime. With
`onBuildError: 'fail'` or `INTH_ON_BUILD_ERROR=fail`, the build stops instead.
Common parenthesized causes:

- `fetch failed` or `no response within 10 seconds`: the build environment
  cannot reach Inth.
- `/v1/consent/manifest responded 404` (or another status): wrong project URL, placeholder
  URL or missing path prefix.
- `/v1/consent/manifest returned an invalid consent manifest`: endpoint is not a
  compatible Inth project URL.
- `no backend URL is set`: neither `projectUrl` nor
  `NEXT_PUBLIC_INTH_PROJECT_URL` / `NEXT_PUBLIC_C15T_BACKEND_URL` is set.
- `skipped the consent manifest fetch`: expected for `hosted()`, `testing()`,
  `manifest({ snapshot })`, `manifest({ source: 'runtime' })`, `output: 'export'`
  or a relative URL (fails only with `onBuildError: 'fail'`).
- `@inth/nextjs/build: could not read inth.config.ts`: `inth.config.ts` imports
  something Node cannot evaluate at build time, such as a stylesheet.

**Fix.** Set `NEXT_PUBLIC_INTH_PROJECT_URL` to your absolute Inth project URL
in `.env.local` and CI build settings. Keep `inth.config.ts` free of non-Node
imports. To fail builds instead of falling back to runtime, set
`INTH_ON_BUILD_ERROR=fail`; to skip build-time fetching entirely, use
[runtime manifest caching](/docs/frameworks/next/optimization#reuse-cached-policy-data).

## `server-only` cannot be imported from a Client Component

**Cause.** A Client Component imports `@inth/nextjs/generated`.
`withConsentManifest` keeps the policy snapshot out of browser bundles using
`server-only`.

**Fix.** Remove the import from client code. Most apps never import
`@inth/nextjs/generated` directly because `resolveConsent` and the consent
route read it automatically.

## `snapshot` from `@inth/nextjs/generated` is undefined

**Cause.** Server code reads `snapshot` as `undefined` when
`withConsentManifest` does not wrap `next.config.ts`, when the build-time fetch
failed and fell back to runtime, when the project URL is relative or
`output: 'export'` is set, or when the caller sits in `serverExternalPackages`
and misses bundler aliases.

**Fix.** Wrap `next.config.ts` with `withConsentManifest`, verify the project
URL is absolute, and keep `@inth/nextjs` and `@inth/sdk` out of
`serverExternalPackages`.

## `[inth] InthProvider found no config`

**Cause.** `withConsentManifest` only looks for `inth.config.ts` (or `.mts`,
`.js`, `.mjs`) at the project root next to `next.config.ts`, not inside `src/`.

**Fix.** Confirm that `next.config.ts` exports `withConsentManifest(nextConfig)`,
that `inth.config.ts` sits at the project root with a default export
(`export default defineConsentConfig(...)`), and restart `next dev`.

## `@inth/nextjs: projectUrl is required`

**Cause.** `InthProvider` throws
``inth: `projectUrl` is required. Set it in your config, or use `mode: testing()` from a /testing entry in tests.``
when no `inth.config.ts` project URL or env var was available at compile time.

**Fix.** Set `NEXT_PUBLIC_INTH_PROJECT_URL` (falling back to
`NEXT_PUBLIC_C15T_BACKEND_URL` if unset) in `.env.local` and your host's build
settings, and verify `withConsentManifest` finds `inth.config.ts`. For tests
without a backend, set `mode: testing()` in `inth.config.ts`.

## `inth: mode is the hosted() transport itself`

**Cause.** `options.mode` received a transport factory (`hosted()`, `testing()`
or `manifest()`) imported from `@inth/react`, which bundles the transport into
first-load JavaScript.

**Fix.** Import `manifest()` or `hosted()` from `@inth/nextjs` (or `testing()`
from `@inth/nextjs/testing`) and set `mode` in `inth.config.ts`.

## `@inth/nextjs: defineConsentConfig`

**Cause.** `defineConsentConfig` validates `inth.config.ts` on the server and
during builds and throws a `TypeError`, most commonly
``@inth/nextjs: manifest() needs a backend URL: ... Set NEXT_PUBLIC_INTH_PROJECT_URL at build time, or `projectUrl` in inth.config.ts.``

**Fix.** Check the exact message in the
[config reference](/docs/frameworks/next/data-fetching-reference#config-reference)
and set `NEXT_PUBLIC_INTH_PROJECT_URL` or `projectUrl`.

## Visitor location resolves as unknown on the server

**Cause.** Inth reads platform headers (`cf-ipcountry`, `x-vercel-ip-country`)
and never derives location from an IP address. Some hosts strip geo headers
between middleware/proxy and Server Components.

**Fix.** Log `(await headers()).get('x-vercel-ip-country')` (or your host's
header) in a Server Component. If it is missing there, add `inthProxy` as shown
in [Geography headers](/docs/frameworks/next/geography-headers) to forward
`x-inth-country` and `x-inth-region`.

## `Next.js encountered the unstable value Date.now() while prerendering`

**Cause.** In Next.js 16.3+ with `cacheComponents: true` and
`partialPrefetching: true`, `next dev` flags `Date.now()` after `headers()`
during runtime prefetching.

**Fix.** Upgrade `@inth/nextjs` to the latest release. `resolveConsent` calls
`await connection()` before reading the clock, so you do not need to add
`connection()` in your layout.

## `Next.js encountered data that is not available during a static prerender`

**Cause.** A route sets `ensureStatic = 'navigation'` (also throws
`Next.js encountered uncached or runtime data on a route that must be fully static`
with an awaited layout) under a root layout that calls `resolveConsent`.

**Fix.** Move `ensureStatic = 'navigation'` routes into a route group with the
browser layout (`InthProvider` without `state`). See
[Keep pages static with `ensureStatic`](/docs/frameworks/next/rendering#keep-pages-static-with-ensurestatic).

## Verify manifest fetching and inspect active policy

1. Load a server-rendered page twice: no upstream `/v1/consent/init` request fires, and
   choices post to `/v1/consent/records` (or `/api/inth/v1/consent/records` with `proxy: true`).
2. Test two regions with different policies and rebuild after policy edits (or
   wait for cache refresh under runtime caching).

To inspect live resolution inside `InthProvider` without recording a choice,
temporarily render this Client Component (use `useConsent('marketing')` in
production instead of subscribing to the full snapshot):

{/* example: fragment */}

```tsx title="app/consent-policy-debug.tsx"
'use client';

import { useSnapshot } from '@inth/nextjs';

export function ConsentPolicyDebug() {
	const snapshot = useSnapshot();
	const resolution = snapshot.resolution;

	return (
		<pre>
			{JSON.stringify(
				{
					status: resolution.status,
					policy: resolution.status === 'matched' ? resolution.policy.id : null,
					prompt: snapshot.promptRequirement,
					permissions: snapshot.effectivePermissions,
					location: snapshot.location,
					privacySignals: snapshot.privacySignals,
				},
				null,
				2
			)}
		</pre>
	);
}
```

## The banner or dialog fails to load

**Check.** Open the console. A warning or error from Inth that says the banner, the dialog or the engine failed to load means the browser could not download one of Inth's chunks, for example during a dropped connection or a deploy that removed old files.

After a failure the page stays as it is: Inth never reloads it, because a reload would discard what the visitor typed into your page. Nothing is recorded, and the banner stays or shows again. The next tap, open or snapshot tries the download again. With webpack (the Next.js default), the bundler's runtime forgets a failed chunk, so every retry sends a new request in every browser. With Turbopack, or another bundler that loads chunks with native `import()`, the table in [a consent chunk fails to load](/docs/guides/troubleshooting#a-consent-chunk-fails-to-load) applies.

**Fix.** Nothing on the page. The next page load downloads the chunk again. If the failures follow a deploy, keep the previous build's chunk files available until cached pages that link to them expire. See [a consent chunk fails to load](/docs/guides/troubleshooting#a-consent-chunk-fails-to-load) for which browsers and builds can retry on the same page.
