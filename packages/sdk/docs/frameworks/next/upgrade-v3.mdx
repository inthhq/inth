  4. ## Before you start

- Upgrade React and React DOM to 18 or later, and Next.js to 15 or 16.
- The Inth SDK talks only to an Inth project. An app on a c15t backend it
  runs itself moves to an Inth project first.
- Install the [Inth CLI](/docs/cli/overview#install-the-inth-cli). The
  codemods run through `inth c15t codemods`.

## Replace the packages

Remove `@c15t/nextjs`, `@c15t/react` and `@c15t/scripts`, then install `@inth/nextjs`.

<CommandTabs command="@inth/nextjs @inth/integrations" mode="install" />

Drop `@inth/integrations` if you don't use its vendor helpers.

| v2 import | v3 import |
| --- | --- |
| `@c15t/nextjs` | `@inth/nextjs`. Server helpers are in `@inth/nextjs/server`, `@inth/nextjs/pages` and `@inth/nextjs/api`. |
| `@c15t/react` | `@inth/nextjs`, which re-exports the React components and hooks |
| `@c15t/nextjs/styles.css` | Nothing: remove the import. Keep `@inth/nextjs/styles.css` only with `styles: false` |
| `DevTools` from `@c15t/dev-tools/react` | `DevTools` from `@inth/nextjs/devtools` |
| `@c15t/scripts/*` | `@inth/integrations/*` |

The `packages-to-c15t` codemod rewrites the `@c15t/nextjs` and `@c15t/react`
imports and removes the stylesheet imports. It doesn't edit `package.json`.

The codemods come from c15t, so they write c15t v3 paths such as `c15t/next`,
`c15t/react` and `@c15t/integrations`. After a run, replace `c15t/next` with
`@inth/nextjs`, `c15t/react` with `@inth/react` and `@c15t/integrations` with
`@inth/integrations`.

Every v3 package ships ESM only. If a CommonJS file in your app calls
`require()` on a c15t or Inth package, convert it to ESM.

## Replace `ConsentManagerProvider`

A typical v2 App Router app wrapped the layout in a client component:

{/* example: fragment */}

```tsx title="Before (v2): components/consent-manager/provider.tsx"
'use client';

import {
	ConsentBanner,
	ConsentDialog,
	ConsentManagerProvider,
} from '@c15t/nextjs';

export default function ConsentManagerClient({ children }) {
	return (
		<ConsentManagerProvider
			options={{ mode: 'hosted', backendURL: 'https://your-project.c15t.dev' }}
		>
			<ConsentBanner />
			<ConsentDialog />
			{children}
		</ConsentManagerProvider>
	);
}
```

v3 gives you two ways forward.

**Resolve consent on the server.** This is the recommended path. The server
reads the visitor's policy and stored choice, so gated scripts can start right
after hydration and the banner can be in the first HTML. Replace the client
component with `InthProvider`. Pass it `resolveConsent()` from
`@inth/nextjs/server` as `state` and your `defineConsentConfig()` result as
`config`, then add the manifest route. It already wraps the
`InthProvider` from `@inth/nextjs/react`, so don't mount both. If v2 set `storageConfig.storageKey`,
pass the same name to `resolveConsent()` as `cookieName`, or the server won't
find the stored choice. Follow the
[App Router guide](/docs/frameworks/next/app-router) or the
[Pages Router guide](/docs/frameworks/next/pages-router). This replaces v2's
`fetchInitialData()`, `ssrData` and `C15tPrefetch`, which are gone.

**Keep browser initialization**, as v2 did without `fetchInitialData()`. Keep
your client component and render the `InthProvider` from `@inth/nextjs/react`,
which takes the backend URL as `projectUrl`:

{/* example: fragment */}

```tsx title="After (v3): components/consent-manager/provider.tsx, changed lines"
import { ConsentBanner, ConsentDialog } from '@inth/nextjs';
import { InthProvider, hosted } from '@inth/nextjs/react';

// In the component, replace ConsentManagerProvider:
<InthProvider
  options={{ projectUrl: 'https://your-project.inth.app', mode: hosted() }}
>
```

The `consent-provider-options` codemod rewrites the mode to `hosted()` and
adds its import:

```bash
inth c15t codemods consent-provider-options --dry-run --json
```

Static exports use browser initialization too. See
[static export](/docs/frameworks/next/static-export) and
[client-side setup](/docs/frameworks/next/client-side).

Either way, remove the `@c15t/nextjs/styles.css` import, as
[stylesheets](#stylesheets) explains, and keep your backend URL. An existing hosted URL such as
`https://your-project.c15t.dev` keeps working with v3 clients. New Inth
projects use URLs such as `https://your-project.inth.app`.

The other v2 modes map to transports:

| v2 option | v3 option |
| --- | --- |
| `mode: 'offline'` with `offlinePolicy` | `mode: local({ policyRules })` |
| `mode: 'custom'` with `endpointHandlers` | No equivalent. Point the provider at your Inth project, which records each choice. `endpointHandlers` throws. |

The codemod leaves v2's offline and custom modes as they are, with a
`TODO(c15t v3)` comment. Move `offlinePolicy.policyPacks` to
`local({ policyRules })` by hand. It can't translate `endpointHandlers`.

Local mode keeps choices in the browser and records nothing on a server. Not
recommended for production environments.

## Update dev tools

`@c15t/dev-tools/react` and `@c15t/dev-tools/tanstack` are gone. Import
`DevTools`, `InthTanStackDevtoolsPanel` and `inthDevtools()` from
`@inth/nextjs/devtools`. Dev tools read the consent engine, so `namespace`,
`createStoreConnector()` and `getC15tStore()` are gone too. See
[dev tools](/docs/frameworks/next/components/dev-tools).

The `dev-tools-to-c15t` codemod points the imports at `c15t/next/devtools`
and removes the `namespace` prop. Then point them at `@inth/nextjs/devtools`:

```bash
inth c15t codemods dev-tools-to-c15t --dry-run --json
```

### Removed

Modes and build integrations, in every framework:

<include src="../../shared/upgrade-v3/earlier-alpha-modes.mdx" />

Next.js:

| Removed | Use instead |
| --- | --- |
| `ConsentRoot` and `ConsentRootProps` | `InthProvider` and `InthProviderProps` |
| `ConsentProvider` from `@inth/nextjs` | `InthProvider` from `@inth/nextjs/react` |
| `ConsentProviderOptions`, `ConsentProviderCallbacks` and `ConsentProviderPrefetch` | `InthProviderOptions`, `InthProviderCallbacks` and `InthProviderPrefetch` from `@inth/nextjs/react`. `InthProviderOptions` from `@inth/nextjs` is the root's `options` |
| `defineConsentConfig({ manifestURL, initURL })` | `routePrefix`, or `mode: manifest({ resolve: 'browser', manifestURL })` |
| A named `consentConfig` export, passed to `InthProvider` as `config` | `export default defineConsentConfig(...)` in `inth.config.ts`. `withConsentManifest` finds the file. `config` stays as an optional override. |
| `InthProvider`'s `backendURL` prop | `backendURL` in the config, or `NEXT_PUBLIC_INTH_PROJECT_URL` |
| The `'use client'` wrapper that passed `config` and `scripts` | `scripts` and other browser options in `inth.config.ts`. A Server Component renders `InthProvider` directly. |
| `createNextConsentRouteHandlers()`, its `GET` and `manifestGET` | `createConsentRoute()` in one catch-all route, `app/api/inth/[...inth]/route.ts` |
| `createPagesApiHandlers()` and its `init` and `manifest` | `createPagesConsentRoute()` in `pages/api/inth/[...inth].ts` |
| `resolveConsent(...)` with a JSON round trip in `getServerSideProps` | `export const getServerSideProps = withConsentProps()`, and `AppProps<ConsentPageProps>` in `_app.tsx` |
| `resolveConsent({ manifest })`, and `manifest` on the route helpers | `snapshot`, which defaults to the build's |
| `ConsentManifestOptions` and the `c15t.server.ts` module | `ResolveConsentOptions` or `NextConsentRouteOptions`. The helpers read the config and snapshot themselves. |
| `resolveStrictestDefaultInit` from `c15t/next/static` | `resolveUnknownLocationInit` |
| `InthProvider` falling back to local mode when no config or `NEXT_PUBLIC_INTH_PROJECT_URL` gives it a backend URL | `InthProvider` throws. Set `mode: local()` to run without a backend. |
| `onBuildError: 'runtime'` to build a `hosted()` or `local()` app while the backend is unreachable | Nothing. `withConsentManifest` reads the mode from `inth.config.ts` and skips the download for modes that don't use it. |
| `hosted`, `offline` and `manifest` from `c15t/next` as transports | They are data for `inth.config.ts` now. Import the transports from `@inth/react` for `options.mode`. |
