## When to compose

For a banner that shares nothing with the stock markup, use the

## Compose the banner

`CookieBanner` keeps the stock card, title and copy, and renders each action
the policy asks for as your design system's button. `BrandButton` stands in
for that button:

<include src="../../shared/examples/nextjs/compose-button.mdx" />

<include src="../../shared/examples/nextjs/compose-banner.mdx" />

`@inth/nextjs` re-exports every `@inth/react` component, so `ConsentBanner` and
its parts come from the same import as `InthProvider`. The file starts with
`'use client'` because a Server Component can neither read a property of a
client component, such as `ConsentBanner.Root`, nor pass a function, such as
`renderAction`.

The parts read the provider inside
[InthProvider](/docs/frameworks/next/components/inth-provider). Import
`CookieBanner` in the layout that renders `InthProvider`, from the
[quickstart](/docs/frameworks/next/quickstart#resolve-consent-in-the-root-layout)
or your router guide, and render it in place of `ConsentBanner`, next to
`ConsentDialog`. `CookieBanner` is a client component, so a Server Component
layout can render it:

{/* example: fragment */}

```tsx title="app/layout.tsx (partial)"
<InthProvider state={resolveConsent()}>
	{children}
	<CookieBanner />
	<ConsentDialog />
	<footer>
		<ConsentDialogLink>Privacy settings</ConsentDialogLink>
	</footer>
</InthProvider>;
```

The Pages Router renders the same components in `pages/_app.tsx`, so the
composed banner works in both routers.

`@inth/nextjs` exports `ConsentDialog` and `ConsentWidget` with their parts.
It has no `components/consent-dialog` subpath, so import the parts without
the deferral from `@inth/react/components/consent-dialog`, in a Client
Component. [ConsentDialog](/docs/frameworks/next/components/consent-dialog)
and [ConsentWidget](/docs/frameworks/next/components/consent-widget) list
every part and its slots.
