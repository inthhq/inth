Configure a strict Content Security Policy with `@inth/nextjs` by forwarding a
per-request nonce to `InthProvider` and allowing your Inth project origin in
`connect-src`.

## Pass the request nonce to InthProvider

Generate a per-request nonce in `proxy.ts` (Next.js 16) or `middleware.ts`
(Next.js 15), set `Content-Security-Policy` with `'nonce-<value>'` on
`script-src` and `style-src`, and forward `x-nonce` on the request as described
in the
[Next.js CSP guide](https://nextjs.org/docs/app/guides/content-security-policy).

If you also use [`inthProxy`](/docs/frameworks/next/geography-headers), set
both `x-nonce` and `Content-Security-Policy` on `request.headers` before
calling `inthProxy` and set the policy header on the returned response, so
Next.js can stamp its own bootstrap scripts.

Read `x-nonce` in your root layout and pass it to `InthProvider` as
`options={{ nonce }}`:

{/* example: fragment */}

```tsx title="app/layout.tsx"
import { ConsentBanner, ConsentDialog, InthProvider } from '@inth/nextjs';
import { resolveConsent } from '@inth/nextjs/server';
import { headers } from 'next/headers';
import { Suspense } from 'react';
import type { ReactNode } from 'react';

import './globals.css';

async function ResolvedConsent({ children }: { children: ReactNode }) {
	const nonce = (await headers()).get('x-nonce') ?? undefined;
	const state = await resolveConsent();

	return (
		<InthProvider state={state} options={{ nonce }}>
			{children}
			<ConsentBanner />
			<ConsentDialog />
		</InthProvider>
	);
}

export default function RootLayout({ children }: { children: ReactNode }) {
	return (
		<html lang="en">
			<body>
				<Suspense fallback={null}>
					<ResolvedConsent>{children}</ResolvedConsent>
				</Suspense>
			</body>
		</html>
	);
}
```

Per-request nonces require dynamic rendering and cannot be combined with
`cacheComponents: true` (Partial Prerendering); use a hash-based CSP for
prerendered shells instead. `options.nonce` is read at mount per full page
load; client-side navigations keep the initial nonce.

## What the nonce applies to

Inth stamps `options.nonce` onto:

- Every `<script>` created by the script loader for `scripts` entries (an
  entry's own `nonce` overrides `options.nonce`).
- Inline `<style>` tags rendered by `ConsentBanner`, `ConsentDialog` and other
  stock components (rendered inline beside each component instead of hoisted to
  `<head>` so React preserves the nonce).
- The `<style id="inth-theme">` element from `ConsentTheme` when you pass
  `<ConsentTheme theme={theme} nonce={nonce} />`.
- Stock `ConsentBanner`'s pre-hydration tap script (blocking it only disables
  taps before hydration).
- `InthProvider`'s
  [pre-hydration script loader](/docs/frameworks/next/rendering#start-allowed-scripts-before-hydration)
  (dynamic per visitor, so incompatible with hash-only CSP; if blocked, scripts
  load after hydration).
- `InthProvider`'s
  [engine chunk preloader](/docs/frameworks/next/optimization#start-returning-visitors-scripts-sooner)
  (static across visitors, so compatible with hashes; if blocked, the engine
  loads normally).

What the nonce does not cover:

- **Nested vendor scripts.** Scripts injected by a vendor (such as tags loaded
  by GTM) do not inherit the nonce. Add `'strict-dynamic'` to `script-src` or
  allowlist vendor hosts.
- **External stylesheet.** If you import `@inth/nextjs/styles.css` with
  `styles: false`, cover it with `style-src 'self'`.
- **Inline `style` attributes.** The IAB dialog, trigger toolbar and animated
  collapses use inline `style` attributes. Allow them with
  `style-src-attr 'unsafe-inline'` if your policy triggers `style-src`
  violations.
- **Vendor requests and embeds.** Allow each vendor's hosts in `frame-src`,
  `img-src` and `connect-src`.

## Allow your Inth project in connect-src

Allow your Inth project origin (and any separate manifest CDN host) in
`connect-src` for `/v1/consent/records`, `/v1/consent/init` and `/v1/consent/manifest` requests:

```txt title="Content-Security-Policy (partial)"
connect-src 'self' https://<your-project-host> https://<your-manifest-host>;
```

With `proxy: true` and `routePrefix: '/api/inth'` (see
[Performance](/docs/frameworks/next/optimization#keep-browser-consent-requests-on-your-origin)),
`'self'` covers every browser consent request because the Next.js server talks
to Inth outside the browser's CSP. If you use the
[IAB TCF add-on](/docs/frameworks/next/iab), also allow the Global Vendor List
host in `connect-src`.

## Verify

Load a page with the policy enforced (not report-only) and check DevTools:

1. No CSP errors reference `inth-theme` or an Inth script or style element.
2. Grant a category and inspect the injected `<script>` element's `.nonce`
   property (`getAttribute('nonce')` is hidden by browsers) and
   `<style id="inth-theme">` to confirm they match the request nonce.
3. Confirm the `POST /v1/consent/records` request succeeds without a `connect-src` error.
4. Reload and confirm the nonce updates (a stale nonce indicates cached HTML).
