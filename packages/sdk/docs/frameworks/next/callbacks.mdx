Subscribe to consent lifecycle events in `inth.config.ts` and report server
prefetch failures from `resolveConsent()`.

## Put callbacks in inth.config.ts

Because Server Components cannot pass functions to Client Components, define
browser callbacks in a module and attach them under `options` in
`inth.config.ts`:

<include src="../../shared/examples/nextjs/callbacks.mdx" />

{/* example: fragment */}

```ts title="inth.config.ts"
import { defineConsentConfig } from '@inth/nextjs';

import { callbacks } from './lib/consent-callbacks';

export default defineConsentConfig({ options: { callbacks } });
```

`InthProvider` reads this file in both App Router layouts and
[Pages Router](/docs/frameworks/next/pages-router) `_app.tsx`. Keep your
existing `scripts` and options in the same call. Callbacks subscribe after
mount in the browser, never run during SSR, and always invoke the latest
object passed.

## Available callbacks

| Callback | Runs when | Receives |
| --- | --- | --- |
| `onChoiceRecorded` | Visitor clicks Accept All, Reject All or Save Settings (stock UI or `useSaveConsents()`) | `snapshot`, `confirmed` categories, `actionAt` timestamp (ms) |
| `onPermissionsChanged` | Any effective permission changes value | `snapshot`, `previous` permissions |
| `onError` | A browser consent command fails (`/v1/consent/init` or `/v1/consent/records`) | `error` message string |
| `onBeforeConsentRevocationReload` | Right before Inth reloads the page after a save or one-click opt-out withdraws a granted category or vendor. Privacy signals and backend-synced opt-outs do not reload | `preferences` after the withdrawal |

Import the object type as `InthProviderCallbacks` from `@inth/nextjs`.
Callbacks fire after state updates, so `snapshot` and hooks already reflect the
new values.

## onChoiceRecorded or onPermissionsChanged

| Event | `onChoiceRecorded` | `onPermissionsChanged` |
| --- | --- | --- |
| Visitor accepts, rejects or saves | Yes | Yes, if a permission changed |
| Policy resolves and allows categories before any choice | No | Yes |
| Global Privacy Control turns off a grant | No | Yes |
| Recorded choice expires | No | Yes |
| Visitor dismisses a notice | No | No |

Use `onChoiceRecorded` for audit trails and consent analytics. Use
`onPermissionsChanged` to start or stop features (never treat it as proof of
consent or call save inside it; see
[a permission is not a recorded choice](/docs/concepts/how-consent-works#a-permission-is-not-a-recorded-choice)).
Track notice dismissals with `useNoticeDismissal()`, and use
[hooks](/docs/frameworks/next/hooks) inside individual components.

## Report server-side failures

Pass `onError` to `resolveConsent()` to catch server manifest or `/v1/consent/init`
failures and timeouts (without it, warnings log outside production only):

{/* example: fragment */}

```tsx title="app/layout.tsx"
const state = resolveConsent({ onError: (error) => reportToMonitoring(error) });
```

This runs only on the server and never crosses the client boundary.

## Before a revocation reload

When a visitor revokes a granted category or vendor, Inth waits for the save to
settle, calls `onBeforeConsentRevocationReload` synchronously, and reloads the
page so running vendor code stops. Keep the handler short and synchronous (the
reload does not await promises). Expiry, policy updates and privacy signals do
not trigger reloads. Set `options: { reloadOnConsentRevoked: false }` only if
every vendor cleans up via its own opt-out API.

## Verify

1. Clear site data and load under an opt-in policy with DevTools open.
2. Click **Accept All**: `onChoiceRecorded` and `onPermissionsChanged` log and
   `/v1/consent/records` succeeds.
3. Reload: `onChoiceRecorded` does not fire again.
4. Open **Privacy settings**, turn off an allowed category and save:
   `onBeforeConsentRevocationReload` logs, the page reloads, and that vendor's
   requests stop.
