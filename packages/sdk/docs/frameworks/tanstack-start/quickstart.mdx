Add a consent banner to a TanStack Start app. Your root loader resolves consent on the server in the same response as the page, and analytics wait until consent allows them.

<Prompt title="Add Inth consent to this TanStack Start app" description="Paste into Claude Code, Codex, Cursor, or another coding agent at the root of your app.">
  Add Inth consent management to this TanStack Start app.

  1. Check that the app runs `@tanstack/react-start` 1.168.60 or later on a Start server. If it uses SPA mode or static prerendering, stop and tell me.
  2. Install `@inth/tanstack-start` and `@inth/integrations`. Read `node_modules/@inth/tanstack-start/AGENTS.md`, then follow the TanStack Start quickstart it links to, in order. Do not guess the API from memory.
  3. Set `VITE_INTH_PROJECT_URL` in `.env`. Ask me for my project URL, and use `https://example-inth.inth.app` only for a demo. `VITE_INTH_PROJECT_URL` wins over any legacy `VITE_C15T_BACKEND_URL`.
  4. Add `consentManifest()` from `@inth/tanstack-start/build` before `tanstackStart()` in `vite.config.ts`. Add nothing to `.gitignore`.
  5. Update `src/routes/__root.tsx`: define a top-level `getConsentState` server function wrapping `createConsentStateHandler()`, await it in the root loader with `...consentLoaderOptions`, and render `InthProvider`, `ConsentBanner`, `ConsentDialog`, and a footer `ConsentDialogLink`.
  6. Move every analytics and marketing script into `scripts` in `src/routes/__root.tsx` using helpers from `@inth/integrations`, carry over settings such as PostHog's `region` or `apiHost`, and remove old loaders from `head()` or app code. If a vendor has no helper, tell me.
  7. Run `vite build` and start the production server. Check that the server HTML contains `data-testid="consent-banner-root"` under an opt-in policy, that no vendor request fires before consent, that rejecting survives a reload, and that granting analytics from the footer link loads PostHog.

  Then list the files you changed, any script still outside consent, and how you checked the requests.
</Prompt>

## Prerequisites

- A TanStack Start app on a Start server (`@tanstack/react-start` 1.168.60+ on React 18 or 19). For SPA mode, prerendering, or streaming, see [Rendering and deployment](/docs/frameworks/tanstack-start/rendering).
- An [Inth project](https://inth.com/dashboard/sign-up?framework=tanstack-start) with your site's origin in its trusted origins. See [connect an Inth project](/docs/concepts/choose-your-setup#connect-an-inth-project).

## Install the SDK

<CommandTabs command="@inth/tanstack-start @inth/integrations" mode="install" />

Components render their own `<style>` elements, so no stylesheet import is needed. On Tailwind CSS 3, [load the stylesheet yourself](/docs/frameworks/tanstack-start/customize#load-the-stylesheet-yourself).

## Set the project URL

Add your Inth project URL, including any path prefix, to `.env` and your host's build settings:

```sh title=".env"
VITE_INTH_PROJECT_URL=https://example-inth.inth.app
```

This URL is public. `https://example-inth.inth.app` is a demo project for testing. Vite inlines it at build time, so rebuild after changing it. `VITE_INTH_PROJECT_URL` wins over any legacy `VITE_C15T_BACKEND_URL`, which is read as a fallback if unset.

## Bundle your policy at build time

Add `consentManifest()` from `@inth/tanstack-start/build` before `tanstackStart()` in `vite.config.ts`:

<include src="../../shared/examples/tanstack-start/vite-config.mdx" />

`vite build` and `vite dev` download your policy manifest for server code only, keeping it out of the browser bundle. Rebuild after changing policies or translations in Inth. If the download fails, the build warns and falls back to runtime fetching; set `INTH_ON_BUILD_ERROR=fail` to stop builds on fetch errors. For updates without rebuilding, see [runtime fetching](/docs/frameworks/tanstack-start/rendering#await-consent-in-the-loader).

Keep `createServerFn()` at module top level so Start strips it from the browser bundle. `consentLoaderOptions` prevents re-running the loader on client navigation.

Keep `scripts` in the route module because server functions return serializable data only. Replace `phc_your_project_key` with your PostHog key or pick another [integration](/docs/integrations/overview). PostHog defaults to EU; add `region: 'us'` for US projects or `apiHost` for a proxy. Keep `cookieless_mode: 'never'` and remove any existing PostHog loader.

## Gate your own features

Check a category inside `InthProvider` with `useConsent`:

{/* example: fragment */}

```tsx title="src/components/marketing-banner.tsx"
import { useConsent } from '@inth/tanstack-start';

export function MarketingBanner() {
	return useConsent('marketing') ? <aside>Spring sale</aside> : null;
}
```

For iframes, use [`ConsentGate`](/docs/frameworks/tanstack-start/components/consent-gate).

## Check it works

Run `vite build`, start the production server, and open a private window with DevTools Network open. Locally without a CDN geo header, pass `{ country: 'DE' }` to `createConsentStateHandler` while testing, then remove it.

1. View page source under an opt-in policy: `data-testid="consent-banner-root"` is present and no requests go to `posthog.com`.
2. Click **Reject All**, then reload and view source: the banner is gone and PostHog stays blocked.
3. Click **Privacy settings**, enable **Analytics**, and click **Save Settings**. PostHog loads.
4. Open **Privacy settings**, turn **Analytics** off, and click **Save Settings**. The page reloads without PostHog.

See [Geography headers](/docs/frameworks/tanstack-start/geography-headers), [Troubleshooting](/docs/frameworks/tanstack-start/troubleshooting), and [Verify consent](/docs/guides/verify-consent).
