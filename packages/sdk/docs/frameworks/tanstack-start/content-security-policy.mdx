Run Inth in TanStack Start under a strict Content Security Policy by forwarding TanStack Router's per-request nonce to `InthProvider` and allowing your Inth project and vendor origins.

## What Inth adds to the page

A TanStack Start app using Inth adds these elements and requests, each needing a matching CSP directive:

| What | Directive |
| --- | --- |
| `<style>` elements rendered by the banner, dialog, and other built-in components | `style-src` with the request nonce |
| Inth stylesheet, only if linked manually with `styles: false` | `style-src 'self'` |
| `<style id="inth-theme">`, when rendering `ConsentTheme` | `style-src` with the request nonce |
| `<script>` elements created by the script loader for `scripts` entries | `script-src` with the request nonce or each vendor host |
| Inline `<script>` emitted by `InthProvider` to start already-allowed `scripts` before hydration | `script-src` with the request nonce |
| Inline `consentPrefetchHead` script on prerendered pages | `script-src` with its hash |
| Browser requests to `/api/inth/*` when mounting the same-origin route | `connect-src 'self'` |
| Browser requests to `/v1/consent/init` and `/v1/consent/records` on your Inth project | `connect-src` with your Inth project origin |
| Iframes inside `ConsentGate`, plus frames, images, and requests loaded by vendors | `frame-src`, `img-src`, and `connect-src` per vendor |

Server-side requests made by `createConsentStateHandler` and `createConsentRoute` run outside the browser and are not subject to browser CSP.

## Pass the request nonce to Inth

When TanStack Router has `ssr.nonce`, it stamps that nonce onto router scripts and styles. Pass the same nonce to Inth in three steps so the script loader, component `<style>` tags, and `ConsentTheme` share it.

**1. Create the nonce and header in request middleware.** Generate a fresh nonce per request, set the CSP header, and attach the nonce to middleware context:

```ts title="src/csp-middleware.ts"
import { createMiddleware } from '@tanstack/react-start';
import { setResponseHeader } from '@tanstack/react-start/server';

export const cspMiddleware = createMiddleware().server(({ next }) => {
	const bytes = crypto.getRandomValues(new Uint8Array(16));
	const nonce = btoa(String.fromCharCode(...bytes));
	setResponseHeader(
		'Content-Security-Policy',
		[
			"default-src 'self'",
			`script-src 'nonce-${nonce}' 'strict-dynamic'`,
			`style-src 'self' 'nonce-${nonce}'`,
			"connect-src 'self' https://<your-project-host>",
			"img-src 'self' data:",
		].join('; ')
	);
	return next({ context: { nonce } });
});
```

Register `cspMiddleware` in `requestMiddleware` inside `src/start.ts` before `consentRequestMiddleware()` if you use both. Replace `https://<your-project-host>` with your Inth project origin and add your vendor origins.

**2. Give the router the nonce.** `getRouter` runs after global request middleware and passes the nonce to SSR; in the browser, TanStack Router reads it back from `<meta property="csp-nonce">` rendered by `HeadContent`:

```tsx title="src/router.tsx"
import { createRouter } from '@tanstack/react-router';
import { getGlobalStartContext } from '@tanstack/react-start';

import { routeTree } from './routeTree.gen';

export const getRouter = function getRouter() {
	return createRouter({
		routeTree,
		ssr: { nonce: getGlobalStartContext()?.nonce },
	});
};
```

**3. Pass the router's nonce to InthProvider.** In `src/routes/__root.tsx` from the [quickstart](/docs/frameworks/tanstack-start/quickstart#resolve-consent-in-the-root-route), read the nonce with `useRouter` and pass `options={{ nonce }}`:

{/* example: fragment */}

```tsx title="src/routes/__root.tsx (partial)"
const nonce = useRouter().options.ssr?.nonce;

<InthProvider
  state={consent}
  options={{ nonce }}
  scripts={scripts}
>
```

If you render `ConsentTheme`, pass the same nonce: `<ConsentTheme theme={theme} nonce={nonce} />`.

`InthProvider` reads `options.nonce` on mount and stamps it onto every `<script>` inserted by the script loader (unless overridden per script) and onto the inline pre-hydration start script. If CSP blocks that inline script, the script loader starts those entries after hydration instead. Never serve nonced HTML from a shared cache.

## What the nonce does not cover

- **Nested scripts loaded by vendors**, such as tags inside a tag manager. `'strict-dynamic'` permits them; without it, list each vendor's script hosts in `script-src`.
- **Inline `style` attributes.** Browser-side React style updates are not blocked by CSP, but if SSR HTML triggers `Refused to apply inline style`, add `style-src-attr 'unsafe-inline'` because nonces do not apply to `style` attributes.
- **Embeds, images, and API calls.** Add vendor hosts to `frame-src`, `img-src`, and `connect-src`, such as `https://www.youtube-nocookie.com` for YouTube embeds in `ConsentGate`.
- **DevTools panel.** DevTools injects an un-nonced `<style>` element, so load it only in development.

## Allow your Inth project

Which origins the browser contacts depends on your [rendering setup](/docs/frameworks/tanstack-start/rendering):

| Setup | Browser requests | Policy |
| --- | --- | --- |
| Quickstart | `/v1/consent/init` and `/v1/consent/records` on your Inth project URL | `connect-src` with your Inth project origin |
| Same-origin route with `routePrefix: '/api/inth'` | `/api/inth/v1/consent/init` on your origin, `/v1/consent/records` on your Inth project URL | `connect-src 'self'` plus your Inth project origin |
| Same-origin route with `proxy: true` and `routePrefix: '/api/inth'` | All consent requests on your origin | `connect-src 'self'` |

Under an IAB TCF policy, the browser also fetches the Global Vendor List. With `routePrefix`, `/api/inth/v1/consent/init` serves it under `'self'`; otherwise allow the vendor list host in `connect-src`. See [IAB TCF](/docs/frameworks/tanstack-start/iab).

## Prerendered pages and SPA mode

Prerendered pages are shared across all visitors and cannot use per-request nonces. Use host allowlists and hashes instead:

- List `'self'` and each vendor script host in `script-src`.
- Allow `consentPrefetchHead` and `ConsentTheme` by copying their `sha256-...` hashes from the browser console when CSP is enforced, updating the hashes whenever their options or theme change.

Consult TanStack Start's docs for allowing TanStack Start's own inline scripts on prerendered pages.

## Verify

Build the app, start the production server with CSP enforced rather than report-only, and open DevTools under an opt-in policy.

1. Confirm the banner renders with your theme colors and the console shows zero `Refused to` errors for Inth, your project URL, or vendors.
2. In DevTools Console, verify `<style id="inth-theme">` and `<meta property="csp-nonce">` expose the response nonce via their `.nonce` property.
3. Before a choice, confirm DevTools Network shows zero vendor requests.
4. Click **Accept All**. Confirm script loader `<script>` elements (with `inth-` IDs) carry the nonce and vendor requests appear.
5. Confirm `POST /v1/consent/records` succeeds.
6. Reload and confirm the response issues a new nonce applied to all elements.
