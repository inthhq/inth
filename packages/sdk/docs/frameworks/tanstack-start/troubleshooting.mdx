Diagnose and resolve common build, SSR, proxy, and script issues in TanStack Start apps using `@inth/tanstack-start`.

## vite build or vite dev can't fetch the manifest

**Check.** Read the error or warning message. `consentManifest()` downloads the policy once per build and on first server load in `vite dev`. By default (`onBuildError: 'runtime'`), if the fetch fails or exceeds 10 seconds, both `vite build` and `vite dev` log a warning and set `snapshot` to `undefined` so the server falls back to runtime fetching. With `onBuildError: 'fail'` or `INTH_ON_BUILD_ERROR=fail`, `vite build` exits with an error starting with `@inth/tanstack-start/build: could not fetch the consent manifest from <url> during the build`.

| Message | Fix |
| --- | --- |
| `no backend URL is set` | Set `VITE_INTH_PROJECT_URL` (falling back to `VITE_C15T_BACKEND_URL` if unset) in `.env` or build env, or pass `projectUrl` to `consentManifest()` |
| `skipped the consent manifest fetch because ... is not an absolute http(s) URL` | Use your absolute Inth project URL such as `https://your-project.inth.app`, not `/api/inth`. With `onBuildError: 'fail'`, this raises `build-time manifests require an absolute upstream URL` |
| `/v1/consent/manifest responded 404` | Copy the exact project URL from Inth, including any path prefix |
| `/v1/consent/manifest responded` with another status | Confirm the Inth project exists and the build machine can reach it |
| `/v1/consent/manifest returned an invalid consent manifest` | Verify the URL points to your Inth project rather than an HTML page or redirect |
| `fetch failed` (`ENOTFOUND` or network error) or `no response within 10 seconds` | Allow outbound HTTPS from the build machine, override `onBuildError: 'fail'` with `INTH_ON_BUILD_ERROR=runtime`, or switch to [runtime fetching](/docs/frameworks/tanstack-start/rendering#await-consent-in-the-loader) |

## snapshot is undefined

**Check.** Log `snapshot` from `@inth/tanstack-start/generated` inside your server function. In the browser bundle, `snapshot` is always `undefined` by design. On the server, it is `undefined` when `consentManifest()` is missing from `vite.config.ts`, the fetch failed under the default `'runtime'` mode (or `INTH_ON_BUILD_ERROR=runtime`), or the project URL is relative.

**Fix.** Add `consentManifest()` before `tanstackStart()` in `vite.config.ts` or resolve the [manifest fetch error](#vite-build-or-vite-dev-cant-fetch-the-manifest), then restart `vite dev` or rebuild. While `snapshot` is `undefined`, the server fetches and caches the policy at runtime.

## The banner is not in the server HTML

**Check.** View page source under an opt-in policy and search for `data-testid="consent-banner-root"`.

| Cause | Fix |
| --- | --- |
| Root loader streams the promise with `streamBanner: false` | Expected: the banner mounts after hydration. Remove `streamBanner: false` or await the loader; see [Rendering](/docs/frameworks/tanstack-start/rendering) |
| Page is prerendered or app runs in SPA mode | Expected: the browser resolves consent after load |
| Runtime fetch exceeded 500 ms on cold start | Server rendered without consent and the browser resolved it. Subsequent requests hit cache; increase `timeoutMs` on `createConsentStateHandler` if needed |
| No country header reaches the server | Verify your host or CDN sends a geo header; see [Geography headers](/docs/frameworks/tanstack-start/geography-headers). Without one, your fallback policy applies |
| Visitor already has a stored choice | Expected: the server reads the `inth` cookie and omits the banner |

## The server function fails to resolve at runtime

**Check.** Inspect where `createServerFn()` is called. TanStack Start's compiler detects server functions only at top-level module declarations; calls inside helper functions, conditionals, or npm packages fail.

**Fix.** Declare `const getConsentState = createServerFn(...).handler(createConsentStateHandler())` at top level in your route module, matching the [quickstart](/docs/frameworks/tanstack-start/quickstart#resolve-consent-in-the-root-route).

## A serialization error mentions a function

**Check.** Inspect what your server functions and loaders return. Vendor script helpers and transports from `@inth/react` contain functions and cannot be serialized (`hosted()` and `manifest()` from `@inth/tanstack-start` are plain serializable data).

**Fix.** Return only the consent state from the server function. Import `scripts` in the root route module and pass them directly to `InthProvider`.

## The same-origin setup never renders the banner on the server

**Check.** Inspect `projectUrl` passed to `createConsentStateHandler`, plus `VITE_INTH_PROJECT_URL` and `VITE_C15T_BACKEND_URL`. Passing `/api/inth` as `projectUrl` skips server fetching to avoid a server rendering deadlock.

**Fix.** Keep `VITE_INTH_PROJECT_URL` set to your absolute Inth project URL, and pass `routePrefix: '/api/inth'` and `proxy: true` to `createConsentStateHandler` instead.

## Saves through /api/inth fail with 403 or a challenge page

**Check.** A WAF or bot challenge (such as Vercel Attack Challenge Mode or Cloudflare Super Bot Fight Mode) blocks the server-side proxied `POST /v1/consent/records`.

**Fix.** Exempt consent paths from browser challenges using the `x-inth-proxy: @inth/tanstack-start` header. If rate limits group all visitors behind one IP and your host overwrites `x-forwarded-for`, set `trustForwardedHeaders: true` on `createConsentRoute`.

## The browser calls /api/inth/v1/consent/init and gets a 404

**Check.** `InthProvider` calls `/api/inth/v1/consent/init` only when `createConsentStateHandler` sets `routePrefix: '/api/inth'`. Verify `src/routes/api/inth/$.ts` is mounted.

**Fix.** Mount the [same-origin route](/docs/frameworks/tanstack-start/rendering#keep-consent-requests-on-your-origin), or remove `routePrefix` so the browser calls your Inth project directly.

## InthProvider throws that it needs a project URL

**Check.** The page throws an error from `InthProvider` such as:

- ``inth: `projectUrl` is required. Set it in your config, or use `mode: testing()` from a /testing entry in tests.``

Neither the loader state nor `consentManifest()` supplied a project URL (for example, `state={{}}` without the Vite plugin).

**Fix.** Add `consentManifest()` to `vite.config.ts` and set `VITE_INTH_PROJECT_URL` (falling back to `VITE_C15T_BACKEND_URL` if unset). To run offline for tests, pass `mode: testing()` to `createConsentStateHandler` or `state={{ mode: testing() }}`.

## A vendor loads before the visitor chooses

**Check.** Search route `head()` definitions, your root component, and any tag manager for vendor `<script>` tags or SDK initializers.

**Fix.** Remove every loader outside `InthProvider`'s `scripts` prop. Inth only gates scripts registered with it; see [Scripts](/docs/frameworks/tanstack-start/scripts).

## Inspect the active policy

Render this temporary component inside `InthProvider` to inspect resolved state without recording a choice:

{/* example: fragment */}

```tsx title="src/components/consent-policy-debug.tsx"
import { useSnapshot } from '@inth/tanstack-start';

export function ConsentPolicyDebug() {
	const snapshot = useSnapshot();
	const resolution = snapshot.resolution;

	return (
		<pre>
			{JSON.stringify(
				{
					status: resolution.status,
					policy: resolution.status === 'matched' ? resolution.policy.id : null,
					prompt: snapshot.promptRequirement,
					location: snapshot.location,
				},
				null,
				2
			)}
		</pre>
	);
}
```

`location` shows the country and region resolved on the server. Remove the component after debugging.

## Names from an earlier alpha are missing

**Check.** TypeScript reports missing exports or props such as `createConsentServerRoute`, `DEFAULT_INIT_ROUTE`, or `projectUrl` on `InthProvider`.

**Fix.** Update to the current Inth API:

| Removed | Use instead |
| --- | --- |
| `InthProvider` `projectUrl` and `routePrefix` props | `createConsentStateHandler({ routePrefix })` so state carries URL, mode, and route prefix |
| `InthProvider` `initRoute` prop and `DEFAULT_INIT_ROUTE` | `createConsentStateHandler({ routePrefix: '/api/inth' })` (no default route) |
| `createConsentServerRoute` (`manifestGET`, `initGET`, `proxyHandler`) | `createConsentRoute()`, returning `GET` plus write handlers when `proxy: true` |
| `createConsentStateHandler({ projectUrl, manifest })` | `createConsentStateHandler()`, reading from `consentManifest()`, or `{ snapshot }` |
| `manifestUrl` on state handler | `mode: manifest({ manifestUrl })` |
| `ConsentManifestOptions`, `resolveStrictestDefaultInit` | `ResolveConsentOptions`, `resolveUnknownLocationInit` |
| Silent fallback to local mode when URL is unset | Pass `mode: testing()` explicitly for offline mode |
| `hosted`, `offline`, and `manifest` as transport functions | Pass them as serializable mode data to `createConsentStateHandler({ mode })` |

For shared package and API renames, see [Migrate from c15t](/docs/migrate-from-c15t). Replace deprecated `Frame` imports with `ConsentGate`.

## The banner or dialog fails to load

**Check.** Open the console. A warning or error from Inth that says the banner, the dialog or the engine failed to load means the browser could not download one of Inth's chunks, for example during a dropped connection or a deploy that removed old files.

After a failure the page stays as it is: Inth never reloads it, because a reload would discard what the visitor typed into your page. Nothing is recorded, and the banner stays or shows again. The next tap, open or snapshot tries the download again. Your bundler loads chunks with native `import()`. Firefox 155 or later, Chrome 156 or later, and Safari send a new request for a chunk that failed. Earlier Chromium and Firefox keep the failure for the life of the page; there Inth loads the chunk again from its URL with `inth-retry=<n>` added, which works unless another chunk imports it by its plain URL. A chunk whose own dependency failed stays failed in every browser.

**Fix.** Nothing on the page. The next page load downloads the chunk again. If the failures follow a deploy, keep the previous build's chunk files available until cached pages that link to them expire. See [a consent chunk fails to load](/docs/guides/troubleshooting#a-consent-chunk-fails-to-load) for which browsers and builds can retry on the same page.
