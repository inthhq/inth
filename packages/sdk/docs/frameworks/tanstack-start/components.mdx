`@inth/tanstack-start` exports `InthProvider` and re-exports every UI component and hook from `@inth/react` under one import path. All components render on the server using the state resolved by your root loader.

## Import from @inth/tanstack-start

| Component | Renders | Reference |
| --- | --- | --- |
| `InthProvider` | The consent runtime seeded with your root loader's state | [Below](#inthprovider) |
| `ConsentBanner` | The consent banner when the policy requires one | [ConsentBanner](/docs/frameworks/tanstack-start/components/consent-banner) |
| `ConsentDialog` | The preference dialog | [ConsentDialog](/docs/frameworks/tanstack-start/components/consent-dialog) |
| `ConsentWidget` | Preference controls inline on a privacy page | [ConsentWidget](/docs/frameworks/tanstack-start/components/consent-widget) |
| `ConsentDialogLink` | An unstyled button that opens the dialog, suited for footers | [ConsentDialogLink](/docs/frameworks/tanstack-start/components/consent-dialog-link) |
| `ConsentDialogTrigger` | A floating, draggable corner button that opens the dialog. `ConsentDialogTriggerToolbar` adds app actions beside it | [ConsentDialogTrigger](/docs/frameworks/tanstack-start/components/consent-dialog-trigger) |
| `ConsentGate` | Its children while a category is allowed, or a placeholder otherwise | [ConsentGate](/docs/frameworks/tanstack-start/components/consent-gate) |
| `ConsentTheme` | A `<style>` element with your theme tokens | [Customize](/docs/frameworks/tanstack-start/customize) |
| `DevTools` from `@inth/react/devtools` | A development panel for consent state and scripts | [DevTools](/docs/frameworks/tanstack-start/components/dev-tools) |

Render all consent components inside a single `InthProvider` from `@inth/tanstack-start`. Do not also mount `@inth/react`'s `InthProvider`, because `@inth/tanstack-start`'s `InthProvider` already wraps it.

## InthProvider

`InthProvider` wraps your app in `src/routes/__root.tsx`, creating the runtime from server-resolved state so server HTML matches the first client render. See the [quickstart](/docs/frameworks/tanstack-start/quickstart#resolve-consent-in-the-root-route).

| Prop | Purpose |
| --- | --- |
| `state` | Required. Loader consent state, a promise for a [streamed loader](/docs/frameworks/tanstack-start/rendering#stream-the-page-while-consent-resolves), or `{}` for [prerendered or SPA pages](/docs/frameworks/tanstack-start/rendering#spa-mode-prerendered-pages-and-static-hosts) |
| `scripts` | Consent-gated vendor scripts. See [Scripts](/docs/frameworks/tanstack-start/scripts) |
| `vendors` | Vendors listed under their category with individual switches |
| `networkBlocker` | Rules holding `fetch` and `XMLHttpRequest` calls until their category is allowed |
| `clearOnRevocation` | Cookies and storage keys deleted when a category is denied |
| `persistence` | Stores the visitor's choice. Enabled by default |
| `scriptLoader` | Options for the script loader module |
| `options` | Any other `InthProvider` option, such as `theme`, `i18n`, `presentation`, `callbacks`, `consentCategories`, `reloadOnConsentRevoked`, or `preloadDialog` |

`state` carries the project URL, mode, and route prefix from `createConsentStateHandler`. With `state={{}}`, `InthProvider` reads the URL from `consentManifest()` and uses `manifest()`, throwing if neither supplies a URL unless `mode` is `testing()`. `options.mode` overrides the state's mode.

`InthProvider` initializes its runtime once on mount and ignores later `state` prop changes. Keep it in the root route so navigation never remounts it.

The root entry also exports `consentPrefetchHead` and `buildPrefetchScript` for prerendered or SPA pages.

## Server and other entry points

| Import | Exports | Use |
| --- | --- | --- |
| `@inth/tanstack-start` | `manifest`, `hosted`, `testing` | Serializable mode config for `createConsentStateHandler({ mode })`. See [Consent modes](/docs/concepts/modes) |
| `@inth/tanstack-start/server` | `createConsentStateHandler`, `resolveConsent`, `consentLoaderOptions`, `mergeInitIntoConsentState` | Resolve visitor state in a server function |
| `@inth/tanstack-start/middleware` | `consentRequestMiddleware` | Normalize location, language, and GPC headers on every request. See [Geography headers](/docs/frameworks/tanstack-start/geography-headers) |
| `@inth/tanstack-start/api` | `createConsentRoute` | Serve `/api/inth/*` from `src/routes/api/inth/$.ts` |
| `@inth/tanstack-start/build` | `consentManifest` | Vite plugin bundling the policy manifest at build time. See [Quickstart](/docs/frameworks/tanstack-start/quickstart#bundle-your-policy-at-build-time) |
| `@inth/tanstack-start/generated` | `snapshot`, `projectUrl` | Build-time manifest and project URL (`snapshot` is `undefined` in browser builds) |
| `@inth/tanstack-start/static` | `createStaticConsentResolver`, `loadStaticManifest`, `createStaticManifestModule`, `resolveUnknownLocationInit` | Lower-level build-time manifest helpers. See [Rendering](/docs/frameworks/tanstack-start/rendering#spa-mode-prerendered-pages-and-static-hosts) |
| `@inth/tanstack-start/headless` | Headless hooks | [Custom markup](/docs/frameworks/tanstack-start/headless) |
| `@inth/tanstack-start/components/consent-dialog-link` | `ConsentDialogLink` only | Import the link without pulling in the full adapter |

Call `resolveConsent({ request })` directly inside server routes or middleware that already hold a `Request`. Import `/server`, `/middleware`, and `/api` only in server code.

## IAB TCF components

Import `IABProvider`, `IABConsentBanner`, and `IABConsentDialog` from `@inth/react/iab` and mount them inside `InthProvider` next to `ConsentBanner` and `ConsentDialog`. The built-in banner and dialog stay closed under an `iab` policy. See [IAB TCF](/docs/frameworks/tanstack-start/iab).
