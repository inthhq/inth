Hold browser `fetch` and `XMLHttpRequest` calls to vendor domains in TanStack Start until their consent category is allowed.

## Add rules

Pass `networkBlocker` as a top-level prop on `InthProvider` as a backstop for beacons or API calls sent by bundled SDKs. Prefer registering vendor SDKs through [`scripts`](/docs/frameworks/tanstack-start/scripts) first so they do not run before consent.

{/* example: fragment */}

```tsx title="src/routes/__root.tsx"
const networkBlocker = {
	rules: [
		{
			id: 'google-analytics',
			domain: 'google-analytics.com',
			category: 'measurement',
		},
		{
			id: 'meta-pixel',
			domain: 'facebook.com',
			pathIncludes: '/tr',
			category: 'marketing',
		},
	],
};

<InthProvider
	state={consent}
	scripts={scripts}
	networkBlocker={networkBlocker}
>
```

The network blocker runs in the browser only and never intercepts requests made by server functions or server routes.

## Verify the blocked requests

Open DevTools Network in a private window under an opt-in policy.

1. Before a choice, confirm requests matching a rule do not appear and the console logs each blocked request.
2. Allow the rule's category and save. Confirm matching requests fire.
3. Reject, reload, and confirm they stay absent.
