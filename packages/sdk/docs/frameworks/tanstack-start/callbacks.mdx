Run browser callbacks in TanStack Start when a visitor records a choice, effective permissions change, a request fails, or a revocation reload is about to happen.

## Pass callbacks to InthProvider

Define callbacks in their own module:

<include src="../../shared/examples/tanstack-start/callbacks.mdx" />

Import `callbacks` in `src/routes/__root.tsx` and pass it under `options` on `InthProvider`:

{/* example: fragment */}

```tsx title="src/routes/__root.tsx"
<InthProvider
  state={consent}
  scripts={scripts}
  options={{ callbacks }}
>
```

Import `callbacks` in the route component rather than returning functions from a root loader or server function, because loader data must be serializable.

`InthProvider` subscribes callbacks after mounting in the browser and never invokes them during SSR. It always invokes the latest `callbacks` object without remounting.

## Available callbacks

| Callback | Runs when | Receives |
| --- | --- | --- |
| `onChoiceRecorded` | The visitor clicks Accept All, Reject All, or Save Settings in built-in UI or via `useSaveConsents()`. | `snapshot`, state after the choice; `confirmed`, categories recorded by this action; `actionAt`, millisecond timestamp |
| `onPermissionsChanged` | Any effective permission changes value. | `snapshot`, state after the change; `previous`, permissions before it |
| `onError` | A browser consent command fails, such as a failed `/v1/consent/init` or rejected `/v1/consent/records` save. | `error`, message string |
| `onBeforeConsentRevocationReload` | A save or one-click opt-out revokes a granted category or vendor, right before Inth reloads the page. Privacy signals and backend-synced opt-outs do not reload. | `preferences`, permissions after the withdrawal |

The full object type is `InthProviderCallbacks` from `@inth/tanstack-start`. Callbacks run after state updates, so `snapshot` and hooks such as `useConsent()` already return the new values.

Server-side `resolveConsent` has no error callback. If a runtime manifest fetch fails or hits `timeoutMs`, the loader returns request-only state and the browser resolves consent after hydration, where any failure reaches `onError`.

## onChoiceRecorded or onPermissionsChanged

`onChoiceRecorded` fires only on an explicit visitor action. `onPermissionsChanged` fires whenever effective permissions change for any reason:

| Event | `onChoiceRecorded` | `onPermissionsChanged` |
| --- | --- | --- |
| Visitor accepts, rejects, or saves | Yes | Yes, if a permission changed |
| Policy resolves in the browser and allows categories before any choice | No | Yes |
| Global Privacy Control turns off a grant | No | Yes |
| Recorded choice expires | No | Yes |
| Visitor dismisses a notice | No | No |

Use `onChoiceRecorded` for consent analytics and audit trails because it fires only when the visitor acts. Use `onPermissionsChanged` to start or stop app code, never as proof of consent and never to save consent. See [how consent works](/docs/concepts/how-consent-works#a-permission-is-not-a-recorded-choice).

Dismissing a notice records no choice and changes no permission; read it with `useNoticeDismissal()`. For reactive UI inside components, use [hooks](/docs/frameworks/tanstack-start/hooks).

## Before a revocation reload

Removing a `<script>` tag cannot stop code already executing in memory, so Inth reloads the page after a save revokes a previously granted category or vendor. The reload waits for the save request to finish, then runs `onBeforeConsentRevocationReload` synchronously right before reloading. Use it for vendor shutdown calls or flushing queued events, and keep it synchronous because the reload does not await promises.

Expiry, policy changes, and privacy signals do not reload the page because they are not triggered by a visitor save.

To manage revocation yourself, pass `options={{ reloadOnConsentRevoked: false }}` on `InthProvider`. Revoked code then stays active until the next full page load, and `onBeforeConsentRevocationReload` never runs.

## Verify

1. Add the callbacks, open DevTools Console and Network, clear site data, and reload under a policy showing a banner.
2. Click **Accept All**. Confirm both `onChoiceRecorded` and `onPermissionsChanged` log and `/v1/consent/records` appears in Network.
3. Reload and confirm `onChoiceRecorded` does not fire again.
4. Open Privacy settings, turn off an allowed category, and save. Confirm `onBeforeConsentRevocationReload` logs before the page reloads and that category's vendor requests stay absent afterwards.
