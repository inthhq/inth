## Render your own banner

`@inth/tanstack-start/headless` re-exports all hooks from `@inth/react/headless`. Render your custom banner inside `InthProvider` in place of `ConsentBanner`, keeping `ConsentDialog` and a persistent preferences link mounted:

{/* example: fragment */}

```tsx title="src/components/consent-banner.tsx"
import {
	StreamedConsentSurface,
	useBannerCopy,
	useConsentLabels,
	useHeadlessConsentUI,
} from '@inth/tanstack-start/headless';

function BannerContent() {
	const { banner, performAction, openDialog } = useHeadlessConsentUI();
	const { title, description } = useBannerCopy();
	const labels = useConsentLabels();

	if (!banner.isVisible) {
		return null;
	}

	return (
		<section role="region" aria-label={title}>
			<h2>{title}</h2>
			<p>{description}</p>
			{banner.preferenceControls.map((right) => (
				<button key={right} type="button" onClick={openDialog}>
					{labels.preferenceControls[right]}
				</button>
			))}
			{banner.actionGroups.map((group) => (
				<div key={group.join('-')}>
					{group.map((action) => (
						<button
							key={action}
							type="button"
							data-primary={banner.primaryActions.includes(action) || undefined}
							onClick={() => performAction(action)}
						>
							{labels.actions[action]}
						</button>
					))}
				</div>
			))}
		</section>
	);
}

export function Banner() {
	return (
		<StreamedConsentSurface>
			<BannerContent />
		</StreamedConsentSurface>
	);
}
```

With an awaited root loader, `banner.isVisible` is already `true` on the server so your banner renders in the first HTML. With a [streamed loader](/docs/frameworks/tanstack-start/rendering#stream-the-page-while-consent-resolves), `StreamedConsentSurface` wraps a `Suspense` boundary around the consent promise so your banner streams before hydration. Call headless hooks inside `StreamedConsentSurface`; hooks above it read unresolved state. `options={{ streamBanner: false }}` disables streaming for custom banners just like the built-in banner. On prerendered pages, the banner appears after hydration.

Check `useModel()` before rendering custom surfaces: it returns `null` before resolution and `'none'` when no consent UI is owed.
