Load vendor scripts in TanStack Start only when their consent category is allowed, and clean up when visitors withdraw consent.

## Register vendor scripts

Pass vendor helpers to `InthProvider` through its `scripts` prop. The [quickstart](/docs/frameworks/tanstack-start/quickstart) defines PostHog in `src/routes/__root.tsx`:

<include src="../../shared/examples/tanstack-start/scripts.mdx" />

Pass the array to `InthProvider`:

{/* example: fragment */}

```tsx title="src/routes/__root.tsx"
<InthProvider state={consent} scripts={scripts}>
```

Move `scripts` to a shared file such as `src/scripts.ts` if multiple modules need it.

Always import vendor helpers in route modules, never inside a server function: server function return values must be serializable, and vendor loaders contain callbacks. Scripts run only in the browser.

Each `@inth/integrations` helper sets its own category and stable `id`. Remove any duplicate loader for the same vendor from route `head()` entries or app startup code so it loads only through Inth. See [Integrations](/docs/integrations/overview) and [Custom integrations](/docs/integrations/building-integrations).

## What happens when consent changes

- **Allowed.** Inth loads the script or starts its SDK the first time its category is allowed. With server-rendered state, most `@inth/integrations` helpers already permitted by consent or `alwaysLoad` start before hydration; with streamed state, they start when the consent chunk arrives. See [Rendering](/docs/frameworks/tanstack-start/rendering).
- **Denied later.** Inth removes the script element and reloads the page once the save settles because already-executed code continues running in memory. Set `options={{ reloadOnConsentRevoked: false }}` on `InthProvider` only if every gated vendor stops cleanly on its own.
- **`alwaysLoad` helpers.** Integrations such as Google Consent Mode load before consent and pass consent state to the vendor. Check each vendor guide before expecting zero initial requests.

## Embeds and other requests

`scripts` gates vendor code Inth loads for you. For other third-party requests:

- [Embeds](/docs/frameworks/tanstack-start/embeds) blocks iframes with `ConsentGate` or the iframe blocker.
- [Network blocker](/docs/frameworks/tanstack-start/network-blocker) holds matching `fetch` and XHR calls until their category is allowed.

## Clear stored data after revocation

Removing a script does not delete cookies or storage keys it already wrote. Pass `clearOnRevocation` as a top-level prop on `InthProvider` to clear each category's entries when denied. `InthProvider` reads it once on mount. See [Clear on revocation](/docs/frameworks/tanstack-start/clear-on-revocation).

## Let visitors turn off one vendor

Optionally let visitors allow a category such as marketing while turning off one vendor in it. Pass `vendors` as a top-level prop on `InthProvider`; `@inth/integrations` helpers already carry their vendor slug. See [Vendor consent](/docs/frameworks/tanstack-start/vendor-consent).

## Send your own analytics events

`useEventDispatcher()` from `@inth/tanstack-start` returns an event dispatcher that checks consent before sending events to registered `scripts`. Render a component watching the router location to track pageviews:

<include src="../../shared/examples/tanstack-start/analytics-events.mdx" />

Call `events.track('sign_up', { method: 'email' })` inside event handlers. `track` sends to every registered script with an event API and drops events while `measurement` is denied. `pageview` sends only to integrations listed in `pageviews`, recording the first path without sending. All dispatchers share one pageview history for the provider's lifetime. See [send events only to allowed integrations](/docs/integrations/overview#send-events-only-to-allowed-integrations).

## Check the scripts

Open DevTools Network in a private window, filter by each vendor domain, and reload.

1. Before a choice under an opt-in policy, confirm zero vendor scripts load and page source contains no vendor `<script>` tags.
2. Allow one category and confirm only that category's vendors load.
3. Turn the category off and confirm the page reloads without the vendor.
4. Reload again and confirm the rejection holds and server HTML renders no banner.

[Verify consent](/docs/guides/verify-consent) has the full checklist.
