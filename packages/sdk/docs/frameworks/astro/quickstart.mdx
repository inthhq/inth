Add a consent banner and preference dialog to an Astro site on static or server output. The banner renders as plain `.astro` HTML, the dialog loads on demand, and analytics wait until consent allows them.

<Prompt title="Add Inth consent to this Astro site" description="Paste into Claude Code, Codex, Cursor or another coding agent at the root of your app.">
  Add Inth consent management to this Astro site.

  1. Check `astro.config.mjs` for `output: 'server'` with an adapter versus `output: 'static'`, and check if `@astrojs/svelte`, `@astrojs/react`, or `@astrojs/vue` is already installed.
  2. Install `@inth/astro` and `@inth/integrations`. If no UI framework integration is installed, install `@astrojs/svelte` and `svelte` for the preference dialog island. Read `node_modules/@inth/astro/AGENTS.md`, then follow the Astro quickstart it links to, in order. Do not guess the API from memory.
  3. Set `PUBLIC_INTH_PROJECT_URL` in `.env`. Ask me for my project URL, and use `https://example-inth.inth.app` only for a demo. `PUBLIC_INTH_PROJECT_URL` wins over any legacy `PUBLIC_C15T_BACKEND_URL`.
  4. In `astro.config.mjs`, register the UI framework before `inth()` from `@inth/astro`. Use `inth()` on server output and `inth({ mode: hosted() })` on static output. Pass `ui: 'react'` or `ui: 'vue'` if multiple UI frameworks are registered.
  5. Create `src/inth.client.ts` exporting `{ scripts: [...] }` as default. Move analytics and marketing scripts into it with `@inth/integrations`, carrying over settings like PostHog's `region` or `apiHost`, and remove old `<script>` tags or SDK imports. If a vendor has no helper, tell me.
  6. In the shared layout, render `ConsentScript` in `<head>`, plus `ConsentBanner`, `ConsentDialog`, and a footer `ConsentDialogLink` from `@inth/astro/components`.
  7. Run `astro build` and `astro preview`. Verify no vendor request fires before consent, rejection survives reload, and granting analytics from the footer loads the vendor.

  Then list the files you changed, any script still outside consent, and how you checked the requests.
</Prompt>

## Prerequisites

- An Astro 5, 6, or 7 site on static or server output. Not on Astro? See the [framework list](/docs/frameworks).
- An [Inth project](https://inth.com/dashboard/sign-up?framework=astro) with your site's origin in its trusted origins.

## Install the SDK

<CommandTabs command="@inth/astro @astrojs/svelte svelte @inth/integrations" mode="install" />

`ConsentBanner` renders plain `.astro` HTML, while `ConsentDialog` loads on demand as a Svelte, React, or Vue island. Reuse your existing framework by swapping `@astrojs/svelte svelte` for `@astrojs/react react react-dom` or `@astrojs/vue vue`. With multiple UI frameworks registered, pass `ui: 'react'` or `ui: 'vue'` to `inth()`.

## Set the project URL

Add your absolute Inth project URL to `.env` and your host's build settings:

```sh title=".env"
PUBLIC_INTH_PROJECT_URL=https://example-inth.inth.app
```

The URL is public, not a secret. `https://example-inth.inth.app` is a demo project. Rebuild after changing it. `PUBLIC_INTH_PROJECT_URL` wins over any legacy `PUBLIC_C15T_BACKEND_URL`, which is read as a fallback if unset.

## Configure the integration

Register your UI framework before `inth()` in `astro.config.mjs`. Pick the config matching your output.

### Server output

<include src="../../shared/examples/astro/server-config.mdx" />

`inth()` defaults to `manifest()`, bundling your policy at build time so responses include the banner in the first HTML. Replace `@astrojs/node` with your adapter. Rebuild after policy edits, or set `mode: manifest({ source: 'runtime' })`. See [what happens when the download fails](/docs/concepts/modes#what-happens-when-the-download-fails).

### Static output

<include src="../../shared/examples/astro-static/static-config.mdx" />

`hosted()` resolves consent in the browser against Inth's `/v1/consent/init` with no adapter.

`inth()` serializes options to JSON and throws on functions; put vendor helpers and callbacks in `src/inth.client.ts`.

## Check it works

Run `astro build` and `astro preview`, then open the site in a private window with DevTools open on the Network panel.

1. Under an opt-in policy, the banner appears and no PostHog request fires. On server output, page source contains the banner markup.
2. Click **Reject All**, then reload. The banner stays closed and PostHog does not load.
3. Open **Privacy settings**, turn on **Analytics**, and click **Save Settings**. PostHog loads.
4. Turn **Analytics** off and click **Save Settings**. The page reloads and PostHog does not load.

See [Astro troubleshooting](/docs/frameworks/astro/troubleshooting) and [Verify consent](/docs/guides/verify-consent).
