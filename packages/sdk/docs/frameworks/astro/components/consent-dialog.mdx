## Add the dialog to your layout

Render one `ConsentDialog` in the layout that wraps every page:

<include src="../../../shared/examples/astro/layout.mdx" />

`ConsentDialog` renders an empty host element on the server. The preference
dialog mounts into the page the first time something opens it:

- The banner's **Customize** button, or a "Manage preferences" or "Do not sell
  or share my data" button on a notice.
- A [`ConsentDialogLink`](/docs/frameworks/astro/components/consent-dialog-link).
- A link to `#inth-preferences`, when the page loads with that hash.
- `openDialog()` from [`@inth/astro/client`](/docs/frameworks/astro/client-api#open-and-close-dialogs).

## Props

| Prop | Type | Default | Effect |
| --- | --- | --- | --- |
| `preload` | `boolean` | `false` | Downloads the dialog once the browser is idle, on every page that renders it |
| `legalLinks` | `('privacyPolicy' \| 'cookiePolicy' \| 'termsOfService')[] \| null` | None | Which links from the integration's `legalLinks` the dialog shows, the same list `ConsentBanner` takes |

## When the dialog downloads

A visitor who only accepts or rejects from the banner never downloads the
dialog. The download starts before the click, when the pointer moves over a
control that opens the dialog or keyboard focus reaches one. On a touch
screen, the tap itself starts it, so the first open can wait for the download.

With `preload`, the dialog downloads in the browser's first idle period, or
after two seconds in browsers without `requestIdleCallback`. Use it when the
first open must feel instant for every visitor. It costs a background download
on each page, including for visitors who never open the dialog.

To download the dialog from your own code, call `preloadDialog()` from
`@inth/astro/client`.

## Which framework renders it

The dialog is the `ConsentDialog` component of the framework that the
integration's `ui` option names:

| `ui` | Renders with | Astro integration to install |
| --- | --- | --- |
| `'svelte'` (default) | `@inth/svelte` | `@astrojs/svelte` and `svelte` |
| `'react'` | `@inth/react` | `@astrojs/react`, `react` and `react-dom` |
| `'vue'` | `@inth/vue` | `@astrojs/vue` and `vue` |

Pick the framework your site already ships, so visitors do not download a
second one for a single dialog. See
[Dialog islands and your own islands](/docs/frameworks/astro/islands).

## What the dialog contains

The dialog lists the categories the policy covers, each with a switch, and
offers Accept All, Reject All and Save Settings. `necessary` is always on. The dialog
follows the integration's `theme`, `presentation.preferences` and
`consentCategories`. With `vendors` declared, each category also lists its
vendors with a switch per vendor. See
[vendor consent](/docs/frameworks/astro/vendor-consent).

To link your policies from the dialog, define them in the integration's
`legalLinks` option and list the keys in the `legalLinks` prop:

{/* example: fragment */}

```astro title="src/layouts/base.astro (partial)"
<ConsentDialog legalLinks={['privacyPolicy', 'cookiePolicy']} />
```

Inth passes the list to the Svelte, React or Vue dialog island. A key renders
only when the integration defines it. A link without a `label` reads as the
translated name for its type, such as "Privacy Policy" in English.

Save Settings, Accept All and Reject All record a choice and close the dialog. Turning
off a category that was allowed reloads the page, unless the integration sets
`reloadOnConsentRevoked: false`. See
[withdraw consent without reloading](/docs/frameworks/astro/scripts#withdraw-consent-without-reloading).

### Sale-and-sharing block and two-step opt back in

Under an `opt-out` policy, the dialog renders a sale-and-sharing block first,
above the category list and outside any accordion item. Under an `opt-in` or
other policy model, no block renders.

- Before the visitor opts out, the block shows the configured opt-out link
  title, a neutral status sentence, and an **Opt out** button. One click records
  the opt-out through the shared action without toggling a category or clicking
  **Save Settings**.
- Once an opt-out is held, the button disappears and the block shows the
  honored status line (`role="status"`), receipt sentence, recorded time, and
  local reference when this browser created the opt-out. Once the backend
  confirms the refused rights, the heading updates to name them. Before
  confirmation, it keeps the configured link title.
- When Global Privacy Control is not locking the opt-out, the block shows an
  **Opt back in…** link. Clicking **Opt back in…**, clicking **Accept All**, or
  turning `marketing` back on and clicking **Save Settings** (`measurement`
  when `marketing` is not in scope) opens a separate modal confirmation dialog
  instead of saving right away. Focus starts on **Stay opted out**, both buttons
  have equal prominence, and pressing Escape cancels with nothing saved.
  Confirming lifts a device opt-out or asks the backend to lift an account
  opt-out. Turning `measurement` on while `marketing` stays off saves without
  confirmation and keeps the opt-out held.
- While Global Privacy Control is active under a policy that maps it, restricted
  switches stay off and disabled, and no **Opt back in…** link renders. Under an
  `opt-in` policy, **Accept All** still lifts a held opt-out in one step.

The dialog does not open while no policy is resolved, or under a rule that owes
no consent interface. An `openDialog()` call made while `/v1/consent/init` is still in
flight waits for the answer.

## Stylesheets

The page carries only the banner's rules. The first time a visitor reaches
for the dialog, Inth links the dialog's stylesheet, plus the primitives
stylesheet for the
Svelte dialog, and waits for them to load before the dialog paints. On a
Tailwind CSS 3 site, the dialog's rules come with `@inth/astro/styles.css` on
every page, and Inth links only the primitives stylesheet. With
`styles: false`, import `@inth/astro/styles.css` yourself, which holds the
dialog's rules too, and `@inth/astro/primitives.css` for the Svelte dialog. See
[load the stylesheet yourself](/docs/frameworks/astro/customize#load-the-stylesheet-yourself).

## Across `ClientRouter` navigation

The dialog host is part of `<body>`, which `ClientRouter` replaces. When a
visitor navigates while the preference dialog or an opt-out or opt-in
confirmation dialog is open, Inth mounts it again on the new page, so it stays
open. A stylesheet Inth linked for the dialog carries over to the new page too.

## Accessibility

The dialog keeps the focus and keyboard behavior of its framework's
`ConsentDialog`. It opens as a modal dialog, and Escape closes it. Whether it
locks page scroll follows `presentation.preferences` in the integration
options. Every framework renders the same markup and labels, so the dialog
behaves the same whichever `ui` you pick.
