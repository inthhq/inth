## Add the link to your footer

Put one `ConsentDialogLink` in your footer, so visitors can change their
choice at any time. Its children are the label:

<include src="../../../shared/examples/astro/layout.mdx" />

`ConsentDialogLink` renders a plain `<button>` or `<a>` with no styles of
its own. By default it carries `data-inth-action="customize"`, and the same
shared listener the banner uses opens the dialog on click. With
`right="opt-out"` under an opt-out policy, the click follows the resolved
`presentation.optOutLink` title: `'do-not-sell'` (the default) records an
opt-out in one click and opens the confirmation view with a receipt (honored
status line, covered scope and backend-confirmed rights, recorded time, and
local reference when this browser created the opt-out), while
`'privacy-choices'` and `'california-privacy-choices'` open the preference
dialog without recording an opt-out. Programmatic calls to `client.optOut()`
still opt out in one step whatever `presentation.optOutLink` is set to. Under
other models the link opens the preference dialog.

## Props

| Prop | Type | Default | Effect |
| --- | --- | --- | --- |
| `kind` | `'preferences' \| 'iab'` | `'preferences'` | Which dialog to open |
| `right` | `'opt-out' \| 'preferences'` | None | Under an opt-out rule, `'opt-out'` follows `presentation.optOutLink`: `'do-not-sell'` records an opt-out in one click and opens the confirmation view, while `'privacy-choices'` and `'california-privacy-choices'` render with the California Privacy Protection Agency opt-out icon and open the preference dialog without recording an opt-out. When the slot is empty, uses the label resolved from `presentation.optOutLink` |
| `as` | `'button' \| 'a'` | `'button'` | Renders a `<button type="button">`, or an `<a href="#inth-preferences">` |
| `class` | `string` | None | Class names for your own styles |
| `noStyle` | `boolean` | `false` | Omits the bundled icon class name when `right="opt-out"` renders the Privacy Choices icon |

<include src="../../../shared/privacy-choices-link.mdx" />

Use `as="a"` when your footer styles links and not buttons. The click handler
cancels the link's navigation, so the page does not jump.

## When the link is hidden

The link renders with the `hidden` attribute while there is nothing to
manage:

- No policy is resolved yet, or the backend request failed.
- The resolved rule has `prompt: 'none'` and no rights, so it owes no consent
  interface.

The browser removes `hidden` as soon as a later `/v1/consent/init` answer supplies a rule
that owes one, and adds it back if the rule stops owing one.

If your own CSS sets `display` on the link, keep `[hidden]` hidden too, for
example with `.footer-link[hidden] { display: none; }`.

## Open the IAB preference center

With an IAB TCF policy, set `kind="iab"`:

{/* example: fragment */}

```astro title="src/layouts/iab.astro (partial)"
<ConsentDialogLink kind="iab">Privacy settings</ConsentDialogLink>
```

The page needs `IABConsentDialog` for `kind="iab"`, and `ConsentDialog` for
the default kind. See [IAB TCF](/docs/frameworks/astro/iab).

## Accessibility

The link is a real `<button>` or `<a>`, so it is reachable with Tab and
activates with Enter. Give it a label that says what it opens, such as
"Cookie preferences" or "Privacy settings". Keyboard focus or a hover on a
link for the preference dialog starts downloading it, so by the time the
visitor presses Enter the dialog is usually ready.

## Open a dialog from your own control

A control that is not a `ConsentDialogLink` can open the dialog with
`openDialog()` from `@inth/astro/client`. See
[open and close dialogs](/docs/frameworks/astro/client-api#open-and-close-dialogs).
