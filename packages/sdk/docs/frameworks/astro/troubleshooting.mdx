## The build says manifest() needs a server adapter

**Check.** The error reads `manifest() resolves each visitor on the server and injects an on-demand route at /api/inth/[...path]`. `manifest()` is the default mode, and `astro build` stops when no adapter can serve its route.

**Fix.** Add your host's adapter and set `output: 'server'`. For a static site, set `inth({ mode: hosted() })` or `inth({ mode: manifest({ resolve: 'browser' }) })`. See [Rendering and deployment](/docs/frameworks/astro/rendering).

## The config fails with "is a function"

**Check.** A serialized `inth()` option holds a function. The error names it, such as `inth().scripts[0].onLoad`. Vendor helpers from `@inth/integrations` return script objects with callbacks.

**Fix.** Move the option to the default export of `src/inth.client.ts`. See [`clientEntrypoint`](/docs/frameworks/astro/integration#cliententrypoint).

## The build says `ui` needs an Astro integration

**Check.** The preference dialog is an island rendered by the framework `ui` names. Confirm that framework's Astro integration is registered before `inth()` in `astro.config.mjs`.

**Fix.** Install and register the integration before `inth()`: `@astrojs/svelte` and `svelte` for `'svelte'`, `@astrojs/react`, `react`, and `react-dom` for `'react'`, or `@astrojs/vue` and `vue` for `'vue'`. A notice-only site that never opens a dialog can set `requireUIIntegration: false` instead.

**Check.** If your site registers more than one UI integration and the dialog still renders in Svelte, `ui` defaulted to `'svelte'`.

**Fix.** Set `ui: 'react'` or `ui: 'vue'` to match the framework your site already ships.

## Consent requests go to the wrong backend

**Check.** Inspect `PUBLIC_INTH_PROJECT_URL` and `PUBLIC_C15T_BACKEND_URL` in `.env`, `.env.local`, and your build environment, plus any `projectUrl` in `astro.config.mjs`. `PUBLIC_INTH_PROJECT_URL` wins if both are set; `PUBLIC_C15T_BACKEND_URL` is read as a fallback when `PUBLIC_INTH_PROJECT_URL` is unset.

**Fix.** Set `PUBLIC_INTH_PROJECT_URL` to your Inth project URL (including any path prefix), remove any stale `PUBLIC_C15T_BACKEND_URL`, restart `astro dev`, and rebuild for production.

## `astro build` or `astro dev` can't fetch the manifest

**Check.** In `manifest()` mode, the integration downloads `${projectUrl}/v1/consent/manifest` (or `manifestUrl`) when `astro build` or `astro dev` starts, with a 10-second timeout. By default (`onBuildError: 'runtime'`), both `astro build` and `astro dev` log a warning starting with `@inth/astro: could not fetch the consent manifest from <url>` and fall back to runtime fetching; with `onBuildError: 'fail'` or `INTH_ON_BUILD_ERROR=fail`, both stop with an error. The text in parentheses names the cause:

- `fetch failed` or `no response within 10 seconds`: the build machine cannot reach Inth.
- `/v1/consent/manifest responded 404` (or another status): the URL is wrong or still points to a placeholder.
- `/v1/consent/manifest returned an invalid consent manifest`: the URL responds, but not with an Inth manifest.

A relative or empty URL skips the fetch (or throws `build-time manifests require an absolute upstream URL` when `onBuildError: 'fail'`). A missing project URL logs `no backend URL is set` as a warning by default, or stops the command when `onBuildError: 'fail'` is set.

**Fix.** Set `PUBLIC_INTH_PROJECT_URL` (falling back to `PUBLIC_C15T_BACKEND_URL`, or pass `projectUrl` on `inth()`) to your absolute Inth project URL and ensure the build machine can reach it. To deploy during an outage when `onBuildError: 'fail'` is set, build with `INTH_ON_BUILD_ERROR=runtime`. To always fetch at runtime, set `mode: manifest({ source: 'runtime' })`.

## The build is slow during consent setup

**Check.** On Astro 7.4 or later, run:

```sh
npm run build -- --timings
```

Find `@inth/astro` in the `Integrations` section and check `astro:config:setup`. In `manifest()` mode with build-time fetching, this includes the manifest download and setup work. Astro omits `Integrations` when hooks take under 1% of build time and lists at most eight integrations. If the build fails before printing the report, follow the [manifest-fetch error guidance](/docs/frameworks/astro/troubleshooting#astro-build-or-astro-dev-cant-fetch-the-manifest).

**Fix.** Check latency from your build machine to `${projectUrl}/v1/consent/manifest` (or `manifestUrl`). See [build-time manifests](/docs/frameworks/astro/rendering#bundle-the-manifest-during-builds) before switching to `manifest({ source: 'runtime' })`, which skips the build download. Note `onBuildError: 'runtime'` still attempts the download before falling back.

## A component says `Astro.locals.inth` is missing

**Check.** Confirm `inth()` is in `integrations` in `astro.config.mjs`, `middleware: false` is not set, and the route is not in `middleware.skip`.

**Fix.** Add `inth()` to `integrations`, remove `middleware: false`, or remove the route from `middleware.skip`.

## Why is there no banner?

**Check.** In DevTools Network, inspect `/v1/consent/init` (or `Astro.locals.inth.snapshot.policyRule`) to see which policy matched.

**Fix.** Work through these causes in order:

1. **The visitor already chose.** Open a fresh private window.
2. **The policy asks for no banner.** Rules with `prompt: 'none'` show no banner; see [why the banner may be absent](/docs/concepts/policies#why-the-banner-may-be-absent).
3. **The policy did not resolve.** If `/v1/consent/init` failed or was blocked, no banner or `ConsentDialogLink` appears and optional categories stay denied.
4. **The page shares its HTML.** On static or prerendered pages, the banner appears after `/v1/consent/init` returns, not in the first HTML.

On server output, location comes from host headers (`cf-ipcountry`, `x-vercel-ip-country`, and similar). Send `x-inth-country` locally to test a region, and strip incoming `x-inth-*` headers at your production edge.

## The browser's `/v1/consent/init` request fails with a CORS error

**Check.** In `hosted()` mode, the browser calls Inth directly, and each preview deployment has its own origin.

**Fix.** Add the exact site origin (scheme and port included), plus preview deployment origins, to your Inth project's trusted origins.

## The banner is missing from server HTML now and then

**Check.** The middleware waits up to 500 ms for the policy. With runtime fetching (`hosted()`, `manifest({ source: 'runtime' })`, or a fallback after `onBuildError: 'runtime'`), slow responses render without the server banner and fall back to browser resolution.

**Fix.** Bundle the manifest during builds with `manifest()` and an absolute project URL, or raise `middleware: { timeoutMs }`. See [Rendering and deployment](/docs/frameworks/astro/rendering#set-how-long-a-render-waits-for-the-backend).

## The config fails with "manifest() needs a backend URL"

**Check.** The server reads `${projectUrl}/v1/consent/manifest` and the browser saves consent to `${projectUrl}/v1/consent/records`, so `astro.config` refuses to load without a URL. `hosted()` fails similarly with `hosted() needs a backend URL`.

**Fix.** Set `PUBLIC_INTH_PROJECT_URL` (falling back to `PUBLIC_C15T_BACKEND_URL` if unset) in `.env`, or pass `projectUrl` to `inth()`. Even `manifest({ snapshot })` needs a project URL because the consent route answers `GET` only and saves go to Inth.

## Options from an earlier alpha have no effect

**Check.** `astro.config.mjs` uses removed v3 alpha options (`hosted({ url })`, `manifest({ projectUrl, manifest })`, `endpoints`, `buildManifest`) or imports `consent-dialog-trigger.astro`.

**Fix.** Replace them with the current names:

| Earlier | Now |
| --- | --- |
| `hosted({ url })` | `hosted()` with top-level `projectUrl` |
| `manifest({ projectUrl })` | `manifest()` with top-level `projectUrl` |
| `manifest({ manifest })` | `manifest({ snapshot })` |
| `endpoints: { initPath, manifestPath }` | `routePrefix` (one catch-all for both) |
| `endpoints: false` | `routePrefix: false` |
| `buildManifest: false` | `manifest({ source: 'runtime' })` |
| `buildManifest: true` | `onBuildError: 'fail'` |
| `ConsentDialogTrigger` from `consent-dialog-trigger.astro` | `ConsentDialogLink` from `@inth/astro/components` |
| `hosted({ domain })` | Top-level `projectUrl` |
| `@inth/astro/api/init`, `@inth/astro/api/manifest`, `@inth/astro/api` | `routePrefix`, `createConsentRouteHandlers`, and manifest helpers from `@inth/astro/server` |
| `resolveTransportFactory`, `custom`, `C15tModeDescriptor`, `C15tHostedDescriptor`, `C15tManifestDescriptor`, `C15tOfflineDescriptor`, `C15tEndpointOptions` | `ConsentMode` from `@inth/astro` |
| `/// <reference types="@inth/astro/middleware" />` in `src/env.d.ts` | Remove it; the integration adds `Astro.locals.inth` types automatically |

## A vendor loads before the visitor chooses

**Check.** Search your layout and tag manager for the vendor's own snippet.

**Fix.** Remove the extra snippet so only Inth loads the vendor.

**Check.** Inspect any gated inline `<script>`. It needs both `type="text/plain"` and `is:inline`.

**Fix.** Add the missing attribute; without `is:inline`, Astro bundles and runs the script immediately.

**Check.** Read `effectivePermissions` in the snapshot. Under an opt-out policy, measurement can be allowed before any choice.

**Fix.** None. See [Scripts](/docs/frameworks/astro/scripts) and [Embeds](/docs/frameworks/astro/embeds) for gating options.

## A gated inline script never runs

**Check.** Open the console. Inth logs a warning and skips tags whose `data-inth-category` is not a valid category name.

**Fix.** Set `data-inth-category` to a valid category, such as `measurement`.

**Check.** Under a nonce-based CSP, Inth skips gated tags missing the page nonce, logs a warning, and marks them `data-inth-activated="untrusted"`.

**Fix.** Add `nonce={Astro.locals.inth?.nonce}` to the tag and reload. Inth never retries a tag marked `untrusted`. See [put the nonce on your gated scripts](/docs/frameworks/astro/content-security-policy#put-the-nonce-on-your-gated-scripts).

## The preference dialog opens without styles

**Check.** Check for `styles: false` in `inth()`, or look in DevTools Network and Console for a blocked stylesheet or CSP error.

**Fix.** When `styles: false`, import `@inth/astro/styles.css` (and `@inth/astro/primitives.css` for the Svelte island's confirmations) from your global stylesheet. See [load the stylesheet yourself](/docs/frameworks/astro/customize#load-the-stylesheet-yourself).

## The banner loses its padding with Tailwind CSS

**Check.** Tailwind's preflight in `base` overrides Inth's `components` layer when your stylesheet declares layer order before Inth's rules load.

**Fix.** Place `components` after `base` in your first `@layer` statement, or set `styles: false` and import `@inth/astro/styles.css` after your layer order statement.

## The dark mode is wrong or flashes

**Check.** Verify `ConsentScript` renders inside `<head>` so the color scheme applies before first paint.

**Fix.** Keep `ConsentScript` in `<head>`. If your site manages its own theme switch, set `colorScheme: 'none'` and toggle `inth-dark` on `<html>` yourself, including after `ClientRouter` navigation. See [set light or dark mode](/docs/frameworks/astro/customize#set-light-or-dark-mode).

## `getConsentClient()` returns `null`

**Check.** The runtime starts from a module script, so your script ran earlier or ran on the server.

**Fix.** Call `getConsentClient()` in the browser and retry on `DOMContentLoaded`. See [Client API](/docs/frameworks/astro/client-api).

## The banner shows no links to my policies

**Check.** `ConsentBanner` and `ConsentDialog` render only keys listed in their `legalLinks` prop.

**Fix.** Define keys in `inth({ legalLinks })` and pass `legalLinks={['privacyPolicy', 'cookiePolicy']}` to each component. See [ConsentBanner legal links](/docs/frameworks/astro/components/consent-banner#legal-links).

## An iframe loads before the visitor chooses

**Check.** Look for an iframe with `src` in the initial HTML; browsers load `src` before scripts run.

**Fix.** Use `data-src` with `data-category`, or render the iframe from a component only while the category is allowed. See [Embeds](/docs/frameworks/astro/embeds).

## My own island is out of step with the banner, or turns dark mode off

**Check.** Your island created its own consent runtime, or its adapter is toggling `inth-dark`.

**Fix.** Pass `getConsentClient()?.runtime` as `runtime`, set `colorScheme: null`, and render the island with `client:only`. See [use consent in your own islands](/docs/frameworks/astro/islands#use-consent-in-your-own-islands).

## The console reports a Content Security Policy violation

**Check.** Inth renders inline scripts and `<style id="inth-theme">`. Check whether you use middleware nonces or Astro's `security.csp`.

**Fix.** Under a nonce policy, set `Astro.locals.inth.nonce` in your middleware. Under `security.csp`, the integration registers hashes automatically. Note `ConsentBannerDeferred` does not work under a middleware nonce policy because Astro's server island loader has no nonce. See [Content Security Policy](/docs/frameworks/astro/content-security-policy).
