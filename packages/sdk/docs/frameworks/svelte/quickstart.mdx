Add a consent banner and preference dialog to a Svelte 5 Vite app. The browser resolves each visitor's policy from Inth, and analytics wait until consent allows them.

<Prompt title="Add Inth consent to this Svelte app" description="Paste into Claude Code, Codex, Cursor or another coding agent at the root of your app.">
  Add Inth consent management to this Svelte 5 Vite app.

  1. Check that the app uses Svelte 5.20 or later with Vite and without SvelteKit. If it uses SvelteKit, stop and tell me.
  2. Install `@inth/svelte` and `@inth/integrations`. Read `node_modules/@inth/svelte/AGENTS.md`, then follow the Svelte quickstart it links to, in order. Do not guess the API from memory.
  3. Set `VITE_INTH_PROJECT_URL` in `.env`. Ask me for my project URL, and use `https://example-inth.inth.app` only for a demo. `VITE_INTH_PROJECT_URL` wins over any legacy `VITE_C15T_BACKEND_URL`.
  4. Add `consentManifest()` from `@inth/svelte/vite` to `plugins` in `vite.config.ts`. Add nothing to `.gitignore`: the plugin writes no files to the project.
  5. In `src/App.svelte`, wrap the app in `InthProvider` with `mode={hosted()}` and move analytics and marketing scripts into `scripts` using helpers from `@inth/integrations`. Carry over vendor settings such as PostHog's `region` or `apiHost`, and remove old `<script>` tags or SDK imports. If a vendor has no helper, tell me.
  6. Render `ConsentBanner`, `ConsentDialog`, and a `ConsentDialogLink` in the footer inside `InthProvider`.
  7. Run `vite build` and `vite preview`. Check in a browser that no vendor request fires before consent, rejection survives a reload, and granting analytics from the footer loads the vendor.

  Then list the files you changed, any script still outside consent, and how you checked the requests.
</Prompt>

## Prerequisites

- A Svelte 5.20+ app built with Vite. On SvelteKit or another framework? See [choose your setup](/docs/concepts/choose-your-setup) or the [framework list](/docs/frameworks).
- An [Inth project](https://inth.com/dashboard/sign-up?framework=svelte) with your app's origin in its trusted origins.

## Install the SDK

<CommandTabs command="@inth/svelte @inth/integrations" mode="install" />

Components inject their own styles on first render, so there is no stylesheet to import. On Tailwind CSS 3, [import the stylesheet yourself](/docs/customization/stylesheets#import-the-stylesheet-yourself) and pass `styles={false}`.

## Set the project URL

Add your Inth project URL, including any path prefix, to `.env` and your host's build settings:

```sh title=".env"
VITE_INTH_PROJECT_URL=https://example-inth.inth.app
```

The URL is public, not a secret. `https://example-inth.inth.app` is a demo project. Vite inlines this value at build time, so rebuild after changing it. `VITE_INTH_PROJECT_URL` wins over any legacy `VITE_C15T_BACKEND_URL`, which is read as a fallback if unset.

## Add the Vite plugin

Add `consentManifest()` to `plugins` in `vite.config.ts`:

<include src="../../shared/examples/svelte/vite-config.mdx" />

`consentManifest` passes the project URL to `InthProvider` and adds a small script to `index.html` that starts `/v1/consent/init` while your JavaScript downloads. Without the plugin, pass `projectUrl` directly to `InthProvider`.

## Mount the provider

Wrap your app in `InthProvider` in `src/App.svelte` and register your vendor scripts:

<include src="../../shared/examples/svelte/app.mdx" />

Replace `phc_your_project_key` with your key, or pick another [integration](/docs/integrations/overview). Keep `cookieless_mode: 'never'`, or PostHog falls back to cookieless capture after a rejection. Remove any existing PostHog `<script>` tags or SDK imports so PostHog loads only through Inth.

Keep `InthProvider` at the root of your app. `ConsentDialog` loads lazily in its own chunk, and `ConsentDialogLink` lets visitors reopen preferences from the footer.

## Check it works

Run `vite build` and `vite preview`, then open the app in a private window with DevTools open on the Network panel.

1. Under an opt-in policy, one `/v1/consent/init` request goes to Inth, the banner appears, and no PostHog request fires.
2. Click **Reject All**, then reload. The banner stays closed and PostHog does not load.
3. Open **Privacy settings** in the footer, turn on **Analytics**, and click **Save Settings**. PostHog loads.
4. Open **Privacy settings** again, turn **Analytics** off, and click **Save Settings**. The page reloads and PostHog does not load.

Inspect requests in the Network panel to confirm blocking; a visible banner alone proves nothing. If no banner appears, inspect `/v1/consent/init` and see [Svelte troubleshooting](/docs/frameworks/svelte/troubleshooting). [Verify consent](/docs/guides/verify-consent) has the full checklist.

## Use another setup

| Your setup | Option |
| --- | --- |
| Tests without a backend | Pass `mode={testing()}` from `@inth/svelte/testing`; see [testing mode](/docs/concepts/modes#testing) |
| Bundled policy at build time | Pass `mode={manifest()}` when location rules do not vary or your page supplies `inputs`; see [consent modes](/docs/concepts/modes) |
| Custom `fetch`, `headers`, or `projectUrl` on `hosted()` | Pass `initPrefetch: false` to `consentManifest()` to prevent a duplicate `/v1/consent/init` |
| Banner in server HTML | Use SvelteKit; see [choose your setup](/docs/concepts/choose-your-setup) |
