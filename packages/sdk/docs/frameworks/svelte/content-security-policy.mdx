## Set the policy where you host the app

A Svelte app built with Vite has no server of its own, so your host or CDN serves the `Content-Security-Policy` header, or you set a `<meta http-equiv="Content-Security-Policy">` tag in `index.html`. Test it against `vite build` and `vite preview`. The dev server injects CSS through `<style>` elements, so a strict policy breaks `vite dev` even when production works.

A static host serves the same file to everyone and cannot generate a fresh nonce per response, so allow each vendor's script host in `script-src` instead of relying on the provider's `nonce`.

In a Svelte app without server rendering, Svelte sets every `style` value through the DOM, which CSP allows without `'unsafe-inline'` for style attributes.

Inth components add their rules to `<head>` as `<style>` elements, which a `style-src` without `'unsafe-inline'` blocks. Because a static host has no nonce to pass, set `styles={false}` on `InthProvider` and import `@inth/svelte/styles.css` from your entry module. `'self'` covers that stylesheet.

Allow the early `/v1/consent/init` script that `consentManifest()` adds to `index.html` in `script-src` using the hash from the browser's `Refused to execute inline script` message. If the policy blocks it, the provider sends `/v1/consent/init` itself.
