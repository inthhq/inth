The standard React Native integration opens SwiftUI and Compose consent
screens. Customize those screens through native `ConsentTheme` settings or
native build metadata. React `style` props and web CSS do not style them. The
theme uses the web token names from `@c15t/ui`, so a brand defined for the web
theme maps onto the native screens field for field.

## Choose what to change

| Change | Use |
| --- | --- |
| Colors, radii, spacing and type | One theme object: the Expo plugin's `theme` option for the native screens, and `createConsentTheme` for the React Native components. Bare apps write native theme metadata. |
| One part, such as the decision buttons | The theme's `slots`. |
| Your app's name and logo | Native app-identity settings. |
| c15t, Inth or custom provider attribution | Native branding settings. |
| First-layer heading and introduction | Native copy settings. |
| Entirely custom React controls | [Headless hooks and commands](/docs/frameworks/react-native/headless). |

The presenter keeps Accept and Reject on the same decision style. Their
first-layer action labels are not replaceable introductory copy.

## Theme both renderers from one object

In Expo, keep the theme in a JSON file. Node loads JSON in `app.config.ts`, and
Metro bundles the same file into the app, so one object reaches both
renderers. This theme sets the primary and decision colors, the button radius,
spacing, type sizes, the headline face and a pill shape for the decision
buttons:

```json title="src/inth/consent-theme.json"
{
	"colors": {
		"decision": "#172554",
		"primary": "#2563EB",
		"textOnDecision": "#FFFFFF"
	},
	"dark": {
		"decision": "#DBEAFE",
		"primary": "#60A5FA",
		"textOnDecision": "#172554"
	},
	"radius": { "md": 16 },
	"slots": { "buttonPrimary": { "borderRadius": 26 } },
	"spacing": { "lg": 28, "md": 20 },
	"typography": {
		"fontSize": { "base": 17, "sm": 15 },
		"headlineFont": "serif"
	}
}
```

Pass it to the config plugin's `theme` option. Prebuild writes it into
`Info.plist` and `AndroidManifest.xml`:

Pass the same object to `createConsentTheme` for `ConsentBanner`,
`ConsentDialog`, `ConsentPreferences` and `ConsentIabDrawer`:

<include src="../../shared/examples/expo-dev/expo-theme-components.mdx" />

The object's type is `ConsentThemeOptions` from `@inth/react-native`. Each
renderer reads the fields it draws and ignores the rest: the native screens
ignore `motion`, `typography.fontWeight`, `typography.lineHeight` and the
colors only the components draw, such as `border`; the components ignore
`slots`, `brand`, `branding` and the native-only colors `canvas`,
`surfaceMuted`, `decision` and `textOnDecision`. The plugin still fails
prebuild on a field neither renderer draws, such as `shadows`, and on a value
the native screens cannot read, such as an `hsl()` color.

A value in `colors` applies in both appearances unless `dark` sets its own.
The components follow the device appearance with a host theme too.

Rebuild the binary after a theme change, then open Privacy settings and check
both appearances and a large text size.

[Expo and EAS](/docs/frameworks/react-native/expo#theme-the-native-screens)
shows where the option sits in the plugin config.

## Set theme values in a bare app

For bare React Native, merge these iOS entries into the app target's
`Info.plist`. This fragment changes the primary color, the decision fill, the
button radius, the page gutter and the body size:

{/* example: fragment */}

```xml title="Info.plist entries"
<key>com.inth.consent.primary</key>
<string>#2563EB,#60A5FA</string>
<key>com.inth.consent.decision</key>
<string>#172554,#DBEAFE</string>
<key>com.inth.consent.textOnDecision</key>
<string>#FFFFFF,#172554</string>
<key>com.inth.consent.radiusMd</key>
<real>16</real>
<key>com.inth.consent.spaceLg</key>
<real>28</real>
<key>com.inth.consent.fontSizeBase</key>
<real>17</real>
```

On Android, add the corresponding metadata inside `<application>`:

{/* example: fragment */}

```xml title="AndroidManifest.xml application entries"
<meta-data android:name="com.inth.consent.PRIMARY" android:value="#2563EB,#60A5FA" />
<meta-data android:name="com.inth.consent.DECISION" android:value="#172554,#DBEAFE" />
<meta-data android:name="com.inth.consent.TEXT_ON_DECISION" android:value="#FFFFFF,#172554" />
<meta-data android:name="com.inth.consent.RADIUS_MD" android:value="16" />
<meta-data android:name="com.inth.consent.SPACE_LG" android:value="28" />
<meta-data android:name="com.inth.consent.FONT_SIZE_BASE" android:value="17" />
```

A single `#RRGGBB` color applies in both appearances. A comma-separated pair
selects light and dark values. Radii and spacing use points on iOS and dp on
Android; font sizes use points on iOS and sp on Android.

## How type, spacing and radius apply

The native screens group their text roles under the three web sizes:

- `fontSize.sm` sets supporting text, footnotes and captions. The default is
  the platform size: 15 on iOS (subheadline) and 14 on Android (bodyMedium).
- `fontSize.base` sets body text, row titles and buttons. The default is 17 on
  iOS and 16 on Android.
- `fontSize.lg` sets the first-layer headline and screen titles. The default
  headline is 34.

Each role keeps its ratio to its group, so a footnote stays smaller than the
subheadline beside it. Dynamic Type on iOS and the font scale on Android still
apply on top. `fontFamily` sets the face of every role except the headline,
which `headlineFont` sets: `serif`, `rounded`, `sans`, or a bundled font. Font
names are PostScript names on iOS and font resource names on Android.

Spacing sets the page gutters, the gaps between sections and the padding of
the footer and the notice card. A control's own padding stays fixed so its tap
target keeps its size. `radius.md` rounds buttons and cards; `radius.sm` (the
status callouts) and `radius.lg` (the notice card and dialogs) follow `md`
until you set them.

## Restyle one part

`slots` restyle one part of the native screens. The names come from the web
`slots`, and each field is the CSS property a web slot's `style` would set:

| Slot | Part | Fields |
| --- | --- | --- |
| `consentBannerTitle` | The first-layer headline | `color`, `fontSize` |
| `consentBannerDescription` | The sentence under the headline | `color`, `fontSize` |
| `buttonPrimary` | Accept all, Reject all and the other filled decisions | `color`, `backgroundColor`, `borderRadius`, `fontSize` |
| `buttonSecondary` | Outlined actions such as Customize | `color`, `backgroundColor`, `borderRadius`, `fontSize` |

A slot color is `#RRGGBB` or `{ "light": "#RRGGBB", "dark": "#RRGGBB" }`. Accept
all and Reject all always share `buttonPrimary`. If its colors fall under 5:1
text contrast in either appearance, the screens draw the stock decision colors
instead, as they do for `colors.decision`. The React Native components take
per-part styles through their `styles` prop.

## Add your app's identity

Use `brandName` and `brandMark` on iOS, or `BRAND_NAME` and `BRAND_MARK` on
Android. iOS marks name bundled image assets; Android marks name drawable
resources. Set the `brand` or `BRAND` boolean to false to hide the app identity.

App identity and provider attribution are separate. Hiding the app identity
does not select a different consent provider.

## Use Inth attribution

Set `com.inth.consent.brandingProvider` to `inth` in iOS `Info.plist`, or
`com.inth.consent.BRANDING_PROVIDER` to `inth` in Android application metadata.
Use `c15t` for the other built-in provider. Both names use bundled marks.

For custom attribution, set `brandingName` and optionally `brandingMark` on
iOS, or `BRANDING_NAME` and `BRANDING_MARK` on Android. The mark uses a bundled
native asset. `branding` or `BRANDING` controls attribution visibility.

On supported iOS 27.1+ layouts, the presenter can place compact provider
attribution in the system's vertical side area, aligned with Customize. The
layout follows window geometry and system-reserved regions. It does not test
the device model. It falls back below Customize when that area is unavailable
or accessibility text needs more space.

## Native setting reference

Every iOS suffix below starts with `com.inth.consent.`. Android suffixes use
the same prefix inside application metadata. The Expo column is the field in
the config plugin's `theme` option.

| Setting | iOS suffix | Android suffix | Expo `theme` field |
| --- | --- | --- | --- |
| Primary and text on primary | `primary`, `textOnPrimary` | `PRIMARY`, `TEXT_ON_PRIMARY` | `colors.primary`, `colors.textOnPrimary` |
| Page and card surfaces | `canvas`, `surface`, `surfaceMuted` | `CANVAS`, `SURFACE`, `SURFACE_MUTED` | `colors.canvas`, `colors.surface`, `colors.surfaceMuted` |
| Main and muted text | `text`, `textMuted` | `TEXT`, `TEXT_MUTED` | `colors.text`, `colors.textMuted` |
| Decision buttons | `decision`, `textOnDecision` | `DECISION`, `TEXT_ON_DECISION` | `colors.decision`, `colors.textOnDecision` |
| Corner radii | `radiusSm`, `radiusMd`, `radiusLg` | `RADIUS_SM`, `RADIUS_MD`, `RADIUS_LG` | `radius.sm`, `radius.md`, `radius.lg` |
| Spacing | `spaceXs` to `spaceXl` | `SPACE_XS` to `SPACE_XL` | `spacing.xs` to `spacing.xl` |
| Font sizes | `fontSizeSm`, `fontSizeBase`, `fontSizeLg` | `FONT_SIZE_SM`, `FONT_SIZE_BASE`, `FONT_SIZE_LG` | `typography.fontSize` |
| Body and headline faces | `fontFamily`, `headlineFont` | `FONT_FAMILY`, `HEADLINE_FONT` | `typography.fontFamily`, `typography.headlineFont` |
| One part | `<slot>.<field>`, such as `buttonPrimary.borderRadius` | `<SLOT>_<FIELD>`, such as `BUTTON_PRIMARY_BORDER_RADIUS` | `slots.<slot>.<field>` |
| App name and mark | `brandName`, `brandMark` | `BRAND_NAME`, `BRAND_MARK` | `brand.name`, `brand.mark` |
| Show app identity | `brand` | `BRAND` | `brand.hidden` (inverted) |
| First-layer copy | `headline`, `introduction` | `HEADLINE`, `INTRODUCTION` | None |
| Show provider attribution | `branding` | `BRANDING` | `branding.hidden` (inverted) |
| Built-in provider | `brandingProvider` | `BRANDING_PROVIDER` | `branding.provider` |
| Custom provider name and mark | `brandingName`, `brandingMark` | `BRANDING_NAME`, `BRANDING_MARK` | `branding.name`, `branding.mark` |

Android maps `rounded` headline type to its system sans face. Check contrast
and larger text after changing theme values; the native screen retains its
layout and interaction rules.

### Token names before this release

Mobile is in private alpha, so the old names have no aliases. Rename them in
native code and build metadata:

| Before | Now (iOS key, Android key) |
| --- | --- |
| `colors.accent` | `colors.primary` (`primary`, `PRIMARY`) |
| `colors.onAccent` | `colors.textOnPrimary` (`textOnPrimary`, `TEXT_ON_PRIMARY`) |
| `colors.textSecondary` | `colors.textMuted` (`textMuted`, `TEXT_MUTED`) |
| `colors.onDecision` | `colors.textOnDecision` (`textOnDecision`, `TEXT_ON_DECISION`) |
| `cornerRadius` | `radius.md` (`radiusMd`, `RADIUS_MD`) |
| `headlineFont` | `typography.headlineFont` (key unchanged) |

## Copy and languages

The native presenter reads every label from `@c15t/translations`, in the
policy's translation language, on iOS and Android alike. Buttons, headings and
category names use the web banner's keys, so they read "Accept All" and
"Reject All". App-only sentences, such as the category explanations and save
errors, come from native-only keys in the same package. A language Inth has
no copy for falls back to English.

`headline` and `introduction` replace the first-layer copy in every language.
Leave them unset to keep the translated stock copy. They are not a complete
localization dictionary.

GVL descriptions use the available language disclosures and fallback. ATT
usage descriptions have separate native localization. If your app needs a
fully app-owned localized category interface today, use
[headless controls](/docs/frameworks/react-native/headless) and include the
required policy information in that UI.

## React-rendered components

The package also exports `ConsentBanner`, `ConsentDialog`,
`ConsentPreferences`, `ConsentIabDrawer` and React theme helpers. Those render
React Native UI. They take a theme from `createConsentTheme` through their
`theme` prop and per-part styles through `styles`. The theme reaches the native
presenter only through the plugin or native metadata at build time, as shown
in [Theme both renderers from one object](#theme-both-renderers-from-one-object).

`createConsentTheme` returns both palettes, `colors` and `dark`, and the
components draw the one the device appearance selects. Its names changed with
the native ones: `onPrimary` is `textOnPrimary`, `switchTrackOn` is
`switchTrackActive`, `surfaceRaised` is `surfaceHover`, spacing steps are `xs`
to `xl`, and radii are `sm`, `md`, `lg` and `full`. `lightTheme` and
`darkTheme` became `defaultConsentTheme`. The type tokens are the web scale
(`fontSize`, `fontWeight`, `lineHeight`); `resolveConsentTypeRoles` returns the
banner and dialog text styles derived from them.

Use the shared native screens for the standard flow. If you use the React
components or your own controls, preserve the native engine, check every
[commit result](/docs/frameworks/react-native/usage#inspect-every-local-commit)
and keep SDK startup gates.
