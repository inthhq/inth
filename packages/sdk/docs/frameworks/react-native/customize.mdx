The default React Native setup presents native SwiftUI and Compose consent screens. Style them through the Expo plugin's `theme` option or native metadata; React `style` props and CSS affect only React-rendered components. Both renderers share web token names so one theme object maps cleanly across platforms.

## Choose what to change

| Customization | Approach |
| --- | --- |
| Colors, radii, spacing, and typography | Share one theme object across the Expo plugin `theme` option and `createConsentTheme`, or write bare native metadata. |
| Single screen part (such as decision buttons) | Set `slots` on the theme object. |
| App name and logo | Configure native `brand` settings. |
| Provider attribution (`inth`, `c15t`, or custom) | Configure native `branding` settings. |
| First-layer headline and introduction | Set native copy metadata. |
| Fully custom React UI | Follow [Build your own UI](/docs/frameworks/react-native/headless). |

Accept all and Reject all always share one decision button treatment.

## Theme both renderers from one object

In Expo, store your theme in a JSON file so Node reads it in `app.config.ts` and Metro bundles it for React Native components:

```json title="src/inth/consent-theme.json"
{
	"colors": {
		"decision": "#172554",
		"primary": "#2563EB",
		"textOnDecision": "#FFFFFF"
	},
	"dark": {
		"decision": "#DBEAFE",
		"primary": "#60A5FA",
		"textOnDecision": "#172554"
	},
	"radius": { "md": 16 },
	"slots": { "buttonPrimary": { "borderRadius": 26 } },
	"spacing": { "lg": 28, "md": 20 },
	"typography": {
		"fontSize": { "base": 17, "sm": 15 },
		"headlineFont": "serif"
	}
}
```

Pass the same object to `createConsentTheme` for `ConsentBanner`, `ConsentDialog`, `ConsentPreferences`, and `ConsentIabDrawer`:

Type the object with `ConsentThemeOptions` from `@inth/react-native`. Each renderer reads its supported keys and ignores the other renderer's keys (`motion`, `fontWeight`, `lineHeight`, and `border` are React-only; `slots`, `brand`, `branding`, `canvas`, `surfaceMuted`, `decision`, and `textOnDecision` are native-only). Prebuild still fails on invalid native values (such as `hsl()`) or unsupported web fields (`shadows`).

Any color in `colors` applies in both appearances unless overridden in `dark`. Rebuild the native binary after theme edits and verify light mode, dark mode, and large text. See [Theme the native screens](/docs/frameworks/react-native/expo#theme-the-native-screens).

## Set theme values in a bare app

In bare React Native, add iOS entries to your app target's `Info.plist`:

{/* example: fragment */}

```xml title="Info.plist entries"
<key>com.inth.consent.primary</key>
<string>#2563EB,#60A5FA</string>
<key>com.inth.consent.decision</key>
<string>#172554,#DBEAFE</string>
<key>com.inth.consent.textOnDecision</key>
<string>#FFFFFF,#172554</string>
<key>com.inth.consent.radiusMd</key>
<real>16</real>
<key>com.inth.consent.spaceLg</key>
<real>28</real>
<key>com.inth.consent.fontSizeBase</key>
<real>17</real>
```

Add matching `<meta-data>` entries inside `<application>` in `AndroidManifest.xml`:

{/* example: fragment */}

```xml title="AndroidManifest.xml application entries"
<meta-data android:name="com.inth.consent.PRIMARY" android:value="#2563EB,#60A5FA" />
<meta-data android:name="com.inth.consent.DECISION" android:value="#172554,#DBEAFE" />
<meta-data android:name="com.inth.consent.TEXT_ON_DECISION" android:value="#FFFFFF,#172554" />
<meta-data android:name="com.inth.consent.RADIUS_MD" android:value="16" />
<meta-data android:name="com.inth.consent.SPACE_LG" android:value="28" />
<meta-data android:name="com.inth.consent.FONT_SIZE_BASE" android:value="17" />
```

Pass `#RRGGBB` for both appearances or `#RRGGBB,#RRGGBB` for `light,dark`. Radii and spacing use pt (iOS) and dp (Android); font sizes use pt (iOS) and sp (Android).

## How typography, spacing, and radii apply

Native text roles group under three sizes while preserving relative ratios and system font scaling (Dynamic Type on iOS, font scale on Android):

- `fontSize.sm`: supporting text, footnotes, and captions (default 15pt iOS, 14sp Android).
- `fontSize.base`: body text, row titles, and buttons (default 17pt iOS, 16sp Android).
- `fontSize.lg`: first-layer headline and screen titles (default 34).

`fontFamily` sets body roles; `headlineFont` takes `serif`, `rounded` (maps to sans on Android), `sans`, or a bundled font (PostScript name on iOS, resource name on Android).

`spacing` adjusts page gutters, section gaps, and footer/notice padding without reducing tap targets. `radius.md` rounds buttons and cards (`radius.sm` and `radius.lg` inherit it until set).

## Restyle one part

`slots` target individual parts of the native screens using web slot names:

| Slot | Part | Fields |
| --- | --- | --- |
| `consentBannerTitle` | First-layer headline | `color`, `fontSize` |
| `consentBannerDescription` | Sentence under headline | `color`, `fontSize` |
| `buttonPrimary` | Accept all, Reject all, and filled decision actions | `color`, `backgroundColor`, `borderRadius`, `fontSize` |
| `buttonSecondary` | Outlined actions such as Customize | `color`, `backgroundColor`, `borderRadius`, `fontSize` |

Slot colors accept `#RRGGBB` or `{ "light": "#RRGGBB", "dark": "#RRGGBB" }`. Accept all and Reject all always share `buttonPrimary`, falling back to stock decision colors if contrast drops below 5:1. React Native components take per-part overrides via their `styles` prop.

## Add your app's identity

Set `brandName` and `brandMark` on iOS (`BRAND_NAME` and `BRAND_MARK` on Android) pointing to an image asset or drawable resource. Set `brand` / `BRAND` to `false` to hide the app header without changing provider attribution.

## Place Save Settings

Privacy Settings keeps Reject All and Accept All together at the bottom with Save in the top bar by default. Set `savePlacement: 'bottom'` in the Expo theme (or `com.inth.consent.savePlacement` / `com.inth.consent.SAVE_PLACEMENT` to `bottom`) for a full-width Save Settings button below them. Accessibility text sizes always place Save at the bottom.

## Choose a first-layer layout

Set `firstLayer` in the Expo theme (or `com.inth.consent.firstLayer` / `com.inth.consent.FIRST_LAYER`):

| Layout | Behavior |
| --- | --- |
| `page` | Full-screen page (default). |
| `sheet` | Floating bottom sheet over a dimmed app background. |
| `prompt` | Centered alert-style card (translucent glass on iOS, near-opaque surface on Android) over a dimmed app. |

Every container renders the same copy, partner link, and equal Accept all and Reject all buttons. Customize always opens full screen, accessibility text sizes switch every layout to `page`, and IAB TCF expands `sheet` and `prompt` to `page` on tablets and wide windows.

`appearance` selects the base palette: `system` (default) uses platform backgrounds, text colors, your app accent (`AccentColor` on iOS, `colorPrimary` on Android), centered layout, and app name/icon fallbacks, darkening your accent until white text hits 5:1 contrast. `c15t` uses the warm paper and ink palette. `sheet` and `prompt` always use system colors and tinted surface buttons rather than `buttonPrimary` fills. Explicit colors always override stock palettes.

## Choose provider attribution

Attribution displays the Inth wordmark by default. Set `brandingProvider` / `BRANDING_PROVIDER` to `c15t`, or supply `brandingName` and optional `brandingMark` (`BRANDING_NAME`, `BRANDING_MARK`) for custom attribution. Set `branding` / `BRANDING` to `false` to hide it. On supported iOS 27.1+ layouts with side-column space, compact attribution aligns beside Customize and falls back inline when space is limited or accessibility text is active.

## Native setting reference

All iOS and Android keys share the `com.inth.consent.` prefix:

| Setting | iOS suffix | Android suffix | Expo `theme` field |
| --- | --- | --- | --- |
| Primary and text on primary | `primary`, `textOnPrimary` | `PRIMARY`, `TEXT_ON_PRIMARY` | `colors.primary`, `colors.textOnPrimary` |
| Page and card surfaces | `canvas`, `surface`, `surfaceMuted` | `CANVAS`, `SURFACE`, `SURFACE_MUTED` | `colors.canvas`, `colors.surface`, `colors.surfaceMuted` |
| Primary and muted text | `text`, `textMuted` | `TEXT`, `TEXT_MUTED` | `colors.text`, `colors.textMuted` |
| Decision buttons | `decision`, `textOnDecision` | `DECISION`, `TEXT_ON_DECISION` | `colors.decision`, `colors.textOnDecision` |
| Corner radii | `radiusSm`, `radiusMd`, `radiusLg` | `RADIUS_SM`, `RADIUS_MD`, `RADIUS_LG` | `radius.sm`, `radius.md`, `radius.lg` |
| Spacing | `spaceXs` to `spaceXl` | `SPACE_XS` to `SPACE_XL` | `spacing.xs` to `spacing.xl` |
| Font sizes | `fontSizeSm`, `fontSizeBase`, `fontSizeLg` | `FONT_SIZE_SM`, `FONT_SIZE_BASE`, `FONT_SIZE_LG` | `typography.fontSize` |
| Body and headline faces | `fontFamily`, `headlineFont` | `FONT_FAMILY`, `HEADLINE_FONT` | `typography.fontFamily`, `typography.headlineFont` |
| Per-part slot | `<slot>.<field>` (e.g. `buttonPrimary.borderRadius`) | `<SLOT>_<FIELD>` (e.g. `BUTTON_PRIMARY_BORDER_RADIUS`) | `slots.<slot>.<field>` |
| App name and mark | `brandName`, `brandMark` | `BRAND_NAME`, `BRAND_MARK` | `brand.name`, `brand.mark` |
| Show app identity | `brand` | `BRAND` | `brand.hidden` (inverted) |
| First-layer copy | `headline`, `introduction` | `HEADLINE`, `INTRODUCTION` | None |
| First-layer layout | `firstLayer` | `FIRST_LAYER` | `firstLayer` |
| Stock palette | `appearance` | `APPEARANCE` | `appearance` |
| Save placement | `savePlacement` | `SAVE_PLACEMENT` | `savePlacement` |
| Show attribution | `branding` | `BRANDING` | `branding.hidden` (inverted) |
| Built-in provider | `brandingProvider` | `BRANDING_PROVIDER` | `branding.provider` |
| Custom provider | `brandingName`, `brandingMark` | `BRANDING_NAME`, `BRANDING_MARK` | `branding.name`, `branding.mark` |

## Copy and languages

Native screens load labels from `@inth/sdk/translations` in the policy's served language (falling back to English), while IAB screens follow the served GVL language. Setting `headline` or `introduction` overrides that text verbatim in every language; leave them unset to keep translated stock copy. ATT usage descriptions use standard iOS localization. For fully custom localized screens, use [Build your own UI](/docs/frameworks/react-native/headless).

## React-rendered components

`@inth/react-native` also exports `ConsentBanner`, `ConsentDialog`, `ConsentPreferences`, `ConsentIabDrawer`, and `createConsentTheme`. Pass the returned theme (`colors` and `dark` palettes following device appearance) to `theme` and per-part overrides to `styles`. Updated component tokens include `textOnPrimary`, `switchTrackActive`, `surfaceHover`, `xs` to `xl` spacing, `sm`/`md`/`lg`/`full` radii, `defaultConsentTheme`, and `resolveConsentTypeRoles`.

Prefer the stock native screens for standard mobile flows; when using React components, inspect every [commit result](/docs/frameworks/react-native/usage#inspect-every-local-commit) and keep native SDK gates active.
