Call `useSaveConsents()` under `InthProvider` when custom React controls save a choice. For stock native screens, call `presentConsentPrompt` or `presentPreferences` and let the native presenter handle forms and retries.

## Save a category choice

- `saveConsents({ measurement: true })` saves the listed categories while keeping previous receipts for omitted ones.
- `saveConsents('all')` grants every category in the resolved policy scope.
- `saveConsents('none')` saves a necessary-only choice.

Invoke saves only from explicit user actions. Reading permissions or mounting `InthProvider` never records a choice. For custom screens, see [Build your own UI](/docs/frameworks/react-native/headless).

## Inspect every local commit

`saveConsents` returns `Promise<CommitResult>`. Always check `result.ok` before dismissing UI or confirming a save, because a resolved promise can still carry a refused commit:

<include src="../../shared/examples/react-native-bare/commit-results.mdx" />

`onSaved` runs only after durable local storage succeeds; a refused or rejected call leaves the form open with an error message.

| Field | Meaning |
| --- | --- |
| `ok` | `true` when the native engine applied and durably stored the choice. |
| `reason` | Failure code when `ok` is `false`. |
| `revision` | Resulting snapshot revision, or `null` when unchanged. |
| `confirmed` | Optional categories with receipts recorded by this commit. |
| `queued` | `true` when backend delivery was durably queued (not a queue-length count). |
| `delivered` | `true` when the backend accepted the save before returning (when reported). |

`ok: true, queued: true` confirms durable local success so your UI and SDK gates can update immediately, even offline (iOS reports backend delivery asynchronously rather than setting `delivered: true` on the local result). Common refusal reasons include `policy-pending`, `queue-write-failed`, `concurrent-change`, and invalid intent. A later network failure never reverses a durable withdrawal; see [Mobile offline consent](/docs/guides/mobile-offline).

## Open the native screens

`InthProvider` passes `autoPresent` and `privacyPolicyUrl` to native `ConsentPrompt`, which automatically opens an owed prompt once ready. Call these helpers for a Privacy settings entry or manual presentation when `autoPresent={false}`:

| Function | Behavior |
| --- | --- |
| `presentConsentPrompt(privacyPolicyUrl)` | Opens the initial prompt only when the policy owes an interaction. |
| `presentPreferences(privacyPolicyUrl)` | Opens standing privacy settings anytime, even after a saved choice. |

See the [quickstart Privacy settings button](/docs/frameworks/react-native/quickstart#keep-privacy-settings-reachable). Both return a `ConsentPresenterSession`:

| `status` | Meaning |
| --- | --- |
| `presented` | A native session opened. |
| `already-presented` | A session is already open and reused. |
| `not-required` | No prompt is owed (`sessionId` is `null`). |

An open session includes `presentation` (`prompt` or `preferences` on current binaries). Rejections carry `INTH_PRESENTER_INVALID_URL` (the native host refused the URL) or `INTH_PRESENTER_UNAVAILABLE` (no foreground window, Activity, or installed core yet).

With `autoPresent` enabled, native opens an owed prompt once the app is foregrounded, after open settings close, or across a reinstall, while keeping a dismissed prompt closed until policy requirements change. Invalid URLs log `console.error` in every build, and binaries built before native auto-present log `console.error` asking for a rebuild while still supporting explicit `presentConsentPrompt` and `presentPreferences` calls.

Subscribe with `onConsentPresenterOutcome(listener)` before presenting, and invoke its returned unsubscribe callback on unmount.

## Handle the final presenter outcome

Each final outcome reports `sessionId`, snapshot revision, and `kind` (a session whose notice was cleared elsewhere via `dismissNotice()` closes immediately as `dismissed`):

| `kind` | Meaning |
| --- | --- |
| `committed` | A choice was saved durably on the device. |
| `acknowledged` | A notice was acknowledged (grants no optional consent). |
| `dismissed` | The screen closed without a new committed choice. |
| `unavailable` | The native host could not complete the session. |

Draft toggle changes do not emit bridge events; React hooks update from committed native snapshots. `closeConsentPresenter(sessionId)` asks native to dismiss a session (ignoring obsolete IDs, asking confirmation on dirty drafts, and refusing to interrupt an active save).

## Other actions

| Action | Purpose |
| --- | --- |
| `dismissNotice()` | Acknowledge a notice locally without sending a consent save. |
| `refresh()` | Re-resolve policy and retry pending delivery without saving a choice. |
| `identify(externalId)` | Link the installation to a signed-in app account. |
| `logout()` | Detach the external account identity. |
| `reset()` | Clear local consent authority and prompt again while keeping the Inth subject. |
| `setOverrides(overrides)` | Override QA country, region, language, or GPC inputs. |
| `requestTrackingAuthorization()` | Request Apple ATT manually (automatic after consent unless `trackingRequest="manual"`). |

Await asynchronous actions and handle errors. See [Identity, reset and withdrawal](/docs/frameworks/react-native/identity), [Configuration](/docs/frameworks/react-native/configuration), and [ATT](/docs/frameworks/react-native/iab#keep-att-separate). For TCF vendor and purpose choices, use the native presenter or headless IAB hooks rather than category commands; see [Mobile IAB and ads](/docs/guides/mobile-iab).
