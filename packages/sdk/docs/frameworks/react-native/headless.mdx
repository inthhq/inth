Build custom consent prompts, settings screens, and IAB flows in React Native while the native engine owns policy resolution, durable storage, and SDK gates.

## Start with the same native setup

Complete [Expo](/docs/frameworks/react-native/expo) or [bare RN setup](/docs/frameworks/react-native/bare) and mount one `InthProvider` above navigation. Pass `autoPresent={false}` when your React UI owns both the initial prompt and settings:

{/* example: fragment */}

```tsx
<InthProvider autoPresent={false}>
	<App />
</InthProvider>;
```

Your app then renders any owed prompt and keeps Privacy settings reachable (`presentConsentPrompt` and `presentPreferences` still work if called). To exclude stock SwiftUI and Compose screens from your binary, see [Build without the stock native screens](#build-without-the-stock-native-screens).

## Read one permission

Call `useConsent('measurement')` to read a category permission without rerendering on unrelated snapshot changes (returns `false` while unresolved or denied). Use `useConsentDecision('measurement')` when you need to distinguish `pending` from `denied`.

## Build a preferences screen with a draft

Use `useConsentDraft()` to stage multiple category edits and commit them together on `save()`:

<include src="../../shared/examples/react-native-bare/draft-preferences.mdx" />

`displayedCategories` lists in-scope categories (`necessary` first). Categories with receipts seed from recorded choices; undecided ones seed from effective permissions (excluding GPC restrictions). `isDirty` tracks unsaved edits; `acceptAll` and `rejectAll` stage values without saving.

Unedited categories track external updates. If another surface saves a conflicting value for a staged category, the newer decision wins and that category appears in `staleCategories`. When `isStale` is `true` (from conflicting edits or policy changes), `save()` resolves `ok: false` with `reason: 'concurrent-change'`; call `reset()` and let the user review again.

Draft saves pass the snapshot revision they opened on. If native refuses a commit with `concurrent-change` and no staged category was overtaken, the draft retries once automatically; otherwise it reports `concurrent-change` with `staleCategories` populated. (Older native binaries where `useInthBootstrap().commitRevision` is `false` fall back to JS-side checks and log a dev warning.)

Components outside `ConsentDraftProvider` share one draft so a separate Save button can call `useSaveConsents()()` with no arguments. Wrap a screen in `ConsentDraftProvider` (with optional `initial` defaults) for an isolated draft. Read `snapshot.explicitChoice` when distinguishing explicit choices from opt-out defaults.

## Build your own IAB screen

Under a TCF policy, `useIAB()` stages purpose, vendor, special feature, custom partner, and Additional Consent edits on the same draft, while `usePurposeConsent`, `useVendorConsent`, `useSpecialFeatureOptIn`, and `useAdTechProviderConsent` read staged switches and `useTCString()` reads the committed TC String:

<include src="../../shared/examples/react-native-bare/iab-preferences.mdx" />

Build your UI from `useIABSnapshot()?.disclosure` (the exact disclosure model used by stock screens):

- `vendors[id]`: each vendor's legal bases after publisher restrictions (`consentPurposes`, `legitimateInterestPurposes`, `notAllowedPurposes`, `consentRequiredPurposes`, `legitimateInterestRequiredPurposes`). Offer a switch only when its basis array is non-empty; native rejects empty-basis enables with `reason: 'invalid-iab-choices'`.
- `adTechProviders`: Google Additional Consent providers (`id`, `name`, `policyUrl`), rendered in a separate section and toggled via `useAdTechProviderConsent(id)` and `setAdTechProviderConsent(id, value)`. Native records providers as off unless TCF purposes 1, 3, and 4 (`adTechProviderPurposeIds`) all have consent.
- `purposes[id]`: post-restriction partner counts plus `declaredPurposeIds` and `declaredSpecialFeatureIds`.
- `bannerSummary`: first-layer combined partner count and purpose, stack, and special feature names.
- `consentStorageMaxDays`: maximum TC String retention on the device.

`useIAB()` returns `null` unless the policy is `iab`, a vendor list is loaded, and native supports editing (older binaries without `disclosure` report `headlessUnsupported` and return `null`). When `useIABSnapshot()?.editable` is `false` (stale or offline vendor list), show the committed decision and call `useConsentActions().refresh()`.

`acceptAll()` stages every live partner's allowed bases and grants displayed categories; `rejectAll()` stages withdrawal of all consents and categories while leaving legitimate interest unobjected (use `useSaveConsents()('all')` or `('none')` for immediate one-tap commits). First decisions open with all consents off and disclosed legitimate interests unobjected. Passing `false` to `setPurposeLegitimateInterest` or `setVendorLegitimateInterest` records an objection (purposes 1 and 3 through 6 never use legitimate interest).

Custom partners live in `useIABSnapshot()?.customVendors` and use the same `setVendorConsent`, `setVendorLegitimateInterest`, and `useVendorConsent` APIs. Display them separately from IAB vendors and note they are not registered with IAB. Always gate ad SDKs on committed decisions (native gates and `IABTCF_*` keys), never staged values.

## Show your own first prompt

`ConsentPrompt` invokes its render function only while a policy interaction is owed, passing `activeUI`, `promptRequirement`, and `actions`. Check `promptRequirement.kind` (`choice`, `notice`, or `none`). Call `dismissNotice()` for notices (acknowledgement grants no optional categories) and include your privacy policy link. Wrap policy-dependent UI in `ConsentReady` rather than blocking necessary app screens.

## Hook and component reference

| API | Purpose |
| --- | --- |
| `useConsent(category)` | Boolean effective permission for one category. |
| `useConsentDecision(category)` | `pending`, `denied`, or `granted` state for one category. |
| `useConsentStatus()` | Readiness, pending policy flag, active UI, and owed prompt. |
| `useConsentSelector(selector, equals?)` | Custom snapshot slice with optional equality check. |
| `useSnapshot()` | Full consent snapshot (scope, restrictions, explicit choices). |
| `useSaveConsents()` | Save `'all'`, `'none'`, a category map, or the current draft. |
| `useConsentDraft()` | Stage category edits and commit together. |
| `ConsentDraftProvider` | Isolated draft scope with optional `initial` defaults. |
| `useIAB()` | Stage and commit TCF purpose, vendor, and provider selections. |
| `usePurposeConsent(id)`, `useVendorConsent(id)`, `useSpecialFeatureOptIn(id)`, `useAdTechProviderConsent(id)` | Read one staged TCF or Additional Consent switch. |
| `useTCString()` | Committed TC String. |
| `useIABSnapshot()`, `useIABEnabled()` | Served vendor list, native `disclosure`, committed decision, and TCF active flag. |
| `useDismissNotice()` | Acknowledge a notice without recording optional consent. |
| `useIdentify()` | Link an external account ID. |
| `useSetOverrides()` | Set QA country, region, language, or GPC overrides. |
| `useConsentActions()` | Stable `refresh`, `logout`, `reset`, and `requestTrackingAuthorization` actions. |
| `useInthBootstrap()` | Native protocol, subject bootstrap, and `nativeUI` availability flag. |
| `ConsentGate` | Render children while a category is allowed (with optional fallback). |
| `ConsentReady` | Render children once native consent and policy resolve. |
| `ConsentPrompt` | Render your initial prompt while an interaction is owed. |
| `useTrackingAuthorization()` | Apple ATT status (`unsupported` on Android). |
| `useIsTrackingAllowed(category)` | Category permission combined with platform tracking authorization. |

## Build without the stock native screens

If your app draws every consent screen in React Native, strip the SwiftUI and Compose presenters from your binary. In Expo, add `nativeUI: false` to the plugin config:

{/* example: fragment */}

```ts title="app.config.ts plugin options"
nativeUI: false,
```

In a bare app, set `inth.nativeUI=false` in `android/gradle.properties`, and either add `"inth.nativeUI": "false"` to `ios/Podfile.properties.json` or run `INTH_NATIVE_UI=0 pod install`, then rebuild both platforms.

The consent core, IAB encoding, storage, and SDK gates remain intact while `useInthBootstrap().nativeUI` reads `false` and `presentConsentPrompt`/`presentPreferences` reject with `INTH_NATIVE_UI_EXCLUDED`. Prebuild rejects combining `nativeUI: false` with `theme`; pass your theme to `createConsentTheme` instead.

In development, if a prompt stays owed for three seconds with no `ConsentPrompt` or `ConsentBanner` mounted, the SDK logs a warning. Under a TCF policy, builds without stock native screens support headless IAB only when neither publisher restrictions nor Additional Consent providers are configured (otherwise the SDK logs `console.error` at startup and refuses TCF commits); keep stock screens for those setups.

## Verify the custom flow

Test fresh prompts, reopened settings, refused saves (confirming controls retain prior values), relaunch persistence, withdrawal cleanup, and accessibility (large text, focus order, labels, error announcements). For IAB, inspect the decoded TC String and `IABTCF_*` keys following [Mobile IAB and ads](/docs/frameworks/react-native/iab).
