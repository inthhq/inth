Explore Inth's native engine and consent screens with the runnable demo apps in the source repository before integrating your own app. To add Inth to your app, pick your platform from the [framework list](/docs/frameworks).

## Choose an example

| Example | Source path | Highlights |
| --- | --- | --- |
| SwiftUI app | `packages/swift/Examples/swiftui-consent` | Stock screens, custom category form, consent-gated counter, Keychain persistence |
| SwiftUI and UIKit demo | `examples/native/consent-demo/ios` | Category, notice, and IAB local fixtures plus hosted review mode |
| Kotlin/Compose demo | `examples/native/consent-demo/android` | Matching Android category, notice, IAB, and custom UI flows |
| Bare React Native | `internals/fixtures/react-native-bare` | Native presentation from RN, hooks, and preference reopening |
| Expo | `internals/fixtures/expo-dev` | Config plugin setup and native presentation in a custom build |
| Minimal Swift starters | `packages/swift/Examples/AppleInstallation/Quickstart` | Complete source files used by the SwiftUI and UIKit guides |

Local IAB scenarios use sample disclosures with test CMP ID `53`. Keep local fixtures separate from hosted review runs when gathering compliance evidence.

## Prepare the checkout

Install Bun `1.3.11` plus the platform toolchain you need: Xcode, an iOS simulator runtime, XcodeGen, and CocoaPods for iOS; JDK 17, Android SDK, and `ANDROID_HOME` for Android. From the repository root:

```sh
bun install --frozen-lockfile
bun run --cwd packages/react-native build
```

React Native Android builds require the versioned `com.inth` Maven repository from [Bare React Native](/docs/frameworks/react-native/bare); the standalone Android demo uses the local Gradle project.

## Run the SwiftUI app

Generate and open the project:

```sh
xcodegen generate --spec packages/swift/Examples/swiftui-consent/project.yml
open packages/swift/Examples/swiftui-consent/InthSwiftUI.xcodeproj
```

Run the `InthSwiftUI` scheme (add `--headless` to Run arguments for the custom category form). Follow the [SwiftUI walkthrough](/docs/frameworks/react-native/swiftui) for a code tour.

## Run the SwiftUI or UIKit demo

Generate the project into a fresh directory outside the checkout:

```sh
bun examples/native/consent-demo/ios/generate-project.ts /tmp/inth-consent-demo
open /tmp/inth-consent-demo/InthConsentDemo.xcodeproj
```

Run `InthConsentDemo` (SwiftUI) or `InthUIKitDemo` (UIKit) with simulator signing enabled. In Debug, choose a local Category, Notice, or IAB fixture, or enter your hosted project URL, privacy policy URL, and CMP settings ([Mobile IAB and ads](/docs/guides/mobile-iab)).

## Run the Android demo

Build from the repository root, then open `packages/android` in Android Studio and run `consent-demo`:

```sh
sh packages/android/gradlew -p packages/android :consent-demo:assembleDebug
```

## Run bare React Native

Follow `internals/fixtures/react-native-bare/README.md` for native dependency setup and platform builds, and verify TypeScript types with:

```sh
bun run --cwd internals/fixtures/react-native-bare check-types
```

Normal mode launches native SwiftUI/Compose screens (`INTH_FAKE_NATIVE=true` switches to a labeled JavaScript fixture).

## Run Expo

Follow `internals/fixtures/expo-dev/README.md` and [Expo and EAS](/docs/frameworks/react-native/expo) to build a custom native binary (Expo Go cannot load native modules), and check types with:

```sh
bun run --cwd internals/fixtures/expo-dev check-types
```

Standard TCF configuration uses the plugin's `iab` option; publisher restrictions or custom purposes require app-owned native installation.

## Walk through the IAB flow

In the native demo's local IAB fixture:

1. Tap **Customize** and expand a purpose's details.
2. Open the partner list, search, and inspect a vendor before toggling consent.
3. Open **Other ad partners** for sample Additional Consent providers `10` and `20`.
4. Save a granular choice and inspect the native authority readout.
5. Accept all, reopen **Privacy settings**, then reject all and restart to verify the refusal persists.

Additional Consent providers require TCF consent for purposes 1, 3, and 4. Use hosted review mode with live disclosures and follow [Verify mobile consent](/docs/guides/mobile-verify) before release.
