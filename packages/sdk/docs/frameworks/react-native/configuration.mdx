Configure the consent engine in the native app before React starts. Expo uses
the config plugin; bare RN uses native metadata. `ConsentProvider` reads the
installed engine and has no backend or policy-options prop.

## Set your Inth project URL

The mobile SDKs work only with Inth hosted projects. There is one mode, so
there is no `mode` option and no self-hosted backend on mobile. Set
`projectUrl` to the project URL from your Inth dashboard. The app fetches
policy from that project and sends consent records to it.

`projectUrl` takes these forms. Each one becomes
`https://your-project.inth.app`:

| You write | What happens |
| --- | --- |
| `https://your-project.inth.app` | Used as written. |
| `your-project.inth.app` | A missing scheme means `https`. |
| `https://your-project.inth.app/` | Trailing slashes are dropped. |
| `HTTPS://Your-Project.Inth.App` | The scheme and host are lowercased. |

Whitespace around the value is trimmed.

Prebuild refuses everything else: another host, `http`, a port, a path, a
query, a fragment, or a username or password. The error quotes your value and
names the rule it broke:

{/* example: fragment */}

```txt
projectUrl must be the project URL from your Inth dashboard, such as https://your-project.inth.app. Got "https://consent.example.com": the host must be a project host under inth.app.
```

Native startup checks the URL again with the same rule. The URL is public
binary configuration; keep credentials out of it.

### Replace removed options

`mode` and `initURL` are gone. Prebuild stops with an error that names the
replacement:

| Removed | Use instead |
| --- | --- |
| `mode: 'hosted'` | Remove it. Hosted is the only mode. |
| `mode: 'selfHosted'` | Nothing. Mobile works only with Inth. Set `projectUrl` to your Inth project URL. |
| `mode: 'offline'` | `dryRun: true` in development and CI. In production keep `projectUrl`; `bundleManifest` or `policy` covers a launch without network. |
| `mode: 'custom'` | `autoBootstrap: false`. Your native app installs Inth before React Native starts. Custom transports are gone. |
| `initURL` | Nothing. The app fetches policy from `projectUrl`. |

## Use dryRun in development and CI

`dryRun: true` runs consent on the device and sends no consent records. The
prompt, storage, SDK gates and consent signals (the TC string, the GPP string,
the `IABTCF_*` and `IABGPP_*` keys and Consent Mode) work as normal. The engine
drops each consent record instead of queueing or sending it. Identity calls,
such as the one `useIdentify()` returns, change local state and send nothing.
A save still succeeds, with nothing queued.

The app still fetches policy from `/init`, so you see your project's real
policy. With a bundled manifest or an in-code `policy`, a dry-run launch needs
no network.

{/* example: fragment */}

```ts title="app.config.ts"
{
	projectUrl: 'https://your-project.inth.app',
	dryRun: process.env.INTH_DRY_RUN === '1',
}
```

A release build refuses `dryRun`. No engine starts, every read answers
deny-all, and the device log says why. Prebuild cannot see which build comes
next, so the plugin writes the flag and warns once, and native code decides at
launch:

| Platform | What counts as a release build | Where the refusal appears |
| --- | --- | --- |
| iOS | The app was compiled without `DEBUG`. The pod compiles the engine with your app's configuration. | Console, code `INTH_CONFIGURATION_DRY_RUN` |
| Android | The app is not debuggable (`FLAG_DEBUGGABLE` is off). | Logcat, tag `inth` |

Remove `dryRun`, or leave its environment variable unset, in release builds.

With `dryRun` on, `projectUrl` also takes any `https` URL, or `http` on
`localhost`, `127.0.0.1` or `[::1]`, with a port and a path. Usernames,
passwords, queries and fragments stay refused.

## Set Expo options

Use the [complete Expo configuration](/docs/frameworks/react-native/expo#configure-the-plugin)
for a working `app.config.ts`. The plugin accepts:

| Option | Purpose |
| --- | --- |
| `projectUrl` | Required. The project URL from your Inth dashboard. See [Set your Inth project URL](#set-your-inth-project-url). |
| `dryRun` | Development and CI switch that drops consent records. Defaults to false. See [Use dryRun in development and CI](#use-dryrun-in-development-and-ci). |
| `property` | The `property` each consent record names. Defaults to the iOS bundle identifier and the Android application ID. Sent lowercase. |
| `consentCategories` | Optional app category declaration. |
| `vendors` | Optional IAB disclosure scope. |
| `iab` | Optional IAB TCF CMP identity and publisher settings. See [Turn on IAB TCF](#turn-on-iab-tcf). |
| `gpp` | Optional IAB GPP string and `IABGPP_*` keys. See [IAB GPP](/docs/frameworks/react-native/gpp). |
| `policyResource` | Build-exported policy JSON, relative to the Expo project. |
| `bundleManifest` | Fetch the manifest at prebuild with `c15t mobile-manifest` and bundle it. Replaces `policyResource`. See [bundle the manifest at build time](/docs/guides/mobile-offline#bundle-the-manifest-at-build-time). |
| `policy` | Policy rules in source control, as `{ rules: [...] }` in the backend's `PolicyRule` names. The device resolves them and never calls `/init`. It cannot be combined with `policyResource`, `bundleManifest` or `iab`. See [define the policy in code](/docs/guides/mobile-offline#define-the-policy-in-code). |
| `androidMavenRepository` | Build-time native artifact repository and credential environment-variable names. |
| `autoBootstrap` | Whether native launch installs the engine. Defaults to true. Set false when your native app installs it. |
| `forceGPC` | GPC input for a staged or test build. |
| `enableAppTrackingTransparency` | Enable Apple's tracking-authorization declarations. Defaults to false. |
| `trackingUsageDescription` | App-specific plain-text ATT explanation, required when ATT is enabled. |
| `trackingMarkdownUsageDescription` | Optional expanded ATT copy on supported Apple systems. |
| `trackingMarkdownUsageDescriptionLocalizations` | Locale-to-copy map for that expanded description. |
| `skAdNetworkIdentifiers` | Native SKAdNetwork declarations when ATT is enabled. |
| `privacyTrackingDomains` | Native tracking-domain declarations when ATT is enabled. |

Repository settings affect dependency resolution during the build. They do
not select the consent backend. Store repository credentials in the build
environment; the plugin accepts their environment-variable names, not their
values.

## Set bare RN metadata

Use these keys when configuring the same engine without Expo:

| Expo option | iOS `Info.plist` key | Android application metadata |
| --- | --- | --- |
| `projectUrl` | `com.inth.backend.url` | `com.inth.BACKEND_URL` |
| `dryRun` | `com.inth.dryRun`, boolean | `com.inth.DRY_RUN` |
| `property` | `com.inth.backend.property` | `com.inth.BACKEND_PROPERTY` |
| `consentCategories` | `com.inth.categories`, string array | `com.inth.CATEGORIES`, comma-separated |
| `vendors` | `com.inth.vendors` | `com.inth.VENDORS`, comma-separated |
| `policyResource` | `com.inth.policy.resource` | `com.inth.POLICY_RESOURCE` |
| `forceGPC` | `com.inth.forceGPC` | `com.inth.FORCE_GPC` |
| `iab` | `com.inth.iab.*`, see below | `com.inth.IAB_*`, see below |
| `autoBootstrap: false` | `com.inth.reactnative.AutoBootstrap` | `com.inth.reactnative.AUTO_BOOTSTRAP` |

The project URL follows the [same rule](#set-your-inth-project-url) as the
Expo option, and both platforms check it at launch. Follow
[bare setup](/docs/frameworks/react-native/bare) for the full file context and
linking steps.

Remove these retired keys. Expo prebuild deletes them for you.

| Retired key | Use instead |
| --- | --- |
| `com.inth.backend.mode` (iOS), `com.inth.MODE` (Android) | Nothing for hosted. `com.inth.dryRun` or `com.inth.DRY_RUN` in development and CI. |
| `com.inth.backend.initUrl` (iOS), `com.inth.BACKEND_INIT_URL` (Android) | Nothing. The app fetches policy from the project URL. |

A build that still declares one does not start the engine. iOS logs
`INTH_CONFIGURATION_RETIRED` with the key and its replacement. Android logs an
error under the `inth` tag. Every read answers deny-all until you remove the
key.

## Declare the categories your app uses

Category IDs are `necessary`, `functionality`, `experience`, `measurement` and
`marketing`. The app declaration and the resolved policy determine the offered
scope. A declaration narrows scope; it never grants permission.

Omit `consentCategories` to use the policy's scope rules. An empty plugin array
is refused because an empty declaration would be ambiguous. Always read the
resolved `snapshot.consentCategories` when building your own category list.

Vendor IDs similarly narrow the served IAB disclosures. Omit `vendors` to keep
the served list. It must be nonempty when supplied. Vendor scope does not
install CMP/publisher identity or grant a vendor. Use `iab` for that.

## Turn on IAB TCF

Set the `iab` plugin option in Expo, or the matching native metadata in bare
RN. Native startup then installs the engine with IAB TCF on. It writes
`IABTCF_CmpSdkID` and `IABTCF_CmpSdkVersion` at launch, and the stock native
presenter can save IAB choices. Leave `iab` out to keep IAB TCF off.

| Expo `iab` field | iOS `Info.plist` key | Android metadata | Value |
| --- | --- | --- | --- |
| `cmpId` | `com.inth.iab.cmpId`, integer | `com.inth.IAB_CMP_ID` | Required. The CMP ID IAB Europe registered for your CMP, 2 to 4095. There is no default. |
| `cmpVersion` | `com.inth.iab.cmpVersion`, integer | `com.inth.IAB_CMP_VERSION` | Required. Your internal CMP version, 0 to 4095. |
| `publisherCountryCode` | `com.inth.iab.publisherCountryCode` | `com.inth.IAB_PUBLISHER_COUNTRY_CODE` | Required. Two letters, such as `DE`. |
| `consentScreen` | `com.inth.iab.consentScreen`, integer | `com.inth.IAB_CONSENT_SCREEN` | Optional. 0 to 63. Defaults to 1. |

The Expo plugin stops prebuild when a value is missing or out of range. Native
startup checks the same ranges. If any `iab` key is present but the set is
incomplete or out of range, startup logs an error and starts the engine
without IAB TCF. Category consent still works, no CMP ID is written, and IAB
saves fail with `iab-unavailable` until you fix the values.

Your Inth project must also serve an IAB policy for the regions where TCF
applies. Rebuild the native app after changing these values. Apps that need
publisher restrictions or custom purposes still install the engine
themselves; see [IAB setup](/docs/guides/mobile-iab).

## Preview a regional policy

The function `useSetOverrides()` returns accepts `country`, `region`, `language` and
`gpc`. Use these in a debug menu to exercise your policy rules. Omitted values
stay as they are; explicit null clears country, region or GPC overrides.

Overrides change policy inputs without recording a choice. The effective GPC
answer is `snapshot.privacySignals.gpc.active`; the detected and overridden
values remain separate. Remove test overrides before shipping.

## Add a policy for offline startup

A valid bundled policy lets a fresh installation show its prompt while
disconnected. Set `bundleManifest` or `policyResource` in Expo, or the
corresponding native metadata. The engine queues the choice and delivers it to
your Inth project when the app reconnects.
[Offline policies](/docs/guides/mobile-offline) explains export, embedding,
expiry and updates.

## Let your app install the engine

Use `autoBootstrap: false` when your app owns native installation, as a
brownfield app does. Install once, before RN and optional SDK startup, with
`InthApple.install` on iOS and `InthAndroid.install` on Android, then attach
the RN adapter to that engine. The native installers take the same Inth
project URL and `dryRun` switch. They do not take a custom transport.

The [native startup guide](/docs/frameworks/react-native/native-behaviour)
explains ordering and protected-storage recovery. Use
[mobile IAB setup](/docs/guides/mobile-iab) when your native installation also
needs CMP and publisher settings.
