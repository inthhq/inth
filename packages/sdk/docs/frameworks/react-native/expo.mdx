Add the `@inth/react-native` config plugin to write your Inth project URL, categories, theme, and native permissions at prebuild time. Your app then uses the same provider, hooks, and native consent screens as bare React Native.

Target Expo SDK 55 through 58 with a development build or standalone binary, using the React Native and React versions Expo prescribes (target Expo 58 for new apps). Expo Go cannot load native modules. See [Compatibility and updates](/docs/frameworks/react-native/platform-support).

## Install the package

Install the private prerelease tarball from your Expo project root:

```sh
npm install /absolute/path/to/inth-react-native.tgz
```

Obtain your Android Maven repository URL and build credentials from your maintainer; the plugin defines no default artifact repository. See [mobile availability](/docs/guides/mobile-status).

The package ships an `inth-react-native` agent skill. On Expo SDK 58 and later, run `npx @expo/agent-cli skills:sync` to link it for your coding agent.

## Configure the plugin

Merge `@inth/react-native` into the `plugins` array in `app.config.ts`, keeping your existing bundle identifier, Android package name, and other plugins:

<include src="../../shared/examples/expo-dev/expo-config.mdx" />

Import plugin types from `@inth/react-native/expo-plugin` (which also works as the plugin name). The plugin runs against your app's installed `expo/config-plugins` and declares `expo` 55 through 58 as an optional peer dependency.

Update these values before building:

| Option | Purpose |
| --- | --- |
| `projectUrl` | Your Inth dashboard project URL (`https://your-project.inth.app`). Prebuild refuses any other host. |
| `consentCategories` | Categories your app uses, matching your Inth policy. |
| `androidMavenRepository.url` | Versioned Maven repository URL for native Android artifacts. |
| Maven credential env var names | Environment variable names present locally and in EAS (never inline secrets in `app.config.ts`). |
| `policyResource` | Optional build-exported policy file; omit if not bundling an offline policy. |

If you keep `policyResource`, export `inth-policy.json` beside `app.config.ts` following [Mobile offline consent](/docs/guides/mobile-offline). For development and CI without sending consent records, set `dryRun: true` (refused in release builds; see [Use dryRun in development and CI](/docs/frameworks/react-native/configuration#use-dryrun-in-development-and-ci)).

The plugin writes native launch metadata, Android startup and internet permissions, iOS privacy declarations, and denied [Firebase Consent Mode defaults](/docs/integrations/firebase-analytics#deny-consent-mode-signals-by-default) in `Info.plist` and `AndroidManifest.xml` (harmless without Firebase). Do not pass a project URL to `InthProvider` in JavaScript.

The plugin raises the iOS deployment target to 16.4 when lower (including Expo 55's 15.1 default) and keeps higher targets. On Android, it checks for `minSdkVersion >= 24` and `compileSdkVersion >= 36` (Expo 58 defaults to 37) and fails prebuild if your configuration sets lower values.

## Theme the native screens

Pass a `theme` object in the plugin options to configure native screen colors, radii, spacing, typography, slots, branding, and layout at prebuild. Because it shares the `createConsentTheme` shape, one JSON file can theme both native screens and React Native components; see [Theme both renderers from one object](/docs/frameworks/react-native/customize#theme-both-renderers-from-one-object):

<include src="../../shared/examples/expo-dev/expo-theme.mdx" />

`colors` holds light values and `dark` overrides them for dark mode. Native colors must be `#RRGGBB`, and every native `dark` field requires its matching field in `colors`:

| Field | Web token | Native setting |
| --- | --- | --- |
| `colors.primary` | `--inth-primary` | Accent (links, switches, Save) |
| `colors.textOnPrimary` | `--inth-text-on-primary` | Text on accent |
| `colors.surface` | `--inth-surface` | Cards and list rows |
| `colors.text` | `--inth-text` | Primary text |
| `colors.textMuted` | `--inth-text-muted` | Supporting text |
| `colors.canvas` | None | Page background |
| `colors.surfaceMuted` | None | Secondary surface for partner lists |
| `colors.decision`, `colors.textOnDecision` | None | Shared Accept all and Reject all fill and label |
| `radius.sm`, `radius.md`, `radius.lg` | `--inth-radius-*` | Callout, button/card, and notice radii (pt/dp) |
| `spacing.xs` to `spacing.xl` | `--inth-space-*` | Page gutters, section gaps, and padding (pt/dp) |
| `typography.fontSize.sm`, `.base`, `.lg` | `--inth-font-size-*` | Supporting, body, and headline sizes (pt/sp) |
| `typography.fontFamily` | `--inth-font-family` | Bundled font for body roles |
| `typography.headlineFont` | None | `serif`, `rounded`, `sans`, or a bundled font |
| `slots.consentBannerTitle`, `consentBannerDescription`, `buttonPrimary`, `buttonSecondary` | Web `slots` | Per-part `color`, `backgroundColor`, `borderRadius`, or `fontSize` |
| `brand.name`, `brand.mark`, `brand.hidden` | None | App name and mark above the headline |
| `branding.provider`, `branding.name`, `branding.mark`, `branding.hidden` | None | Provider attribution |
| `firstLayer` | None | `page` (default), `sheet`, or `prompt` |
| `appearance` | None | `system` (default) or `c15t` stock color palette |
| `savePlacement` | None | `top` (default) or `bottom` Save placement in Privacy Settings |

Bundled fonts take a PostScript name on iOS and a font resource name on Android (`{ ios: 'Inter-Bold', android: 'inter_bold' }` when they differ, or one string when valid for both). To exclude stock native screens altogether, pass `nativeUI: false` instead of `theme`; see [Build without the stock native screens](/docs/frameworks/react-native/headless#build-without-the-stock-native-screens).

Prebuild ignores React-only fields (`motion`, `colors.border`, `typography.lineHeight`) and fails on unsupported values (such as `hsl()`), unused web fields (`shadows`), or `copy` (see [Copy and languages](/docs/frameworks/react-native/customize#copy-and-languages)). When `theme` is present, the plugin owns native theme keys and prunes removed entries. Rebuild the binary after changing `theme`.

## Add the React root

Create `setup.tsx` outside your Expo Router routes directory using the [quickstart's Privacy settings button](/docs/frameworks/react-native/quickstart#keep-privacy-settings-reachable).

If your entry point is `App.tsx`, use the quickstart snippet directly. For Expo Router, wrap your existing `Stack` or `Slot` inside `app/_layout.tsx` (or `src/app/_layout.tsx`), keeping your other providers and splash handling:

{/* example: fragment */}

```tsx
return (
	<InthProvider privacyPolicyUrl="https://example.com/privacy">
		<Stack />
	</InthProvider>
);
```

Keep `InthProvider` mounted across route transitions and keep Privacy settings reachable after dismissal.

## Run on Expo web

A universal Expo app runs on web with `npx expo start --web` using the `@inth/sdk` browser engine and the same plugin options. See [Expo web](/docs/frameworks/react-native/web) for web setup and native-only differences.

## Build locally

Run prebuild after any plugin change, then build one platform at a time:

```sh
npx expo prebuild
npx expo run:ios
npx expo run:android
```

Verify Reject all, relaunch, and Privacy settings with the [quickstart checklist](/docs/frameworks/react-native/quickstart#check-that-it-works).

## Configure EAS builds

EAS build workers need access to both the package tarball and Android artifacts:

1. Point `package.json` at an authorized package source or tarball reachable by the remote EAS worker (not a local machine path).
2. Store Maven username and token as EAS secrets matching the names in `androidMavenRepository.credentials`. Ensure `androidMavenRepository.url` is reachable over HTTPS (local file paths work locally only).
3. Run a development build profile:

```sh
npx eas-cli build --profile development --platform ios
npx eas-cli build --profile development --platform android
```

## Keep OTA updates compatible

Always configure `runtimeVersion` when `updates.url` is set (the example uses Expo's fingerprint policy). JavaScript OTA updates cannot add native methods, themes, permissions, or embedded policies; ship a new binary whenever native inputs change. See [Compatibility and updates](/docs/frameworks/react-native/platform-support).

## Enable App Tracking Transparency when needed

If your app requires Apple tracking authorization, enable `enableAppTrackingTransparency` and set an app-specific `trackingUsageDescription` (plus optional `trackingMarkdownUsageDescription`, localizations, `skAdNetworkIdentifiers`, and `privacyTrackingDomains`).

`<InthProvider>` requests ATT after the consent prompt closes when marketing is granted (override with `trackingRequest` set to `beforeConsent` or `manual`). Read [ask for ATT after the consent prompt](/docs/frameworks/react-native/iab#ask-for-att-after-the-consent-prompt) and [keep ATT separate](/docs/frameworks/react-native/iab#keep-att-separate) before wiring ad SDKs.

## Turn on IAB TCF

Set the plugin's `iab` option with your registered `cmpId`, `cmpVersion`, `publisherCountryCode`, and optional `consentScreen`. Prebuild validates ranges and fails on missing values; see [Turn on IAB TCF](/docs/frameworks/react-native/configuration#turn-on-iab-tcf).

`iab` cannot combine with an in-code `policy` because the Global Vendor List comes from `/v1/consent/init`. `vendors` narrows disclosures without enabling IAB. For publisher restrictions or custom purposes, follow [Mobile IAB and ads](/docs/guides/mobile-iab).

For EAS telemetry, see [Expo Observe](/docs/integrations/expo-observe) and [PostHog](/docs/integrations/posthog#apps-set-up-with-the-eas-posthog-integration).
