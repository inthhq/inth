description: Fix React Native linking, native startup, policy loading, refused saves, and consent screen issues with Inth.

Start from the native error and failing stage (linking, startup, policy resolution, presentation, or saving). Keep optional SDKs off whenever the consent engine is unavailable.

## `NativeInthUnavailableError` on launch

The installed app binary does not contain the Inth native module.

1. Run a custom native build (Expo Go and web targets do not load native modules).
2. Confirm `@inth/react-native` is installed in the app project.
3. Run `npx expo prebuild` in Expo, or `pod install` in bare iOS.
4. Rebuild and reinstall the native binary (restarting Metro updates JavaScript only).

See [Expo and EAS](/docs/frameworks/react-native/expo) or [Bare React Native](/docs/frameworks/react-native/bare).

## Android cannot resolve `com.inth`

The Gradle build cannot reach the versioned `com.inth` Maven repository (the plugin defines no default repository).

- Add the supplied repository URL and `com.inth` group filter to Gradle.
- Export the expected Maven credential environment variables locally and in CI/EAS.
- Let `@inth/react-native` select the matching `com.inth` version.
- Use an HTTPS repository for EAS builds (local file paths work locally only).

See [Set up Android](/docs/frameworks/react-native/bare#set-up-android) or [Configure the plugin](/docs/frameworks/react-native/expo#configure-the-plugin).

## CocoaPods cannot find the native sources

Run `pod install` after installing `@inth/react-native` and build the generated `.xcworkspace`. The pod compiles vendored Swift sources inside the npm package; never link standalone `InthCore` or `InthApple` SwiftPM products alongside it.

## Hooks report a missing provider

Mount one `InthProvider` above every screen and navigator that calls consent hooks, including settings screens opened later. See [Add the consent provider](/docs/frameworks/react-native/quickstart#add-the-consent-provider). Adding the provider does not replace native `projectUrl` metadata.

## The consent prompt never appears

Inspect `useConsentStatus()` and your snapshot:

| State | Cause and fix |
| --- | --- |
| `ready` is `false` | Native hydration failed or is still running. Check installation and protected-storage errors. |
| `policyPending` is `true` | Verify `projectUrl`, network connectivity, and any bundled policy resource. |
| `promptRequirement.kind` is `'none'` | No prompt is owed (valid saved choice or non-prompting region). Open **Privacy settings** to edit choices. |
| Choice is owed, nothing opens | Check the console for `Inth InthProvider` errors or warnings (refused `privacyPolicyUrl`, outdated binary predating auto-present, or no foreground window yet). Verify the outermost `InthProvider` passes `privacyPolicyUrl` without `autoPresent={false}`. |

A `not-bootstrapped` error means native startup was disabled, unconfigured, or rejected. Native startup refuses invalid configurations (leaving every read deny-all) and logs the reason in the iOS console or Android Logcat (`inth` tag):

| iOS code | Cause | Fix |
| --- | --- | --- |
| `INTH_CONFIGURATION_BACKEND_URL` | Missing or non-Inth project URL. | Set `projectUrl` to your Inth dashboard URL (`https://your-project.inth.app`). |
| `INTH_CONFIGURATION_DRY_RUN` | `dryRun` enabled in a release build. | Disable `dryRun` for release builds. |
| `INTH_CONFIGURATION_RETIRED` | Stale `com.inth.backend.mode`, `com.inth.backend.initUrl`, or `com.inth.test` keys (Android: `com.inth.MODE`, `com.inth.BACKEND_INIT_URL`). | Delete the retired keys (rerun `npx expo prebuild` in Expo). |

On iOS, `protectedStorageUnavailable` means Keychain was locked at launch; retry after unlock or activation without substituting memory storage. See [Native startup and SDK gates](/docs/frameworks/react-native/native-behaviour).

## `InthProtocolMismatchError` or missing native method

The JavaScript package and compiled binary come from different releases. Install the matching `@inth/react-native` version, rebuild the binary, and keep Expo's `runtimeVersion` aligned before publishing OTA updates. See [Compatibility and updates](/docs/frameworks/react-native/platform-support).

## Development warning about bridge payload drift

In development, the client warns if a native bootstrap or commit payload omits an expected key, indicating a JS/native version mismatch. Rebuild so both halves match. To inspect payloads manually, use `describeBridgePayloadDrift` from `@inth/react-native/bridge-schema` (kept out of the main entry for bundle size):

{/* example: fragment */}

```ts
import { describeBridgePayloadDrift } from '@inth/react-native/bridge-schema';

const problems = describeBridgePayloadDrift('commitResult', result, {
	allowUnknownKeys: true,
});
```

## A save resolves without changing consent

Always inspect `CommitResult.ok` and `reason` (`COMMIT_FAILURE_REASONS` lists all native codes):

| `reason` | Fix |
| --- | --- |
| `policy-pending` | Wait for policy resolution before saving grants. |
| `queue-write-failed` | Keep the form open, surface an error, and let the user retry once storage recovers. |
| `concurrent-change` | Reload current settings and let the user review the draft again. |
| `invalid-iab-choices`, `iab-list-stale`, `bundled-policy-unusable` | Refresh disclosures or fix out-of-scope selections. |

Offline saves with `ok: true, queued: true` succeeded locally and do not need manual retries. See [Commands and outcomes](/docs/frameworks/react-native/usage).

## Fresh offline launch shows no prompt

Export and embed a bundled policy manifest for the same `projectUrl` and rebuild the binary. Expired or mismatched bundles block new optional grants while keeping withdrawal working. See [Mobile offline consent](/docs/frameworks/react-native/offline).

## Consent records never appear in Inth

Check whether `dryRun` is enabled (which drops all outgoing records while reporting local success). If using an in-code `policy`, make sure its rules match your Inth dashboard policy so the backend does not reject records with HTTP `422`. See [define the policy in code](/docs/frameworks/react-native/offline#define-the-policy-in-code).

## IAB choices are unavailable

`consentCategories` and `vendors` do not enable IAB TCF. Configure `iab` (or native CMP installation), ensure your Inth project serves an IAB policy and current GVL, and refresh stale disclosures rather than editing `IABTCF_*` keys directly. See [Mobile IAB and ads](/docs/frameworks/react-native/iab).

## Optional SDK sends requests before consent

Disable the vendor's automatic native initializer or Expo plugin, gate initialization natively before React boots, and keep a subscription that stops collection on withdrawal. See [Native startup and SDK gates](/docs/frameworks/react-native/native-behaviour).

## Theme changes do not appear

Native SwiftUI and Compose screens ignore React `style` props. Set [native theme keys](/docs/frameworks/react-native/customize) (or the Expo plugin [`theme` option](/docs/frameworks/react-native/expo#theme-the-native-screens)) and rebuild the native binary.

## ATT request fails or reports unsupported

Verify `NSUserTrackingUsageDescription` is present in `Info.plist` and rebuild iOS. Android has no ATT prompt and always returns `unsupported`. See [keep ATT separate](/docs/frameworks/react-native/iab#keep-att-separate).

## Expo rejects `updates.url`

Set `runtimeVersion` (such as Expo's fingerprint policy) before enabling EAS Updates so OTA JavaScript never ships to an incompatible binary. After fixing any issue, re-run the affected flow against [Verify mobile consent](/docs/frameworks/react-native/verify).
