A fresh install presents the native Inth consent prompt before your first screen. The stock SwiftUI and Compose screens expose identical stable selectors on iOS and Android, and `@inth/react-native` ships ready-made Maestro subflows to dismiss or test consent flows.

## Answer the prompt in Maestro

Call `dismiss-if-shown.yaml` right after `launchApp`. It waits for the prompt or notice, taps Reject all (or Got it), and passes cleanly when no prompt appears:

```yaml title=".maestro/home.yaml"
appId: com.example.app
---
- launchApp:
    clearState: true
    clearKeychain: true
- runFlow: ../node_modules/@inth/react-native/maestro/dismiss-if-shown.yaml
- assertVisible: 'Welcome!'
```

`runFlow` paths are relative to the calling file. Subflows declare `appId: ${APP_ID}` automatically and inherit the caller's app ID. To accept instead of rejecting, set `INTH_CHOICE: accept-all` (rejecting is safer for unrelated tests so optional SDKs send no test traffic):

```yaml title=".maestro/home.yaml"
- runFlow:
    file: ../node_modules/@inth/react-native/maestro/dismiss-if-shown.yaml
    env:
      INTH_CHOICE: accept-all
```

### Shipped subflows

All subflows live in `node_modules/@inth/react-native/maestro/`:

| Flow | Action | Variables |
| --- | --- | --- |
| `dismiss-if-shown.yaml` | Dismisses a prompt or notice if shown within timeout | `INTH_CHOICE` (`reject-all` or `accept-all`), `INTH_TIMEOUT` (default `10000` ms) |
| `accept-all.yaml` | Waits for first layer and taps Accept all (fails if absent) | `INTH_TIMEOUT` (default `15000` ms) |
| `reject-all.yaml` | Waits for first layer and taps Reject all (fails if absent) | `INTH_TIMEOUT` |
| `open-preferences.yaml` | Taps Customize or Privacy settings and waits for preferences | `INTH_TIMEOUT` |
| `toggle-category.yaml` | Toggles one category switch in preferences | `INTH_CATEGORY` (such as `measurement` or `marketing`) |
| `save-preferences.yaml` | Taps Save in category or IAB preferences and waits for close | `INTH_TIMEOUT` |
| `close-preferences.yaml` | Closes preferences without saving (confirming Discard if prompted) | `INTH_TIMEOUT` |

### Test a custom category choice

```yaml title=".maestro/consent-custom.yaml"
appId: com.example.app
---
- launchApp:
    clearState: true
    clearKeychain: true
- runFlow: ../node_modules/@inth/react-native/maestro/open-preferences.yaml
- runFlow:
    file: ../node_modules/@inth/react-native/maestro/toggle-category.yaml
    env:
      INTH_CATEGORY: measurement
- runFlow: ../node_modules/@inth/react-native/maestro/save-preferences.yaml
```

Assert after saving that your UI reflects measurement enabled while other optional categories stay off.

### Reopen preferences from your app

Tap your app's Privacy settings button, wait for the Save control, and reuse the toggle and save subflows:

```yaml title=".maestro/privacy-settings.yaml"
- tapOn: 'Privacy settings'
- extendedWaitUntil:
    visible:
      id: 'inth\.(prefs|iab)\.save'
    timeout: 15000
- runFlow:
    file: ../node_modules/@inth/react-native/maestro/toggle-category.yaml
    env:
      INTH_CATEGORY: marketing
- runFlow: ../node_modules/@inth/react-native/maestro/save-preferences.yaml
```

## Start from a fresh install

iOS stores consent in Keychain, which survives `clearState`, so pass both `clearState: true` and `clearKeychain: true` on `launchApp` (Android ignores `clearKeychain`, so one block works on both platforms). Note that `clearKeychain` clears the whole Simulator Keychain; omit both options when carrying a decision across tests.

## Selectors

Each selector maps to SwiftUI `accessibilityIdentifier` on iOS and Compose `testTag` (resource ID) on Android, readable by Maestro (`id:`), XCUITest (`identifier`), and UI Automator (`By.res()`). Escape literal dots when combining IDs with `|` in Maestro regexes.

| Selector | Screen | Element |
| --- | --- | --- |
| `inth.first-layer` | First layer | Full-screen prompt |
| `inth.first-layer.title` | First layer | Headline |
| `inth.first-layer.accept-all` | First layer | Accept all |
| `inth.first-layer.reject-all` | First layer | Reject all |
| `inth.first-layer.customize` | First layer | Opens preferences |
| `inth.first-layer.description` | First layer (IAB) | Disclosure sentence with partner count |
| `inth.first-layer.summary.item.<index>` | First layer (IAB) | Summary purpose item (0-indexed) |
| `inth.first-layer.partner-count` | First layer (IAB) | Opens partner list |
| `inth.notice` | Notice | Notice card |
| `inth.notice.acknowledge` | Notice | Got it button |
| `inth.notice.settings` | Notice | Opens preferences |
| `inth.prefs` | Preferences | Category list |
| `inth.prefs.category.<category>.switch` | Preferences | Optional category switch (such as `measurement`) |
| `inth.prefs.category.<category>.locked` | Preferences | Locked status for `necessary` |
| `inth.prefs.category.<category>.restricted` | Preferences | Restricted optional category indicator |
| `inth.prefs.accept-all` | Preferences | Accept all |
| `inth.prefs.reject-all` | Preferences | Reject all |
| `inth.prefs.save` | Preferences | Save |
| `inth.prefs.cancel` | Preferences / IAB | Back, Cancel, or Close |
| `inth.prefs.discard.confirm` | Preferences / IAB | Discard unsaved changes |
| `inth.prefs.discard.keep` | Preferences / IAB | Keep editing |
| `inth.iab` | IAB preferences | IAB purpose list |
| `inth.iab.accept-all` | IAB preferences | Accept all |
| `inth.iab.reject-all` | IAB preferences | Reject all |
| `inth.iab.save` | IAB preferences | Save |
| `inth.iab.purpose.<purpose>.consent` | IAB preferences | IAB purpose consent switch |
| `inth.iab.special-feature.<feature>.switch` | IAB preferences | Special feature switch |
| `inth.iab.partners` | IAB preferences | Opens partner list |
| `inth.iab.vendors` | Partner list | Partner list container |
| `inth.iab.vendors.search` | Partner list | Partner search field |
| `inth.iab.vendors.vendor.<vendor>` | Partner list | Vendor row by GVL ID |
| `inth.iab.vendors.back` | Partner list | Back to IAB preferences |
| `inth.privacy-policy` | Any | Privacy policy link |

Inth's test suite locks these selectors across both platforms (see `node_modules/@inth/react-native/maestro/selectors.json`). At accessibility text sizes, Reject All and Accept All move into the scrolling area; use `scrollUntilVisible` before `tapOn` in large-text tests.

## Choose a backend for test builds

- **Debug builds:** Set `dryRun: true` so prompts and gates work normally without sending records ([details](/docs/frameworks/react-native/configuration#use-dryrun-in-development-and-ci)).
- **Release builds (including EAS E2E builds):** Release builds reject `dryRun`. Point `projectUrl` at a dedicated staging Inth project per build profile so test traffic stays out of production.

To test a specific region, pin location in a debug menu via `useSetOverrides()` ([Preview a regional policy](/docs/frameworks/react-native/configuration#preview-a-regional-policy)). For non-consent UI suites, pass `autoPresent={false}` in your test build so optional gates remain closed under opt-in rules without blocking unrelated screens.

## Run on EAS Workflows

Because EAS Workflows' `maestro` job does not install `node_modules` by default, install dependencies in `after_checkout` or copy the subflows into `.maestro/inth/` (re-copy when upgrading `@inth/react-native`):

```sh
mkdir -p .maestro/inth
cp node_modules/@inth/react-native/maestro/* .maestro/inth/
```

Call them as `runFlow: inth/dismiss-if-shown.yaml` from `.maestro/`. Add an `e2e-test` profile in `eas.json` pointing at your staging Inth project:

```json title="eas.json"
{
	"build": {
		"e2e-test": {
			"withoutCredentials": true,
			"env": {
				"INTH_PROJECT_URL": "https://your-test-project.inth.app"
			},
			"ios": { "simulator": true },
			"android": { "buildType": "apk" }
		}
	}
}
```

Read `INTH_PROJECT_URL` in `app.config.ts` inside your [Inth plugin options](/docs/frameworks/react-native/expo#configure-the-plugin):

{/* example: fragment */}

```ts title="app.config.ts"
projectUrl: process.env.INTH_PROJECT_URL ?? 'https://your-project.inth.app',
```

Wire the build and Maestro jobs in `.eas/workflows/e2e-test-ios.yml` (mirror with `platform: android` for Android):

```yaml title=".eas/workflows/e2e-test-ios.yml"
name: e2e-test-ios
on:
  pull_request:
    branches: ['*']
jobs:
  build_ios_for_e2e:
    type: build
    params:
      platform: ios
      profile: e2e-test
  maestro_test:
    needs: [build_ios_for_e2e]
    type: maestro
    params:
      build_id: ${{ needs.build_ios_for_e2e.outputs.build_id }}
      flow_path: ['.maestro/home.yaml', '.maestro/consent-custom.yaml']
```

See Expo's [E2E tests guide](https://docs.expo.dev/eas/workflows/examples/e2e-tests/) for full workflow options.

## Use agent-device and e2e.com

[e2e.com](https://docs.expo.dev/guides/using-e2e/) drives simulators and emulators via Callstack's `agent-device`, accepting the same selectors as `id=` (for example, `agent-device press id=inth.first-layer.reject-all`). On Android, close one tool's UI Automator session before starting the other on the same emulator to avoid driver timeouts.

## Custom headless UIs

Shipped selectors and Maestro flows apply to Inth's stock native screens. If you build custom screens with [headless hooks](/docs/frameworks/react-native/headless), attach your own `testID` props.
