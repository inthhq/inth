`@inth/react-native` bundles the Swift consent engine, Apple platform services, and SwiftUI presenter inside its CocoaPods target. Use this guide when your React Native app owns native iOS initialization. For standalone SwiftUI or UIKit apps, choose Swift in the [framework list](/docs/frameworks).

## Resolve the source products

In React Native, `InthReactNative.podspec` compiles the vendored Swift sources directly into `InthReactNative`. Do not also link the standalone `InthCore`, `InthApple`, or `InthConsentUI` SwiftPM products from `packages/swift` into the same React Native process, or your app will run two competing consent authorities.

The mobile consent UI targets iOS 16.4 or later.

## Install before optional SDKs

Call `InthApple.install` during app startup before initializing optional native SDKs or attaching React Native, replacing the placeholder with your Inth project URL:

<include src="../../shared/examples/native/core-swift/AppleInstallation/apple-install.mdx" />

The installer verifies Keychain access, hydrates saved choices synchronously, and returns the process-wide core (repeated calls return the same engine without changing configuration). Gate optional SDKs with `Inth.isAllowed(.measurement)` or `Inth.decision(for: .measurement)` and keep a subscription active so withdrawals stop collection.

If Keychain is locked at launch, `protectedStorageUnavailable` leaves no engine installed. Retry when protected data becomes available or the app becomes active, and never fall back to memory or plaintext storage. Keychain entries can persist across uninstalls.

## Present native screens

Apply `.inth(privacyPolicyURL:theme:autoPresent:)` to your SwiftUI root, or host `ConsentRootViewController(root:privacyPolicyURL:)` in UIKit. Both share `ConsentPrompt` on the installed core and present an owed choice by default. Pass `autoPresent: false` to control timing via `ConsentPrompt.current?.presentPrompt()`. Whenever native code presents the prompt, pass `autoPresent={false}` to JavaScript's `InthProvider` so only one side presents it. Style screens with `ConsentTheme` (see [Customize](/docs/frameworks/react-native/customize)).

## Attach to a React Native CocoaPods host

For host-owned installation in a CocoaPods React Native app:

1. Set `com.inth.reactnative.AutoBootstrap` to `false` in `Info.plist`.
2. Import only `InthReactNative`.
3. Create `InthAppleConfiguration(backendURL:)` with `configuration.platform = "rn"` so requests attribute to React Native rather than Swift.
4. Call `InthApple.install(configuration)` and then `InthReactNativeBootstrap.install(core)` before starting the React Native bridge.

## Manage ATT and lifecycle

`InthApple.tracking` coordinates App Tracking Transparency separately from Inth consent (requiring `NSUserTrackingUsageDescription` in `Info.plist`). By default, the stock prompt asks for ATT after consent when marketing is granted; see [ask for ATT after the consent prompt](/docs/frameworks/react-native/iab#ask-for-att-after-the-consent-prompt). Platform services own foreground and reachability refresh; `InthApple.shutdown()` tears down those subscriptions without clearing stored consent.

`InthAppleConfiguration` accepts only your Inth dashboard project URL (any other host throws `invalidBackendURL`). Pass `dryRun: true` inside `#if DEBUG` for development and CI (release builds throw `dryRunInReleaseBuild`).
