A universal Expo app imports `@inth/react-native` once for iOS, Android, and web. On iOS and Android, consent runs inside the native core. On web, the same `InthProvider`, hooks, and React Native components run on `@inth/sdk` against the same Inth project.

Expo web supports Expo SDK 55 through 58 with Metro, reading configuration written by the Expo config plugin in `app.config.ts`.

## Install the web engine

Install `@inth/sdk` alongside `@inth/react-native` and Expo's web packages:

```sh
npx expo install @inth/sdk react-dom react-native-web @expo/metro-runtime
```

`@inth/sdk` is an optional peer dependency bundled only for web builds (excluded from iOS and Android binaries). Web support requires Expo's Metro bundler (`.web.js` resolution); webpack setups are unsupported. For standalone web apps outside Expo, use `@inth/sdk` directly.

`npx expo start --web` bypasses the plugin's Expo Go check because browsers need no native build. Still use a custom native build rather than Expo Go on iOS and Android.

## Share plugin configuration on web

The [Expo config plugin](/docs/frameworks/react-native/expo#configure-the-plugin) writes `projectUrl`, `dryRun`, `domain`, `consentCategories`, and `forceGPC` into `extra.inth`, which the web engine reads automatically. Restart Metro with `--clear` after editing plugin options. `npx expo start --web`, `expo export`, and `expo serve` run without generated `ios` or `android` folders.

## Render consent UI on web

Because web has no stock native screens, `InthProvider` behaves like `nativeUI: false` and does not auto-present or require `privacyPolicyUrl`. Mount `ConsentBanner` (or your own `ConsentPrompt` UI) on web only:

{/* example: fragment */}

```tsx title="App.tsx"
import { ConsentBanner, InthProvider } from '@inth/react-native';
import { Platform } from 'react-native';

export default function App() {
	return (
		<InthProvider privacyPolicyUrl="https://example.com/privacy">
			<Root />
			{Platform.OS === 'web' ? <ConsentBanner /> : null}
		</InthProvider>
	);
}
```

Keep the `Platform.OS === 'web'` guard so iOS and Android do not show a duplicate banner. For Privacy settings on web, render `ConsentDialog` with `open` and `onRequestClose` (`presentConsentPrompt()` and `presentPreferences()` reject with `INTH_NATIVE_UI_EXCLUDED`). In development, if an owed prompt stays unrendered for three seconds without `ConsentBanner` or `ConsentPrompt`, the console logs a warning.

## Supported web features

| Feature | Web behavior |
| --- | --- |
| `InthProvider`, `useConsent`, `useConsentDecision`, `useSnapshot`, read hooks | Identical API backed by the browser engine. |
| `ConsentGate`, `ConsentReady`, `ConsentPrompt` | Identical API. |
| `ConsentBanner`, `ConsentDialog`, `ConsentPreferences` | Render via React Native for Web. |
| `useSaveConsents`, `commit` | Save to browser cookies and `localStorage`, then deliver to Inth with offline retry. |
| `reset()` | Withdraws choices while keeping the Inth subject ID. |
| `useSetOverrides()` | Updates country, region, language, or GPC and re-fetches policy. |
| `useIdentify()` | Links an external account ID to the Inth subject. |
| `dryRun` | Fetches live `/v1/consent/init` policy and drops outgoing consent records. |

The browser engine detects browser Global Privacy Control automatically and stores consent per browser, separate from native mobile installs.

## Native-only features

| Feature | Web behavior |
| --- | --- |
| Stock native screens and auto-present | Unavailable; mount `ConsentBanner` or custom UI. |
| `presentConsentPrompt()`, `presentPreferences()` | Reject with `INTH_NATIVE_UI_EXCLUDED`. |
| `onConsentPresenterOutcome()` | Never fires; read state from hooks. |
| App Tracking Transparency | `useTrackingAuthorization()` returns `unsupported`; requests reject with `INTH_TRACKING_UNSUPPORTED`. |
| WebView consent sync | `useWebViewConsent()` returns no payload. |
| IAB TCF and GPP | `snapshot.iab` and `useGPPString()` return `null`; TCF commits fail with `iab-unavailable`. The web client falls back to opt-in category consent without writing a TC String. |
| `logout()` | No-op until page reload; call `reset()` on shared devices. |
| `policyResource`, `bundleManifest`, in-code `policy` | Native-only; web always loads policy from `/v1/consent/init`. |
| `bootstrap.hasStoredSnapshot` | Always `false` before browser hydration; wait for `useConsentStatus().ready`. |

## Check `dryRun` before releasing

Production web builds (`npx expo export --platform web`) refuse `dryRun`, leaving every optional category denied and setting `error.code === 'INTH_CONFIGURATION_DRY_RUN'`. Leave `dryRun` unset in release builds.

## Statically rendered pages

On server pre-renders and the initial browser render, the web client starts unready with optional categories set to `pending` so server HTML matches client hydration, then reads stored consent and calls `/v1/consent/init` after hydration. Check for hydration warnings before relying on Expo Router static export.

## Check it works

1. Run `npx expo start --web` and open the app.
2. Confirm the banner renders once `/v1/consent/init` resolves.
3. Click **Accept all** and confirm `useConsentDecision('measurement')` switches to `granted`.
4. Reload and confirm the banner stays closed while `measurement` remains `granted`.
