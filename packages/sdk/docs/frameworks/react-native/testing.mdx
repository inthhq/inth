Jest and Vitest run without the native Inth module, so mounting `InthProvider` directly throws `NativeInthUnavailableError`. Use `@inth/react-native/testing` to run the real consent client over an in-memory fake core: pick the initial consent state, render your screens, assert what they saved, and answer the native prompt.

## Set up Jest with jest-expo

Install `jest-expo` and React Native Testing Library as dev dependencies:

```bash
npx expo install --dev jest-expo jest @types/jest @testing-library/react-native test-renderer
```

Because `@inth/react-native` ships ES modules, add `@inth` to `transformIgnorePatterns` in `package.json`:

```json title="package.json"
{
	"scripts": {
		"test": "jest"
	},
	"jest": {
		"preset": "jest-expo",
		"transformIgnorePatterns": [
			"/node_modules/(?!(.pnpm|react-native|@react-native|@react-native-community|expo|@expo|@expo-google-fonts|react-navigation|@react-navigation|@sentry/react-native|native-base|@inth))"
		]
	}
}
```

Without `@inth` in the allowlist, Jest stops with `Must use import to load ES Module`. Keep any extra entries your preset needs (such as `/node_modules/react-native-reanimated/plugin/`; check `node_modules/jest-expo/jest-preset.js`). Plain logic tests can import `@inth/react-native` without creating a test client because native lookup waits until a provider or client starts.

## Choose the starting consent

Call `createTestConsentClient(options)` once per test (each call replaces the previous test client):

| Option | Default | Behavior |
| --- | --- | --- |
| `consent` | `'unset'` | `'unset'` owes a prompt with optional categories denied; `'granted'` or `'denied'` stores that choice for all optional categories; an object like `{ measurement: true }` stores those choices with omitted categories denied. |
| `ready` | `true` | `false` holds startup in `pending` (`useConsent` returns `false`) until you call `consent.setReady()`. |
| `nativeUI` | `true` | `false` simulates a build without stock native screens (render `InthProvider` with `autoPresent={false}`). |
| `trackingAuthorization` | `'unsupported'` | Simulated Apple ATT status (`'unsupported'` matches Android). |
| `snapshot` | none | Raw snapshot field overrides such as `{ model: 'opt-out' }`. |

## Check what the app saved

`consent.commits` records every JavaScript save sent to the core in order:

| App call | Recorded entry |
| --- | --- |
| `useSaveConsents()('all')` | `{ action: 'all' }` |
| `useSaveConsents()('none')` | `{ action: 'necessary' }` |
| `useSaveConsents()({ measurement: true })` | `{ action: 'explicit', consents: { measurement: true } }` |

Accept all and reject all satisfy the owed prompt; per-category saves update only the named categories while leaving the prompt owed until every in-scope category has an answer.

## Change consent from the native side

Call `consent.setConsent(state)` with the same shapes accepted by `consent`, or toggle readiness with `consent.setReady(true | false)`. Affected hooks rerender immediately, wrapped in React's `act` automatically when the act environment is enabled.

## Answer the native prompt

The fake presenter mirrors native lifecycle rules without rendering UI:

- A default `InthProvider` (with `privacyPolicyUrl`) opens an owed prompt on mount (`consent.prompt.current` has `automatic: true`).
- `presentConsentPrompt()` opens when owed (`not-required` otherwise), `presentPreferences()` always opens, and both return `already-presented` while open.
- `consent.prompt.acceptAll()`, `rejectAll()`, and `save({ marketing: true })` persist choices and close with `committed`. `acknowledge()` closes a notice with `acknowledged` without granting optional consent. `dismiss()` closes without saving (keeping the choice owed without re-auto-presenting until the requirement changes).
- Saves do not commit while policy is pending or when standing preferences are stale. Choice actions throw on notices, `acknowledge()` throws on non-notices, and calling prompt methods while `consent.prompt.isOpen` is `false` throws.
- `client.reset()` returns to cold start until you call `consent.setReady()`.

Native prompt answers do not appear in `consent.commits`; read them from rendered UI or `consent.client.getSnapshot()`.

## Test components with their own provider

The active test client also backs the default shared client, so you can render an unmodified root `<App />`:

{/* example: fragment */}

```tsx
const consent = createTestConsentClient({ consent: 'unset' });

await render(<App />);
expect(consent.prompt.isOpen).toBe(true);
```

## Use Vitest

`createTestConsentClient` works with Vitest once `react-native` is configured for your runner and `@inth/react-native` is added to `server.deps.inline` (so Node resolves extensionless platform imports). Under a web preset, pass `nativeUI: false` and test your JS banner because `consent.prompt` simulates native screens only.

## Limits of the fake core

- Category consent only (IAB vendor and purpose choices are ignored).
- `identify`, `logout`, `refresh`, and `setOverrides` resolve as no-ops.
- Tracking requests return `trackingAuthorization` without prompting.

Verify real native screens, policy resolution, and Keychain/SharedPreferences persistence on a device using [Verify mobile consent](/docs/frameworks/react-native/verify).
