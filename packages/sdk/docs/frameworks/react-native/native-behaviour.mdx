Native analytics and advertising SDKs often initialize before React mounts. Gate their startup natively so zero pre-consent traffic fires, and use React hooks only for work owned by JavaScript.

## Install before JavaScript starts

Both the Expo plugin and bare React Native metadata install Inth through native launch hooks. Before `InthProvider` mounts, the native engine hydrates saved choices and begins policy resolution. `InthProvider` attaches to that engine and checks protocol compatibility rather than creating a second instance.

| Setup | Where native startup lives |
| --- | --- |
| Expo | Config plugin in `app.config.ts`, applied by prebuild and native build |
| Bare RN (iOS) | App target `Info.plist` or app-owned native installation |
| Bare RN (Android) | `AndroidManifest.xml` metadata and AndroidX Startup, or app-owned installation |

Finish [Expo](/docs/frameworks/react-native/expo) or [bare setup](/docs/frameworks/react-native/bare) first. Disable every optional vendor's automatic collection, manifest initializers, app-delegate hooks, and config plugins. Inth does not intercept arbitrary native network calls.

## Read the cached native gate

| Platform | Boolean permission | Decision state |
| --- | --- | --- |
| Swift | `Inth.isAllowed(.measurement)` | `Inth.decision(for: .measurement)` |
| Kotlin | `Inth.isAllowed(ConsentCategory.MEASUREMENT)` | `Inth.decision(ConsentCategory.MEASUREMENT)` |

Both reads inspect in-memory native state with no disk or network I/O. `decision` distinguishes pending, denied, and granted; keep optional collection off for both pending and denied while allowing necessary app features to run. Because effective permission can reflect a regional policy default before any explicit save, read recorded choices separately when displaying user selections.

## Subscribe for the integration's lifetime

Retain a Swift gate subscription or Kotlin `gate`/`gateDecision` handle inside the app-wide owner of each optional SDK. Register after installation to apply the initial decision and respond to every later grant, withdrawal, policy update, identity change, or foreground refresh through the vendor's enable, disable, or shutdown API.

Close the handle only when that SDK owner ends (never tie an app-wide analytics gate to a short-lived screen or rotating Activity). Native callbacks may run on worker threads, so marshal UI work onto the main thread, or observe `snapshotFlow`/`decisionFlow` in Kotlin and `PublishedConsent` in Swift.

## Handle unavailable storage

On iOS, `InthApple.install` checks Keychain access before installing. If it reports `protectedStorageUnavailable`, leave optional SDKs disabled and retry once protected data unlocks or the app becomes active. Never substitute memory or plaintext storage.

On Android, treat storage read or write errors as closed consent gates, keep failed saves visible, and retry once storage recovers.

## Keep collection and delivery separate

Every native commit writes locally before attempting network delivery, replaying queued saves on launch, foreground, and reconnect. A network failure after withdrawal must never re-enable collection. See [Commands and outcomes](/docs/frameworks/react-native/usage) and [Mobile offline consent](/docs/guides/mobile-offline).

For ad SDKs, combine category checks with native IAB vendor, purpose, Additional Consent, and ATT gates; see [Mobile IAB and ads](/docs/guides/mobile-iab).
