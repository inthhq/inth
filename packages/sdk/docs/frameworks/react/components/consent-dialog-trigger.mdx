Add a draggable floating button or multi-action toolbar inside `InthProvider` so visitors can reopen preferences from any page.

## Add the trigger inside InthProvider

Place `ConsentDialogTrigger` once inside `InthProvider`, next to the banner and dialog from the [quickstart](/docs/frameworks/react/quickstart):

{/* example: fragment */}

```tsx title="src/consent.tsx"
import { ConsentDialogTrigger } from '@inth/react';

// Inside the InthProvider from your quickstart, next to the dialog:
<ConsentDialogTrigger showWhen="after-prompt" />;
```

`showWhen="after-prompt"` hides the button while a choice or notice is owed and reveals it after the visitor responds, keeping the banner and trigger from overlapping in the same corner. The default, `always`, shows the button whenever the preference center is closed.

The button sets `data-inth-rights` with the active policy's rights so CSS can adjust its styling or wording for opt-out rules.

## Configurable toolbar

Use `ConsentDialogTriggerToolbar` to place app-owned controls beside the privacy trigger. It always renders one built-in preferences action, so pass only app-owned controls in `actions`:

```tsx
import { ConsentDialogTriggerToolbar } from '@inth/react';

<ConsentDialogTriggerToolbar
	ariaLabel="Site controls"
	actions={[
		{
			id: 'theme',
			label: isDark ? 'Switch to light theme' : 'Switch to dark theme',
			icon: isDark ? <SunIcon /> : <MoonIcon />,
			pressed: isDark,
			onSelect: toggleColorScheme,
		},
		{
			id: 'support',
			label: 'Open support chat',
			icon: <ChatIcon />,
			onSelect: openSupportChat,
		},
	]}
	preferences={{ icon: 'fingerprint', label: 'Manage privacy settings' }}
/>;
```

Each custom action needs a stable `id`, accessible `label`, `icon`, and `onSelect` callback. Use `pressed` for toggles and `disabled` for unavailable controls. The preferences action anchors nearest the snapped corner while custom actions keep their array order.

Toolbars lay out horizontally by default. Pass `orientation="vertical"` to stack actions vertically and switch arrow-key navigation to up and down:

```tsx
<ConsentDialogTriggerToolbar orientation="vertical" actions={toolbarActions} />;
```

### When the controls show

App-owned toolbar actions stay visible regardless of consent policy. The built-in preferences action and standalone `ConsentDialogTrigger` follow the active rule:

| Situation | Built-in action and `ConsentDialogTrigger` |
| --- | --- |
| A choice or notice is still owed with `showWhen="after-prompt"` | Hidden until the visitor answers |
| `showWhen="never"` on the toolbar | Omitted from the toolbar |
| No policy rule has resolved | Hidden; appears automatically once a rule resolves |
| Rule uses `model: 'none'` | Hidden unless the rule includes `rights: ['preferences']` |
| Any other case | Shown |

On `ConsentDialogTriggerToolbar`, `showWhen` controls only the built-in preferences action; on `ConsentDialogTrigger`, it controls the entire button. The toolbar renders nothing only when it has zero visible items.

### What the built-in action says

- Under a rule with the `opt-out` right, such as a US opt-out notice, its accessible name is the translated "Do Not Sell or Share My Personal Information" with `data-right="opt-out"`.
- Under any other rule, it reads "Manage preferences" with `data-right="preferences"`.
- In both cases it opens the preference center, carries `data-inth-rights`, and honors any `preferences.label` override.

### Toolbar styling

Styles resolve in standard order: built-in styles, provider slots, then `className` and `style` on the toolbar or an individual action. Pass `noStyle` for fully custom styling.

{/* example: fragment */}

```tsx
<InthProvider
	options={{
		mode,
		components: {
			trigger: {
				toolbar: { className: 'my-toolbar' },
				toolbarItem: { className: 'my-toolbar-item' },
				toolbarIcon: { className: 'my-toolbar-icon' },
			},
		},
	}}
>
	<ConsentDialogTriggerToolbar
		className="fixed-toolbar"
		actions={[
			{
				id: 'support',
				label: 'Open support chat',
				icon: <ChatIcon />,
				onSelect: openSupportChat,
				className: 'support-action',
			},
		]}
	/>
</InthProvider>;
```

Slot keys are `trigger.toolbar`, `trigger.toolbarItem`, and `trigger.toolbarIcon`. With `noStyle`, target `data-corner`, `data-dragging`, and `data-snapping` on the toolbar element.
