Render `ConsentBanner` once inside `InthProvider`, next to `ConsentDialog`, so every visitor sees the right prompt for their region.

## Render the banner inside `InthProvider`

The [quickstart](/docs/frameworks/react/quickstart) mounts both in `src/consent.tsx`:

<include src="../../../shared/examples/react/consent.mdx" />

The banner adapts automatically to the active policy rule:

- A `choice` prompt renders the rule's actions: Reject and Accept at equal prominence, plus Customize when offered.
- A `notice` prompt renders an "OK" button and an underlined text button labelled "Do Not Sell or Share My Personal Information" that opens preferences. Notices never trap focus or lock scroll.
- A rule with `prompt: 'none'` renders nothing.

An opt-out rule with `prompt: 'none'` still grants rights, so the preference center and dialog trigger stay available. A rule with `model: 'none'` owes no rights and renders nothing unless you add `rights: ['preferences']`. When no rule has resolved yet, no consent surface renders; all surfaces appear automatically without remounting once a rule resolves. `testing()` without a custom `policy` resolves the recommended pack and displays the opt-in banner until you pass a country.

Acknowledging a notice records dismissal only, without recording consent or changing permissions, denials, or privacy-signal restrictions. Customize the label via `common.acknowledge` in translations, or pass `dismissButtonText` for a single banner.

The extra preferences button uses the opt-out label when applicable. A choice prompt without Customize renders "Manage preferences". Both are button elements styled as underlined text that open the preference center rather than submitting an opt-out directly.

`preferenceControls` suggests these controls for the built-in UI, but does not verify legal disclosure or persistent preferences access. Configure legal links and keep a preferences link reachable after the banner closes.

## Per-policy buttons

By default, Customize is primary on a choice banner and OK is primary on a notice. To customize button order and prominence per policy rule, read the active rule inside `InthProvider`:

```tsx
import { ConsentBanner, usePolicyRule } from '@inth/react';
import type { ConsentBannerProps } from '@inth/react';

const banners: Record<
	string,
	Pick<ConsentBannerProps, 'layout' | 'primaryButton' | 'variant'>
> = {
	europe_opt_in: {
		layout: [['reject', 'accept'], 'customize'],
		primaryButton: 'customize',
	},
	us_privacy_states: {
		layout: ['dismiss'],
		primaryButton: 'dismiss',
		variant: 'bar',
	},
};

export function RegionalBanner() {
	const policy = usePolicyRule();
	return <ConsentBanner {...(policy ? banners[policy.id] : undefined)} />;
}
```

Render `RegionalBanner` inside `InthProvider`. `layout` controls action grouping; the opt-out preferences link still renders on a notice, and any required action omitted from `layout` is restored automatically. Accept and Reject keep equal default prominence.

Apply one brand color and fill whichever action is primary via the provider theme:

```ts
const theme = {
	colors: { primary: '#2f6f4e', primaryHover: '#24563c' },
	consentActions: { primary: { variant: 'primary', mode: 'filled' } },
} as const;
```

Pass `theme` in `InthProvider` options. Per-action entries such as `consentActions.dismiss` override `primary`. See [Customize](/docs/frameworks/react/customize) for tokens and slots, and [Policies](/docs/concepts/policies) for rule IDs.

## Variants

The policy controls which actions appear; `variant` controls the banner shape. Set `variant` on `ConsentBanner`, or on the provider under `presentation.prompt` for a global default. The component prop takes precedence.

```tsx
<ConsentBanner variant="floating" position="bottom-center" />;
```

`floating` renders a card in a corner or centered on an edge. This is the default for all prompts, including notices.

```tsx
<ConsentBanner variant="bar" position="top" />;
```

`bar` spans the viewport width. At 1024px and wider, copy, rights links, and controls share a single row.

```tsx
<ConsentBanner variant="widget" position="bottom-right" />;
```

`widget` renders a compact card with smaller typography while keeping the full description and legal links visible.

```tsx
<ConsentBanner variant="wall" />;
```

`wall` renders a centered card over a backdrop and blocks page interaction until the visitor responds.

Each variant supports specific positions:

| Variant | Positions | Default |
| --- | --- | --- |
| `floating` | `bottom-left`, `bottom-right`, `top-left`, `top-right`, `bottom-center`, `top-center` | `bottom-left` |
| `bar` | `top`, `bottom` | `bottom` |
| `widget` | `bottom-left`, `bottom-right`, `top-left`, `top-right` | `bottom-right` |
| `wall` | `center` | `center` |

Right-to-left languages keep the same position and flip only text direction. Passing a position unsupported by the variant falls back to its default and logs an `invalid-position` diagnostic in development.

`blocking` controls backdrop, scroll lock, and focus trap together, overriding the deprecated `scrollLock` and `trapFocus` props. A choice `wall` always blocks, whereas notices never block and requesting a notice `wall` falls back to `floating` with an `invalid-variant` diagnostic. Blocking banners carry `role="dialog"` and `aria-modal="true"`; non-blocking banners leave page controls interactive.

`@inth/react` exports `PromptVariant` and `PromptPosition`. Compound parts can read resolved layout values with `useConsentBannerSurface()`, returning `variant`, `position`, `positionSource` (`host` or `default`), and `blocking`.

## Composition

Every banner part is available as `ConsentBanner.<Part>` for custom layouts that stay policy-driven:

```tsx
import { ConsentBanner } from '@inth/react';

export function CompactBanner() {
	return (
		<ConsentBanner.Root>
			<ConsentBanner.Card>
				<ConsentBanner.Header>
					<ConsentBanner.Title />
					<ConsentBanner.Description />
				</ConsentBanner.Header>
				<ConsentBanner.PolicyActions />
			</ConsentBanner.Card>
		</ConsentBanner.Root>
	);
}
```

`ConsentBanner.PolicyActions` renders the resolved action groups preceded by any recommended preferences links. Pass children to replace the links while keeping the policy action groups.

Use individual parts when you need custom ordering or markup:

- `ConsentBanner.AcceptButton`, `ConsentBanner.RejectButton`, `ConsentBanner.CustomizeButton`, and `ConsentBanner.DismissButton` render one action each (`DismissButton` defaults to `common.acknowledge`).
- `ConsentBanner.Rights` renders recommended preferences links, or nothing when empty. Pass `rights` to override.
- `ConsentBanner.RightLink` renders one right (`'opt-out'` or `'preferences'`) as an underlined text button with `data-action="right"` and `data-right`. Under an `opt-out` policy, activating `right="opt-out"` records the opt-out in one click and opens `OptOutConfirmation`; under other models it opens the preference center. Set `presentation.optOutLink` to `'do-not-sell'`, `'privacy-choices'`, or `'california-privacy-choices'`; the two "Privacy Choices" forms always render with the California Privacy Protection Agency opt-out icon. Pass `asChild` to render your own element, such as an anchor to a dedicated opt-out page.

<include src="../../../shared/privacy-choices-link.mdx" />

```tsx
<ConsentBanner.Rights>
	<ConsentBanner.RightLink right="opt-out" asChild>
		<a href="/privacy/do-not-sell">
			Do Not Sell or Share My Personal Information
		</a>
	</ConsentBanner.RightLink>
</ConsentBanner.Rights>;
```

`useBannerCopy()` returns the resolved title, description, and prompt kind for custom headers.

## Data attributes

The root element exposes attributes for CSS or Tailwind targeting, and the card sets `data-state` (`open` or `closed`) for animations:

| Attribute | Values |
| --- | --- |
| `data-prompt` | `choice`, `notice` |
| `data-model` | `opt-in`, `opt-out`, `iab` |
| `data-variant` | `floating`, `bar`, `widget`, `wall` |
| `data-position` | Resolved position for the variant |
| `data-blocking` | `true`, present only while blocking |

Each action button sets `data-action`, and each right link sets `data-action="right"` and `data-right`. Built-in CSS keys variant geometry on `data-variant` and `data-position`, and uses `data-prompt="notice"` to lay out the footer on one row with rights links leading and "OK" trailing.
