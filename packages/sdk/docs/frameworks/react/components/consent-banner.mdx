Render `ConsentBanner` once inside `InthProvider`, next to `ConsentDialog`, so every visitor sees the right prompt for their region.

## Render the banner inside `InthProvider`

The [quickstart](/docs/frameworks/react/quickstart) mounts both in `src/consent.tsx`:

<include src="../../../shared/examples/react/consent.mdx" />

The banner adapts to the active policy rule:

- A `choice` prompt renders the rule's actions: Reject and Accept at equal prominence, plus Customize when offered. Customize opens the category choices inside the banner, with a Save button.
- A `notice` prompt renders an "OK" button and the policy's opt-out link. Notices never trap focus or lock scroll.
- A rule with `prompt: 'none'` renders nothing.

An opt-out rule with `prompt: 'none'` still grants rights, so the dialog and its trigger stay available. A rule with `model: 'none'` owes no rights and renders nothing unless you add `rights: ['preferences']`. When no rule has resolved yet, no consent surface renders; all surfaces appear without remounting once a rule resolves. `testing()` without a custom `policy` resolves the recommended pack and displays the opt-in banner until you pass a country.

Acknowledging a notice records dismissal only, without recording consent or changing permissions, denials, or privacy-signal restrictions. Customize the label via `common.acknowledge` in translations, or pass `dismissButtonText` for a single banner.

Under an `opt-out` policy, the banner's opt-out link follows the resolved `presentation.optOutLink` title. With `'do-not-sell'` (the default), activating it records the opt-out in one click and opens `OptOutConfirmation` (reloading first when that turns off a running category and `reloadOnConsentRevoked` is enabled). With `'privacy-choices'` or `'california-privacy-choices'`, the link renders with the California Privacy Protection Agency opt-out icon and opens `ConsentDialog` without recording an opt-out. Programmatic calls to `useOptOut()` still opt out in one step whatever `presentation.optOutLink` is set to. Keep a [`PrivacyChoicesLink`](./privacy-choices-link) reachable after the banner closes.

## Per-policy layouts

To change the container or the button order per policy rule, read the active rule inside `InthProvider`:

{/* example: fragment */}

```tsx
import { ConsentBanner, usePolicyRule } from '@inth/react';
import type { ConsentBannerProps } from '@inth/react';

const banners: Record<
	string,
	Pick<ConsentBannerProps, 'container' | 'layout'>
> = {
	europe_opt_in: {
		container: { position: 'center', type: 'card' },
		layout: [['reject', 'accept'], 'customize'],
	},
	us_privacy_states: {
		container: { edge: 'bottom', type: 'banner' },
		layout: ['dismiss'],
	},
};

export function RegionalBanner() {
	const policy = usePolicyRule();
	return <ConsentBanner {...(policy ? banners[policy.id] : undefined)} />;
}
```

`layout` controls action grouping. Any required action omitted from `layout` is restored automatically, and Accept and Reject keep equal prominence. Apply one brand color and fill the primary action via the provider theme:

```ts
const theme = {
	colors: { primary: '#2f6f4e', primaryHover: '#24563c' },
	consentActions: { primary: { variant: 'primary', mode: 'filled' } },
} as const;
```

Pass `theme` in `InthProvider` options. Per-action entries such as `consentActions.dismiss` override `primary`. See [Customize](/docs/frameworks/react/customize) for tokens and slots, and [Policies](/docs/concepts/policies) for rule IDs.

`useBannerCopy()` returns the resolved title, description, and prompt kind for custom headers. For your own markup, see [Headless](/docs/frameworks/react/headless).
