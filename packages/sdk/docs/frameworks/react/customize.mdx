Change the colors, typography, layout, button styles, and wording of the Inth banner and dialog in a React app.

## Pick the right tool

| Change | Use |
| --- | --- |
| Brand colors, fonts, radius, spacing | [Theme tokens](#change-colors-fonts-and-radius) |
| Light and dark colors, animation | [Dark mode and motion](#turn-on-dark-mode-and-change-motion) |
| Which button is filled or outlined | [`consentActions`](#style-the-action-buttons) |
| Banner shape and position | [`ConsentBanner` props or `presentation`](#change-the-banner-shape) |

[Customization](/docs/customization/overview) compares these options across frameworks, and the [design gallery](/docs/customization/recipes) shows five tested banner designs for React.

## Import the stylesheet yourself

A React app imports no stylesheet by default: `ConsentBanner`, `ConsentDialog`, and the other built-in components render their own `<style>` elements.

Import the stylesheet yourself on Tailwind CSS 3 to place Inth's rules in a named cascade layer. Set `styles: false` in the provider options so components stop injecting duplicate `<style>` elements, and import `@inth/react/styles.css` once in the module that renders `InthProvider`:

{/* example: fragment */}

```tsx title="src/consent.tsx (partial)"
import '@inth/react/styles.css';

// In the InthProvider options:
styles: false,
```

If you import it from CSS instead, place it at the top of your global stylesheet above any `@tailwind` directives because Vite's `postcss-import` ignores `@import` statements after other rules. Tailwind CSS 3 also requires the PostCSS plugin; see [Tailwind CSS](/docs/customization/tailwind#set-up-tailwind-css-3).

## Change colors, fonts and radius

<import src="../../shared/react/styling/overview.mdx#tokens-intro" />

In a single-page app without server rendering, choose one of two approaches:

- **Set the variables in CSS.** Adds zero JavaScript to your bundle:

  ```css title="src/index.css"
  :root {
    --inth-primary: #2f6f4e;
    --inth-primary-hover: #24563c;
    --inth-text-on-primary: #fff;
    --inth-radius-lg: 4px;
  }
  ```

- **Render `ConsentTheme` next to the provider.** Use this when the theme lives in TypeScript or changes at runtime; the browser downloads the theme generator.

  {/* example: fragment */}

  ```tsx title="src/consent-theme.ts"
  import { defineTheme } from '@inth/react';

  export const theme = defineTheme({
    colors: { primary: '#2f6f4e', primaryHover: '#24563c' },
    radius: { lg: '4px' },
  });
  ```

  In `src/consent.tsx`, render `<ConsentTheme theme={theme} />` from `@inth/react` just before `<InthProvider>`.

In a server-rendered app such as React Router framework mode, render `ConsentTheme` in the root component so the `<style>` element ships in server HTML. [Theme tokens](/docs/customization/tokens) lists every variable.

`ConsentTheme` outranks a plain `:root` rule regardless of load order. If you combine both, use `:root:root` in CSS to override `ConsentTheme`, or keep all token values in one place.

## Style the action buttons

`consentActions` sets how each button role looks: `default` styles every button, `primary` styles primary actions, and `accept`, `reject`, `customize`, and `dismiss` style one role each. Pass it in the provider `theme` option:

{/* example: fragment */}

```tsx title="src/consent.tsx"
<InthProvider
  options={{
    mode,
    scripts,
    theme: {
      consentActions: {
        primary: { variant: 'primary', mode: 'filled' },
        dismiss: { variant: 'neutral', mode: 'stroke' },
      },
    },
  }}
>
```

The provider `theme` option reads only `consentActions` and slot styles. Token fields passed there are ignored with a development warning. Changing button styles never alters the policy or expires a saved choice.

## Change the banner shape

`ConsentBanner` accepts `variant` (`floating`, `bar`, `widget`, or `wall`) and `position`. To apply one shape globally, set `presentation.prompt` in the provider options. This example uses a full-width bar for notices and a floating card for choices:

{/* example: fragment */}

```tsx title="src/regional-banner.tsx"
import { ConsentBanner, usePolicyRule } from '@inth/react';

export function RegionalBanner() {
	const policy = usePolicyRule();
	return (
		<ConsentBanner variant={policy?.prompt === 'notice' ? 'bar' : 'floating'} />
	);
}
```

Render `RegionalBanner` instead of `ConsentBanner` inside the provider. [ConsentBanner](/docs/frameworks/react/components/consent-banner#variants) lists every variant, position, and per-policy button layout.

## Style one component part

Each component part is a slot configured under `options.components`, keyed by component and part. A slot accepts any attribute the element supports, including `className` and `style`.

<import src="../../shared/react/styling/overview.mdx#slot-recipes" />

[Component parts](/docs/customization/slots) lists every slot key and explains `noStyle`. `ConsentGate`'s placeholder parts are `components['consent-gate'].root`, `.title`, and `.button`. See [Class names and CSS-in-JS](/docs/customization/class-names) and [Tailwind CSS](/docs/customization/tailwind) for styling examples.

## Turn on dark mode and change motion

Pass the same `colorScheme` to `InthProvider` and `ConsentTheme`. Omit it to follow a `dark` class on `<html>`, and customize dark colors with `theme.dark`. See [Dark mode](/docs/customization/dark-mode).

Set `disableAnimation` in provider options to disable animations across the banner and dialog, or pass `disableAnimation` to a single component. See [Motion and animation](/docs/customization/motion) for timing tokens and reduced motion.

## Change the copy

Labels, descriptions, and languages come from your Inth project translations and the provider `i18n` option. For the active language, `i18n.messages` replaces project copy key by key while leaving omitted keys untouched. See [Copy and translations](/docs/customization/translations) for message keys, or pass text props such as `dismissButtonText` directly to `ConsentBanner`.

## Check the result

Clear site data and reload under a policy that shows a banner. Inspect both the banner and the preferences dialog, check narrow viewports, test keyboard focus, and verify button contrast. In development, check the console to make sure no `inth-theme` warning appears.
