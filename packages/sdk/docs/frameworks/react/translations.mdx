Customize Inth banner and dialog copy in a React app, override strings per language, and switch languages at runtime.

## Where the copy comes from

The banner, dialog, widget, and gate placeholder read from one translation set for the visitor's language, depending on the provider `mode`:

| Mode | Copy comes from |
| --- | --- |
| `hosted()` | Your Inth project's `/v1/consent/init` response for the visitor's language, with your `i18n` messages merged on top |
| `testing()` | Your `i18n` messages merged over bundled English |

Edit wording in your Inth project first so copy changes ship without a deploy. Override copy in code in two places:

- `i18n` in `InthProvider` options replaces a message everywhere it appears.
- Text props on `ConsentBanner` replace copy on one banner.

See [Copy and translations](/docs/customization/translations) for message keys and merge rules.

## How Inth picks the language

In `hosted()` mode, the browser sends its `Accept-Language` header to `/v1/consent/init` and Inth returns copy in that language, falling back to your project's default language when untranslated. Set `overrides.language` in provider options to request a specific language instead.

In `testing()` mode, `i18n.locale` sets the language (`en` by default) and the browser language is ignored.

The banner, dialog, and widget set `dir` from the active language. Right-to-left languages such as Arabic and Hebrew render with `dir="rtl"` while keeping the banner in the same corner.

## Change the copy in code

Define messages in a separate module:

<include src="../../shared/examples/react/i18n.mdx" />

Pass `i18n` to `InthProvider` in `src/consent.tsx` from the [quickstart](/docs/frameworks/react/quickstart):

{/* example: fragment */}

```tsx title="src/consent.tsx"
<InthProvider options={{ mode, scripts, i18n }}>
```

For the active language, your messages replace project copy key by key while omitted keys keep your project wording. Messages for other languages are ignored. In `testing()` mode, Inth bundles only English, so omitted keys in other languages fall back to English.

The provider reads `i18n` once on mount and logs a development warning if it changes later. Define the object at module level rather than inside a component.

## Change one banner's copy

`ConsentBanner` accepts `title`, `description`, `acceptButtonText`, `rejectButtonText`, `customizeButtonText`, and `dismissButtonText`. These props override text in every language, so pass strings already translated for the current page:

{/* example: fragment */}

```tsx
<ConsentBanner
	title="Cookies on this site"
	rejectButtonText="Reject optional"
/>;
```

## Switch the language at runtime

`useSetLanguage()` updates the active language and `useInit()` resolves the policy again to fetch translations for that language. Call both in your language switcher:

<include src="../../shared/examples/react/language-switcher.mdx" />

Calling `setLanguage()` without `init()` leaves on-screen copy unchanged. Your `i18n` overrides for the new language apply on top of the fetched copy. Render the switcher inside `InthProvider`.

Runtime switching requires an Inth project connection. In `testing()` mode, copy stays in `i18n.locale`.

If your app already manages locale through an i18n library, pass its locale as `overrides.language` in `InthProvider` options instead; changing that value re-resolves the policy in the new language.

## Verify

1. Set your browser language to a language translated in your Inth project, clear site data, and reload under a policy showing a banner. Confirm DevTools Network shows `/v1/consent/init` with that `Accept-Language` header and the banner renders in that language.
2. Confirm any string overridden in `i18n` appears in the banner.
3. Switch languages with your switcher and confirm a new `/v1/consent/init` request updates the banner and dialog without reloading.
