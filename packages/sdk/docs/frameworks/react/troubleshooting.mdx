Diagnose and resolve common setup issues in React apps using `@inth/react`.

## There is no banner

**Check.** Open DevTools Network and look for `/v1/consent/init` on your Inth project URL. With `hosted()`, the browser sends it during the provider's first render. With bundled `manifest()`, the browser makes no `/v1/consent/init` request unless the policy needs a country or region it does not know.

| What you see | Cause | Fix |
| --- | --- | --- |
| No request and no banner | `InthProvider` is not mounted, an error stopped `src/consent.tsx` from rendering, or the bundled policy requires no banner | Check the console for errors, mount one provider at the app root as in the [quickstart](/docs/frameworks/react/quickstart), and inspect the active policy below |
| `/v1/consent/init` fails with a CORS error | Your site's origin is not trusted | Add the exact origin, including port in development, to trusted origins in your Inth project |
| `/v1/consent/init` returns 200 | The visitor's policy requires no banner, or a valid stored choice already exists | Inspect the active policy below, or clear site data |

A policy with `prompt: 'none'` shows no banner by design, as does a returning visitor with a valid stored choice. See [Policies](/docs/concepts/policies).

## Inspect the active policy

Render this temporary component inside `InthProvider` to inspect resolved state without recording a choice:

{/* example: fragment */}

```tsx title="src/consent-policy-debug.tsx"
import { useSnapshot } from '@inth/react';

export function ConsentPolicyDebug() {
	const snapshot = useSnapshot();
	const resolution = snapshot.resolution;

	return (
		<pre>
			{JSON.stringify(
				{
					status: resolution.status,
					policy: resolution.status === 'matched' ? resolution.policy.id : null,
					prompt: snapshot.promptRequirement,
					permissions: snapshot.effectivePermissions,
					location: snapshot.location,
					privacySignals: snapshot.privacySignals,
				},
				null,
				2
			)}
		</pre>
	);
}
```

This component re-renders on every consent change, so remove it after debugging. Use `useConsent('marketing')` or the specific category hook for feature gates.

## A vendor loads before the visitor chooses

**Check.** Search `index.html`, your entry modules, and any tag manager for the vendor's script tag or SDK initializer.

**Fix.** Remove every loader except the one in `options.scripts`. Inth only gates scripts registered with it, and the network blocker cannot stop code running before `InthProvider` renders. See [Scripts](/docs/frameworks/react/scripts).

## The banner has no styles

**Check.** In DevTools Elements, the banner has classes but no CSS rules apply. Look for Inth's `<style>` element: `<style data-href="inth-tokens inth-button inth-banner">` in `<head>` on React 19, or `<style data-inth-styles>` next to the banner on React 18 or when `nonce` is set. Check the console for Content Security Policy errors.

**Fix.**

- No Inth `<style>` element: `options.styles` is `false` or `noStyle` is set. With `styles: false`, import `@inth/react/styles.css` once in the module that renders `InthProvider`.
- Blocked inline style in the console: pass `options.nonce` to `InthProvider`. See [Content Security Policy](/docs/frameworks/react/content-security-policy).
- Missing button padding or borders on Tailwind CSS 3: Tailwind 3's unlayered preflight overrides Inth's layered rules. Set `styles: false`, import `@inth/react/styles.css` above `@tailwind`, and add `@inth/react/postcss-tailwind3` before `tailwindcss` in your PostCSS config. Without that plugin, Tailwind 3 drops Inth's rules or fails the build with `` `@layer components` is used but no matching `@tailwind components` directive is present ``. See [Tailwind CSS](/docs/customization/tailwind#set-up-tailwind-css-3).

## The console warns that theme tokens are no longer turned into CSS

**Check.** `options.theme` contains color, radius, or other tokens while the page has no `inth-theme` style element. `InthProvider` reads only `consentActions` and slot styles from `theme`.

**Fix.** Move tokens into your CSS or render `ConsentTheme`. See [Customize](/docs/frameworks/react/customize#change-colors-fonts-and-radius).

## The banner is missing from server-rendered HTML

**Check.** Your app uses React Router framework mode, Remix, or another SSR setup without a dedicated Inth server adapter. Inth resolves consent in the browser after hydration in those setups.

**Fix.** No change is required for consent gating to work. See [Rendering](/docs/frameworks/react/rendering#react-router-remix-and-other-server-rendered-apps) for available options.

## The banner or dialog fails to load

**Check.** Open the console. A warning or error from Inth that says the banner, the dialog or the engine failed to load means the browser could not download one of Inth's chunks, for example during a dropped connection or a deploy that removed old files.

After a failure the page stays as it is: Inth never reloads it, because a reload would discard what the visitor typed into your page. Nothing is recorded, and the banner stays or shows again. The next tap, open or snapshot tries the download again. How the retry reaches the network depends on your bundler: webpack and rspack forget a failed chunk, so every retry sends a new request. With Vite or another bundler that uses native `import()`, Firefox 155 or later, Chrome 156 or later, and Safari send a new request; earlier Chromium and Firefox keep the failure, and Inth loads the chunk again from its URL with `inth-retry=<n>` added, which works unless another chunk imports it by its plain URL.

**Fix.** Nothing on the page. The next page load downloads the chunk again. If the failures follow a deploy, keep the previous build's chunk files available until cached pages that link to them expire. See [a consent chunk fails to load](/docs/guides/troubleshooting#a-consent-chunk-fails-to-load) for which browsers and builds can retry on the same page.
