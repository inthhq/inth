Add a consent banner to a React Vite app. The browser resolves each visitor's policy from Inth, and analytics wait until consent allows them.

<Prompt title="Add Inth consent to this React app" description="Paste into Claude Code, Codex, Cursor, or another coding agent at the root of your app.">
  Add Inth consent management to this React Vite app.

  1. Check that the app is a React app built with Vite. If it uses Next.js or TanStack Start, stop and tell me.
  2. Install `@inth/react` and `@inth/integrations`. Read `node_modules/@inth/react/AGENTS.md`, then follow the React quickstart it links to, in order. Do not guess the API from memory.
  3. Set `VITE_INTH_PROJECT_URL` in `.env`. Ask me for my project URL. `VITE_INTH_PROJECT_URL` wins over any legacy `VITE_C15T_BACKEND_URL`.
  4. Add `consentManifest()` from `@inth/react/build` to `vite.config.ts`. Add nothing to `.gitignore`.
  5. Create `src/consent.tsx` with `InthProvider`, `ConsentBanner`, `ConsentDialog`, and a footer `ConsentDialogLink`. Move every analytics and marketing script into `options.scripts` with the matching helper from `@inth/integrations`, carry over settings such as PostHog's `region` or `apiHost`, and remove old loaders from `index.html` or app code. If a vendor has no helper, tell me.
  6. Wrap `<App />` in `<Consent>` in `src/main.tsx` and wrap third-party iframes in `ConsentGate`.
  7. Run `vite build` and `vite preview`. In a browser, check that no vendor request fires before consent, that rejecting survives a reload, and that granting analytics from the footer link loads PostHog.

  Then list the files you changed, any script still outside consent, and how you checked the requests.

## Prerequisites

- A React single-page app built with Vite. For Next.js or TanStack Start, see the [framework list](/docs/frameworks). For React Router framework mode or Remix, see [rendering](/docs/frameworks/react/rendering#react-router-remix-and-other-server-rendered-apps).
- An [Inth project](https://inth.com/dashboard/sign-up?framework=react) with your site's origin in its trusted origins. See [connect an Inth project](/docs/concepts/choose-your-setup#connect-an-inth-project).

## Install the SDK

<CommandTabs command="@inth/react @inth/integrations" mode="install" />

Components render their own `<style>` elements, so no stylesheet import is needed. On Tailwind CSS 3, [import the stylesheet yourself](/docs/frameworks/react/customize#import-the-stylesheet-yourself).

## Set the project URL

Add your Inth project URL, including any path prefix, to `.env` and your host's build settings:

```sh title=".env"
VITE_INTH_PROJECT_URL=https://your-project.inth.app
```

This URL is public. Vite inlines it at build time, so rebuild after changing it. `VITE_INTH_PROJECT_URL` wins over any legacy `VITE_C15T_BACKEND_URL`, which is read as a fallback if unset.

## Gate your own features

Check a category inside the provider with `useConsent`:

{/* example: fragment */}

```tsx title="src/marketing-banner.tsx"
import { useConsent } from '@inth/react';

export function MarketingBanner() {
	return useConsent('marketing') ? <aside>Spring sale</aside> : null;
}
```

For third-party iframes, use [`ConsentGate`](/docs/frameworks/react/components/consent-gate).

## Check it works

Run `vite build` and `vite preview`, then open a private window with DevTools Network open.

1. Under an opt-in policy, one `/v1/consent/init` request fires, the banner appears, and no requests go to `posthog.com`.
2. Click **Reject All**, then reload. The banner stays closed and PostHog stays blocked.
3. Click **Privacy settings**, enable **Analytics**, and click **Save Settings**. PostHog loads.
4. Open **Privacy settings**, turn **Analytics** off, and click **Save Settings**. The page reloads without PostHog.

Inspect requests in DevTools Network to confirm blocking; a visible banner alone proves nothing. In an opt-out region, pass `overrides: { country: 'DE' }` locally to test an EU policy, then remove it. See [Troubleshooting](/docs/frameworks/react/troubleshooting) and [Verify consent](/docs/guides/verify-consent).
