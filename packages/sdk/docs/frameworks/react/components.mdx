`@inth/react` exports the provider, consent UI components, and hooks from one entry point. Every component except `InthProvider` and `ConsentTheme` reads the runtime from the nearest `InthProvider`.

## Component reference

| Component | Renders | Reference |
| --- | --- | --- |
| `InthProvider` | The consent runtime that loads policy, stores choices, and runs scripts. Renders no markup of its own | [InthProvider](/docs/frameworks/react/components/inth-provider) |
| `ConsentBanner` | The consent banner when the visitor's policy requires one | [ConsentBanner](/docs/frameworks/react/components/consent-banner) |
| `ConsentDialog` | The preference center modal | [ConsentDialog](/docs/frameworks/react/components/consent-dialog) |
| `ConsentWidget` | The preference center inline on a privacy or settings page | [ConsentWidget](/docs/frameworks/react/components/consent-widget) |
| `ConsentDialogLink` | An unstyled button that opens the dialog, suited for footers | [ConsentDialogLink](/docs/frameworks/react/components/consent-dialog-link) |
| `PrivacyChoicesLink` | A footer link for US opt-out regions that renders the configured opt-out title and opens the dialog | [PrivacyChoicesLink](/docs/frameworks/react/components/privacy-choices-link) |
| `ConsentDialogTrigger` | A floating, draggable corner button that opens the dialog. `ConsentDialogTriggerToolbar` adds app actions beside it | [ConsentDialogTrigger](/docs/frameworks/react/components/consent-dialog-trigger) |
| `ConsentGate` | Its children when a category is allowed, or a placeholder otherwise | [ConsentGate](/docs/frameworks/react/components/consent-gate) |
| `ConsentTheme` | A `<style>` element with your theme tokens | [Customize](/docs/frameworks/react/customize) |
| `DevTools` from `@inth/react/devtools` | A development panel for consent state, scripts, and events | [DevTools](/docs/frameworks/react/components/dev-tools) |

Mount one `InthProvider` at your app root and keep it mounted across route transitions. The provider reads `mode` and module options once on mount.

## Start with the provider, banner and dialog

Most apps start with four components: `InthProvider`, `ConsentBanner`, `ConsentDialog`, and a footer `ConsentDialogLink` so visitors can reopen preferences. The [quickstart](/docs/frameworks/react/quickstart) keeps them together in `src/consent.tsx`:

Add `ConsentWidget`, `ConsentDialogTrigger`, or `ConsentGate` where pages need them. Keep `ConsentDialog` mounted even when you add `ConsentWidget`, because the banner's Customize button and `ConsentDialogLink` open the dialog.

## Server-rendered React apps

React Router framework mode, Remix, and other SSR React setups use the same components. `InthProvider` renders safely on the server without touching browser APIs, and the banner mounts after hydration once the browser resolves the policy. See [Rendering](/docs/frameworks/react/rendering#react-router-remix-and-other-server-rendered-apps).

## IAB TCF components

Import `IABProvider`, `IABConsentBanner`, and `IABConsentDialog` from `@inth/react/iab` and mount them inside `InthProvider` next to `ConsentBanner` and `ConsentDialog`. The built-in banner and dialog stay closed under an `iab` policy. See [IAB TCF](/docs/frameworks/react/iab).

## Check the components

Load the app in a private window under an opt-in policy:

1. Confirm the banner appears and DevTools Network shows zero vendor requests.
2. Click the footer `ConsentDialogLink` and confirm the dialog opens with optional categories off.
3. Enable one category and save. Confirm its vendor requests fire and any `ConsentGate` for that category mounts its children.
4. Reload and confirm the banner stays closed while the footer link still reopens the dialog.
