  3. Install `@inth/react`, plus `@inth/integrations` if the app uses vendor helpers.
  4. ## Before you start

- Upgrade React and React DOM to 18 or later.
- If you run your own c15t backend, upgrade it in the same release. A v3
  client can't read a v2 backend. See
  [Upgrade a self-hosted backend](/docs/self-host/upgrade-v3).
  Inth-hosted backends need no change.
- Install the [Inth CLI](/docs/cli/overview#install-the-inth-cli). The
  codemods run through `inth c15t codemods`.

## Replace the packages

Remove `@c15t/react` and `@c15t/scripts`, then install `@inth/react`.

<CommandTabs command="@inth/react @inth/integrations" mode="install" />

Drop `@inth/integrations` if you don't use its vendor helpers.

| v2 import | v3 import |
| --- | --- |
| `@c15t/react` | `@inth/react` |
| `@c15t/react/headless` | `@inth/react/headless` |
| `@c15t/react/styles.css` | Nothing: remove the import. Keep `@inth/react/styles.css` only with `styles: false` |
| `DevTools` from `@c15t/dev-tools/react` | `DevTools` from `@inth/react/devtools` |
| `@c15t/scripts/*` | `@inth/integrations/*` |

The `packages-to-c15t` codemod rewrites the `@c15t/react` imports and removes
the stylesheet import. It doesn't edit `package.json`.

The codemods come from c15t, so they write c15t v3 paths such as
`c15t/react` and `@c15t/integrations`. After a run, replace `c15t/react` with
`@inth/react` and `@c15t/integrations` with `@inth/integrations`.

Every v3 package ships ESM only. If a CommonJS file in your app calls
`require()` on a c15t or Inth package, convert it to ESM.

## Replace `ConsentManagerProvider`

Swap `ConsentManagerProvider` for `ConsentProvider` from `@inth/react`, and pass
a transport as `mode`:

| v2 option | v3 option |
| --- | --- |
| `mode: 'hosted'` with `backendURL` | `mode: hosted({ backendURL })` |
| `mode: 'offline'` with `offlinePolicy` | `mode: local({ policyRules })` |
| `mode: 'custom'` with `endpointHandlers` | No equivalent. Point the provider at your Inth project, which records each choice. `endpointHandlers` throws. |

{/* example: fragment */}

```tsx title="After (v3): the provider, changed lines"
import { ConsentBanner, ConsentDialog, ConsentProvider, hosted } from '@inth/react';

// Replace ConsentManagerProvider:
<ConsentProvider
  options={{ mode: hosted({ backendURL: 'https://your-project.c15t.dev' }) }}
>
```

The `consent-provider-options` codemod rewrites the hosted mode and adds the
`hosted` import. It leaves offline and custom modes as they are, with a
`TODO(c15t v3)` comment. Move `offlinePolicy.policyPacks` to
`local({ policyRules })` by hand. It can't translate `endpointHandlers`:

```bash
inth c15t codemods consent-provider-options --dry-run --json
```

Keep your backend URL. An existing hosted URL such as
`https://your-project.c15t.dev` keeps working with v3 clients. New Inth
projects use URLs such as `https://your-project.inth.app`. The
[React quickstart](/docs/frameworks/react/quickstart) shows the full provider,
and [data fetching](/docs/concepts/data-fetching) covers what each mode sends.

The quickstart keeps `hosted()` and adds `consentManifest()` from
`@inth/react/build` to `vite.config.ts`. `hosted()` then reads the backend URL from
`VITE_INTH_PROJECT_URL`, so it needs no arguments. v3 also adds `manifest()`,
which bundles the policy when Vite builds. It skips `/init` only when the
policy has no location rules or the page knows the visitor's location. See
[consent modes](/docs/concepts/modes).

Local mode keeps choices in the browser and records nothing on a server. Not
recommended for production environments.

If your app renders on the server with React Router or Remix, the banner still
mounts after hydration, as in v2. `fetchSSRData()` from `@inth/react/server`
can save the browser its first `/init` request. See
[rendering](/docs/frameworks/react/rendering).

## Update dev tools

`@c15t/dev-tools/react` and `@c15t/dev-tools/tanstack` are gone. Import
`DevTools`, `InthTanStackDevtoolsPanel` and `inthDevtools()` from
`@inth/react/devtools`. Dev tools read the consent engine, so `namespace`,
`createStoreConnector()` and `getC15tStore()` are gone too. See
[dev tools](/docs/frameworks/react/components/dev-tools).

The `dev-tools-to-c15t` codemod points the imports at `c15t/react/devtools`
and removes the `namespace` prop. Then point them at `@inth/react/devtools`:

```bash
inth c15t codemods dev-tools-to-c15t --dry-run --json
```
