  Read https://v3.c15t.com/docs/frameworks/react/upgrade-v3.md first and follow it in order. Do not guess v3 APIs from memory.

  1. List every Inth dependency and import: `@c15t/react`, `@c15t/scripts`, `@c15t/dev-tools` and `inth`.
  2. Check that React is 18 or later. Stop and tell me if it needs a major upgrade.
  3. Replace the packages with `inth`, plus `@c15t/integrations` if the app uses vendor helpers.
  4. Install the Inth CLI with `npm install -g @inth/cli` if `inth` is missing, then run `inth inth codemods packages-to-inth consent-provider-options root-exports-to-subpaths use-consent-manager-to-hooks scripts-to-integrations dev-tools-to-inth policy-packs-to-policy-rules callbacks-to-v3 theme-to-consent-theme iab-option-to-iab-provider css-variables-to-v3 postcss-tailwind3 --dry-run --json`. Review the output, then run the same command without `--dry-run`. The codemods leave a `TODO(inth v3)` comment wherever they need you to finish a change.
  5. Check that `ConsentManagerProvider` is now `ConsentProvider` from `inth/react`, with a transport such as `hosted()` as `mode`. Finish any custom mode the codemod marked.
  6. Update callbacks, policy presets, renamed options and components, theme CSS, CSS variables and IAB setup as the guide describes.
  7. Keep the existing backend URL. If the app runs its own Inth backend, stop and tell me, because it has to be upgraded in the same release with https://v3.c15t.com/docs/self-host/upgrade-v3.md.

## Before you start

- Upgrade React and React DOM to 18 or later.
- If you run your own Inth backend, upgrade it in the same release. A v3
  client can't read a v2 backend. See
  [Upgrade a self-hosted backend](/docs/self-host/upgrade-v3).
  Inth-hosted backends need no change.
- Install the [Inth CLI](/docs/cli/overview#install-the-inth-cli). The
  codemods run through `inth inth codemods`.

## Replace the packages

Remove `@c15t/react` and `@c15t/scripts`, then install `inth`.

<CommandTabs command="inth @c15t/integrations" mode="install" />

Drop `@c15t/integrations` if you don't use its vendor helpers.

| v2 import | v3 import |
| --- | --- |
| `@c15t/react` | `inth/react` |
| `@c15t/react/headless` | `inth/react/headless` |
| `@c15t/react/styles.css` | Nothing: remove the import. Keep `inth/react/styles.css` only with `styles: false` |
| `DevTools` from `@c15t/dev-tools/react` | `DevTools` from `inth/react/devtools` |
| `@c15t/scripts/*` | `@c15t/integrations/*` |

The `packages-to-inth` codemod rewrites the `@c15t/react` imports and removes
the stylesheet import. It doesn't edit `package.json`.

`@c15t/react` is still published at v3, so its imports keep working after you
upgrade it. These docs use `inth/react`.

Every v3 package ships ESM only. If a CommonJS file in your app calls
`require()` on a Inth package, convert it to ESM.

## Replace `ConsentManagerProvider`

Swap `ConsentManagerProvider` for `ConsentProvider` from `inth/react`, and pass
a transport as `mode`:

| v2 option | v3 option |
| --- | --- |
| `mode: 'hosted'` with `backendURL` | `mode: hosted({ backendURL })` |
| `mode: 'offline'` with `offlinePolicy` | `mode: local({ policyRules })` |
| `mode: 'custom'` with `endpointHandlers` | `mode: custom(transport)`, where `transport` implements the v3 transport interface. `endpointHandlers` throws. |

{/* example: fragment */}

```tsx title="After (v3): the provider, changed lines"
import { ConsentBanner, ConsentDialog, ConsentProvider, hosted } from 'inth/react';

// Replace ConsentManagerProvider:
<ConsentProvider
  options={{ mode: hosted({ backendURL: 'https://your-project.c15t.dev' }) }}
>
```

The `consent-provider-options` codemod rewrites the hosted mode and adds the
`hosted` import. It leaves offline and custom modes as they are, with a
`TODO(inth v3)` comment. Move `offlinePolicy.policyPacks` to
`local({ policyRules })` by hand. It can't translate `endpointHandlers`:

```bash
inth inth codemods consent-provider-options --dry-run --json
```

Keep your backend URL. An existing hosted URL such as
`https://your-project.c15t.dev` keeps working with v3 clients. New Inth
projects use URLs such as `https://your-project.inth.app`. The
[React quickstart](/docs/frameworks/react/quickstart) shows the full provider,
and [data fetching](/docs/concepts/data-fetching) covers custom transports.

The quickstart keeps `hosted()` and adds `consentManifest()` from
`inth/build` to `vite.config.ts`. `hosted()` then reads the backend URL from
`VITE_INTH_PROJECT_URL`, so it needs no arguments. v3 also adds `manifest()`,
which bundles the policy when Vite builds. It skips `/init` only when the
policy has no location rules or the page knows the visitor's location. See
[consent modes](/docs/concepts/modes).

Local mode keeps choices in the browser and records nothing on a server. Not
recommended for production environments.

If your app renders on the server with React Router or Remix, the banner still
mounts after hydration, as in v2. `fetchSSRData()` from `inth/react/server`
can save the browser its first `/init` request. See
[rendering](/docs/frameworks/react/rendering).

## Update dev tools

`@c15t/dev-tools/react` and `@c15t/dev-tools/tanstack` are gone. Import
`DevTools`, `InthTanStackDevtoolsPanel` and `inthDevtools()` from
`inth/react/devtools`. Dev tools read the consent engine, so `namespace`,
`createStoreConnector()` and `getInthStore()` are gone too. See
[dev tools](/docs/frameworks/react/components/dev-tools).

The `dev-tools-to-inth` codemod points the imports at `inth/react/devtools` and
removes the `namespace` prop:

```bash
inth inth codemods dev-tools-to-inth --dry-run --json
```
