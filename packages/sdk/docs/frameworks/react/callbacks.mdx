Run custom logic in React when a visitor records a choice, effective permissions change, a request fails, or a revocation reload is about to run.

## Pass callbacks to the provider

Define callbacks in their own module:

<include src="../../shared/examples/react/callbacks.mdx" />

Pass `callbacks` to `InthProvider` in `src/consent.tsx` from the [quickstart](/docs/frameworks/react/quickstart):

{/* example: fragment */}

```tsx title="src/consent.tsx"
<InthProvider options={{ mode, scripts, callbacks }}>
```

`InthProvider` subscribes callbacks after mount, so they run only in the browser and never during server rendering. It always invokes the latest `callbacks` object without remounting; defining the object at module level avoids unnecessary churn across renders.

When you pass an external `runtime` to `InthProvider`, pass `callbacks` and `reloadOnConsentRevoked` to `createConsentRuntime` instead.

## Available callbacks

| Callback | Runs when | Receives |
| --- | --- | --- |
| `onChoiceRecorded` | The visitor clicks Accept All, Reject All, or Save Settings in built-in UI or via `useSaveConsents()`. | `snapshot`, state after the choice; `confirmed`, categories recorded by this action; `actionAt`, millisecond timestamp |
| `onPermissionsChanged` | Any effective permission changes value. | `snapshot`, state after the change; `previous`, permissions before it |
| `onError` | A consent command fails, such as a failed `/v1/consent/init` or rejected `/v1/consent/records` save. | `error`, message string |
| `onBeforeConsentRevocationReload` | A save or one-click opt-out revokes a granted category or vendor, immediately before Inth reloads the page. Privacy signals and backend-synced opt-outs do not reload. | `preferences`, permissions after the withdrawal |

The full object type is `InthProviderCallbacks` from `@inth/react`. Callbacks run after state updates, so `snapshot` and hooks such as `useConsent()` already reflect the new values.

## onChoiceRecorded or onPermissionsChanged

`onChoiceRecorded` fires only on an explicit visitor action. `onPermissionsChanged` fires whenever effective permissions change for any reason:

| Event | `onChoiceRecorded` | `onPermissionsChanged` |
| --- | --- | --- |
| Visitor accepts, rejects, or saves | Yes | Yes, if a permission changed |
| Policy resolves and allows categories before any choice | No | Yes |
| Global Privacy Control turns off a grant | No | Yes |
| Recorded choice expires | No | Yes |
| Visitor dismisses a notice | No | No |

Use `onChoiceRecorded` for consent analytics and audit logs because it fires only when the visitor acts. Use `onPermissionsChanged` to start or stop app code, never as proof of consent and never to save consent. See [how consent works](/docs/concepts/how-consent-works#a-permission-is-not-a-recorded-choice).

Dismissing a notice records no choice and changes no permission; read it with `useNoticeDismissal()`. For reactive UI inside a single component, use [hooks](/docs/frameworks/react/hooks).

## Before a revocation reload

Removing a `<script>` tag cannot stop code already executing in memory, so Inth reloads the page after a save revokes a previously granted category or vendor. The reload waits for the save request to complete, then runs `onBeforeConsentRevocationReload` synchronously right before reloading. Use it to call a vendor shutdown API or flush queued events, and keep it synchronous because the reload does not await promises.

Policy changes, expired choices, and privacy signals do not reload the page because they are not triggered by a visitor save.

To manage revocation yourself, set `reloadOnConsentRevoked: false` in provider options. Revoked vendor code then stays active until the next full page load, and `onBeforeConsentRevocationReload` never runs.

## Verify

1. Add the callbacks, open DevTools Console and Network, clear site data, and reload under a policy showing a banner.
2. Click **Accept All**. Confirm both `onChoiceRecorded` and `onPermissionsChanged` log and `/v1/consent/records` appears in Network.
3. Reload and confirm `onChoiceRecorded` does not fire again.
4. Open Privacy settings, turn off an allowed category, and save. Confirm `onBeforeConsentRevocationReload` logs before the page reloads and that category's vendor requests stay absent afterwards.
