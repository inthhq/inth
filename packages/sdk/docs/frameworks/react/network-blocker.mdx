Hold `fetch` and `XMLHttpRequest` calls to vendor domains in a React app until their consent category is allowed.

## Add rules

Some SDKs already live in your bundle and send beacons or API calls directly. Add `networkBlocker` rules to `InthProvider` options to hold matching `fetch` and `XMLHttpRequest` calls until consent allows them. Prefer loading vendor SDKs through [`scripts`](/docs/frameworks/react/scripts) first so they do not execute at all before consent.

Add `networkBlocker` next to `mode` and `scripts` in `src/consent.tsx`:

{/* example: fragment */}

```tsx title="src/consent.tsx"
const networkBlocker = {
	rules: [
		{
			id: 'google-analytics',
			domain: 'google-analytics.com',
			category: 'measurement',
		},
		{
			id: 'meta-pixel',
			domain: 'facebook.com',
			pathIncludes: '/tr',
			category: 'marketing',
		},
	],
};

<InthProvider options={{ mode, scripts, networkBlocker }}>
```

## Verify the blocked requests

Open DevTools Network in a private window under an opt-in policy.

1. Before a choice, confirm requests matching a rule do not appear and the console logs each blocked request.
2. Allow the rule's category and save. Confirm matching requests fire.
3. Reject, reload, and confirm they stay absent.
