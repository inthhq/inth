Load vendor scripts in a React app only when their consent category is allowed, and clean up when visitors withdraw consent.

## Register vendor scripts

Pass vendor helpers to `InthProvider` through `options.scripts`. The provider loads each script once its category is allowed and removes it when denied. The [quickstart](/docs/frameworks/react/quickstart) registers PostHog in `src/consent.tsx`:

<include src="../../shared/examples/react/consent.mdx" />

Each helper from `@inth/integrations` defines its own category and stable `id`. Remove any duplicate loader for the same vendor from `index.html` or app startup code so it loads only through Inth. See [integrations](/docs/integrations/overview) for built-in helpers and [custom integrations](/docs/integrations/building-integrations) for vendors without one.

## What happens when consent changes

- **Allowed.** Inth loads the script or initializes its SDK the first time its category is allowed.
- **Denied later.** Inth removes the script element. Because already-executed code keeps running in memory, the provider reloads the page after a save revokes a granted category. Set `reloadOnConsentRevoked: false` only if every gated vendor stops cleanly on its own.
- **`alwaysLoad` helpers.** Helpers such as Google Consent Mode load before consent and forward the visitor's state to the vendor. Check each vendor guide so you know what requests fire before consent.

## When the script loader downloads

Inth splits the script loader into a separate chunk downloaded only when `scripts` is non-empty. `InthProvider` starts downloading it on mount, whereas Next.js and TanStack Start `InthProvider` begin earlier during the first render when consent already allows a script.

## Embeds and other requests

`scripts` gates vendor scripts Inth loads for you. For other third-party requests:

- [Embeds](/docs/frameworks/react/embeds) blocks iframes with `ConsentGate` or the iframe blocker.
- [Network blocker](/docs/frameworks/react/network-blocker) holds matching `fetch` and XHR calls until their category is allowed.

## Clear stored data after revocation

Removing a script does not delete cookies or storage entries it already wrote. Add `clearOnRevocation` to `InthProvider` options to delete each category's entries when denied. The provider reads `clearOnRevocation` once on mount. See [Clear on revocation](/docs/frameworks/react/clear-on-revocation).

## Let visitors turn off one vendor

Optionally let visitors allow a category such as marketing while disabling a single vendor in it. Pass `vendors` to the provider options; helpers from `@inth/integrations` already include their vendor slug. See [Vendor consent](/docs/frameworks/react/vendor-consent).

## Send your own analytics events

`useEventDispatcher()` returns the provider's event dispatcher, which checks consent before sending events to registered `scripts`. Call `pageview` from your router with the current path:

`track` sends to every registered script with an event API and drops events while `measurement` is denied. `pageview` sends only to integrations listed in `pageviews`, and the first call records the initial path without sending. Every dispatcher shares one pageview history for the provider's lifetime. See [send events only to allowed integrations](/docs/integrations/overview#send-events-only-to-allowed-integrations).

## Check the scripts

Open DevTools Network in a private window, filter by each vendor's domain, and reload.

1. Before a choice under an opt-in policy, no vendor script loads.
2. Allow one category and confirm only that category's vendors load.
3. Turn the category off and confirm the page reloads with the vendor absent.
4. Reload again and confirm the rejection holds.

[Verify consent](/docs/guides/verify-consent) has the full checklist.
