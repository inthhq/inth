Enable IAB TCF in your Vue app so visitors under an IAB policy receive the
IAB banner, preference center, and `window.__tcfapi`.

## Turn on IAB TCF

IAB TCF is off by default. Pass `iab` to `inth` in `src/main.ts`; an empty
object enables it:

<include src="../../shared/examples/vue/iab-opt-in.mdx" />

With `iab` enabled, `InthProvider` automatically switches to the IAB banner and
preference center whenever the visitor's policy uses the `iab` model with a
CMP ID, and Inth installs `__tcfapi`. Configure your CMP ID and vendors in
your Inth project. No extra component or stylesheet is required.

Leaving `iab` unset, `false`, or `{ enabled: false }` keeps IAB disabled:
`__tcfapi` is not installed and `@inth/sdk/iab` is never loaded. The plugin
reads `iab` once on install.

If a visitor matches an `iab` policy that returns a vendor list while `iab` is
disabled, Inth throws `IABUnavailableError` (`INTH_IAB_UNAVAILABLE`) because
the standard banner cannot satisfy IAB TCF. When the policy arrives via
`prefetch`, `app.use()` throws; during browser resolution, the plugin throws
an uncaught error and `InthProvider` renders nothing. Either enable `iab` or
remove the `iab` model from that policy. If the policy response returns
`gvl: null`, IAB stays off and the policy runs as opt-in. See
[IABUnavailableError troubleshooting](/docs/frameworks/vue/troubleshooting#the-app-throws-iabunavailableerror).

To compose surfaces yourself instead of using `InthProvider`, import
[`IABConsentBanner`](/docs/frameworks/vue/components/iab-consent-banner) and
[`IABConsentDialog`](/docs/frameworks/vue/components/iab-consent-dialog). For
a custom preference center, use `useConsentIabSelection()` and
`useConsentIabSave()`.

## Restrict how vendors use a purpose

Publisher restrictions override a vendor's declared legal basis for a purpose.
Configure them inside `iab` (replace the placeholder vendor IDs with vendors
from your list whose declarations permit each restriction):

{/* example: fragment */}

```ts title="src/main.ts (partial)"
app.use(inth, {
	iab: {
		publisherRestrictions: [
			// Vendors 10 and 755 may not use purpose 4.
			{ purposeId: 4, restrictionType: 0, vendorIds: [10, 755] },
			// Vendor 755 must use legitimate interest for purpose 7.
			{ purposeId: 7, restrictionType: 2, vendorIds: [755] },
		],
	},
	mode: hosted(),
});
```

`iab` also accepts `publisherCountryCode`, a `vendors` allowlist,
`customVendors`, and `cmpVersion`. Omitted fields come from your Inth policy.
The CMP mounts only when the visitor's policy uses the `iab` model.

## Vendor list loading

The policy response includes a reference to the Global Vendor List. The IAB
module fetches the full list as soon as it mounts and waits for it before
writing a TC String. If the fetch fails, the banner stays open and grants
nothing. Allow the vendor list's origin in your CSP `connect-src`. See
[Content Security Policy](/docs/frameworks/vue/content-security-policy).

## Verify IAB consent

Load the app under your IAB policy and confirm the IAB banner appears. Accept
or reject, then run `__tcfapi('getTCData', 2, console.log)` in the browser
console and confirm a valid TC String is returned.
