Render `InthProvider` once in your root Vue component to display the right
consent surfaces for each visitor's policy.

## Render `InthProvider` in your root component

Import `InthProvider` from `@inth/vue/vue-plugin` and render it beside your
page content:

<include src="../../../shared/examples/vue/app.mdx" />

`InthProvider` reads the runtime created by
[the inth plugin](/docs/frameworks/vue/plugin) and ships its own styles.
Keep it in `src/App.vue` so it stays mounted across route changes.

The `inth` Vue plugin already provides the runtime to every component;
`InthProvider` renders the stock consent UI surfaces. Render `<InthProvider />`
as a sibling to your layout rather than wrapping your app in it.

## What InthProvider renders

`InthProvider` picks surfaces based on the visitor's policy and `activeUI`:

| Policy | `activeUI` is `'banner'` | `activeUI` is `'dialog'` |
| --- | --- | --- |
| Standard, opt-in, or opt-out | [`ConsentBanner`](/docs/frameworks/vue/components/consent-banner) | [`ConsentDialog`](/docs/frameworks/vue/components/consent-dialog) |
| IAB TCF with vendor list | [`IABConsentBanner`](/docs/frameworks/vue/components/iab-consent-banner) | [`IABConsentDialog`](/docs/frameworks/vue/components/iab-consent-dialog) |

It also renders [`ConsentDialogTrigger`](/docs/frameworks/vue/components/consent-dialog-trigger)
when `showTrigger: true` is configured.

Nothing renders until the policy resolves. The dialog and IAB surfaces load as
separate chunks (with IAB surfaces active only when `iab` is set and the
policy uses `iab`). The banner starts loading the dialog chunk when the
visitor reaches for one of its buttons, so the dialog opens without waiting
on the network. The dialog unmounts when closed.

## Theme tokens

`inth` writes `tokens` (including defaults) into `<style id="inth-css-vars">`
in `document.head` before the first render. Set token values in plugin options
rather than a `:root` stylesheet rule. See
[set theme tokens](/docs/frameworks/vue/customize#set-theme-tokens).

## Props

| Prop | Type | Default | Behavior |
| --- | --- | --- | --- |
| `country` | `string` | Location detected by Inth | Overrides country and re-resolves the policy. |
| `region` | `string` | Location detected by Inth | Overrides region (such as `CA`) and re-resolves the policy. |
| `language` | `string` | Browser language | Overrides language and re-resolves to fetch copy in that language. |

Use `country` and `region` to preview regional policies locally, and bind
`language` to your app's locale switcher:

{/* example: fragment */}

```vue
<InthProvider :language="locale" />
```

## Compose the surfaces yourself

To place or configure `ConsentBanner`, `ConsentDialog`, and the IAB
components yourself, render them instead of `InthProvider`. See
[ConsentBanner](/docs/frameworks/vue/components/consent-banner#import-the-banner-into-your-root-component).
Never mount both `InthProvider` and individual surfaces together, or visitors
see two banners.

## Verify

Open the app in a private window under an opt-in policy. Confirm the banner
appears once the policy request finishes, `<style id="inth-css-vars">` holds
your `--inth-*` tokens in `<head>`, Customize opens the choices in the banner, and rejecting
stays closed after a reload.
