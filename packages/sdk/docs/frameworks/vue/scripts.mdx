Register analytics and marketing scripts with `inth` so Inth loads them
only when their consent category is allowed.

## Register vendor scripts

A consent banner does not stop `<script>` tags in `index.html` or vendor SDKs
you initialize directly. Remove those loaders and pass helpers from
`@inth/integrations` to `inth` via `scripts`:

<include src="../../shared/examples/vue/main.mdx" />

The plugin starts one script loader on mount after reading stored choices and
privacy signals. Do not call `createScriptLoader` in a component; `onMounted`
runs before stored choices apply and loads each script twice.

See [integrations](/docs/integrations/overview) for every vendor helper and
its options.

## Register scripts from a component

For scripts decided at runtime, such as a tenant tag or a route-specific
script, call `useScriptLoader()`. It registers scripts with the app's single
loader, prevents duplicates, and cleans them up on unmount. Passing a ref or
getter reconciles updates automatically.

<include src="../../shared/examples/vue/script-loader.mdx" />

The returned handle exposes `updateScripts(next)` to replace scripts and
`dispose()` to remove them early. Revoking consent reloads the page just like
plugin-level scripts.

## Embeds and other requests

`scripts` covers code Inth loads for you. For other third-party requests:

- [Embeds](/docs/frameworks/vue/embeds): gate iframes with `ConsentGate` or
  the iframe blocker.
- [Network blocker](/docs/frameworks/vue/network-blocker): hold matching
  `fetch` and XHR calls until their category is allowed.

## When a visitor withdraws consent

Removing a `<script>` tag cannot stop JavaScript already running in memory.
When a save withdraws a granted category or vendor, Inth reloads the page so
only permitted code executes. Set `reloadOnConsentRevoked: false` to handle
revocation yourself, or register
[`onBeforeConsentRevocationReload`](/docs/frameworks/vue/callbacks#before-a-revocation-reload)
to run cleanup before the reload.

Use `clearOnRevocation` to delete first-party cookies and storage keys when a
category is denied. See
[clear on revocation](/docs/frameworks/vue/clear-on-revocation).

## Let visitors turn off one vendor

To let visitors allow a category while switching off individual vendors inside
it, declare them in `vendors`. Built-in `@inth/integrations` helpers already
include their vendor slug. See
[vendor consent](/docs/frameworks/vue/vendor-consent).

## Content Security Policy

Allow each vendor's script host in `script-src`, or pass `nonce` to `inth`
to attach a nonce to every loaded script. See
[Content Security Policy](/docs/frameworks/vue/content-security-policy).

## Send your own analytics events

`useEventDispatcher()` from `@inth/vue/vue-plugin` dispatches events to the
`scripts` in your config and checks consent before sending. Call it in `setup`
to track route changes:

<include src="../../shared/examples/vue/analytics-events.mdx" />

Call `events.track('sign_up', { method: 'email' })` from event handlers.
`track` forwards to every registered script with an event API and drops events
while measurement is denied. `pageview` targets only the integrations listed
in `pageviews`, records the initial path without sending, and shares pageview
history across dispatchers for the runtime's lifetime. See
[send events only to allowed integrations](/docs/integrations/overview#send-events-only-to-allowed-integrations).

## Verify gating

Open the app in a private window with the Network tab open under an opt-in
policy. Confirm vendor requests stay absent, allow one category and confirm
only its vendors load, then withdraw it and confirm the page reloads without
the vendor. See [verify consent](/docs/guides/verify-consent).
