Add a consent banner to a Vue 3 app built with Vite. The browser resolves each
visitor's policy from Inth, and analytics wait until consent allows them.

<Prompt title="Add Inth consent to this Vue app" description="Paste into Claude Code, Codex, Cursor or another coding agent at the root of your app.">
  Add Inth consent management to this Vue 3 Vite app.

  1. Check that the app is a Vue 3 app built with Vite. If it uses Nuxt or a custom Vue SSR server, stop and tell me.
  2. Install `@inth/vue` and `@inth/integrations`. Read `node_modules/@inth/vue/AGENTS.md`, then follow the Vue quickstart it links to, in order. Do not guess the API from memory.
  3. Set `VITE_INTH_PROJECT_URL` in `.env`. Ask me for my project URL. `VITE_INTH_PROJECT_URL` wins over any legacy `VITE_C15T_BACKEND_URL`.
  4. Add `consentManifest()` from `@inth/vue/vite` next to `vue()` in `vite.config.ts`. Add nothing to `.gitignore`.
  5. Install `inth` with `mode: hosted()` in `src/main.ts`. Move every analytics and marketing script into `scripts` with the matching helper from `@inth/integrations`, carry over settings such as PostHog's `region` or `apiHost`, and remove old loaders from `index.html` or app code. If a vendor has no helper, tell me.
  6. Render `InthProvider` and a `ConsentDialogLink` in `src/App.vue`, and wrap third-party iframes in `ConsentGate`.
  7. Run `vite build` and `vite preview`. In a browser, check that no vendor request fires before consent, that rejecting survives a reload, and that granting analytics from the footer link loads PostHog.

  Then list the files you changed, any script still outside consent, and how you checked the requests.
</Prompt>

## Prerequisites

- A Vue 3 single-page app built with Vite. For Nuxt or another framework, see
  the [framework list](/docs/frameworks).
- An [Inth project](https://inth.com/dashboard/sign-up?framework=vue) with
  your site's origin in its trusted origins.

## Install the SDK

<CommandTabs command="@inth/vue @inth/integrations" mode="install" />

The components ship their own styles, so there is no stylesheet to import.

## Set the project URL

Add your Inth project URL (including any path prefix) to `.env` and your
host's build settings:

```sh title=".env"
VITE_INTH_PROJECT_URL=https://your-project.inth.app
```

This URL is public. Vite
inlines it at build time, so rebuild after changes. `VITE_INTH_PROJECT_URL`
wins over any legacy `VITE_C15T_BACKEND_URL`, which is read as a fallback if
unset.

`vite.config.ts`:

<include src="../../shared/examples/vue/vite-config.mdx" />

`consentManifest()` passes your project URL to the plugin, excludes Inth's
`.vue` files from dependency pre-bundling, and injects an early `/v1/consent/init`
prefetch into `index.html`. See
[send `/init` before the app loads](/docs/frameworks/vue/rendering#send-init-before-the-app-loads).

## Check it works

Run `vite build` and `vite preview`, then open the site in a private window on
the DevTools Network tab.

1. Under an opt-in policy, `/v1/consent/init` runs, the banner appears, and no requests
   go to `posthog.com` or `youtube-nocookie.com`.
2. Click **Reject All** and reload. The banner stays closed and vendor
   requests stay absent.
3. Click **Privacy settings**, enable **Analytics**, and click **Save
   Settings**. PostHog loads and the video appears.
4. Open **Privacy settings**, disable **Analytics**, and save. The page
   reloads without PostHog or the video.

Inspect requests in the Network tab to confirm blocking; a visible banner
alone proves nothing. To preview an EU policy locally, pass
`<InthProvider country="DE" />` temporarily. See
[troubleshooting](/docs/frameworks/vue/troubleshooting) and
[verify consent](/docs/guides/verify-consent).
