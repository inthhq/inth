Every Inth Vue component reads the consent runtime provided by
[the inth plugin](/docs/frameworks/vue/plugin) and ships its own styles.

## Component reference

Render components inside the Vue app that called `app.use(inth, ...)`.
Import every component except `ConsentDevTools` by name from
`@inth/vue/vue-plugin` so your bundler tree-shakes unused components.

| Component | What it renders |
| --- | --- |
| [`InthProvider`](/docs/frameworks/vue/components/inth-provider) | Banner and preference dialog (switching to IAB surfaces under an IAB policy when `iab` is set). |
| [`ConsentBanner`](/docs/frameworks/vue/components/consent-banner) | First-layer banner on its own. |
| [`ConsentManager`](/docs/frameworks/vue/components/consent-manager) | Preference dialog on its own. |
| [`ConsentWidget`](/docs/frameworks/vue/components/consent-widget) | Inline category switches and save buttons for a privacy page. |
| [`ConsentDialogLink`](/docs/frameworks/vue/components/consent-dialog-link) | Button that reopens preferences. |
| [`ConsentDialogTrigger`](/docs/frameworks/vue/components/consent-dialog-trigger) | Floating, draggable button that reopens preferences. |
| [`ConsentGate`](/docs/frameworks/vue/components/consent-gate) | Default slot while a category is allowed, otherwise its `placeholder` slot. |
| [`IABConsentBanner`](/docs/frameworks/vue/components/iab-consent-banner) | IAB TCF first layer. |
| [`IABConsentDialog`](/docs/frameworks/vue/components/iab-consent-dialog) | IAB TCF preference center. |
| [`ConsentDevTools`](/docs/frameworks/vue/components/dev-tools) | Development inspection panel, imported from `@inth/vue/devtools`. |

{/* example: fragment */}

```ts
import { ConsentDialogLink, ConsentGate } from '@inth/vue/vue-plugin';
```

Because the components ship as `.vue` files, keep
[`consentManifest()`](/docs/frameworks/vue/quickstart#add-the-vite-plugin) in
`vite.config.ts` so Vite excludes them from dependency pre-bundling.

## InthProvider or the parts

`InthProvider` renders `ConsentBanner` and `ConsentManager` (or the IAB
components when `iab` is enabled) automatically for each visitor's policy.
Mount either `InthProvider` or the individual surfaces, never both, so visitors
do not see two banners. Compose the individual components only when you need
different variants per route or custom placement.

## Building blocks

`@inth/vue/vue-plugin` also exports smaller building blocks: `ConsentButton`,
`ConsentSwitch`, `ConsentActions`, `ConsentLink`, `ConsentDescription`,
`ConsentTag`, and `ConsentBrandingIcon`. `ConsentLegalLinks` lives at
`@inth/vue/runtime/components/consent-legal-links.vue`. For custom consent
markup, use the [headless composables](/docs/frameworks/vue/headless) instead.

`ConsentLink` renders a single legal link such as
`<ConsentLink context="banner" link="privacyPolicy" />` using `legalLinks` or
an explicit `href` prop, and renders nothing if neither supplies a URL.
`ConsentLegalLinks` skips missing URLs the same way.
