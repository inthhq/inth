Configure your Content Security Policy so Inth can fetch policies, record
consent choices, apply theme tokens, and load permitted vendor scripts in Vue.

## What Inth adds to the page

| What | Directive |
| --- | --- |
| Requests to Inth's `/v1/consent/records`, plus `/v1/consent/init` (`hosted()`) or `/v1/consent/manifest` (`manifest({ source: 'runtime' })`) | `connect-src` |
| Code-split chunks such as the manifest resolver and non-English copy | `script-src 'self'` |
| `<script>` elements created by the script loader for `scripts` | `script-src` |
| Inline `<script>` added to `index.html` by `consentManifest()` to prefetch `/v1/consent/init` | `script-src` with a nonce or hash |
| Vendor scripts, frames, images, and API calls | `script-src`, `frame-src`, `img-src`, `connect-src` per vendor |
| Bundled component CSS from Vite | `style-src 'self'` |
| Inline `<style id="inth-css-vars">` element for theme tokens in `<head>` | `style-src` |
| Runtime style bindings set through the CSSOM, such as trigger position | None |

## Allow your Inth project

Add your Inth project origin to `connect-src`. If you use a custom
`manifestUrl` or `geoUrl` on another origin, allow that origin as well. With
`iab` enabled, also allow the Global Vendor List origin (usually your Inth
project host).

```txt title="Content-Security-Policy (partial)"
connect-src 'self' https://<your-inth-project-host>;
```

## Allow scripts

List each vendor's script host in `script-src` (each
[integration guide](/docs/integrations/overview) lists its hosts).

Static Vue files cannot carry a per-request nonce on their own. If your server
generates a nonce per response, pass it via `inth`'s `nonce` option so the
script loader attaches it to every `<script>` it creates (a script-level
`nonce` overrides the plugin option). To allow sub-scripts loaded by a vendor
script, add `'strict-dynamic'` to `script-src` or list those hosts explicitly.

{/* example: fragment */}

```ts title="src/main.ts"
app.use(inth, { mode: hosted(), nonce, scripts });
```

The plugin `nonce` does not apply to the early `/v1/consent/init` script injected into
`index.html`. If your server injects per-request nonces, configure Vite's
`html.cspNonce` placeholder and replace it per response. On a static host,
allow that script by copying its `sha256-...` hash from the browser's
`Refused to execute inline script` console error. If blocked, the app still
sends `/v1/consent/init` after mounting.

## Allow styles

Vite bundles component CSS into your production stylesheet, which
`style-src 'self'` covers. In development, Vite injects `<style>` elements
that require `'unsafe-inline'` in `style-src`.

`inth` appends `<style id="inth-css-vars">` to `<head>` for theme tokens.
Without `'unsafe-inline'`, copy its `sha256-...` hash from the browser's
`Refused to apply inline style` error into `style-src`, and update the hash
whenever you edit `tokens`. Passing `nonce` to `inth` attaches that nonce
to `<style id="inth-css-vars">` as well.

Vue applies inline component styles (such as trigger drag positions) via the
CSSOM, which does not require a CSP rule.

## Verify

Enforce the CSP (not report-only) and load the app. Confirm your theme colors
render and no `Refused to connect`, `Refused to load the script`, or
`Refused to apply inline style` error references Inth or an allowed vendor.
Click **Accept All** and confirm vendor scripts load and `POST /v1/consent/records`
succeeds.
