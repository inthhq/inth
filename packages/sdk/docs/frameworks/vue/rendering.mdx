Choose how your Vue app fetches and resolves visitor policies using the `mode`
option in `app.use(inth, { mode })`.

## Pick the setup for your deployment

The Vue plugin runs in the browser only. Import the mode factory from
`@inth/vue/vue-plugin` (or `@inth/vue/testing` for tests):

| Your app | `mode` |
| --- | --- |
| Vue with Vite, served as static files | [`hosted()`](#ask-the-backend-for-each-visitors-policy), as in the [quickstart](/docs/frameworks/vue/quickstart). Inth resolves each visitor's policy from their location. |
| Policy without location rules, or a page that already knows the visitor's location | [`manifest()`](#bundle-the-manifest-during-builds). The build bundles the policy and the browser resolves it. |
| Browser resolution with policy edits without rebuilding | [`manifest({ source: 'runtime' })`](#fetch-the-manifest-at-runtime) |
| Tests without a backend | [`testing()`](#test-without-a-backend) from `@inth/vue/testing`. Throws in production builds. |
| Vue rendered on the server without Nuxt | Any of the above; the banner mounts after hydration. For server-rendered banners, [use Nuxt](#server-rendering-without-nuxt). |

`mode` is required; omitting it throws in `app.use()`. Static mode imports
let your bundler tree-shake unused modes.

## Ask the backend for each visitor's policy

The [quickstart](/docs/frameworks/vue/quickstart) and `examples/vue` use
`hosted()`. Each page load calls Inth's `/v1/consent/init`, which reads the visitor's
location from the request, resolves the active policy, and returns copy in
their language:

{/* example: fragment */}

```ts title="src/main.ts"
import { inth, hosted } from '@inth/vue/vue-plugin';

app.use(inth, { mode: hosted(), scripts });
```

`hosted()` reads the project URL from `consentManifest()`, or accepts
`hosted({ projectUrl: 'https://your-project.inth.app' })`. Keep
`consentManifest()` in `vite.config.ts` either way so Vite excludes Inth's
`.vue` components from dependency pre-bundling. A `hosted()` build never
downloads a manifest.

Until `/v1/consent/init` completes, optional categories stay denied so gated scripts and
iframes wait. Deploy the static files to any static host and add your site's
origin to your Inth project's trusted origins. See
[data fetching](/docs/concepts/data-fetching) for the tradeoffs.

## Bundle the manifest during builds

`manifest()` resolves the policy in the browser from a build-time snapshot. It
avoids the `/v1/consent/init` request only when your policy has no location rules or when
the browser already knows the visitor's location. Otherwise it adds roughly
3 KB gzipped for the resolver without saving a request, requires a rebuild on
policy edits, and does not count browser-resolved visitors in Inth analytics.

<include src="../../shared/build-manifests/vue.mdx" />

### Tell the browser where the visitor is

Because a browser has no request geo headers, `manifest()` falls back to
Inth's `/v1/consent/init` on the first visit whenever the policy depends on country or
region, rather than applying the unknown-location rule. `vite build` logs a
warning when bundling a regional policy and suggests `hosted()`. To resolve
in the browser instead:

- Pass `country` and `region` props to `InthProvider` when your edge server
  injects the location.
- Pass `inputs: { country, region }` to `manifest()` when installing the
  plugin.
- Set `geoUrl` to a same-origin endpoint returning `{ country, region }` JSON.
  `manifest()` requests it only when a policy requires a location.
- Pass `initFallback: false` to `manifest()` to resolve the unknown-location
  rule without calling Inth. Use this only when that rule is valid for every
  visitor.

### Load the visitor's language

The bundle includes English copy. When a visitor resolves to another
translated language, the browser loads that language chunk from your site on
demand.

## Fetch the manifest at runtime

`manifest({ source: 'runtime' })` skips the build snapshot and fetches
`${projectUrl}/v1/consent/manifest` on app startup so policy edits apply without
rebuilding:

{/* example: fragment */}

```ts title="src/main.ts"
import { inth, manifest } from '@inth/vue/vue-plugin';

app.use(inth, { mode: manifest({ source: 'runtime' }), scripts });
```

Keep `consentManifest({ source: 'runtime' })` in `vite.config.ts` so
`manifest()` reads the project URL without downloading a build snapshot.

To fetch the manifest from another origin such as a CDN, pass
`manifest({ manifestUrl })` and keep `consentManifest({ source: 'runtime' })`.
Consent saves still go to your Inth project URL. Location handling, `geoUrl`,
and language loading match
[tell the browser where the visitor is](#tell-the-browser-where-the-visitor-is).

## Test without a backend

`testing()` from `@inth/vue/testing` evaluates rules locally and stores
choices in cookies and localStorage. It throws in production builds.

{/* example: fragment */}

```ts title="src/main.ts"
import { testing } from '@inth/vue/testing';
import { inth } from '@inth/vue/vue-plugin';

app.use(inth, { mode: testing(), scripts });
```

Without options, `testing()` uses Inth's recommended policy pack. Pass
`testing({ policy })` to supply custom rules.

## Server rendering without Nuxt

Inth does not ship a server helper for custom Vue SSR. Although `inth`
accepts `prefetch` and `initialRecords`, plain Vue pages render without the
banner and mount it after hydration.

You can still inline theme tokens in your first HTML response using
`generateTokensCSS()` from `@inth/vue/vue-plugin`. Place it in a
`<style id="inth-css-vars">` element so the browser plugin reuses it:

{/* example: fragment */}

```ts
import { generateTokensCSS } from '@inth/vue/vue-plugin';

const tokensStyle = `<style id="inth-css-vars">${generateTokensCSS(tokens)}</style>`;
```

For server-rendered consent banners in the first HTML response, use the Nuxt
module from the [framework list](/docs/frameworks).

## Verify your deployment

Serve the production build and inspect the Network tab:

| `mode` | Policy requests on first load |
| --- | --- |
| `hosted()` | One `GET` to `${projectUrl}/v1/consent/init` |
| `manifest()` with build snapshot | None if no location rules apply or location is supplied; otherwise one `GET` to `${projectUrl}/v1/consent/init`. Non-English copy loads from your site. |
| `manifest({ source: 'runtime' })` | One `GET` to `${projectUrl}/v1/consent/manifest` |
| `manifest({ manifestUrl })` | One `GET` to `manifestUrl` |
| `testing()` | None |

Reject, reload, confirm the banner stays closed, and run through
[verify consent](/docs/guides/verify-consent).
