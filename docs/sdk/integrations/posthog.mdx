Connect PostHog capture to c15t permission on [the web](#web) or in
[Swift, Android, React Native and Expo apps](#mobile). Web setup uses
`@c15t/integrations/posthog`. Mobile helpers ship inside the existing c15t
platform packages and connect your app's configured PostHog client.

## Web

By default, the c15t `posthog` helper loads PostHog's `array.js` on every page,
before the visitor chooses. While `measurement` has no consent, the helper calls
`opt_out_capturing()`. This is also true before the visitor chooses. While
`measurement` has consent, the helper calls `opt_in_capturing()`. The default
`cookieless_mode: 'on_reject'` changes PostHog to cookieless capture after an
opt-out. To wait for consent before the load, set `loadMode: 'after-consent'`.

### Configure PostHog

Use the project token that starts with `phc_`, and the region of your PostHog
project. This example waits for measurement permission before requesting the
SDK, and turns off cookieless capture after a refusal.

<CommandTabs command="@c15t/integrations" mode="install" />

```ts title="src/consent-scripts.ts"
import { posthog } from '@c15t/integrations/posthog';

export const scripts = [
	posthog({
		id: 'phc_YOUR_PROJECT_TOKEN',
		region: 'eu',
		loadMode: 'after-consent',
		initOptions: { cookieless_mode: 'never' },
	}),
];
```

The helper initializes PostHog itself. Remove any `posthog-js` initializer,
framework plugin or array snippet that also does, or follow
[use an existing PostHog SDK](#use-an-existing-posthog-sdk) instead.

### Options

| Option | Default | Behavior |
| --- | --- | --- |
| `id` | Required | Project token, starting with `phc_`. The helper trims it. Empty or whitespace-only values log an error and the script does not load. |
| `region` | `'eu'` | `'eu'` or `'us'`. Picks the API, UI and loader hosts when you do not set them. |
| `apiHost` | `https://eu.i.posthog.com` | API host for a proxy or self-hosted PostHog. Without `scriptUrl`, the loader URL becomes `<apiHost>/static/array.js`. |
| `uiHost` | The region's UI host | UI host, for example `https://eu.posthog.com`. A custom `apiHost` with no `region` uses the API host. |
| `scriptUrl` | `https://eu-assets.i.posthog.com/static/array.js` | Loader URL override. A blank value falls back to the default. |
| `loadMode` | `'always'` | When the SDK loads. See the table below. |
| `features.surveys` | Unset | `false` sets `disable_surveys: true` and skips `surveys.js`. See [turn off features you do not use](#turn-off-features-you-do-not-use). |
| `features.heatmaps` | Unset, follows the project | Sets `capture_heatmaps`. |
| `features.deadClicks` | Unset, follows the project | Sets `capture_dead_clicks`. |
| `features.webVitals` | Unset, follows the project | Sets `capture_performance: { web_vitals }`. Replay network timing keeps following the project. |
| `features.featureFlags` | Unset, follows the project | `false` sets `advanced_disable_feature_flags: true` and stops `/flags` requests. |
| `initOptions` | `{ cookieless_mode: 'on_reject', defaults: '2026-01-30' }` | Options passed to `posthog.init`, merged over the defaults and `features`. The helper sets `api_host` and `ui_host` after your values, so change hosts with the options above. |

### Loading and revocation

| `loadMode` | When PostHog loads | Consent sync |
| --- | --- | --- |
| `'always'` | On every page, before consent | Calls `opt_in_capturing` or `opt_out_capturing` at load and on every change |
| `'after-consent'` | Only while measurement is allowed | Calls `opt_in_capturing` at load and `opt_out_capturing` on revocation |
| `'disabled'` | Never | None. The helper returns an empty callback-only script |

With `'after-consent'`, a refusal can arrive while `array.js` is still
downloading. The download keeps going after c15t removes the script, so c15t
also clears PostHog's queued init. When `array.js` runs, it starts nothing, sends
no events and writes no cookies. If the visitor allows measurement again before
`array.js` runs, PostHog starts on the same page. If `array.js` has already
run, PostHog starts on the next page load. With the default
`reloadOnConsentRevoked`, the page reloads after the refusal anyway.

`posthog` uses the `measurement` category. With the default
`cookieless_mode: 'on_reject'`, PostHog keeps capturing without cookies after a
refusal. That mode needs cookieless server hashing turned on in your PostHog
project; see
[PostHog's cookieless guide](https://posthog.com/tutorials/cookieless-tracking).
Set `cookieless_mode: 'never'`, as in the example, if a refusal must stop
capture.

### Turn off features you do not use

After `array.js` loads, PostHog reads your `posthog.init` options and the
project's remote config, then decides which extra modules to download and
whether to request `/flags`. Set a `features` switch to `false` for each
feature your site does not use:

{/* example: fragment */}

```ts
posthog({
	id: 'phc_YOUR_PROJECT_TOKEN',
	region: 'eu',
	loadMode: 'after-consent',
	features: {
		surveys: false,
		heatmaps: false,
		deadClicks: false,
		webVitals: false,
		featureFlags: false,
	},
});
```

| Switch | `false` sets | What PostHog skips |
| --- | --- | --- |
| `surveys` | `disable_surveys: true` | `surveys.js`, about 29 KB |
| `heatmaps` | `capture_heatmaps: false` | Heatmap capture. With `deadClicks: false` too, `dead-clicks-autocapture.js` |
| `deadClicks` | `capture_dead_clicks: false` | `dead-clicks-autocapture.js`, about 8 KB, once heatmaps are off too |
| `webVitals` | `capture_performance: { web_vitals: false }` | `web-vitals-with-attribution.js`, about 6 KB |
| `featureFlags` | `advanced_disable_feature_flags: true` | `/flags` requests. The remote config still loads |

Sizes are brotli-compressed, measured from posthog-js 1.436.1.

An unset switch adds nothing to `posthog.init`. For heatmaps, dead clicks, web
vitals and feature flags, PostHog then follows the setting in your PostHog
project. `true` sets the opposite value and overrides the project. For
`surveys` and `featureFlags`, `true` is PostHog's own default, so it behaves
the same as unset.

Surveys work differently. PostHog downloads `surveys.js` whenever the remote
config includes a `surveys` value, even when surveys are off in the project.
`surveys: false` is the only way to skip it.

`initOptions` wins over a switch that sets the same key. A
`capture_performance` value in `initOptions` replaces the whole object that
`webVitals` builds.

#### Avoid PostHog's option traps

These rules also apply when you pass PostHog options yourself, in
`initOptions` or in your own `posthog.init`:

- Use `advanced_disable_feature_flags: true` to stop `/flags`, not
  `advanced_disable_flags: true`. The second also stops PostHog loading the
  remote config, so session replay never starts and other features fall back to
  local config.
- With feature flags off, surveys that target a feature flag never show.
  PostHog logs a warning about it. If you need those surveys, leave
  `featureFlags` unset and pass
  `advanced_only_evaluate_survey_feature_flags: true` instead. PostHog still
  requests `/flags`, but evaluates only survey flags.
- While heatmaps are on, in `posthog.init` or in the project, PostHog loads
  `dead-clicks-autocapture.js` whatever `capture_dead_clicks` says. Turn off
  both to skip it.
- `capture_performance: false` turns off web vitals and session replay network
  timing. `{ web_vitals: false }`, which `webVitals: false` sets, leaves network
  timing to the project. `capture_performance: true` forces both on.

Product tours (`product-tours.js`, about 36 KB) and exception autocapture
(`exception-autocapture.js`, about 6 KB) load only when the project turns them
on. To keep them off whatever the project says, pass
`disable_product_tours: true` or `capture_exceptions: false` in `initOptions`.

### Guard your own capture calls

Events your code sends need their own permission check. The `posthog` global
exists before the SDK loads, so its presence does not mean measurement is
allowed:

```ts title="src/track-signup.ts"
export function trackSignupStarted(measurementAllowed: boolean) {
	if (!measurementAllowed) return;
	window.posthog?.capture('signup_started');
}
```

Pass the current measurement permission from your framework, for example
`useConsent('measurement')` in React.

### Use an existing PostHog SDK

If your app already initializes `posthog-js`, keep that setup and register a
callback-only script instead of the helper. Initialize the SDK with
`opt_out_capturing_by_default: true` and `cookieless_mode: 'never'` so it
captures nothing before c15t reports a permission.

```ts title="src/posthog-consent.ts"
import type { Script, ScriptCallbackInfo } from 'c15t/modules/script-loader';

type PostHogConsentApi = {
	opt_in_capturing: () => unknown;
	opt_out_capturing: () => unknown;
};

export function posthogConsent(instance: PostHogConsentApi): Script {
	const sync = ({ hasConsent }: ScriptCallbackInfo) => {
		if (hasConsent) instance.opt_in_capturing();
		else instance.opt_out_capturing();
	};

	return {
		id: 'posthog-sdk-consent',
		category: 'measurement',
		callbackOnly: true,
		alwaysLoad: true,
		onBeforeLoad: sync,
		onConsentChange: sync,
	};
}
```

Add `posthogConsent(posthog)` to the `scripts` you register, passing your
initialized SDK instance. `callbackOnly` means c15t inserts no script element.
`alwaysLoad` makes `onBeforeLoad` run on the first page load even while
measurement is denied, so the SDK is told to opt out. `onConsentChange` runs on
every later change. This does not delay the SDK import or its first request.
`loadMode: 'disabled'` is not a substitute, because it syncs nothing.

`features` belongs to the helper, so it does nothing here. To skip modules you
do not use, pass the PostHog options from
[turn off features you do not use](#turn-off-features-you-do-not-use) to your
own `posthog.init`, for example `disable_surveys: true`.

### Measure opt-in rate

If you run a banner experiment, the backend already counts visitors and
choices per arm. To see the arm in PostHog as well, forward the `onSurfaceShown` and
`onChoiceRecorded` callbacks, which carry `experiment: { id, arm }`. See
[banner experiments](/docs/guides/banner-experiments#send-the-events-to-your-own-analytics-too).

### Verify PostHog

These checks assume `loadMode: 'after-consent'` from the example. After you
allow measurement, `array.js` loads and capture requests to your API host
follow. Trigger one guarded event and check that it is sent.

With `loadMode: 'always'`, `array.js` loads before a choice instead. Check that
no capture request is sent while measurement is denied, unless you chose
cookieless capture.

If you turned features off, allow measurement and filter the DevTools Network
panel by `posthog`. Reload the page. You should see `array.js`, the remote
config and capture requests, but no `/flags` request with `featureFlags: false`
and none of the modules you turned off, such as `surveys.js` or
`dead-clicks-autocapture.js`.

## Mobile

Use the bundled PostHog helper to keep event capture in sync with a native
c15t category. It opts the configured client in when permission is granted,
and out while permission is pending, denied or the integration is closed.

The helper ships inside `C15tApple`, `c15t-android` and
`@c15t/react-native/integrations`. Your app installs and configures PostHog
separately. There is no additional c15t integration package.

### Before you start

Complete the [Swift](/docs/frameworks/swift/quickstart),
[Android](/docs/frameworks/android/quickstart) or
[React Native](/docs/frameworks/react-native/quickstart) quickstart. Include
`measurement` in the Inth policy and native category configuration, or choose
another optional category that covers the events you collect.

Install PostHog using its [iOS](https://posthog.com/docs/libraries/ios),
[Android](https://posthog.com/docs/libraries/android) or
[React Native](https://posthog.com/docs/libraries/react-native) guide. This
page connects the same configured client your app uses for capture. c15t's
mobile packages remain a private prerelease; see
[mobile availability](/docs/guides/mobile-status) for access.

Keep session replay, surveys, automatic error capture and lifecycle capture
disabled in the initial analytics setup. Each product needs its own scope,
configuration and verification. This category helper does not provide IAB
vendor permission, an advertising integration or Apple ATT authorization.

### Choose when PostHog can start

For capture disabled by default, use `optOut = true` in native PostHog
configuration or `defaultOptIn: false` in React Native. Persisted earlier
opt-ins can override defaults, so reconcile current c15t authority on every
launch before relying on capture permission.

Opt-out controls event capture. It does not establish that PostHog makes no
requests. Remote configuration and some `/flags` requests are independent of
analytics opt-out. Disabling preloaded feature flags does not establish a
zero-request startup, and deprecated remote-config switches in current SDKs
do not turn remote configuration off.

If your app requires no PostHog traffic before permission, defer constructing
or setting up its client until the current native category grants it. Keep a
c15t gate alive to perform that first setup when permission changes. Once the
client exists, connect the helper below to manage capture and withdrawal.
Implement and test that deferred-start path in the app; the helper accepts
an already configured client and does not construct it for you.

For native SDKs, put the first setup behind a
[native startup gate](/docs/frameworks/react-native/native-behaviour). React
hooks cannot prevent a native SDK that has already initialized. For Expo,
install PostHog using its Expo instructions and rebuild the app's native
binary. c15t does not add the vendor module or its configuration, and Expo Go
does not load c15t's native engine.

### Connect a Swift app

Create `PostHogOwner.swift` in your app target:

<include src="../shared/examples/native/core-swift/AppleInstallation/swift-posthog-binding.mdx" />

After your app has installed c15t and configured PostHog, construct the owner
with the client's supported APIs. Retain `posthogOwner` on the app's service
owner:

{/* example: fragment */}

```swift
import PostHog

let posthogOwner = PostHogOwner(
    core: core,
    optIn: { PostHogSDK.shared.optIn() },
    optOut: { PostHogSDK.shared.optOut() }
)
```

`core` is the `ConsentCore` returned by installation. The helper immediately
applies current permission. Calls run synchronously on the registering thread
or native consent notification thread and are serialized per helper. Pass
the direct vendor calls; independently dispatched tasks can reorder opt-in
and withdrawal.

The owner uses `measurement`. If your events belong to another optional
category, pass that category to its `PostHogIntegration` initializer. Retain
one owner for the client lifetime. Releasing it cancels observation and opts
out of capture.

### Connect an Android app

Copy this helper into your app's Kotlin source directory, replacing the
sample package name with your own:

<include src="../shared/examples/native/examples/consent-demo/android-posthog-integration.mdx" />

Call it after native installation and the permitted PostHog setup. This
fragment uses PostHog's shared client:

{/* example: fragment */}

```kotlin
import com.posthog.PostHog

val posthogConsent = connectAppPostHog(
	optIn = { PostHog.optIn() },
	optOut = { PostHog.optOut() },
	onError = ::reportAnalyticsError,
)
```

Retain `posthogConsent` on your application or service owner. The native core keeps
applying consent until you call `close()`, even if the app drops the handle. Do not close an
app-wide integration each time an Activity rotates. The required `onError`
receives automatic vendor-update exceptions; use an error handler that works
while analytics capture is off and does not throw. Construction, `sync()` and `close()` can also
throw to their caller, so handle failures at those call sites.

Callbacks run synchronously and are serialized per helper. If your app uses
a separate PostHog client instance, bind that instance's opt-in/out methods
instead of the shared singleton.

### Connect React Native or Expo

Copy this connection function into `posthog-consent.ts`:

<include src="../shared/examples/react-native-bare/rn-posthog-integration.mdx" />

Pass the app's configured PostHog client. In your existing asynchronous
startup function, retain the returned connection and await its first update:

{/* example: fragment */}

```ts
const posthogConsent = connectAppPostHog(posthog, reportAnalyticsError);
await posthogConsent.ready;
```

`posthog` is the existing `PostHog` instance. The connection invokes methods
on that instance, preserving their receiver. Use one app-lifetime connection
for it. Await `ready` before capture that depends on the connection's first
permission update.

For a newly constructed RN client, these options disable the automatic
analytics products used outside this recipe:

{/* example: fragment */}

```ts
import { PostHog } from 'posthog-react-native';

const posthog = new PostHog('YOUR_POSTHOG_PROJECT_TOKEN', {
	host: 'https://eu.i.posthog.com',
	defaultOptIn: false,
	preloadFeatureFlags: false,
	disableRemoteFeatureFlags: true,
	enableSessionReplay: false,
	captureAppLifecycleEvents: false,
	disableSurveys: true,
});
```

Replace the token and EU ingest host with your project's settings. If you need the
strict startup path described earlier, construct this client only after
permission allows it. These options still do not promise that remote
configuration makes no requests. Mounting a PostHog provider with its own
token-based initialization can create a second client; give it the existing
client instead, following PostHog's provider instructions.

The connection awaits each opt-in/out operation. If permission closes during
an asynchronous opt-in, it reconciles to opt-out. PostHog does not expose a
way to cancel a vendor operation already submitted, so withdrawal is not an
instantaneous network cancellation.

Supply a required `onError` handler. It receives initial and later vendor
failures. The promises from `ready`, `sync()` and `disconnect()` also reject
on failure; handle those at their call sites. If PostHog's own opt-out fails,
you cannot assume capture is disabled.

### Apps set up with the EAS PostHog integration

`eas integrations:posthog:connect` prepares an Expo project for PostHog. In
`eas-cli` 27.10.0 it does the following:

- Creates or links a PostHog organization and project for the EAS project, in
  the US or EU region you pick.
- Installs `posthog-react-native`, `expo-file-system`, `expo-application`,
  `expo-device` and `expo-localization`. It also installs
  `@posthog/react-native-plugin` when you keep session replay, which the
  command selects by default.
- Adds the `posthog-react-native/expo` config plugin. The plugin changes
  native build files to upload source maps and native debug symbols, and adds
  an `onNewIntent` override to Android's `MainActivity`. It adds no code that
  starts PostHog.
- Writes `EXPO_PUBLIC_POSTHOG_API_KEY` and `EXPO_PUBLIC_POSTHOG_HOST` to
  `.env.local` and to the project's EAS environment variables. With error
  tracking it also stores `POSTHOG_CLI_API_KEY`, `POSTHOG_CLI_PROJECT_ID`
  and `POSTHOG_CLI_HOST` for symbol uploads.

The command does not create a PostHog client or start capture. Its next step
tells you to wrap the app in `PostHogProvider`. A provider that receives the
project token creates its own client when it mounts, with capture on unless
its `options` set `defaultOptIn: false`. Build the client yourself from the
same variables instead, with capture off, so c15t controls the one client
your app uses:

<include src="../shared/examples/expo/expo-posthog-client.mdx" />

The client throws when the two variables are missing, so a build without
them fails at launch instead of sending nowhere. It opts out as soon as it is
built, because an opt-in that PostHog stored before your app used c15t
overrides `defaultOptIn: false`. It also turns off remote
feature flags and surveys, because both can call PostHog before anyone has
consented. If your app uses flags or surveys, remove those two options
and load them only after measurement is granted.

Then give that client to the provider:

<include src="../shared/examples/expo/expo-posthog-root.mdx" />

Connect the same `posthog` instance to c15t as shown in
[Connect React Native or Expo](#connect-react-native-or-expo). Leave session
replay off until you have scoped and tested it, even if the command installed
the replay plugin. The provider's `autocapture={false}` keeps screen and
lifecycle autocapture off for the same reason. The config plugin's symbol
uploads run on your build machine and send no data from users' devices.

### Reapply permission after reset

PostHog's own reset can change its capture settings while c15t's saved choice
stays unchanged. After the reset completes, use `syncAfterReset()` on the
Swift owner, `sync()` on the Kotlin helper or
`await posthogConsent.sync()` in React Native. This reapplies current native
permission without recording another consent choice.

For final service teardown, use the Swift owner's `stop()`, Kotlin's
`close()` or `await posthogConsent.disconnect()` in React Native. These
detach c15t observation and request opt-out. Keep their lifetime attached to
the service, rather than a short-lived settings screen.

Opt-out does not delete historical events. Previously queued native events
can still be delivered, and requests already sent cannot be retracted.
Configure retention and data deletion through PostHog's supported controls
when your app needs them.

### Check the integration

Use the real client and build configuration your app ships:

1. Launch with no saved choice. Confirm capture remains opted out while
   native permission is pending and after Reject all.
2. Grant measurement. Confirm the connected client opts in, then capture a
   deliberate test event.
3. Withdraw measurement. Confirm the client opts out and newly captured
   events are refused.
4. Terminate and relaunch after grant and refusal. Check persisted PostHog
   settings and native startup before JavaScript.
5. Reset the vendor client, call `sync()` and confirm that current permission
   is reapplied without recording a new choice.
6. Exercise error handling and teardown. Inspect configuration traffic and
   old queued events separately from new event capture.

The helper tests exercise consent changes, reset, teardown and callback
ordering. The RN client contract was type-checked with PostHog RN 4.85.1;
native API review used iOS 3.93.1 and Android 3.75.0. This is source and type
validation. It does not establish real-device capture, startup traffic or
withdrawal behavior for your app. Complete
[mobile verification](/docs/guides/mobile-verify) with its actual vendor
versions and launch path before relying on those behaviors.
