---
title: Inth CLI flags and raw API requests
description: Choose output and authentication options or call the Inth API directly.
---

Use `--json` for structured output, `--non-interactive` to disable prompts, and `inth api <path>` for a raw API request. Check `inth <command> --help` before choosing flags, because accepted options depend on the command.

## Which flags control output and authentication?

| Flag | Behavior |
| --- | --- |
| `--help` | Show the relevant command's options and examples |
| `--version` | Print the installed CLI version |
| `--json` | Emit one JSON result and disable prompts and browser login |
| `--non-interactive` | Disable prompts while keeping text output |
| `--token <key>` | Use an organization API key instead of `INTH_TOKEN` or saved credentials |
| `--auth browser\|agent` | Override the selected saved connection |
| `--organization <id>` | Override the organization for commands that support it |

Flags are command-specific. Use `inth <command> --help` to check whether a flag is accepted. Most commands that target a resource ID reject `--organization`, since the server resolves ownership from the ID. Billing invoice reads and PDF downloads also accept an organization selector.

Piping output does not select JSON mode. The [automation guide](./automation) describes the JSON envelope, error codes, and exit statuses. Skill installation forwards upstream text output and does not support `--json`; the bundled skill catalog supports `--list --json`.

## How do I set pagination and JSON request bodies?

Each list invocation returns one page. Standard resource lists accept `--limit` from 1 through 100 and an opaque `--cursor`. Resource-specific pagination can use a different default or fixed numbered pages. Check the command's help, and pass the returned continuation unchanged with the same organization and filters.

Resource writes with body options accept `--data '<JSON object>'` or `--data-file <path|->` instead of individual fields, except `org create`. This supports nested fields and explicit null values. Choose one body form.

```sh
inth project update prj_123 --data '{"description":null}'
inth project update prj_123 --data-file project-update.json
```

An empty `consent.trustedOrigins` array allows every origin. Use an explicit list to restrict origins.

Only a file flag with `-` reads stdin. Files and stdin must contain UTF-8 text. JSON input is limited to 1 MiB, or 64 KiB for feedback. `--data @file` has no special file meaning. Raw `api` writes also accept `--data-file`.

Chat and Support writes also accept `--message-file <path|->` for message text. `--message -` sends a literal hyphen. See [chat commands](./commands#how-do-i-use-inth-agent-chats) for limits and safe retries.

Binary download commands require `--output <new-file>`. They refuse existing paths and `-`, and enforce a 128 MiB limit. `--json` reports file metadata on stdout. See [download examples](./commands#how-do-i-download-screenshots-invoices-and-support-attachments).

## How do I call the Inth API directly?

`api` prints the server JSON response by default. Add `--json` to wrap it in the CLI envelope.

```sh
inth api /v1/me
inth api /v1/projects --organization org_123 --json
inth api /v1/projects/prj_123 --method PATCH --data '{"description":null}'
inth api GET /v1/agent-chat-attachments/att_123/content \
  --output ./attachment.bin --json
```

Requests support `GET`, `POST`, `PUT`, `PATCH`, and `DELETE`. GET is the default. Authenticated requests must stay under `https://api.inth.com/v1/`, and redirects are rejected. Raw requests do not use the saved or directory-linked organization. Pass `--organization` or an `organizationId` query parameter only when the endpoint accepts that selector. Resource IDs resolve their own organization.

Use `api GET <path> --output <new-file>` for binary reads without a named command, including chat attachment paths returned by the API. The existing form `api <path> --method GET --output <new-file>` also works. File output accepts GET only and rejects body input. Without `--output`, raw responses must be JSON. With `--output`, stdout contains JSON file metadata; add `--json` for the versioned CLI envelope. The normal 128 MiB limit and no-overwrite policy apply.

Writes take effect immediately without confirmation prompts. The requested endpoint determines the required scopes and accepted credentials.

## Which environment variables does the Inth CLI read?

| Variable | Purpose |
| --- | --- |
| `INTH_TOKEN` | Organization API key for commands that accept keys |
| `INTH_TELEMETRY_DISABLED=1` | Disable analytics and unexpected-error reporting |
| `CI` | A truthy value disables telemetry |
| `NO_COLOR=1` | Disable terminal colors |
| `CODEX_HOME` | Select the Codex global configuration directory for MCP setup |
| `DO_NOT_TRACK`, `DISABLE_TELEMETRY` | Passed through to the upstream skills installer |

For telemetry overrides, empty values, `0`, and `false` do not override the saved preference. See [Telemetry](./telemetry) for exactly what production builds send.

Avatar and organization-logo commands use `--file` for raw image bytes up to 1 MiB. `--data-file` remains JSON input. Financial previews can use `--save-approval <new-file>` to save the exact organization, input and full quote for later review and execution. `--yes` approves the stated effect; it does not replace required confirmation strings, preconditions, UUIDs, rotation overlap or spending limits.
